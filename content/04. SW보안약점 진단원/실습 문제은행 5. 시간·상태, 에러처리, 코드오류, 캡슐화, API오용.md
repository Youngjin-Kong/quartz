> ⚠️ **기출문제가 아님.** 공개 가이드(SW 개발보안 가이드) 내용을 근거로 만든 **연습문항**임. 근거 범위는 `SW보안약점 진단원 통합 수험서.md` 제3장 「유형 3. 시간 및 상태」 ~ 「유형 7. API 오용」의 3-1 ~ 7-2 열여섯 항목이며, 각 항목의 「보안대책」·「정탐/오탐 판단」 문장에서 채점 키워드를 추출함.

**사용법**
- 실습시험 조건 — 100분 / 15문항 / 100점 / 60점 미만 과락. 문항당 평균 6.7분.
- 각 문항에 ① 정탐·오탐 판단 ② 사유 서술(근거 코드 지목) ③ 정탐이면 개선방안까지 작성할 것.
- **채점은 핵심 키워드 포함 여부로 함** — 뜻만 맞게 쓰면 0점. 해설의 `[채점 키워드]` 단어 자체가 답안에 들어가야 함.
- 총 34문항 — 항목당 2문항이 기본이고, **4-1(오류 메시지 정보노출)만 3문항**, **7-2(취약한 API 사용)는 3문항**임. 정탐 17 / 오탐 15 / 함수 쌍 비교 2.
- **순서는 섞여 있음.** 홀짝으로 찍지 말 것.
- 언어 — 3-2·5-3·5-4·7-2 는 C(가이드 제3장 코드예제가 C), 나머지는 Java. C 9문항 / Java 25문항.
- 해설은 문서 하단에 일괄 배치. 답안을 쓰기 전에 내려가지 말 것.

**출처 표시 — 해설 끝의 괄호를 먼저 볼 것**

- `(가이드 원문 예제 기준)` — 제3장 해당 항목의 「취약 코드」 또는 「안전 코드」를 **식별자 수준(변수명·파일명·클래스명·경로)만 바꿔** 옮긴 문항임. **16문항** — 3-1~7-2 열여섯 항목마다 정확히 1문항씩임
- `(재구성)` — 같은 약점을 다른 코드로 새로 지어낸 문항임. **18문항**
- **원문 표시가 붙은 쪽을 먼저 외울 것.** 변형이 식별자 수준에 그치므로 원문을 알면 변형을 알아보고, 「안전 코드」가 그대로 개선방안 답안이 됨

public class AllowedClassInputStream extends ObjectInputStream {
    public Set<String> allowed;

    public AllowedClassInputStream(InputStream in, Set<String> list) throws IOException {
        super(in);
        allowed = list;
    }

    @Override
    protected Class<?> resolveClass(ObjectStreamClass cls)
            throws IOException, ClassNotFoundException {
        if (!allowed.contains(cls.getName())) {
            throw new InvalidClassException("Unexpected serialized class", cls.getName());
        }
        return super.resolveClass(cls);
    }
}

**20. 정탐.** 브라우저가 되돌려 보내는 `state` 파라미터, 즉 **공격자가 조작 가능한 바이트 스트림**을 검증 없이 `ois.readObject()` 로 역직렬화함. `CartState` 로의 형 변환은 readObject 가 **끝난 뒤** 일어나므로 캐스팅은 방어가 되지 않고, 클래스패스의 가젯 체인으로 원격 코드 실행이 가능함. [채점 키워드: 신뢰할 수 없는 데이터 / 검증 없이 readObject / 역직렬화(원격 코드 실행)] 개선: `resolveClass` 를 재정의해 **허용 클래스 화이트리스트**만 역직렬화하거나, 송신 측 서명 추가·수신 측 서명 확인으로 무결성을 검증. 가능하면 JSON 등 데이터 전용 포맷으로 대체. (재구성)

**21. 오탐.** `ObjectInputStream` 을 상속하고 **`resolveClass` 를 재정의**하여, `ObjectStreamClass` 의 클래스명이 **화이트리스트**(`allowed`)에 없으면 `InvalidClassException` 을 던져 역직렬화를 중단함. 사전에 검증된 클래스만 복원되므로 가젯 체인이 성립하지 않음. [채점 키워드: 화이트리스트 검증(resolveClass) / 허용 클래스만 역직렬화 / 미허용 시 InvalidClassException] (가이드 원문 예제 기준)

**22. 오탐.** 멤버 필드는 상태를 갖지 않는 **불변 의존 객체(dao)** 뿐이고, 요청별 값인 `userId`·`month` 는 모두 **메소드 내 지역변수**로 선언됨. 싱글톤이어도 스레드 간에 공유되는 요청 데이터가 없음. [채점 키워드: 지역변수 선언 / 요청별 정보 멤버 필드 없음 / 스레드 간 공유 없음] (재구성)

**23. 정탐.** `@Controller` 는 **하나의 인스턴스로 만들어져 여러 스레드가 공유**되는데, 요청별 정보인 페이지 번호를 **멤버 변수 `pageNo`** 에 저장함. 두 사용자의 요청이 겹치면 A 가 대입한 값으로 B 의 목록이 조회되어 **세션 간에 데이터가 공유·노출**됨. [채점 키워드: 싱글톤(Controller) 멤버 변수 / 요청별 정보 저장 / 스레드 간 공유(세션 간 노출)] 개선: 필드 선언을 삭제하고 `int pageNo = Integer.parseInt(request.getParameter("page"));` 처럼 **메소드 내 지역변수**로 선언. (가이드 원문 예제 기준)

**24. 정탐.** J2EE 배포 대상 클래스에 **디버그 용도로 만든 `main()` 메소드가 삭제되지 않고 남아** 있음. 클래스 파일만 있으면 실행되어 디버그 경로와 내부 처리 값이 드러나고, 공격자가 식별 과정을 우회할 수 있음. [채점 키워드: 디버그 코드(main() 메소드) 잔존 / 배포 전 확인 및 삭제 / J2EE] 개선: 릴리즈 전 `main()` 메소드와 디버그용 출력 코드를 **삭제**하고 동작 코드(`encode()`)만 남김. (가이드 원문 예제 기준)

**25. 오탐.** 디버그용 `main()` 메소드와 콘솔 출력 코드가 **없고**, 남은 것은 운영 로그 레벨(INFO)에서 출력되지 않는 `logger.debug` 호출뿐이며 주문번호·처리결과만 담아 **민감정보나 콜스택을 노출하지 않음**. [채점 키워드: main() 메소드 없음 / 민감정보·콜스택 미출력 / 로그 레벨로 통제] (재구성)

**26. 오탐.** private 배열의 레퍼런스를 반환하지 않고 **새 배열을 생성**한 뒤, 원소가 가변 객체이므로 **원소까지 `clone()` 으로 복사**해 담아 반환함. 반환값을 외부에서 고쳐도 `colors` 와 그 원소는 영향을 받지 않음. [채점 키워드: 복사본 반환 / 원소 clone() 복사 / private 배열 레퍼런스 미노출] (가이드 원문 예제 기준)

**27. 정탐.** `Arrays.copyOf` 는 **얕은 복사**라 배열 껍데기만 새로 만들고 **원소는 같은 UserRole 객체를 가리킴**. 원소가 가변 객체이므로 호출자가 `getRoles()[0].setScope(...)` 로 내부 권한을 바꿀 수 있어 사실상 private 배열이 공개됨. **원소가 String 같은 불변 타입일 때만 복사본 반환으로 충분함.** [채점 키워드: 얕은 복사(원소 레퍼런스 공유) / 가변 객체 원소 / 원소 clone() 필요] 개선: 새 배열의 각 원소를 `clone()` 으로 복사해 담아 반환하거나, 조회용 값 객체(불변 DTO)로 변환해 반환. (재구성)

**28. 정탐.** public 메소드 `setUserGrades` 가 **외부에서 받은 배열 인자를 복사 없이 그대로 필드에 할당**(`this.userGrades = userGrades`)함. 호출자가 원래 배열을 계속 쥐고 있으므로 나중에 원소를 바꿔 등급을 조작할 수 있어 private 필드가 **사실상 public** 이 됨. [채점 키워드: public 메소드 인자 / 복사 없이 참조 할당 / 사실상 public 필드] 개선: `this.userGrades = new UserGrade[userGrades.length];` 로 새 배열을 생성하고 각 원소를 `clone()` 으로 복사해 할당. (가이드 원문 예제 기준)

**29. 오탐.** 인자 배열을 그대로 저장하지 않고 **길이가 같은 새 배열을 생성**한 뒤 **각 원소를 `clone()` 으로 복사**해 담음. 호출자가 원본 배열이나 그 원소를 수정해도 `endpoints` 는 바뀌지 않음. [채점 키워드: 복사본 생성 / 원소 clone() 복사 / 참조 직접 할당 아님] (재구성)

**30. 오탐.** 호스트명 조회 없이 `req.getRemoteAddr()` 로 얻은 **IP 주소를 신뢰 목록과 직접 문자열 비교**함. DNS 응답이 개입하지 않으므로 DNS 변조로 판정을 뒤집을 수 없음. [채점 키워드: IP 주소 직접 비교 / DNS lookup 미사용 / 호스트명 비교 아님] (재구성)

**31. 정탐.** `InetAddress.getByName(ip)` 로 얻은 주소에 **`getCanonicalHostName()` 으로 DNS 조회**를 하고, 그 **도메인명이 사내 도메인으로 끝나는지**로 신뢰 시스템 여부라는 **보안결정**을 내림. 공격자가 자기 IP 의 역방향 DNS 엔트리를 `*.corp.example.com` 으로 등록하거나 로컬 DNS 캐시를 오염시키면 관리자 기능이 열림. [채점 키워드: DNS lookup(도메인명 조회) / 도메인(호스트)명으로 보안결정 / DNS 변조·캐시 오염] 개선: 호스트명 비교를 제거하고 `ip.equals(trustedAddr)` 처럼 **이용하려는 실제 서버의 IP 주소를 직접 비교**. (가이드 원문 예제 기준)

**32. 정탐.** 길이 제한이 없는 **금지 API `strcpy`·`strcat`·`sprintf`** 를 외부입력(user·name)에 대해 사용함. `path`(256바이트)·`title`(64바이트) 경계를 넘는 입력이 들어오면 스택 버퍼를 넘어 써 프로그램이 변조됨. [채점 키워드: 금지된(banned) 함수(strcpy·strcat·sprintf) / 길이 제한 불가 / 안전한 대체 함수] 개선: `strcpy_s`·`strcat_s`·`sprintf_s`(또는 `snprintf`)처럼 **목적지 크기를 인자로 받는 대체 함수**로 교체하고, 조직이 금지 API 목록을 정한 경우 그것을 준수. (재구성)

**33. 함수 A 정탐 / 함수 B 오탐.** A 는 **금지 API `gets()`** 를 사용함 — 문자열 길이를 제한할 인자가 없어 16바이트 `line` 버퍼를 넘는 입력을 그대로 써 버림. B 는 **`fgets(line, sizeof(line), stdin)`** 로 **버퍼 크기를 인자로 넘겨 읽는 길이를 제한**하고 반환값 NULL 검사까지 수행하므로 약점이 성립하지 않음. [채점 키워드: gets() 금지 함수 / 길이 제한 불가 vs 버퍼 크기 인자 전달 / 안전한 대체 함수(fgets·gets_s)] 개선(A): `gets(line)` 을 `gets_s(line, sizeof(line))` 또는 `fgets(line, sizeof(line), stdin)` 으로 교체. (가이드 원문 예제 기준)

⚠️ **33번은 1차 시험 복원에서 함수 비교 문항으로 특정된 쌍임**(`gets` ↔ `gets_s()`/`fgets()`). 출처는 응시자 기억이며 공식 기출이 아님.

**34. 함수 C 정탐 / 함수 D 오탐 `[가정]`.** C 는 `vfork()` 로 자식을 만든 뒤 `execl` 전에 `setup_child_env()` 를 호출함. `vfork` 로 만든 자식은 **부모와 주소공간을 공유**한 채 실행되며 `exec` 계열 호출이나 `_exit()` 전까지 부모가 정지하므로, 그 사이에 전역 설정 구조체·환경변수를 수정하면 **부모의 상태까지 훼손**됨. 반환값 검사도 없어 생성 실패 시 실패 경로가 부모 문맥에서 그대로 실행됨. D 는 `fork()` 를 사용해 자식이 **독립된 주소공간**을 갖고, `pid < 0` 으로 **반환값을 검사**하므로 약점이 성립하지 않음. 개선(C): `vfork()` 를 `fork()`(또는 `posix_spawn()`)로 교체하고 반환값을 검사할 것. (재구성)

- `[가정]` — **`fork`/`vfork` 는 통합 수험서 제3장 7-2 에 근거 문장이 없음**(전 문서 검색 결과 0건). 위 판정은 일반 지식으로 구성한 것임
- 수험서 7-2 문장 중 걸 수 있는 근거는 「금지 API 목록」이 아니라 **「금지되지 않았어도 취약하게 쓰일 수 있는 API 에 주의하고, 개발 조직이 취약 API 를 명시한 경우 반드시 준수한다」** 쪽임. `vfork` 는 수험서가 열거한 금지 API(gets·strcat·strcpy·strncat·strncpy·sprintf)에 **없음**
- [채점 키워드: 부주의하게 사용될 가능성이 많은 API / 안전한 대체 함수 / 반환값 검사] — 앞 둘은 수험서 7-2·4-3 의 용어임. 반면 **「주소공간 공유」·「부모 정지」·「POSIX 삭제(obsolescent)」는 수험서 용어가 아니므로** 답안의 득점 키워드로 기대하지 말 것

## 오답 정리 포인트

- **4-1 vs 4-2 vs 4-3** — 오류 정보를 **밖으로 내보내면** 4-1, 오류를 **잡고도 아무것도 안 하면** 4-2, **잡긴 하는데 뭉뚱그리면(Exception 하나)** 4-3. 문항 9(빈 catch)와 문항 10(광범위 catch)의 차이가 그것임.
- **4-1 의 두 형태** — 스택 트레이스 출력(문항 5)만 정탐이 아니라 **`e.getMessage()` 를 화면에 뿌리는 것(문항 7)도 정탐**임. 반대로 서버 로그에만 남기면 오탐(문항 6). 판정 기준은 「**어디로** 나가는가」이지 「로깅을 했는가」가 아님.
- **5-1 의 함정** — null 검사를 **하기는 했으나 다른 변수는 안 한** 경우는 정탐(문항 13). 「검사가 있다」가 아니라 「**역참조되는 그 변수**가 검사됐나」로 볼 것.
- **5-2 의 함정** — `close()` 가 코드에 보이더라도 **`finally` 밖**이면 정탐. 예외 경로뿐 아니라 **조기 return 경로**도 누수임(문항 14).
- **6-3 vs 6-4** — 밖으로 **내보내면** 6-3(반환), 밖에서 **받아 저장하면** 6-4(할당). 대응책은 양쪽 모두 「복사본 + 가변 원소는 clone()」으로 같음.
- **6-3 의 핵심 분기** — 복사본을 만들었어도 **얕은 복사이고 원소가 가변 객체면 정탐**(문항 27). **원소가 String 등 불변일 때만** 배열 복사본 반환으로 충분함(가이드 「보안대책」 세 번째 항목).
- **7-1 판정선** — 「DNS 를 썼는가」가 아니라 「**DNS 결과로 보안결정을 했는가**」임. 로깅·통계용 호스트명 조회는 보안결정이 아님.
- **오탐으로 착각하기 쉬운 형태** — `synchronized` 를 걸되 검사와 사용이 서로 다른 블록, catch 하되 로그만 남기고 그대로 진행, `close()` 를 try 본문 끝에서 호출, 배열을 복사하되 가변 원소를 그대로 담기. **전부 정탐임.** 이 문제은행의 오탐 문항 15개는 그런 함정 없이 대응책이 실제로 동작하도록 작성함.
