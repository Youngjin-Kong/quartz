# 실습 문제은행 적대적 검증 — 감사 A (파일 1·2·3·7)

**감사 대상** — `실습 문제은행 1. 입력데이터 검증 및 표현 (1-9).md`(26문항) / `2. 입력데이터 검증 및 표현 (10-17).md`(21문항) / `3. 보안기능 (1-8).md`(16문항) / `7. 코드 작성형.md`(20문항). 총 83문항.
**근거 문서** — `SW보안약점 진단원 통합 수험서.md` 제3장(1-1~1-17 · 2-1~2-8 · 2-14 · 2-16 · 4-2 · 4-3 · 5-1 · 5-2 · 6-3 · 6-4 · 7-2 전량 대조). **수정하지 않음.**
**실행 검증 환경** — 로컬 OpenJDK 24(`javac 24.0.1`), 원격 Kali gcc(`-Wall -Wextra`, glibc).

| 파일 | 검증 문항 | 정정 | 극성 뒤집힘 | 키워드 교체 |

**가짜 오탐 0건.** 32개 오탐 문항의 대응책을 하나씩 추적해 「검증 후 원본 변수 사용 / 블랙리스트를 화이트리스트라 주장 / 필터가 문자를 못 거름 / 토큰 미검증 / 검사 결과 미사용 / 고정 상수 솔트 / 뒤에서 무력화 / 카운터만 있고 조치 없음」 여덟 가지 전형을 대조했고, **해당하는 문항이 없었음.** 유일하게 필터가 실제로 무력한 문제 1-9(`replaceAll("|","")`)는 **이미 파일에 실측 유보가 달려 있었음.**

**극성을 뒤집은 문항 0건.** 따라서 각 파일의 정답 분포·배열은 변경되지 않았고, 자가채점 산식 정정은 **문항 수 누락 때문**이지 정답이 바뀐 것이 아님.

## 1. 파일 1 — 입력데이터 검증 및 표현 (1-9), 26문항

### ① 지적한 것
1. **문항 수 선언이 26이 아니라 18** — 머리말 「범위」·항목 표·자가채점 산식이 전부 기본 18문항만 반영. 보강 8문항(19~26)이 산식에서 통째로 빠져 있었음.
2. **자가채점 만점·목표선이 실제 재고와 어긋남** — 45점/32점은 18문항 기준인데 파일에는 26문항이 있음.
3. **문제 26이 파일의 선언 범위(1-1~1-9) 밖** — 항목이 **2-5**(유형2 보안기능)인데 머리말에 표시가 없어, 범위대로 공부한 사람이 항목 대응을 못 찾음.
4. **문제 20 해설의 XXE 배제 근거가 약함** — 「`disallow-doctype-decl=true` 라 XXE 가 성립하지 않음」이라고 썼으나, **진짜 근거는 파싱 대상이 외부 전송 XML 이 아니라 서버 로컬 파일**(`new File("/app/conf/org.xml")`)이라는 점임. 1-8 의 전제가 「외부에서 전송된 XML」이므로 파서 설정을 근거로 대면 문제 21·22 와 구분이 흐려짐.
5. **오탐 필터의 실제 동작 여부가 문항마다 갈리는데 표시가 없음** — 문제 6(`replaceAll("\\.","")`)은 동작하고 문제 9(`replaceAll("|","")`)는 무동작인데, 둘 다 「가이드 원문 예제 기준」이라 학습자가 「가이드에 있으면 안전」으로 일반화할 위험이 있었음.

### ② 고친 것

| 위치 | 전 | 후 |
|---|---|---|
| 머리말 「범위」 | `18문항 (9개 항목 × 2문항)` | `26문항 (기본 18 + 보강 8)`, 항목 표에 19~26 행 8줄 추가 |
| 보강 문항 도입부 | (범위 밖 표시 없음) | 「문제 26 만 선언 범위 밖 — 항목은 **2-5 암호화되지 않은 중요정보**」 경고 추가 |
| 자가채점 | `만점 = 18문항 × 2점 + 정탐 9 × 1 = 45점 / 목표 32점` | 기본 18문항(45점·32점)과 **보강 포함 26문항(65점·46점)** 두 갈래로 분리 |
| 정답 분포 줄 | 기본 18문항 분포만 | 「보강 합산 시 **정탐 13 / 오탐 13**」 추가 |
| 해설 20 | 「파서도 `disallow-doctype-decl=true` 라 XXE 가 별건으로 성립하지 않음」(본문 안에 섞임) | 본문에서 빼고 ⚠️ 줄로 분리, **근거를 「파싱 대상이 서버 로컬 설정 파일」로 교체.** 정규식 실측(입력 `a'b[c]d(e)f,g/h@i*j\|k=l"m` → 출력 `abcdefghijklm`, 12문자 전부 제거) ✅ 줄 추가 |
| 해설 6 | (실측 없음) | 실측 `../../etc/passwd` → `etcpasswd` ✅ 줄 + **「문제 9 와 짝지어 — 이스케이프 유무로 동작이 갈린다」** ⚠️ 줄 추가 |

### ③ 지적했다가 스스로 반증해 철회한 것
- **「문제 7 의 `replaceAll` 다섯 줄이 JSP 스크립틀릿 `<% %>` 밖에 있어 문법 오류」** → 철회. **제3장 1-4 안전예제(원문)가 정확히 같은 형태**로 스크립틀릿 없이 나열함(수험서 477~481행). 원문 재현이므로 오류가 아님.
- **「문제 17 의 `bindString` 이 `'$xmname'`(따옴표 안)이라 XQJ 에서 외부변수로 안 잡힘」** → **철회하지 않았으나 고치지도 않음.** 아래 §5 「의심」으로 남김.
- **「문제 12 는 `shell.jsp.png` 가 통과하므로 가짜 오탐」** → 철회. `lastIndexOf(".")` 로 `png` 판정 후 **UUID 로 재명명 + 웹루트 밖(`/data/upload`) 저장**이라 웹으로 직접 호출할 경로가 없음. 1-6 보안대책 3개 중 3개가 다 적용된 진짜 오탐임.
- **「문제 5 의 `Paths.resolve` 는 정규화하므로 정탐이 아님」** → 철회. `resolve` 는 `..` 를 정규화하지 않음(`normalize()` 가 하는 일임). 정탐 유지.

### ④ 의심이 남지만 못 고친 것
- **문제 17 XQuery 변수 바인딩의 실제 동작** — §5 참조.

## 2. 파일 2 — 입력데이터 검증 및 표현 (10-17), 21문항

### ① 지적한 것
1. **문항 수 선언이 「총 16문항」** — 보강 5문항(17~21) 미반영.
2. **자가채점 만점 40점/목표 28점이 16문항 기준** — 21문항 재고와 불일치.
3. **기본 16문항의 정답 분포 줄이 없음** — 보강 5문항에만 분포가 붙어 있어, 기본을 푼 뒤 자가채점할 근거가 파일 안에 없었음(파일 1 에는 있음).
4. **해설 17 의 피해 서술이 부정확** — 「변환 결과에 `%x` · `%n` 이 남으면」이라고 썼으나, `%n`·`%x` 는 **strftime 자신의 변환 지시자**(개행 · 로케일 날짜)라 그 단계에서 소비돼 `printf` 까지 남지 않음. 실제로 남기려면 `%%n`·`%%x` 여야 함.

### ② 고친 것

| 위치 | 전 | 후 |
|---|---|---|
| 머리말 「범위」 | `항목당 2문항, 총 16문항` | `기본 16 + 보강 5(문제 17~21) = 총 21문항` |
| 자가채점 | `만점 = 16 × 2 + 정탐 8 = 40점 / 28점` | 기본 16문항(40점·28점)과 **보강 포함 21문항(52점·37점)** 두 갈래 |
| 자가채점 | (기본 분포 없음) | `정탐 8 / 오탐 8, 배열 정·오·오·정·정·오·정·오·오·정·오·정·정·오·오·정` 추가 |
| 해설 17 본문 | `변환 결과에 %x · %n 이 남으면` | `변환 결과에 포맷 지시자가 남으면` 으로 중립화 + ⚠️ 실측 줄 2개 추가 |
| 해설 20 | (실측 없음) | LDAP 메타문자 제거 실측 ✅ 줄 추가 |

**해설 17 에 추가한 실측**(Kali gcc/glibc):

```
in=[%x|%n|]   -> buf=[08/28/26|<개행>|]     ← 지시자가 남지 않음
in=[%%x|%%n|] -> buf=[%x|%n|]               ← 리터럴로 남음
```
`%%n` 케이스로 만든 `buf` 를 `printf(buf)` 에 넘긴 프로그램은 **SIGSEGV(exit 139)로 죽음** — `%n` 의 메모리 쓰기가 실제로 일어난 것임.
**판정에는 영향 없음**을 해설에 명시함 — 1-17 정탐 근거는 「외부입력이 포맷 문자열 인자에 도달하는가」이고 `strftime(buf, sizeof(buf), user_fmt, tm_now)` 한 줄에서 이미 성립함.

### ③ 지적했다가 스스로 반증해 철회한 것
- **「문제 20 의 정규식 `[*()\\\\&\|!=<>~+,;\"]` 은 `&&` 교집합·`\"` 미지원으로 컴파일 실패 또는 오동작」** → 철회. OpenJDK 24 실측: 정상 컴파일, 입력 `a*b(c)d\e&f\|g!h=i<j>k~l+m,n;o"p` → 출력 `abcdefghijklmnop` 으로 **대상 15문자 전부 제거.** 문자클래스 안에서 `*`·`|`·`+` 는 리터럴이고 단일 `&` 도 리터럴임. 진짜 오탐.
- **「문제 9 는 상한 검사가 없어 `new String[2000000000]` 이 통과하므로 정탐」** → 철회. 제3장 1-14 안전예제가 **음수 검사만** 둔 형태 그대로이고, 파일에 이미 그 유보가 ⚠️ 로 달려 있음. 채점 기준(가이드)에서는 오탐.
- **「문제 3 의 `${SESSION_BOARD_TOKEN}` 은 세션 스코프를 못 찾음」** → 철회. JSP EL 의 기본 스코프 탐색이 page→request→session→application 이므로 세션 속성이 해석됨. 제3장 1-11 안전예제도 동일 형태.

### ④ 의심이 남지만 못 고친 것 — 없음

## 3. 파일 3 — 보안기능 (2-1~2-8), 16문항

### ① 지적한 것
1. **문제 6(오탐) 「권한 회수 후 소유자 한정 부여」가 실제로 최소권한을 만드는지 미검증** — 오탐 문항의 핵심이라 흉내인지 실동작인지 확인이 필요했음.
2. **문제 7(오탐) 에 `doFinal` 없이 `update` 만 있는 미완성 코드가 섞여 판단이 갈릴 소지** — 학습자가 여기를 근거로 정탐을 쓸 위험.
3. **문제 10(오탐) 의 `insert` 컬럼 목록에 `regno`(주민등록번호)가 있어 「주민번호 평문 저장 → 2-5 정탐」으로 오독될 소지.**
4. **문제 11(오탐) 은 환경변수 값이 Base64(암호화 아님)인데, 제3장 2-6 오탐 판단 문장은 「외부 공간에 «암호화하여» 보관」을 요구함** — 근거 문장과 코드 사이에 틈이 있음.
5. **자가채점 절과 정답 분포 줄이 아예 없음** — 파일 1·2 에는 있고 이 파일만 없어 채점 기준이 문서 안에 없었음.

### ② 고친 것

| 위치 | 전 | 후 |
|---|---|---|
| 해설 6 | 근거 서술만 | ✅ **실측 줄 추가** — `0777` 파일에 다섯 줄 실행 → `-rw------- (600)`. + ⚠️ 「가이드 원문은 인자 하나짜리 `setReadable(true)` 형태이나 같은 대책임」 |
| 해설 7 | (경고 없음) | ⚠️ 「`doFinal` 없이 `update` 만인 것은 **기능 결함이지 2-4 가 아님**. 가이드 원문 안전예제도 `c.update(msg)` 로 끝남. 2-4 의 판정 축은 오직 알고리즘 이름」 |
| 해설 10 | (경고 없음) | ⚠️ 「`regno` 를 근거로 정탐을 쓰지 말 것 — 바인딩 코드가 생략된 발췌라 **「관측 없음」이지 약점 관측이 아님**. 가이드 원문도 동일하게 앞 2개만 바인딩」 |
| 해설 11 | (경고 없음) | ⚠️ 「Base64 는 전송 표현일 뿐 — 2-6 의 판정 축은 **키가 소스에 상수로 있는가**」 + `[가정]` 「제3장 문장은 엄밀히 환경변수 값의 암호화까지 요구하므로, 답안에 「운영에서는 환경변수 값도 암호화 보관」 한 줄을 덧붙이면 양쪽 충족」 |
| 오답 정리 끝줄 | 「오탐 8개는 함정 없이 작성됨」(근거 없는 단언) | **재검증 사실로 교체** — 「1·4·6·7·10·11·14·15 를 하나씩 재검증했고, 실행 확인이 필요했던 6번은 리눅스에서 `600` 실측」 |
| 문서 끝 | (없음) | **자가채점 절 신설** — 만점 40점 / 목표 28점, 정답 분포 `오·정·정·오·정·오·오·정·정·오·오·정·정·오·오·정` |

### ③ 지적했다가 스스로 반증해 철회한 것
- **「문제 6 은 `setReadable(false,false)` 가 플랫폼에 따라 실패해 가짜 오탐」** → 철회. 리눅스 실측에서 `777 → 600` 확인.
- **「문제 15 의 `secureRandom.setSeed(...)` 는 setSeed 호출 자체가 시드 고정이므로 정탐」** → 철회. 제3장 2-8 안전예제가 **정확히 이 코드**이며(수험서 1361~1370행), 판정 축은 「넣는 값이 상수인가」임. 파일의 「오답 정리」가 이미 이 함정을 정확히 서술하고 있었음.
- **「문제 15 의 `new Random()` 배너 선택은 난수 용도가 보안결정이므로 정탐」** → 철회. 제3장 2-8 오탐 판단 원문이 「**보안결정이 아닌 용도로** 매번 변경되는 시드의 Random 을 쓰는 경우」를 오탐으로 명시함.
- **「문제 12 는 `USER = "APPUSR"` 도 하드코딩이라 해설이 불완전」** → 철회. 제3장 2-6 안전예제도 `USER` 상수는 **그대로 남겨 둠**. 해설이 「`USER`·`URL` 상수 자체는 쟁점이 아니고 패스워드 상수가 결함」이라고 이미 정확히 구분해 뒀음.

### ④ 의심이 남지만 못 고친 것 — 없음

## 4. 파일 7 — 코드 작성형, 20문항

Java 16문항 전량을 **스텁 포함 단일 컴파일 단위로 묶어 `javac` 통과 확인**, C 4문항을 **Kali gcc `-Wall -Wextra` 경고 0 + 실행 확인**함.

### ① 지적한 것
1. ⛔ **문제 20 모범 코드가 컴파일되지 않음** — 가장 중대. 아래 ②에 실측 원문.
2. **머리말의 「모범 코드는 실제로 컴파일·실행해 확인한 것임」이 1번 때문에 사실과 다름.**
3. **문제 3 모범 코드가 요구사항을 절반만 만족** — 취약 소스의 출력 지점이 `<%=keyword%>`(HTML 본문)와 `document.write(...)`(DOM) **두 곳**인데, 모범 코드는 앞의 하나만 고치고 뒤는 통째로 사라짐. 대신 취약 소스에 없는 `<c:out value="${m.content}"/>` 한 줄이 들어가 있었음.
4. **문제 17 모범 코드가 문항이 요구하지 않은 곳을 바꿈** — 문항의 `FileCopyUtils.copy(in, out)` 을 바이트 루프로 교체. 요구사항은 「`finally` 로 자원 해제」 하나이고, 제3장 5-2 안전예제도 `FileCopyUtils` 를 유지함.

6. **문제 8 모범 코드의 `sizeof(cv_struct.x) - 1` 이 가이드 원문(`sizeof(cv_struct.x)`, `-1` 없음)과 다름** — 둘 다 정답인데 표시가 없음.
7. **문제 6 채점 키워드에 「web document root 밖 저장」이 있으나 모범 코드에 그 표시가 없음.**
8. **문제 10 의 `gets_s` 유보가 `[가정]` 으로 남아 있었음** — 실행 확인이 가능한 사안.

### ② 고친 것

**⛔ 문제 20 — 컴파일 실패 실측 (JDK 24)**

```

            this.userRoles[i] = userRoles[i].clone();
                                            ^
T1.java:8: error: incompatible types: Object cannot be converted to UserRole

                                                  ^

```

**모범 코드 본문은 바꾸지 않음** — 제3장 6-4 안전예제와 글자 그대로 같고(수험서 2293~2301행), 채점은 `clone()` 키워드 기준이며 원소 클래스 정의는 문항에 주어지지 않기 때문임. 대신 **전제 코드를 해설에 실어 컴파일 가능한 형태로 닫음**:

```java
class UserRole implements Cloneable {
    @Override
    public UserRole clone() {                   // public + 공변 반환형
        try { return (UserRole) super.clone(); }
        catch (CloneNotSupportedException e) { throw new AssertionError(e); }
    }
}
```
이 전제를 붙이면 컴파일·실행 통과함(실측). 「시험 답안에는 굳이 쓰지 않아도 됨」을 함께 명시함.

### ③ 지적했다가 스스로 반증해 철회한 것
- **「문제 7 의 범위 위반 `IllegalArgumentException` 이 아래 `catch (NumberFormatException)` 에 잡혀 삼켜짐」** → 철회. `NumberFormatException` 은 `IllegalArgumentException` 의 **하위** 클래스이므로 상위 예외를 잡지 못함. 범위 예외는 정상 전파됨(컴파일·논리 모두 확인).
- **「문제 16 의 `catch (MalformedURLException)` 은 try 에서 발생 불가능해 컴파일 오류」** → 철회. `MalformedURLException` 이 `IOException` 의 하위이고 `url.openStream()` 이 `IOException` 을 던지므로 적법함. 실제로 컴파일 통과.
- **「문제 12 의 `String.format("%02x", key[i])` 는 `byte` 가 음수일 때 `ffffffxx` 로 8자리가 됨」** → 철회. 자바 `Formatter` 가 `Byte` 를 `'x'` 변환할 때 `1L << 8` 을 더해 마스킹함. 실측 `String.format("%02x", (byte)-1)` → `ff`.
- **「문제 13 이 `md.update(salt)` → `md.update(password)` 순서라 가이드(패스워드 먼저)와 반대」** → 철회. 파일 3 문제 10(제3장 2-5 안전예제)이 **솔트 먼저** 순서를 씀. 가이드 안에 두 순서가 다 있고, 채점 키워드는 「함께 해쉬 입력」이라 순서 무관.
- **「문제 18 이 `AutoCloseable` 키워드를 코드에서 보여주지 않아 키워드 미충족」** → 철회. 키워드는 답안 텍스트 기준이고 해설 산문에 설명이 있음.

### ④ 의심이 남지만 못 고친 것
- **문제 9 모범 코드에 `#include <stdlib.h>` 가 없어 `atoi` 가 암시적 선언 경고를 냄**(실측: `implicit declaration of function 'atoi'`). 다만 **문항의 취약 소스도 헤더가 없는 함수 단위 발췌**이고, 시험 답안은 고친 함수만 쓰는 형식이라 **가감이 오히려 노이즈**로 판단해 두지 않음. 실제 컴파일 시에는 필요함.

## 5. 의심이 남지만 확신이 없어 고치지 않은 것

**파일 1 문제 17 — XQuery 파라미터 바인딩이 실제로 성립하는가**

```java
String es = "doc('members.xml')/memberlist/member[mname='$xmname']";
XQPreparedExpression expr = conn.prepareExpression(es);
expr.bindString(new QName("xmname"), mname, null);
```

- **의심 내용** — XQuery 에서 `'$xmname'` 은 **작은따옴표 안이라 문자열 리터럴**이지 변수 참조가 아님. 변수로 쓰려면 따옴표 없는 `$xmname` 이어야 하고, XQJ `bindString` 은 쿼리에 선언되지 않은 외부 변수를 바인딩할 때 `XQException` 을 던지는 것이 규격임. 즉 이 코드는 **런타임에 예외로 죽거나, 바인딩이 무시되고 문자열 `$xmname` 으로 검색될** 가능성이 있음.
- **고치지 않은 이유 세 가지** — ⓐ **제3장 1-9 안전예제(수험서 674~681행)가 글자 그대로 같은 형태**임(`user[uname='$xname']` + `bindString(new QName("xname"), ...)`). 즉 오류가 있다면 **가이드 원문의 오류를 그대로 상속한 것**이고, 채점은 가이드 기준임. ⓑ XQJ 구현체(Saxon 등)를 이 환경에 설치해 **실행 확인을 하지 못했음** — 부재를 근거로 「틀렸다」고 단정하지 않는다는 규율에 걸림. ⓒ **판정(오탐)은 어느 쪽이든 바뀌지 않음** — 바인딩이 되면 구조 변경 불가라 오탐이고, 바인딩이 실패해 예외가 나도 외부입력이 구문에 연결되지 않으므로 역시 1-9 오탐임.
- **등급** — `근거부족`. 파일 1-5(`replaceAll("|","")`)처럼 **실행으로 반증한 사안이 아니므로 유보 주석을 달지 않았음.** 실측 없이 유보를 달면 확정된 실측 유보(1-5·1-9)와 신뢰도가 섞임.

## 7. 검증 방법 기록

- **오탐 32문항 전수 추적** — 각 문항의 「대응책 코드 → 실제 사용 지점」 데이터 흐름을 손으로 따라가, 검증값과 사용값이 같은 변수인지 / 검사 결과가 분기에 쓰이는지 / 필터 정규식이 대상 문자를 실제로 잡는지 셋을 확인함.
- **실행 검증한 것**(총 9건) — ① 파일1 Q6 경로순회 제거 ② 파일1 Q9 파이프 잔존(재확인) ③ 파일1 Q20 XPath 필터 ④ 파일2 Q2 화이트리스트 정규식 ⑤ 파일2 Q20 LDAP 필터 ⑥ 파일2 Q17 strftime→printf 지시자 생존 + SIGSEGV ⑦ 파일3 Q6 파일권한 `777→600` ⑧ 파일7 Java 16문항 일괄 컴파일 ⑨ 파일7 C 4문항 컴파일·실행 + `gets_s` 부재.
- **키워드 대조** — 83문항의 `[채점 키워드]` 를 제3장 해당 항목의 「보안대책」·「정탐/오탐 판단」 문장과 1:1 대조함. **지어낸 용어가 없어 교체 0건.** 「경로순회 문자열(`. / \`)」·「멀티라인·리다이렉트 특수문자」·「사전 정의된 리스트에서 선택」·「web document root」·「검증필 암호모듈」·「ACL(접근제어목록)」·「%s 지정 후 2번째 파라미터」 등이 모두 원문 표현임.
- **정직성 점검** — 네 파일 전부 머리말에 「기출문제가 아님」 고지가 있고, 응시자 기억 기반 복원을 인용하는 곳마다 「공식 확인된 것이 아님」이 붙어 있음. 지어낸 통계·수치 없음. 근거 없는 대응책을 표준으로 서술한 곳 없음. **정직성 관련 정정 0건.**
