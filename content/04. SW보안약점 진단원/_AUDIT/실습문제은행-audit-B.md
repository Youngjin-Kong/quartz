## 0. 총평 — 극성 뒤집기는 0건

**우선순위 ① (오탐 문항이 진짜 오탐인가)에서 뒤집을 문항이 하나도 없었음.** 파일 4 오탐 8문항, 파일 5 오탐 15문항 전부 대책이 «흉내»가 아니라 실제로 동작하는 형태였음. 지시받은 위험 목록(3-1 동기화 블록 분리 / 4-3 빈 catch / 5-2 finally 밖 close / 5-1 다른 참조 역참조 / 6-3 얕은 복사 / 6-4 레퍼런스 저장 / 2-14 고정 솔트 / 2-16 잠금 없음)을 하나씩 대조했고 **해당하는 함정 문항은 전부 이미 「정탐」으로 배치**돼 있었음.

정정은 전부 **해설의 사실관계·주변 서술·메타 규칙** 층에서 나왔고, 그중 하나(파일 4 문항 3)는 **근거 문서를 그대로 옮겼는데도 기술적으로 거짓인** 사례임.

## 1. 파일 4 — 보안기능 (2-9 ~ 2-16), 16문항

### ① 지적한 것 / ② 고친 것

| # | 지적 | 전 → 후 |
|---|---|---|
| 해설 3 | **`new JarFile(f)` 의 verify 기본값이 `false` 라는 서술이 사실과 다름** | 「(기본값 verify=false)」 삭제 → 실제 약점을 「`getCodeSigners()` 부재」로 정정 + JDK 소스 실측 근거를 `⚠️ 실측 보정` 인용으로 명시 |
| 문항 16 코드 | `} catch (IOException e) { }` — **빈 catch 가 4-2(오류 상황 대응 부재) 약점을 섞음.** 2-16 오탐 문항인데 파일 5 문제 9(빈 catch=정탐)와 정면으로 충돌해 판단이 갈림 | `logger.error("ERROR-51: 인증 서버 연결 실패");` 추가 |
| 문항 16 주석 | 「복원된 1차 시험이 **변수명까지 동일하게** 냈다」 — 복원 기록과 불일치 | 단정 삭제 → 복원본의 `counts`/`if` 와 다르다는 사실을 명시하고 「네 요소만 갖추면 됨」으로 대체 |
| 해설 14 | 「**원격 경로**의 클래스를」 — 코드는 `new URL("file:plugins/")` 로 로컬 경로임 | 「외부에서 받아 둔 경로(`file:plugins/`)의 클래스를」 |

**해설 3 정정의 근거(실측)**

```
$ unzip -p "C:\Program Files\Java\jdk-24\lib\src.zip" java.base/java/util/jar/JarFile.java
275:    public JarFile(File file) throws IOException {
276-        this(file, true, ZipFile.OPEN_READ);
277-    }
```

`verify` 기본값은 **`true`** 임. 「기본값이 false 라 검증이 꺼진다」는 서술은 반증됨. 이 문항이 정탐인 «진짜» 이유는 ⓐ 서명이 없는 JAR 은 검증 대상 자체가 없어 무조건 통과하고 ⓑ `getCodeSigners()` 로 **서명 주체를 확인하지 않음**임. 단 `new JarFile(f, true)` 는 근거 문서가 대책으로 제시한 표기이므로 **답안 키워드는 그대로 유지**함 — 채점은 가이드 문장을 따르므로 표기를 바꾸면 손해임.

### ③ 지적했다가 철회한 것

- **문항 2 정규식이 「특수문자 필수」를 강제하지 않는다 → 오탐 근거가 약하다** — 철회. 실행 확인 결과 `[0-9@#$%]` 는 숫자·특수문자를 **택일**로 받는 것이 맞으나, 이것이 **근거 문서 2-9 「안전」 예제 원문 그대로**이고 채점 기준도 그 원문임. 문항의 잘못이 아니라 가이드의 설계임
  ```
  "abcdefghi"(9) -> false   "abcdefgh1"(9) -> true   "abcdefgh!"(9) -> false
  "Passw0rd"(8)  -> false   "Passw0rd!"(9) -> true   "abcdefgh@"(9) -> true
  ```
- **문항 4 가 `targetPath` 와 다른 엔트리는 검증 없이 통과시킨다 → 사실상 정탐** — 철회. 근거 문서 2-10 「안전」 예제의 구조가 정확히 그러하고, 문항은 거기에 `isTrustedSigner` 거부 경로를 **추가**해 원문보다 오히려 강함
- **문항 11 `SecureRandom.getInstanceStrong()` 이 솔트를 해쉬 입력에 넣지 않았을 가능성** — 철회. 실행 확인, `md.update(pw)` 뒤 `md.update(salt)` 로 해쉬값이 실제로 달라짐(`salt 반영? true`)

### ④ 의심이 남지만 못 고친 것

- 문항 14 는 근거 문서 2-15 「취약」 예제를 옮긴 것인데, **원문 자체가 `file:subdir/`(로컬 경로)를 「원격 다운로드」라고 서술**함. 해설 문구만 정정했고 코드는 원문 유지 — 시험이 원문을 낼 가능성이 더 크기 때문임

### ③ 지적했다가 철회한 것

- **문제 22(6-1 오탐)는 `private final SettlementDao dao;` 라는 멤버 필드를 가지므로 근거 문서의 「멤버 필드를 선언하지 않고」에 어긋난다** — 철회. 근거 문서 6-1 「오탐」 정의가 「해당 값이 지역변수·세션변수로 선언되어 **스레드 간 공유가 발생하지 않는 경우**」로, 금지 대상은 「**요청별 정보**를 저장하는 멤버 필드」임. 상태 없는 의존 객체는 대상이 아니며 해설이 이미 그렇게 서술함. 다만 §5 에 잔여 위험으로 남김
- **문제 30(7-1 오탐)이 사실상 근거 문서의 「안전」 예제인데 `(재구성)` 으로 잘못 표시됨** — 철회. 문서 머리말이 「원문 표시는 항목마다 정확히 1문항」으로 규정했고 7-1 의 그 자리는 문제 31(취약 원문)임. 규칙 위반이 아님
- **문제 21 의 `public Set<String> allowed;` 가 public 가변 필드라 캡슐화 약점을 섞음** — 철회(문항 잘못 아님). 근거 문서 5-5 「안전」 예제가 `public Set<String> whitelist;` 로 **원문이 그러함.** §5 에 근거 문서 쪽 문제로 기록

## 3. 파일 6 — 복합서술형 12세트

### ④ 「심은 결함」이 「개발가이드 발췌」로 판정 가능한가 — 세트별 전수 대조

**가이드 근거 없는 지적: 0건.** 12세트 34개 지적 전부가 해당 세트 개발가이드 발췌의 문장 하나로 판정 가능함.
**모범답안이 놓친 결함: 0건**(단, 아래 세트 5 의 「가이드 범위 밖 약점」 1건은 별개 — 지적해도 감점이 아니라 무배점임).

### ① 지적한 것 / ② 고친 것

| 세트 | 지적 | 전 → 후 |
|---|---|---|
| 2 | 모범답안이 「DB 질의를 PreparedStatement 로 바인딩하는 점은 **가이드를 준수**한다」고 쓰는데 **그 규칙이 개발가이드 발췌에 없음.** 준수 판정의 근거가 없는 상태 | 개발가이드 발췌 끝에 「DB 질의는 PreparedStatement 로 바인딩한다.」 추가(세트 8 발췌에는 이미 있던 문장) |
| 5 | 소스의 `sha256(pw)` 가 **솔트 없는 해쉬(2-14)**인데 개발가이드 발췌에 해당 규칙이 없어 채점 불가. 성실한 응시자가 4번째 결함으로 적고 시간을 태울 위험 | 모범답안에 「가이드 발췌 범위 밖 — 지적해도 감점 없으나 배점도 없음」 주석 추가 |
| 7 | 문서가 두 곳에서 「**세트마다 준수 항목이 1개 이상** 섞여 있음」이라 단언하는데 **세트 7 은 소스 전체가 결함이라 준수 항목이 0개**임. 응시자가 없는 준수 항목을 찾느라 시간을 쓰거나, 결함 하나를 준수로 오판할 위험 | 두 곳 모두 「세트 7 을 뺀 열한 세트」로 정정 + 세트 7 모범답안에 명시 |

### 모범답안의 기술적 주장 — 실행으로 확인함

세트 10 ②·세트 7 ② 의 우회 주장은 실제로 성립함:

```
  ....//etc/passwd  ->  ../etc/passwd      (replaceAll("\.\./","") 1회 치환이 되살림)
  ..\..\win.ini     ->  ..\..\win.ini      (역슬래시는 걸러지지 않음)
  "//evil.com".startsWith("/") = true      (프로토콜 상대 URL 이 접두 검사를 통과)
```

### ③ 지적했다가 철회한 것

- **세트 1 — `MultipartRequest` 생성자가 MIME 검사 «전에» 파일을 디스크에 이미 기록하므로 「검증 전 저장」이 별도 결함인데 모범답안이 놓쳤다** — 철회하지 않고 **§5 의심**으로 남김. 개발가이드 발췌에 「저장 전에 검증한다」는 문장이 없어 **판정 근거가 없고**, 모범답안 ① 이 「위조하면 …저장된다」로 결과를 이미 서술함
- **세트 3 — `resetPw` 에 인증(세션) 검사도 없으므로 결함이 3개다** — 철회. 모범답안 ② 의 「요청 사용자의 작업 권한 확인이 전혀 없어 **비인증 사용자도**」가 인증 부재를 이미 포함함
- **세트 4 — 쿠키에 `HttpOnly` 가 없으므로 결함이 4개다** — 철회. 개발가이드 발췌가 요구한 것은 **Secure 속성뿐**임. 없는 규칙으로 지적하면 그 자체가 감점 대상이므로 모범답안이 옳음

### ④ 검산

`(가이드 원문 예제 기준)` 8세트(1,2,3,5,7,9,10,12) / `(재구성)` 4세트(4,6,8,11) — 머리말 주장과 일치 ✅. 총점 12×8 = 96점 ✅.

### ⑤ 파트 B 발췌문이 자연스러운가 — **「보안을 고려하지 않는다」식 문장 0건**

다섯 발췌 모두 **업무상 합리화 어투**로 결함을 심었고 대놓고 쓴 곳이 없음. 실제 설계서에서 나올 법한 형태임.

| 문항 | 결함을 심은 방식 |
|---|---|
| 21 | 「운영 편의를 위해 DBA 권한을 부여한다」 — 편의 명분 |
| 22 | 「장애 분석을 위해 `printf` 로 그대로 출력」 — 운영 명분 |
| 23 | 「민원 업무 편의를 위해 별도로 제한하지 않는다」 — 업무 명분 |
| 24 | 「연속 실패 횟수는 **로그인 화면의 자바스크립트 변수**에 누적」 — 구현 위치만 서술, 판정은 응시자 몫 |
| 25 | 「업무 특성상 화면을 장시간 열어두는 경우가 많으므로」 — 사용성 명분 |

### ③ 지적했다가 철회한 것

- **문항 23 이 「`/webapps/minwon/upload/` 는 web document root 내부」라 단정하는데 근거가 없다** — 철회. Tomcat 계열에서 `webapps/<앱>/` 이 컨텍스트 루트라는 것은 표준 배치이고, 발췌가 「민원 첨부파일 등록·조회」 웹 모듈임을 명시함
- **문항 22 의 「length 가 부호 있는 2바이트여서 음수·정수형 오버플로우」가 과장이다** — 철회. 부호 있는 16비트는 음수를 담을 수 있고 그 값이 `size_t` 로 확장되면 거대한 길이가 되므로 서술이 정확함

### ④ 검산

자가채점 기록표 25행의 「키워드 수」를 각 해설의 `[채점 키워드]` 개수와 전건 대조 — 문항 10(위에서 정정) 외 **24행 일치** ✅.
