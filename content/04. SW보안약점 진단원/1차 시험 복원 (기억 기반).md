## 2. 이 복원에서 «새로 드러난» 것 — 기존 훈련의 공백

### 공백 1. 「코드·정규식을 직접 작성」 문항이 존재함

복원 #4(정규식 작성) · #5(카운터 제한 코딩) · #10(exception 작성) — **최소 3문항.**
기존 `실습 집중 특훈 세트.md`는 전 문항이 「정탐/오탐 판단 + 사유 서술」 하나뿐이라 이 유형을 **한 번도 훈련시키지 않음.** 판단·서술이 되더라도 **빈 종이에 안전한 코드를 써내는 것은 별개 능력**임.

### 공백 2. 실습시험에 「설계단계 대응방안 서술」이 나옴

복원 #3(DBMS 설계) · #7(메모리 버퍼 오버플로우 설계 고려사항) · #16(세션 대응방안) — **최소 3문항.**
기존 플랜은 설계단계 20항목을 **이론시험 대비**로만 배치했고, 실습 훈련은 구현단계 코드 정오탐에 한정함. 실제로는 **실습에서 설계 기준의 「설명·대응방법」을 문장으로 써야 함.**

### 공백 3. XML 계열 편중

복원 #9 · #11(XInclude) · #12(XPath) — **XML 계열만 3문항.** 여기에 #13 LDAP 필터까지 더하면 삽입 계열 파서류가 4문항. 기존 재고는 XML 관련 2문항(XXE 오탐 1 · 해설 1)뿐임.

### 공백 4. C 계열 비중이 기존 재고보다 큼

복원 #1(포맷스트링) · #2(fork/vfork, gets/fgets) · #19(정수형 오버플로우) · #20(메모리 오버플로우) — **4문항이 C 계열.** 기존 정탐/오탐 15문항은 **전부 Java**였음.

## 4. 결정적 발견 — 시험은 「가이드 원문 코드 예제」를 거의 그대로 냄

복원 항목을 `SW보안약점 진단원 통합 수험서.md` 제3장(=「소프트웨어 개발보안 가이드」 2021.12 예제)과 대조한 결과 **8건이 원문 예제로 특정됨.**

| 복원 기억 | 가이드 원문 | 판정 |
|---|---|---|
| src 특수문자 정규식 | 1-2 안전코드 `src.matches("[ \w]*")` + 특수문자 시 `IllegalArgumentException` | 일치 |
| `counts` / `MAX_ATTEMPTS` | 2-16 `MAX_ATTEMPTS = 5`, `while (result == FAIL && count < MAX_ATTEMPTS)` | **변수명까지 일치** |
| `kisaDB.bat` (DOS) | 1-5 `cmd.exe /c backuplog.bat` | **파일명만 교체** |
| 그레고리안 데이트핸들러 포맷스트링 | 1-17 `Calendar.getInstance()`(= GregorianCalendar) + `%1$tY`/`%1$terd` 날짜 노출 | 일치 |
| JarFile 검증 | **2-10** `new JarFile(f)` → `new JarFile(f, true)` + `getCodeSigners()` | 일치 |
| exception 작성 | 4-3 `catch (Exception e)` → `MalformedURLException`/`IOException`/`ParseException` 3단 세분화 | 일치 |
| `gets` vs `fgets` | 7-2 금지 함수 → `gets_s()`/`fgets()` 등 안전 대체 함수 | 일치 |
| XInclude | 1-8 XXE 대책 묶음에 `setXIncludeAware(false)` 포함 | 분류는 **XXE(1-8)** — 단 아래 정정 참조 |

### 이 발견이 바꾸는 것

- **최고효율 학습법 = 제3장 49항목의 「취약 코드 ↔ 안전 코드」 쌍을 통째로 체화하는 것.** 개념을 아는 것으로는 부족하고, **안전 코드가 곧 코드작성형 문항의 모범답안**임
- 변형은 **식별자 수준**(`backuplog.bat` → `kisaDB.bat`)에 그침 → 원문을 알면 변형을 알아봄
- 반대로 원문을 모르면 **개념을 알아도 백지에 못 씀** — 1차 실습 실패의 유력한 기전임

### 정정 이력 (초판 대비)

- #4 정규식 작성: 초판 「1-4 XSS」 → **1-2 코드 삽입**. 근거 — `src`·정규식·특수문자 예외가 모두 1-2 원문 예제에 있고, 1-4 XSS 절에는 `src`도 정규식도 없음
- #11 XInclude: 초판 「1-9 / 1-8 계열」 → **1-8 XXE 확정**. 근거 — `setXIncludeAware(false)`가 1-8 대책에 명시됨
- ⛔ **#11의 「XInclude 함정」 서술 철회(2026-08-28).** 초판은 「DOCTYPE 금지만 있고 `setXIncludeAware(false)`가 없으면 정탐」이라 적었으나 **성립하지 않음** — `setXIncludeAware()`는 **기본값이 false**라 호출하지 않아도 `xi:include`가 처리되지 않음. XInclude 동작에는 `setXIncludeAware(true)` + `setNamespaceAware(true)`가 둘 다 필요함. 정탐의 근거는 **DOCTYPE 금지·외부 엔티티 비활성화의 부재**임
- ⛔ **#23 매핑 오류 정정(2026-08-28).** 초판 「2-15 무결성 검사 없는 코드 다운로드」 → **2-10 부적절한 전자서명 확인**. 근거 — `JarFile`·`getCodeSigners()` 코드는 2-10 절에 있고, 2-15 절의 예제는 `URLClassLoader`임
- ⚠️ 여전히 미특정: `fork` vs `vfork` — 수험서 제3장에 없음. 가이드 원문 C 계열 취약한 API에 있을 가능성 `[가정]`
