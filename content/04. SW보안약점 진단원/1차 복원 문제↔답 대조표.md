# 1차 복원 문제↔답 대조표

> **용도**: [[1차 시험 복원 (기억 기반)]] §4에서 확인된 대로 **시험은 가이드 원문 코드 예제를 식별자 수준만 바꿔 출제함.** 따라서 왼쪽(취약 코드)을 보고 오른쪽(안전 코드)을 **손으로 재현**할 수 있으면 정오탐·서술·코드작성 세 유형이 동시에 커버됨.
>
> **코드는 `SW보안약점 진단원 통합 수험서.md` 제3장에서 «자동 추출»했으므로 원문과 일치함**(옮겨 적기 오류 없음). 주석도 원문 그대로임.
>
> **사용법**: 안전 코드를 가리고 취약 코드만 본 뒤 ① 보안약점 명칭 ② 정탐/오탐 ③ 사유(채점 키워드 포함) ④ 안전 코드를 볼펜으로 작성. 채점은 **키워드 단어 자체**의 포함 여부로 함.

⚠️ 「복원 #」은 응시자 기억 기반이며 공식 기출이 아님. 출제 «가중치와 유형»의 근거로만 쓸 것.

## SQL 삽입

`복원 #8` · 수험서 1-1. SQL 삽입

### 문제 (취약)

```java
String gubun = request.getParameter("gubun");
// 외부로부터 입력받은 값을 검증 없이 쿼리 생성에 사용
String sql = "SELECT * FROM board WHERE b_gubun = '" + gubun + "'";
Connection con = db.getConnection();
Statement stmt = con.createStatement();
// 검증 또는 처리 없이 쿼리로 수행되어 안전하지 않다.
ResultSet rs = stmt.executeQuery(sql);
```

### 답 (안전)

```java
String gubun = request.getParameter("gubun");
// PreparedStatement 사용을 위해 ?문자로 바인딩 변수를 사용한다.
String sql = "SELECT * FROM board WHERE b_gubun = ?";
Connection con = db.getConnection();
PreparedStatement pstmt = con.prepareStatement(sql);
// 파라미터 부분을 setString 등의 메소드로 설정하여 안전하다.
pstmt.setString(1, gubun);
ResultSet rs = pstmt.executeQuery();
```

**채점 키워드: 외부입력 / 검증 없이 / 동적 질의문 구조 변경 / PreparedStatement 바인딩**

⚠️ **복원 #8은 이 원문의 「오탐 변형」**임 — `request.getParameter`가 빠지고 상수로만 조립된 형태로 출제됨. 그 경우 `Statement`를 써도 **오탐**임. 「PreparedStatement 미사용 = 정탐」으로 답하면 0점.

## 코드 삽입 — 정규식 작성

`복원 #4` · 수험서 1-2. 코드 삽입

### 문제 (취약)

```java
@RequestMapping(value = "/execute", method = RequestMethod.GET)
public String execute(@RequestParam("src") String src) throws ScriptException {
    ScriptEngineManager scriptEngineManager = new ScriptEngineManager();
    ScriptEngine scriptEngine = scriptEngineManager.getEngineByName("javascript");
    // 외부 입력값인 src를 javascript eval 함수로 실행하고 있어 안전하지 않다.
    String retValue = (String) scriptEngine.eval(src);
    return retValue;
}
```

### 답 (안전)

```java
@RequestMapping(value = "/execute", method = RequestMethod.GET)
public String execute(@RequestParam("src") String src) throws ScriptException {
    // 정규식을 이용하여 특수문자 입력시 예외를 발생시킨다.
    if (src.matches("[ \\w]*") == false) {
        throw new IllegalArgumentException();
    }
    ScriptEngineManager scriptEngineManager = new ScriptEngineManager();
    ScriptEngine scriptEngine = scriptEngineManager.getEngineByName("javascript");
    String retValue = (String) scriptEngine.eval(src);
    return retValue;
}
```

**채점 키워드: 화이트리스트 / 정규식 / 특수문자 차단(예외 발생) / 동적 코드 실행 함수**

**코드 작성형으로 출제됨.** `matches()`는 문자열 «전체» 일치라 부분 우회가 안 됨(`find()`였으면 뚫림). 블랙리스트(`contains(";")`)로 쓰면 방향이 반대라 감점.

## 운영체제 명령어 삽입

```java
// 외부로부터 입력받은 값을 검증 없이 사용할 경우 안전하지 않다.
```

### 답 (안전)

```java
String date = request.getParameter("date");

date = date.replaceAll(";", "");
date = date.replaceAll("&", "");
date = date.replaceAll(":", "");
date = date.replaceAll(">", "");
Runtime.getRuntime().exec(command + date);
```

```java
String bn = request.getParameter("gubun");
// 외부로부터 입력받은 URL이 검증 없이 다른 사이트로 이동이 가능하여 안전하지 않다.

......

    response.sendRedirect(rd);
    return;

```

### 답 (안전)

```java
// 이동할 수 있는 URL 범위를 제한하여 피싱 사이트 등으로 이동하지 못하도록 한다.
String allowedUrl[] = { "/main.do", "/login.jsp", "list.do" };
String rd = request.getParameter("redirect");
try {
    rd = allowedUrl[Integer.parseInt(rd)];
} catch (NumberFormatException e) {

```

**채점 키워드: 외부입력 URL / 검증 없이 / 화이트리스트(인덱스 선택) / 피싱 사이트 이동**

## XXE — XInclude 함정

`복원 #11` · 수험서 1-8. 부적절한 XML 외부 개체 참조

### 문제 (취약)

```java
// receivedXml 예: <!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]><foo>&xxe;</foo>
JAXBContext jaxbContext = JAXBContext.newInstance(Student.class);
Unmarshaller jaxbUnmarshaller = jaxbContext.createUnmarshaller();
DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
dbf.setNamespaceAware(true);
DocumentBuilder db = dbf.newDocumentBuilder();
Document document = db.parse(receivedXml);
// 외부 엔티티로 만들어진 document를 이용하여 마샬링을 수행하여 안전하지 않다.
Student employee = (Student) jaxbUnmarshaller.unmarshal(document);
```

### 답 (안전)

```java
DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
// XML 파서가 doctype을 정의하지 못하도록 설정한다.
dbf.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
// 외부 일반 엔티티를 포함하지 않도록 설정한다.
dbf.setFeature("http://xml.org/sax/features/external-general-entities", false);
// 외부 파라미터도 포함하지 않도록 설정한다.
dbf.setFeature("http://xml.org/sax/features/external-parameter-entities", false);
// 외부 DTD를 비활성화한다.
dbf.setFeature("http://apache.org/xml/features/nonvalidating/load-external-dtd", false);
dbf.setXIncludeAware(false);
dbf.setExpandEntityReferences(false);
DocumentBuilder db = dbf.newDocumentBuilder();
Document document = db.parse(receivedXml);
Model model = (Model) u.unmarshal(document);
```

**채점 키워드: 외부 엔티티 비활성화 / DOCTYPE 선언 금지 / setXIncludeAware(false)**

⚠️ **정정(2026-08-28).** 초판은 「DOCTYPE 금지만 있고 `setXIncludeAware(false)`가 없으면 정탐」이라 적었으나 **성립하지 않음.** `DocumentBuilderFactory.setXIncludeAware()`는 **기본값이 false**라 호출하지 않아도 `xi:include`가 처리되지 않음. XInclude가 실제로 동작하려면 `setXIncludeAware(true)`와 `setNamespaceAware(true)`가 **둘 다** 있어야 함.

→ 올바른 이해: 위 6줄은 **가이드가 권고하는 심층방어 설정 묶음**이며, `setXIncludeAware(false)`는 «다른 계층이 켰을 경우를 대비한 명시적 차단»임. **정탐의 근거는 앞의 3줄(DOCTYPE 금지·외부 일반/파라미터 엔티티 비활성화)이 없는 것**이지 XInclude 줄의 부재가 아님.

📌 시험 답안에는 **가이드 원문대로 6줄을 다 쓰는 것이 정답**임. 위 내용은 「왜 그런가」를 묻는 서술에서 틀리지 않기 위한 것.

## XML 삽입 (XPath·XQuery 통합)

`복원 #9·12` · 수험서 1-9. XML 삽입

### 문제 (취약)

```java
// 외부 입력 값을 검증하지 않고 XQuery 표현식에 사용한다.
String name = props.getProperty("name");
// 외부 입력 값에 의해 쿼리 구조가 변경되어 안전하지 않다. (예: something' or '1'='1)
String es = "doc('users.xml')/userlist/user[uname='" + name + "']";
XQPreparedExpression expr = conn.prepareExpression(es);
XQResultSequence result = expr.executeQuery();
```

### 답 (안전)

```java
// bindString 함수로 쿼리 구조가 변경되는 것을 방지한다.
String name = props.getProperty("name");
String es = "doc('users.xml')/userlist/user[uname='$xname']";
XQPreparedExpression expr = conn.prepareExpression(es);
expr.bindString(new QName("xname"), name, null);
XQResultSequence result = expr.executeQuery();
```

**채점 키워드: 외부입력 / 검증 없이 / XML 질의문(XPath) 구조 조작 / 변수 바인딩**

2021 개정에서 **XPath 삽입 + XQuery 삽입 → 「XML 삽입」**으로 통합됨. 안전코드 구조가 SQL의 `PreparedStatement`+`setString`과 **완전히 동일**(`$변수` 자리표시자 → `bindString`).

`복원 #13` · 수험서 1-10. LDAP 삽입

### 문제 (취약)

```java
DirContext dctx = new InitialDirContext(env);
SearchControls sc = new SearchControls();
String[] attributeFilter = { "cn", "mail" };
sc.setReturningAttributes(attributeFilter);
sc.setSearchScope(SearchControls.SUBTREE_SCOPE);

```

### 답 (안전)

```java
DirContext dctx = new InitialDirContext(env);
SearchControls sc = new SearchControls();
sc.setReturningAttributes(new String[] { "cn", "mail" });
sc.setSearchScope(SearchControls.SUBTREE_SCOPE);
String base = "dc=example,dc=com";
// userSN과 userPassword 값에서 LDAP 필터를 조작할 수 있는 문자열을 제거하고 사용
if (!userSN.matches("[\\w\\s]*") || !userPassword.matches("[\\w]*")) {
    throw new IllegalArgumentException("Invalid input");
}
String filter = "(&(sn=" + userSN + ")(userPassword=" + userPassword + "))";
NamingEnumeration<?> results = dctx.search(base, filter, sc);
```

**채점 키워드: 외부입력 / 검색 필터(DN) 조립 / 특수문자 이스케이프(화이트리스트)**

안전코드가 **1-2 코드삽입과 같은 `matches("[\w...]*")` 관용구**를 씀. 가이드가 반복하는 패턴이므로 이것 하나는 손에 붙일 것. 필터 특수문자 `( ) * \ NUL`, DN 특수문자 `, + " \ < > ;`.

## 메모리 버퍼 오버플로우

`복원 #20` · 수험서 1-16. 메모리 버퍼 오버플로우

### 문제 (취약)

```c
typedef struct _charvoid {
    char x[16];
    void *y;
    void *z;
} charvoid;

void badCode() {
    charvoid cv_struct;
    cv_struct.y = (void *) SRC_STR;
    /* sizeof(cv_struct)의 사용으로 포인터 y에 덮어쓰기 발생 */
    memcpy(cv_struct.x, SRC_STR, sizeof(cv_struct));
    printLine((char *) cv_struct.x);
    printLine((char *) cv_struct.y);
}
```

### 답 (안전)

```c
static void goodCode() {
    charvoid cv_struct;
    cv_struct.y = (void *) SRC_STR;
    /* sizeof(cv_struct.x)로 변경하여 포인터 y의 덮어쓰기를 방지함 */
    memcpy(cv_struct.x, SRC_STR, sizeof(cv_struct.x));
    /* 문자열 종료를 위해 널 문자를 삽입함 */
    cv_struct.x[(sizeof(cv_struct.x) / sizeof(char)) - 1] = '\0';
    printLine((char *) cv_struct.x);
    printLine((char *) cv_struct.y);
}
```

**채점 키워드: 경계(범위) 검사 / 정확한 크기 지정 / 널 문자 삽입 / 안전한 함수**

`sizeof(구조체 전체)` → `sizeof(대상 필드)` 로 바꾸고 **마지막 인덱스에 `'\0'` 패딩**까지 해야 완성. 널 문자 언급을 빼면 키워드 실점.

## 포맷 스트링 — 「그레고리안 데이트핸들러」

`복원 #1` · 수험서 1-17. 포맷 스트링 삽입

### 문제 (취약)

```java
// args[0]의 값으로 "%1$tY-%1$tm-%1$te"를 전달하면 시스템이 가진 날짜 정보가 노출
public static void main(String[] args) {
    Calendar validDate = Calendar.getInstance();
    validDate.set(2014, Calendar.OCTOBER, 14);
    // 외부 입력값의 포맷 문자열 포함 여부를 확인하지 않고 포맷 문자열에 사용
    System.out.printf(args[0]
            + " did not match! HINT: It was issued on %1$terd of some month", validDate);
}
```

### 답 (안전)

```java
// 외부 입력값이 포맷 문자열 출력에 사용되지 않도록 수정
public static void main(String[] args) {
    Calendar validDate = Calendar.getInstance();
    validDate.set(2014, Calendar.OCTOBER, 14);
    // %s 포맷 문자열을 지정하고 사용자 입력값은 2번째 이후의 파라미터로 사용
    System.out.printf("%s did not match! HINT: It was issued on %2$terd of some month",
            args[0], validDate);
}
```

**채점 키워드: 외부입력을 포맷 문자열로 사용 / 고정 포맷(%s) 지정 / 입력값은 2번째 이후 파라미터 / %n 금지**

`Calendar.getInstance()`가 반환하는 것이 **GregorianCalendar** — 복원의 「그레고리안」이 이것. 원리 한 줄: **외부입력을 포맷 «문자열»이 아니라 포맷 «인자»로 옮긴다.**

## 적절하지 않은 난수값

`복원 #22` · 수험서 2-8. 적절하지 않은 난수값

### 문제 (취약)

```java
public static int getRandomValue(int maxValue) {
    // 고정된 시드값을 사용하여 동일한 난수값이 생성되어 안전하지 않다.
    Random random = new Random(100);
    return random.nextInt(maxValue);
}

public static String getAuthKey() {
    // 매번 변경되는 시드값을 사용하여 다른 난수값이 생성되나 보안결정을 위한 난수로는 안전하지 않다.
    Random random = new Random();
    String authKey = Integer.toString(random.nextInt());
}
```

## Null Pointer 역참조

`복원 #15` · 수험서 5-1. Null Pointer

### 문제 (취약)

```java
public static int cardinality(Object obj, final Collection col) {
    int count = 0;
    if (col == null) { return count; }
    Iterator it = col.iterator();
    while (it.hasNext()) {
        Object elt = it.next();
        // obj가 null이고 elt가 null이 아닐 경우, Null.equals가 되어 널 포인터 역참조가 발생한다.
        if ((null == obj && null == elt) || obj.equals(elt)) {
            count++;
        }
    }
    return count;
}
```

### 답 (안전)

```java
public static int cardinality(Object obj, final Collection col) {
    int count = 0;
    if (col == null) { return count; }
    Iterator it = col.iterator();
    while (it.hasNext()) {
        Object elt = it.next();
        // obj가 null인지 검사 후 참조해야 한다.
        if ((null == obj && null == elt) || (null != obj && obj.equals(elt))) {
            count++;
        }
    }
    return count;
}
```

**채점 키워드: null 검사 없이 참조 / 참조 전 null 검증 / 단락평가(&&)**

```java
    public WhitelistedObjectInputStream(InputStream inputStream, Set<String> wl)
```

`gets`는 **버퍼 크기 인자가 아예 없어** 구조적으로 오버플로우를 막을 수 없음(C11에서 표준 삭제). ⚠️ **`fork` vs `vfork`는 수험서 제3장에 없음** `[가정]` — `vfork`는 자식이 부모 주소공간을 «공유»하고 부모가 정지하므로 동작이 미정의라 사용 금지, `fork`로 대체.

## 부록. 가이드 원문(수험서 제3장)의 알려진 오류 5건

⚠️ **채점 기준은 가이드이므로 시험 답안은 원문대로 쓸 것.** 아래는 「왜 그런가」를 서술할 때 논리가 꼬이지 않게 하기 위한 메모이며, 원문을 고치지 않고 그대로 둠.

| 절 | 원문 | 실제 |
|---|---|---|
| 1-5 OS 명령어 삽입 | `date.replaceAll("|", "")` 로 파이프 제거 | `replaceAll`은 정규식을 받으며 `\|`는 빈 교대라 **파이프가 제거되지 않음.** 올바른 형태는 문자클래스 `[|;&:>]` 또는 `Pattern.quote` |
| 2-10 부적절한 전자서명 확인 | `new JarFile(f)`는 「서명 확인 없이」 | `JarFile(File)`은 **`verify=true`가 기본값**이라 변조 시 `SecurityException` 발생. 진짜 약점은 `getCodeSigners()` 부재(서명 «주체» 미확인) |
| 1-8 XXE | `setXIncludeAware(false)` 를 대책으로 열거 | JAXP **기본값이 이미 false**. 심층방어 설정이며 이 줄의 부재가 곧 취약을 뜻하지 않음 |
| 5-3 해제된 자원 사용 | `stmcpy` | `strncpy` 오타 |
| 5-4 초기화되지 않은 변수 | `beak` | `break` 오타 |

그 외 4-2(오류 상황 대응 부재)의 안전 예제가 같은 문서 4-1(오류 메시지 정보노출) 기준을 스스로 위반하는 구성이 있음 — 항목별로 묻는 약점이 다르므로 **문항이 지목한 약점명을 먼저 확인할 것**.
