# 실습 문제은행 2 — 입력데이터 검증 및 표현 (1-10 ~ 1-17)

> ⚠️ **기출문제 아님.** 공개 가이드(「소프트웨어 개발보안 가이드」) 내용을 근거로 만든 **연습문항**임. 통합 수험서 제3장 1-10~1-17 여덟 항목의 「보안대책」·「정탐/오탐 판단」 문장을 출제·채점 근거로 삼음.

**범위** — 1-10 LDAP 삽입 / 1-11 크로스사이트 요청 위조 / 1-12 서버사이드 요청 위조 / 1-13 HTTP 응답분할 / 1-14 정수형 오버플로우 / 1-15 보안기능 결정에 사용되는 부적절한 입력값 / 1-16 메모리 버퍼 오버플로우 / 1-17 포맷 스트링 삽입. 기본은 항목당 2문항 = 16문항이고, **보강 5문항(문제 17~21)을 합쳐 총 21문항**임.

**푸는 법** — 실습시험 1교시 단순서술형 형식 그대로임. 각 문항에 ① 정탐/오탐 판단 ② 사유 서술(**근거 코드 지목 포함**) ③ 정탐이면 개선방안까지 씀. 문항당 6분, 검은색 볼펜으로 종이에 쓸 것.

**채점** — 해설의 `[채점 키워드]`와 대조해 포함 개수를 셈. **뜻만 맞고 키워드 단어가 없으면 0점**임. 키워드 3개 중 2개 미만이면 오답노트행.

⛔ **정탐/오탐이 홀짝으로 배열돼 있지 않음.** 패턴으로 찍지 말 것.

**출처 표시** — 각 해설 끝에 다음 둘 중 하나가 붙음. **`(가이드 원문 예제 기준)` 쪽을 먼저 외울 것.**
- `(가이드 원문 예제 기준)` — 제3장 해당 항목의 「취약/안전 코드예제」를 **식별자 수준(변수명·파일명·필드명·경로)만 바꿔** 옮긴 문항. 구조와 API 호출은 원문 그대로임
- `(재구성)` — 같은 항목의 「보안대책」·「정탐/오탐 판단」 문장을 근거로 **새로 지어낸** 문항. 판별력 훈련용임

> 응시자 기억 기반 복원(`1차 시험 복원 (기억 기반).md` §4)에서 **원문 예제가 식별자만 바뀐 채 출제된 정황이 확인됨**(2-16 은 `MAX_ATTEMPTS` 변수명까지 동일). 따라서 원문 변형 문항의 코드 형태를 눈에 익히는 것이 우선순위가 높음. ⚠️ **다만 그 복원의 출처는 응시자 기억이고 공식 기출이 아님.**

# 해설 및 채점 키워드

**1. 정탐.** 외부입력 `dept` 가 특수문자 검증 없이 문자열 연결로 DN(`base`) 에 포함된 뒤 `ctx.search` 에 도달함. `*` · `)` · `,` 등으로 검색 범위(DN 구조)를 조작해 다른 조직의 항목을 열람할 수 있음. [채점 키워드: 외부입력 / 특수문자 검증 없이 / DN(검색 base) 문자열 연결] 개선: DN·필터에 사용되는 입력값에서 특수문자(`= + < > # ; \` 등)를 제거하거나 실행명령이 아닌 일반문자로 인식되도록 처리. (재구성)

**2. 오탐.** 필터를 구성하기 **전에** 정규식으로 두 입력값을 검증해 — `empSN` 은 `[\w\s]*`, `empPassword` 는 `[\w]*` — 통과하지 못하면 `IllegalArgumentException` 을 던짐. LDAP 필터를 조작할 수 있는 문자(`*` · `(` · `)` · `=` · `&` · `|` · `\`)가 정규식상 허용되지 않아 필터 구조 조작이 불가함. [채점 키워드: 정규식 검증(`[\w\s]*`) / LDAP 필터 조작 문자 통과 불가 / 필터 구성 전 검증] (가이드 원문 예제 기준)
- ⚠️ 문제 19(정탐)와 **같은 구조의 짝**임 — 필터 조립 뼈대는 같고 정규식 검증 유무 하나로 판정이 갈림.

**3. 오탐.** 입력화면 요청 시 `UUID.randomUUID()` 로 임의 토큰을 만들어 세션에 저장하고 HIDDEN 필드로 전달한 뒤, 처리 단계에서 요청 파라미터 토큰과 세션 토큰이 일치하는 경우에만 삭제 로직을 실행함. 공격자는 피해자 세션의 토큰 값을 알 수 없어 요청을 위조할 수 없음. [채점 키워드: 세션 저장 토큰(UUID) / HIDDEN 필드로 전달 / 요청 파라미터 토큰과 비교 검증 후 처리] (가이드 원문 예제 기준)

**4. 정탐.** 상태 변경(등급 수정) 요청인데 로그인 세션 존재 여부만 확인하고 정상 요청 여부(토큰)를 검증하지 않은 채 `memberService.updateGrade` 에 도달함. GET 방식이라 `<img src>` 만으로도 관리자 브라우저에서 실행 가능함. [채점 키워드: 상태 변경 요청 / 토큰 검증 없이 / GET 방식] 개선: POST 방식으로 변경하고 세션 저장 토큰과 HIDDEN 필드 토큰을 비교 검증, 중요기능은 재인증 유도. (재구성)
- ⚠️ 제3장 1-11 의 **「취약 (Java)」 코드예제는 주석 두 줄뿐이고 실제 코드가 없음.** 따라서 이 항목의 정탐 문항은 원문 변형이 불가하며 재구성으로만 존재함.

**5. 정탐.** 외부입력 `imgUrl` 이 검증 없이 서버 간 요청(`restTemplate.getForObject`)의 대상 주소로 도달함. `http://127.0.0.1:8080/admin` · 내부망 IP 를 넣어 접근통제를 우회하고 신뢰된 네트워크의 데이터를 획득할 수 있음. [채점 키워드: 외부입력 URL / 검증 없이 / 서버 간 요청 대상 주소 / 내부망] 개선: 사전 정의 URL 목록의 키 값으로만 대상을 선택(화이트리스트 필터링), 내부 URL 블랙리스트 병행. (재구성)

**6. 오탐.** 접속할 URL 을 key·value 형식의 `bankUrlMap` 에 미리 작성해 두고, 외부입력 `bankCode` 는 그 맵의 **키**로만 쓰여 참조된 `URL` 객체로 `openConnection` 을 수행함. 외부입력이 요청 대상 주소 자체가 될 수 없음. [채점 키워드: 사전 정의 URL 리스트(Map) / 키 값으로만 참조 / 임의 URL 불가] (가이드 원문 예제 기준)
- ⚠️ 등록되지 않은 키를 넣으면 `url` 이 `null` 이 돼 `NullPointerException` 이 발생함(5-1 Null Pointer 역참조 소지). 보고된 약점명(1-12 SSRF) 기준 판정은 오탐임.

**7. 정탐.** 외부입력 `lastVisit` 이 개행문자 제거 없이 쿠키 값으로 설정돼 `response.addCookie` 에 도달함. 쿠키는 `Set-Cookie` 응답헤더로 전달되므로 `20260828%0d%0a%0d%0a<script>...` 입력 시 응답이 둘로 분리돼 XSS·캐시 훼손이 가능함. [채점 키워드: 외부입력 / 개행문자(CR, LF) 제거 없이 / 쿠키·응답헤더 설정(addCookie) 도달] 개선: 응답헤더(쿠키) 값으로 사용하기 전에 `replaceAll("[\\r\\n]", "")` 로 CR·LF 개행문자를 제거할 것. (가이드 원문 예제 기준)
- ⚠️ `setSecure(true)` 는 전송 구간 보호 설정이라 응답분할 대책이 **아님.** 보안 관련 호출이 보인다고 오탐으로 넘기지 말 것.

**8. 오탐.** `replaceAll("[\\r\\n]", "")` 로 CR·LF 개행문자를 제거한 결과 `safeKeyword` 만 응답헤더 값으로 사용함. 응답을 분리할 개행문자가 남지 않으므로 약점이 성립하지 않음. [채점 키워드: 개행문자(CR, LF) 제거 / replaceAll / 제거 후 헤더 사용] (재구성)

**9. 오탐.** `Integer.parseInt` 를 `try~catch` 로 감싸고, 배열 크기로 쓰기 **전에** `row_ct < 0` 로 음수 여부를 검사해 해당하면 예외를 던져 처리를 중단함. 검증을 통과한 값만 배열 할당에 도달하므로 음수 크기로 인한 예기치 않은 동작이 발생하지 않음. [채점 키워드: 입력값 크기 검증 후 사용 / 음수(범위) 검사 / 예외 처리] (가이드 원문 예제 기준)
- ⚠️ 가이드 안전예제는 **음수 검사만** 두고 상한은 두지 않음. 상한까지 요구하는 문제 21(C, 곱셈 오버플로우)과 판정 근거가 다르므로 구분해 쓸 것 — 여기서는 배열 크기 직접 사용이라 곱셈 오버플로우 경로가 없음.

**10. 정탐.** `atoi(arg)` 결과 `count` 를 범위(음수·상한) 검증 없이 `count * sizeof(struct record)` 곱셈에 사용해 메모리 할당 크기로 넘김. 오버플로우로 실제보다 작은 크기가 할당된 뒤 반복문이 `count` 회 쓰기를 수행해 할당 범위를 벗어남. [채점 키워드: 외부입력 정수 / 범위(음수·상한) 검증 없이 / 메모리 할당 크기(곱셈 오버플로우)] 개선: 파싱 후 상·하한 범위를 검사하고 연산 결과 값의 범위를 체크하는 모듈을 사용. (재구성)

**11. 오탐.** 보안결정 값인 단가와 할인율을 클라이언트 입력이 아니라 서버가 보유한 정보(`productService.getPrice` · `couponService.getRate`)에서 조회하고, 사용자 식별도 세션(`memberId`)에서 가져옴. 외부입력은 조회 키로만 쓰임. [채점 키워드: 서버 보유 정보 / 세션 / 보안결정 값 외부입력 미사용] (재구성)

**12. 정탐.** 서버가 보유해야 할 단가 정보를 히든필드(`unitPrice`)로 클라이언트에 내려보낸 뒤 `request.getParameter("unitPrice")` 로 되받아 결제금액 계산에 그대로 사용함. 히든필드는 조작 가능한 외부입력이므로 `unitPrice=1` 로 바꾸면 가격 산정이라는 보호메커니즘이 우회됨. [채점 키워드: 히든필드(조작 가능한 외부입력) / 보안결정(단가·금액) 계산에 사용 / 서버측 검증 없음] 개선: 가격이 아니라 품목(item) 식별자만 입력받고 서버가 보유한 가격정보로 전체 금액을 계산하며, 보안확인 절차도 서버에서 실행할 것. (가이드 원문 예제 기준)

**13. 정탐.** 복사 크기로 대상 필드가 아니라 **구조체 전체 크기** `sizeof(bp)` 를 넘김. 대상 `bp.buf` 는 16바이트인데 그보다 큰 길이가 복사돼 인접 멤버인 포인터 `p1` 이 덮어써지고, 널 문자 종료 처리도 없어 `printLine` 이 버퍼 범위를 넘어 읽음. [채점 키워드: 잘못된 크기(구조체 전체 sizeof) 사용 / 인접 메모리(포인터) 덮어쓰기 / 널 문자 종료 없음] 개선: `sizeof(bp.buf)` 처럼 **대상 버퍼의 정확한 크기**로 복사 범위를 제한하고, 배열 마지막 인덱스에 널 문자(`'\0'`)를 삽입해 문자열을 종료할 것. (가이드 원문 예제 기준)

**14. 오탐.** 대상 버퍼 크기 `sizeof(name)` 에서 1을 뺀 만큼으로 복사 범위를 제한하고, 마지막 인덱스에 널 문자(`'\0'`)를 직접 넣어 종료 처리함. 소스 길이와 무관하게 할당 범위를 넘지 않음. [채점 키워드: 대상 버퍼 크기로 복사 범위 제한 / 널 문자('\0') 종료] (재구성)

**15. 오탐.** 고정 포맷 문자열 `"error: %s"` 를 지정하고 외부입력 `user_msg` 는 2번째 파라미터(데이터)로만 전달함. 출력도 포맷을 해석하지 않는 `fputs` 를 사용하므로 `%n` · `%x` 가 포맷 지시자로 처리되지 않음. [채점 키워드: 고정 포맷 문자열(%s 지정) / 데이터 파라미터로 전달 / fputs(포맷 해석 없음)] (재구성)

**16. 정탐.** 외부입력 `args[0]` 이 포맷 문자열 포함 여부 확인 없이 **문자열 연결로 포맷 문자열 자체를 구성**해 `System.out.printf` 에 전달됨. `%1$tY-%1$tm-%1$te` 를 넣으면 인자로 넘어간 `Calendar` 객체(`issueDate`)의 날짜 정보가 노출되고, 인자 개수를 넘는 지시자를 주면 예외로 서비스가 중단됨. [채점 키워드: 외부입력을 포맷 문자열 생성에 포함(연결) / printf(포맷 함수) 도달 / 포맷 지시자로 내부 정보 노출] 개선: `"%s did not match! ... %2$terd ..."` 처럼 **고정 포맷 문자열을 지정**하고 외부 입력값은 **2번째 이후의 파라미터**로 전달할 것. (가이드 원문 예제 기준)
- ⚠️ Java 에서는 `%n` 이 줄바꿈 지시자이고 C 처럼 메모리 값을 쓰지 못함. 이 문항의 피해는 **내부 정보 노출과 예외 유발**이며, `%n`·`%hn` 메모리 변조는 **C 계열 문항(문제 17)** 의 서술임. 언어에 맞는 피해를 쓸 것.

## 보강 문항 해설

**17. 정탐.** 외부입력 `user_fmt` 가 검증 없이 `strftime` 의 **포맷 문자열 인자**로 사용되고, 그 결과 `buf` 가 다시 `printf(buf)` 의 포맷 문자열이 됨. `%Y-%m-%d %H:%M` 류로 시스템이 가진 날짜·시각 정보가 노출되고, 변환 결과에 포맷 지시자가 남으면 `printf` 단계에서 메모리 내용 읽기·특정 메모리 위치 값 변경이 가능함. [채점 키워드: 외부입력을 포맷 문자열로 사용 / strftime·printf(포맷 함수) / %n(메모리 값 변경)] 개선: 날짜 포맷은 소스에 고정(`"%Y-%m-%d"`)하고 외부입력은 `printf("%s", ...)` 처럼 고정 포맷의 2번째 이후 파라미터로만 전달하거나 `fputs` 로 출력할 것. (재구성)
- ⚠️ **`printf` 까지 지시자를 남기려면 `%%n` 이지 `%n` 이 아님** — `%n`·`%x` 는 **strftime 자신의 변환 지시자**(각각 개행·로케일 날짜)라 그 단계에서 소비돼 버림. 실측(Kali gcc, glibc): 입력 `%x|%n|` → `buf = "08/28/26|<개행>|"` 로 **지시자가 남지 않음.** 반면 입력 `%%x|%%n|` → `buf = "%x|%n|"` 로 리터럴이 남고, 이어지는 `printf(buf)` 가 그것을 해석해 **프로세스가 SIGSEGV(exit 139)로 죽음** — `%n` 의 메모리 쓰기가 실제로 일어난 것임.
- **판정에는 영향 없음** — 1-17 의 정탐 근거는 「외부입력이 포맷 문자열 인자에 도달하는가」이고, `strftime(buf, sizeof(buf), user_fmt, tm_now)` 한 줄에서 이미 성립함. 위 `%%` 는 **피해 서술을 정확히 쓰기 위한 것**이지 정탐 성립 조건이 아님.

**18. 오탐.** 날짜 포맷 문자열 `"%Y-%m-%d"` 이 소스에 고정된 상수이고, 외부입력 `label` 은 고정 포맷 `"%s: %s\n"` 의 **2번째 이후 데이터 파라미터**로만 전달됨. 입력에 `%n` · `%x` 가 있어도 포맷 지시자로 해석되지 않음. [채점 키워드: 고정 포맷 문자열(%s 지정) / 데이터 파라미터로 전달 / 포맷 문자열 생성에 미포함] (재구성)

**19. 정탐.** 외부입력 `userSN` 이 특수문자 검증 없이 문자열 연결로 LDAP 검색 필터 `(&(objectClass=person)(sn=...))` 에 포함돼 `dctx.search` 에 도달함. `*` 입력 시 조건이 항상 참이 되고, `*)(uid=admin)` 처럼 괄호를 닫아 필터 구조 자체를 조작해 다른 항목의 속성(`mail` · `telephoneNumber`)을 열람할 수 있음. [채점 키워드: 외부입력 / 특수문자 검증 없이 / LDAP 검색 필터 문자열 연결(search 도달)] 개선: 필터·DN 에 사용되는 입력값에서 특수문자(`* ( ) = + < > # ; \` 등)를 제거하거나 정규식으로 검증하고, 특수문자가 필요하면 실행명령이 아닌 일반문자로 인식되도록 처리할 것. (가이드 원문 예제 기준)

**20. 오탐.** 필터 조립 **전에** LDAP 필터 메타문자(`*` · `(` · `)` · `\` · `&` · `|` · `!` · `=` · `<` · `>` · `~` · `+` · `,` · `;` · `"`)를 `replaceAll` 로 제거한 `safeCn` 만 사용함. 괄호·와일드카드가 남지 않아 필터 구조를 끊거나 조건을 항상 참으로 만들 수 없음. [채점 키워드: LDAP 특수문자 제거(필터링) / 필터 구성 전 처리 / 필터 구조 조작 불가] (재구성)
- ⚠️ 문제 2 는 **정규식 화이트리스트 검증**(허용 문자만 통과, 가이드 안전예제 방식), 이 문항은 **특수문자 제거**(블랙리스트 치환)임. 둘 다 제3장 1-10 보안대책에 있는 정당한 대응책이지만 사유 서술의 근거 문장이 다르므로 구분해 쓸 것.
- ✅ **실측(OpenJDK 24)** — 자바 문자열 `"[*()\\\\&|!=<>~+,;\"]"` 은 정규식 문자클래스 `[*()\\&|!=<>~+,;"]` 로 컴파일되고, 입력 `a*b(c)d\e&f|g!h=i<j>k~l+m,n;o"p` → 출력 `abcdefghijklmnop` 으로 **대상 15문자가 전부 제거됨.** 문자클래스 안이라 `*`·`|`·`+` 가 메타문자로 해석되지 않고 리터럴로 지워지는 것이 확인됨 — 즉 **흉내가 아니라 실제로 동작하는 필터**임.

**21. 오탐.** `strtol` 결과 `count` 를 메모리 할당에 쓰기 **전에** `count <= 0 || count > MAX_RECORDS` 로 상·하한을 모두 검사하고 범위를 벗어나면 반환함. 상한이 4096 이라 `count * sizeof(struct record)` 곱셈이 `size_t` 범위를 넘지 않고, 음수 입력도 하한 검사에서 차단됨. 반복문 상한도 검증된 같은 값이라 할당 범위를 벗어나지 않음. [채점 키워드: 상·하한 범위 검사 / 할당 전 검증 / 곱셈 오버플로우 불가] (재구성)
- ⚠️ 문제 10(정탐)과 짝임 — 같은 구조에서 **범위 검사 유무 하나**로 판정이 갈림. `malloc` 의 `NULL` 검사는 오버플로우 대책이 아님(문제 10 에도 있음)에 유의할 것.

**보강 문항 정답 분포** (채점 후에만 볼 것): 정탐 2 / 오탐 3. 배열은 정·오·정·오·오 순임.

- **1-13** — 응답 **본문** 인코딩(XSS 대책)과 응답 **헤더** 개행문자 제거를 혼동함. 쿠키(`addCookie`)도 `Set-Cookie` 응답헤더라 같은 대상임
