# 실습 문제은행 1. 입력데이터 검증 및 표현 (1-1 ~ 1-9)

> ⚠️ **기출문제가 아님.** 공개 가이드(전자정부 SW 개발보안 가이드) 내용을 근거로 만든 **연습문항**임. 문항 코드·해설은 `SW보안약점 진단원 통합 수험서.md` 제3장 1-1~1-9 의 「보안대책」·「정탐/오탐 판단」 문장을 근거로 작성함.

**시험 조건** — 실습시험 100분 / 15문항 / 100점 / 60점 미만 과락. 단순서술형은 진단도구 보고에 대해 ①정탐·오탐 판단 ②사유 서술(근거 코드 지목) ③정탐이면 개선방안 을 쓰는 형식임.

**채점 방식** — 예시 답안의 **핵심 키워드 포함 여부**로 채점함. 뜻만 맞게 쓰면 0점임. 답안을 쓴 뒤 하단 `[채점 키워드]` 와 대조해 포함 개수를 셀 것.

**사용법**
- 문항당 6분 제한, 볼펜으로 종이에 쓸 것
- 해설을 먼저 보지 말 것
- 키워드 3개 중 2개 미만 적중이면 그 항목은 오답노트행
- ⚠️ **정탐/오탐이 홀짝 교대로 배열돼 있지 않음.** 패턴으로 찍지 말 것

**출처 표시** — 각 해설 끝에 다음 둘 중 하나가 붙음. **`(가이드 원문 예제 기준)` 쪽을 먼저 외울 것.**
- `(가이드 원문 예제 기준)` — 제3장 해당 항목의 「취약/안전 코드예제」를 **식별자 수준(변수명·파일명·테이블명·경로)만 바꿔** 옮긴 문항. 구조와 API 호출은 원문 그대로임
- `(재구성)` — 같은 항목의 「보안대책」·「정탐/오탐 판단」 문장을 근거로 **새로 지어낸** 문항. 판별력 훈련용임

> 응시자 기억 기반 복원(`1차 시험 복원 (기억 기반).md` §4)에서 **원문 예제가 식별자만 바뀐 채 출제된 정황이 확인됨**(예: `backuplog.bat` → `kisaDB.bat`). 따라서 원문 변형 문항의 코드 형태를 눈에 익히는 것이 우선순위가 높음. ⚠️ **다만 그 복원의 출처는 응시자 기억이고 공식 기출이 아님.**

# 해설 및 채점 키워드

**1. 오탐.** MyBatis `@Select` 구문의 외부입력 자리가 `${deptCd}` 가 아니라 `#{deptCd}` 로 선언돼 PreparedStatement 바인딩 변수로 처리됨. 값이 쿼리 문자열에 연결되지 않아 쿼리 구조 변경이 불가함. [채점 키워드: 파라미터 바인딩(`#{}`) / `${}` 미사용 / 쿼리 구조 변경 불가] (재구성)

**2. 정탐.** 외부입력 `grade` 가 검증·바인딩 없이 문자열 연결로 SQL 쿼리에 포함돼 `Statement.executeQuery` 실행에 도달함. `' or '1'='1` 입력 시 조회 조건이 조작돼 전체 레코드가 열람됨. [채점 키워드: 외부입력 / 검증 없이 문자열 연결로 쿼리 생성 / executeQuery 실행 도달] 개선: `?` 문자로 바인딩 변수를 선언한 `PreparedStatement` 를 사용하고 `setString` 등의 메소드로 파라미터를 설정할 것. (가이드 원문 예제 기준)

**7. 오탐.** 스크립트 삽입에 사용되는 문자(`&` · `<` · `>` · `"` · `'`)를 HTML 엔티티로 치환한 값만 화면에 출력하고, DB 저장값은 JSTL `c:out` 으로, 스크립트 영역은 XSS 방지 라이브러리(`Encoder.encodeForJS`·`encodeForHTML`)로 인코딩해 출력함. 세 경로 모두 대책이 적용됨. [채점 키워드: 스크립트 문자 치환(HTML 엔티티) / JSTL c:out 출력 / XSS 방지 라이브러리] (가이드 원문 예제 기준)

**9. 오탐.** 명령 문자열에 연결하기 **전에** 멀티라인 특수문자(`|` · `;` · `&` · `:`)와 리다이렉트 특수문자(`>`)를 `replaceAll` 로 제거한 `period` 만 사용함. 명령어를 이어붙일 구분자가 남지 않아 추가 명령 실행이 불가함. [채점 키워드: 멀티라인·리다이렉트 특수문자(`| ; & : >`) 제거 / replaceAll 필터 / 제거 후 exec 실행] (가이드 원문 예제 기준)
- ⚠️ **실측 유보** — `replaceAll("|", "")` 의 첫 인자는 정규식으로 해석되고 `|` 는 「빈 대안」이라 **파이프 문자가 실제로는 제거되지 않음.** OpenJDK 21 로 확인: 입력 `20260828 | id ; whoami & ls : cat > /tmp/x` → 출력 `20260828 | id  whoami  ls  cat  /tmp/x`(파이프 잔존). 리터럴 제거를 의도했다면 `replaceAll("\\|", "")` 여야 함. **채점은 가이드 기준이므로 답안은 오탐으로 쓰되**, 실제 진단에서는 이 한 줄이 무력함을 알아둘 것.

**10. 정탐.** 인자 배열을 썼으나 `/bin/sh -c` 에 넘기는 **단일 명령 문자열**에 외부입력 `target` 이 검증 없이 연결됨. `; rm -rf /` 같은 명령어 구분자 입력으로 임의 명령 실행이 가능함. [채점 키워드: 외부입력 / 검증 없이 명령 문자열 연결 / 명령어 실행 함수 도달(`sh -c`)] 개선: 멀티라인·리다이렉트 특수문자(`| ; & : > >>`)를 제거하거나, 명령어를 미리 지정해 두고 외부입력으로는 선택만 하게 할 것. (재구성)

**11. 정탐.** 업로드된 파일명 `imageName` 을 확장자·타입·크기 검증 없이 그대로 받아 저장 경로 문자열에 결합해 사용함. `.jsp` 등 서버에서 실행 가능한 확장자가 그대로 통과하고 저장 파일명도 원본이라, 공격자가 업로드한 스크립트를 웹으로 직접 호출해 실행할 수 있음. [채점 키워드: 업로드 파일명 검증 없이 사용 / 확장자 화이트리스트 없음 / 서버 실행 가능 스크립트 업로드] 개선: 마지막 `.` 기준으로 확장자를 추출·소문자 변환해 화이트리스트(`gif`·`jpg`·`png`)만 허용하고, 저장 파일명을 추측 불가한 문자열로 변경하며, 저장 경로를 web document root 밖에 둘 것. (가이드 원문 예제 기준)

**12. 오탐.** 마지막 `.` 기준으로 확장자를 추출해 소문자로 변환한 뒤 화이트리스트(`gif`·`jpg`·`png`)에 있을 때만 저장하고, 저장 파일명을 UUID 로 난수화하며 저장 경로도 web document root 외부(`/data/upload`)임. [채점 키워드: 확장자 화이트리스트 / 마지막 `.` 기준·소문자 처리 / 웹루트 외부 저장·파일명 난수화] (재구성)

**13. 정탐.** 검사가 `contains` 부분 문자열 일치라 화이트리스트가 아니며, `http://attacker.com/?ref=intra.company.co.kr` 처럼 사내 도메인 문자열만 끼워 넣은 URL 이 통과함. 통과 시 외부입력 값이 그대로 `sendRedirect` 대상이 됨. [채점 키워드: 외부입력 URL / 화이트리스트 아님(부분 문자열 검사) / sendRedirect 자동접속] 개선: 자동 연결할 URL·도메인을 화이트리스트로 관리하고, 입력값이 목록에 존재하는지 확인해 목록에 등록된 URL 로만 이동할 것. (재구성)

**14. 오탐.** 외부입력 `next` 는 `Integer.parseInt` 로 정수 인덱스로만 해석돼 사전 정의 배열 `allowedUrl` 의 원소를 고르는 데 쓰임. 이동할 수 있는 URL 범위가 배열 안으로 제한되고, 숫자가 아니거나 범위를 벗어나면 예외로 차단되므로 외부입력이 이동 URL 자체가 될 수 없음. [채점 키워드: 화이트리스트(allowedUrl 배열)로 URL 범위 제한 / 인덱스로만 선택 / 범위 밖 예외 처리] (가이드 원문 예제 기준)

**15. 오탐.** `disallow-doctype-decl=true` 로 doctype 정의를 금지하고, `external-general-entities=false`·`external-parameter-entities=false` 로 외부 엔티티를, `load-external-dtd=false` 로 외부 DTD 를 각각 비활성화한 뒤 `setXIncludeAware(false)`·`setExpandEntityReferences(false)` 까지 적용한 파서로만 파싱함. 파서에 맞는 보안설정이 모두 적용된 경우임. [채점 키워드: doctype 선언 금지(`disallow-doctype-decl=true`) / 외부 엔티티·외부 DTD 비활성화 / setXIncludeAware(false)·setExpandEntityReferences(false)] (가이드 원문 예제 기준)

**16. 정탐.** 외부에서 전송된 XML(`request.getInputStream()`)이 외부 엔티티·외부 DTD 제한 설정 없는 파서의 `parse` 에 도달함. `setValidating(false)` 는 DTD 유효성 검사만 끄는 설정이라 외부 엔티티 확장은 그대로 수행됨. [채점 키워드: 외부 XML / 외부 엔티티·DTD 비활성화 설정 없음 / parse 도달] 개선: `disallow-doctype-decl=true`, `external-general-entities=false`, `external-parameter-entities=false`, `load-external-dtd=false` 를 `setFeature` 로 설정할 것. (재구성)

**17. 오탐.** 외부 입력값 `mname` 이 XQuery 표현식에 문자열로 연결되지 않고 `$xmname` 변수 자리로 선언된 뒤 `bindString` 으로 바인딩됨. 값이 구문 구조에 영향을 주지 못해 쿼리 구조 변경이 불가함. [채점 키워드: 파라미터화된 XQuery / bindString 변수 바인딩 / 쿼리 구조 변경 불가] (가이드 원문 예제 기준)
- ⚠️ 문제 19(정탐)와 **같은 구조의 짝**임 — 표현식 조립이 문자열 연결이냐 `bindString` 바인딩이냐 하나로 판정이 갈림.

**18. 정탐.** 외부입력 `id`·`pw` 가 검증·바인딩 없이 문자열 연결로 XPath 구문에 삽입돼 `evaluate` 에 도달함. `' or '1'='1` 입력 시 조건이 항상 참이 돼 인증 우회가 가능함. [채점 키워드: 외부입력 / 문자열 연결로 XPath 구문 생성 / evaluate 도달(인증 우회)] 개선: 파라미터화된 XPath/XQuery 로 값을 변수 바인딩하거나, XPath 조작 가능 문자(`' [ ] ,` 등)를 제거하는 필터링을 적용할 것. (재구성)

## 보강 문항 해설

**19. 정탐.** 외부입력 `uname` 이 필터링·바인딩 없이 문자열 연결로 XQuery 표현식 `es` 에 삽입돼 `prepareExpression`·`executeQuery` 에 도달함. `something' or '1'='1` 입력 시 쿼리 구조가 바뀌어 전체 사용자 정보가 열람됨. [채점 키워드: 외부입력 / 문자열 연결로 XQuery 구문 생성 / executeQuery 도달] 개선: `$xname` 변수를 선언한 파라미터화된 XQuery 로 바꾸고 `bindString` 으로 값을 바인딩할 것. (가이드 원문 예제 기준)

**20. 오탐.** XPath 구문 조작에 사용되는 문자(`'` · `[` · `]` · `(` · `)` · `,` · `/` · `@` · `*` · `|` · `=` · `"`)를 `replaceAll` 로 제거한 `safeTeam` 만 구문 조립에 사용함. 구문 경계를 끊을 인용부호·술어 문자가 남지 않아 구조 변경이 불가함. [채점 키워드: XPath 조작 문자 제거(필터링) / replaceAll 후 구문 생성 / 쿼리 구조 변경 불가] (재구성)
- ✅ **실측(OpenJDK 24)** — 자바 문자열 `"['\\[\\]\\(\\),/@*|=\"]"` 은 정규식 문자클래스 `['\[\]\(\),/@*|="]` 로 컴파일되고, 입력 `a'b[c]d(e)f,g/h@i*j|k=l"m` → 출력 `abcdefghijklm` 으로 **대상 12문자가 전부 제거됨.** 문제 9(`replaceAll("|", "")`)와 달리 이쪽은 필터가 실제로 동작함.
- ⚠️ **XXE 는 애초에 성립 여지가 없음** — 파싱 대상이 외부 전송 XML 이 아니라 **서버 로컬 설정 파일**(`new File("/app/conf/org.xml")`)임. `disallow-doctype-decl=true` 는 덤이고, 1-8 의 전제인 「외부에서 전송된 XML」이 없다는 것이 근거임. 문제 21·22 와 갈리는 지점이 여기임.

**21. 정탐.** 외부 엔티티 설정 두 개는 껐으나 `setXIncludeAware(true)` 로 XInclude 처리를 **활성화**한 파서가 외부 전송 XML 을 `parse` 함. `<xi:include href="file:///etc/passwd" parse="text"/>` 로 서버 파일 내용이 문서에 포함돼 노출됨. [채점 키워드: 외부 XML / XInclude 처리 활성화(`setXIncludeAware(true)`) / parse 도달] 개선: `setXIncludeAware(false)`·`setExpandEntityReferences(false)` 를 적용하고, `disallow-doctype-decl=true`·`load-external-dtd=false` 도 함께 설정할 것. (재구성)
- ⚠️ **`setXIncludeAware(true)` 가 이 문항의 정탐 근거임 — 「DOCTYPE 금지만 걸린 파서가 XInclude 로 뚫린다」는 서술은 틀림.** JAXP `DocumentBuilderFactory` 는 XInclude 처리가 **기본 비활성**이라, 명시적으로 켜지 않으면 `xi:include` 를 아예 처리하지 않음. OpenJDK 21 실측 — `disallow-doctype-decl=true` 만 건 파서로 `<xi:include href="file:///etc/passwd" parse="text"/>` 를 파싱하면 `textContent` 가 빈 문자열이고, `setXIncludeAware(true)` **와** `setNamespaceAware(true)` 를 **둘 다** 준 경우에만 `/etc/passwd` 내용이 포함됨(`setXIncludeAware(true)` 만으로는 포함되지 않음). 즉 XInclude 정탐의 표식은 **`setXIncludeAware(true)` 의 존재**이지 DOCTYPE 설정의 부재가 아님.

**22. 오탐.** 보고된 약점명(XML 삽입) 기준으로는 오탐임 — XPath 식 `/request/user/@role` 이 소스에 고정된 상수이고 외부입력이 구문 조립에 전혀 쓰이지 않아 쿼리 구조 변경이 불가함. [채점 키워드: 고정 XPath 구문(상수) / 외부입력 미포함 / 쿼리 구조 변경 불가] (재구성)
- ⚠️ **다만 이 코드에는 별건으로 1-8 부적절한 XML 외부 개체 참조가 성립함** — 외부 전송 XML 이 DTD·외부 엔티티 제한 설정 없는 파서의 `parse` 에 도달함. 실제 진단 시에는 「XML 삽입은 오탐, 단 XXE 로 별도 지적」이 정확한 판정임.
- **두 약점을 가르는 기준**: 「외부입력이 **쿼리 구문(XPath/XQuery)을 만드는 문자열**로 쓰이는가」 → 1-9 XML 삽입. 「외부에서 받은 **XML 문서 자체**를 파서가 외부 개체(엔티티·XInclude)까지 확장해 처리하는가」 → 1-8 XXE. 즉 **1-9 는 쿼리 조립 문제, 1-8 은 파서 설정 문제**임. 문제 18 과 19 는 전자, 문제 21 과 이 문항은 후자임.

**23. 오탐.** 문자열 연결로 쿼리를 조립하고 `PreparedStatement` 를 쓰지 않았으나, 연결되는 값이 전부 내부 상수(`ARCHIVE_MONTHS`)와 서버측 산출값(`LocalDate.now()` 파생 `cutoff`·`table`)임. 요청 파라미터·헤더·파일 등 **외부입력이 이 메소드에 도달하지 않아** 공격자가 쿼리 구조에 개입할 수 없음. [채점 키워드: 외부입력 없음(내부 상수·서버측 산출값) / 공격자 개입 불가 / 쿼리 구조 변경 불가] (재구성)
- ⚠️ **진단도구는 「문자열 연결 + `Statement.executeUpdate`」 패턴만 보고 SQL 삽입으로 보고하나, 오염 경로(외부입력 → 쿼리)가 성립하지 않으므로 오탐임.** 정탐 판정의 첫 조건은 문자열 연결이 아니라 **외부입력의 도달 여부**임 — 이 순서를 뒤집으면 오탐을 정탐으로 씀.

**24. 정탐.** 외부입력 `date` 가 검증 없이 명령 문자열 `"cmd.exe /c C:\app\bin\kisaDB.bat"` 뒤에 연결돼 `Runtime.getRuntime().exec` 에 도달함. `& dir C:\` 처럼 DOS 명령어 구분자(`&` · `&&` · `|`)를 붙이면 배치파일 실행 뒤 임의 명령이 이어서 실행됨. [채점 키워드: 외부입력 / 검증 없이 명령 문자열 연결 / exec 명령어 실행 함수 도달] 개선: 멀티라인 특수문자(`| ; & :`)와 리다이렉트 문자(`> >>`)를 `replaceAll` 로 제거하거나, 명령어를 미리 지정해 두고 외부 입력으로는 선택만 하게 할 것. (가이드 원문 예제 기준)
- ⚠️ 문제 9(오탐)와 **같은 구조의 짝**임 — 배치파일 실행 명령에 외부입력을 연결하는 뼈대는 같고, 특수문자 제거 필터의 유무 하나로 판정이 갈림.

**25. 오탐.** 보고된 약점명(1-7 신뢰되지 않는 URL 주소로 자동접속 연결) 기준으로는 오탐임 — `sendRedirect` 등으로 **사용자 브라우저를 외부 주소로 이동시키는 코드가 없어** 피싱 유도가 성립하지 않음. [채점 키워드: sendRedirect 없음(브라우저 이동 아님) / 서버가 직접 요청 / 1-7 미성립] (재구성)
- ⚠️ **별건으로 1-12 서버사이드 요청 위조가 정탐임** — 외부입력 `target` 이 검증 없이 `new URL(target).openConnection()` 의 대상 주소가 돼 `http://127.0.0.1:8080/admin` · 내부망 IP 로 접근통제를 우회할 수 있음. 개선: 사전 정의 URL 맵의 키로만 대상을 선택(화이트리스트)하고 내부 URL 블랙리스트를 병행할 것.
- **셋을 가르는 판정 기준**: **누가 요청을 보내는가**로 갈림.
  - **1-7 자동접속 연결** — 서버가 **응답(Location 헤더)으로 사용자 브라우저를 이동**시킴. 피해자는 사용자 본인, 피해는 피싱. 표식은 `sendRedirect` · `redirect:` 임
  - **1-12 SSRF** — **서버가 스스로** 대상 주소로 요청을 보냄. 피해는 내부망 접근통제 우회. 표식은 `openConnection` · `RestTemplate` · `HttpClient` 임
  - **1-11 CSRF** — 요청 주체가 **공격자가 유도한 피해자 브라우저**이고, 서버가 「이 요청이 사용자가 의도한 것인가」를 토큰으로 확인하지 않는 것이 약점임. 표식은 **상태 변경 기능 + 토큰 검증 부재**이며 URL 파라미터가 없어도 성립함

**26. 정탐.** 주민등록번호(`ssn`)가 GET 요청의 질의문자열로 전달되고, 응답의 링크 `href` 에도 평문으로 다시 실려 나감. URL 은 브라우저 히스토리·프록시/웹서버 접근로그·`Referer` 헤더에 그대로 기록되므로 중요정보가 암호화·보호 없이 노출됨. [채점 키워드: 중요정보(주민등록번호) 평문 / URL 질의문자열 노출(로그·Referer) / 암호화·암호채널 미적용] 개선: 중요정보를 URL 파라미터로 전달하지 말고 POST 본문 또는 서버 세션에서 조회하도록 바꾸고, 전송 구간은 SSL/HTTPS 암호채널을 사용하며 저장 시에도 암호화할 것. (재구성)
- `[가정]` **항목 대응은 확정적이지 않음.** 이 문항은 **2-5 암호화되지 않은 중요정보**로 판단함 — 근거는 제3장 2-5 보안대책의 「중요정보는 전송·저장 시 반드시 암호화한다」·「필요한 경우 SSL 또는 HTTPS 등 암호채널을 사용한다」 문장이며, 노출 경로가 **전송 구간**이라 2-5 의 「평문 송·수신」에 해당함. 다만 **「GET 질의문자열 노출」이라는 표현 자체는 제3장 본문에 명시돼 있지 않음.**
- 경합 항목과의 구분: **1-11 CSRF** 는 「GET 방식보다 POST 를 사용한다」를 대책으로 두지만 약점의 본질이 **토큰 검증 부재**라 이 코드(조회 기능·상태 변경 없음)에는 맞지 않음. **4-1 오류 메시지 정보노출** 은 오류·예외 경로의 노출이라 해당 없음.
