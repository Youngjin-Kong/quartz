## 4. 복합서술형 모의 2세트 (각 8점 규모)

### 세트 A. 파일 업로드 기능 (전제: 요구사항 정의서 내용 이상 없음)

**요구사항 정의서(발췌)**: "첨부파일 업로드 시 허용된 파일 형식만 저장해야 하며, 업로드된 파일이 웹을 통해 직접 실행되지 않아야 한다."

**개발가이드(발췌)**: "업로드 파일은 확장자 화이트리스트(jpg, png, pdf)로 검증하고, 저장 경로는 web document root 외부로 하며, 저장 파일명은 난수화한다."

**공통모듈 소스**:

```java
String fileName = multipartFile.getOriginalFilename();
String ext = fileName.substring(fileName.lastIndexOf(".") + 1).toLowerCase();
if (ext.equals("jsp") || ext.equals("exe")) {
    throw new IllegalArgumentException("업로드 불가");
}
multipartFile.transferTo(new File("/var/www/html/upload/" + fileName));
```

**작성**: 보완요청서의 ① 현황 및 문제점(4점) ② 해결 방안(4점)

### 세트 B. 중요정보 암호화 기능 (전제: 요구사항 정의서 내용 이상 없음)

**요구사항 정의서(발췌)**: "회원 비밀번호는 복호화가 불가능한 방식으로 저장하고, 암호화 키는 소스코드와 분리하여 관리해야 한다."

**개발가이드(발췌)**: "비밀번호는 솔트를 적용한 SHA-2 이상 해쉬로 저장한다. 대칭키 암호화가 필요한 항목은 검증된 알고리즘(AES 등, 키 128bit 이상)을 사용하며 키는 암호화된 외부 설정에서 로드한다."

**공통모듈 소스**:

```java
private static final String CRYPTO_KEY = "a1b2c3d4";   // 8byte(64bit)
public String encryptPhone(String phone) throws Exception {
    SecretKeySpec key = new SecretKeySpec(CRYPTO_KEY.getBytes(), "DES");
    Cipher cipher = Cipher.getInstance("DES");
    cipher.init(Cipher.ENCRYPT_MODE, key);
    return Base64.getEncoder().encodeToString(cipher.doFinal(phone.getBytes()));
}
```

**작성**: 보완요청서의 ① 현황 및 문제점(4점) ② 해결 방안(4점) — 결함이 여러 개이므로 모두 지적할 것

# 해설 및 채점 키워드

## 정탐/오탐 15문항

**1. 정탐.** 외부입력 formula가 검증 없이 동적 코드 실행 함수 eval()의 인자로 도달. [채점 키워드: 외부입력 / 검증 없이 / eval(동적 코드 실행)] 개선: 화이트리스트·정규식으로 유효 문자만 허용.

**2. 오탐.** doctype 선언 금지(disallow-doctype-decl=true)와 외부 일반/파라미터 엔티티 비활성화 설정이 적용되어 외부개체 참조가 차단됨. [키워드: doctype 금지 / 외부 엔티티 비활성화 / setFeature]

**3. 정탐.** 외부입력 url이 검증 없이 서버 측 요청(openConnection)의 대상 주소로 사용되어 내부망 접근·접근통제 우회 가능. [키워드: 외부입력 URL / 검증 없이 / 서버 간 요청(openConnection) / 내부망] 개선: 사전 정의 URL 맵(화이트리스트) 키로만 선택.

**4. 오탐.** 이동 대상이 사전 정의된 화이트리스트 배열에서 인덱스로만 선택되고, 예외 시 기본 경로로 이동하므로 외부입력이 URL 자체가 될 수 없음. [키워드: 화이트리스트 / 인덱스 선택 / 임의 URL 불가]

**5. 정탐.** 외부입력 정수가 음수·상한 범위 검증 없이 배열 크기로 사용되어 예외·비정상 동작 가능. [키워드: 범위(음수) 검증 없이 / 배열 크기] 개선: 파싱 후 하한·상한 검사.

**6. 정탐.** 조작 가능한 쿠키 값(userRole)이 검증 없이 권한(관리자) 결정에 사용되어 보호메커니즘 우회 가능. [키워드: 쿠키(조작 가능한 외부입력) / 보안결정(권한) / 서버측 검증 없음] 개선: 권한 정보는 서버 세션에 저장·확인.

**7. 오탐.** 세션의 사용자 정보로 ACL(checkAccessControlList) 검사를 통과한 경우에만 삭제를 수행하므로 접근제어가 구현됨. [키워드: 세션 사용자 / ACL(권한 검사) 후 수행]

**8. 정탐.** 다운로드한 JAR을 서명 검증 없이(new JarFile(f) 기본, verify 미활성) 로드. [키워드: 서명 검증 없이 / 다운로드 파일 로드] 개선: new JarFile(f, true) + getCodeSigners()로 서명 주체 확인.

**9. 정탐.** 세션키(중요정보)를 담은 쿠키의 만료시간을 1년으로 설정해 영속 쿠키로 하드디스크에 저장됨. setSecure는 전송 보호일 뿐 저장 노출을 막지 못함. [키워드: 만료시간 과도(1년) / 영속 쿠키 / 중요정보(세션키)] 개선: 만료시간 최소화(세션 쿠키), 중요정보 미포함.

**10. 정탐.** 패스워드 해쉬 생성 시 솔트 없이 패스워드만 입력으로 사용 — 레인보우 테이블 공격 가능. [키워드: 솔트 없이 / 레인보우 테이블] 개선: 랜덤 솔트를 함께 update 후 저장.

**11. 오탐.** MAX_ATTEMPTS 카운터로 인증시도 횟수를 제한하고 초과 시 계정 잠금까지 수행. [키워드: 횟수 제한(카운터) / 초과 시 잠금]

**12. 정탐.** 멀티스레드 환경에서 파일의 검사(exists)와 사용(readFile) 사이에 동기화가 없어 검사시점과 사용시점의 자원 상태가 달라질 수 있음. [키워드: 검사시점/사용시점 / 동기화(synchronized) 없음 / 공유자원] 개선: 임계코드를 synchronized로 보호.

**13. 정탐.** 다중 스레드가 공유하는 @Controller(싱글톤) 클래스의 멤버 변수에 요청별 사용자 ID를 저장하여 세션 간 데이터가 섞여 노출될 수 있음. [키워드: 싱글톤(컨트롤러) 멤버 변수 / 요청별 데이터 / 세션 간 공유] 개선: 지역변수로 선언.

**14. 오탐.** private 배열의 레퍼런스를 그대로 반환하지 않고 복사본(arraycopy)을 만들어 반환하며, 원소가 String(불변)이라 복사본 반환으로 충분. [키워드: 복사본 반환 / 원소 불변(String)]

**15. 정탐.** 업로드 파일(공격자가 조작 가능한 바이트 스트림)을 검증 없이 readObject()로 역직렬화 — 원격 코드 실행 등 가능. [키워드: 신뢰할 수 없는 데이터 / 검증 없이 readObject / 역직렬화] 개선: 역직렬화 허용 클래스 화이트리스트(resolveClass 검증) 또는 서명 검증.

**자가채점**: 판단 정오 1점 + 키워드 적중(과반) 1점 + 개선방안(정탐 문항) 1점 기준으로 45점 만점 환산 → 70% 이상이 목표.

## 복합서술형 모의

**세트 A 모범답안**

- 현황 및 문제점(4점): 개발가이드는 **화이트리스트**(jpg, png, pdf) 검증을 요구하나 소스는 jsp·exe만 차단하는 **블랙리스트** 방식이어서 jspx, php, war 등 목록 외 실행 파일이 통과한다. 또한 저장 경로가 **web document root 내부**(/var/www/html/upload)이고 파일명 **난수화도 미적용**이라 업로드 파일이 URL로 직접 실행될 수 있다. [키워드: 블랙리스트(화이트리스트 위반) / 웹루트 내부 저장 / 파일명 난수화 미적용]
- 해결 방안(4점): 확장자 검증을 화이트리스트(jpg, png, pdf만 허용)로 변경하고, 저장 경로를 web document root **외부**로 이동하며, 저장 파일명을 난수 문자열로 변경한다(실행권한 제거 병행). [키워드: 화이트리스트 변경 / 웹루트 외부 / 난수화]

**세트 B 모범답안** (결함 3개 모두 지적해야 만점)

- 현황 및 문제점(4점): ① 암호화 키가 소스코드에 **상수로 하드코딩**되어 있어 "키는 외부 설정에서 로드" 규칙 위반(하드코드된 중요정보). ② 알고리즘이 **DES**로, 검증된 알고리즘(AES 등) 요구 위반(취약한 암호화 알고리즘). ③ 키 길이가 **64bit**로 대칭키 최소 **128bit 이상** 요구 위반(충분하지 않은 키 길이). [키워드: 하드코딩 / DES(취약 알고리즘) / 64bit(키 길이 미달)]
- 해결 방안(4점): 알고리즘을 **AES(CBC/PKCS5Padding 등)**로 교체하고 키 길이를 **128bit 이상**으로 생성하며, 키는 소스에서 제거해 **암호화된 외부 설정파일(또는 키 관리 시스템)에서 로드**하도록 수정한다. [키워드: AES / 128bit 이상 / 외부 설정 로드]
