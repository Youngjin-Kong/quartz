## 4. 기존 서술 1건을 «반증하여 정정»함 — `A-3-10`

기존 본문(반영 전):

> **일반 절차** — `no job control in this shell` 상태의 nc 리버스셸에서 `su` 가 거부될 수 있음. `su` 는 비밀번호를 stdin 이 아니라 **TTY 에서 읽으므로** `echo 'pass' | su -` 도 거부 환경에서는 안 통함.

**반증** — Kali 재확인(util-linux 2.41.2, 2026-08-26):
```bash
ssh kali@10.44.44.128 "echo 'wrongpass' | su root -c id"
```
```text
Password: su: Authentication failure
```
`su` 는 TTY 가 없어도 stdin 에서 비밀번호를 읽음. `must be run from a terminal` 계열 문구를 내는 것은 **`sudo`** 임(`a terminal is required to read the password; either use ssh's -t option or configure an askpass helper`). `su` 바이너리에는 그 문자열이 아예 없고 `--pty` 옵션 설명만 있음.

**제목·번호는 그대로 두었음**(앵커 보호). 본문만 정정하고 근거·[[Codo]]·[[Zipper]] 실측을 붙였음. 옛 서술 전문은 위에 인용해 두었으므로 복원 가능함.
