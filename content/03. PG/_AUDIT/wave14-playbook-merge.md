## 3. 반증한 것

### 3-1. 상충하는 두 제안을 Kali 실측으로 갈랐음 — pyLoader P10 ↔ RubyDome P3

두 제안이 `curl` 플래그에 **정반대 결론**을 적어 그대로 넣었으면 서로 모순되는 카드 둘이 생겼을 자리임.

- pyLoader P10 — 「페이로드가 이미 퍼센트 인코딩됐으면 `--data-binary`. `--data-urlencode` 는 이중 인코딩으로 죽인다」
- RubyDome P3 — 「`%20` 이 살아야 하므로 `--data-urlencode`. `-d` 는 서버가 진짜 공백으로 바꿔 죽인다」

**둘 다 옳음.** 축은 플래그가 아니라 **「그 `%XX` 가 «디코드된 바이트»로 도착해야 하는가, «리터럴 문자열»로 도착해야 하는가」**임. Kali 에서 요청 본문을 `nc` 로 캡처해 확정:

```text
--data-binary 'jk=pyimport%20os'    -> jk=pyimport%20os
-d 'jk=pyimport%20os'               -> jk=pyimport%20os      (인라인은 --data-binary 와 동일)
--data-urlencode 'jk=pyimport%20os' -> jk=pyimport%2520os
python requests data={'jk':'pyimport%20os','s':'a b','p':'a+b'}
                                    -> jk=pyimport%2520os&s=a+b&p=a%2Bb
```
```text
-d @file            -> a=1b=2      (개행 제거)
--data-binary @file -> a=1\nb=2    (개행 보존)
```

→ **`A-2-30` 한 카드로 통합**하고 판정표에 실측값을 그대로 실었음. 부수로 두 사실이 확정됨 — ⓐ `-d` 와 `--data-binary` 는 **인라인에서는 동일**하고 `@파일`에서만 갈림(pyLoader P10 의 서술이 맞음) ⓑ **Python `requests` 는 `+` 를 `%2B` 로 감싸므로 base64 의 `+` 문제가 없음** — RubyDome P3 이 「단 공백은 `+` 가 됨」만 적고 이 점을 안 적었음.
