## 제안 1 — 쿠키 기반 가짜 잠금에 손이 걸림 (25분)

①어느 절: **A-2 그룹(진입/foothold)** — A-2-12(웹 로그인 잠금) 인접, 성격은 다름(서버 잠금이 아니라 클라이언트 쿠키뿐인 가짜 잠금)
②병합/신규: **신규**
③넣을 본문:
> 로그인 잠금이 서버 카운터가 아니라 클라이언트 쿠키(`login_attempts`)에만 있는 앱을 만나면, 쿠키 단지를 재사용하는 수동 테스트(`curl -c ck.txt -b ck.txt`)가 오히려 자기 자신을 잠근다. hydra 처럼 쿠키를 안 보내는 도구는 이 잠금을 아예 못 받아 오히려 안전하다. 응답 크기 차이(예: 8507B vs 8513B)를 "플래시 메시지가 쌓였겠지"로 넘기지 말고 반드시 본문을 열어 확인할 것 — 재현 조건(쿠키 유무)을 바꿔 뜬 diff 는 원래 관측을 반증하지 못한다.
④지우기 전 원문 인용:
```

20:11 KST 에 수동으로 7개 조합을 돌렸다.

  out=$(curl -s -m 20 -c ck.txt -b ck.txt -d "login=admin&password=$p&login_submit=Log+In" \
        'http://192.168.248.180/blog/admin/' -o /dev/null -w '%{http_code} %{redirect_url} %{size_download}')
  echo "admin:$p -> $out"
done

**증거는 화면에 있었다.** 앞의 다섯은 8507, 뒤의 둘만 8513. 6바이트 차이. 그걸 보고도 "플래시 메시지가 쌓였겠지"로 넘겼다. 더 나쁘게는, 곧바로 쿠키 없이 두 응답을 다시 받아 `diff` 를 떠서 차이 없음을 확인하고 오판을 확정지었다 — 쿠키가 없으니 밴이 안 걸린 게 당연했다.

교훈 두 개.
- **로그인 시도를 반복할 때 쿠키 단지를 공유하지 마라.** 시도마다 `-c` 를 새 파일로 하거나 아예 쿠키 옵션을 빼라.
- **응답 크기 차이는 반드시 본문을 열어봐라.** "왜 다른지"를 설명하지 못하면 넘어가면 안 된다. 재현 조건(쿠키 유무)을 바꿔서 뜬 diff 는 원래 관측을 반증하지 못한다.

이 사고 덕에 hydra 가 왜 통했는지도 설명된다. **잠금이 클라이언트 쿠키에 있어서 쿠키를 안 보내는 hydra 는 잠금을 못 받는다.** 소스를 읽고서야 알았다.
```

## 제안 7 — 안 통한 것들 표 (SMB null·경로우회·XPath·CVE-2024-4577·exif·UDP)

①어느 절: **A-2 그룹 전체(신규 항목) + XPath 행은 B-16(XPath injection) 병합 후보 + CVE-2024-4577 행은 B(윈도우/웹) 신규 카드 후보** — 세부는 관리자 판단
②병합/신규: **혼합** — XPath 행만 B-16 병합 시도, 나머지는 신규 한 항목으로 통합 제안
③넣을 본문 (신규 A 항목):
> Monster 에서 확인 후 폐기한 벡터 표 — SMB null/guest 세션 완전 거부, `/blog/storage/database/*.xml` 직접 읽기(Monstra 가 `storage/.htaccess` 에 `Deny from all` 로 출하), 경로 우회(`//`,`/./`,대소문자) 전부 403, 로그인/비밀번호재설정 XPath 인젝션(직후 동등검사가 막음), XAMPP `php-cgi.exe` CVE-2024-4577(엔드포인트는 있으나 이 로케일에서 안 움직임 — best-fit 문자 매핑은 CJK 코드페이지 전제로 알려져 있고 확인 못함, **[가정]**), 이미지 exif/strings 무소득, UDP top-100 무소득.
③-XPath 넣을 본문 (B-16 병합용):
> [[Monster]] 반증 사례 — Monstra 로그인/재설정의 `select("[login='...']")` 는 XPath 인젝션 자리로 보이나, 바로 다음 줄 `$user['login'] == Request::post('login')`(재설정은 `$user['hash'] == $_GET['hash']`) 동등검사가 막는다. 인젝션 문자열을 넣으면 반환된 값과 POST 원문이 달라져 통과하지 못함 — **XPath 인젝션은 결과 재검증 한 줄로 쉽게 무력화된다는 반증 사례.**
④지우기 전 원문 인용:
```
### 5. 안 통한 것들 (전부 확인 후 폐기)

| 시도 | 결과 |
|---|---|
| SMB null / guest 세션 | `NT_STATUS_ACCESS_DENIED` / `NT_STATUS_ACCOUNT_DISABLED`. `rpcclient -U '' -N` 도 `Cannot connect`, `enum4linux-ng` 도 세션 실패 |
| `/blog/storage/database/users.table.xml` 직접 읽기 | 403. Monstra 가 `storage/.htaccess` 에 `Deny from all` 을 넣어 출하한다 |
```
