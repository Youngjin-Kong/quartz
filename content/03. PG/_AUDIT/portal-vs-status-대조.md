# 포털 Completed vs `_STATUS.md` 대조

작성 2026-08-20. 포털 조회는 하지 않았다 — 포털 쪽 사실은 총괄이 직접 확인해 넘긴 두 가지(**22/283 Completed, XP 285** · **Bratarina 1/1**)만 쓴다. 나머지 포털 칸은 전부 `확인필요`이고 총괄이 브라우저로 채운다.

## 0. 결론 먼저

**"10개 차이"는 단일 원인의 오프셋이 아니다. 반대 방향의 오류 둘이 상쇄돼 10으로 보인 것이고, 실제 간극은 최소 14다.**

| | |
|---|---:|
| `_STATUS.md` 완료 | 32 |
| 미착수 목록에 있으나 **실제로는 solved** (§3) | +4 |
| **볼트가 아는 실제 완료** | **36** |
| 포털 Completed | 22 |
| **미제출 또는 미완결 후보** | **14 이상** |

총괄이 관측한 `32 − 22 = 10` 은 **미분류 solved 4개가 간극을 4만큼 가려서** 나온 수다.

간극의 원인은 최소 셋이고, 서로 구별해야 한다.

1. **오분류** — solved 인 박스가 미착수 목록에 있다. 4건 확정(§3).
2. **미제출** — 풀었는데 포털에 값을 넣지 않았다. 가설이며 미검증(§4).
3. **미완결** — `_STATUS.md` 가 `1/1` 로 적었지만 실제로 2플래그 박스라면 포털은 Completed 로 찍지 않는다. 후보 3건(§5).

## 1. 가설 검증 결과

총괄이 준 가설은 **"볼트 완료 = 셸+플래그 / 포털 Completed = 제출"** 이었다.

- **반증하지 못했다** — 미제출 박스가 존재할 개연성은 남아 있다.
- **그러나 이 가설만으로는 간극이 설명되지 않는다.** 오분류 4건(§3)은 제출 여부와 무관한 별개 원인이고, 이것을 먼저 빼지 않으면 미제출 규모를 14가 아니라 10으로 과소평가하게 된다.
- **날짜 기준의 하위가설("최근 파이프라인 박스는 제출됐고 6~7월 레거시는 미제출")도 세워봤으나 성립하지 않는다.** 8월 파이프라인 박스 20개 + Bratarina = 21 로 22에 하나 모자라고, 반대로 레거시 전부가 제출됐다고 놓으면 8월 박스 대부분이 미제출이어야 하는데 Algernon·Pebbles 노트에 제출 기록이 실측으로 남아 있어 모순이다. **어느 쪽도 확정 못 한다 — 포털 조회가 필요하다.** `[가정]`

## 4. 부재 증거 — 「산출물 없음」을 「안 풀었다」로 읽지 마라

`~/PG/` 에 디렉터리가 아예 없는 solved 박스가 **Kevin · Slort** 둘이다. 그러나 두 노트 모두 타겟측 `dir` 출력이 실측으로 남아 있다.

- `Kevin.md:783` — `06/29/2026  08:59 PM                34 proof.txt`
- `Slort.md:391` — `06/29/2026  10:20 PM                34 proof.txt`

**2026-06-29 는 스크린샷이 34장 있는 날이다.** 볼트 `파일보관\` 전체에서 단일 날짜 최다에 해당한다. `~/.zsh_history` 는 리버스셸 안에서 친 명령을 기록하지 않으므로, 이날은 **손으로 깊이 판 날인데 Kali 쪽에 파일을 안 남긴 것**으로 읽는 편이 정합적이다.

→ **Kevin·Slort 의 판정 등급 상한은 `근거부족` 이다. 「미해결」로 단정할 근거가 없다.**

타임존 주의: 위 `dir` 시각은 **타겟 머신 기준**이라 로컬(KST)과 최대 하루 어긋난다. 실제로 Access 노트의 `06/30/2026 05:07 PM` 은 Kali 산출물 mtime `07-01` 과 대응한다. 스크린샷 날짜 매칭은 이 오차를 감안해 읽어야 한다.

## 6. 세 번째 위험 — 값이 스크린샷에만 있는 박스

**Pelican · Sorcerer · Zipper** 는 `local.txt` 값이 노트 텍스트에 없고 스크린샷에만 있다. 세 노트 중 둘은 이 사실을 스스로 「이 노트의 실수」로 적어뒀다.

미제출로 판명되면 **랩이 리버트돼 값이 이미 바뀌었을 것이므로 다시 풀지 않으면 제출할 수 없다.** 재작업 비용이 붙는 유일한 그룹이라 우선순위가 다르다.

## 8. 총괄이 포털에서 채울 것 — 우선순위 순

1. **§5 후보 3개의 진행도 표기** — Hutch · MiddlewareBypass · Pebbles 가 `1/1` 인가 `1/2` 인가. 이것 하나로 원인 둘이 갈린다.
2. **§3 의 Access · Slort · CVE-2025-10952** — Completed 면 `_STATUS.md` 오분류 확정, 아니면 미제출 확정. 어느 쪽이든 즉시 반영 가능.
3. **§2 의 32개 진행도 일괄 확인** — 포털 목록 페이지에 박스별 `n/m` 이 그대로 뜬다. 한 화면으로 14건의 정체가 전부 확정된다.
4. **Cockpit · Nagoya · Jacko 진행도** — §9 참조. 이 셋이 Completed 면 간극은 14보다 커진다.

XP 285 를 역산해 완료 목록을 추정하려 했으나 **쓰지 않기로 했다.** OffSec XP 는 PG Practice 외 활동(코스·챌린지랩)에서도 누적되므로 분해가 성립하지 않고, 플래그당 XP 도 Algernon 의 `+5` 한 건밖에 실측이 없다. 근거 하나로 세운 산식은 확정처럼 보이는 추측이 된다. `[가정]`
