# `_AUDIT/` — 작업 산출물 보관소

에이전트가 낸 **긴 리포트**가 여기 쌓인다. 총괄에게는 5줄 요약과 이 경로만 올라가고, 전문은 필요할 때만 읽는다.

총괄은 하나인데 에이전트는 열이다. 리포트 전문을 총괄 컨텍스트로 반환하면 총괄이 병목이 된다 — 실제로 한 건이 220k 토큰이었다. 그래서 데이터를 컨텍스트 밖으로 뺀다.

## 파일명

```
<박스명>-<작업>.md
```

`<작업>` 은 `audit`(적대적 검증+정정) · `forge`(개작·신규 작성) · `run`(박스 풀이) 중 하나.

예: `Squid-audit.md` · `Twiggy-forge.md` · `Bratarina-run.md`

같은 박스를 다시 감사하면 **덮어쓰지 말고** `-audit2` 로 붙여라. 판정이 뒤집힌 이력 자체가 자료다.

## 프론트매터

```yaml
---
tags:
  - type/report
  - platform/pg
publish: false
---
```

`publish: false` 를 **반드시** 넣어라. 이 볼트는 quartz 로 발행되는데 감사 기록까지 나갈 이유가 없다.
`tech_count`·`manual_tags` 는 넣지 마라 — 색인 도구가 머신 노트로 오인한다.

## 본문

정해진 틀은 없다. 다만 총괄이 나중에 이 파일만 읽고 판단할 수 있어야 하므로:

- **위치는 파일:행이 아니라 문자열로** 적어라. 노트를 고치면 행번호가 밀린다.
- **삭제한 원문은 전문 인용**하라. 되살릴 수 있어야 한다.
- **근거를 어디서 얻었는지** 적어라 — Kali 산출물 경로 / git 커밋 / 1차 사료 URL / 직접 실행한 명령.
- **반증에 실패한 것**(= 노트가 옳았던 것)도 적어라. 검증 절차 자체의 정확도를 총괄이 판단해야 한다.

## 정리

박스가 완료되고 노트가 안정되면 해당 `_AUDIT` 파일은 지워도 된다. 다만 **판정이 한 번이라도 뒤집힌 건은 남겨라** — 같은 실수를 반복하지 않게 하는 기록이다.
