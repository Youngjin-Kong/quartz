## 3. 반증한 것 — 지적으로 올랐다가 확인 결과 노트가 옳았던 것

지시받은 3건의 「작성자 반증」은 **셋 다 진짜 반증이었다.** 새 창작이 아니다.

1. **`/tmp` nosuid 건 — 작성자가 옳다.** `harvest_bob.txt` 1185행부터의 `===== MOUNTS =====` 전문을 직접 읽었다. `/tmp` 항목이 **존재하지 않고**, `/dev/sda2 on / type ext4 (rw,relatime)` 만 있으며 `-- fstab --` 에도 `/tmp` 엔트리가 없다(`/dev/disk/by-uuid/… / ext4 defaults 0 0` 와 swap 뿐). `nosuid` 가 붙은 것은 `tmpfs on /dev/shm type tmpfs (rw,nosuid,nodev)` 쪽이다. 따라서 산출물 `traces_confirmed.log` 의 `/dev/shm & /tmp are nosuid anyway` 가 **틀렸고**, 노트가 그것을 지적한 것이 맞다.
2. **nmap 서비스 문자열 복원 — 작성자가 옳다.** `.bak` 43행은 `22/tcp open  ssh   OpenSSH 8.2p1 Ubuntu 4ubuntu0.4` 로 `(Ubuntu Linux; protocol 2.0)` 가 잘려 있었다. `nmap.log` 원문은 잘리지 않은 형태이고, 개작본이 원문과 **완전히 일치**한다.
3. **`bash -p` 서술 — 작성자가 옳다.** Kali `man bash` 를 직접 렌더해 확인했다. 해당 문단 원문 요지 — euid≠ruid 로 시작했고 `-p` 가 없으면 시작 파일을 읽지 않고 `SHELLOPTS`·`BASHOPTS`·`CDPATH`·`GLOBIGNORE` 를 무시하며 **effective user id 가 real user id 로 설정된다**. `-p` 가 있으면 effective user id 를 되돌리지 않는다.

추가로 반증한 것:

4. **objdump 블록은 창작이 아니다.** `~/PG/Wheels/get-list` 를 **재실행**해 `<main>` 전체와 대조했다. 노트의 16행이 주소·바이트열·니모닉까지 **전부 일치**한다(`124f`·`1257`·`1260`·`1268`·`127a`·`1282`·`1294`·`129c`·`12bb`·`12d6`·`1418`·`1425`·`1462`·`1467`·`1469`·`1478`). 필터 3종·`strstr` OR 구조·`snprintf` 0xc8·`geteuid`→`setuid`→`system` 순서 모두 실물이다. 이 블록은 개작에서 가장 의심스러워 보였으나 **가장 확실한 실측**이다.
5. **`works.xml` 6명 전원 — 산출물과 완전 일치.** 탭 들여쓰기까지 `works_xml.txt` 와 같다.
6. **`config.php`·`register.php` 폼·`portal.php` 게이트 코드 — 전부 실물.** `portal.php` 인용의 「55–80행」이라는 행번호도 날조가 아니다. `collect.sh` 가 실제로 `sed -n '55,80p' /var/www/html/portal.php` 를 돌렸다.
7. **`pwn.sh` 인용 — 셰뱅 한 줄 빼고 바이트 일치.**
8. **시간 서사에 모순 없음(타임존 환산 확인).** `proof_user.txt` 본문 `Thu 20 Aug 2026 07:11:31 PM UTC` = KST 04:11:31 → 파일 mtime `2026-08-21 04:11:31.861 +0900`. `proof_root.txt` 는 `07:15:53 PM UTC` → mtime `04:15:53.275 +0900`. **초 단위까지 일치**한다.

## 5. 총괄에 올릴 것 — `_PLAYBOOK` A-22 의 한 줄

내 편집 범위 밖이라 고치지 않았다. `03. PG\_PLAYBOOK.md:109`:

> **동시성을 40→48 로 올렸는데 속도가 938→215/min 으로 «떨어진» 것**이 bcrypt 의 직접 증거(CPU 포화)

두 수치는 **동시 실행된 두 워커가 아니라 시각이 다른 별개의 두 run** 이다 — admin 은 03:05:47 시작, bob 은 03:18:25 시작이고 겹치지 않는다(`hydra_admin.full.txt`·`hydra_bob.full.txt` 헤더). 따라서 「동시성을 올렸더니 떨어졌다」는 통제된 비교가 아니고, **bcrypt 의 «직접 증거»** 라는 등급은 과하다. 두 run 사이에 다른 부하가 있었을 가능성을 배제할 자료가 없다.
같은 이유로 이 노트에서는 bcrypt 단정을 `[가정]` 으로 내렸다. `_PLAYBOOK` 쪽도 「신호」 등급으로 맞추는 것이 일관된다.

## 6. 관측만 남기는 것 (고치지 않음)

- **`### Initial Access` 제목이 두 개**다(33행 4항목 블록, 126행 서술 블록). 관리자가 「구조 검산 통과」로 확정했으므로 손대지 않았다. 다만 같은 레벨의 동일 접두 제목이라 Obsidian 앵커가 모호해진다 — 다른 노트에서 `[[Wheels#Initial Access …]]` 로 걸 일이 생기면 문제가 된다.
- **`### Initial Access`(33) 가 `### Service Enumeration`(54) 보다 앞에 온다.** 이것도 확정 범위라 두었다.
- **문체 이관 0건.** 서술형 종결·번역투로 `pg-doc-reviewer` 에 넘길 건은 발견되지 않았다. 개작본은 이미 명사 종결형 개조식이다.

## 7. 색인

- `manual_tags: true` / `manual_cves: true` 유지. `tech/*` 5개(`enum/dirbust`·`web/auth`·`web/xpathi`·`rce/cmd`·`lin/suid`)는 전부 실제 사용 기법이고 `tech_count: 5` 와 맞는다. 본문의 CVE-2021-41773·42013 은 **반증용 언급**이라 `manual_cves` 로 차단되는 것이 옳다.
- `ports: [22, 80]` 유지. nmap raw 행(`22/tcp open …`·`80/tcp open …`) 보존 확인 — `extract.py` `PORT_RE` 가 긁을 수 있다.
- **색인 갱신 필요.** 행수·본문이 바뀌었다. `refresh.ps1` 은 규율대로 돌리지 않았다.
