## 6. 총괄 판단이 필요한 것 — 색인 파급

이관으로 `_PLAYBOOK.md` 본문에 CVE 6개가 새로 들어옴.

```
이관 전(.bak2): CVE-2024-32651
이관 후:        + CVE-2019-10149 · CVE-2021-44142 · CVE-2022-25018
                + CVE-2022-26123 · CVE-2022-26134 · CVE-2024-48138
```

- `extract.py` 는 `_PLAYBOOK.md` 를 **meta.json 에 넣는다**(walk 제외 목록에 `_AUDIT`·`_INDEX`·`파일보관` 등만 있고 `_PLAYBOOK` 은 없음)
- `build_index.py` 의 CVE 색인은 프론트매터가 아니라 **meta.json 의 `cves`** 로 만들어짐
- 따라서 다음 `refresh.ps1` 실행 시 CVE 색인에 **`_PLAYBOOK` 이 7개 CVE 의 참조 노트로 등장**함
- 그중 **CVE-2019-10149 와 CVE-2022-25018 은 본문이 「이 박스는 여기 해당하지 않았다」고 반증하려 적은 번호**임. `CLAUDE.md` §5 가 `manual_cves` 를 두는 바로 그 이유에 해당
- `tech/*` 자동 판정도 같은 경로로 파급됨 — `_PLAYBOOK` 이 다수 기법 색인에 등장하게 됨

**감사자가 고치지 않은 이유** — `_PLAYBOOK.md` 프론트매터는 `tech_count`·`manual_tags`·`manual_cves` 중 어느 것도 없어 `inject.py` 가 「수동 프론트매터 보존」으로 건너뛰는 상태임. 여기에 `manual_cves: true` 를 넣으면 `ours` 판정이 뒤집혀 **`inject.py` 가 기존 블록을 제거하고 자기 형식으로 재작성**함. 그러면 손으로 넣은 `tags: type/index · platform/pg` 가 `DECL_TAG_RE`(`tech/` 만 매칭)에 걸리지 않아 소실될 수 있음. **공유 인프라 사안이므로 총괄에 올림**(`CLAUDE.md` §8).

선택지 — ⓐ `extract.py` 의 `NOT_A_NOTE`/walk 제외에 `_PLAYBOOK.md`·`_STATUS.md` 류 메타 문서를 추가 ⓑ `_PLAYBOOK` 프론트매터에 `manual_cves: true` + `manual_tags: true` 를 넣되 `build_fm` 의 태그 보존 동작을 먼저 확인 ⓒ 현상 유지(색인에 메타 문서가 섞이는 것을 허용).
