# PG writeup 작성 표준 — OSCP 시험 대비용

> [!abstract] 이 문서의 목적
> `03. PG/<박스명>.md` 는 재현 기록이 아니라 **OSCP 시험 대비 학습 자료**다.
> 판단 기준은 하나다 — **"시험장에서 이 노트가 나를 구해주는가?"**
> 시험은 24시간 안에 낯선 박스 여러 대를 뚫어야 하고, **인터넷 검색은 되지만 시간이 없다.** 그래서 노트는 **"이 상황에서 다음에 뭘 쳐야 하는지"**를 즉시 알려줘야 한다.

## OSCP 시험 제약 — 노트에 항상 반영할 것

| 제약 | 노트에 미치는 영향 |
|---|---|
| **자동 익스플로잇 도구 금지** — `sqlmap`, `metasploit`(1대 한정), `автоexploit` 계열, AutoRecon 등 | **수동 방법을 반드시 함께 기록**한다. sqlmap으로 풀었어도 **수동 payload를 별도로 적어라.** 자동 도구만 적힌 노트는 시험장에서 무용지물 |
| **msfvenom·nc·수동 스크립트는 허용** | 페이로드 생성 명령은 정확히 기록 |
| **24시간 제한** | "이 단계에서 얼마나 걸렸는가", "언제 손절했어야 하는가"를 적는다 |
| **증거 스크린샷 필수** | 플래그는 `whoami`/`hostname`/`ip a`와 **한 화면에** 찍어야 인정된다. 이 관례를 노트에도 반영 |
| **재부팅/리버트 시 재현 필요** | 원샷 트릭이 아니라 **재현 가능한 절차**로 적는다 |

> [!danger] 시험 금지 도구를 썼다면 반드시 표시하라
> 노트에 `⚠️ 시험 금지` 태그를 달고 **바로 아래에 수동 대안**을 적는다.
> 예: sqlmap으로 확인했다면 → 수동 `' UNION SELECT sleep(5)-- ` 와 blind 추출 절차를 함께.

## 원칙 6가지

1. **메커니즘을 설명한다.** CVE 번호와 페이로드만 적으면 복붙 노트다. **코드/프로토콜 수준에서 왜 뚫리는지** 쓴다. 시험에는 같은 CVE가 안 나오지만 **같은 유형**은 나온다.
2. **명령의 플래그를 해설한다.** `--path-as-is`·`-p`·`-R`·`-f`·`--data-urlencode`가 왜 필요한지, **빼면 어떻게 실패하는지**까지.
3. **실패와 막다른 길을 기록한다.** 시험장에서 시간을 태우는 건 성공 경로가 아니라 **잘못된 가정**이다. 무엇을 시도했다 왜 안 됐는지가 다음 박스를 구한다.
4. **일반화한다.** "이 박스는 이랬다" → **"이런 신호를 보면 이렇게 접근한다"** 로 승격.
5. **수동 대안을 항상 병기한다.** 시험 제약 때문이다.
6. **방어 관점을 한 줄.** OSCP 보고서에 remediation을 써야 한다.

## 노트 구조

```markdown
> [!info] 상단 요약
> 타겟 / OS / 난이도 / 플래그 수 + 경로 한 줄

## 0. 이 박스에서 배우는 것
- 핵심 기법 3~5개
- **시험 출제 가능성**: 이 유형이 실제 시험에 나올 법한가, 변형은 어떤 모습일까

## 1. 정찰
### Nmap                      원문 + "이 줄이 왜 중요한가"
### 서비스 식별                버전 판정 근거 (출처 2개 이상 교차)
### 열거                      디렉터리/엔드포인트 + **스캐너 함정**

## 2. 취약점 분석              ← 학습용 노트의 핵심
### 배경 지식                  이 취약점 클래스가 무엇인가
### 왜 취약한가                취약 코드 원문 + 데이터 흐름
### 왜 이 페이로드인가          페이로드를 조각내어 각 부분의 역할

## 3. Foothold
명령 전문 + 원문 출력 + 각 단계에서 무슨 일이 일어나는지
**⚠️ 자동 도구를 썼다면 수동 대안 병기**

## 4. 권한상승
### 열거로 무엇을 발견했는가     `id`·`sudo -l`·`find -perm`·`getcap`·`crontab` 출력과 **읽는 법**
### 왜 그것이 권한상승이 되는가  메커니즘
경로가 둘 이상이면 전부 기록하고 우열 비교

## 5. 플래그                   위치 + 값 (표준 위치가 아니면 그 이유)

## 6. 막혔던 지점 / 시행착오    ← 반드시 채운다
무엇을 시도했다 실패했는가 · 왜 · 어떻게 알아챘는가 · 얼마나 걸렸는가

## 7. OSCP 시험 관점           번호 목록
- 일반화된 교훈
- **수동 대안** (자동 도구 금지 대비)
- **시간 배분** 관점 — 어디서 손절했어야 하는가

## 8. 방어 관점                어떻게 막았어야 하는가

## 9. 참고 자료                CVE 링크 · GTFOBins · 원 익스플로잇 출처
## 남긴 흔적 / 관련 노트
```

## 반드시 포함할 "시험 반사" 항목

노트를 쓸 때 아래 질문에 답이 없으면 **아직 덜 쓴 것**이다:

- [ ] 셸을 잡자마자 칠 명령 5개는? (`id` · `sudo -l` · `find / -perm -4000` · `getcap -r /` · `crontab -l`/`/etc/crontab`)
- [ ] 이 서비스를 다시 만나면 **가장 먼저** 확인할 것은?
- [ ] 자동 도구 없이 같은 결과를 얻는 방법은?
- [ ] 이 단계에서 실패했다면 **다음 후보 경로**는 무엇이었나?
- [ ] 리버스셸이 안 붙으면 뭘 의심하나? (아웃바운드 포트 제한 · 방화벽 · 인라인 블로킹)

## 분량 기준

- **최소 300행.** 학습용이므로 짧으면 부실한 것이다.
- **취약점 분석(2장) + 시행착오(6장)가 전체의 40% 이상.**
- 터미널 원문은 아끼지 말되 **각 블록 앞뒤에 해설 문장**을 둔다. 원문 나열만으로는 학습 자료가 아니다.

## 스크린샷

- **웹 UI·관리자 패널·대시보드·버전이 보이는 화면**은 캡처해 넣는다.
- **터미널 출력은 캡처하지 않는다** — 코드블록이 검색·복사가 된다.
- 단, **시험 증거 형식 연습**을 위해 플래그 획득 시점은 `whoami; hostname; ip a; cat proof.txt`를 한 화면에 담는 습관을 노트에도 남긴다.
- 절차:
  ```bash
  chromium --headless --disable-gpu --no-sandbox --hide-scrollbars \
    --window-size=1280,860 --screenshot=/tmp/x.png http://TARGET/
  scp kali@10.44.44.128:/tmp/x.png "<볼트>/파일보관/PG-<박스>-<내용>.png"
  ```
  노트에서 `![[PG-<박스>-<내용>.png]]`

## frontmatter — 태그는 손으로 관리한다

> [!danger] 노트를 다 쓰면 **반드시** frontmatter에 `manual_tags: true` 를 넣어라
> `_INDEX/_tools/extract.py` 는 본문 키워드로 기법 태그를 자동 판정한다.
> 그런데 이 표준대로 쓴 노트는 **배경 지식·대안 경로·GTFOBins 비교표**에서 실제로 쓰지 않은 기법을 대량으로 언급한다. 자동 판정은 그것까지 잡아내 **과잉 태깅**이 된다.
> 실측: Crane 6개 → 21개, Squid 4개 → 19개, Osaka 7개 → 18개(쓰지도 않은 `ad/pth`·`mimikatz`가 붙었다).
>
> `manual_tags: true` 가 있으면 `extract.py` 가 **본문 스캔을 건너뛰고 프론트매터에 적힌 `tech/*` 태그를 그대로 쓴다.**
> `ip`·`ports`·`services`·`cves`·`status` 는 계속 자동 갱신되므로 **`refresh.ps1` 은 정상 동작한다.**

작성 예:

```yaml
---
tags:
  - type/machine
  - platform/pg
  - os/linux
  - status/solved
  - tech/web/sqli          # ← 실제로 쓴 기법만
  - tech/db/mysql
  - tech/payload/revshell
type: machine
platform: pg
os: linux
status: solved
manual_tags: true          # ← 이 줄이 자동 태거를 멈춘다
---
```

**판단 기준: "내가 이 박스를 뚫는 데 실제로 사용했는가."**
설명만 하고 쓰지 않은 기법은 태그하지 않는다 — 태그는 검색 색인이지 목차가 아니다.

노트를 저장한 뒤 색인을 갱신한다:

```powershell
& "C:\Users\QQ\Documents\Obsidian Vault\_INDEX\_tools\refresh.ps1"
```

## 상호 링크

같은 기법·같은 함정이 다른 박스에서 나오면 **양쪽 노트에 서로 링크**한다. 누적되면 그 자체가 패턴 색인이 된다.
현재 누적 중인 패턴: "응답이 성공을 뜻하지 않는다"([[Crane]] · [[RubyDome]] · [[Astronaut]] · [[Exghost]] · [[Hawat]] · [[Squid]]), "버전 판정은 독립 근거 2개"([[Hub]] · [[Levram]] · [[RubyDome]] · [[Astronaut]] · [[Squid]]), "크론 기반 권한상승"([[Astronaut]] · [[Exfiltrated]] · [[Muddy]]), "인용이 깨지면 인코딩으로 도망간다"([[Hawat]] hex · [[Exfiltrated]] base64 · [[Squid]] hex+`-enc`+배치래핑).
