복기
이제 보입니다 — **Apache 기본 "Index of /"가 텅 비어 있습니다.** 디렉토리 리스팅은 켜져 있는데 루트에 파일이 없어요. 이건 "막다른 길"이 아니라 **"진짜 콘텐츠가 다른 곳에 숨어 있다"** 는 강력한 신호입니다. 즉 이 박스의 foothold는 **전적으로 디렉토리/파일/vhost 열거**에 달려 있었어요.

**여기서 했어야 할 것 (이게 전부):**

**1) 디렉토리·파일 브루트포싱 — 제대로**

bash

```bash
feroxbuster -u http://192.168.91.110 \
  -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
  -x php,txt,html,zip,bak -t 50
```

안 나오면 **워드리스트를 바꿔가며** 재시도 (raft-large, directory-list-2.3-big). "없다"가 아니라 "이 단어장엔 없다"입니다.

**2) ★가장 의심되는 부분 — 당신의 과한 필터**

전에 당신이 쓰던 명령이 `-s 200 -t 200` 이었죠. **`-s 200`은 디렉토리의 301 리다이렉트를 숨깁니다.** 즉 숨은 디렉토리가 있어도 301로 응답하면 화면에 안 떠서 **"텅 비었다"로 착각**하게 됩니다. 이 박스에서 막힌 게 **바로 이것일 가능성이 높습니다.** `-s 200` 빼고 기본 상태코드(301/302/403 포함)로 돌렸다면 숨은 경로가 보였을 거예요.

**3) vhost 열거 — 빈 기본 docroot의 전형적 단서**

기본 페이지가 비어 있으면 **진짜 사이트가 가상호스트(vhost)에 있는** 경우가 많습니다:

bash

```bash
ffuf -u http://192.168.91.110 -H "Host: FUZZ.offsec" \
  -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -fs <기본크기>
gobuster vhost -u http://192.168.91.110 -w subdomains.txt --append-domain
```

**4) 기본 확인**

bash

```bash
curl -s http://192.168.91.110/robots.txt
whatweb http://192.168.91.110
nikto -h http://192.168.91.110
```

**복기 결론:** 이 박스는 **"빈 웹루트 → 숨은 경로/vhost를 찾아라"** 형이었고, 정답은 **워드리스트를 바꿔가며 끈질기게 디렉토리 브루트포싱 + vhost 퍼징**이었습니다. 그리고 십중팔구 당신이 막힌 진짜 이유는 기법을 몰라서가 아니라 **`-s 200` 같은 과한 필터로 301 디렉토리를 못 본 것** — 화면이 "비어 있으니 여기 아무것도 없네" 하고 넘어간 거죠.

이게 우리가 계속 얘기한 그 지점입니다: **"비어 보인다 = 없다"가 아니라 "내가 제대로 안 봤다"**. 지금 만든 foothold 체크리스트 7번("막히면 열거 더 깊게, 과한 필터 제거, vhost")이 정확히 이 상황용이에요.

혹시 그때 실제로 어떤 feroxbuster/gobuster 명령을 썼는지 기억나면 알려주세요 — 필터 때문에 놓친 건지 워드리스트 문제였는지 정확히 짚어드리겠습니다. 그리고 지금이라도 이 박스 다시 켤 수 있으면, 위 명령으로 숨은 경로가 뜨는지 확인해보는 게 최고의 복습입니다.
