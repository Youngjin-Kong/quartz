# 시험 중 "진짜 막혔을 때" 행동 방침

> 3월 실패의 100%가 "막힘 → 멈춤"이었다. 이 파일은 그 순간의 **강제 프로토콜**이다. 벽에 붙이고, 막힐 때마다 위에서 아래로 실행한다.

> **7월(2026-07-16)의 실패는 형태가 달랐다 — "막힘 → 멈춤"이 아니라 "이미 답을 뽑아놓고 못 읽음"이었음.** winPEAS 를 돌렸고 권한상승 답이 그 출력 안에 평문으로 있었으나, 389KB 가 한 줄로 뭉개져 grep 이 무력했고 그대로 3시간을 다른 벡터에 씀. **3월의 병목은 「도구 전환」, 7월의 병목은 「출력 소비」임.** 이 파일은 원래 전자만 다뤘으므로 아래 **0.5단계**로 후자를 보강함.

---

## 0. 발동 조건 — "나 지금 막혔나?"

- **정의:** 현재 시도에서 **20~30분간 새 정보/진전이 0** → 멈추고 이 프로토콜 발동.
- **주의:** "익스가 한 번 실패함" = 막힌 게 아니다. 그건 **1단계**다. 첫 저항에 이 프로토콜을 발동하지 마라 — 먼저 1단계를 다 하라.
- **또 하나의 발동 신호 — 시계와 무관함:** **같은 도구를 두 번 받거나 두 번 돌리려 하고 있으면 그 자체가 발동 조건임.** 앞의 출력을 못 읽었다는 신호이고, 진전 0 을 스스로 못 알아챈 상태라 20~30분 감각이 작동하지 않음. (2026-07-16: 11:21 에 winPEAS 출력이 파일로 떨어져 있는데 13:04 에 winPEAS 를 **재다운로드**함.)

---

## 0.5단계 — 이미 뽑은 정보를 다 소비했나 ("다음 무기" 이전)

**순서가 중요함.** 이 파일의 원래 구조는 「막힘 → 다음 무기」였으나, **「막힘 → 이미 뽑은 정보를 다 썼는가 → 그 다음에 다음 무기」** 여야 함. 1단계로 내려가기 전에 여기서 걸러야 하는 이유는, **새 도구를 꺼내는 순간 이미 손에 쥔 답을 영영 안 읽게 되기 때문임.**

```
□ 이미 돌린 도구(PEAS·nmap·gobuster/ferox·whatweb)의 출력을 "파일로" 갖고 있나?
   → 화면으로만 봤으면 소비한 게 아니다. 스크롤은 읽은 게 아니다.
□ 그 파일에 정해진 grep 배터리를 실제로 쳤나?
   → 기억이 아니라 명령 이력으로 확인. "돌렸다"가 아니라 "배터리를 끝까지 쳤다"가 체크 항목.
□ 출력이 한 줄로 뭉개져 있지 않은지 확인했나?
   → wc -lc peas.txt   (줄 수가 0/한 자릿수면 grep 도 -A/-B/-C 도 전부 무력)
   → 뭉개졌으면 줄부터 복원하고 나서 배터리를 친다.
□ 이미 갖고 있는 자격증명·사용자명을 전 서비스에 스프레이했나?
   → 사용자 N명 × 패스워드 M개 = N×M 조합. 다 안 돌렸으면 아직 안 한 거다.
   → SMB·WinRM·SSH·RDP·웹 로그인·DB 전부. 확보 시점이 몇 시간 전이어도 마찬가지.
□ 같은 도구를 다시 받거나 다시 돌리려 하고 있지 않나?
   → 그건 앞의 출력을 못 읽었다는 신호다. 재다운로드 대신 앞 출력 파일을 열어라.
```

- **PEAS 출력의 줄 복원 방법과 grep 배터리 실물은 [[07. PEAS 출력 트리아지]] 에 있음.** 여기에 복사하지 않음 — 두 벌이 되면 갈라져서 둘 다 못 믿게 됨.
- **2단계의 스프레이 항목과 중복이 아니라 «시점»이 다름.** 2단계는 「**새로** 얻은 크리덴셜을 재사용했나」이고, 여기는 「**이미 갖고 있는데 아직 안 쓴 것**이 남아 있나」의 재확인임. (2026-07-16 112: 09:52 에 사용자 3명 + 패스워드 10개를 확보하고도 30조합 스프레이를 한 번도 안 돌림 — 결과를 소비하지 않은 것.)

## 1단계 — 지금 이 실마리를 "완주"했나 (성급한 포기 방지)

```
□ 익스/기법이 한 번 실패했다고 버린 거 아닌가?
   → 에러 메시지를 읽었나? 익스 코드를 읽고 경로/버전/타깃을 고쳤나?
   → (Sorcerer: ssh 안 됨 → authorized_keys 읽었어야. CVE 실패 → 실제 버전 확인)
□ 이 blocker의 "다음 무기 목록"을 다 순회했나?
   - 웹 빈 페이지 → 워드리스트 교체·확장자·vhost·robots·소스·필터제거
   - 업로드 필터 → .phtml/.phar·htaccess·MIME·magic byte·클라이언트우회·업로드+LFI
   - juicy 권한 없음 → winPEAS/linpeas·서비스·AlwaysInstallElevated·크리덴셜·설치SW
   - 셸 접속 안 됨 → authorized_keys(ForceCommand)·권한(chmod 600)·passphrase 크랙
□ foothold_체크리스트 / 실전_반사규칙을 실제로 펴봤나?
```

## 2단계 — 넓게 다시 열거 (덜 판 문 찾기)

```
□ 전체 포트(-p-) + UDP 스캔 다 했나? (top1000만 본 거 아님?)
□ ★열린 서비스를 하나도 빠짐없이 두드렸나?
   → nmap을 한 줄씩 다시 읽어라. (Sorcerer: NFS 건너뜀 / 웹만 팜)
   → "웹에 매달려 다른 서비스를 안 봤다"가 내 3월 패턴이다
□ ★nmap이 "지문을 못 뜬" 포트가 있나? 있으면 그게 문이다.
   → 나머지 서비스가 전부 최신 패치면 더욱 그렇다 — 커스텀 서비스만 인증 없이 말이 통한다.
   → 배너가 안 뜬 포트에는 nc로 직접 붙어 한 줄 던져봐라. 스캐너가 못 읽은 것뿐이다.
   → (2026-07-16 110: 22/110/143은 전부 인증 필요 + 배너상 최신 패치 계열.
      43/tcp 커스텀 whois만 응답했는데 쿼리를 한 번도 안 보냄. 5시간 중 그 타깃에 쓴 시간 약 2분.)
□ 웹은 포트마다 각각 dirbust 했나? (whatweb만 하고 멈춘 거 아님?)
□ 새로 얻은 크리덴셜을 모든 서비스/유저에 재사용(스프레이)했나?
```

## 3단계 — 관점 전환 (터널비전 리셋)

```
□ 10~15분 휴식 (물·산책). 터널비전은 쉬면 풀린다 — 이건 시간낭비 아님.
□ 이 박스를 "방금 시작한 것처럼" 처음부터 다시 본다. 지금이면 뭘 먼저?
□ 노트에서 "아직 안 해본 것" 명시적 리스트를 만든다.
□ 러버덕: 이 박스를 소리 내어 설명한다 (막힌 지점이 저절로 보임).
```

## 4단계 — 박스 전환 (규율)

```
□ 한 박스에 2시간(foothold) / privesc 체크리스트 소진 후에도 막힘 → 다른 박스로.
□ 떠나기 전: "정확히 어디서 멈췄는지 + 다음에 시도할 것" 한 줄 기록.
□ 다른 박스 풀다가 돌아오면 답이 보이는 경우가 많다 (fresh eyes).
□ 한 박스에 6시간 침몰 = 최악. 점수는 여러 박스에서 나온다.
```

## 5단계 — 점수 트리아지 (전체 관점)

```
□ 쉬운 점수부터: 여러 박스의 local.txt > 한 박스 root에 6시간
□ 지금 페이스가 70점 궤도인가? (AD 40 + 독립 중 2.5개)
□ 남은 시간 배분 재조정. 완성 가까운 것부터 마무리.
□ 최후: 스킵한 서비스 재방문, 스프레이, 안 읽은 파일 다시.
```

## 🚫 3월의 안티패턴 (이것만 안 하면 절반은 성공)

1. **익스 한 번 실패 → 포기** (X) → 코드 읽고 고쳐서 완주 (O)
2. **웹 한 서비스에 터널비전** (X) → 모든 포트/서비스 두드리기 (O)
3. **whoami /priv juicy 없음 → 끝** (X) → winPEAS 먼저 (O)
4. **whatweb 하고 멈춤** (X) → 포트마다 dirbust (O)
5. **"비어있다/안 된다"로 결론** (X) → "덜 팠다"로 재열거 (O)
6. **한 박스 6시간 침몰** (X) → 2시간 룰로 전환 (O)

## 🧠 멘탈 규칙 (막힐 때 스스로에게)

- **"막힘은 종료가 아니라 신호다."** 반드시 다음 무기가 있다.
- **"안 되는 것은 정보다."** 무엇이 막는지 = 어떻게 뚫을지의 힌트.
- **휴식은 생산적이다.** 터널비전 상태로 30분 vs 쉬고 5분에 발견.
- **완벽이 아니라 점수 계산.** 70점이 목표지 100점이 아니다.
- **패닉 금지.** 25시간 있다. 한 박스 막힘 = 재앙 아님.
