
아시다시피, AD는 상당히 복잡합니다. 하지만 AD가 실제로 어떻게 작동하는지에 대한 모델을 갖추면 공격 방식을 훨씬 직관적이고 명확하게 이해할 수 있습니다. 그래서 제가 최대한 간략하게 정리해 보았습니다.

Active Directory(AD)는 단 하나의 질문에 답하기 위해 존재합니다. 바로 "이 사용자가 이 컴퓨터에서 지금 이 작업을 수행하도록 허용해야 하는가?"입니다. 사용자, 그룹, GPO, 트러스트, Kerberos 등 모든 구성 요소는 수천 대의 컴퓨터에 걸쳐 이 질문에 대한 답을 대규모로 제공하기 위해 존재합니다.

-사용자와 그룹은 단순히 ID를 담는 컨테이너입니다. 사용자는 권한 집합에 연결된 자격 증명 집합입니다. 그룹은 여러 사용자에게 동일한 권한을 적용하기 위한 간편한 방법입니다. 사용자 계정이 손상되면 해당 사용자가 속한 그룹(알지 못했던 그룹 포함)에 부여된 모든 권한을 상속받게 됩니다.

- GPO는 정책이 전파되는 방식입니다. 그룹 정책 개체(GPO)는 구성을 컴퓨터에 자동으로 적용합니다. 공격자 관점에서 보면, 특정 컴퓨터에 적용되는 GPO를 제어하는 ​​주체가 해당 컴퓨터를 제어하게 된다는 의미입니다. GPO 구성 오류는 Active Directory 환경에서 가장 간과되는 권한 상승 경로 중 하나입니다.

- 케르베로스는 암호 시스템이 아니라 티켓 시스템입니다. Active Directory에서 인증할 때 암호를 계속 전송하는 대신, 사용자를 증명하는 티켓을 받습니다. 케르베로스팅이 작동하는 이유는 서비스 티켓이 서비스 계정의 암호 해시로 암호화되어 있으며, 인증된 사용자라면 누구나 티켓을 요청할 수 있기 때문입니다. 티켓 자체가 자격 증명입니다.

- 신뢰 관계는 Active Directory(AD)에서 "이 사용자가 내 도메인에서 생성한 사용자가 아니더라도, 이 사용자가 자신을 누구라고 주장하는지 신뢰해야 할까?"라는 질문에 대한 답을 찾는 방식입니다. 두 AD 도메인이 서로 신뢰 관계를 맺으면 한 도메인의 사용자가 다른 도메인의 리소스에 접근할 수 있습니다. 신뢰 관계 설정이 잘못되면 가치가 낮은 도메인이 가치가 높은 도메인으로 바뀌게 됩니다. BloodHound는 이러한 신뢰 관계를 시각적으로 보여줍니다.

-블러드하운드. 모든 노드는 ID이고, 모든 엣지는 권한 관계이며, 해킹당한 사용자 계정에서 도메인 관리자 계정까지의 모든 경로는 누군가가 지나치게 관대한 구성 결정을 내린 결과 발생하는 이러한 관계들의 사슬입니다.
