# 6.4.4 SMB 열거

> **SMB Enumeration** · PEN-200 §6.4.4

SMB(Server Message Block)는 구현이 복잡하고 개방적이어서 오랫동안 보안 이력이 나빴음 — Windows 2000·XP 의 인증 없는 SMB null 세션부터 수년간 쏟아진 다수의 버그·취약점까지. Windows 릴리스와 나란히 갱신·개선돼 왔으나 열거 대상으로서의 값은 여전함.

**포트를 갈라 볼 것.** NetBIOS 는 TCP 139(및 여러 UDP 포트)에서 리스닝하고, SMB 는 TCP 445 이며 **둘은 별개 프로토콜**임. NetBIOS 는 로컬 네트워크의 컴퓨터끼리 통신하게 해 주는 독립적인 세션 계층 프로토콜·서비스임. 현대적 SMB 구현은 NetBIOS 없이도 동작하지만 하위 호환을 위해 NBT(NetBIOS over TCP)가 필요해 **둘이 함께 켜져 있는 경우가 많고, 그래서 열거도 함께 감**.

두 포트를 nmap 으로 한 번에 훑고 grepable 형식으로 저장함.

```
kali@kali:~$ nmap -v -p 139,445 -oG smb.txt 192.168.50.1-254
kali@kali:~$ cat smb.txt
# Nmap 7.92 scan initiated Thu Mar 17 06:03:12 2022 as: nmap -v -p 139,445 -oG smb.txt
192.168.50.1-254
# Ports scanned: TCP(2;139,445) UDP(0;) SCTP(0;) PROTOCOLS(0;)
Host: 192.168.50.1 ()   Status: Down
...
Host: 192.168.50.21 ()  Status: Up
Host: 192.168.50.21 ()  Ports: 139/closed/tcp//netbios-ssn///,
445/closed/tcp//microsoft-ds///
...
Host: 192.168.50.217 () Status: Up
Host: 192.168.50.217 () Ports: 139/closed/tcp//netbios-ssn///,
445/closed/tcp//microsoft-ds///
# Nmap done at Thu Mar 17 06:03:18 2022 -- 254 IP addresses (15 hosts up) scanned in
6.17 seconds
```

139·445 가 열린 호스트들이 드러남. NetBIOS 정보에 특화된 도구로는 nbtscan 이 있음 — `-r` 로 발신 UDP 포트를 137 로 지정해 NetBIOS 이름 서비스에 유효한 NetBIOS 이름을 질의함.

```
kali@kali:~$ sudo nbtscan -r 192.168.50.0/24
Doing NBT name scan for addresses from 192.168.50.0/24
IP address       NetBIOS Name     Server    User             MAC address
------------------------------------------------------------------------------
192.168.50.124   SAMBA            <server>  SAMBA            00:00:00:00:00:00
192.168.50.134   SAMBAWEB         <server>  SAMBAWEB         00:00:00:00:00:00
...
```

두 호스트의 NetBIOS 이름이 나옴. **NetBIOS 이름은 조직 내에서 그 호스트가 맡은 역할을 매우 서술적으로 드러내는 경우가 많아**, 스캔한 호스트의 맥락을 보강하고 다음 정보 노출로 이어지는 재료가 됨.

nmap 의 NSE 스크립트도 SMB 서비스 발견·열거에 유용함. `/usr/share/nmap/scripts` 디렉터리에 `smb2-security-mode`·`smb-enum-shares`·`smb-enum-users`·`smb-os-discovery` 등이 들어 있음.

```
kali@kali:~$ ls -1 /usr/share/nmap/scripts/smb*
/usr/share/nmap/scripts/smb2-capabilities.nse
/usr/share/nmap/scripts/smb2-security-mode.nse
/usr/share/nmap/scripts/smb2-time.nse
/usr/share/nmap/scripts/smb2-vuln-uptime.nse
/usr/share/nmap/scripts/smb-brute.nse
/usr/share/nmap/scripts/smb-double-pulsar-backdoor.nse
/usr/share/nmap/scripts/smb-enum-domains.nse
/usr/share/nmap/scripts/smb-enum-groups.nse
/usr/share/nmap/scripts/smb-enum-processes.nse
/usr/share/nmap/scripts/smb-enum-sessions.nse
/usr/share/nmap/scripts/smb-enum-shares.nse
/usr/share/nmap/scripts/smb-enum-users.nse
/usr/share/nmap/scripts/smb-os-discovery.nse
...
```

*SMB 관련 NSE 스크립트 목록 확인*

⚠️ **SMB discovery 스크립트는 대상에 SMBv1 이 켜져 있어야만 동작함** — 현대 Windows 의 기본값이 아님. 다만 레거시 시스템에는 아직 SMBv1 이 흔하고, 실습 환경의 Windows 호스트는 그 상황을 재현하려고 이 버전을 켜 둔 것임.

```
kali@kali:~$ nmap -v -p 139,445 --script smb-os-discovery 192.168.50.152
...
PORT    STATE SERVICE      REASON
139/tcp open  netbios-ssn  syn-ack
445/tcp open  microsoft-ds syn-ack
Host script results:
| smb-os-discovery:
|   OS: Windows 10 Pro 22000 (Windows 10 Pro 6.3)
|   OS CPE: cpe:/o:microsoft:windows_10::-
|   Computer name: client01
|   NetBIOS computer name: CLIENT01\x00
|   Domain name: megacorptwo.com
|   Forest name: megacorptwo.com
|   FQDN: client01.megacorptwo.com
|_  System time: 2022-03-17T11:54:20-07:00
...
```

⚠️ **결과를 그대로 믿지 말 것.** 대상은 Windows 11 인데 스크립트는 Windows 10 으로 보고함 — nmap 의 서비스·OS 열거는 어떤 알고리즘도 완전하지 않으므로 걸러 들어야 함. 그럼에도 NSE 방식이 값을 하는 이유는 둘임 — ① 앞서 본 OS 핑거프린팅과 달리 **도메인명·포리스트명·FQDN 등 Active Directory 도메인 서비스 관련 정보가 함께 나옴** ② 트래픽이 적어 정상적인 기업 네트워크 활동에 섞이므로 **눈에 띄지 않을 가능성이 큼**.

Windows 환경에서 SMB 공유를 열거할 때는 `net view` 가 유용함 — 주어진 호스트에 속한 도메인·자원·컴퓨터를 나열함. client01 VM 에 접속한 상태에서 dc01 의 공유를 전부 나열한 예:

```
C:\Users\student>net view \\dc01 /all
Shared resources at \\dc01
Share name  Type  Used as  Comment
-------------------------------------------------------------------------------
ADMIN$      Disk           Remote Admin
C$          Disk           Default share
IPC$        IPC            Remote IPC
NETLOGON    Disk           Logon server share
SYSVOL      Disk           Logon server share
The command completed successfully.
```

`/all` 키워드를 붙이면 달러 기호로 끝나는 관리 공유(`ADMIN$`·`C$`·`IPC$`)까지 나옴.
