# 26.5 파이프라인 오염

> **Poisoning the Pipeline** · PEN-200 §26.5

저장소가 보이므로 열거를 이어 파이프라인 오염을 시도함.

파이프라인은 **새 버전 배포까지 거쳐야 하는 동작들** — 컴파일·DB 시딩·설정 갱신 등을 자동화해 반복 가능하게 만든 것.

정의 파일은 애플리케이션 소스와 **같은 저장소에** 있는 경우가 많아, 저장소 접근이 곧 파이프라인 접근이 됨.

| 플랫폼 | 정의 파일 |
|---|---|
| GitLab | `.gitlab-ci.yml` |
| GitHub | `.github/workflows` 폴더 |
| Jenkins | `Jenkinsfile` |

문법은 각각 다름. 트리거도 설정에 달림 — main 브랜치 커밋이 돌리기도, 들어온 pull request 가 변경을 테스트하려 돌리기도 함.

학습 목표 — 파이프라인 찾기, 파일 수정법, 빌더에서 셸 얻기, 빌더 추가 정보 확보.
