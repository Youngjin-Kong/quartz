# 3.4.2 보안 통제와 전략

> **Security Controls and Strategies** · PEN-200 §3.4.2

최소 권한·open security·defense-in-depth 같은 이상을 실제로 구현하려면 보안 전략(Security Strategy)이 필요함. 원문이 드는 개입 수단은 24/7 경계, 위협 모델링, 테이블탑 논의, 전술·프로세스·절차에 대한 지속 교육, 지속적 자동 패치, 지속적 공급망 검증, 안전한 코딩과 설계, 일일 로그 검토, 그리고 잘 구현된 보안 통제의 다층 배치임.

- 항목이 많아 압도적으로 보이나, 요지는 하나 — defense-in-depth 전략이란 사람과 기술이 자원 앞에 장벽 계층을 쌓는 것임
- 보안을 가용성보다 앞세우면 다운타임과 사용자 불만이 늘어남. 예로 GNU/Linux 에서 대체 인증 경로 없이 Kerberos 만 두면, Kerberos 에 문제가 생기는 순간 아무도 네트워크 서비스에 접근하지 못함. 보안이 최우선인 조직에는 이것이 오히려 이상적일 수 있으나, 가용성이 최우선이면 「보안만 올리고 시스템을 해친」 것이 됨
- 통제는 제대로 쓰고 유지하는 데 시간이 많이 들고, 비용이 크면 조직의 수익성 자체를 잃게 함. 재정·인력 제약과도 균형을 맞춰야 함
