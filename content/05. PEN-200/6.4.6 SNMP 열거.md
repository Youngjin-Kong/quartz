# 6.4.6 SNMP 열거

> **SNMP Enumeration** · PEN-200 §6.4.6

SNMP(Simple Network Management Protocol)는 네트워크 관리자들이 잘 이해하지 못하는 경우가 많고, **그래서 오설정이 잦고 상당한 정보 유출로 이어짐**. 구조적 약점이 겹쳐 있음:

- **UDP 기반의 단순·무상태 프로토콜**이라 IP 스푸핑과 리플레이 공격에 취약함
- 널리 쓰이는 **v1·v2·v2c 는 트래픽 암호화가 없음** — 로컬 네트워크에서 SNMP 정보와 자격 증명이 쉽게 가로채짐
- 전통적 SNMP 는 인증 체계가 약하고 **기본 community string 인 `public`·`private` 가 그대로 남아 있는 경우가 흔함**
- 인증·암호화를 제공하는 SNMPv3 조차 최근까지 DES-56 만 지원해 배포돼 왔음 — 쉽게 브루트포스되는 약한 암호화임. 더 최신 구현은 AES-256 을 지원함

정의상 「네트워크를 관리하는」 프로토콜에 위의 것들이 전부 해당되므로, SNMP 는 유용한 열거 프로토콜임.

수년 전 OffSec 이 수행한 내부 침투 테스트가 그 규모를 보여줌. 기업 고객·은행 등에 네트워크 통합 서비스를 제공하던 회사였고, 수천 대의 Cisco 라우터가 물린 대형 class B 네트워크가 있었음 — 각 라우터가 고객사로 가는 관리·설정용 게이트웨이였음. 기본 telnet 자격 증명 `cisco/cisco` 를 훑다 저사양 Cisco ADSL 라우터 한 대가 걸렸고, 그 설정 파일에서 복잡한 public·private community string 이 나왔음. **그런데 같은 문자열이 class B 전 범위와 그 너머의 모든 네트워크 장비에 동일하게 쓰이고 있었음.** 기업용 라우팅 장비는 private community string 접근만으로 설정 파일 읽기·쓰기를 지원하는 경우가 많아서, SNMP 와 TFTP 로 네트워크의 전 라우터 설정을 복사하는 간단한 스크립트만으로 그 회사와 **고객사들의 인프라까지** 함께 뚫렸음.

SNMP 의 핵심 기능 중 하나가 **MIB 트리**임. MIB(Management Information Base)는 주로 네트워크 관리와 관련된 정보를 담은 데이터베이스로, 조직이나 네트워크 기능별 가지를 갖는 트리로 구성됨. **트리의 잎(최종 엔드포인트)이 외부 사용자가 접근·탐침할 수 있는 개별 변수 값**임. 아래 Windows MIB 값들은 네트워크 정보에 그치지 않는 것을 보여줌:

| MIB 값 | 내용 |
|---|---|
| 1.3.6.1.2.1.25.1.6.0 | System Processes |
| 1.3.6.1.2.1.25.4.2.1.2 | Running Programs |
| 1.3.6.1.2.1.25.4.2.1.4 | Processes Path |
| 1.3.6.1.2.1.25.2.3.1.4 | Storage Units |
| 1.3.6.1.2.1.25.6.3.1.2 | Software Name |
| 1.3.6.1.4.1.77.1.2.25 | User Accounts |
| 1.3.6.1.2.1.6.13.1.3 | TCP Local Ports |

*Windows SNMP MIB 값*

열린 SNMP 포트 탐색은 nmap 으로 함 — `-sU` 로 UDP 스캔, `--open` 으로 출력을 열린 포트로만 제한함.

```
kali@kali:~$ sudo nmap -sU --open -p 161 192.168.50.1-254 -oG open-snmp.txt
Starting Nmap 7.92 ( https://nmap.org ) at 2022-03-14 06:02 EDT
Nmap scan report for 192.168.50.151
Host is up (0.10s latency).
PORT    STATE SERVICE
161/udp open  snmp
Nmap done: 1 IP address (1 host up) scanned in 0.49 seconds
...
```

대안으로 onesixtyone 을 쓰면 IP 목록에 대해 브루트포스를 시도함. 먼저 community string 파일과 스캔할 IP 파일을 만들어야 함.

```
kali@kali:~$ echo public > community
kali@kali:~$ echo private >> community
kali@kali:~$ echo manager >> community
kali@kali:~$ for ip in $(seq 1 254); do echo 192.168.50.$ip; done > ips
kali@kali:~$ onesixtyone -c community -i ips
Scanning 254 hosts, 3 communities
192.168.50.151 [public] Hardware: Intel64 Family 6 Model 79 Stepping 1 AT/AT
COMPATIBLE - Software: Windows Version 6.3 (Build 17763 Multiprocessor Free)
...
```

SNMP 서비스를 찾았으면 흥미로운 MIB 데이터를 질의함. snmpwalk 같은 도구로 값을 탐침·조회할 수 있으며 **읽기 전용 community string 을 알아야 하는데 대개 `public`** 임. `-c` 로 community string, `-v` 로 SNMP 버전, `-t 10` 으로 타임아웃을 10초까지 늘려 MIB 트리 전체를 열거함.

```
kali@kali:~$ snmpwalk -c public -v1 -t 10 192.168.50.151
iso.3.6.1.2.1.1.1.0 = STRING: "Hardware: Intel64 Family 6 Model 79 Stepping 1 AT/AT
COMPATIBLE - Software: Windows Version 6.3 (Build 17763 Multiprocessor Free)"
iso.3.6.1.2.1.1.2.0 = OID: iso.3.6.1.4.1.311.1.1.3.1.3
iso.3.6.1.2.1.1.3.0 = Timeticks: (78235) 0:13:02.35
iso.3.6.1.2.1.1.4.0 = STRING: "admin@megacorptwo.com"
iso.3.6.1.2.1.1.5.0 = STRING: "dc01.megacorptwo.com"
iso.3.6.1.2.1.1.6.0 = ""
iso.3.6.1.2.1.1.7.0 = INTEGER: 79
iso.3.6.1.2.1.2.1.0 = INTEGER: 24
...
```

위 출력에서 대상의 이메일 주소를 얻을 수 있고, 이는 **새로 발견한 연락처를 겨냥한 사회공학 공격의 재료**가 됨.

snmpwalk 는 MIB 트리의 특정 가지(OID)만 파싱할 수도 있음. 위 표의 OID 를 붙여 항목별로 열거함. 예로 dc01 의 Windows 사용자 계정:

```
kali@kali:~$ snmpwalk -c public -v1 192.168.50.151 1.3.6.1.4.1.77.1.2.25
iso.3.6.1.4.1.77.1.2.25.1.1.5.71.117.101.115.116 = STRING: "Guest"
iso.3.6.1.4.1.77.1.2.25.1.1.6.107.114.98.116.103.116 = STRING: "krbtgt"
iso.3.6.1.4.1.77.1.2.25.1.1.7.115.116.117.100.101.110.116 = STRING: "student"
iso.3.6.1.4.1.77.1.2.25.1.1.13.65.100.109.105.110.105.115.116.114.97.116.111.114 =
STRING: "Administrator"
```

로컬 사용자 계정명 전체가 매핑된 MIB 하위 트리를 질의한 것임. 같은 방식으로 다음을 뽑음:

- **실행 중 프로세스**(`1.3.6.1.2.1.25.4.2.1.2`) — 프로세스명 문자열 배열이 돌아옴. 취약한 애플리케이션이나 대상에서 도는 백신 종류가 드러날 수 있음
- **설치된 소프트웨어**(`1.3.6.1.2.1.25.6.3.1.2`) — 앞의 프로세스 목록과 결합할 때 값이 커짐. **어떤 프로세스가 정확히 어느 버전 위에서 도는지 교차 확인**이 됨
- **TCP 리스닝 포트**(`1.3.6.1.2.1.6.13.1.3`) — 출력의 정수값이 곧 현재 리스닝 중인 TCP 포트임. **로컬에서만 리스닝하던 포트까지 드러나 그동안 몰랐던 서비스가 노출**되므로 특히 유용함
