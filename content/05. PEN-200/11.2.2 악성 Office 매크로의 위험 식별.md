# 11.2.2 악성 Office 매크로의 위험 식별

> **Identifying Risks of Malicious Office Macros** · PEN-200 §11.2.2

Microsoft Office 가 오랜 표적인 이유는 **보급률과 악용 가능한 기능**이 겹치기 때문임. Office 제품군 여럿이 VBA(Visual Basic for Applications) 를 내장해 문서가 매크로를 실행할 수 있음. 원래 의도는 대규모 조직에서 복잡한 문서를 자동화하는 것이었으나, 그대로 코드 실행 경로가 됨. 1999년 US-CERT 가 경고한 Melissa 매크로 바이러스가 악성 Word 문서에서 시작된 사례임.

Microsoft 쪽 대응은 단계적으로 쌓여 옴 —

- **매크로 기본 비활성화** — 사용자가 명시적으로 켜야 함
- **Mark of the Web(MotW)** — 외부에서 내려받은 파일에 Windows 가 붙이는 속성. 기본 NTFS 파일 시스템에서 동작함

![[PEN200-Fig-168.png]]

*파일 속성 화면에 나타난 MotW — 다운로드된 파일임을 Windows 가 표시*

> **Info** — MotW 는 CVE-2022-41091 같은 익스플로잇으로 우회될 수 있으나, 이런 구멍은 보안 패치로 빠르게 막히는 편임.

애플리케이션은 MotW 를 보고 그 파일을 신뢰할지 정함. 이 위에 얹힌 것이 **Protected View** 로, MotW 가 붙은 Office 문서를 열면 경고를 띄우고 편집·매크로 등 동적 기능을 쓰려면 사용자가 직접 해제해야 함. 나아가 Microsoft 는 **MotW 가 붙은 문서의 매크로 실행을 기본 차단**하기 시작함 — 메일로 받은 파일에는 이 속성이 항상 붙으므로 **Office 매크로 피싱의 효력이 크게 떨어짐.**

AD 그룹 정책으로 이 보호들을 강제하면 도메인 가입 머신은 Protected View 를 벗어나거나 매크로를 실행하는 것 자체가 막히고, **개별 사용자가 뒤집을 수 없음.**

그래도 벡터에서 배제할 것은 아님 — 최신 보안 기능을 못 쓰는 **구버전 Office 를 돌리는 조직**이 많고, Office 문서에 기본 그룹 정책만 적용해 보안 기능이 꺼져 있는 환경도 있음. 상세는 이후 모듈에서 다룸.
