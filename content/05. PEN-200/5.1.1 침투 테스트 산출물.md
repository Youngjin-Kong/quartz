# 5.1.1 침투 테스트 산출물

> **Penetration Testing Deliverables** · PEN-200 §5.1.1

침투 테스트·레드팀 훈련은 사전 각본화가 어려움 — 고객이 어떤 머신·네트워크를 테스트받길 원할지 일관되게 예측할 수 없기 때문임. 결과가 예측 불가여도 사전 미팅에서 상세 스코프를 정의하는 것은 권장되며, 대형 네트워크에서 비즈니스 핵심 타겟의 우선순위를 정할 때 특히 유용함.

실행 계획은 대개 특정 모델을 따르지만 실제 진행은 「어떤 계획도 적과의 첫 접촉에서 살아남지 못한다」는 격언대로 감 — 테스트 환경의 현실이 초기 가설과 거의 항상 다르므로 예상했던 활동이 실제로는 일어나지 않을 수 있음. 그래서 미리 채워둔 양식으로 보고하기 어렵고, 고객과 사전 논의가 거의 없이 진행되는 경우(예: 고객이 자기 방어팀을 기습하려는 경우) 특히 그러함.

따라서 보고서를 미리 준비하는 대신 테스트를 수행하면서 노트를 남겨 무엇을 했는지 상세 기록을 확보함. 이 기록이 보장하는 것 셋:

- 이슈가 실재함을 증명해야 할 때 테스트를 재현할 수 있음
- 조치 이후 재수행해 수정 여부를 확인할 수 있음
- 테스트 기간 중 시스템 장애가 나면 테스트가 원인인지 고객과 테스터가 판별할 수 있음

일부 활동은 허용되지 않으므로 어떤 Rules of Engagement(RoE) 아래에서 테스트하는지 매우 분명해야 함. 레드팀 테스트에서는 RoE 준수를 감시하는 「referee」 역할을 배정하는 경우가 많음. 제약의 예 — 서비스 거부 공격 금지, 사회공학 금지. 규제 준수 요구에 대응하는 작업이면 OWASP Penetration Testing Execution Standard 같은 특정 방법론을 따라야 할 수도 있음. 이런 제약은 전부 착수 시점부터 명확해야 함.
