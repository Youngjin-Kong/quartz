# 26.4.1 버킷 다운로드

> **Downloading the Bucket** · PEN-200 §26.4.1

버킷 나열 결과부터 다시 놓음.

```
kali@kali:~$ aws s3 ls staticcontent-lgudbhv8syu2tgbk
                           PRE .git/
                           PRE images/
                           PRE scripts/
                           PRE webroot/
2023-04-04 13:00:52        972 CONTRIBUTING.md
2023-04-04 13:00:52         79 Caddyfile
2023-04-04 13:00:52        407 Jenkinsfile
2023-04-04 13:00:52        850 README.md
2023-04-04 13:00:52        176 docker-compose.yml
```

*앞 절에서 얻은 버킷 나열 결과*

여기서 읽어야 할 신호 셋 — `.git/` 가 있으니 저장소 통째, `Jenkinsfile` 이 있으니 파이프라인의 일부, 그리고 `scripts/` 디렉터리.

나열이 된다고 다운로드까지 되는 것은 아니므로 먼저 `README.md` 하나로 시험함. 버킷 이름 앞에 `s3://` 를 붙여야 CLI 가 로컬 폴더가 아니라 S3 로 인식함.

```
kali@kali:~$ aws s3 cp s3://staticcontent-lgudbhv8syu2tgbk/README.md ./
download: s3://staticcontent-lgudbhv8syu2tgbk/README.md to ./README.md
```

> 실전 팁 — 민감 정보가 대량이면 직접 내려받는 대신 **다른 S3 버킷으로 `cp` 하는 편**이 전송이 빠르고 즉각적인 주의를 덜 끌어 나중에 접근할 시간을 벌어 줌. 방어 측 관점에서는 비정상 S3 활동을 모니터링하고 접근 정책을 엄격히 적용할 것.

받아진 README 내용을 확인함.

```
kali@kali:~$ cat README.md
# Static Content Repository
This repository holds static content.
While it only hold images for now, later it will hold PDFs and other digital assets.
Git probably isn't the best for this, but we need to have some form of version control
on these assets later.
## How to use
To use the content in this repository, simply clone or download the repository and
access the files as needed. If you have access to the S3 bucket and would like to
upload the content to the bucket, you can use the provided script:
./scripts/upload-to-s3.sh
This script will upload all the files in the repository to the specified S3 bucket.
## Contributing
If you would like to contribute to this repository, please fork the repository and
submit a pull request with your changes. Please make sure to follow the contribution
guidelines outlined in CONTRIBUTING.md.
# Collaborators
Lucy
Roger
```

*README 본문 — 업로드 스크립트 경로와 협력자 명단이 드러남*

README 는 저장소가 정적 콘텐츠 보관용이며 `./scripts/upload-to-s3.sh` 로 S3 에 올린다고 안내함. 하단 Collaborators 에 Lucy·Roger 가 적혀 있음.

받아지는 것이 확인됐으니 전체를 동기화함.

```
kali@kali:~$ mkdir static_content
kali@kali:~$ aws s3 sync s3://staticcontent-lgudbhv8syu2tgbk ./static_content/
download: s3://staticcontent-lgudbhv8syu2tgbk/.git/COMMIT_EDITMSG to
static_content/.git/COMMIT_EDITMSG
...
download: s3://staticcontent-lgudbhv8syu2tgbk/images/kittens.jpg to
static_content/images/kittens.jpg
kali@kali:~$ cd static_content
kali@kali:~/static_content$
```

스크립트에서 노리는 것은 **개발자가 잊고 남긴 하드코딩 AWS 액세스 키**임. `upload-to-s3.sh` 는 소득 없음 — 키 없이 `AWS_PROFILE=prod` 로 프로파일만 지정해 저장소를 통째로 동기화함.

```
kali@kali:~/static_content$ cat scripts/upload-to-s3.sh
# Upload images to s3
SCRIPT_DIR=$( cd -- "$( dirname -- "${BASH_SOURCE[0]}" )" &> /dev/null && pwd )
AWS_PROFILE=prod aws s3 sync $SCRIPT_DIR/../ s3://staticcontent-lgudbhv8syu2tgbk/
```

`scripts/` 에는 하나가 더 있음 — `update-readme.sh`. SCM API 로 협력자 목록을 받아 README 의 `# Collaborators` 절을 갱신하는 스크립트임.

```
kali@kali:~/static_content$ ls scripts
update-readme.sh  upload-to-s3.sh
kali@kali:~/static_content$ cat -n scripts/update-readme.sh
01  # Update Readme to include collaborators images to s3
02
03  SCRIPT_DIR=$( cd -- "$( dirname -- "${BASH_SOURCE[0]}" )" &> /dev/null && pwd )
04
05  SECTION="# Collaborators"
06  FILE=$SCRIPT_DIR/../README.md
07
08  if [ "$1" == "-h" ]; then
09    echo "Update the collaborators in the README.md file"
10    exit 0
11  fi
12
13  # Check if both arguments are provided
14  if [ "$#" -ne 2 ]; then
15    # If not, display a help message
16    echo "Usage: $0 USERNAME PASSWORD"
17    exit 1
18  fi
19
20  # Store the arguments in variables
21  username=$1
22  password=$2
23
24  auth_header=$(printf "Authorization: Basic %s\n" "$(echo -n "$username:$password"
| base64)")
25
26  USERNAMES=$(curl -X 'GET'
'http://git.offseclab.io/api/v1/repos/Jack/static_content/collaborators' -H 'accept:
application/json' -H $auth_header | jq .\[\].username |  tr -d '"')
27
28  sed -i "/^$SECTION/,/^#/{/$SECTION/d;//!d}" $FILE
29  echo "$SECTION" >> $FILE
30  echo "$USERNAMES" >> $FILE
31  echo "" >> $FILE
```

*`update-readme.sh` 전문 — 24행에서 Basic 인증 헤더를 만들고 26행에서 SCM API 를 호출함*

여기서 걷을 것 셋:

- 호출 URL 이 `http://git.offseclab.io/api/v1/repos/Jack/static_content/collaborators` → **저장소 소유자가 Jack** 이고, 앞서 추측한 대로 **SCM 에 비공개 저장소가 실재함**
- 스크립트가 `USERNAME PASSWORD` 를 인자로 받아 Basic 인증 헤더를 만듦 → **이 스크립트를 실행한 사용자의 bash history 를 잡으면 git 자격 증명이 평문으로 나올 수 있음**
- 현재 파일 상태에서는 시크릿 자체가 없음

파일 «현재 상태»에서 얻을 것은 여기까지임. 다만 이것은 git 저장소이므로 **모든 변경 이력이 남아 있음** — 다음은 git 특화 방법으로 이력을 뒤짐.
