# 17.1.2 상황 파악

> **Situational Awareness** · PEN-200 §17.1.2

클라이언트 사이드 공격이나 취약점 익스플로잇으로 Windows 시스템에 비권한 사용자로 접근한 상태를 가정함. 권한 상승을 시도하기 전에 지금 올라선 시스템에 관한 정보부터 확보해야 함 — 장악한 머신의 성격을 이해하고 가능한 상승 벡터를 찾아내는 결정적 단계임. 많은 정보를 훑고 해석하는 일이 서비스나 머신을 공격하는 것만큼 재미있지 않아 경험이 적은 테스터가 건너뛰거나 대충 넘기는 구간이지만, 최대한 모아둔 정보가 곧 실행 가능한 상승 벡터의 재료가 됨.

항상 확보해야 하는 항목:

```
- Username and hostname
- Group memberships of the current user
- Existing users and groups
- Operating system, version and architecture
- Network information
- Installed applications
- Running processes
```
*상황 파악을 위해 수집할 정보*

이하 예시의 대상은 CLIENTWK220 이며, 앞서 클라이언트 사이드 공격으로 4444 포트에 바인드 셸을 띄워둔 상황임. 이 절과 이어지는 절에서 바인드 셸 연결이 끊기면 다시 접속 가능해질 때까지 최대 1분이 걸릴 수 있음. netcat 으로 접속해 `whoami` 로 사용자명과 호스트명부터 확보함.

```
kali@kali:~$ nc 192.168.50.220 4444
Microsoft Windows [Version 10.0.22000.318]
(c) Microsoft Corporation. All rights reserved.
C:\Users\dave>whoami
whoami
clientwk220\dave
C:\Users\dave>
```

*CLIENTWK220 의 로컬 사용자*

내장 Administrator 계정은 비활성 상태임. 일반 사용자로 보이는 steve·dave 외에 daveadmin·BackupAdmin 이 있고, 이름에 admin 이 들어가 관리자 계정일 가능성이 높은 가치 표적임. daveadmin 은 dave 의 권한 계정으로 추정됨 — 관리자들은 일상 업무용 비권한 계정과 관리 작업용 권한 계정을 나눠 쓰고, 보안상 인터넷 브라우징처럼 위험이 따르는 작업에는 권한 계정을 쓰지 않음.

*CLIENTWK220 의 로컬 그룹*

비표준 그룹은 adminteam·BackupUsers·helpdesk 임. adminteam 은 이름에 admin 이 들어가고 「2층의 모든 워크스테이션 관리자」라는 별도 설명이 붙어 있어 관심 대상이지만, 어느 층이 있고 어느 부서가 어느 층에 있는지 모르는 상태라 아직 활용할 수 없음. BackupUsers 는 앞서 본 BackupAdmin 과 같은 맥락 — 백업 솔루션은 파일시스템에서 넓은 권한을 갖는 경우가 많아 둘 다 가치 있는 표적임.

비표준 그룹 외에 분석할 내장 그룹 — Administrators, Backup Operators, Remote Desktop Users, Remote Management Users. Backup Operators 구성원은 **권한이 없는 파일까지 포함해** 컴퓨터의 모든 파일을 백업·복원할 수 있음(예시의 비표준 그룹 BackupUsers 와 혼동하지 말 것). Remote Desktop Users 구성원은 RDP 로, Remote Management Users 구성원은 WinRM 으로 시스템에 접근할 수 있음.

그룹 구성원은 `Get-LocalGroupMember` 에 그룹명을 인자로 넘겨 확인함.


*adminteam 과 Administrators 의 구성원*

adminteam 구성원은 daveadmin 뿐이고, adminteam 자체는 로컬 Administrators 에 들어 있지 않음. 2층 워크스테이션 관리자라는 것만 아는 상태라 지금 당장 실행에 옮길 수 있는 정보는 아니지만, 네트워크 안쪽으로 들어가 어느 시스템이 2층에 있는지 식별하면 활용 가능해짐. 비활성 로컬 Administrator 를 제외하면 daveadmin·BackupAdmin 이 로컬 Administrators 소속으로, 가치 높은 표적 둘을 확보한 셈임. 누가 권한 계정인지만큼 **누가 RDP 를 쓸 수 있는지**도 중요함 — 그 사용자의 자격 증명을 얻으면 GUI 접근으로 이어져 시스템을 다루는 수단이 크게 늘어남.

여기까지 정리 — 바인드 셸은 CLIENTWK220 에서 helpdesk 소속 dave 로 돌고 있고, dave 의 권한 계정으로 보이는 daveadmin 은 2층 워크스테이션 관리 권한을 시사하는 adminteam 소속이며, daveadmin 과 BackupAdmin 이 이 머신의 로컬 관리자임.

*운영체제와 아키텍처 정보*

Windows 11 Pro 이고, 정확한 버전은 빌드 번호로 판정함 — 빌드 22621 은 Windows 11 22H2 임. 64비트 시스템이라는 점은 바이너리 파일을 실행할 때 걸림 — 32비트 시스템에서는 64비트 애플리케이션을 실행할 수 없기 때문임.

네트워크 정보 단계의 목표는 모든 네트워크 인터페이스·경로·활성 연결을 식별하는 것임. 이를 통해 새 서비스나 다른 네트워크로의 접근을 발견할 수 있음. 권한 상승으로 바로 이어지지 않더라도 머신의 용도를 이해하고 다른 시스템·네트워크로 가는 벡터를 얻는 데 필요함. 참고로 침투 테스트에서 모든 머신의 권한 접근을 얻는 것은 유용하지도 현실적이지도 않은 목표임 — 실제 평가에서는 rootable 하지 않은 머신을 다수 만나므로, 무턱대고 모든 머신에 상승을 시도하는 것이 아니라 **권한 접근이 고객 인프라의 추가 장악으로 이어지는 머신**을 식별하는 것이 숙련된 테스터의 목표임.

*CLIENTWK220 의 활성 네트워크 연결*

*설치된 애플리케이션 — 교재 PDF 자체의 조판으로 명령이 여러 줄로 접혀 있어 그대로 복사해 쓰면 실패함*

표준 Windows 애플리케이션 외에 FileZilla FTP 클라이언트, KeePass 패스워드 관리자, 7-Zip, XAMPP 가 설치돼 있음. 상황 파악을 마친 뒤 「공개 익스플로잇 찾기」 모듈에서 다룬 대로 이들의 공개 익스플로잇을 검색할 수 있고, 패스워드 공격으로 패스워드 관리자의 마스터 비밀번호를 얻어 다른 비밀번호들을 확보하고 권한 사용자로 로그온하는 경로도 있음. 단 이 목록이 완전하지 않을 수 있음 — 설치 과정이 불완전하거나 결함이 있었던 경우가 그러함. 따라서 `C:\` 의 32비트·64비트 Program Files 디렉터리를 항상 확인하고, 사용자의 Downloads 디렉터리 내용도 함께 살펴 추가 프로그램을 찾을 것.

설치 목록을 만드는 것만큼 **그중 무엇이 지금 실행 중인지** 식별하는 것도 중요함. 실행 중 프로세스는 `Get-Process` 로 확인함.

PID 2064 는 바인드 셸, 9756 은 열거용으로 시작한 PowerShell 세션임. 앞의 netstat 출력과 대조하면 PID 3508 이 mysqld, 4316 이 httpd 로 표시되는 Apache 임이 확인되고, 설치 목록과 합치면 둘 다 XAMPP 를 통해 기동된 것으로 추정됨.
