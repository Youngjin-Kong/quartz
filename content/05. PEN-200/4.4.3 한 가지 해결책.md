# 4.4.3 한 가지 해결책

> **One Potential Solution** · PEN-200 §4.4.3

해법은 여럿임. 가장 단순한 것은 정상 `chmod` 파일을 구해 교체하는 것이고, 복잡한 쪽은 올바른 권한을 가진 다른 바이너리의 맥락에서 실행하는 것임. 여기서는 후자 계열의 흥미로운 경로 하나를 따라감.

목표를 다시 정리하면 — **`chmod` 가 하는 일을 하되, `ls` 같은 다른 파일의 권한을 가진 파일**을 만드는 것임. 필요한 권한 집합을 가진 파일을 복사하는 데서 출발함.

```
kali@kali:~$ cp /usr/bin/ls chmodfix
kali@kali:~$ ls -l chmodfix
-rwxr-xr-x 1 kali kali 147176 Jun  8 08:16 chmodfix
```

*권한까지 딸려 온 `ls` 사본 `chmodfix`*

`chmodfix` 는 `ls` 의 완전한 사본이라 같은 옵션이 그대로 먹고, `ls` 를 쓰던 자리에 그대로 쓸 수 있음 — 자기 자신에게 걸어 보면 확인됨.

```
kali@kali:~$ ./chmodfix -l chmodfix
-rwxr-xr-x 1 kali kali 147176 Jun  8 08:16 chmodfix
```

*`chmodfix` 가 `ls` 와 똑같이 동작함*

그런데 지금 깨진 것은 `chmod` 의 **권한뿐이고 파일 내용은 멀쩡함.** 그러니 필요한 것은 내용뿐임 — `cp` 는 파일을 통째로 복사하므로 쓸 수 없고, 내용을 출력하는 `cat` 과 리다이렉트 `>` 를 써서 내용만 `chmodfix` 에 밀어 넣음.

```
kali@kali:~$ ls -l chmodfix
-rwxr-xr-x 1 kali kali 147176 Jun  8 08:20 chmodfix
kali@kali:~$ cat /usr/bin/chmod > chmodfix
kali@kali:~$ ls -l chmodfix
-rwxr-xr-x 1 kali kali 64448 Jun  8 08:21 chmodfix
```

*크기는 147176 → 64448 로 바뀌었는데 권한은 그대로 — 내용만 교체됨*

`ls -l` 출력의 숫자는 파일 크기임. 크기가 바뀌었다는 것은 내용이 `chmod` 의 것으로 바뀌었다는 뜻이고, 권한 표시는 그대로 유지됨. 이제 이 파일로 원래 하려던 일을 함.

```
kali@kali:~$ ./chmodfix +x find_employee_names.py
kali@kali:~$ ./find_employee_names.py
R. Jones
R. Diggs
G. Grice
C. Smith
C. Woods
D. Coles
J. Hunter
L. Hawkins
E. Turner
D. Hill
```

*내용은 chmod, 권한은 ls — 스크립트 실행 권한 복구 성공*

한 걸음 더 나가 원본 `/usr/bin/chmod` 까지 고치려 하면 새 장벽이 나옴.

```
kali@kali:~$ ./chmodfix +x /usr/bin/chmod
./chmodfix: changing permissions of '/usr/bin/chmod': Operation not permitted
```

*이번엔 대상 파일 쪽 권한이 막음*

파일이나 그 내용을 **복사하는 것**은 허용됐지만, `/usr/bin/` 안의 파일에 **쓰는 것**은 일반 사용자에게 허용되지 않음. 지금은 `kali` 사용자로 실행 중이므로, `sudo` 로 슈퍼유저 권한을 얻어 같은 명령을 다시 실행함(암호를 물음).

```
kali@kali:~$ sudo ./chmodfix +x /usr/bin/chmod
[sudo] password for kali:
```

*sudo 로 원본 chmod 의 실행 권한 복구*

시스템이 의도하지 않은 방식으로 권한을 얻어내는 것 — 이것이 사이버 보안의 핵심에 있는 사고방식임.
