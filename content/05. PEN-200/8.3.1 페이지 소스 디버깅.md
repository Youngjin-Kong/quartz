# 8.3.1 페이지 소스 디버깅

> **Debugging Page Content** · PEN-200 §8.3.1

매핑을 시작하기 좋은 지점은 **URL** 임. URL 에 붙은 파일 확장자가 애플리케이션의 작성 언어를 드러냄. `.php` 처럼 뻔한 것도 있고, 프레임워크에 따라 알아보기 어려운 것도 있음 — 예로 Java 기반 애플리케이션은 `.jsp`·`.do`·`.html` 을 씀.

다만 확장자 단서는 점점 줄고 있음. 다수 언어·프레임워크가 **라우트(route)** 를 지원해 URI 를 코드 구획에 직접 매핑하기 때문임. 라우트를 쓰는 애플리케이션은 반환할 내용을 로직으로 결정하므로 URI 확장자가 사실상 무의미해짐.

그래서 단서 대부분은 **페이지 소스** 쪽에 있음. Firefox 의 Debugger(Web Developer 메뉴)는 페이지의 리소스와 내용을 보여줌 — JavaScript 프레임워크, 숨은 입력 필드, 주석, HTML·JavaScript 안의 클라이언트 측 제어 등.

![[PEN200-Fig-104.png]]

*Debugger 로 JavaScript 소스 확인 — 예제 대상은 jQuery 3.6.0 사용*

코드가 minify 돼 있으면 읽기 어려움. 압축은 리소스를 아끼려는 개발자의 선택이고, Firefox 의 **Pretty print source**(이중 중괄호 아이콘) 버튼을 누르면 읽기 좋은 형태로 다시 펼쳐 줌.

특정 요소를 파고들 때는 Inspector 를 씀. 페이지에서 대상 요소를 우클릭하고 Inspect 를 고르면 Inspector 가 열리며 해당 요소의 HTML 이 강조됨.

![[PEN200-Fig-108.png]]

*Inspector 로 입력 요소 확인 — HTML 소스의 **숨은 폼 필드**를 빠르게 찾는 데 특히 유용함*
