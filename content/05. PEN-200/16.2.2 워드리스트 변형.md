# 16.2.2 워드리스트 변형

> **Mutating Wordlists** · PEN-200 §16.2.2

**문제 — 흔한 워드리스트는 패스워드 정책을 통과하지 못함.** 정책이 최소 길이·대문자·숫자·특수문자를 요구하는데, `rockyou.txt` 앞 10개(`123456`·`password`·`iloveyou`·`abc123` 등)는 하나도 조건을 못 맞춤. 손으로 걸러내거나 고치는 대신 **자동으로 변형(mutate)** 하는 것이 rule 기반 공격임.

```
kali@kali:~$ head /usr/share/wordlists/rockyou.txt
123456
12345
123456789
password
iloveyou
princess
1234567
rockyou
12345678
abc123
```
*`rockyou.txt` 앞 10개 — 길이·대문자·숫자·특수문자 어느 정책도 통과하지 못함*

구조는 세 층임 — **rule 함수** 하나하나가 워드리스트 속 기존 패스워드를 변형하고(문자 추가·대소문자 변경 등), 함수 하나 이상이 모여 **rule** 하나가 되며, rule 을 모은 **rule 파일**을 크래킹 도구에 `-r` 로 넘김. 실제로는 rule 하나에 함수를 여러 개 쓰는 것이 보통임.

실습 준비 — `rockyou.txt` 앞 10줄을 `passwordattacks/demo.txt` 로 뽑고, 정책에 맞지 않는 숫자열을 `sed -i '/^1/d'` 로(「1 로 시작하는 줄」을 삭제, `-i` 로 제자리 편집) 지워 5개만 남긴 상태에서 시작함.

```
kali@kali:~$ mkdir passwordattacks
kali@kali:~$ cd passwordattacks
kali@kali:~/passwordattacks$ head /usr/share/wordlists/rockyou.txt > demo.txt
kali@kali:~/passwordattacks$ sed -i '/^1/d' demo.txt
kali@kali:~/passwordattacks$ cat demo.txt
password
iloveyou
princess
rockyou
abc123
```
*실습 워드리스트 준비 — `1` 로 시작하는 줄을 지워 5개만 남김*

⚠️ **대가는 시도 횟수의 폭증임.** 다만 8자 미만의 흔한 패스워드는 현대 하드웨어가 감당하는 범위임.

**기본 함수 둘** — `$` 는 뒤에 붙이고(append), `^` 는 앞에 붙임(prepend). 둘 다 함수 뒤에 문자 하나를 받음(`^3` = 앞에 `3` 을 붙임). 숫자 요구가 있을 때 사용자 다수가 `1` 을 뒤에 붙이므로 `$1` 부터 시작함. 셸에서 `$` 는 이스케이프해야 파일에 제대로 들어감.

```
kali@kali:~/passwordattacks$ echo \$1 > demo.rule
```

`--stdout` 은 Hashcat 을 디버깅 모드로 돌려 **해시를 깨지 않고 변형 결과만 출력**함 — rule 을 검증할 때 항상 이것부터 볼 것.

```
kali@kali:~/passwordattacks$ hashcat -r demo.rule --stdout demo.txt
password1
iloveyou1
princess1
rockyou1
abc1231
```

⚠️ `Not enough allocatable device memory for this attack` 가 뜨면 Kali VM RAM 부족임 — 4GB 면 충분함.

**대문자는 `c` 함수** — 첫 글자를 대문자로 올리고 나머지를 소문자로 내림. 사용자 다수가 첫 글자를 대문자화하기 때문임.

**여기서 가장 헷갈리는 지점 — 같은 줄이냐 다른 줄이냐로 의미가 완전히 달라짐.**

- **한 줄에 공백으로 나열** = 하나의 rule → 함수를 **연달아 적용**함. 결과는 패스워드 **하나당 하나**
- **줄을 나눔** = 별개의 rule → 각각 **독립 적용**함. 결과는 패스워드 **하나당 둘**

```
kali@kali:~/passwordattacks$ cat demo1.rule
$1 c
kali@kali:~/passwordattacks$ hashcat -r demo1.rule --stdout demo.txt
Password1
Iloveyou1
Princess1
Rockyou1
Abc1231
kali@kali:~/passwordattacks$ cat demo2.rule
$1
c
kali@kali:~/passwordattacks$ hashcat -r demo2.rule --stdout demo.txt
password1
Password
iloveyou1
Iloveyou
princess1
Princess
...
```

특수문자는 `$!` 를 같은 줄에 더해 세 조건을 한 번에 충족시킴. **rule 함수는 왼쪽에서 오른쪽으로 적용**되므로 `$1 c $!` 는 `Password1!`, `$! $1 c` 는 `Password!1` 이 됨 — 순서가 곧 결과임.

```
kali@kali:~/passwordattacks$ cat demo1.rule
$1 c $!
kali@kali:~/passwordattacks$ hashcat -r demo1.rule --stdout demo.txt
Password1!
Iloveyou1!
Princess1!
Rockyou1!
Abc1231!
kali@kali:~/passwordattacks$ cat demo2.rule
$! $1 c
kali@kali:~/passwordattacks$ hashcat -r demo2.rule --stdout demo.txt
Password!1
Iloveyou!1
Princess!1
Rockyou!1
Abc123!1
```
*같은 세 함수라도 나열 순서에 따라 결과가 달라짐*

실전 예 — 대상에서 MD5 해시 `f621b6c9eab51a3e2f4e167fee4c6860` 을 얻었고 정책이 대문자·숫자·특수문자를 요구한다고 가정함. 흔한 숫자 조합 `1`·`2`·`123` 을 각각 별도 rule 로 둠.

```
kali@kali:~/passwordattacks$ cat crackme.txt
f621b6c9eab51a3e2f4e167fee4c6860
kali@kali:~/passwordattacks$ cat demo3.rule
$1 c $!
$2 c $!
$1 $2 $3 c $!
```

`--stdout` 을 빼면 실제 크래킹임. `-m` 으로 해시 유형을 지정하는데 **MD5 는 모드 `0`**(값은 Hashcat hash example 페이지에서 확인). GPU 가 없는 Kali VM 이라 경고를 무시하는 `--force` 를 붙임.

결과는 `Computer123!` 이고, **이 값은 원본 `rockyou.txt` 에 없었음** — 변형이 없었으면 못 깼다는 뜻임. CPU 만으로 수 초 걸림.

**rule 설계의 기준은 알고리즘이 아니라 사람의 습관임.** 대부분 주력 단어 하나를 정책에 맞게 조금 고쳐 씀 — 대문자 요구 시 첫 글자를 올리고, 특수문자 요구 시 **끝에 붙이며 키보드 왼쪽의 치기 쉬운 문자**를 고른다는 연구 결과가 있음.

직접 만드는 대신 Hashcat 기본 제공 rule 을 써도 됨 — `/usr/share/hashcat/rules/` 에 `best64.rule`·`d3ad0ne.rule`·`dive.rule`·`leetspeak.rule`·`rockyou-30000.rule` 등이 있음. **대상 정책을 전혀 모를 때 유용**하지만, 정책을 알아내거나 해당 소프트웨어의 기본 정책을 조사해 좁히는 편이 언제나 더 효율적임.
