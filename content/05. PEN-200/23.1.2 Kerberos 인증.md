# 23.1.2 Kerberos 인증

> **Kerberos Authentication** · PEN-200 §23.1.2

Microsoft 의 Kerberos 는 MIT 가 만든 Kerberos version 5 를 가져온 것이고, Windows Server 2003 이래 주 인증 메커니즘임. NTLM 이 챌린지-리스폰스 방식이라면 Kerberos 는 **티켓** 방식임.

두 프로토콜의 결정적 차이는 «누구와 먼저 말하는가»임 — NTLM 은 클라이언트가 애플리케이션 서버 자체와 인증을 시작하는 반면, Kerberos 는 클라이언트가 **Key Distribution Center(KDC)** 역할을 하는 도메인 컨트롤러와 먼저 시작함. KDC 서비스는 각 도메인 컨트롤러에서 돌며 사용자·컴퓨터에 세션 티켓과 임시 세션 키를 발급함.

*Kerberos 인증의 전체 흐름*

**AS-REQ (Authentication Server Request)** — 사용자가 워크스테이션에 로그인하면 도메인 컨트롤러로 전송됨. 사용자 패스워드에서 파생한 해시로 암호화한 **타임스탬프**와 사용자명이 실림.

도메인 컨트롤러는 `ntds.dit` 에서 해당 사용자의 패스워드 해시를 찾아 타임스탬프 복호화를 시도함. 복호화가 성공하고 그 타임스탬프가 중복이 아니면 인증 성공으로 봄. 중복이면 리플레이 공격의 정황임.

**AS-REP (Authentication Server Reply)** — Kerberos 는 상태를 저장하지 않는 프로토콜이라 응답에 **세션 키**와 **TGT(Ticket Granting Ticket)** 가 함께 실림.

- 세션 키 — 사용자의 패스워드 해시로 암호화됨. 따라서 클라이언트가 복호화해 재사용할 수 있음
- TGT — 사용자·도메인·타임스탬프·클라이언트 IP·세션 키를 담음. 변조를 막기 위해 **KDC 만 아는 비밀 키(`krbtgt` 계정의 NTLM 해시)** 로 암호화되므로 클라이언트는 복호화할 수 없음

세션 키와 TGT 를 받은 시점에서 KDC 는 클라이언트 인증이 끝난 것으로 봄. TGT 기본 유효기간은 10시간이고, 이후 갱신되며 갱신에는 패스워드 재입력이 필요 없음.

**TGS-REQ (Ticket Granting Service Request)** — 네트워크 공유나 메일함 같은 도메인 리소스를 쓰려면 다시 KDC 를 거쳐야 함. 이 패킷은 세 부분임 — **세션 키로 암호화한** 현재 사용자명과 타임스탬프, 리소스 이름, 그리고 암호화된 TGT.

KDC 의 ticket-granting service 는 요청받은 리소스가 도메인에 존재하면 자기만 아는 비밀 키로 TGT 를 복호화하고, 거기서 세션 키를 꺼내 요청의 사용자명·타임스탬프를 복호화함. 그리고 셋을 검사함.

1. TGT 의 타임스탬프가 유효할 것
2. TGS-REQ 의 사용자명이 TGT 의 사용자명과 일치할 것
3. 클라이언트 IP 가 TGT 의 IP 와 일치할 것

**TGS-REP (Ticket Granting Server Reply)** — 검증을 통과하면 세 요소가 돌아옴.

1. 접근이 허가된 서비스의 이름
2. 클라이언트와 서비스 사이에 쓸 세션 키
3. 사용자명·그룹 소속과 새로 만든 세션 키를 담은 **서비스 티켓**

암호화 주체가 갈리는 지점이 여기임 — 서비스 이름과 세션 키는 **TGT 생성 때의 원래 세션 키**로 암호화되고, 서비스 티켓 자체는 **해당 서비스에 등록된 서비스 계정의 패스워드 해시**로 암호화됨.

**AP-REQ (Application Request)** — 세션 키와 서비스 티켓을 모두 쥐면 이제 서비스 인증이 시작됨. 클라이언트는 애플리케이션 서버에 사용자명, 서비스 티켓에 딸린 세션 키로 암호화한 타임스탬프, 그리고 서비스 티켓 자체를 보냄.

애플리케이션 서버는 서비스 계정 패스워드 해시로 서비스 티켓을 복호화해 사용자명과 세션 키를 꺼내고, 그 세션 키로 AP-REQ 의 사용자명을 복호화함. 두 사용자명이 일치하면 요청을 받아들임. 접근 허용 직전에 서비스는 서비스 티켓에 실린 그룹 소속을 검사해 그에 맞는 권한을 배정함.

절차가 번잡해 보이지만 각종 네트워크 공격을 완화하고 위조 자격 증명 사용을 막으려는 설계임.
