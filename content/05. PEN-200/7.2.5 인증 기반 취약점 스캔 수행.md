# 7.2.5 인증 기반 취약점 스캔 수행

> **Performing an Authenticated Vulnerability Scan** · PEN-200 §7.2.5

- 인증 스캔은 더 상세한 정보를 주고 오탐을 줄임. 예시 대상은 DESKTOP.
- 대신 소음이 큼 — 네트워크 트래픽뿐 아니라 대상 시스템에 로그 항목과 AV 알림을 대량으로 남김.
- 템플릿은 Credentialed Patch Audit 을 씀. 모든 템플릿이 자격 증명을 받지만, 이 템플릿은 대상에 대한 «로컬 보안 점검»만 미리 구성돼 있고 외부 관점의 일반 취약점 점검은 하지 않는다는 점이 자격 증명을 넣은 Basic Network Scan 과 다름. 누락된 OS 패치뿐 아니라 권한 상승에 악용될 수 있는 구버전 애플리케이션도 찾음.
- 자격 증명 설정 — Credentials 탭 → Host 범주의 SSH → Authentication method 를 password 로 → 사용자 "offsec", 암호 "lab" → Elevate privileges with 를 sudo 로 두고 sudo 사용자 "root", 암호 "lab".

![[PEN200-Fig-068.png]]
*SSH 로그인과 sudo 승격 자격 증명을 함께 넣는 위치*

- 다른 인증 방식은 Categories 드롭다운에서 All 을 고르면 전체 목록이 나옴. Linux·macOS 는 SSH 를 쓰고, Windows 에도 SSH 를 쓸 수는 있으나 실무에서는 대개 SMB(Server Message Block)와 WMI(Windows Management Instrumentation)를 씀 — 둘 다 로컬 계정·도메인 계정과 여러 인증 옵션을 지원함.
- 인증 스캔이 의미 있는 결과를 내려면 대상 쪽 «준비»가 필요함.
  - 쓰려는 인증 방식의 연결을 막는 방화벽이 없어야 함.
  - Linux·Windows 모두 AV 가 스캔을 악성으로 판단해 연결을 끊거나 결과를 무의미하게 만들 수 있음 → 예외를 넣거나 일시적으로 끔.
  - Windows 의 UAC(User Account Control)도 방해가 됨. 관리자 계정도 대부분의 작업을 표준 권한으로 돌리고 필요할 때만 관리자 권한을 받는 구조여서임 → Nessus 를 허용하도록 설정하거나 일시적으로 끔. Windows 대상이면 특히 Tenable 문서를 먼저 확인할 것.
- 예시 대상은 AV 없는 Linux 라 그대로 Save 옆 화살표로 실행함.
- 결과 보기 — Vulnerabilities 페이지에서 톱니 아이콘 → Disable Groups 로 그룹핑을 끄면 발견이 개별로 나열됨.
- 결과에는 Ubuntu Local Security Checks 플러그인 패밀리의 항목이 다수 잡힘. 플러그인 패밀리는 같은 맥락의 취약점을 점검하는 플러그인 묶음으로, 데이터베이스·방화벽·웹 서버용 패밀리가 따로 있음. 이 패밀리는 Ubuntu 의 로컬 취약점과 누락 패치를 점검하는 플러그인을 담음.
- Name 열은 취약한 Ubuntu 버전, 짧은 설명, 패치 번호를 보여 줌. 목록에는 Firefox·cURL 처럼 로컬에 노출된 애플리케이션의 취약점 정보도 포함됨.
