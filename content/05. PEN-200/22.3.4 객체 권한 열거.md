# 22.3.4 객체 권한 열거

> **Enumerating Object Permissions** · PEN-200 §22.3.4

AD 객체에 붙은 권한을 열거하는 절임. 세부는 이 모듈 범위를 넘지만 원리는 짚고 가야 함.

객체 하나에는 여러 개의 **접근 제어 항목(Access Control Entry, ACE)** 이 붙고, 그 묶음이 **접근 제어 목록(Access Control List, ACL)** 임. ACE 하나하나가 해당 객체에 대한 허용 또는 거부를 정의함. 검증 흐름은 두 단계임 — 사용자가 신원과 권한을 담은 **액세스 토큰**을 보내면, 대상 객체가 그 토큰을 자신의 ACL 과 대조해 허용/거부를 결정함.

권한 종류는 많으나 공격자가 노리는 것은 몇 개로 좁혀짐.

```
GenericAll: Full permissions on object
GenericWrite: Edit certain attributes on the object
WriteOwner: Change ownership of the object
WriteDACL: Edit ACE's applied to object
AllExtendedRights: Change password, reset password, etc.
ForceChangePassword: Password change for object
Self (Self-Membership): Add ourselves to for example a group
```

**`Get-ObjectAcl` 이 ACE 열거 도구임.** `-Identity` 로 대상을 지정함. 자기 계정부터 확인함.

```
PS C:\Tools> Get-ObjectAcl -Identity stephanie
...
ObjectDN               : CN=stephanie,CN=Users,DC=corp,DC=com
ObjectSID              : S-1-5-21-1987370270-658905905-1781884369-1104
ActiveDirectoryRights  : ReadProperty
ObjectAceFlags         : ObjectAceTypePresent
ObjectAceType          : 4c164200-20c0-11d0-a768-00aa006e0529
InheritedObjectAceType : 00000000-0000-0000-0000-000000000000
BinaryLength           : 56
AceQualifier           : AccessAllowed
IsCallback             : False
OpaqueLength           : 0
AccessMask             : 16
SecurityIdentifier     : S-1-5-21-1987370270-658905905-1781884369-553
AceType                : AccessAllowedObject
AceFlags               : None
IsInherited            : False
InheritanceFlags       : None
PropagationFlags       : None
AuditFlags             : None
...
```

한 객체에 걸린 모든 ACE 가 나오므로 출력이 방대함. 이 중 실제로 볼 것은 셋임 — `ObjectSID`(권한이 걸린 대상), `ActiveDirectoryRights`(어떤 권한인가), `SecurityIdentifier`(**누가** 그 권한을 갖는가). SID 는 AD 객체를 유일하게 가리키는 값이지만 사람이 읽을 형태가 아니므로, PowerView 의 `Convert-SidToName` 으로 이름으로 되돌림.

```
PS C:\Tools> Convert-SidToName S-1-5-21-1987370270-658905905-1781884369-1104
CORP\stephanie
```

`ObjectSID` 는 예상대로 지금 쓰는 stephanie 계정임. `ReadProperty` 권한을 **누가** 가졌는지는 `SecurityIdentifier` 쪽을 변환해야 나옴.

```
PS C:\Tools> Convert-SidToName S-1-5-21-1987370270-658905905-1781884369-553
CORP\RAS and IAS Servers
```

`RAS and IAS Servers` 라는 AD 기본 그룹이 우리 사용자에 대해 `ReadProperty` 를 가진 것임. AD 의 흔한 기본 구성이라 공격 경로는 아니지만, **읽는 법**은 이것으로 정해짐 — 앞으로 어떤 객체를 열거하든 `ActiveDirectoryRights` 와 `SecurityIdentifier` 두 값만 보면 됨.

가장 강한 권한은 `GenericAll` 임. 관심 있는 권한만 남기려면 `?`(`Where-Object`)로 `ActiveDirectoryRights` 를 `-eq` 비교해 거르고, 그 결과를 `select` 로 두 속성만 뽑음. `ObjectSID` 는 지정한 객체 자신의 SID 일 뿐이라 이 단계에서는 필요 없음. 도메인 전체를 훑는 것이 원칙이나 여기서는 Management Department 그룹을 예로 씀.

```
PS C:\Tools> Get-ObjectAcl -Identity "Management Department" | ?
{$_.ActiveDirectoryRights -eq "GenericAll"} | select
SecurityIdentifier,ActiveDirectoryRights
SecurityIdentifier                            ActiveDirectoryRights
------------------                            ---------------------
S-1-5-21-1987370270-658905905-1781884369-512             GenericAll
S-1-5-21-1987370270-658905905-1781884369-1104            GenericAll
S-1-5-32-548                                             GenericAll
S-1-5-18                                                 GenericAll
S-1-5-21-1987370270-658905905-1781884369-519             GenericAll
```

다섯 주체가 이 그룹에 `GenericAll` 을 가짐. SID 배열을 그대로 `Convert-SidToName` 에 파이프하면 한 번에 변환됨.

```
PS C:\Tools> "S-1-5-21-1987370270-658905905-1781884369-512","S-1-5-21-1987370270-
658905905-1781884369-1104","S-1-5-32-548","S-1-5-18","S-1-5-21-1987370270-658905905-
1781884369-519" | Convert-SidToName
CORP\Domain Admins
CORP\stephanie
BUILTIN\Account Operators
Local System
CORP\Enterprise Admins
```

첫 SID 인 `Domain Admins` 는 도메인 최고 권한이라 `GenericAll` 이 붙어 있어도 놀랄 것이 없음. [가정] `Enterprise Admins`·`Account Operators`·`Local System` 은 교재가 따로 짚지 않으나 같은 성격의 고권한 주체임. 문제는 **stephanie** 임 — 일반 도메인 사용자가 AD 의 다른 객체에 `GenericAll` 을 갖는 것은 통상적이지 않아 **오설정일 가능성이 높고**, 이 계정이 생각보다 강하다는 신호임. 이것이 객체 권한 열거의 목적임 — 권한 자체가 공격 경로가 되는 지점을 찾는 것.

앞서 이 그룹의 유일한 구성원은 jen 이었음. `GenericAll` 이 실제로 무엇을 허용하는지 보이기 위해 `net.exe` 로 자기 계정을 그룹에 넣어봄.

```
PS C:\Tools> net group "Management Department" stephanie /add /domain
The request will be processed at a domain controller for domain corp.com.
The command completed successfully.
```

`Get-NetGroup` 으로 반영 여부를 확인함.

```
PS C:\Tools> Get-NetGroup "Management Department" | select member
member
------
{CN=jen,CN=Users,DC=corp,DC=com, CN=stephanie,CN=Users,DC=corp,DC=com}
```

stephanie 가 구성원으로 들어갔음. **남긴 흔적은 되돌릴 것** — 같은 명령의 `/del` 로 제거함.

```
PS C:\Tools> net group "Management Department" stephanie /del /domain
The request will be processed at a domain controller for domain corp.com.
The command completed successfully.
```

`Get-NetGroup` 으로 다시 확인해 jen 만 남았는지 봄.

```
PS C:\Tools> Get-NetGroup "Management Department" | select member
member
------
CN=jen,CN=Users,DC=corp,DC=com
```

복잡한 환경에서 AD 권한을 관리하는 것은 관리자에게 어려운 일임. 그래서 여기서 본 것 같은 약한 권한 설정이 흔하고, **도메인 안에서 권한 상승으로 이어지는 일이 잦아** 공격자의 상용 벡터가 됨. 이 예에서는 그룹 가입이 추가 도메인 권한으로 이어지지는 않았으나, **권한을 찾아내고 남용하는 절차 자체**가 실전에서 그대로 쓰이는 흐름임.
