# 18.2.2 서비스 흔적 조사

> **Inspecting Service Footprints** · PEN-200 §18.2.2

시스템 데몬은 부팅 시 떠서 사용자 개입 없이 도는 서비스임. SSH·웹서버·데이터베이스 같은 표준 데몬 외에 관리자가 임시 작업용으로 만든 **커스텀 데몬**이 보안 관례를 무시한 채 도는 일이 잦아 열거 가치가 큼.

핵심 전제 — **리눅스에서는 root 컨텍스트로 도는 상위 권한 프로세스의 정보도 일반 사용자가 조회 가능함**(Windows 와 다른 점). 즉 root 데몬이 명령줄에 평문 패스워드를 실어 실행하면 그대로 읽힘.

`ps` 는 한 시점의 스냅샷만 찍으므로 **주기적으로 뜨는 프로세스는 한 번의 `ps` 로는 놓침.** `watch` 로 반복 실행하면서 관심 키워드로 거름.

```
joe@debian-privesc:~$ watch -n 1 "ps -aux | grep pass"
...
joe      16867  0.0  0.1   6352  2996 pts/0    S+   05:41   0:00 watch -n 1 ps -aux |
grep pass
root     16880  0.0  0.0   2384   756 ?        S    05:41   0:00 sh -c sshpass -p
'Lab123' ssh  -t eve@127.0.0.1 'sleep 5;exit'
root     16881  0.0  0.0   2356  1640 ?        S    05:41   0:00 sshpass -p zzzzzz ssh
-t eve@127.0.0.1 sleep 5;exit
...
```

관리자가 `sshpass` 로 평문 패스워드를 넘겨 로컬 접속하는 데몬을 걸어 둔 것이고, root 프로세스임에도 인자가 그대로 노출됨.

두 번째 각도는 **트래픽 캡처 권한**임. `tcpdump` 는 raw socket 을 열어야 해서 sudo 없이는 못 돌지만, 문제 해결 목적으로 IT 담당 계정에 이 도구만 예외적으로 허용해 둔 구성이 드물지 않음. 그 권한 하나로 루프백을 훔쳐볼 수 있음 — `-i lo` 로 로컬 통신을, `-A` 로 페이로드를 ASCII 로 덤프한 뒤 키워드로 거름.

```
joe@debian-privesc:~$ sudo tcpdump -i lo -A | grep "pass"
[sudo] password for joe:
tcpdump: verbose output suppressed, use -v or -vv for full protocol decode
listening on lo, link-type EN10MB (Ethernet), capture size 262144 bytes
...{...zuser:root,pass:lab -
...5...5user:root,pass:lab -
```

몇 초 만에 root 의 평문 자격 증명이 잡힘. 두 사례 모두 root 가 아닌 계정이 root 의 자격 증명을 **관찰**해 얻은 것임 — 열거 단계에서 프로세스 인자와 자기 캡처 권한을 반드시 확인할 것.
