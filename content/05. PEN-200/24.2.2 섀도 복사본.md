# 24.2.2 섀도 복사본

> **Shadow Copies** · PEN-200 §24.2.2

Shadow Copy(볼륨 섀도 서비스, VSS)는 파일이나 볼륨 전체의 스냅샷을 만드는 Microsoft 백업 기술임. 도메인 관리자 권한으로 이 기술을 악용해 스냅샷을 뜨면 도메인 컨트롤러의 AD 데이터베이스 `NTDS.dit` 를 꺼낼 수 있음.

`[가정]` 교재는 「스냅샷이 `NTDS.dit` 추출을 가능하게 한다」고만 하고 직접 복사가 왜 안 되는지는 쓰지 않음. 일반적으로 알려진 이유는 구동 중인 AD DS 가 그 파일을 잠그고 있다는 것 — 이 절의 원문에 없는 배경 지식임.

관리 도구는 Windows SDK 에 포함된 Microsoft 서명 바이너리 `vshadow.exe` 임. 전제는 도메인 관리자 권한 — 예제는 jeffadmin 으로 DC1 에 접속해 상승된 명령 프롬프트에서 실행함. `-nw` 는 writer 를 비활성화해 백업 생성을 빠르게 하고, `-p` 는 사본을 디스크에 남김.

```
C:\Tools>copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy2\windows\ntds\ntds.dit
```

*섀도 복사본 장치 경로에서 AD 데이터베이스를 C: 루트로 복사*

데이터베이스만으로는 내용을 풀 수 없고 부트키가 든 `SYSTEM` 하이브가 함께 있어야 함. `reg` 의 `save` 인자로 뽑음.

```
C:\>reg.exe save hklm\system c:\system.bak
The operation completed successfully.
```

두 `.bak` 를 Kali 로 옮긴 뒤 impacket 의 secretsdump 로 오프라인 추출함. `-ntds` 에 데이터베이스, `-system` 에 하이브를 주고 `LOCAL` 키워드로 원격 접속 없이 로컬 파싱을 지시함. 결과는 도메인 전 사용자의 NTLM 해시(`domain\uid:rid:lmhash:nthash` 형식)와 Kerberos 키이며, 크랙하거나 그대로 pass-the-hash 에 씀.

*오프라인 추출 결과 — 도메인 전 사용자의 NTLM 해시와 Kerberos 키*

> ⚠️ **교재 오류** — 해시 줄 끝의 `</div>` 는 교재 지면의 렌더링 잔여물임. 실제 NT 해시는 그 앞 32자 hex 까지임.

함정 — 이 경로는 도구를 올려야 하고 파일·레지스트리 접근 흔적을 남김. 더 조용한 대안은 DC 로 측면 이동한 뒤 Mimikatz 의 DCSync 로 원격에서 해시만 받아오는 것임. 침투 테스트가 은밀성을 요구하는 경우는 드물지만, 기법의 은밀성을 따져두면 red team 교전에서 값을 함.
