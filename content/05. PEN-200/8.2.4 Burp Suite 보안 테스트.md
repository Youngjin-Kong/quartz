# 8.2.4 Burp Suite 보안 테스트

> **Security Testing with Burp Suite** · PEN-200 §8.2.4

Burp Suite 는 웹 애플리케이션 보안 테스트용 GUI 통합 플랫폼임. 하나의 UI 안에서 여러 도구를 제공하며, 무료 Community Edition 은 주로 수동 테스트용 도구를 담고 상용판에는 강력한 웹 취약점 스캐너 등이 추가됨. HTTPS 트래픽 가로채기도 지원하나 그러려면 **Burp 인증서**가 필요함(이 절의 범위 밖).

Kali 에서는 Applications > 03 Web Application Analysis > burpsuite 로 실행하거나 터미널에서 `burpsuite` 로 띄움. 첫 실행에서 뜨는 **JRE 미검증 경고는 무시해도 됨** — Kali 팀이 OS 에 동봉된 Java 버전으로 항상 Burp 를 시험하기 때문임. 이어 Temporary project 를 고르고 Use Burp defaults 인 채로 Start Burp 를 누름. UI 최초 화면의 네 개 창은 대부분 Pro 판 스캐너 요약이라 무시하고 **상단 탭**에 집중함.

```
kali@kali:~$ burpsuite
```

*터미널에서 Burp Suite 실행*

**웹 프록시**는 일반적으로 웹 클라이언트와 웹 서버 사이의 요청·응답을 가로채기 위한 전용 하드웨어나 소프트웨어를 뜻함. 가로챈 요청을 수동으로도 자동으로도 고칠 수 있어 관리자와 진단자 양쪽이 씀. 회사 전체 TLS 트래픽을 가로채는 용도의 것은 **TLS inspection device** 라 부르며, 복호화 후 재암호화하므로 HTTPS 가 주는 프라이버시 계층을 무력화함.

Burp Proxy 로는 브라우저가 보낸 요청이 서버로 넘어가기 전에 거의 모든 것을 바꿀 수 있음 — 파라미터 이름, 폼 값, 새 헤더 추가까지. 그래서 **예상 밖의 임의 입력에 애플리케이션이 어떻게 반응하는지** 시험할 수 있음. 입력 필드에 20자 제한이 걸려 있어도 요청을 고쳐 30자를 보내는 식임.

설정은 Proxy 탭에서 시작함. Intercept 하위 탭에서 **Intercept 를 꺼 둘 것** — 켜져 있으면 요청마다 Forward 를 눌러야 목적지로 나가고(Drop 을 누르면 보내지 않음), 단순히 사이트를 둘러보는 동안에는 이게 매우 번거로움. 가로채 고쳐야 할 때만 켬.

Options 하위 탭에서 프록시 리스너가 어느 포트를 듣는지 확인함. 기본값은 **localhost:8080** 이고, 브라우저는 이 호스트·포트로 붙어야 트래픽이 Burp 를 거침.

![[PEN200-Fig-091.png]]

*프록시 리스너 설정 — 기본 localhost:8080*

Burp 는 자체 Chromium 기반 브라우저를 동봉하고 그것이 Burp 기능에 맞춰 미리 설정돼 있으나, 이 과정에서는 더 유연하고 모듈화된 **Kali 의 Firefox** 만 씀. Firefox 설정은 `about:preferences#general` → Network Settings → Settings → Manual 로 IP·포트를 지정하는 방식임. 프록시(Burp)와 브라우저가 같은 호스트에 있으므로 루프백 `127.0.0.1` 과 포트 8080 을 넣음. 여러 대의 트래픽을 잡아야 하는 상황이면 프록시를 별도 IP 에 두고 브라우저에는 그 외부 IP 를 넣음. **모든 프로토콜 옵션에 이 프록시를 적용**해야 테스트 중 요청을 빠짐없이 가로챌 수 있음.

![[PEN200-Fig-092.png]]

*Firefox 프록시 설정 — 수동 지정, 전 프로토콜 적용*

설정 후 브라우징하면 Proxy > HTTP History 에 요청이 쌓임. ⚠️ **페이지 로딩이 멈춰 있으면 Intercept 가 켜져 있는 것** — 끄면 트래픽이 다시 흐름. 요청 하나를 클릭하면 하단에 클라이언트 요청(왼쪽)과 서버 응답(오른쪽) 전문이 펼쳐짐.

![[PEN200-Fig-093.png]]

*HTTP History — 브라우저가 대상에 보낸 요청 목록*

히스토리에 `detectportal.firefox.com` 이 계속 뜨는 것은 **캡티브 포털** 탐지 때문임. 캡티브 포털은 Wi-Fi 인증이나 이용약관 동의 때 뜨는 관문 페이지임. 없애려면 주소창에 `about:config` 를 넣고 경고를 지난 뒤 `network.captive-portal-service.enabled` 를 더블클릭해 `false` 로 바꿈.

**Repeater** 는 Proxy 다음으로 기본이 되는 도구임 — 새 요청을 만들거나 History 의 요청을 고쳐 다시 보내고 응답을 확인함. Proxy > HTTP History 에서 요청을 우클릭해 Send to Repeater 를 고르면 Repeater 탭에 하위 탭으로 붙고, 여러 개를 보내면 탭이 각각 생김. Send 를 누르면 오른쪽에 응답 헤더와 렌더링되지 않은 원본 응답 내용이 그대로 나옴.

**Intruder** 는 단순한 것부터 복잡한 것까지 여러 공격 각도를 자동화하는 도구임. 실습에 앞서 Kali 의 `/etc/hosts` 에 대상 호스트명을 고정으로 넣음.

```
kali@kali:~$ cat /etc/hosts
...
192.168.50.16 offsecwp
```

*`/etc/hosts` 에 대상 호스트명 고정*

이유 — 일부 웹 애플리케이션은 링크와 리다이렉트에 자기 **호스트명**을 넣음. `/etc/hosts` 에 대응 항목이 없으면 브라우저와 도구가 그 링크를 따라가지 못함. 이 방법은 DNS 를 우회해 호스트명으로 VM 에 접근하게 해 줌.

비밀번호 브루트포싱 시뮬레이션 흐름은 이렇게 됨. ① 새 Burp 세션을 열고 앞과 같이 Proxy 를 설정함 ② Firefox 로 `http://offsecwp/wp-login.php` 에 접속해 사용자명 `admin`, 비밀번호 `test` 로 로그인 실패를 한 번 만듦 ③ Proxy > HTTP History 에서 `/wp-login.php` 로 간 POST 요청을 우클릭해 Send to Intruder ④ Intruder 탭에서 그 POST 요청을 고르고 Positions 하위 탭으로 이동함. 사용자명 `admin` 이 맞다는 것을 아니 **비밀번호 필드만** 브루트포싱하면 됨 — 오른쪽 Clear 로 자리를 전부 지운 뒤 `pwd` 키의 값을 선택하고 Add 를 누름.

![[PEN200-Fig-100.png]]

*Positions — `pwd` 값만 페이로드 자리로 지정, 요청마다 비밀번호만 바뀜*

⑤ Payloads 하위 탭의 Payload Options: [Simple list] 에 워드리스트를 붙여넣음. 여기서는 정답 `password` 가 포함된 rockyou 앞 10 줄을 씀.

```
kali@kali:~$ cat /usr/share/wordlists/rockyou.txt | head
123456
12345
123456789
password
iloveyou
princess
1234567
rockyou
12345678
abc123
```

*rockyou 앞 10 줄 확보*

⑥ 우상단 Start Attack 을 누름. Intruder 기능 제한 경고가 뜨지만 이 공격에는 영향이 없어 넘어감.

공격이 끝나면 최초 탐색 요청 외에 워드리스트 항목 수만큼 10 회 요청이 나간 것을 볼 수 있고, **4번째 요청의 Status code 가 다른 것**이 정답 비밀번호라는 단서임. 실제로 그 값으로 WordPress 관리 콘솔에 로그인해 가설을 확인함.
