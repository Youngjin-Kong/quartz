# 4.4.1 실행 권한이란

> **What is Executable Permission?** · PEN-200 §4.4.1

리눅스의 모든 파일에는 생성 시각·생성한 사용자·파일명 같은 부가 속성이 딸려 있고, 그중 특히 중요한 것이 **파일 권한(file permissions)** 임. 권한은 읽기·쓰기·실행 세 가지 동작의 허용 여부를 정함. 여기서 쓰기(write)는 그 파일에 일정한 변경을 가할 수 있는 능력을 뜻함. 쓰기를 막아 실수로 지워지는 것을 방지하거나, 볼 자격이 없는 내용을 읽지 못하게 막는 용도로 쓰임.

권한은 세 부류의 사용자에게 각각 부여됨 — 파일 소유자, 소유 그룹, 그 외 전부. 이 단원은 소유자(=자기 자신)만 다룸.

`touch` 로 파일을 만들면 만든 사람이 소유자가 되고, `ls -l` 의 롱 리스팅으로 권한을 확인할 수 있음. 새 파일의 권한은 `-rw-r--r--` 로 나옴 — `r`=읽기, `w`=쓰기, `x`=실행이고 `-` 는 그 권한이 없다는 뜻임. 즉 **새로 만든 파일에는 기본적으로 실행 권한이 없음.** 원치 않는 것을 실수로 실행하는 것을 막는 작지만 유용한 보안 장치임.

```
kali@kali:~$ touch newfilename.txt
kali@kali:~$ ls -l newfilename.txt
-rw-r--r-- 1 kali kali 0 Jun  6 12:31 newfilename.txt
```

*`touch` 로 만든 새 파일의 권한 — 읽기·쓰기만 있고 `x` 가 없음*

> [!warning] `touch` 는 디렉터리 권한 때문에 실패할 수 있음
> 디렉터리 권한은 그 안의 모든 파일·디렉터리에 적용됨. 해당 위치에 파일을 만들 권한이 없으면 `touch` 는 당연히 실패함. `touch` 가 아무 출력도 내지 않는 것은 정상임.

직원 명단을 뽑는 파이썬 스크립트 `find_employee_names.py` 를 실행해 보면 권한 문제가 그대로 드러남. `./` 는 파일의 위치를 시스템에 알려주는 부분임.

```
kali@kali:~$ ./find_employee_names.py
zsh: permission denied: ./find_employee_names.py
kali@kali:~$ ls -l find_employee_names.py
-rw-r--r-- 1 kali kali 206 Jun  7 12:31 find_employee_names.py
```

*스크립트 실행 첫 시도 — `x` 가 없어 거부됨*

`permission denied` 가 뜨는 이유는 `ls -l` 출력에 `x` 가 없기 때문임. `chmod +x` 로 실행 권한을 더하면 세 부류 전부에 `x` 가 붙고, 스크립트가 기대한 대로 명단을 출력함.

```
kali@kali:~$ chmod +x find_employee_names.py
kali@kali:~$ ls -l find_employee_names.py
-rwxr-xr-x 1 kali kali 206 Jun  7 12:31 find_employee_names.py
kali@kali:~$  ./find_employee_names.py
R. Jones
R. Diggs
G. Grice
C. Smith
C. Woods
D. Coles
J. Hunter
L. Hawkins
E. Turner
D. Hill
```

*chmod 이후 두 번째 시도 — 권한이 붙자 실행됨*

권한을 더할 때 `+x` 를 썼으니 되돌릴 때는 `-x` 를 씀. 그러면 처음의 오류 메시지로 돌아감.

```
kali@kali:~$ chmod -x find_employee_names.py
kali@kali:~$ ./find_employee_names.py
zsh: permission denied: ./find_employee_names.py
```

*원상 복구 — `chmod -x` 로 실행 권한 제거*

여기까지가 실행 권한 비트, `chmod` 도구, `+x`·`-x` 옵션에 대한 아주 기초적인 이해임.
