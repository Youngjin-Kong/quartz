# 26.4.2 Git 이력에서 시크릿 검색

> **Searching for Secrets in Git** · PEN-200 §26.4.2

git 은 현재 파일뿐 아니라 **이력 전체**를 담으므로 이력까지 봐야 함. **자동 도구가 못 찾았다고 없는 것이 아니므로 수동 검토를 반드시 붙일 것.**

도구는 `gitleaks` 를 씀. apt 로 설치함.

```
kali@kali:~/static_content$ sudo apt update
...
kali@kali:~/static_content$ sudo apt install -y gitleaks
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
The following NEW packages will be installed:
  gitleaks
...
```

*gitleaks 설치 — 패키지 목록 갱신 후 설치*

저장소 루트(`static_content/`)에서 `gitleaks detect` 를 실행함.

```
kali@kali:~/static_content$ gitleaks detect
    ○
    │╲
    │ ○
    ○ ░
    ░    gitleaks
1:58PM INF no leaks found
1:58PM INF scan completed in 61.787205ms
```

`no leaks found` — 자동 스캔은 실패. 여기서 멈추면 이 절의 소득이 0 이 됨.

*`Fix issue` 커밋의 diff — 삭제된 `-` 줄에 하드코딩 Authorization 헤더가 남아 있음*

diff 는 `scripts/update-readme.sh` 에서 **미리 채워져 있던 Authorization 헤더를 지우고 자격 증명을 명령행 인자로 받도록 바꾼 것**임. 삭제된 줄에 `-H 'authorization: Basic YWRtaW5pc3RyYXRvcjo5bndrcWU1aGxiY21jOTFu'` 가 그대로 남아 있음.

테스트 중 하드코딩했다 지우는 것은 흔한 실수이고, **지워진 자격 증명이 아직 유효한 경우가 많음** — 커밋에서 지웠을 뿐 계정에서 폐기한 것이 아니라서임.

Basic 인증 헤더는 `<username>:<password>` 를 base64 로 인코딩한 것일 뿐이므로 그대로 되돌릴 수 있음(값은 랩마다 다름).

```
kali@kali:~/static_content$ echo "YWRtaW5pc3RyYXRvcjo5bndrcWU1aGxiY21jOTFu" | base64 -
-decode
administrator:9nwkqe5hlbcmc91n
```

*헤더 디코딩 — 평문 자격 증명이 그대로 나옴. `--decode` 가 두 줄로 나뉜 것은 교재 지면 폭 때문임*

이 자격 증명으로 Gitea 의 Sign In 을 통과해 **administrator 로 로그인됨.** 권한이 올라갔으므로 **열거를 처음부터 다시 돌려야 함** — 인증 전에 안 보이던 자산이 이제 보임.
