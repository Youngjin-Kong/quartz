# 28.1.2 챌린지 랩 0-3

> **Challenge Labs 0-3** · PEN-200 §28.1.2

챌린지 랩은 세 종류이고, 그중 첫 넷(0~3)이 «시나리오»형임. 네트워크로 묶인 머신 집합에 배경 스토리가 붙는 구성이며, 목표는 Active Directory 도메인의 Domain Administrator 계정 확보와 가능한 한 많은 머신의 침해임.

Capstone 이 여러 Learning Unit 을 묶어 시험하듯 시나리오는 여러 모듈을 묶어 시험함. 어느 머신이 어떤 공격에 취약한지 모르는 채 시작하므로 불확실성 수준이 실제 침투 테스트에 가까움. 0 → 3 으로 갈수록 머신·서브넷·공격 벡터가 늘어 복잡도가 올라감.

특정 머신이 «직접» 취약하다는 보장 자체가 없다는 점이 핵심임 — 다른 머신에서 얻은 정보·자격 증명·능력에 의존하는 머신이 있고, 도메인 컨트롤러를 먼저 침해해야 비로소 (의도적으로) 공략 가능해지는 머신도 있음.

모든 머신에 `local.txt` 또는 `proof.txt`, 혹은 둘 다 존재함. 내용은 무작위 해시이고 OLP 에 제출해 침해를 기록함. 모듈 연습 플래그와 마찬가지로 **머신을 revert 할 때마다 값이 바뀜**.

**랩 0 — SECURA.** 3대 규모 기업 환경. 랩 1~3 에 들어가기 전 워밍업용임. ManageEngine 취약점 공략 → 내부 서비스로 피벗 → 취약한 GPO 권한으로 권한 상승해 도메인 장악. 모의 시험은 아니지만 OSCP+ 시험과 동일한 Assumed Breach 방식이라 초기 자격 증명이 주어짐.

**랩 1 — MEDTECH.** 신생 IoT 헬스케어 스타트업. AD 보안 태세를 개선하고 공격 표면을 줄이기 위해 취약점과 오설정을 최대한 많이 찾는 것이 목표.

**랩 2 — RELIA.** 임업용 주행 시스템을 만드는 산업 회사. 몇 주 전 공격을 당해 IT 보안 진단을 의뢰한 설정임. 외부 경계를 뚫고 내부망에서 Domain Admin 권한까지 갈 수 있는지 확인하는 것이 의뢰 목적.

**랩 3 — SKYLARK.** 항공우주 다국적 기업. 지사가 APT 랜섬웨어 공격을 받은 뒤 CISO 가 선제 진단을 의뢰함. ⚠️ **0·1·2 보다 현저히 어렵고 OSCP 시험 범위 밖임** — 대량의 피벗과 터널링, 여러 타겟에 걸친 정보 수집, 포스트 익스플로잇에 대한 세밀한 주의가 필요함. 시험 준비가 주목적이면 4·5·6 을 먼저 하고 나중에 돌아올 것.
