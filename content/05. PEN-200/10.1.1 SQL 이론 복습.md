# 10.1.1 SQL 이론 복습

> **SQL Theory Refresher** · PEN-200 §10.1.1

SQL — 관계형 데이터베이스의 데이터를 조회·삽입·수정·삭제하는 언어. 구성에 따라 **OS 명령 실행까지** 가능해 SQL 인스턴스가 가진 관리 권한 자체가 위험 요소임.

현대 웹앱의 3계층 구조 — 프런트엔드(HTML/CSS/JavaScript) → 백엔드(PHP·Java·Python 등) → 데이터베이스. 사용자가 프런트엔드에 넣은 값이 백엔드를 거쳐 DB 질의에 실린다는 것이 SQLi 의 출발점임.

문법·함수는 DB 구현마다 다름 — MySQL, Microsoft SQL Server, PostgreSQL, Oracle 이 주요 변종이라 대상 판별(fingerprinting)이 선행돼야 함.

기본형 — `SELECT` 로 가져올 컬럼(`*` = 전부), `FROM` 으로 대상 테이블, `WHERE` 로 조건을 건다.

```
SELECT * FROM users WHERE user_name='leon'
```

*users 테이블에서 특정 사용자만 걸러내는 질의*

로그인 처리 백엔드가 이 질의를 소스에 박아두는 전형적 형태:

```
<?php
$uname = $_POST['uname'];
$passwd = $_POST['password'];
$sql_query = "SELECT * FROM users WHERE user_name= '$uname' AND password='$passwd'";
$result = mysqli_query($con, $sql_query);
?>
```

*POST 로 받은 값을 그대로 질의 문자열에 이어 붙이는 취약 코드*

POST 로 받은 `uname`·`passwd` 가 **아무 검사 없이** `$sql_query` 문자열에 연결됨 → 사용자가 질의문의 일부를 직접 쓰는 셈이 됨. `mysqli_query` 로 실행되기 전에 공격자가 최종 SQL 문을 바꿔치기할 수 있는 것이 취약점의 실체임.

⚠️ `mysqli_query` 의 `i` 는 improved 의 약자로 injection 과 무관함.

동작 예 — 입력이 `leon` 이면 `WHERE user_name= leon` 이 실행됨. 입력이 `leon '+!@#$` 이면 그 특수문자가 그대로 질의에 들어가 문법이 깨짐. **특수문자를 걸러내는 코드가 없다는 것**이 곧 취약점이고, 이 깨짐을 통제 가능한 방향으로 유도하는 것이 이후 절의 공격임.
