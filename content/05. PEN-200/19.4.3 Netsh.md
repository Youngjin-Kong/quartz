# 19.4.3 Netsh

> **Netsh** · PEN-200 §19.4.3

Netsh(Network Shell)는 Windows 내장 네트워크·방화벽 설정 도구임. `interface` 컨텍스트의 `portproxy` 서브컨텍스트로 **추가 바이너리를 올리지 않고** 포트 포워드를 만들 수 있어, 도구 반입이 막힌 제한적 상황에서 값이 큼.

⚠️ **전제 둘을 놓치면 반드시 실패함.**
- `netsh interface portproxy` 로 무엇이든 바꾸려면 **관리자 권한**이 필요함. 즉 대부분의 경우 UAC 를 고려해야 함. 예제는 관리자 계정의 RDP 셸에서 실행해 UAC 가 문제되지 않는 조건임
- 포워드 규칙을 만들어도 **Windows 방화벽이 그 포트를 막고 있음.** 인바운드 허용 규칙을 별도로 열어야 외부에서 닿음(아래에서 그대로 겪음)

시나리오는 MULTISERVER03 이 TCP/80 웹앱을 외부에 서비스하고, 편의상 3389 도 인바운드 허용돼 RDP 직접 로그인이 되는 상황임. CONFLUENCE01 은 WAN 에서 접근 불가함. 목표는 Kali 에서 PGDATABASE01 의 SSH 로 바로 붙는 것이고, 그러려면 MULTISERVER03 의 WAN 인터페이스에서 듣고 PGDATABASE01 의 22 로 넘기는 포워드가 필요함.

*xfreerdp 로 MULTISERVER03 에 RDP 접속*

RDP 세션에서 `cmd.exe` 를 관리자로 실행한 뒤 `v4tov4`(IPv4 리스너 → IPv4 포트) 규칙을 추가함. `listen*` 이 외부에 노출할 쪽, `connect*` 가 전달 대상임.

```
C:\Windows\system32>netsh interface portproxy add v4tov4 listenport=2222
listenaddress=192.168.50.64 connectport=22 connectaddress=10.4.50.215
C:\Windows\system32>
```

**성공해도 출력이 없음.** 확인은 둘로 나눠서 함 — `netstat` 으로 실제 리슨 여부를, `portproxy show all` 로 규칙 저장 여부를 봄.

```
C:\Windows\system32>netstat -anp TCP | find "2222"
  TCP    192.168.50.64:2222     0.0.0.0:0              LISTENING
C:\Windows\system32>
```

```
C:\Windows\system32>netsh interface portproxy show all
Listen on ipv4:             Connect to ipv4:
Address         Port        Address         Port
--------------- ----------  --------------- ----------
192.168.50.64   2222        10.4.50.215     22
```

그런데 Kali 에서는 붙지 않음. nmap 으로 찍으면 `filtered` 임 — 포워드 자체는 살아 있는데 Windows 방화벽이 인바운드를 막고 있는 것임.

```
kali@kali:~$ sudo nmap -sS 192.168.50.64 -Pn -n -p2222

*WAN 쪽에서 온 2222 접속을 Windows 방화벽이 차단하는 상태*

`netsh advfirewall firewall add rule` 로 구멍을 뚫음. `localport`·`localip` 이 열 대상, `dir=in` 이 인바운드 방향, `action=allow` 가 허용임. 성공하면 `Ok.` 가 나옴. **`name=` 은 나중에 삭제할 때 참조하는 키이므로 알아볼 수 있게 지을 것.**

```
C:\Windows\system32> netsh advfirewall firewall add rule name="port_forward_ssh_2222"
protocol=TCP dir=in localip=192.168.50.64 localport=2222 action=allow
Ok.
C:\Windows\system32>
```

이제 같은 nmap 이 `open` 으로 바뀌고, Kali 에서 `-p2222` 로 SSH 하면 PGDATABASE01 로 붙음.

```
kali@kali:~$ sudo nmap -sS 192.168.50.64 -Pn -n -p2222
Starting Nmap 7.92 ( https://nmap.org ) at 2022-07-21 06:28 EDT

**끝나면 반드시 되돌릴 것.** 방화벽 규칙은 만들 때 준 이름으로 지우고, portproxy 는 `v4tov4` 와 생성 시의 `listenaddress`·`listenport` 를 그대로 넘겨 어느 규칙인지 특정해 지움.

```
C:\Users\Administrator>netsh advfirewall firewall delete rule
name="port_forward_ssh_2222"
Deleted 1 rule(s).
Ok.
```

```
C:\Windows\Administrator> netsh interface portproxy del v4tov4 listenport=2222
listenaddress=192.168.50.64
C:\Windows\Administrator>
```

포워드 삭제는 생성과 마찬가지로 성공해도 아무 출력이 없음 — 무응답을 실패로 오판하지 말 것.

PowerShell 에는 `New-NetFirewallRule`·`Disable-NetFirewallRule` 같은 대응 cmdlet 이 있으나 **`netsh interface portproxy` 에 해당하는 cmdlet 은 없음.** 방화벽 열거·설정은 PowerShell 이 편해도 포트프록시만은 Netsh 를 써야 함.
