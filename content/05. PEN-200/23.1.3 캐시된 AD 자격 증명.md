# 23.1.3 캐시된 AD 자격 증명

> **Cached AD Credentials** · PEN-200 §23.1.3

Microsoft 의 Kerberos 구현은 싱글 사인온을 쓰므로 TGT 갱신 요청을 하려면 패스워드 해시를 어딘가 보관해야 함. 최신 Windows 는 이를 **LSASS(Local Security Authority Subsystem Service)** 의 메모리 공간에 저장함.

이 해시를 손에 넣으면 크랙해 평문 패스워드를 얻거나 그대로 재사용할 수 있음. 다만 LSASS 는 운영체제의 일부이고 SYSTEM 으로 돌기 때문에 **SYSTEM 또는 로컬 관리자 권한**이 있어야 접근이 됨 — AD 공격이 로컬 권한 상승부터 시작하는 경우가 많은 이유임. 게다가 메모리 내 해시 저장 구조는 공개돼 있지 않고 LSASS 가 쥔 키로 암호화까지 돼 있음.

그럼에도 캐시 자격 증명 추출은 Windows·AD 를 상대로 한 대형 공격 벡터라 전용 도구가 여럿 만들어졌고, 그 중 가장 유명한 것이 **Mimikatz** 임.

아래 예시는 Mimikatz 를 standalone 애플리케이션으로 실행하지만, 워낙 대중적이라 탐지 시그니처가 잘 알려져 있으므로 실제로는 피하는 편이 나음. PowerShell 같은 인젝터로 메모리에서 직접 실행하거나, 작업 관리자 같은 내장 도구로 LSASS 프로세스 메모리를 통째로 덤프해 다른 머신으로 옮긴 뒤 Mimikatz 에 로드하는 방법이 있음.

도메인 사용자 jeff 는 CLIENT75 의 로컬 관리자이므로 `HenchmanPutridBonbon11` 로 RDP 접속한 뒤 권한 상승된 PowerShell 을 띄울 수 있음. 거기서 Mimikatz 를 실행하고 `privilege::debug` 로 SeDebugPrivilege 를 켬 — 다른 계정이 소유한 프로세스와 상호작용하기 위한 권한임.

```
kali@kali:~$ xfreerdp /cert-ignore /u:jeff /d:corp.com /p:HenchmanPutridBonbon11
/v:192.168.50.75
```

*Kali 에서 CLIENT75 로 RDP 접속*

```
PS C:\Windows\system32> cd C:\Tools
PS C:\Tools\> .\mimikatz.exe
...
mimikatz # privilege::debug
Privilege '20' OK
```

*도메인 워크스테이션에서 Mimikatz 실행 — jeff·dave 의 캐시 해시*

출력에 해시가 두 종류 보이는데, 어떤 것이 나오는지는 AD 구현의 기능 수준에 달림. Windows 2003 기능 수준이면 NTLM 만 쓸 수 있고, Windows Server 2008 이상이면 NTLM 과 SHA-1(AES 암호화의 흔한 동반자)이 함께 나올 수 있음. Windows 7 처럼 오래된 OS 이거나 수동으로 켜 둔 경우 **WDigest** 가 활성이고, 그러면 Mimikatz 가 해시 옆에 **평문 패스워드**까지 보여줌.

방어 측면에서는 **LSA Protection** 을 추가로 켜는 것이 효과적임 — 레지스트리 키 하나로 Windows 가 이 프로세스의 메모리 읽기를 막음.

Mimikatz 의 다른 쓰임은 TGT·서비스 티켓을 악용하는 것임. 로컬 머신에 로그온한 사용자의 Kerberos 티켓도 LSASS 에 저장되므로 자기 티켓뿐 아니라 다른 로컬 사용자의 티켓도 꺼낼 수 있음. 서비스 티켓을 만들어 캐시시키려면 해당 리소스를 한 번 건드리면 됨 — WEB04 의 SMB 공유를 UNC 경로로 나열하는 것으로 충분함.

*`sekurlsa::tickets` 로 메모리에 저장된 Kerberos 티켓 추출*

출력에 TGT 와 TGS 가 모두 보임. TGS 를 훔치면 그 티켓에 묶인 특정 리소스에만 접근할 수 있지만, TGT 를 쥐면 도메인 안에서 노리는 리소스의 TGS 를 새로 요청할 수 있음. Mimikatz 는 티켓을 디스크로 내보내고 다시 LSASS 로 불러오는 것도 지원함.

캐시·저장 객체의 다른 축으로 PKI 가 있음. Microsoft 는 **AD CS(Active Directory Certificate Services)** 역할로 PKI 를 제공하며, 인증된 사용자와 신뢰 리소스 사이에 디지털 인증서를 교환함. Certification Authority(CA)로 설치된 서버는 인증서를 발급·폐기할 수 있음. 웹 서버의 HTTPS 용이나 스마트카드 기반 사용자 인증에 쓰임.

보안상 인증서는 **개인 키를 export 불가**로 표시할 수 있고, 그러면 관리자 권한으로도 개인 키를 빼낼 수 없음. 그러나 우회 방법이 여럿 있고 여기서도 Mimikatz 를 씀 — crypto 모듈의 `crypto::capi` 는 CryptoAPI 함수를, `crypto::cng` 는 KeyIso 서비스를 패치해 export 불가 키를 export 가능하게 만듦.
