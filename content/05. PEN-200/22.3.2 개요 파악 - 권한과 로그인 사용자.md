# 22.3.2 개요 파악 - 권한과 로그인 사용자

> **Getting an Overview - Permissions and Logged on Users** · PEN-200 §22.3.2

컴퓨터·사용자·그룹 목록을 확보했으니 이제 **객체 사이의 관계**로 넘어감. 관계가 공격에서 핵심 역할을 하는 대표 예가 자격 증명의 캐싱임 — 사용자가 도메인에 로그인하면 그 자격 증명이 **로그인한 컴퓨터의 메모리에 캐시로 남음**. 그 컴퓨터를 장악해 캐시를 훔치면 해당 도메인 사용자로 인증할 수 있고, 대상에 따라 도메인 권한 상승까지 이어짐. 그래서 「누가 어디에 로그인해 있는가」가 곧 지도의 간선이 됨.

다만 권한 상승을 곧바로 노리는 것이 항상 최선은 아님. 먼저 할 일은 **발판을 굳히고 접근을 유지하는 것**임. 이미 가진 계정과 같은 권한을 가진 다른 사용자를 추가로 장악해두면, 원래 계정의 비밀번호가 재설정되거나 관리자가 이상 징후를 보고 계정을 비활성화해도 도메인 접근이 끊기지 않음.

상승 대상도 반드시 Domain Admins 여야 하는 것은 아님. 뒤에서 다룰 **서비스 계정**처럼 Domain Admins 가 아니면서도 일반 도메인 사용자보다 큰 권한 — 예컨대 특정 서버의 로컬 관리자 권한 — 을 가진 계정이 있음. 조직의 진짜 핵심 데이터도 데이터베이스나 파일 서버처럼 도메인 관리자 권한 없이 닿는 곳에 있는 경우가 많아, 실무에서는 도메인 관리자가 목표가 아닐 수 있음(단 Challenge Lab 의 목표는 도메인 관리자임). 이렇게 여러 계정을 단계적으로 갈아타며 목표에 접근하는 것을 **연쇄 침해(chained compromise)** 라 부름.

**어디에 관리자 권한이 있는가** — PowerView 의 `Find-LocalAdminAccess` 가 현재 사용자로 도메인 내 컴퓨터에 관리자 권한이 있는지 훑음. 동작 원리는 `OpenServiceW` 함수로 대상의 서비스 제어 관리자(Service Control Manager, SCM)에 접속을 시도하는 것임. SCM 은 설치된 서비스·드라이버의 데이터베이스를 관리하는데, PowerView 는 이것을 **`SC_MANAGER_ALL_ACCESS` 권한으로** 열어보고 성공하면 관리자 권한이 있다고 판정함 — 그 접근권 자체가 관리자를 요구하기 때문임. `-ComputerName`·`-Credential` 로 대상과 자격 증명을 지정할 수 있으나, 인자 없이 돌리면 현재 로그인 컨텍스트로 전 대상을 훑는 스프레이가 됨. 환경 규모에 따라 수 분이 걸림.

```
PS C:\Tools> Find-LocalAdminAccess
client74.corp.com
```

stephanie 가 CLIENT74 의 관리자라는 결과임. 곧바로 CLIENT74 로 넘어가고 싶어지지만, 여기서 멈추지 말고 열거를 계획대로 마치는 것이 규율임.

**누가 어디에 로그인해 있는가** — 전통적으로 쓰인 Windows API 는 `NetWkstaUserEnum` 과 `NetSessionEnum` 둘임. 전자는 관리자 권한이 필요하고 후자는 필요 없음. PowerView 의 `Get-NetSession` 이 내부에서 이 둘을 씀.

⚠️ **여기가 함정임 — 결과가 없는 것과 실패한 것이 화면상 구분되지 않음.**

```
PS C:\Tools> Get-NetSession -ComputerName files04
PS C:\Tools> Get-NetSession -ComputerName web04
PS C:\Tools>
```

출력이 아예 없으니 「로그인한 사용자가 없다」로 읽기 쉬우나, 실제로는 오류가 조용히 삼켜진 것임. `-Verbose` 를 붙여야 드러남.

```
PS C:\Tools> Get-NetSession -ComputerName files04 -Verbose
VERBOSE: [Get-NetSession] Error: Access is denied
PS C:\Tools> Get-NetSession -ComputerName web04 -Verbose
VERBOSE: [Get-NetSession] Error: Access is denied
```

`Access is denied` — 질의 자체가 거부된 것이지 세션이 없는 것이 아님. **`Get-NetSession` 이 빈 결과를 주면 반드시 `-Verbose` 로 재확인할 것.**

관리자 권한이 있는 CLIENT74 에 돌리면 값이 나오기는 함. 그런데 `CName` 의 IP 가 CLIENT74 가 아니라 **현재 우리 머신인 CLIENT75(192.168.50.75)** 임. CLIENT74 로 세션을 연 적이 없으므로 이 출력도 그대로 믿을 것이 못 됨.

```
PS C:\Tools> Get-NetSession -ComputerName client74
CName        : \\192.168.50.75
UserName     : stephanie
Time         : 8
IdleTime     : 0
ComputerName : client74
```

**왜 안 되는가** — `NetSessionEnum` 은 질의 레벨 0·1·2·10·502 를 가짐. 레벨 0 은 세션을 맺은 컴퓨터 이름만 반환하고, 1·2 는 정보가 많지만 관리자 권한이 필요함. 남는 10 과 502 는 컴퓨터 이름과 사용자 이름을 함께 주며, PowerView 는 기본으로 **레벨 10** 을 씀. 그 권한을 정하는 것이 `SrvsvcSessionInfo` 레지스트리 키이고, 위치는 `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\LanmanServer\DefaultSecurity` 임. `Get-Acl` 의 `-Path` 로 그 하이브의 권한을 확인함.

```
PS C:\Tools> Get-Acl -Path
HKLM:SYSTEM\CurrentControlSet\Services\LanmanServer\DefaultSecurity\ | fl
Path   :
Microsoft.PowerShell.Core\Registry::HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Servic
es\LanmanServer\DefaultSecurity\
Owner  : NT AUTHORITY\SYSTEM
Group  : NT AUTHORITY\SYSTEM
Access : BUILTIN\Users Allow  ReadKey
         BUILTIN\Administrators Allow  FullControl
         NT AUTHORITY\SYSTEM Allow  FullControl
         CREATOR OWNER Allow  FullControl
         APPLICATION PACKAGE AUTHORITY\ALL APPLICATION PACKAGES Allow  ReadKey
         S-1-15-3-1024-1065365936-1281604716-3511738428-1654721687-432734479-
3232135806-4053264122-3456934681 Allow  ReadKey
```

`BUILTIN\Users` 가 `ReadKey` 를 가진 것처럼 보이지만, `BUILTIN`·`NT AUTHORITY`·`CREATOR OWNER`·`APPLICATION PACKAGE AUTHORITY` 는 전부 **시스템이 정의한 주체**라 원격에서 이 키를 열거하는 데 쓰이지 않음. 끝의 긴 문자열은 **capability SID** — Windows 구성요소나 UWP 앱에 특정 자원 접근을 부여하는 위조 불가 토큰이며, 이것 역시 원격 접근을 주지 않음. 예전 Windows 에서는 `Authenticated Users` 가 이 하이브를 읽어 `SrvsvcSessionInfo` 를 가져올 수 있었으나, 최소 권한 원칙에 따라 일반 도메인 사용자가 세션 정보를 캐지 못하도록 권한이 바뀐 것으로 보임. 즉 기본 설정의 Windows 11 에서는 **이 권한 구성 때문에** `NetSessionEnum` 이 이런 정보를 못 가져오는 것이 확실함.

언제부터인지는 OS 빌드로 추정할 수 있음. `operatingsystemversion` 까지 붙여 다시 열거함.

```
PS C:\Tools> Get-NetComputer | select
dnshostname,operatingsystem,operatingsystemversion
dnshostname       operatingsystem              operatingsystemversion
-----------       ---------------              ----------------------
DC1.corp.com      Windows Server 2022 Standard 10.0 (20348)
web04.corp.com    Windows Server 2022 Standard 10.0 (20348)
FILES04.corp.com  Windows Server 2022 Standard 10.0 (20348)
client74.corp.com Windows 11 Pro               10.0 (22000)
client75.corp.com Windows 11 Pro               10.0 (22000)
CLIENT76.corp.com Windows 10 Pro               10.0 (16299)
```

가장 오래된 Windows 10 이 빌드 16299, 즉 1709 임. Microsoft 문서가 변경 시점을 명시하지 않으나 대략 이 빌드 전후로 보이고, 서버 계열은 Windows Server 2019(빌드 1809) 이후 전부 영향을 받는 것으로 보임. 그래도 `NetSessionEnum` 을 도구함에서 빼지는 말 것 — 실환경에는 그보다 낡은 시스템이 흔함.

**대안 — PsLoggedOn.** SysInternals Suite 의 도구로, `HKEY_USERS` 아래 레지스트리 키를 훑어 로그인한 사용자의 SID 를 얻고 그것을 사용자명으로 변환함. 동시에 `NetSessionEnum` 도 써서 리소스 공유를 통해 붙은 사용자까지 보여줌. 제약은 **원격 레지스트리(Remote Registry) 서비스에 의존**한다는 것임 — Windows 8 이후 워크스테이션에서는 기본 비활성이지만 관리 작업·하위 호환·모니터링 에이전트 설치 때문에 관리자가 켜두는 경우가 있고, Server 2012 R2·2016(1607)·2019(1809)·2022(21H2) 에서는 기본 활성임. 유휴 10분이면 멈추지만 접속 시 자동 트리거로 다시 뜸. CLIENT75 의 `C:\Tools\PSTools` 에 있고 대상 호스트명만 붙여 실행함.

```
PS C:\Tools\PSTools> .\PsLoggedon.exe \\files04
PsLoggedon v1.35 - See who's logged on
Copyright (C) 2000-2016 Mark Russinovich
Sysinternals - www.sysinternals.com
Users logged on locally:
     <unknown time>             CORP\jeff
Unable to query resource logons
```

FILES04 에 jeff 가 로컬 로그인 중임 — 새 공격 벡터라 기록해둘 것.

```
PS C:\Tools\PSTools> .\PsLoggedon.exe \\web04
PsLoggedon v1.35 - See who's logged on
Copyright (C) 2000-2016 Mark Russinovich
Sysinternals - www.sysinternals.com
No one is logged on locally.
Unable to query resource logons
```

WEB04 는 로그인 사용자가 없음. 원격 레지스트리가 실제로 도는지 확인할 수 없으므로 **결과가 틀렸을 가능성이 남으나**, 오류 메시지가 없었으므로 결과를 신뢰함.

> ⚠️ **교재 표현** — 교재는 이 경우를 `false positive` 로 적으나, 「로그인 사용자 없음」이 틀린 것이면 실제로는 거짓 음성(false negative)임.

CLIENT74 는 stephanie 로 관리자 권한이 있다고 판정된 곳이라 특히 중요함(교육 목적으로 원격 레지스트리가 켜져 있음).

```
PS C:\Tools\PSTools> .\PsLoggedon.exe \\client74
PsLoggedon v1.35 - See who's logged on
Copyright (C) 2000-2016 Mark Russinovich
Sysinternals - www.sysinternals.com
Users logged on locally:
     <unknown time>             CORP\jeffadmin
Users logged on via resource shares:
     10/5/2022 1:33:32 AM       CORP\stephanie
```

jeffadmin 이 CLIENT74 에 세션을 열어둔 상태임. 앞선 열거가 정확해서 그 머신의 관리자 권한이 실제로 우리에게 있다면 **로그인해서 jeffadmin 의 자격 증명을 훔칠 수 있다**는 뜻임. `jeffadmin` 은 §22.2.1 에서 `Domain Admins` 소속으로 확인된 계정이라, 도메인 관리자까지 그대로 이어질 수 있는 경로임. 또 stephanie 가 `Users logged on via resource shares` 로 잡히는데, 이는 PsLoggedOn 이 `NetSessionEnum` 도 함께 쓰기 때문이며 앞서 `Get-NetSession` 이 CLIENT75 의 IP 를 보여준 것도 같은 이유로 설명됨.

여기까지가 장악한 사용자와 도메인 내 활성 세션의 열거임. 다음 절은 성격이 다른 사용자, 곧 서비스 계정으로 넘어감.
