# 22.3.3 SPN을 통한 열거

> **Enumeration Through Service Principal Names** · PEN-200 §22.3.3

사용자 열거의 마지막은 **서비스 계정**임. 고권한 그룹에 들어 있는 경우가 있어 값을 함.

모든 애플리케이션은 어떤 OS 사용자의 컨텍스트로 실행됨. 사용자가 직접 띄운 것이면 그 사용자가 컨텍스트지만, 시스템이 띄우는 서비스는 **서비스 계정**의 컨텍스트로 돌아감. 단순한 애플리케이션은 `LocalSystem`·`LocalService`·`NetworkService` 같은 사전 정의 계정으로 충분하나, 도메인 내 자원에 접근해야 하는 복잡한 애플리케이션은 **도메인 사용자 계정**을 서비스 계정으로 씀. Exchange·MS SQL·IIS 처럼 AD 와 통합된 애플리케이션에서는 **서비스 주체 이름(Service Principal Name, SPN)** 이라는 고유 식별자가 서비스와 그 서비스 계정을 이어줌.

계정 종류의 변천은 알아둘 것 — Windows Server 2008 R2 의 Managed Service Account 는 AD 와의 통합을 강화했으나 서버 이중화를 지원하지 않았고, 가용성이 필요한 MS SQL·Exchange 를 위해 Windows Server 2012 에서 Group Managed Service Account 가 나옴. 다만 후자는 도메인 컨트롤러가 2012 이상이어야 해서, **여전히 평범한 도메인 계정을 서비스 계정으로 쓰는 조직이 남아 있음.**

공격자 관점에서 SPN 이 값을 하는 이유는 **포트 스캔을 대신하기 때문**임. AD 와 통합된 서버에서 도는 애플리케이션의 호스트명과 포트가 SPN 으로 등록돼 DC 에 저장돼 있으므로, 광범위한 스캔 없이 DC 에 질의하는 것만으로 서비스 지도를 얻음.

열거 수단은 여럿인데, Windows 에 기본 설치된 `setspn.exe` 를 쓸 수 있음. `-L` 은 서버·클라이언트 양쪽에 대해 동작함. 앞서 발견한 `iis_service` 계정부터 확인함.

```
c:\Tools>setspn -L iis_service
Registered ServicePrincipalNames for CN=iis_service,CN=Users,DC=corp,DC=com:
        HTTP/web04.corp.com
        HTTP/web04
        HTTP/web04.corp.com:80
```

전체 도메인 계정을 훑는 방법은 PowerView 임. `-SPN` 으로 SPN 이 걸린 계정만 걸러내고, `select samaccountname,serviceprincipalname` 으로 계정과 SPN 만 뽑음.

```
PS C:\Tools> Get-NetUser -SPN | select samaccountname,serviceprincipalname
samaccountname serviceprincipalname
-------------- --------------------
krbtgt         kadmin/changepw
iis_service    {HTTP/web04.corp.com, HTTP/web04, HTTP/web04.corp.com:80}
```

`krbtgt` 는 뒤의 AD 모듈에서 다룸. `iis_service` 의 `serviceprincipalname` 이 `HTTP/web04.corp.com`·`HTTP/web04`·`HTTP/web04.corp.com:80` 이라 웹 서버임이 드러남 — 프로토콜·호스트·포트가 SPN 문자열 자체에 들어 있음. 호스트명을 `nslookup.exe` 로 풀어봄.

```
PS C:\Tools\> nslookup.exe web04.corp.com
Server:  UnKnown
Address:  192.168.50.70
Name:    web04.corp.com
Address:  192.168.50.72
```

내부 IP 로 해석되고, 그 주소로 접속하면 로그인을 요구하는 웹사이트가 나옴. 서비스를 구동하는 계정이므로 일반 도메인 사용자보다 권한이 클 것으로 가정할 수 있음. 지금은 `iis_service` 에 SPN 이 걸려 있다는 사실만 기록해두고, 이후 AD 모듈에서 이것을 공격에 씀.
