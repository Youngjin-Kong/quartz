# 25.5.3 JMESPath로 API 응답 데이터 처리

> **Processing API Response data with JMESPath** · PEN-200 §25.5.3

`aws` 클라이언트는 기본적으로 JSON 을 출력함. JMESPath 는 JSON 질의 언어로, 문서에서 원하는 요소를 뽑고 변형하는 데 씀. 언어 전체를 한 번에 익힐 필요는 없고 **열거 단계에서 모은 응답을 걸러내는 정도**면 충분함. AWS CLI 에서는 `--query` 인자로 표현식을 전달함.

⚠️ `--filter` 와 `--query` 는 동작 위치가 다름 — `--filter` 는 **서버 쪽**에서 걸러 응답 자체를 줄이고, `--query` 는 받은 응답을 **클라이언트 쪽**에서 JMESPath 로 거름. 즉 서버가 안 보낸 것은 `--query` 로 뽑을 수 없음.

예제는 `get-account-authorization-details` 의 출력에 질의를 걸어 봄. 먼저 `--filter User` 로 사용자 데이터만 받은 원본임.

```
kali@kali:~$ aws --profile target iam get-account-authorization-details --filter User
{
    "UserDetailList": [
        {
            "Path": "/admin/",
            "UserName": "admin-alice",
            "UserId": "AIDAQOMAIGYUSSOCFCREC",
            "Arn": "arn:aws:iam::123456789012:user/admin/admin-alice",
            "GroupList": [
                "admin"
            ],
            "AttachedManagedPolicies": [],
            "Tags": []
        },
        {
            "Path": "/amethyst/",
            "UserName": "admin-cbarton",
            "UserId": "AIDAQOMAIGYUTHT4D5YLG",
            "Arn": "arn:aws:iam::123456789012:user/amethyst/admin-cbarton",
            "GroupList": [
                "amethyst_admin"
            ],
            "AttachedManagedPolicies": [],
            "Tags": []
        },
...
```

출력은 최상위에 `UserDetailList` 배열이 있고 각 원소가 사용자 객체(`UserName`·`Path`·`GroupList` 등의 키-값 쌍)인 구조임. 배열의 모든 원소에서 키 하나만 뽑으려면 `UserDetailList[].UserName` 을 씀.

```
kali@kali:~$ aws --profile target iam get-account-authorization-details --filter User
--query "UserDetailList[].UserName"
[
    "admin-alice",
    "admin-cbarton",
    "admin-srogers",
    "admin-tstark",
    "clouddesk-bob",
...
```

*배열 전체에서 `UserName` 값만 추출*

키를 여러 개 뽑는 방법은 둘 — 배열 형태 `[key1, key2, key3]` 이거나 객체 형태 `{식별자1: key1, 식별자2: key2}` 이며 식별자 이름은 임의로 정함. 결과의 형태만 다르고 취향 문제임. 인덱스 `UserDetailList[0]` 으로 첫 원소만 고를 수 있고 `[1]` 은 둘째임.

```
kali@kali:~$ aws --profile target iam get-account-authorization-details --filter User
--query "UserDetailList[0].[UserName,Path,GroupList]"
[
    "admin-alice",
    "/admin/",
    [
        "admin"
    ]
]
kali@kali:~$ aws --profile target iam get-account-authorization-details --filter User
--query "UserDetailList[0].{Name: UserName,Path: Path,Groups: GroupList}"
{
    "Name": "admin-alice",
    "Path": "/admin/",
    "Groups": [
        "admin"
    ]
}
```

*키 여러 개 뽑기 — 배열 형태와 객체 형태*

인덱스보다 강력한 것이 **필터 프로젝션**(filter projection) — 조건으로 원소를 고르는 기능. `[?contains(UserName, 'admin')]` 처럼 함수를 쓰거나 `[?Path=='/admin/']` 처럼 비교를 씀. 이름에 `admin` 이 들어간 고권한 후보를 한 번에 추리는 데 유용함.

```
kali@kali:~$ aws --profile target iam get-account-authorization-details --filter User
--query "UserDetailList[?contains(UserName, 'admin')].{Name: UserName}"
[
    {
        "Name": "admin-alice"
    },
    {
        "Name": "admin-cbarton"
    },
    {
        "Name": "admin-srogers"
    },
...
```

*이름에 `admin` 이 포함된 IAM 사용자만 필터링*

서로 다른 객체에서 뽑아 **새 JSON 객체를 조립**할 수도 있음. 사용자와 그룹을 함께 얻으려면 `--filter User Group` 을 같이 줘야 함 — 서버가 보내지 않은 객체는 클라이언트에서 뽑을 수 없기 때문.

```
kali@kali:~$ aws --profile target iam get-account-authorization-details --filter User
Group --query "{Users: UserDetailList[?Path=='/admin/'].UserName, Groups:
GroupDetailList[?Path=='/admin/'].{Name: GroupName}}"
{
   "Users": [
       "admin-alice"
   ],
   "Groups": [
       {
           "Name": "admin"
       }
   ]
}
```

*사용자와 그룹에서 각각 뽑아 하나의 JSON 객체로 조립*

권고 — 요청 수를 줄이기 위해 출력을 로컬 파일에 저장해 두고 `jp` 같은 외부 도구로 같은 JMESPath 표현식을 적용할 것. Azure CLI 도 JMESPath 를 지원하며, Google Cloud 는 직접 지원하지 않지만 JSON 출력을 주므로 외부 도구로 동일하게 처리 가능함.
