# 3.5.2 표준과 프레임워크

> **Standards and Frameworks** · PEN-200 §3.5.2

**PCI DSS** — 2004년 최초 공표된 정보보안 표준. 주요 카드사의 고객 결제 데이터를 다루는 조직이 대상이며 PCI Standards Council 이 관리함. 목적은 결제 데이터를 제대로 보호해 카드 부정사용 위험을 낮추는 것. 여러 요구사항으로 구성되고 **준수 여부를 매년 평가받아야 함**. 대부분은 네트워크·시스템 보안, 접근 통제, 취약점 관리, 모니터링 같은 업계 모범사례와 겹치고, 일부는 카드 특화 형태임 — 요구사항 2 는 시스템 비밀번호 등 보안 관련 설정에 **벤더 기본값 사용을 금지**하고, 요구사항 3 은 어떤 카드 데이터를 저장할 수 있고 어떻게 보호해야 하는지를 정함.

**CIS Top 18** — Center for Internet Security 의 Critical Security Controls. 조직의 보안 태세를 끌어올리기 위한 권고 통제 18개(이전엔 20개)로, 법·규제는 아니지만 데이터 보호·접근 통제 관리·지속적 취약점 관리·악성코드 탐지 등 규제가 관심 두는 영역을 다룸. 각 통제는 safeguard(옛 sub-control)로 나뉘고, safeguard 는 **구현 우선순위를 정하기 쉽도록** 세 구현 그룹으로 묶임.

| 그룹 | 성격 | 통상 적용 조직 |
|---|---|---|
| IG1 | 정보보안의 최소 기준. 가장 흔한 공격을 막는 수준으로 **모든 조직이 구현해야 함** | IT 전문성이 제한적이고 민감도 낮은 데이터를 다루는 소규모 사업체 |
| IG2 | IG1 에 더해지는 safeguard | 부서가 여럿이고 IT 인프라 전담 인력이 있으며 더 민감한 고객·독점 데이터를 다루는 복잡한 조직 |
| IG3 | 전체 safeguard | 전담 보안 전문가를 두고 감독 대상이 될 수 있는 민감 데이터를 다루는 조직 |

*CIS 구현 그룹 — 위로 갈수록 조직 규모와 데이터 민감도가 커짐*

**NIST Cybersecurity Framework** — 조직이 사이버보안 위험을 이해하고 줄이도록 돕는 표준·실무의 모음. 본래 핵심 기반시설 보호용으로 개발됐으나 이후 폭넓게 채택됨. 구성 요소는 Core, Implementation Tiers, Profiles 세 가지임.

Framework Core 는 보안 활동과 결과의 집합으로, 여섯 개 상위 기능으로 나뉨 — Govern, Identify(ID), Protect(PR), Detect(DE), Respond(RS), Recover(RC).

*NIST 사이버보안 프레임워크의 여섯 기능*

각 기능은 카테고리를 거느림 — 예로 Identify 는 Asset Management(ID.AM), Risk Assessment(ID.RA), Improvement(ID.IM) 세 개로 이뤄짐. 카테고리는 다시 서브카테고리로 내려가 보안 개선의 결과를 서술하고 Information Reference 와 연결됨. ID.RA 는 서브카테고리 10개를 가져 ID.RA.1(자산의 취약점을 식별·검증·기록)에서 시작해 ID.RA.10(핵심 공급자를 도입 전에 평가)으로 끝나며, 여기서 기술적 구현이 구체화됨.

Implementation Tiers 는 조직의 실무가 Core 서브카테고리가 요구하는 결과를 **얼마나 충족하는지**를 나타내는 네 단계임 — partial(최하), risk-informed, repeatable, adaptive.

Profiles 는 현재 수행 수준(Current Profile)과 목표 수준(Target Profile)의 관계임. 목표는 조직의 사업 목표·요구사항·통제·위험 감수 수준으로 정해지고, 둘을 비교해 **격차 분석**을 하고 메울 작업의 우선순위를 잡음.

**ATT&CK 과 D3FEND** — MITRE 가 공격자 그룹이 시스템에 침투하고 목표를 달성하는 방식을 정리해 만든 프레임워크가 ATT&CK 이며, 전 세계 악성 그룹의 최신 TTP 를 반영해 계속 갱신됨. 상세와 공격자 분류법은 OffSec SOC-200 에서 다룸. D3FEND 는 이를 방어 관점에서 대칭으로 만든 것으로, ATT&CK 이 실제 공격 방식을 목록화하는 데 반해 D3FEND 는 방어자가 공격을 예방·탐지·완화·대응하는 모범사례와 방법론을 담음.

**ISA/IEC 62443** — 산업 자동화·제어 시스템(IACS, Operational Technology 라고도 함)을 운영하는 조직에 중요한 표준. 보안 요구사항을 정의하고, 보안 통제의 모범사례와 함께 **조직 운영 보안의 성숙도를 평가하는 방법**을 제공함.

**Cyber Kill Chain** — Lockheed Martin 이 방어자가 공격을 식별·방어하도록 만든 방법론. 공격 생애주기를 일곱 단계로 나눔.
1. reconnaissance — 대상을 정하고 악용 가능한 약점을 열거함
2. weaponization — 그 약점을 칠 공격 수단을 확정함
3. delivery — 공격을 실제로 발사함
4. exploitation — 대상 시스템에서 페이로드가 실행됨
5. installation — 시스템에 악성코드가 설치됨
6. command and control — 그 악성코드로 추가 명령을 실행함
7. actions on objectives — 데이터 절취·변조·파괴 등 최종 목표 행위를 수행함

**FedRAMP** — 미 연방정부가 쓰는 클라우드 서비스에 표준화된 보안 프레임워크를 제공하는 프로그램. 이전에는 기관마다 별도 인가를 받아야 했으나, FedRAMP 는 **한 번의 인가로 전 정부기관에 통용**되게 함. 목적은 정부의 클라우드 도입을 가속하면서 그 서비스의 보안을 담보하는 것. 통제는 NIST SP 800-53 Revision 4 를 기반으로 하고 클라우드 특유의 통제를 추가해 보강함.
