# 26.10.4 Jenkins 익스플로잇

> **Exploiting Jenkins** · PEN-200 §26.10.4

Jenkins 가 자체 가입을 열어 둔 상태여서 계정을 만들면 그대로 로그인됨. 열거를 이어가려면 우선 계정부터 확보할 것.

Jenkins 의 기본 인가(authorization) 모델은 조악함 — 「누구나(미인증 포함) 무엇이든」·「로그인한 사용자면 무엇이든」·「admin 만 전권, 나머지는 읽기 전용」 정도의 선택지뿐임. 세분화하려면 Matrix Authorization Strategy 나 Role-based Authorization Strategy 같은 플러그인을 따로 깔아야 함. 따라서 내 계정이 무엇을 할 수 있는지는 **직접 돌아다녀 확인**하는 수밖에 없음.

Dashboard 에는 프로젝트가 몇 개 있음. `hackshort` 는 앞서 셸을 얻게 해 준 컨테이너를 갱신하는 것으로 보이고, 별도로 `company-dir` 프로젝트가 있음. 이 프로젝트에서 쓸 수 있는 동작은 Status·Changes·Build now·**S3 Explorer** 뿐이라 권한이 좁음 — 전권이 있었다면 설정 편집이 가능했을 것임.

주목할 것은 S3 Explorer 임. Jenkins 기본 플러그인이 아니어서 검색해 보면 플러그인 홈페이지에 **AWS 시크릿이 마스킹 없이 표시된다**는 취약점 배너가 붙어 있음.

이 플러그인은 `aws-js-s3-explorer` 프로젝트를 Jenkins 로 옮긴 것임. 원 프로젝트는 AWS JavaScript SDK 와 S3 API 로 버킷 내용을 브라우저에서 훑게 해 주는 애플리케이션이고, **`index.html`·`explorer.js`·`explorer.css` 세 파일이 전부**임. 애플리케이션 전체가 클라이언트 측 JavaScript 라는 뜻이므로 AWS ID 와 키가 **페이지 소스에 들어 있을 수밖에 없음** — 이것이 이 절의 핵심 추론임.

S3 Explorer 를 열면 나열 대상 버킷 `company-directory-9b58rezp3vvkf90f` 가 보임. 연결이 느려 버킷 목록이 뜨지 않는 경우가 잦지만 **HTML 자체는 달라지지 않으므로** 그대로 진행해도 됨. 화면에는 키가 안 보이므로 우클릭 → View Source 로 소스를 확인함.

소스에는 숨겨진 입력 필드 `awsregion`·`awsid`·`awskey`·`bucket` 이 있고, 액세스 키 ID 와 시크릿 키가 **마스킹 없이 평문으로** 들어 있음. 같은 소스 끝에 Jenkins 버전도 드러남. 이 값들을 적어 두고 `aws` CLI 로 넘어감(값은 랩마다 다름).
