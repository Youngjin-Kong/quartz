# 3.4.1 보안 원칙

> **Security Principles** · PEN-200 §3.4.1

보안 원칙 중 자주 마주칠 것들만 개괄함. 참고 자료로 David Wheeler 의 사이트와 OWASP 치트시트가 제시됨.

**최소 권한 원칙(Principle of Least Privilege)** — 시스템의 각 부분은 제 일을 하는 데 필요한 가장 낮은 권한만 받아야 함. 머신 위의 사용자든 프로그램의 코드 한 줄이든 같고, 이 규율을 제대로 지키면 공격 표면(attack surface)이 크게 좁아짐.

- 대상이 사람·그룹만이 아님. 데이터를 읽고 쓰고 고칠 수 있는 모든 주체 — 머신·라우터·방화벽 포함
- 2019년 Capital One 사건이 반례임. 필요 기능에 비해 과도한 권한을 가진 Web Application Firewall 이 공격을 성립시킴

**Zero Trust** — 최소 권한을 끝까지 밀어붙인 모델. 네트워크의 암묵적 신뢰를 전부 제거하고, 자원 요청마다 세분화된 인가를 거쳐 접근을 보호하는 것이 목표임. 다섯 요소로 구성됨.

- Just in Time Access (JITA) — 접근이 허용되기 직전에 검증
- Just Enough Access (JEA) — 전통적 최소 권한 개념에 해당
- 토큰화(tokenization)와 암호화(encryption) — 데이터 자체를 보호
- 동적(적응형) 접근 통제 정책 — 정책이 항상 목적에 맞게 유지되도록
- 마이크로세그멘테이션(microsegmentation) — 접근을 적절한 입도까지 제한

**Open Security** — 직관에 반하지만, 시스템의 보안이 비밀 유지에 기대면 안 된다는 원칙. 공격자가 보안 구현을 정확히 알아도 여전히 막혀야 함. 모든 것을 공개하라는 뜻은 아님 — 자격 증명은 비밀성이 곧 보안인 명백한 예외임. 요구되는 것은 비밀번호의 존재와 그 암호 알고리즘을 공격자가 알아도 시스템이 안전할 것.

**Defense in Depth** — 방어를 가능한 한 많은 계층에 두어, 하나가 우회돼도 다음 것이 완전 침투를 막게 함. 보안 밖의 비유로는 전자 코드 입력 → 볼트 잠금장치 열쇠 → 음성 인식 내부 경보 해제를 모두 거쳐야 열리는 차고.

- 흔한 실패는 특정 영역 하나만 담당하는 외부 도구·공급자에 지나치게 기대는 것. 단일 실패 지점이 생겨 보안 태세가 매우 약해짐
- 여러 계층의 통제를 적용하고 설계 단계부터 defense in depth 로 가야 더 많은 위협을 견디고 사고 대응도 나아짐
