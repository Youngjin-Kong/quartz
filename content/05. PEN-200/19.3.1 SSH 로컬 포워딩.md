# 19.3.1 SSH 로컬 포워딩

> **SSH Local Port Forwarding** · PEN-200 §19.3.1

Socat 포워딩과의 결정적 차이는 **listen 하는 호스트와 forward 하는 호스트가 갈린다**는 것임. Socat 은 CONFLUENCE01 한 대가 2345 를 열고 자기가 PGDATABASE01 로 넘겼음. SSH 로컬 포워딩에서는 리스닝 포트가 SSH **클라이언트**에 열리고, 그 포트로 들어온 패킷은 SSH 터널을 타고 건너가 SSH **서버**가 지정된 소켓으로 전달함.

시나리오는 앞 절에서 한 겹 비틀린 것임 — CONFLUENCE01 은 CVE-2022-26134 로 다시 잡되 이번엔 **Socat 이 없음**. 대신 크랙해 둔 database_admin 자격 증명으로 CONFLUENCE01 에서 PGDATABASE01 로 직접 SSH 가 됨. 경계 방화벽은 아직 없어서 CONFLUENCE01 WAN 에 바인드한 포트에 Kali 가 그대로 붙을 수 있음. 노리는 것은 PGDATABASE01 이 물려 있는 또 다른 내부 서브넷의 SMB(445) 서버임.

**포워드보다 열거가 먼저임.** `-L` 은 전달 대상 소켓을 «미리» 알아야 성립하므로, 포워딩용 연결을 만들기 전에 평범한 SSH 로 들어가 대상부터 확정해야 함. 리버스셸에는 TTY 가 없어 `python3 -c 'import pty; pty.spawn("/bin/sh")'` 로 pty 를 붙인 뒤 `ssh database_admin@10.4.50.215` 를 띄움.

*PGDATABASE01 라우팅 테이블*

포트 스캐너는 설치돼 있지 않으므로 Netcat 으로 /24 를 훑음. `-z` 는 데이터를 보내지 않고 연결만 확인, `-v` 는 출력, `-w 1` 은 타임아웃을 1초로 낮춰 스윕 시간을 줄임.

```
database_admin@pgdatabase01:~$ for i in $(seq 1 254); do nc -zv -w 1 172.16.50.$i 445;
done
< (seq 1 254); do nc -zv -w 1 172.16.50.$i 445; done
nc: connect to 172.16.50.1 port 445 (tcp) timed out: Operation now in progress
...
nc: connect to 172.16.50.216 port 445 (tcp) failed: Connection refused
Connection to 172.16.50.217 445 port [tcp/microsoft-ds] succeeded!
nc: connect to 172.16.50.218 port 445 (tcp) timed out: Operation now in progress
...
database_admin@pgdatabase01:~$
```

대부분 timeout 은 호스트가 없다는 뜻이고, PGDATABASE01 자신(172.16.50.215)은 **connection refused** 로 응답이 달라짐 — 살아 있으나 포트가 닫힌 것임. 172.16.50.217 만 445 succeeded 로 나옴.

여기서 선택지가 둘임. PGDATABASE01 의 내장 도구로 공유에 붙으면 받은 파일을 PGDATABASE01 → CONFLUENCE01 → Kali 로 손수 릴레이해야 해서 번거로움. 로컬 포워딩을 쓰면 Kali 의 smbclient 가 대상 SMB 에 바로 붙어 이 릴레이가 통째로 사라짐.

**인자 순서가 이 절의 핵심임.** `-L` 은 콜론으로 이어붙인 두 소켓을 받고 각 소켓은 `IP주소:포트` 형식임 — 즉 `IPADDRESS:PORT:IPADDRESS:PORT`. **앞 소켓은 SSH 클라이언트에 바인드되는 리스닝 소켓**, **뒤 소켓은 SSH 서버가 패킷을 전달할 대상**임. 여기서는 `-L 0.0.0.0:4455:172.16.50.217:445` 이고, 명령을 실행하는 곳은 CONFLUENCE01, 접속 대상은 SSH 서버인 PGDATABASE01 임. 4455 를 고른 이유는 confluence 사용자 권한이라 1024 미만 포트를 바인드할 수 없어서임.

```
confluence@confluence01:/opt/atlassian/confluence/bin$ ssh -N -L
0.0.0.0:4455:172.16.50.217:445 database_admin@10.4.50.215
<0:4455:172.16.50.217:445 database_admin@10.4.50.215
Could not create directory '/home/confluence/.ssh'.
The authenticity of host '10.4.50.215 (10.4.50.215)' can't be established.
ECDSA key fingerprint is SHA256:K9x2nuKxQIb/YJtyN/YmDBVQ8Kyky7tEqieIyt1ytH4.
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
yes
Failed to add the host to the list of known hosts (/home/confluence/.ssh/known_hosts).

```

`-N` 은 원격 명령 실행을 막아 셸이 뜨지 않게 함. 그래서 비밀번호를 넣은 뒤 **아무 출력이 없는 것이 정상**이며, 포워딩 관련 출력만 남음. 실패했는데 기본 출력만으로 원인을 못 잡겠으면 `-v` 로 디버그 출력을 켬.

함정 하나 — 이 SSH 세션이 리버스셸을 통째로 점유함. 확인이나 후속 작업을 하려면 CVE-2022-26134 페이로드를 다른 포트로 돌려 **리버스셸을 하나 더** 잡아야 함. 그 셸에서 `ss -ntplu` 를 치면 `0.0.0.0:4455` 가 `ssh` 프로세스 소유로 LISTEN 중인 것이 보임.

*두 번째 리버스셸에서 확인한 4455 LISTEN 상태 — 소유 프로세스가 `ssh`*

이제 Kali 에서 CONFLUENCE01 의 4455 는 172.16.50.217 의 445 와 같음. smbclient 는 `-L` 로 공유 목록을, `-p` 로 비표준 포트를, `-U` 와 `--password` 로 자격 증명을 받음. Confluence 데이터베이스에서 크랙한 hr_admin 자격 증명을 씀 — 접속 주소는 대상 SMB 호스트가 아니라 **리스닝 포트가 열린 CONFLUENCE01** 임.

```
kali@kali:~$ smbclient -p 4455 -L //192.168.50.63/ -U hr_admin --password=Welcome1234
        Sharename       Type      Comment
        ---------       ----      -------
        ADMIN$          Disk      Remote Admin
        C$              Disk      Default share
        IPC$            IPC       Remote IPC
        scripts         Disk
        Users           Disk
Reconnecting with SMB1 for workgroup listing.
do_connect: Connection to 192.168.50.63 failed (Error NT_STATUS_CONNECTION_REFUSED)
```
