# 26.9.1 공격 원리 이해

> **Understanding the Attack** · PEN-200 §26.9.1

핵심 전제 — Python 의 PyPI, JavaScript 의 NPM 같은 패키지 관리자는 설치 시 **특정 저장소나 버전에 우선순위를 둠**. 예컨대 공식 공개 저장소나 더 높은 버전이 커스텀 저장소보다 먼저 선택됨.

여기에 두 번째 사실이 겹침 — 공개 저장소는 **이름이 선점돼 있지만 않으면** 누구나 아무 버전 번호로 패키지를 올릴 수 있음.

두 사실을 합치면 공격이 성립함. 애플리케이션이 내부 커스텀 저장소의 특정 패키지를 요구할 때, 공격자가 **같은 이름 · 더 높은 버전**의 악성 패키지를 공개 저장소에 올리면 패키지 관리자가 내부 정품 대신 그것을 고를 수 있음.

![[PEN200-Fig-347.png]]

*공개 저장소에 패키지가 없을 때 — 사설 저장소 쪽을 내려받음*

![[PEN200-Fig-348.png]]

*공개 저장소에도 있을 때 — 양쪽을 다 조회하고 요청 조건에 맞는 최신 버전을 씀*

우선순위 규칙은 패키지 관리자마다 다름. 이 랩의 대상은 Python 이므로 pip 기준으로 봄. pip 에서 저장소를 바꾸거나 추가하는 설정은 둘임:

- `index-url` — 검색에 쓸 **기본 인덱스**. 기본값은 공개 인덱스 `https://pypi.org/simple`
- `extra-index-url` — 검색할 인덱스를 **추가**함

⚠️ **pip 에서 의존성 체인 공격이 성립하는 이유는 정확히 `extra-index-url` 때문임.** 관리자가 `index-url` 로 기본 인덱스를 **교체**하면 그 인덱스만 조회되므로 공개 저장소가 끼어들 여지가 없음. 반면 `extra-index-url` 로 커스텀 저장소를 **덧붙이면** 기본 공개 저장소를 포함한 여러 저장소가 모두 조회되고, 같은 패키지가 여러 곳에 있으면 **조건에 맞는 가장 높은 버전**이 선택됨.

대상이 둘 중 무엇을 쓰는지는 공격해보기 전에는 알 수 없음. 다만 이 설정은 개발자와 환경마다 각각 필요하므로, **그중 최소 하나가 `extra-index-url` 을 쓸 확률**이 꽤 높음.

버전도 대상이 요구하는 조건에 맞춰야 함. pip 의 버전 지정자 —

- `==` — 정확히 일치. `some-package==1.0.0` 이면 1.0.0 만 받음. 와일드카드가 되므로 `some-package==1.0.*` 는 1.0.0·1.0.1 등에 걸림
- `<=` — 지정 버전 이하 전부. `some-package<=1.0.0` 이면 1.0.0·0.0.9·0.8.9 는 되고 1.0.1·7.0.2 는 안 됨
- `>=` — 지정 버전 이상 전부. `<=` 의 반대
- `~=` — 호환 릴리스. 지정 버전과 호환될 만한 버전을 받음. 개발자가 버전 규약을 지켰다는 전제이며, `some-package~=1.0.0` 이면 1.0.1·1.0.5·1.0.9 는 걸리고 1.2.0·2.0.0 은 안 됨

포럼 글에서 확인한 요구 사항은 이것임:

```
hackshort-util~=1.1.0
```

*`requirements.txt` 의 지정자 — 호환 릴리스 방식으로 1.1.0 을 요구*

`~=` 이므로 **두 번째 소수점 뒤만 올린** 버전, 즉 1.1.2 이상으로 올려야 우리 패키지가 선택됨.

같은 글에서 애플리케이션이 이 패키지를 어떻게 불러오는지도 드러남:

```
from hackshort_util import utils
```

*`utils` 서브모듈을 임포트 — 악성 패키지가 이 이름을 제공해야 함*

⚠️ 임포트 시에는 대시가 아니라 **밑줄**로 참조됨(`hackshort_util` vs `hackshort-util`). 대시가 Python 문법에서 문제를 일으켜 개발자들이 관행적으로 밑줄로 바꾸기 때문임. 따라서 `hackshort_util` 은 `hackshort-util` 패키지에서 온 것으로 보는 것이 타당하고, 그 패키지에서 `utils` 서브모듈을 가져간다는 점을 기억해둘 것.
