# 27.1.1 MAILSRV1

> **MAILSRV1** · PEN-200 §27.1.1

대상을 건드리기 전에 작업 환경부터 잡음. 평가마다 새 Kali 이미지를 쓰는 것이 권장됨 — VM 을 재사용하면 이전 고객 데이터가 새 네트워크에 노출될 수 있어서임. `/home/kali/beyond` 아래에 대상별 디렉터리(`mailsrv1`·`websrv1`)와 확보한 자격 증명·사용자를 모을 `creds.txt` 를 만들어 두고 시작함. 후반으로 갈수록 수집 데이터가 폭증하므로 구조화가 곧 시간임. 실제 평가에서는 Obsidian 같은 마크다운 편집기로 기록하는 방식도 널리 쓰임 — 애플리케이션 독립적이고 보고서 작성·협업에 유리해서임.

```
kali@kali:~$ mkdir beyond
kali@kali:~$ cd beyond
kali@kali:~/beyond$ mkdir mailsrv1
kali@kali:~/beyond$ mkdir websrv1
kali@kali:~/beyond$ touch creds.txt
```
*작업 디렉터리와 자격 증명 수집 파일을 먼저 만들어 둠*

포트 스캔은 대개 가장 먼저 수행하는 능동 정보 수집 수단임. `-sV` 로 서비스·버전 탐지, `-sC` 로 Nmap 기본 스크립트, `-oN` 으로 결과 파일 생성.

*MAILSRV1 스캔 결과 — 마지막 `smb2-security-mode` 의 `Message signing enabled but not required` 는 §27.4.2 에서 릴레이 여지를 판정할 때 다시 쓰이는 줄임*

열린 포트 8개가 나왔고, 여기서 대상이 Windows 이며 IIS 와 hMailServer 를 돌린다는 것이 확정됨.

| 포트 | 서비스 |
|---|---|
| 25 · 587 | smtp — hMailServer smtpd |
| 80 | http — Microsoft IIS httpd 10.0 |
| 110 | pop3 — hMailServer pop3d |
| 135 · 139 · 445 | msrpc · netbios-ssn · microsoft-ds |
| 143 | imap — hMailServer imapd |

실제 평가라면 여기에 Google Dorks·유출 비밀번호 DB 같은 수동 정보 수집을 병행해 사용자명·비밀번호를 추가 확보함. 또 이 모듈에서는 호스트명이 역할을 그대로 알려주지만 현실의 호스트명은 그만큼 친절하지 않음.

hMailServer 는 Windows 용 무료 오픈소스 메일 서버임. CVE 와 공개 익스플로잇을 찾아봤으나 Nmap 이 버전 번호를 못 뽑아 검색을 넓게 돌릴 수밖에 없었고, 오래된 CVE 몇 개 외에 쓸 만한 결과가 없었음.

설령 코드 실행이 되는 취약점을 찾았더라도 나머지 열거 단계를 건너뛰면 안 됨 — 시스템 접근은 얻어도 다른 서비스·시스템의 핵심 데이터를 통째로 놓칠 수 있어서임.

IIS 는 기본 환영 페이지만 노출함. gobuster 를 `dir` 모드로 돌려 `-u` 에 URL, `-w` 에 워드리스트, `-x txt,pdf,config` 로 문서·설정 파일을 노리고 `-o` 로 결과를 남김.

```
kali@kali:~/beyond$ gobuster dir -u http://192.168.50.242 -w
/usr/share/wordlists/dirb/common.txt -o mailsrv1/gobuster -x txt,pdf,config
```
*gobuster 디렉터리 열거 — 줄바꿈은 교재 지면 폭에 따른 것이며 실제로는 한 줄 명령임*

디렉터리·파일이 하나도 나오지 않았음. 열거 기법이 매번 결과를 내야 하는 것은 아니며, 초기 단계에서는 전체 그림을 얻기 위해 여러 방법을 두루 돌리는 것이 중요함.

정리 — MAILSRV1 은 Windows 에 IIS 와 hMailServer 구동. 웹 쪽은 소득 없음. 메일 서버는 지금은 못 씀. 다만 뒤에서 유효한 자격 증명과 수신 대상을 확보하면 피싱 메일 발송 경로로 되살아남. 침투 테스트가 순환 구조라는 것 — 새 정보를 계속 반영해 이전에 못 건드린 벡터로 되돌아가는 사고방식 — 이 여기서 드러남.
