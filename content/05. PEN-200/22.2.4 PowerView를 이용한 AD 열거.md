# 22.2.4 PowerView를 이용한 AD 열거

> **AD Enumeration with PowerView** · PEN-200 §22.2.4

앞 절까지는 .NET 클래스를 직접 호출하는 자작 스크립트로 사용자·그룹을 열거했음. PowerView 는 같은 목적을 위해 만들어진 PowerShell 스크립트로, 내부 동작은 자작 스크립트와 같음 — .NET 클래스로 LDAP 경로를 얻어 AD 에 질의함. 차이는 루프로 속성을 골라 찍던 작업이 함수 하나와 파이프라인으로 줄어든다는 점임. CLIENT75 의 `C:\Tools` 에 설치돼 있고, 스크립트이므로 먼저 메모리에 임포트해야 함.

```
PS C:\Tools> Import-Module .\PowerView.ps1
```

도메인 자체의 기본 정보 — 포리스트, DC 목록, 도메인 기능 수준, PDC·RID·인프라 역할 보유자 — 는 `Get-NetDomain` 으로 얻음. 자작 스크립트의 `GetCurrentDomain` 에 해당함.

```
PS C:\Tools> Get-NetDomain

Parent                  :
PdcRoleOwner            : DC1.corp.com
```

사용자 열거는 `Get-NetUser`. 인자 없이 실행하면 사용자 객체의 **모든 속성**을 그대로 출력하므로 계정 하나에 수십 줄이 나와 읽기 어려움. 자작 스크립트에서 루프로 걸러내던 부분을 PowerView 에서는 `select` 파이프가 대신함 — 관심 있는 속성만 골라 표 형태로 받는 방식임. 전체 출력에서 사용자명이 `cn` 속성에 들어 있음을 확인한 뒤 그것만 뽑으면 깔끔한 계정 목록이 됨.

골라 볼 만한 속성이 여럿 있는데, 특히 `pwdlastset`(마지막 비밀번호 변경 시각)과 `lastlogon`(마지막 로그인 시각)이 값을 함. 이유는 둘임 — ① 최근에 비밀번호를 바꾸지도 로그인하지도 않은 휴면 계정을 탈취하면 교전 중 간섭과 이목이 줄어듦 ② 최근 비밀번호 정책 변경 이후로 비밀번호를 안 바꾼 계정은 현재 정책보다 약한 값을 그대로 쓰고 있을 수 있어 패스워드 공격에 취약함.

그룹은 `Get-NetGroup` 으로 같은 방식으로 열거함.

```
PS C:\Tools> Get-NetGroup | select cn
cn
--
...
Key Admins
Enterprise Key Admins
DnsAdmins
DnsUpdateProxy
Sales Department
Management Department
Development Department
Debug
```

특정 그룹의 구성원만 보려면 그룹명을 인자로 주고 `select member` 로 파이프함. 중첩 그룹까지 풀어내는 작업은 여기서 다루지 않으나, 아래 출력처럼 구성원 목록에 사용자뿐 아니라 **다른 그룹**(`CN=Development Department`)이 섞여 나오는 것이 중첩의 흔적임.

```
PS C:\Tools> Get-NetGroup "Sales Department" | select member
member
------
{CN=Development Department,DC=corp,DC=com, CN=pete,CN=Users,DC=corp,DC=com,
CN=stephanie,CN=Users,DC=corp,DC=com}
```

여기까지가 자작 스크립트로 했던 것을 PowerView 로 재현한 것임. 이후 절부터는 자작 스크립트로는 손이 많이 가던 속성과 기법으로 범위를 넓힘.
