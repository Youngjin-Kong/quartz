# 19.3.5 sshuttle 사용

> **Using sshuttle** · PEN-200 §19.3.5

SSH 서버에 직접 접근할 수 있고 그 뒤에 복잡한 내부망이 있으면, 고전적인 동적 포워딩은 관리가 번거로워짐. sshuttle 은 SSH 연결을 **VPN 처럼** 만듦 — 로컬 라우팅을 세워 지정한 서브넷 트래픽을 SSH 터널로 강제하므로 Proxychains 없이 도구를 평소처럼 씀.

⚠️ 대가는 요구 조건임 — **SSH 클라이언트 쪽 root 권한**과 **SSH 서버 쪽 Python3** 가 필요함. 항상 쓸 수 있는 가벼운 수단은 아니므로 조건이 맞을 때만 고름.

랩에서는 CONFLUENCE01 에 Socat 으로 2222 → PGDATABASE01:22 포워드를 먼저 세우고, 그 위로 sshuttle 을 태움. 인자는 SSH 접속 문자열과 **터널로 보낼 서브넷 목록**임.

*CONFLUENCE01 에서 2222 → PGDATABASE01:22 Socat 포워드를 먼저 세움*

```
confluence@confluence01:/opt/atlassian/confluence/bin$ socat TCP-LISTEN:2222,fork
TCP:10.4.50.215:22
</bin$ socat TCP-LISTEN:2222,fork TCP:10.4.50.215:22
```

```
kali@kali:~$ sshuttle -r database_admin@192.168.50.63:2222 10.4.50.0/24 172.16.50.0/24
[local sudo] Password:
database_admin@192.168.50.63's password:
c : Connected to server.
Failed to flush caches: Unit dbus-org.freedesktop.resolve1.service not found.
fw: Received non-zero return code 1 when flushing DNS resolver cache.
```

출력은 거의 없음. DNS 캐시 플러시 실패 경고가 떠도 라우팅 자체는 서 있음. 이후 Kali 에서 `smbclient -L //172.16.50.217/` 처럼 **프록시 지정 없이 최종 주소를 그대로** 쓰면 같은 네트워크에 있는 것처럼 붙음.

```
kali@kali:~$ smbclient -L //172.16.50.217/ -U hr_admin --password=Welcome1234
        Sharename       Type      Comment
        ---------       ----      -------
        ADMIN$          Disk      Remote Admin
        C$              Disk      Default share
        IPC$            IPC       Remote IPC
        scripts         Disk
Reconnecting with SMB1 for workgroup listing.
do_connect: Connection to 172.16.50.217 failed (Error
NT_STATUS_RESOURCE_NAME_NOT_FOUND)
Unable to connect with SMB1 -- no workgroup available
kali@kali:~$
```
