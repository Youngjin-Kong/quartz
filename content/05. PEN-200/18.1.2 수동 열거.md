# 18.1.2 수동 열거

> **Manual Enumeration** · PEN-200 §18.1.2

수동 열거는 느리지만 통제 가능한 방식임. **자동화 도구가 놓치는 특이한 권한 상승 경로**를 잡아내며, 자동화가 수동을 대체하지 못하는 이유도 여기 있음 — 실제로 오설정된 것은 대개 그 환경에만 있는 커스텀 설정이라 일반 도구의 체크리스트에 없음. 아래 명령들은 대상 OS 버전에 따라 약간의 조정이 필요할 수 있음.

**현재 사용자 컨텍스트**부터 확인함. 초기 접근 직후 가장 먼저 알아야 할 것임.

```
joe@debian-privesc:~$ id
uid=1000(joe) gid=1000(joe)
groups=1000(joe),24(cdrom),25(floppy),29(audio),30(dip),44(video),46(plugdev),109(netd
ev),112(bluetooth),116(lpadmin),117(scanner)
```

UID/GID 와 소속 보조 그룹이 드러남. 그다음 `/etc/passwd` 로 전체 계정을 열거함 — **고권한 계정 후보를 고르는 것이 목적**임.


콜론 구분 7필드의 의미:

- **로그인 이름** — 로그인에 쓰는 사용자명
- **암호화된 패스워드** — `x` 면 해시가 `/etc/shadow` 에 있다는 뜻
- **UID** — root 는 항상 0, 일반 사용자는 1000부터 시작(real user ID)
- **GID** — 사용자의 기본 그룹 ID
- **주석** — 설명 필드. 대개 사용자명 반복
- **홈 디렉터리** — 로그인 시 진입 경로
- **로그인 셸** — 대화형 셸

읽는 요령 둘 — ① `www-data`·`sshd` 같은 **서비스 계정의 존재가 설치된 소프트웨어를 시사**함(웹 서버·SSH 서버가 있다는 신호). ② 홈 디렉터리가 설정된 계정은 실사용자이고, 서비스 계정은 `/usr/sbin/nologin` 으로 로그인이 막혀 있음. 여기서는 `eve` 가 또 다른 실사용자임.

**호스트명**은 기계의 역할을 시사함 — `web`(웹 서버)·`db`(데이터베이스)·`dc`(도메인 컨트롤러) 같은 약어가 붙는 명명 규칙이 흔하고, 기업은 위치·설명·OS·서비스 수준으로 분류하는 규칙을 강제하기도 함. 역할을 특정하면 그 호스트를 둘러싼 맥락이 생겨 정보 수집의 방향이 좁혀짐. `hostname` 명령으로 확인할 것. ⚠️ **프롬프트에 보이는 문자열을 믿지 말 것** — 대부분의 배포판이 프롬프트에 호스트명을 박아 두지만 그 텍스트는 얼마든지 속일 수 있으므로 시스템 명령으로만 확인함.

```
joe@debian-privesc:~$ hostname
debian-privesc
```

**OS·커널 버전**은 커널 익스플로잇을 쓰려면 필수임. 커널 익스플로잇은 특정 OS·버전 조합에만 맞춰 만들어져서, **버전이 어긋난 것을 던지면 시스템 불안정이나 크래시로 이어짐** — SOC 보다 시스템 관리자가 먼저 눈치채는 상황이 됨. 그래서 가능하면 로컬에 같은 환경을 만들어 미리 시험해 볼 것. `/etc/issue` 와 `/etc/*-release` 가 배포판 릴리스를, `uname -a` 가 커널 버전과 아키텍처를 알려줌.

```
joe@debian-privesc:~$ cat /etc/issue

joe@debian-privesc:~$ cat /etc/os-release
```

**네트워크 구성**에서 볼 것은 인터페이스·라우트·열린 포트임. 목적이 둘로 갈림:

- **피벗 가능성** — 대상이 여러 네트워크에 물려 있으면 공격 머신에서 직접 닿지 않는 호스트로 넘어가는 발판이 됨. 가상 인터페이스가 보이면 가상화나 백신 소프트웨어의 존재를 시사함
- **로컬 전용 서비스 발견** — 루프백에만 바인딩된 서비스는 원격 스캔에 안 잡히지만 셸을 잡은 지금은 접근 가능함. **원격에서 안 보이던 공격면이 통째로 열리는 지점**임

명령은 배포판·버전에 따라 `ifconfig` 또는 `ip` 를 씀 — 전자는 인터페이스 통계까지 보여주고 후자는 같은 정보를 압축해 보여주며, 둘 다 `a` 플래그로 전체를 출력함. 라우팅 테이블은 `route` 또는 `routel` 로 확인하고(제공 정보는 비슷함), 연결·리스닝 포트는 `netstat` 또는 `ss` 를 씀. 후자 둘은 인자가 같아서 `ss -anp` 하나로 정리됨 — `-a` 전체 연결, `-n` 호스트명 해석 생략(해석이 걸리면 명령이 멈춤), `-p` 소켓을 소유한 프로세스명 표시. 출력에는 자기 자신의 SSH 세션과 그 리스닝 소켓도 함께 잡히므로 구분해 읽을 것.

**방화벽 규칙**은 원격 침투 단계뿐 아니라 권한 상승에도 쓸모가 있음 — 방화벽에 막혀 원격에서 못 쓰던 서비스가 로컬 루프백으로는 대개 열려 있고, 그것을 악용해 권한을 올릴 수 있음. 인바운드·아웃바운드 필터링 정보는 나중에 포트 포워딩·터널링을 설계할 때도 필요함.

`iptables` 로 규칙을 나열하려면 root 여야 하지만, **설정 파일 쪽으로 우회**할 수 있음. Debian 의 `iptables-persistent` 는 부팅 시 netfilter 규칙을 복원하려고 `/etc/iptables` 아래에 규칙을 저장하는데, 이 파일들이 약한 권한으로 남아 일반 사용자도 읽히는 경우가 흔함. 관리자가 `iptables-save` 로 덤프해 둔 파일이 있을 수도 있으니 `/etc` 를 뒤지거나 파일시스템에서 `iptables` 명령 문자열을 grep 할 것.

```
joe@debian-privesc:~$ cat /etc/iptables/rules.v4
# Generated by xtables-save v1.8.2 on Thu Aug 18 12:53:22 2022
*filter
:INPUT ACCEPT [0:0]
:FORWARD ACCEPT [0:0]
:OUTPUT ACCEPT [0:0]
-A INPUT -p tcp -m tcp --dport 1999 -j ACCEPT
COMMIT
# Completed on Thu Aug 18 12:53:22 2022
```

기본값이 아닌 규칙 하나(포트 1999 허용)가 눈에 띔 — **비기본 설정은 그 자체가 조사 대상 신호**임.

**예약 작업(cron)** 은 서버 역할 기계에서 특히 값이 큼. 작업 파일이 오설정이거나 사용자가 만든 파일이 약한 권한으로 남아 있으면, 그 파일을 고쳐 두면 **스케줄러가 높은 권한으로 대신 실행해 줌**. 확인 경로:

- `/etc/cron.*` — `*` 는 실행 주기(`cron.daily`·`cron.hourly` 등)이며 각 스크립트가 해당 하위 디렉터리에 놓임. `ls -lah /etc/cron*` 으로 한 번에 훑음
- `/etc/crontab` — 관리자가 직접 추가한 작업이 모이는 곳이고 **대부분 root 로 실행**되므로 파일 권한을 특히 눈여겨볼 것
- `crontab -l` — 현재 사용자의 작업. 주석만 나오면 등록된 작업이 없다는 뜻
- `sudo crontab -l` — root 의 작업

**setuid / setgid** 는 rwx 와 별개로 실행 파일에 붙는 특수 권한이며 권한 표기에 `s`(대문자 또는 소문자)로 나타남. 보통 실행 파일은 실행한 사용자의 권한을 물려받지만, **SUID 가 걸려 있으면 파일 소유자의 권한으로 실행됨**(SGID 는 소유 그룹). 즉 root 소유 SUID 바이너리는 어떤 로컬 사용자가 실행해도 상승된 권한으로 돌아감.

이때 상속되는 것을 **eUID/eGID**(effective UID/GID)라 하며, OS 가 권한을 판정할 때 실제로 보는 값이 이것임. 따라서 **setuid root 프로그램이 원하는 명령을 실행하도록 전복하면 root 를 사칭해 시스템 전체 권한을 얻음**. 셸을 잡은 뒤 관행적으로 훑는 항목인 이유임.


`-perm -u=s` 가 SUID 비트 조건임. 악용법은 바이너리마다 다름 — 예로 `/bin/cp` 에 SUID 가 걸려 있으면 `/etc/passwd` 같은 민감 파일을 복사·덮어쓰기 할 수 있음.
