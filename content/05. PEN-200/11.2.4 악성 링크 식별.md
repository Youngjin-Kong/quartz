# 11.2.4 악성 링크 식별

> **Recognize Malicious Links** · PEN-200 §11.2.4

앞의 파일 보호 장치들을 우회하는 방법이 **링크를 클릭하게 만드는 것**임.

자격 증명 수집의 기본형은 널리 쓰이는 서비스의 사이트를 복제해 띄우는 것 — Gmail, Zoom, Microsoft 로그인 페이지 등. 메일의 구실이 그럴듯하면 대상이 진짜 자격 증명을 입력하고, 그것을 캡처해 재사용함.

**비밀번호 관리자가 이 방식의 큰 걸림돌임.** 정확한 도메인에서만 동작하므로 `microsoft.com` 용 자격 증명을 `m1cros0ft.com` 에 채워 넣지 않음 — 즉 사용자가 눈으로 못 잡는 위조를 도구가 잡아냄.

다만 비밀번호 관리자 자체에도 결함이 있었음 —

- **2016** — LastPass 브라우저 확장의 취약점. 특정 URI 를 만들어 비밀번호를 노출시킬 수 있었음
- **2017** — Google Project Zero 가 공개한 LastPass 확장 버그. 사용자 보관함의 비밀번호를 임의로 읽고 코드 실행까지 가능했음
- **2021** — Safari 용 1Password 확장 취약점. 신용카드 정보 같은 보관함 항목을 읽을 수 있었음
- **2023** — AutoSpill 공격. Android 가 WebView 를 부모 앱에 노출하는 방식을 악용해 악성 앱이 자격 증명을 탈취

그러나 캠페인 시점에 이런 취약점을 항상 쓸 수 있는 것은 아니므로, **실무에서는 비밀번호 관리자를 여전히 장애물로 봐야 함.**

자격 증명이 아니라 **코드 실행**을 노리는 링크도 있음. 브라우저 익스플로잇을 띄우는 페이지로 유도하는 방식인데, 0-day 나 N-day 확보 + 매우 안정적인 익스플로잇 + 대상이 하필 그 취약 브라우저로 링크를 여는 조건이 모두 맞아야 해서 드묾.

**CSRF(Cross-Site Request Forgery)** — 대상 브라우저에 특정 서비스의 세션이 열려 있다는 점을 이용해, 그 브라우저가 서비스에 요청을 보내게 강제함. 예를 들어 로그인 상태의 사용자가 새 계정을 만들게 하는 식임. 극단적인 경우 코드 실행까지 감 — **CVE-2024-1879** 는 AutoGPT 의 CSRF 취약점으로 취약 시스템에서 임의 코드 실행이 가능했음.

어느 쪽이든 **링크가 그럴듯하고 클릭할 만해 보여야** 함. 무작위 문자열이 섞였거나 구실과 어울리지 않는 URL 은 대상을 경계시킴. 대응책 둘 —

- **URL 단축 서비스** — TinyURL, Bitly 등으로 링크를 가림. 단 서비스 제공자가 악성으로 판단하면 링크를 죽일 수 있음
- **호모그래프(homograph) URL** — ASCII 문자를 키릴·그리스·라틴 문자로 치환. `apple.com` 과 `аррӏе.com` 은 브라우저 주소창에서 거의 같아 보이지만 **완전히 다른 사이트**임(둘째 URL 의 `l` 이 키릴 문자로 바뀐 것)

**HTTPS 도 사실상 필수임.** 로그인 정보를 받는 사이트가 TLS 없이 도는 경우는 드물고, 브라우저가 경고를 띄우면 그 자리에서 들통남. 유효한 인증서가 걸린 사이트로 유도할 것.

CSRF 처럼 **인증을 강제하는 접근**은 정보 유출이나 무단 동작으로 이어질 수 있음. Windows 가 NTLM 을 폐기해 가는 중이지만 구형 시스템에서는 인증 유출을 노릴 수 있음 — 인증을 강제하는 링크를 보내 대상이 클릭하면 시스템이 NTLM 핸드셰이크에 들어가고, 공격자가 **NetNTLMv2 해시를 캡처**함. SMB 서버에 있는 이미지를 링크로 삽입해두면 **메시지를 여는 것만으로** 핸드셰이크가 유발되기도 함. 다소 오래된 기법이지만 2024년 2월까지도 실사용이 관측됨.
