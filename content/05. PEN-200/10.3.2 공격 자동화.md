# 10.3.2 공격 자동화

> **Automating the Attack** · PEN-200 §10.3.2

지금까지의 과정은 Kali 기본 탑재 도구로 자동화됨. `sqlmap` 은 여러 DB 엔진을 상대로 SQLi 를 **탐지하고 익스플로잇**함. `-u` 로 대상 URL, `-p` 로 시험할 파라미터를 지정함.

> ⚠️ **교재 밖 주의 — OSCP 시험 규정** (원문에 없는 내용임). `sqlmap` 은 시험에서 **명시적으로 금지된 도구**임. 이 절은 자동화 도구가 무엇을 어떤 순서로 하는지 이해하려 읽는 것이고, 시험장에서 실행할 것이 아님.

*sqlmap 으로 주입 지점 탐지*

URL 은 파라미터에 더미 값을 넣은 채로 통째로 넘기고, 중간 질문은 기본값(`I`)으로 넘어가면 됨. 결과로 주입 유형(여기서는 시간 기반 블라인드)과 함께 웹서버 OS·기술 스택·백엔드 DB 판별 정보가 나옴.

⚠️ `sqlmap` 은 은밀성이 사실상 없음 — 트래픽 양이 매우 커서 **탐지를 피해야 하는 과제에서 1순위로 꺼낼 도구가 아님.**

같은 명령에 `--dump` 를 붙이면 현재 DB 의 테이블과 레코드를 통째로 뽑음.

*`--dump` 로 테이블·컬럼·레코드를 차례로 회수 — 타임스탬프가 진행 속도를 보여줌*

시간 기반 블라인드는 응답 지연을 재 가며 값을 하나씩 확인하는 방식이라 **전체 덤프가 매우 느림** — 위 로그의 타임스탬프상 `users` 자격 증명을 걷는 데만 20분 이상 걸림.

`--os-shell` 은 웹셸을 올려 대화형 셸을 붙여 줌. ⚠️ 시간 기반 블라인드는 지연이 커 셸 조작에 부적합하므로 **UNION 기반 지점을 쓸 것.** POST 요청이 대상이면 Burp 로 요청을 가로채 파일로 저장해 둠.

*Burp 로 가로챈 POST 요청*

저장한 요청 파일은 `-r` 로 넘기고, 취약 파라미터(`item`)를 `-p` 로 짚어 주며, 앞서 찾아둔 **쓰기 가능한 웹 디렉터리**를 `--web-root` 로 지정함.

*sqlmap --os-shell 로 대화형 셸 획득*

흐름 — 취약점 확인 → 웹앱 언어 선택(여기서는 PHP) → 지정 디렉터리에 웹셸 업로드 → 일반 시스템 명령을 던지는 셸 제공.
