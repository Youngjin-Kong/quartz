# 25.5.2 IAM 리소스 열거하기

> **Enumerating IAM Resources** · PEN-200 §25.5.2

지금까지 확인된 것 — 탈취한 자격 증명은 IAM 사용자 `clouddesk-plove` 이고, `support` 그룹에 속해 그룹에 붙은 `SupportUser` 정책을 상속함. `SupportUser` 는 계정의 문제 해결을 위해 여러 서비스에 읽기 전용 접근을 주는 AWS 관리형 정책임. 관리형 정책은 재사용 가능한 권한 묶음이라 관리가 편한 대신 **과도하게 관대하게 작성되면 그 자체가 위험**임.

이 정책이 IAM 에 대해 무엇을 허용하는지부터 확인함 — 정책 문서를 뽑아 `grep "iam"` 으로 IAM 관련 줄만 거름.

```
kali@kali:~$ aws --profile target iam get-policy-version --policy-arn
arn:aws:iam::aws:policy/job-function/SupportUser --version-id v8 | grep "iam"
                        "iam:GenerateCredentialReport",
                        "iam:GenerateServiceLastAccessedDetails",
                        "iam:Get*",
                        "iam:List*",
```

*`SupportUser` 정책 중 IAM 서비스 관련 액션만 추출*

허용된 것은 `iam:Get*` 과 `iam:List*` 와일드카드, 그리고 `GenerateCredentialReport`·`GenerateServiceLastAccessedDetails` 두 개. 즉 `get-` 과 `list-` 로 시작하는 IAM 하위 명령은 전부 실행 가능함. 실행 가능한 목록은 `aws iam help` 출력을 걸러 뽑음.

개별 명령의 필수·선택 파라미터는 `aws iam <명령> help` 로 확인함. IAM 은 인증·인가 전체를 관장하므로 읽기 전용이라도 전반을 들여다볼 수 있다는 것은 큰 이점임.

먼저 계정 요약을 봄 — `aws iam get-account-summary`. 소음을 줄이려면 출력을 파일로 남겨 나중에 API 를 다시 부르지 않고 재검토할 것이며, `tee` 를 쓰면 화면 표시와 파일 저장을 동시에 함.

*아이덴티티 열거 — 출력은 `tee` 로 각각 파일에 남김*

관리형 정책은 `list-policies` 로 나열하되, `--scope Local` 로 고객 관리형만 남겨 AWS 관리형을 제외하고 `--only-attached` 로 실제 아이덴티티에 붙어 있는 것만 추림.


*고객 관리형 정책 중 부착된 것만 열거*

여기서 수동 방식의 비용이 드러남. 각 아이덴티티의 인라인 정책을 다 보려면 `list-user-policies`/`get-user-policy`, `list-group-policies`/`get-group-policy`, `list-role-policies`/`get-role-policy` 를 돌려야 하고, 관리형은 `list-attached-user-policies`·`list-attached-group-policies`·`list-attached-role-policies` 를 돌린 뒤 찾아낸 정책마다 다시 `get-policy-version` 을 불러야 함. 호출 수가 곧 이벤트 로그 수임.

더 간단한 대안이 `iam get-account-authorization-details` — 계정의 모든 사용자·그룹·역할·정책과 그 상호 관계를 **한 번의 요청으로** 반환함. `--filter` 에 `User`·`Role`·`Group`·`LocalManagedPolicy`·`AWSManagedPolicy` 를 공백으로 나열해 범위를 좁힘. 실행에는 `GetAccountAuthorizationDetails` 권한이 필요한데, 이것만 단독으로 부여된 경우는 드물어도 `iam:Get*` 와일드카드에 포함되므로 실제로는 자주 통함.

*권한 구성 전체를 한 번에 회수*

같은 정보를 앞서 여러 명령으로 모았던 것과 달리 요청이 하나라 이벤트 기록이 훨씬 덜 남음 — **직접 도구를 만든다면 이 명령부터 시작할 것.**

마지막은 명시적 거부(explicit deny)의 우회임. 앞서 무시했던 `deny_challenges_access` 로 돌아옴 — 사용자에게 붙은 관리형 정책을 다시 확인해 ARN 을 확보함.

```
kali@kali:~$ aws --profile target iam list-attached-user-policies --user-name
clouddesk-plove
{
    "AttachedPolicies": [
        {
            "PolicyName": "deny_challenges_access",
            "PolicyArn": "arn:aws:iam::12345678912:policy/deny_challenges_access"
        }
    ]
}
```

그 ARN 에 `list-policy-versions` 를 불러 문서를 읽으려 하면 거부됨.

```
kali@kali:~$ aws --profile target iam list-policy-versions --policy-arn
arn:aws:iam::12345678912:policy/deny_challenges_access
An error occurred (AccessDenied) when calling the ListPolicyVersions operation: User:
arn:aws:iam::12345678912:user/support/clouddesk-plove is not authorized to perform:
iam:ListPolicyVersions on resource: policy
arn:aws:iam::12345678912:policy/deny_challenges_access with an explicit deny in an
identity-based policy
```

`explicitly denied` 문구는 관리자가 이 사용자의 접근을 특정 리소스에 대해 «명시적으로» 막아 뒀다는 뜻임. 그런데 `get-account-authorization-details --filter LocalManagedPolicy` 로 고객 관리형 정책 전체를 받으면 각 정책의 `PolicyVersionList` 안에 정책 문서가 통째로 들어 있어 **거부된 그 문서를 그대로 읽게 됨.**

```
kali@kali:~$ aws --profile target iam get-account-authorization-details --filter
LocalManagedPolicy
...
        {
            "PolicyName": "deny_challenges_access",
            "PolicyId": "ANPATV2ULYL4RBGWQT5SE",
            "Arn": "arn:aws:iam::253043131129:policy/deny_challenges_access",
            "Path": "/",
            "DefaultVersionId": "v1",
            "AttachmentCount": 1,
            "PermissionsBoundaryUsageCount": 0,
            "IsAttachable": true,
            "CreateDate": "2023-12-11T23:25:03+00:00",
            "UpdateDate": "2023-12-11T23:25:03+00:00",
            "PolicyVersionList": [
                {
                    "Document": {
                        "Statement": [
                            {
                                "Action": "*",
                                "Condition": {
                                    "StringEquals": {
                                        "aws:ResourceTag/challenge": "true"
                                    }
                                },
                                "Effect": "Deny",
                                "Resource": "*",
                                "Sid": "DenyAllIAMActionsOnChallengedResources"
                            }
                        ],
                        "Version": "2012-10-17"
                    },
                    "VersionId": "v1",
                    "IsDefaultVersion": true,
                    "CreateDate": "2023-12-11T23:25:03+00:00"
                }
            ]
        }
    ]
}
```

내용은 `Effect: Deny` 에 `Action: "*"`·`Resource: "*"`, 조건은 `aws:ResourceTag/challenge` 가 `true` 인 리소스 — 그 태그가 붙은 리소스에 대한 모든 액션을 막는 정책이었음.

허용된 액션으로 거부된 정보를 우회 취득한 사례임. 같은 IAM 서비스 안에서도 일어나고, CloudTrail 로그를 읽어 리소스를 열거하는 식으로 **다른 서비스의 액션을 경유**해서도 일어남. 방어 측에서는 아이덴티티에 허용된 액션 전체와 그 액션이 닿을 수 있는 리소스 범위를 함께 봐야 함.
