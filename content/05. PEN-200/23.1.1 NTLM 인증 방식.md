# 23.1.1 NTLM 인증 방식

> **NTLM Authentication** · PEN-200 §23.1.1

NTLM 이 선택되는 조건은 셋임 — 클라이언트가 호스트명이 아니라 **IP 주소로** 서버에 인증할 때, AD 통합 DNS 서버에 등록되지 않은 호스트명으로 인증을 시도할 때, 그리고 서드파티 애플리케이션이 Kerberos 대신 NTLM 을 택했을 때임.

프로토콜은 일곱 단계로 구성됨.

![[PEN200-Fig-309.png]]

*Active Directory 에서의 NTLM 인증 흐름*

- ① 클라이언트 컴퓨터가 사용자 패스워드로 암호학적 해시(NTLM 해시)를 계산함
- ② 클라이언트가 서버에 사용자명을 보냄
- ③ 서버가 난수를 돌려줌 — nonce 또는 challenge 라 부름
- ④ 클라이언트가 NTLM 해시로 nonce 를 암호화한 값(response)을 서버에 보냄
- ⑤ 서버가 response 를 사용자명·nonce 와 함께 도메인 컨트롤러로 전달함
- ⑥ 검증은 도메인 컨트롤러가 함 — 모든 사용자의 NTLM 해시를 이미 갖고 있으므로, 해당 사용자명의 NTLM 해시로 nonce 를 직접 암호화해 받은 response 와 비교함
- ⑦ 두 값이 같으면 인증 요청 성공

즉 회선에 오가는 것은 해시 자체가 아니라 해시로 암호화한 응답이고, 판정 권한은 해시 전체를 쥔 도메인 컨트롤러에 있음.

NTLM 해시도 다른 암호학적 해시와 마찬가지로 역산은 불가함. 다만 **fast hashing 알고리즘**이라 짧은 패스워드는 평범한 장비로도 빠르게 깨짐 — 최상급 GPU 와 Hashcat 조합이면 초당 6000억 개 이상의 NTLM 해시를 시도할 수 있음. 8자 패스워드는 2.5시간, 9자는 11일 안에 깨질 수 있다는 뜻임.

약점이 이렇게 분명한데도 NTLM 을 완전히 끄고 차단하는 것은 광범위한 계획·준비가 필요한 일임 — 중요한 폴백 메커니즘이고 서드파티 애플리케이션이 다수 의존하기 때문임. 그래서 대부분의 평가에서 NTLM 인증이 켜진 채로 발견됨.

AD 와 그에 딸린 서비스의 **기본** 인증 프로토콜은 Kerberos 임.
