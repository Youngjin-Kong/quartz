# 26.3.3 애플리케이션 열거

> **Enumerating the Application** · PEN-200 §26.3.3

`app.offseclab.io` 홈에는 정보가 거의 없음. 링크로 노출되지 않은 HTTP 경로가 있을 수 있으므로 `dirb` 로 빠르게 브루트포싱함.

```
kali@kali:~$ dirb http://app.offseclab.io
....
GENERATED WORDS: 4612
---- Scanning URL: http://app.offseclab.io/ ----
+ http://app.offseclab.io/index.html (CODE:200|SIZE:3189)
...
```

*dirb 결과 — `index.html` 외에 소득 없음*

**HTML 소스는 이 대상에서만 값어치가 있음** — SCM 과 자동화 서버는 기성 제품이라 소스에 쓸 게 없지만 이 애플리케이션은 커스텀이라서임. View Page Source 로 보면 캐러셀 이미지가 전부 S3 버킷(`staticcontent-<랜덤>.s3.us-east-1.amazonaws.com`)에서 로드됨. 버킷 이름은 랩마다 다름.

*페이지 소스의 캐러셀 부분 — 이미지 4장이 모두 같은 S3 버킷에서 로드됨*

여기서 추론이 하나 나옴 — **페이지가 이미지를 정상 로드하는데 presigned URL 이 아니므로, 버킷 정책이 최소한 그 이미지들에는 퍼블릭 접근을 허용한다는 뜻임.**

버킷 루트를 `curl` 로 때려 전체 파일 목록을 노렸으나 거부됨.

```
kali@kali:~$ curl https://staticcontent-lgudbhv8syu2tgbk.s3.us-east-1.amazonaws.com
<?xml version="1.0" encoding="UTF-8"?>
<Error><Code>AccessDenied</Code><Message>Access
Denied</Message><RequestId>VFK5KNV3PV9B8SKJ</RequestId><HostId>0J13xDMdIwQB3e3HLcQvfYp
sRe1MO0Bn0OVUgl+7wtbs2v3XOZZn98WKQ0lsyqmpgnv5FjSGFaE=</HostId></Error>
```

*익명 나열 시도 — `AccessDenied` 로 막힘*

다음으로 워드리스트 앞 50개만 잘라 `dirb` 를 버킷에 돌림(첫 줄이 빈 줄이라 51줄). 전수는 아니지만 버킷이 열거에 어떻게 반응하는지 감을 잡는 용도임.

```
kali@kali:~$ head -n 51 /usr/share/wordlists/dirb/common.txt > first50.txt
kali@kali:~$ dirb https://staticcontent-lgudbhv8syu2tgbk.s3.us-east-1.amazonaws.com
./first50.txt
...
---- Scanning URL: https://staticcontent-lgudbhv8syu2tgbk.s3.us-east-1.amazonaws.com/
----
+ https://staticcontent-lgudbhv8syu2tgbk.s3.us-east-1.amazonaws.com/.git/HEAD
(CODE:200|SIZE:23)
...
DOWNLOADED: 50 - FOUND: 1
```

*앞 50개만 돌린 결과 — `.git/HEAD` 가 200 으로 응답*

**버킷에 git 저장소가 통째로 들어 있다고 봐야 함.**

다만 **브루트포스로 git 데이터를 뽑는 것은 시간 낭비임** — 중요한 git 파일 상당수가 랜덤 해시 이름이라 워드리스트로 맞힐 수 없어서임. 방식을 바꿈.

**AWS CLI 로 전환하는 이유** — CLI 는 다른 API 를 쓰고 무엇보다 **자격 증명을 실을 수 있음.** S3 의 흔한 오설정이 여기 걸림: 버킷 ACL 이 퍼블릭 접근은 막지만 `AuthenticatedUsers` 에는 허용해 두는 경우인데, 이 이름을 **자기 AWS 계정의 인증 사용자**로 착각하는 관리자가 많음. 실제로는 **아무 AWS 계정의 인증 사용자면 다 통과함.**

랩이 준 권한 없는 IAM 계정으로 시험함. 랩 제약상 이 IAM 사용자는 버킷과 같은 AWS 계정에 있지만, 다른 계정의 IAM 사용자를 써도 결과는 같음. 리전은 버킷 URL 에 드러난 `us-east-1` 을 씀.

```
kali@kali:~$ aws configure
AWS Access Key ID [None]: [REDACTED-AWS-KEY-ID]
AWS Secret Access Key [None]: [REDACTED-AWS-SECRET]
Default region name [None]: us-east-1
Default output format [None]:
```

```
kali@kali:~$ aws s3 ls staticcontent-lgudbhv8syu2tgbk
                           PRE .git/
                           PRE images/
                           PRE scripts/
                           PRE webroot/
2023-04-04 13:00:52        972 CONTRIBUTING.md
2023-04-04 13:00:52         79 Caddyfile
2023-04-04 13:00:52        407 Jenkinsfile
2023-04-04 13:00:52        850 README.md
2023-04-04 13:00:52        176 docker-compose.yml
```
