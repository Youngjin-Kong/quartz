# 19.1 포트 리디렉션과 터널링이 필요한 이유

> **Why Port Redirection and Tunneling?** · PEN-200 §19.1

평평한(flat) 네트워크 = 모든 장비가 서로 자유롭게 통신하고 접근 제한이 사실상 없는 구조. 정상 운영에서 통신할 필요가 있는지와 무관하게 열려 있어 보안 관행상 나쁜 설계로 봄 — 공격자가 호스트 하나만 잡으면 곧바로 나머지 전부와 통신할 수 있어 확산이 쉬움.

분할(segmented) 네트워크는 망을 서브넷 단위로 쪼개고, 서브넷마다 목적이 같은 장비를 묶은 뒤 **꼭 필요할 때만** 다른 서브넷·호스트로의 접근을 허용함. 호스트 하나가 뚫려도 나머지 전부가 열리지는 않으므로 공격자의 이동이 크게 제한됨.

분할과 함께 관리자는 트래픽의 유입·유출·횡단을 제한하는 통제를 얹음. 가장 흔한 수단이 방화벽임.

- 엔드포인트 소프트웨어 수준 — Linux 커널의 방화벽 기능(`iptables` 도구 모음으로 설정), Windows 의 Windows Defender Firewall
- 네트워크 장비에 기능으로 내장된 것
- 독립형 하드웨어 방화벽을 놓고 전 트래픽을 필터링하는 것

방화벽이 하는 일 — 원치 않는 인바운드 패킷을 버리고, 악성일 수 있는 트래픽이 망을 가로지르거나 빠져나가는 것을 막고, 특권 서버의 특정 포트에는 허용된 소수 호스트만 붙게 하고, 일부 호스트·서브넷의 외부 인터넷 접근을 차단함.

다만 대부분의 방화벽은 IP 주소와 포트 번호 규칙으로 허용/차단하므로 기능이 제한적임. 더 세밀한 통제가 필요하면 심층 패킷 검사(Deep Packet Inspection)가 들어옴 — 오가는 트래픽의 **내용**을 보고 규칙에 따라 끊음.

관리자가 세운 이 경계들은 데이터가 망을 임의로 드나들지 못하게 하려는 것이고, 공격자 입장에서는 정확히 그 경계가 넘어야 할 대상임. 제약을 만날 때마다 우회 전략이 필요함.

- **포트 리디렉션**(port redirection, 여러 형태의 포트 포워딩을 묶어 부르는 말) — 패킷을 한 소켓에서 다른 소켓으로 돌려 데이터 흐름 자체를 바꿈
- **터널링**(tunneling) — 한 종류의 데이터 스트림을 다른 스트림 안에 캡슐화함. 예를 들어 HTTP 트래픽을 SSH 연결 안에 실어 나르면 외부에서는 SSH 트래픽만 보임

이 모듈은 복잡도가 가장 낮은 기법부터 시작해, 기법마다 앞과 조금씩 다른 네트워크 구성에 적용하며 단계적으로 더 굳은 환경으로 옮겨감. 여기서 다루는 터널링은 SSH 터널링뿐이고 고급 기법은 뒤 모듈에서 다룸.

⚠️ 기법을 엮어 만드는 논리 토폴로지는 직관에 어긋나게 트래픽을 움직이므로 처음에는 잘 안 잡힘. 다음으로 넘어가기 전에 각 기법을 완전히 이해하고 갈 것.
