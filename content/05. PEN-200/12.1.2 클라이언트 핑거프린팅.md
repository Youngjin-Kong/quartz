# 12.1.2 클라이언트 핑거프린팅

> **Client Fingerprinting** · PEN-200 §12.1.2

클라이언트 핑거프린팅(client fingerprinting, 디바이스 핑거프린팅) — 라우팅되지 않는 내부망에 있는 대상의 OS·브라우저 정보를 알아내는 작업임.

왜 먼저 해야 하는가 — 예를 들어 메일에 HTA(HTML Application) 를 붙이는 벡터는 Internet Explorer 문맥(일부는 Microsoft Edge)에서 코드를 실행시킴. 즉 **대상이 Windows 를 쓰고 IE 나 Edge 가 켜져 있어야만 성립**함. 초기 발판 확보용으로 위협 행위자·랜섬웨어 조직이 즐겨 쓰는 인기 벡터지만, 전제 확인 없이 쏘면 그대로 실패임. 대상 메일 주소는 앞서 `theHarvester` 로 확보했다고 가정함.

확인 수단으로 쓰는 것이 **Canarytokens** — 토큰이 박힌 링크를 만들어 주는 무료 웹 서비스임. 대상이 그 링크를 브라우저로 열면 브라우저·IP 주소·OS 정보가 우리 쪽에 기록됨. 대상 화면에는 언제나 빈 페이지만 뜨므로 눈치채기 어려움.

**구실(pretext) 이 없으면 링크는 안 눌림.** 낯선 사람이 보낸 임의의 링크를 클릭할 이유가 없으므로 대상의 직무에서 문맥을 만들어 낼 것. 재무 부서가 대상이라면 "받은 청구서에 금액 오류가 있다, 문제 부분을 표시해 둔 스크린샷 링크를 보낸다" 식임 — 그 링크가 곧 Canarytoken 이고, 클릭하는 순간 IP 로거가 대상의 핑거프린트를 만듦.

토큰 생성 흐름 — 종류 드롭다운에서 `Web bug / URL token` 을 고르고, 알림 받을 이메일 주소나 웹훅 URL 과 코멘트를 입력한 뒤 Create my Canarytoken. 생성 화면에 추적 링크가 나오고, 우상단 `Manage this token` 에서 설정을, `History` 에서 링크를 클릭한 방문자 목록을 봄. 웹 앱이나 페이지에 토큰을 심는 경우가 아니라 단순 핑거프린팅이면 **기본 설정을 그대로 둘 것.**

![[PEN200-Fig-198.png]]

*History 항목을 펼친 상세 화면 — 위치·조직 추정과 브라우저가 보낸 정보가 나옴*

상세 화면 위쪽에는 피해자의 위치와 추정 조직명, 그리고 브라우저가 보낸 User-Agent 가 표시됨. 결과는 `.CSV` 나 `.json` 으로 내려받을 수 있음.

**User-Agent 를 단독 근거로 삼지 말 것 — 얼마든지 조작 가능해 신뢰도가 낮음.** 이 예시의 User-Agent 는 Intel Mac OS 10.15.7 의 Chrome 이라고 주장했지만, 페이지에 심긴 JavaScript 핑거프린팅 코드가 뽑아 온 값은 그보다 정밀하고 신뢰할 만함. 둘이 갈리면 JavaScript 쪽을 믿을 것. 아래 Geo info 영역에는 위치 정보가 추가로 붙음.

같은 서비스의 다른 수집 방식들 — Word 문서나 PDF 에 토큰을 심어 **파일이 열릴 때**, 이미지에 심어 **이미지가 조회될 때** 알림을 받는 유형이 있음. 서비스 밖 대안으로는 Grabify 같은 온라인 IP 로거, `fingerprint.js` 같은 JavaScript 핑거프린팅 라이브러리.

이 예시의 결론은 절반의 성공임 — 대상이 Windows 를 쓴다는 것은 확인했으나 브라우저가 Chrome 이라 원래 노리던 HTA 벡터의 전제가 깨짐. 이럴 때 선택지는 둘. **다른 클라이언트 사이드 벡터로 갈아타거나, 구실을 바꿔** "이 스크린샷은 Internet Explorer 나 Microsoft Edge 에서만 열린다"고 유도해 조건을 만들어 내는 것.
