# 12.1.1 타겟 정보 수집

> **Information Gathering** · PEN-200 §12.1.1

대상 머신과 **상호작용하지 않고** 설치 소프트웨어를 열거하는 방법들임. 접촉 수단이 아예 없을 때 쓰는 것이 원래 용도지만, 부수 효과로 모니터링 시스템을 깨우지 않고 조회 흔적도 남기지 않음.

한 가지 접근이 **공개된 문서의 메타데이터 태그**를 뜯어보는 것임. 수동으로 지울 수 있는 값이지만 실제로는 정리되지 않은 채 공개되는 경우가 많음. 태그(태그 그룹별로 분류됨)에서 나오는 것 — 작성자, 생성 일시, 문서를 만든 소프트웨어의 이름과 버전, 클라이언트 OS 등. 명시적으로 박혀 있기도 하고 추론으로 얻기도 하지만, 어느 쪽이든 조직 클라이언트의 소프트웨어 프로필을 그리는 데 쓸 만함.

한계 둘 — 오래된 문서를 보면 정보가 이미 낡았을 수 있고, 조직의 지사·부서마다 쓰는 소프트웨어가 조금씩 다를 수 있음. **무접촉의 대가로 정확도를 내주는 방식**이라는 점을 전제하고 볼 것.

문서를 모으는 경로 —

- Google dork `site:example.com filetype:pdf` 로 대상 웹페이지의 PDF 를 찾음. 특정 지사·지역을 노리면 키워드를 더해 결과를 좁힘
- 대상 사이트와 직접 상호작용해도 된다면 `gobuster` 의 `-x` 로 확장자를 지정해 훑음. 단 이쪽은 시끄럽고 **대상 서버에 로그가 남음**

모은 파일은 `exiftool` 로 봄. `-a` 는 중복된 태그까지, `-u` 는 알 수 없는 태그까지 표시하는 옵션임.

```
kali@kali:~$ cd Downloads
kali@kali:~/Downloads$ exiftool -a -u brochure.pdf
```

출력량은 많지만 볼 곳은 정해져 있음 — 생성·수정 일시, 작성자 이름, OS, 문서를 만든 애플리케이션.

읽는 법 —

- **Create Date / Modify Date** — 문서의 상대적 나이. 비교적 최근이면 메타데이터를 신뢰할 근거가 됨
- **Author** — 내부 직원 이름. 표적 메일이나 통화에서 이 이름을 자연스럽게 흘리면 신뢰 관계를 만들기 쉬움. 공개 활동이 적은 인물일수록 효과가 큼
- **Producer / Creator Tool** — `Microsoft® PowerPoint® for Microsoft 365` 이므로 대상이 Microsoft Office 를 쓴다는 확증임. 나아가 어느 태그에도 `macOS` 나 `for Mac` 표기가 없어 **Windows 에서 만들어진 문서일 개연성이 높음**

여기까지 확인되면 Windows 시스템 구성요소를 노리는 벡터부터 악성 Office 문서까지 선택지가 열림.
