# 7.1.1 취약점 스캐너의 동작 원리

> **How Vulnerability Scanners Work** · PEN-200 §7.1.1

- 스캐너마다 워크플로는 다르지만 기본 과정은 구현과 무관하게 같음 — ①호스트 발견 ②포트 스캔 ③OS·서비스·버전 탐지 ④결과를 취약점 데이터베이스와 대조.
- 호스트 발견은 대상이 살아 응답하는지를 알려주고, 이어서 열린 포트와 원격 접근 가능한 서비스·버전을 식별하며 이 단계에서 OS 탐지도 함께 수행됨. 모은 정보를 National Vulnerability Database·CVE(Common Vulnerabilities and Exposures) 같은 취약점 DB 에 질의해 매칭함.
- 상용 스캐너 다수는 찾은 취약점을 부분적·전면적으로 익스플로잇해 «검증»하는 기능을 가짐. 놓치는 취약점은 크게 줄지만 서비스·시스템의 안정성에 영향을 줄 수 있음.
- CVE 는 취약점을 «식별»할 뿐 심각도 정보를 담지 않음. 심각도의 특성과 등급을 다루는 체계가 CVSS(Common Vulnerability Scoring System)이고 각 CVE 에 점수가 부여됨. 주요 버전은 v2 와 v3 이며 둘 다 0~10 범위에 심각도 라벨을 붙임. 2019 년 v3.1 이 나와 기존 판을 명확히 하고 개선함.
- 점수는 취약점 DB 에서 해당 CVE 를 보면 되고, CVE 가 부여되지 않았으면 CVSS 계산기를 씀.

- 스캔 결과가 불완전하거나 잘못 탐지된 항목을 담을 수 있음을 전제할 것.
  - 오탐(false positive) — 취약점이 탐지됐으나 대상은 취약하지 않은 경우. 서비스·버전 오탐지, 익스플로잇을 불가능하게 만드는 설정이 원인이 됨. 보안 수정만 구버전 소프트웨어에 적용하는 백포팅(backport)도 오탐을 만듦.
  - 미탐(false negative) — 스캐너가 취약점을 놓친 경우.
- 수동 스캔은 자원·시간 소모가 크고 분석할 데이터가 많아지면 인지 한계에 빨리 걸려 결정적 세부를 놓침. 대신 자동 스캐너로는 발견하기 어려운 복합적·논리적 취약점을 찾아낼 수 있음.
- 자동 스캔이 필요한 이유 둘 — ①거의 모든 평가에 시간 제약이 있어 대규모 기업 네트워크를 손으로 다 볼 수 없음, 새롭거나 복잡한 취약점일수록 더함 ②쉽게 탐지되는 취약점과 저난도 지점을 빠르게 걷어냄.
- 평가에 쓸 자동 도구는 내부 동작을 미리 파악해 둘 것. 설정과 결과 해석뿐 아니라 «수동 전문성으로 메워야 할 한계»가 어디인지를 알게 됨.
