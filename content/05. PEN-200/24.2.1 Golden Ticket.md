# 24.2.1 Golden Ticket

> **Golden Ticket** · PEN-200 §24.2.1

Kerberos 에서 KDC 는 TGT 를 **도메인의 KDC 만 아는 비밀 키**로 암호화함. 그 비밀 키의 정체가 **`krbtgt` 도메인 계정의 비밀번호 해시**임. 따라서 `krbtgt` 해시를 손에 넣으면 **직접 만든 TGT** 를 발급할 수 있고, 이것이 golden ticket 임.

이름이 비슷한 Silver Ticket 과 갈리는 지점 —

- **Silver Ticket** — TGS 를 위조해 **특정 서비스 하나**에 접근
- **Golden Ticket** — TGT 를 위조해 **도메인 전체 자원**에 접근

예컨대 비특권 사용자가 Domain Admins 소속이라고 적은 TGT 를 만들어도, **암호화가 올바르므로 도메인 컨트롤러는 그것을 신뢰함.**

지속성 수단으로서 강력한 이유는 따로 있음 — **`krbtgt` 계정의 비밀번호는 자동으로 바뀌지 않음.** 2008 이전 Windows Server 에서 도메인 기능 수준(Domain Functional Level)을 올릴 때만 변경되고 그 이후 버전에서는 변경되지 않아, **아주 오래된 `krbtgt` 해시가 남아 있는 경우가 드물지 않음.**

⚠️ **훔친 `krbtgt` 해시는 도메인 무제한 접근권이라 각별히 보호할 것.** 이 기법을 실행하기 전에 **고객의 명시적 허가**를 받는 것을 고려할 것.

전제 확인 — golden ticket 을 만들려면 먼저 **Domain Admins 계정 또는 도메인 컨트롤러 자체를 장악**해야 함. 그 전 단계에서는 아래처럼 막힘.

```
C:\Tools\SysinternalsSuite>PsExec64.exe \\DC1 cmd.exe
PsExec v2.4 - Execute processes remotely
Copyright (C) 2001-2022 Mark Russinovich
Sysinternals - www.sysinternals.com
Couldn't access DC1:
Access is denied.
```

DC 에 접근이 되면 mimikatz 의 `lsadump::lsa /patch` 로 `krbtgt` 해시와 **도메인 SID** 를 함께 걷음. 둘 다 위조에 필요함.


**여기서부터는 권한이 필요 없음.** 티켓 생성과 메모리 주입에는 관리자 권한이 필요 없고, **도메인에 가입되지 않은 컴퓨터에서도 가능**함. 그래서 장악한 워크스테이션으로 돌아와 진행함.

티켓을 만들기 전에 기존 Kerberos 티켓을 `kerberos::purge` 로 비움.

```
mimikatz # kerberos::purge
Ticket(s) purge for current session is OK
```

`kerberos::golden` 에 도메인 SID(`whoami /user` 로 확인 가능)와 `krbtgt` 해시를 넣음. 해시를 넘길 때는 `/rc4` 가 아니라 **`/krbtgt`** 를 씀. `/ptt` 는 만든 즉시 현재 세션에 주입하라는 뜻임.

⚠️ **2022년 7월 이후 Microsoft 가 인증 절차를 강화해, `/user:` 에는 «실재하는 계정»을 넣어야 함.** 그 전에는 존재하지 않는 이름이어도 통했음 — 옛 자료를 그대로 따라 하다 여기서 실패함.

기본값 두 개를 읽어둘 것 — **User Id 500** 은 도메인 빌트인 관리자의 RID 이고, **Groups Id** 목록은 Domain Admins 를 포함한 AD 최상위 권한 그룹들임. 즉 옵션을 따로 주지 않아도 도메인 관리자급 TGT 가 나옴.

⚠️ **함정 — 대상을 IP 로 지정하면 실패함.** 직접 만든 TGT 를 PsExec 으로 쓰는 것은 결국 Overpass-the-Hash 와 같은 구조여서 **Kerberos 인증이 성립해야** 함. 호스트명 대신 IP 를 주면 NTLM 인증이 강제되고 접근은 다시 막힘.

```
C:\Tools\SysinternalsSuite> psexec.exe \\192.168.50.70 cmd.exe
PsExec v2.4 - Execute processes remotely
Copyright (C) 2001-2022 Mark Russinovich
Sysinternals - www.sysinternals.com
Couldn't access 192.168.50.70:
Access is denied.
```

정리하면 — **`krbtgt` 해시 하나로 임의의 «실재하는» 저권한 계정에 도메인 관리자급 TGT 를 계속 발급**할 수 있고, 그 접근은 겉보기에 정상 인증이라 눈에 띄지 않음.
