# 22.2.3 스크립트에 검색 기능 추가

> **Adding Search Functionality to our Script** · PEN-200 §22.2.3

지금까지 만든 스크립트는 LDAP 경로를 만들기만 함. 여기에 검색 기능을 붙임. `System.DirectoryServices` 네임스페이스의 두 클래스, **DirectoryEntry** 와 **DirectorySearcher** 를 씀.

- **DirectoryEntry** — AD 계층의 객체 하나를 캡슐화함. 계층 최상단부터 검색할 것이므로 앞 절에서 얻은 LDAP 경로를 넘김. 자격 증명을 넘겨 도메인 인증을 시킬 수도 있으나 이미 로그인 상태라 필요 없음
- **DirectorySearcher** — LDAP 으로 실제 질의를 수행함. 인스턴스를 만들 때 `SearchRoot` 속성으로 **AD 계층의 어느 지점에서 검색을 시작할지** 지정해야 하는데, 최상단을 가리키는 DirectoryEntry 를 그대로 넘겨 씀. `FindAll()` 메서드가 찾은 항목 전체를 컬렉션으로 반환함

앞 절 스크립트 끝에 세 줄을 덧붙임. 전체 스크립트는 아래와 같음.

```
$PDC =
[System.DirectoryServices.ActiveDirectory.Domain]::GetCurrentDomain().PdcRoleOwner.Nam
e
$DN = ([adsi]'').distinguishedName
$LDAP = "LDAP://$PDC/$DN"
$direntry = New-Object System.DirectoryServices.DirectoryEntry($LDAP)
$dirsearcher = New-Object System.DirectoryServices.DirectorySearcher($direntry)
$dirsearcher.FindAll()
```

*DirectoryEntry·DirectorySearcher 를 얹고 FindAll() 로 검색 실행*

> [!warning] 위 블록은 교재 조판에서 줄이 접혀 있음
> `$PDC =` 다음 줄과 `...PdcRoleOwner.Nam` / `e` 는 원래 이어진 한 줄임. 그대로 옮겨 치면 동작하지 않으므로 접힌 줄을 이어 붙일 것.

최상단에서 필터 없이 도는 것이라 출력이 방대함 — 사실상 도메인의 모든 객체가 나옴. 그래도 스크립트가 의도대로 도는 것은 확인됨.

필터링 방법은 여럿인데, **사용자·컴퓨터·그룹 객체 모두에 붙는 `samAccountType` 속성**을 거르는 것이 한 방법임. 값이 여럿이지만 `0x30000000`(10진 `805306368`)이 도메인의 일반 사용자 계정에 해당함. `$dirsearcher.filter="samAccountType=805306368"` 한 줄을 `FindAll()` 앞에 넣으면 사용자 객체만 남음.

*필터 적용 결과 — 도메인의 사용자 객체만 남음*

여기서 한 걸음 더 나감. 열거에서 정작 중요한 것은 객체마다의 **속성(Properties)** 이므로, 검색 결과를 변수에 담고 중첩 loop 로 각 속성을 한 줄씩 출력하도록 고침.

```
$domainObj = [System.DirectoryServices.ActiveDirectory.Domain]::GetCurrentDomain()
$PDC = $domainObj.PdcRoleOwner.Name
$DN = ([adsi]'').distinguishedName
$LDAP = "LDAP://$PDC/$DN"
$direntry = New-Object System.DirectoryServices.DirectoryEntry($LDAP)
$dirsearcher = New-Object System.DirectoryServices.DirectorySearcher($direntry)
$dirsearcher.filter="samAccountType=805306368"
$result = $dirsearcher.FindAll()
Foreach($obj in $result)
{
    Foreach($prop in $obj.Properties)
    {
        $prop
    }
    Write-Host "-------------------------------"
}
```

*필터와 중첩 loop 까지 얹은 완성 스크립트*

동작은 이렇게 갈림 — `$result` 에 검색 결과가 담기고, 바깥 loop 가 객체를 하나씩 `$obj` 로 꺼내고, 안쪽 loop 가 그 객체의 속성을 전부 `$prop` 으로 꺼내 출력함. `Write-Host` 는 기능상 필수는 아니고 객체 사이에 구분선을 넣어 읽기 편하게 하는 것임.

*jeffadmin 의 소속 그룹 — Domain Admins 소속이 확인됨*

다만 지금 형태로는 **열거 대상을 바꿀 때마다 스크립트 본문을 고쳐야 함.** 질의를 명령행 인자로 받도록 지금까지의 기능을 함수로 감싸면 유연해짐.

```
function LDAPSearch {
    param (
        [string]$LDAPQuery
    )
    $PDC =
[System.DirectoryServices.ActiveDirectory.Domain]::GetCurrentDomain().PdcRoleOwner.Nam
e
    $DistinguishedName = ([adsi]'').distinguishedName
    $DirectoryEntry = New-Object
System.DirectoryServices.DirectoryEntry("LDAP://$PDC/$DistinguishedName")
    $DirectorySearcher = New-Object
System.DirectoryServices.DirectorySearcher($DirectoryEntry, $LDAPQuery)
    return $DirectorySearcher.FindAll()
}
```

*LDAP 질의를 인자로 받는 LDAPSearch 함수*

> [!warning] 위 블록은 교재 조판에서 줄이 접혀 있음
> `$PDC =` 다음 줄, `New-Object` 다음 줄이 원래는 이어진 한 줄임. 그대로 옮겨 치면 동작하지 않으므로 접힌 줄을 이어 붙일 것.

구조는 단순함 — 맨 위에서 `LDAPSearch` 라는 이름으로 함수를 선언하고, 필요한 LDAP 연결 문자열을 동적으로 만들어 `$DirectoryEntry` 에 담고, 그것과 `$LDAPQuery` 파라미터를 DirectorySearcher 에 먹인 뒤 `FindAll()` 결과를 배열로 반환함. 쓰려면 먼저 메모리에 import 함.

```
PS C:\Users\stephanie> Import-Module .\function.ps1
```

*Sales Department 의 member 속성 — Development Department 가 구성원으로 확인됨*

이것이 **중첩 그룹(nested group)** 임. AD 에서 흔하고 확장성이 좋아 대규모 환경에서 구성원을 유연하게 관리하는 수단으로 쓰임. `net.exe` 가 이를 놓친 이유는 **사용자 객체만 나열하고 그룹 객체는 보여주지 않으며, 특정 속성을 지정해 출력할 수도 없기** 때문임 — 직접 만든 도구의 값이 여기서 드러남.

`Development Department` 를 이어서 열거함.

```
PS C:\Users\stephanie> $group = LDAPSearch -LDAPQuery
"(&(objectCategory=group)(cn=Development Department*))"

CN=Management Department,DC=corp,DC=com
CN=pete,CN=Users,DC=corp,DC=com
CN=dave,CN=Users,DC=corp,DC=com
```

*Development Department 의 구성원 — Management Department 가 또 중첩돼 있음*

```
PS C:\Users\stephanie\Desktop> $group = LDAPSearch -LDAPQuery
"(&(objectCategory=group)(cn=Management Department*))"
PS C:\Users\stephanie\Desktop> $group.properties.member
CN=jen,CN=Users,DC=corp,DC=com
```

*Management Department 의 구성원 — jen 하나로 사슬이 끝남*

`jen` 은 `Management Department` 소속만으로 보이지만, **그룹이 서로를 상속하므로 `Sales Department` 와 `Development Department` 의 간접 구성원이기도 함.** AD 의 정상 동작이나 잘못 구성되면 사용자가 의도보다 큰 권한을 갖게 되고, 공격자는 그 오구성을 도메인 안에서 발을 넓히는 데 씀. 앞서 한 번에 뽑은 출력에서도 `jen` 은 보였지만, 그룹을 하나씩 짚어 들어간 덕에 상속 관계까지 드러났음.

PowerShell 로 .NET 클래스를 호출해 LDAP 질의를 돌리는 접근은 `net.exe` 류보다 훨씬 강력하고 열거 선택지도 넓음. 다음 절에서는 이미 만들어져 있는 스크립트로 이 과정의 속도를 올림.
