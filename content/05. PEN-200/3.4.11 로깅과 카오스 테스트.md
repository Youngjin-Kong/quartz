# 3.4.11 로깅과 카오스 테스트

> **Logging and Chaos Testing** · PEN-200 §3.4.11

세밀한 데이터에 빠르게 접근하는 것은 조직에 큰 이점이고, 잘 설계된 로깅은 애플리케이션 설계에서 가장 중요한 보안 요소 중 하나임. 일관되고 처리하기 쉬우며 충분히 상세한 로그가 있어야 운영팀이 문제에 빨리 반응하고 사고를 더 빨리 탐지·해결함.

- 로깅 대상이 네트워크에서 일어난 일만은 아님. 라우터·스위치·방화벽 같은 네트워크 장비도 대상이며, 여기서는 구매일·OS 버전·EOL 날짜 같은 항목까지 기록함
- 이 인벤토리가 있으면 경영진은 EOL 이 다가올 때 대규모 구매를 예산에 반영할 수 있고, 보안팀은 자사 네트워크 장비를 즉시 조회할 수 있음
- 가치가 드러나는 순간의 예 — SolarWinds 공격 당일 아침의 네트워크 관리자. 인벤토리 DB 를 조회해 자사가 SolarWinds 장비를 쓰는지 확인하는 쪽과, 원격 사이트마다 전화해 서버실을 확인시키는 쪽의 차이임
- 자산 대장은 노트북·모바일 장비 추적에도 쓰임. 분실·도난 시, EOL 로 보증이 끝나 교체가 필요할 때 대비가 됨

**카오스 테스트(Chaos Testing)** — BCP 또는 재해 복구(DR) 훈련의 한 형태이며 대개 자동화로 수행함.

- 예로 운영 네트워크에서 유효한 관리자 자격 증명을 가진 가상 머신을 두고 «내부에서» 의도적으로 장애를 일으킴
- 접근 방식이 다양함 — 레드팀이 조직에 혼란을 만들어 대응력을 시험하거나, 프로그램된 머신 종료를 여러 간격으로 예약하거나, 인증된 악의적 플랫폼 API 명령을 보내는 식
- 목적은 지저분하고 예측 불가능한 상황에서 통제를 진짜로 시험하는 것. 운영 시스템과 조직이 혼란을 비교적 매끄럽게 견디면, 보안 위협에도 견고하고 회복력이 있다는 지표가 됨
