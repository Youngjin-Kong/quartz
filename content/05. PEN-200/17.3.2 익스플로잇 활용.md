# 17.3.2 익스플로잇 활용

> **Using Exploits** · PEN-200 §17.3.2

권한 상승(privilege escalation)으로 이어지는 익스플로잇을 세 계열로 나눔.

- **애플리케이션 취약점** — 설치된 애플리케이션이 관리자 권한으로 도는 상태에서 코드 실행 취약점을 얻으면 그 권한을 그대로 승계함
- **Windows 커널 취약점** — 취약점 연구·익스플로잇 기법 자체는 고급 영역이라 이 모듈에서는 「존재하고 권한 상승에 쓰인다」까지만 알면 됨
- **Windows 권한(privilege) 악용** — 비특권 사용자에게 할당된 특정 권한을 남용

커널 익스플로잇은 **시스템을 쉽게 크래시시킴**. 침투 테스트의 교전 규칙(rules of engagement)에 따라 서비스·시스템 중단 가능성이 있는 수단이 아예 금지될 수 있으므로, 실제 평가에서는 제약·제외 대상·경계를 먼저 확정할 것.

운용 규율 두 가지 —

- **소스 코드가 함께 공개된 것만 사용함.** 바이너리가 악성 동작을 하지 않음을 확인할 수 없으면 쓰지 않음
- **사용이 허용된 경우에도 대상의 클론에서 먼저 시험함.** 실행 시 크래시 여부를 미리 확인하려는 것

**예시 1 — 커널 익스플로잇 (CVE-2023-29360).** CLIENTWK220 에 steve 로 RDP 접속. 먼저 할당된 권한을 확인함.

```
PS C:\Users\steve> whoami /priv
PRIVILEGES INFORMATION
----------------------
Privilege Name                Description                          State
============================= ==================================== ========
SeSecurityPrivilege           Manage auditing and security log     Disabled
SeShutdownPrivilege           Shut down the system                 Disabled

SeUndockPrivilege             Remove computer from docking station Disabled
```

*steve 에게 특별한 권한이 하나도 없음 — 세 번째 계열(권한 악용)은 이 계정으로 쓸 수 없음*

세 번째 계열인 Windows 권한 악용으로 넘어감. `SeImpersonatePrivilege` — **토큰(token)을 다른 보안 컨텍스트로 활용할 수 있게 하는 권한.** 즉 이 권한을 가진 사용자는 조건이 맞으면 다른 사용자 계정의 보안 컨텍스트로 작업을 수행할 수 있음.

기본 할당 대상은 로컬 Administrators 그룹 구성원과 장비의 LOCAL SERVICE·NETWORK SERVICE·SERVICE 계정. Microsoft 가 이 권한을 둔 목적은 **무단 사용자가 서비스나 서버 애플리케이션을 만들어 접속해 오는 클라이언트를 가장(impersonate)하는 것을 막기 위함** — RPC(Remote Procedure Calls)나 named pipe 가 그런 예임.

권한 상승으로 이어질 수 있는 다른 권한 — `SeBackupPrivilege`, `SeAssignPrimaryToken`, `SeLoadDriver`, `SeDebug`.

**실전에서 언제 만나는가** — 일반 사용자가 이 권한을 가진 경우는 드묾. 대신 **IIS(Internet Information Service) 웹 서버의 취약점으로 코드 실행을 얻었을 때 흔히 마주침.** 대부분의 구성에서 IIS 는 LocalService·LocalSystem·NetworkService·ApplicationPoolIdentity 중 하나로 도는데 전부 이 권한을 가짐. 다른 Windows 서비스도 마찬가지.

named pipe 는 Windows 의 로컬·원격 프로세스 간 통신(IPC) 수단으로, 관계 없는 두 프로세스가 데이터를 주고받게 함. 서버가 파이프를 만들면 클라이언트가 그 이름으로 접속하며, **서버와 클라이언트가 같은 시스템에 있을 필요가 없음.** 클라이언트가 접속하는 순간 서버는 접속 과정의 인증을 캡처해 `SeImpersonatePrivilege` 로 그 클라이언트를 가장할 수 있음.

따라서 공격 흐름은 —

1. 권한 있는 프로세스를 찾음
2. 그것이 **내가 통제하는 named pipe 로 접속하도록 유도(coerce)**
3. `SeImpersonatePrivilege` 로 접속해 온 계정을 가장해 그 보안 컨텍스트로 작업

이 유도를 자동화한 것이 potato 계열 도구임. 여기서는 **SigmaPotato** 를 써서 `NT AUTHORITY\SYSTEM` 이 통제 파이프로 접속하도록 만듦. 전제는 「`SeImpersonatePrivilege` 를 가진 사용자로 코드 실행이 이미 확보돼 있을 것」이고, 결과는 SYSTEM 권한의 명령 실행 또는 대화형 셸.
