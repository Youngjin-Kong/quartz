# 7.1.3 취약점 스캔 시 고려사항

> **Things to consider in a Vulnerability Scan** · PEN-200 §7.1.3

- 대규모 평가일수록 의미 있고 관련성 높은 결과를 얻으려면 스캐너를 신중히 설정해야 함.
- 스캔 소요 시간 — 스캔 유형과 대상 수에 따라 크게 달라짐. 특히 인터넷을 거치는 외부 스캔은 경로상의 홉과 중간 시스템 때문에 오래 걸리므로, IP 목록이 크면 그만큼 일정을 잡을 것.
- 대상 가시성 — IP 를 넣고 시작하는 것은 쉽지만 VPN 이나 방화벽 허용 없이 실제로 닿는지를 먼저 판단해야 함.
  - 고객이 외부 스캔용 IP 목록을 준 경우는 대개 문제가 없음. 반대로 공개 인프라의 공격 표면을 직접 규정해야 한다면 방화벽 등 접근 제한 장치 때문에 일부 시스템·서비스가 아예 안 보일 수 있음을 전제할 것.
  - 예 — 여러 나라에 시스템을 둔 고객이 각 시스템을 그 나라 밖 IP 로부터 차단해 두면, 우리 위치에서는 자국 시스템만 보이고 나머지는 접근 불가임.
  - 내부 평가에서도 네트워크상의 «위치»가 결과를 좌우함. 다른 서브넷을 스캔할 때 특히 그렇고, 방화벽·IPS(intrusion prevention system)·라우터 같은 중간 장비가 트래픽을 걸러내거나 변조함.
  - 대표적 사고 — 호스트 발견 단계의 ICMP 패킷을 중간 장비가 전달하지 않아 스캐너가 살아 있는 대상을 오프라인으로 표시함.
- 레이트 리미팅(rate limiting) — 네트워크 트래픽 총량을 제한하는 장치. 처리량·패킷 수·연결 수 임계를 넘기면 스캔 출발지 시스템의 네트워킹 능력이 크게 제한됨. 호스트 발견과 서비스 탐지 프로브가 느려지면 살아 있는 호스트나 서비스를 놓침. 대부분의 스캐너가 지연·타임아웃·동시 연결 수 제한으로 대응 가능함.
- 네트워크·시스템 영향 — 스캐너는 대부분의 설정에서 많은 트래픽을 만들고, 여러 대상을 병렬로 걸면 네트워크를 못 쓰게 만들 수 있음. 병렬 스캔 수나 스캔 속도를 낮춰 완화함. 더 큰 문제는 대상의 «안정성»이며, 모든 취약점 스캔은 스캔하는 시스템·서비스에 불안정을 초래할 수 있다는 것을 전제해야 함.
