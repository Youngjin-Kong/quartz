# 8.4.3 XSS 취약점 식별

> **Identifying XSS Vulnerabilities** · PEN-200 §8.4.3

XSS 의 진입점은 **새니타이즈되지 않은 입력을 받아 이후 페이지에 출력으로 되돌려주는 필드**임 — 검색창이 전형적인 예. 진입점을 찾으면 특수문자를 넣어보고 출력에서 어떤 문자가 필터링되지 않고 그대로 돌아오는지 관찰함. 이때 쓰는 문자들:

```
< > ' " { } ;
```

*HTML·JavaScript 에서 특별한 의미를 갖는 문자들*

각 문자가 시험 대상인 이유 — `<` `>` 는 HTML 요소(element)의 경계, `{` `}` 는 JavaScript 함수 선언, 따옴표는 문자열 구분, `;` 는 구문 종료를 나타냄. 애플리케이션이 이 문자들을 제거하거나 인코딩하지 않으면 브라우저가 그것을 **코드로 해석**하고, 그 위에 추가 코드를 얹을 수 있게 되어 XSS 가 성립함.

웹 애플리케이션에서 만나는 인코딩은 주로 둘임. URL 인코딩(퍼센트 인코딩)은 URL 안의 비 ASCII 문자와 예약 문자를 변환하는 것으로, 공백이 `%20` 이 되는 식임. HTML 인코딩(문자 참조, character reference)은 원래 특별한 의미를 갖는 문자를 화면에 그대로 보여주기 위한 것으로 `&lt;` 가 `<` 의 문자 참조임 — 이 형태를 만나면 브라우저는 요소의 시작으로 해석하지 않고 문자 자체를 출력함.

**필요한 문자 집합은 입력이 «어디에» 삽입되는가에 따라 달라짐.** 입력이 `div` 태그 사이에 들어간다면 스크립트 태그를 직접 만들어야 하므로 페이로드의 일부로 `<` 와 `>` 를 주입할 수 있어야 함. 반면 이미 존재하는 JavaScript 태그 안으로 들어간다면 따옴표와 세미콜론만으로 자기 코드를 이어붙일 수 있음.
