# 16.3.5 Windows Credential Guard

> **Windows Credential Guard** · PEN-200 §16.3.5

여기까지 다룬 해시는 전부 로컬 계정 것이었음. 도메인 계정으로 로그인한 사용자는 저장 위치가 다름 — 로컬 계정 해시는 SAM 에 있지만 **도메인 자격 증명은 `lsass.exe` 프로세스의 메모리에 캐시**됨. 이걸 뽑아내면 크랙하거나 pass-the-hash 에 그대로 쓸 수 있음. Mimikatz 가 그 메모리를 훑어 줌 — 단 앞 절과 마찬가지로 Administrator 이상으로 실행하고 `SeDebugPrivilege` 를 켜야 함.

실습 흐름은 두 단계임. 먼저 도메인 계정으로 한 번 로그인해 LSASS 에 자격 증명이 캐시되게 만듦(로그인 뒤 로그아웃해도 캐시는 남음).

```
kali@kali:~$ xfreerdp /u:"CORP\\Administrator" /p:"QWERTY123\!@#" /v:192.168.50.246
/dynamic-resolution
```
*CLIENTWK246 에 도메인 관리자로 RDP — 캐시를 만드는 것이 목적이고, 접속 후 로그아웃함*

⚠️ 이 절의 `xfreerdp`·`impacket-wmiexec` 블록은 교재 PDF 자체의 조판으로 한 줄이 여러 줄로 접혀 있음. 실제로는 한 줄이라 그대로 복사하면 실패함. 원문 산문은 비밀번호를 `QWERTY!@#` 로 적지만 실제 명령과 뒤의 로그는 `QWERTY123!@#` 임 — **명령 쪽이 맞음**.

*LM 자리를 0 으로 채운 `LM:NTLM` 형식으로 넘김 — 다른 머신으로 옮겨 감*

자격 증명 해시를 이렇게 쓰는 것이 흔해지자 Microsoft 가 대응을 내놓음. 뿌리는 **VBS(Virtualization-based Security)** 임 — 최신 CPU 의 하드웨어 가상화 기능을 써서 OS 위가 아니라 **물리 하드웨어 위에서 하이퍼바이저(Hyper-V)를 돌리고**, 그 힘으로 메모리에 격리된 영역을 만들어 신뢰의 뿌리로 삼음. 그 위에 얹힌 것이 **VSM(Virtual Secure Mode)** 이고, 여기서 만든 격리 영역은 **하이퍼바이저를 통해서만 접근됨.** 하이퍼바이저는 커널보다 높은 특권에서 돌기 때문에 — 이것이 핵심 인과다 — **SYSTEM 까지 권한을 올려도 그 영역은 못 읽음.**

격리 단위는 **VTL(Virtual Trust Level)** 이고 최대 16단계까지 정의돼 있으나 현재 Windows 는 둘만 씀.

- **VTL0(Normal Mode)** — 평소의 Windows. 일반 사용자 모드 프로세스와 통상 커널(`nt`)이 여기 있음
- **VTL1(Secure Mode)** — 격리된 Windows. 사용자 모드를 IUM(Isolated User-Mode)이라 하고 그 안의 프로세스를 트러스트렛(trustlet)이라 부름

VSM 위에 Device Guard·가상 TPM·Credential Guard 가 올라감. Windows 10 / Server 2016 부터 있었지만 **기본값이 꺼짐**이라 기업 환경 대부분에서 비활성이었음. 최근 설치본은 기본 활성이나, **새로 설치하지 않고 업데이트만 한 머신은 이전 상태를 그대로 끌고 감** — 꺼져 있었으면 업데이트 후에도 꺼져 있음. 시험·실무에서 만나는 머신이 갈리는 지점임.

**Credential Guard 가 켜지면** LSA 환경이 VTL1 의 트러스트렛 `LSAISO.exe`(LSA Isolated)로 돌고, VTL0 의 `LSASS.exe` 와는 RPC 채널로만 통신함. Mimikatz 가 뒤지는 것은 `LSASS.exe` 의 메모리인데 캐시된 해시·자격 증명은 이제 VTL1 쪽에 있으므로 **덤프해도 안 나옴.**

```
kali@kali:~$ xfreerdp /u:"CORP\\Administrator" /p:"QWERTY123\!@#" /v:192.168.50.245
/dynamic-resolution
```
*이번 대상은 CLIENTWK245 — 도메인 관리자로 붙어 캐시를 만듦*

⚠️ **경계가 중요함 — Credential Guard 는 비로컬(도메인) 사용자만 보호함.** 같은 머신의 **로컬 사용자 NTLM 해시는 여전히 뽑힘.** 「CG 켜짐 = 해시 포기」가 아님.

이미 로그인한 뒤의 캐시를 못 가져오니 **시점을 앞으로 옮김 — 로그인하는 «중»에 가로챔.**

Windows 인증의 축은 **SSPI(Security Support Provider Interface)** 임. 인증이 필요한 모든 애플리케이션·서비스가 여기로 요청을 보내고, SSPI 가 어느 제공자를 쓸지 고름. 실제 제공자가 **SSP(Security Support Provider)** 이고 Kerberos·NTLM 등이 DLL 형태로 꽂혀 있음. 여기서 공격 표면이 열림 — **SSP 는 여러 개 등록할 수 있음.** `AddSecurityPackage` API 로도 되고, `HKEY_LOCAL_MACHINE\System\Control\Lsa\Security Packages` 레지스트리 키에 적어도 됨(부팅할 때마다 `lsass.exe` 가 그 목록의 DLL 을 로드함). 즉 **직접 만든 SSP 를 등록하면 SSPI 가 인증에 그것을 쓰게 만들 수 있음.**

Mimikatz 의 `misc::memssp` 가 이걸 그대로 해 주되, **디스크에 DLL 을 떨구지 않고 `lsass.exe` 메모리에 직접 주입**함. 그리고 결정적으로 — **SSP 는 SSPI 로부터 평문 자격 증명을 받아 호출됨.** 그래서 해시를 우회할 필요 자체가 없어지고 비밀번호가 평문으로 떨어짐.

```
mimikatz # privilege::debug
Privilege '20' OK
mimikatz # misc::memssp
Injected =)
```
*SSP 주입 — 성공하면 `Injected =)`*

주입 뒤에는 **누군가 로그인해 주기를 기다려야 함**(또는 사회공학으로 유도). 실습에서는 RDP 세션을 끊고 `CORP\Administrator` 로 다시 붙어 직접 만듦.

```
kali@kali:~$ xfreerdp /u:"CORP\\Administrator" /p:"QWERTY123\!@#" /v:192.168.50.245
/dynamic-resolution
```
