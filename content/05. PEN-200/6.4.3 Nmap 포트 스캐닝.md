# 6.4.3 Nmap 포트 스캐닝

> **Port Scanning with Nmap** · PEN-200 §6.4.3

Nmap — 포트 스캐닝의 사실상 표준 도구(Gordon Lyon, aka Fyodor 작성). 20년 넘게 개발돼 왔고 포트 스캔 외의 기능도 많음.

예제 다수가 `sudo` 로 도는 이유 — 상당수 스캔 옵션이 raw socket 접근을 요구하고, 그것이 다시 root 권한을 요구하기 때문임. raw socket 이 있어야 TCP·UDP 패킷을 정밀하게 조작할 수 있고, 없으면 Nmap 은 표준 Berkeley socket API 로 패킷을 만드는 수준으로 제한됨.

**스캔이 회선과 대상에 남기는 발자국을 먼저 알 것.** 기본 TCP 스캔은 가장 인기 있는 1000개 포트를 훑음. 그 트래픽 양을 iptables 카운터로 재 봄 — `-I` 로 체인(여기서는 INPUT·OUTPUT)에 규칙 번호를 지정해 삽입하고, `-s`·`-d` 로 출발지·목적지 IP 를, `-j ACCEPT` 로 처리 방식을 정하며, `-Z` 로 모든 체인의 패킷·바이트 카운터를 0 으로 만듦.

```
kali@kali:~$ sudo iptables -I INPUT 1 -s 192.168.50.149 -j ACCEPT
kali@kali:~$ sudo iptables -I OUTPUT 1 -d 192.168.50.149 -j ACCEPT
kali@kali:~$ sudo iptables -Z
```

*스캔 트래픽 계측용 iptables 규칙*

참고로 `-Pn` 은 호스트 발견(ping 스캔)을 끄고 모든 대상을 살아 있는 것으로 취급함 — ICMP 요청을 막아 죽은 것처럼 보이는 호스트를 스캔할 때 유용함.

*카운터 초기화 → 전 포트 스캔 → 카운터 재확인*

이상적으로는 전 대상 전 포트 TCP·UDP 스캔이 가장 정확한 그림을 주지만, 느린 업링크 같은 트래픽 제약과 추가 발견 사이에서 저울질해야 함 — 클래스 A·B 규모에서는 특히 그러함. MASSCAN·RustScan 은 Nmap 보다 빠른 대신 동시 트래픽을 크게 만듦. Nmap 은 자체적으로 속도 제한을 걸어 대역 혼잡이 덜하고 상대적으로 덜 튐.

은밀성을 어디까지 챙길지는 과제의 스코프와 목적이 정함. 침투 테스트는 오설정·취약점 식별에 무게를 두고 공개적으로 진행되는 경우 탐지 회피 비중이 낮은 반면, 레드팀은 실제 공격자 전술을 모사해 SOC(Security Operations Center)의 탐지·대응 역량을 평가하므로 은밀성이 핵심임.

**SYN 스캔(`-sS`)** — 가장 많이 쓰이는 기법이고, 스캔 옵션을 지정하지 않고 raw socket 권한이 있으면 기본으로 선택됨. 여러 포트에 SYN 만 보내고 핸드셰이크는 끝내지 않음. 포트가 열려 있으면 SYN-ACK 이 돌아오는데, 스캐너는 그 시점에 마지막 ACK 을 보내지 않음.

*SYN 스캔*

핸드셰이크가 완성되지 않으므로 정보가 애플리케이션 계층까지 올라가지 않고, 따라서 **애플리케이션 로그에 남지 않음.** 주고받는 패킷이 적어 더 빠르고 효율적이기도 함. 다만 「스텔스」라는 이름은 과거 방화벽이 미완성 TCP 연결을 로깅하지 않던 시절의 것임 — 요즘 방화벽에는 해당되지 않으므로 이름에 속지 말 것.

**TCP connect 스캔(`-sT`)** — 이름 그대로 TCP 연결을 끝까지 맺음. raw socket 권한이 없으면 Nmap 이 이 방식으로 물러남. Berkeley socket API 로 3-way 핸드셰이크를 수행하므로 권한 상승이 필요 없지만, API 가 연결 상태를 돌려줄 때까지 기다려야 해서 SYN 스캔보다 훨씬 오래 걸림. 특정 유형의 프록시를 거쳐 스캔할 때처럼 필요한 경우가 있음. 이런 단순한 스캔만으로도 열린 서비스 조합에서 대상의 OS 와 역할(예: 도메인 컨트롤러)을 추정할 수 있음.

```
kali@kali:~$ nmap -sT 192.168.50.149
Starting Nmap 7.92 ( https://nmap.org ) at 2022-03-09 06:44 EST
Nmap scan report for 192.168.50.149
Host is up (0.11s latency).
Not shown: 989 closed tcp ports (conn-refused)
PORT     STATE SERVICE
53/tcp   open  domain
88/tcp   open  kerberos-sec
135/tcp  open  msrpc
139/tcp  open  netbios-ssn
389/tcp  open  ldap
445/tcp  open  microsoft-ds
```

*TCP connect 스캔 — sudo 없이 실행*

**UDP 스캔(`-sU`)** — 두 방식을 섞어 씀. 대부분의 포트는 앞서 본 ICMP port unreachable 방식으로(빈 패킷을 보내) 판정하고, SNMP 가 쓰는 161 처럼 흔한 포트에는 **프로토콜 특화 패킷**을 보내 그 포트에 붙은 애플리케이션의 응답을 끌어냄. raw socket 이 필요해 `sudo` 로 돌림.

```
kali@kali:~$ sudo nmap -sU 192.168.50.149
Starting Nmap 7.70 ( https://nmap.org ) at 2019-03-04 11:46 EST
Nmap scan report for 192.168.131.149
Host is up (0.11s latency).
Not shown: 977 closed udp ports (port-unreach)
PORT      STATE         SERVICE
123/udp   open          ntp
389/udp   open          ldap
...
Nmap done: 1 IP address (1 host up) scanned in 22.49 seconds
```

*TCP·UDP 동시 스캔*

**네트워크 스윕** — 호스트가 많거나 트래픽을 아껴야 하면 넓고 얕은 스캔으로 시작해 관심 대상만 좁혀 파고듦. `-sn` 으로 스윕할 때 Nmap 은 ICMP echo 요청만 보내는 것이 아니라 443/tcp 로 TCP SYN, 80/tcp 로 TCP ACK, 그리고 ICMP timestamp 요청까지 함께 보내 생존 여부를 확인함.

```
kali@kali:~$ nmap -sn 192.168.50.1-253
Starting Nmap 7.92 ( https://nmap.org ) at 2022-03-10 03:19 EST
Nmap scan report for 192.168.50.6
Host is up (0.12s latency).
Nmap scan report for 192.168.50.8
Host is up (0.12s latency).
...
Nmap done: 254 IP addresses (13 hosts up) scanned in 3.74 seconds
```

*-sn 으로 C 클래스 대역 ping 스윕*

*상위 20개 포트 스캔을 greppable 형식으로 저장*

*nmap-services — TCP 80 의 빈도*

**OS 핑거프린팅(`-O`)** — 돌아온 패킷을 뜯어 대상 OS 를 추정함. OS 마다 TCP/IP 스택 구현이 조금씩 달라(기본 TTL 값, TCP 윈도 크기 등) 그 미세한 차이가 지문이 되고, Nmap 이 알려진 목록과 대조함. 기본값은 지문이 아주 정확할 때만 결과를 표시하므로, 대략이라도 보려면 `--osscan-guess` 로 추정 결과 출력을 강제함.

```
kali@kali:~$ sudo nmap -O 192.168.50.14 --osscan-guess
```

*OS 핑거프린팅*

⚠️ 정확도가 항상 100% 는 아님 — 중간의 방화벽·프록시가 패킷 헤더를 고쳐 쓰면 어긋남.

**배너 그래빙·서비스 열거** — OS 를 파악했으면 `-A` 로 특정 포트의 서비스 배너를 확인함. `-A` 는 OS·서비스 열거 스크립트도 함께 돌리므로, 순수한 서비스 스캔만 원하면 `-sV` 만 줌. 배너 그래빙은 트래픽 양과 스캔 속도에 큰 영향을 주므로 어떤 옵션이 스캔에 어떤 영향을 주는지 늘 의식할 것. ⚠️ 배너는 관리자가 고칠 수 있고, 공격자를 속이려고 일부러 가짜 서비스 이름을 넣어 두기도 함.

```
kali@kali:~$ nmap -sT -A 192.168.50.14
Nmap scan report for 192.168.50.14
Host is up (0.12s latency).
Not shown: 996 closed tcp ports (conn-refused)
PORT    STATE SERVICE       VERSION
21/tcp  open  ftp?
```

*스크립트 설명 확인*

**Windows 에서의 포트 스캔** — 인터넷이 없는 Windows 노트북에서 초기 네트워크 열거를 해야 하면 Windows 판 Nmap 같은 도구를 설치할 수 없어 'living off the land' 로 감. 내장 PowerShell 함수가 도움이 됨. `Test-NetConnection` 은 대상 IP 가 ICMP 에 응답하는지, 그리고 지정한 TCP 포트가 열려 있는지 확인함.

```
PS C:\Users\student> Test-NetConnection -Port 445 192.168.50.151
ComputerName     : 192.168.50.151
RemoteAddress    : 192.168.50.151
RemotePort       : 445
InterfaceAlias   : Ethernet0
SourceAddress    : 192.168.50.152
TcpTestSucceeded : True
```

*PowerShell 로 도메인 컨트롤러의 SMB 445 확인*

`TcpTestSucceeded` 값이 True 면 열린 것임. 1024번까지 훑으려면 `TcpClient` 소켓 객체를 직접 만드는 편이 나음 — `Test-NetConnection` 은 이 목적에 필요 없는 트래픽까지 보내기 때문임.

```
PS C:\Users\student> 1..1024 | % {echo ((New-Object
Net.Sockets.TcpClient).Connect("192.168.50.151", $_)) "TCP port $_ is open"} 2>$null
TCP port 88 is open
...
```

*PowerShell 한 줄로 포트 스캔 자동화*

동작 — 1부터 1024까지의 정수를 반복문에 흘려 `$_` 에 담고, `Net.Sockets.TcpClient` 객체를 만들어 그 포트로 TCP 연결을 시도하며, 성공하면 열린 포트를 알리는 로그를 출력함. 여기서 더 확장하면 전통적인 Nmap 기능에 가깝게 만들 수 있음.
