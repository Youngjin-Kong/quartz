# 17.1.3 눈에 띄는 곳에 숨겨진 것

> **Hidden in Plain View** · PEN-200 §17.1.3

앞 절의 정보로 CLIENTWK220 의 사용자들이 패스워드 관리자를 쓴다고 추정할 수 있지만, 비밀번호와 민감 정보를 다루는 사용자의 게으름을 결코 과소평가하지 말 것 — 예전에 키보드 밑에 붙이던 포스트잇이 지금은 바탕화면의 텍스트 파일임. 사용자 홈 디렉터리나 공개 접근이 가능한 폴더를 훑는 것만으로도 회의록·설정 파일·온보딩 문서에서 상승 벡터가 될 민감 정보가 나올 수 있음. 상황 파악에서 얻은 정보가 **어디를 뒤질지에 관한 근거 있는 추측**을 만들어줌 — 여기서는 KeePass 와 XAMPP 가 설치돼 있으므로 패스워드 관리자 데이터베이스와 이 애플리케이션들의 설정 파일이 표적임.

PowerShell 의 `Get-ChildItem` 에 `-Path C:\` 와 `-Include *.kdbx` 를 주어 시스템 전체에서 패스워드 관리자 데이터베이스를 찾음.

```
PS C:\Users\dave> Get-ChildItem -Path C:\ -Include *.kdbx -File -Recurse -ErrorAction
SilentlyContinue
Get-ChildItem -Path C:\ -Include *.kdbx -File -Recurse -ErrorAction SilentlyContinue
```

*asdf.txt 의 내용*

앞의 `type` 대신 `cat` 을 썼는데, 둘 다 PowerShell 의 `Get-Content` Cmdlet 별칭이라 바꿔 써도 됨. 파일은 회의록이고, 웹 애플리케이션이 로컬 사용자 자격 증명으로 로그인하며 테스트용으로 steve 의 비밀번호 `securityIsNotAnOption++++++` 를 쓸 수 있다고 적혀 있음. 상황 파악 단계에서 steve 라는 사용자가 존재함을 이미 확인해둔 것이 여기서 값을 함.

비밀번호를 활용하기 전에 steve 의 그룹 소속을 `net user` 에 사용자명을 붙여 확인함.

```
PS C:\Users\dave> net user steve
net user steve
User name                    steve
...
Last logon                   6/16/2022 1:03:52 PM
Logon hours allowed          All
Local Group Memberships      *helpdesk             *Remote Desktop Users
                             *Remote Management Use*Users
...
```
*steve 의 로컬 그룹 소속*

steve 는 Administrators 소속은 아니지만 Remote Desktop Users 소속이므로 RDP 로 접속할 수 있음.

새 사용자로 접근하면 파일에 대한 권한이 달라지므로 **민감 정보 탐색을 처음부터 다시 시작함.** 이는 이 사례에만 해당하는 것이 아니라 침투 테스트 거의 모든 영역에 해당하는 순환적 성질임 — 새로 얻은 정보와 접근을 계속 되먹여, 이전에는 손댈 수 없었거나 새로 드러난 공격 벡터를 따라가는 사고방식이 필요함. dave 로는 권한 오류가 났던 my.ini 부터 다시 확인함.

```
PS C:\Users\steve> type C:\xampp\mysql\bin\my.ini
# Example MySQL config file for small systems.
...
# The following options will be passed to all MySQL clients
# backupadmin Windows password for backup job
[client]
password       = admin123admin123!
port=3306
socket="C:/xampp/mysql/mysql.sock"
```
*steve 권한으로 읽은 my.ini*

수동으로 설정된 비밀번호 `admin123admin123!` 가 있고, 주석에 이것이 backupadmin 의 Windows 비밀번호이기도 하다고 적혀 있음. RDP·WinRM 같은 서비스로 이 사용자로 접속할 수 있는지 그룹 소속을 확인함.

```
PS C:\Users\steve> net user backupadmin
User name                    BackupAdmin
...
Local Group Memberships      *Administrators       *BackupUsers
                             *Users
Global Group memberships     *None
The command completed successfully.
```
*backupadmin 의 로컬 그룹 소속*

backupadmin 은 Administrators·BackupUsers 소속이지만 Remote Desktop Users 나 Remote Management Users 가 아니어서 RDP·WinRM 으로는 붙을 수 없음 — 다른 접근·실행 수단이 필요함. GUI 접근이 있으므로 다른 사용자로 프로그램을 실행하는 `Runas` 를 쓸 수 있음. Runas 는 대상 사용자가 시스템에 로그온할 수 있기만 하면 로컬·도메인 계정 모두에 쓸 수 있으나, **GUI 가 없으면 쓸 수 없음** — 바인드 셸이나 WinRM 처럼 흔히 쓰는 셸에서는 비밀번호 프롬프트가 입력을 받지 않기 때문임. 조건이 맞을 때 쓸 수 있는 다른 수단 — 해당 그룹 구성원이면 WinRM·RDP, 대상 사용자가 「Log on as a batch job」 접근 권한을 가지면 예약 작업으로 원하는 프로그램 실행, 대상 사용자의 세션이 살아 있으면 Sysinternals 의 PsExec.

`/user:` 인자에 사용자명, 그 뒤에 실행할 명령을 주고, 뜨는 프롬프트에 앞서 찾은 비밀번호를 입력함.

```
PS C:\Users\steve> runas /user:backupadmin cmd
Enter the password for backupadmin:
Attempting to start cmd as user "CLIENTWK220\backupadmin" ...
PS C:\Users\steve>
```
*Runas 로 backupadmin 권한의 cmd 실행*

새 명령 창이 뜨고 제목에 running as CLIENTWK220 이 표시됨. `whoami` 로 실제 backupadmin 인지 확인함.

*backupadmin 컨텍스트에서 실행 중인 cmd*

익스플로잇을 전혀 쓰지 않고 민감 정보만으로 dave → steve → 권한 사용자 backupadmin 까지 이동함. 「패스워드 공격」 모듈에서 배운 대로, 설정 파일이나 텍스트 파일에서 비밀번호를 찾으면 비밀번호 재사용이 흔하므로 **가능한 모든 사용자와 서비스에 대해 시도해볼 것.**
