# 22.4.2 BloodHound 데이터 분석

> **Analysing Data using BloodHound** · PEN-200 §22.4.2

분석은 Kali 에서 함. Windows 에도 의존성과 함께 설치할 수 있음.

BloodHound 를 쓰려면 Neo4j 서비스가 먼저 떠 있어야 함. APT 로 BloodHound 를 설치하면 Neo4j 도 함께 깔림. Neo4j 는 오픈소스 그래프 데이터베이스(NoSQL) 로 단순한 행·열 대신 노드·엣지·속성을 만듦 — **수집 데이터를 시각적으로 표현할 수 있는 근거가 이 저장 구조**임.

```
kali@kali:~$ sudo neo4j start
Directories in use:
home:         /usr/share/neo4j
config:       /usr/share/neo4j/conf
logs:         /usr/share/neo4j/logs
plugins:      /usr/share/neo4j/plugins
import:       /usr/share/neo4j/import
data:         /usr/share/neo4j/data
certificates: /usr/share/neo4j/certificates
licenses:     /usr/share/neo4j/licenses
run:          /usr/share/neo4j/run
Starting Neo4j.
Started neo4j (pid:334819). It is available at http://localhost:7474
There may be a short delay until the server is ready.
```

웹 인터페이스는 `http://localhost:7474` 이고 기본 자격 증명은 사용자명·비밀번호 모두 `neo4j` 임. 첫 로그인 뒤 비밀번호 변경을 요구함. 바꾼 비밀번호는 뒤에서 데이터베이스에 인증할 때도 쓰므로 기억할 것. 직접 질의를 넣을 수도 있으나 데이터를 아직 넣지 않았으므로 할 것이 없고, 질의는 BloodHound 에 맡기는 편이 나음.

```
kali@kali:~$ bloodhound
```

BloodHound 가 뜨면 Neo4j 로그인 창이 나옴. 첫 열의 초록 체크는 Neo4j 가 구동 중임을 자동 감지했다는 표시임. 사용자명 `neo4j` 와 앞서 바꾼 비밀번호로 로그인함.

데이터를 넣으려면 Windows 쪽 zip 을 Kali 로 옮긴 뒤 우측의 `Upload Data` 를 쓰거나 창에 끌어다 놓으면 됨. 진행 막대로 업로드 상태가 보임.

적재량은 좌상단 햄버거 메뉴의 `Database Info` 에서 확인함. 규모가 큰 환경은 갱신에 시간이 걸리므로 `Refresh Database Stats` 로 최신 상태를 부름. 예시 환경에서는 세션 5개(앞서 손으로 쓴 `NetSessionEnum`·PsLoggedOn 계열 기법으로 수집된 것), 사용자 10명, 그룹 57개와 다량의 ACL 이 잡힘.

실제로 쓸 것은 `Analysis` 버튼임. 누르면 사전 정의된 분석 질의 목록이 나옴.

![[PEN200-Fig-301.png]]

*`Analysis` 탭의 사전 정의 질의 목록 — 목적별로 묶여 있음*

시작은 `Domain Information` 의 `Find all Domain Admins` 로 함.

![[PEN200-Fig-302.png]]

*`Find all Domain Admins` 결과 — 원이 노드, 노드를 잇는 선이 엣지*

동그란 아이콘이 노드이고 끌어서 옮길 수 있음. 노드 정보는 마우스를 올리거나 Ctrl 로 토글해 봄. 항상 보이게 하려면 우측 `Settings`(톱니 두 개) 에서 `Node Label Display` 를 `Always Display` 로 바꿈. 노드 사이의 선이 엣지이고 관계를 나타냄 — 여기서는 사용자가 해당 그룹의 구성원임을 뜻하며, 이 도메인의 Domain Admins 는 jeffadmin 과 administrator 임.

BloodHound 의 핵심은 `Analysis` 탭의 `Shortest Paths` 임. **특정 컴퓨터·사용자·그룹 장악이라는 목표까지 가는 최단 경로를 자동으로 찾아주는 것**이 이 도구의 값임. `Find Shortest Paths to Domain Admins` 는 인자가 필요 없고 전체 조망을 줌.

![[PEN200-Fig-305.png]]

*`Find Shortest Paths to Domain Admins` — 수동 열거에서 놓친 연결이 드러남*

여기서 앞선 열거가 놓친 것이 나옴. stephanie 와 CLIENT74 를 잇는 선에 마우스를 올리면 `AdminTo` 가 뜸 — stephanie 가 CLIENT74 에서 관리자 권한을 가진다는 뜻임. 선을 우클릭해 `? Help` 를 열면 더 나옴. `Abuse` 탭은 그 경로로 실제 어떤 공격이 가능한지, `Opsec` 탭은 탐지 관점에서 무엇을 조심할지, 그리고 참고 자료가 붙음.

같은 그래프에서 jeffadmin 도 CLIENT74 에 연결돼 있음. **그 머신에 jeffadmin 의 자격 증명이 캐시돼 있을 수 있다는 뜻**이고, 훔쳐 로그인하면 그의 Domain Admins 소속을 타고 도메인 관리자가 됨.

이 인과가 두 번째 질의로 이어짐 — `Shortest Paths to Domain Admins from Owned Principals`. 아무 설정 없이 돌리면 `NO DATA RETURNED FROM QUERY` 만 나옴. Owned Principals 는 **현재 통제하고 있는 객체**를 가리키고, 그것을 먼저 알려줘야 하기 때문임. 좌상단 검색으로 객체를 찾아 우클릭한 뒤 `Mark User as Owned`(컴퓨터면 `Mark Computer as Owned`) 를 고름. 표시된 노드에는 해골 아이콘이 붙음. 검색 결과 아이콘을 클릭하면 `Node Info` 에 그 객체 상세가 들어감.

확실히 통제하는 것은 stephanie 사용자, 그리고 로그인 중인 CLIENT75 임. CLIENT75 는 관리자 권한이 없어 나중에 권한 상승이 필요할 수 있으나 통제하는 것으로 침. 접근 가능한 객체는 전부 owned 로 표시할 것 — 특정 객체 소유 여부에 걸린 짧은 경로가 있을 수 있어 표시할수록 보이는 벡터가 늘어남. 아직 접근하지 못한 객체를 「만약 이걸 잡으면」 식으로 표시해 보는 것도 평가에서는 유용함.

![[PEN200-Fig-308-2.png]]

*owned 지정 후의 최단 경로 — 원문 그림은 경로가 보이게 노드를 재배치한 것임*

왼쪽부터 읽음 — CLIENT75 에 stephanie 세션이 있고, stephanie 는 CLIENT74 에 접속할 수 있으며, CLIENT74 에는 jeffadmin 세션이 있고, jeffadmin 은 Domain Admins 소속임. 즉 CLIENT74 에서 jeffadmin 을 사칭하거나 자격 증명을 탈취하면 도메인 관리자가 됨.

이 모듈이 다루는 것은 최단 경로 위주이며 나머지 사전 정의 질의는 랩에서 직접 만져볼 것. 수천 명 규모의 실제 환경에서는 수동 열거로 모은 정보를 소화하기 어려워 이 시각화의 값이 커짐. 다만 SharpHound 의 질의는 네트워크에 소음을 만들어 보안 분석가에게 걸릴 공산이 크므로, 상황이 허락할 때 쓸 것.
