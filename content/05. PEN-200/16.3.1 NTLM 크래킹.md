# 16.3.1 NTLM 크래킹

> **Cracking NTLM** · PEN-200 §16.3.1

Windows 는 사용자 패스워드 해시를 SAM(Security Account Manager) 데이터베이스 파일에 저장하고 로컬·원격 사용자 인증에 씀. 오프라인 SAM 공격을 늦추려고 NT 4.0 SP3 부터 SYSKEY 로 SAM 파일을 부분 암호화함.

저장 형식은 LM 과 NTLM 둘임. **LM 은 DES 기반이라 구조적으로 약함** — 대소문자를 구분하지 않고 14자를 못 넘으며, 7자를 넘으면 두 토막으로 쪼개 각각 해시함(긴 패스워드가 짧은 두 개로 전락함). Vista·Server 2008 부터 기본 비활성임. NTLM 은 이 약점들을 걷어냄 — 대소문자를 구분하고 쪼개지도 않음.

**그러나 SAM 의 NTLM 해시에는 salt 가 없음.** salt 는 해시 전에 패스워드에 덧붙이는 무작위 비트로, 미리 계산해 둔 해시 표를 조회해 평문을 역추적하는 공격을 막는 장치임. 그 표를 레인보우 테이블, 그 공격을 레인보우 테이블 공격이라 부름. salt 가 없다는 것은 같은 패스워드가 어디서든 같은 해시가 된다는 뜻이고, 이 성질이 다음 절의 pass-the-hash 를 성립시킴. (교재는 정확한 명칭인 NTHash 대신 업계 관용인 「NTLM 해시」를 씀)

**SAM 파일을 그냥 복사할 수는 없음.** `C:\Windows\system32\config\sam` 은 OS 가 도는 동안 커널이 배타적 잠금을 걸어 복사·이름변경·이동이 전부 막힘. Mimikatz 가 이 제약을 우회해 줌.

Mimikatz 는 Windows 의 여러 출처에서 평문 패스워드와 해시를 뽑아 pass-the-hash 같은 후속 공격으로 이어 줌. 그중 `sekurlsa` 모듈은 LSASS(Local Security Authority Subsystem) 프로세스 메모리에서 해시를 꺼냄 — LSASS 가 사용자 인증·패스워드 변경·액세스 토큰 생성을 담당하면서 **NTLM 해시와 자격 증명을 캐시**하기 때문임.

**권한 요건이 걸림.** LSASS 는 SYSTEM 권한으로 도는, Administrator 급 프로세스보다 강한 프로세스임. 따라서 Mimikatz 를 Administrator 이상으로 실행하고 **SeDebugPrivilege** 를 켠 상태여야 추출이 됨 — 이 권한이 자기 소유가 아닌 남의 프로세스까지 디버그할 수 있게 해 주는 것임. PsExec 이나 Mimikatz 내장 토큰 상승 기능으로 SYSTEM 계정까지 올라가는 길도 있는데, 토큰 상승은 **SeImpersonatePrivilege** 를 요구하고 이건 로컬 관리자면 기본으로 가짐.

실습은 MARKETINGWK01(192.168.50.210)에 `offsec`/`lab` 로 RDP 접속해 시작함. `Get-LocalUser` 로 로컬 계정을 열거하면 `nelly` 가 나오고, 목표는 이 계정의 NTLM 해시를 꺼내 평문을 얻는 것임. 자격 증명은 로그온할 때만 남는 게 아니라 **서비스를 사용자 계정으로 돌릴 때도** 저장되므로 뒤질 값이 있음.

`offsec` 과 `nelly` 두 개의 NTLM 해시가 나옴. `offsec` 은 평문(`lab`)을 이미 아니 건너뛰고 `nelly` 의 해시만 Kali 의 `nelly.hash` 로 옮김. **Mimikatz 출력이 이미 Hashcat 이 받는 형식**이라 이 절에는 별도 변환 단계가 없음.

```

```
