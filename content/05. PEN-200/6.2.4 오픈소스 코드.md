# 6.2.4 오픈소스 코드

> **Open-Source Code** · PEN-200 §6.2.4

수동 수집에 쓸 수 있는 온라인 자원에는 오픈소스 프로젝트와 코드 저장소가 있음 — GitHub, GitHub Gist, GitLab, SourceForge.

온라인에 올라간 코드는 조직이 쓰는 프로그래밍 언어와 프레임워크를 엿보게 해 줌. 드물게는 개발자가 민감 데이터와 자격 증명을 공개 저장소에 실수로 커밋한 경우도 있음. 이는 개발자를 탓할 일이 아니라 대규모 코드베이스를 만들고 유지하는 일 자체가 복잡하기 때문임 — 개선을 향한 관점으로 다룰 것.

일부 플랫폼의 검색은 앞에서 본 Google 검색 연산자를 지원함. GitHub 검색이 특히 유연함. 사용자·조직 단위 저장소 검색은 가능하지만 **전체 공개 저장소를 가로질러 검색하려면 계정이 필요**함(개인·조직 모두 무료). 로그인 후 우측 상단 검색창에 키워드를 넣어 검색함.

`path:users` 로 파일명에 「users」가 든 파일을 찾는 식으로 좁힘. MegaCorp One 저장소에서는 `xampp.users` 파일 하나가 나옴 — XAMPP 가 웹 애플리케이션 개발 환경이라는 점에서 이미 흥미로운 단서임.

![[PEN200-Fig-027.png]]

*`xampp.users` 파일 내용 — 사용자명과 비밀번호 해시가 담겨 있어 능동 공격 단계에서 쓸 수 있음*

이런 수동 방식은 작은 저장소에서 잘 통함. 큰 저장소에서는 Gitrob·Gitleaks 같은 도구로 검색을 자동화함. 대부분 해당 코드 호스팅 제공자의 API 접근 토큰을 요구함.

![[PEN200-Fig-028.png]]

*Gitleaks 가 파일에서 AWS 액세스 키 ID 를 찾아낸 출력 예*

이런 자격 증명을 얻으면 같은 AWS 계정에 제한 없이 접근할 수 있고, 그 자격으로 관리되는 클라우드 서비스 전체의 침해로 이어질 수 있음.

소스 코드에서 비밀값을 찾는 도구들은 대체로 정규표현식이나 **엔트로피 기반 탐지**에 의존함. 엔트로피 기반 탐지는 무작위로 생성된 문자열을 찾는 방식으로, 문자와 숫자가 길게 뒤섞인 문자열이면 비밀번호일 가능성이 높다고 보는 발상임.

⚠️ 어떤 방식이든 완벽한 도구는 없음 — 사람이 직접 훑어봐야 찾을 것을 도구는 놓침.
