# 19.3 SSH 기반 터널링

> **SSH Tunneling** · PEN-200 §19.3

터널링(tunneling)은 한 종류의 데이터 스트림을 다른 스트림 안에 감싸 네트워크를 건너보내는 것임. 이것을 목적으로 설계된 프로토콜을 터널링 프로토콜이라 하며 SSH 가 그중 하나임.

SSH 는 원래 관리자가 서버에 **암호화된 연결로** 원격 로그인하기 위해 만들어짐. 이전의 rsh·rlogin·Telnet 도 같은 원격 관리를 제공했으나 평문이었음. SSH 연결에서는 셸 명령·비밀번호·데이터가 전부 암호화 터널을 타고 오감.

핵심은 SSH 가 **본질적으로 터널링 프로토콜**이라는 것임 — 사실상 어떤 종류의 데이터든 SSH 연결로 통과시킬 수 있고, 그래서 터널링 기능이 대부분의 SSH 도구에 이미 내장돼 있음. 대상에 별도 도구를 심을 필요가 없다는 뜻임.

공격자 관점의 이점은 **정상 트래픽에 섞인다**는 것임. 관리자가 원격 관리와 제약 많은 환경의 포트 포워딩에 SSH 를 일상적으로 쓰므로 Linux 호스트에는 클라이언트가, 때로는 서버까지 이미 있음. Windows 에도 OpenSSH 클라이언트가 깔려 있는 경우가 늘고 있음. 모니터링이 촘촘하지 않은 환경에서 SSH 트래픽은 평범한 관리 트래픽과 구분되지 않고, 암호화돼 있어 내용도 쉽게 들여다볼 수 없음.

공식 문서 대부분은 이 기능을 **SSH 포트 포워딩(port forwarding)** 이라 부름. 구현마다 제공 범위가 조금씩 다르며, 이 학습 단위는 OpenSSH 가 제공하는 일반적인 포워딩 유형 — 로컬·동적·원격·원격 동적 — 을 모두 다루고 마지막에 sshuttle 의 장단점을 봄.
