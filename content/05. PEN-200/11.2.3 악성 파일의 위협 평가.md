# 11.2.3 악성 파일의 위협 평가

> **Assess Threats from Malicious Files** · PEN-200 §11.2.3

클라이언트 측 코드 실행이 매크로만의 일은 아님. EXE 는 실행 파일이지만 애초에 **수신함까지 도달할 확률이 낮고**, 도달해도 대부분의 사용자가 위험을 알고 있음. 그래서 공격자는 SCR·HTA·JScript 같은 다른 확장자로 옮겨감.

또 하나의 방향은 **주변부 Office 문서 형식** — Word·PowerPoint·Excel 본류에 걸린 보호를 비껴가는 경로임.

- **CVE-2017-11882** — 2018년까지 Office 에 번들되던 수식 편집기(Equation Editor)의 메모리 손상 취약점. 2023년까지도 Office 미업데이트 조직을 겨냥한 실제 악용이 보안 업체에 보고됨
- **CVE-2023-21716** — Microsoft Word 의 RTF 파서 취약점. 공개 PoC 존재

이렇게 **매크로 없이도 코드 실행**이 가능하지만, 일반적인 기업 패치 주기 때문에 활용 폭은 제한적임.

파일 파싱 취약점은 Office 만의 문제가 아님. PDF 뷰어도 같고, Adobe Acrobat Reader 는 공격자·취약점 연구자 양쪽의 단골 표적임 — **CVE-2023-21608** 은 use-after-free 취약점으로 임의 코드 실행이 가능한 공개 PoC 가 여럿 있음.

정교한 표적 공격이라면 **대상이 실제로 쓰는 소프트웨어**를 먼저 알아내고 거기 걸리는 취약점을 찾는 편이 나음. 업종마다 쓰는 제품군이 다르므로(문서 뷰어, 메일 클라이언트, 브라우저 등) 채용 공고, Glassdoor·LinkedIn, 회사 웹사이트, G2 Crowd·Capterra 같은 소프트웨어 리뷰 사이트, 업계 포럼·블로그, 기술 뉴스에서 사용 기술을 수집함.

한 단계 더 나아간 공격자는 대상이 쓰는 제품의 **0-day 를 직접 찾음.** 스피어 피싱에서 흔한 접근이지만 비용과 시간이 크고, 공개·패치되면 수명이 짧다는 한계가 있음. 그럼에도 **Microsoft 의 매크로 차단 이후 이쪽 비중이 커지는 추세**임. 최근에는 보안 패치를 역분석해 패치가 배포되기 전의 취약점을 찾아내고, 그 짧은 창을 노려 공격하는 방식도 쓰임.
