# 8.3.2 HTTP 응답 헤더와 사이트맵 검사

> **Inspecting HTTP Response Headers and Sitemaps** · PEN-200 §8.3.2

서버 응답 자체도 정보원임. 쓰는 도구는 두 부류 — 클라이언트와 웹 서버 사이의 요청·응답을 가로채는 **프록시**(Burp Suite 등), 그리고 **브라우저 내장 Network 도구**.

Network 도구는 Firefox 의 Web Developer 메뉴에서 띄움. ⚠️ **실행된 이후의 트래픽만** 보여주므로 페이지를 새로고침해야 내용이 참.

요청을 클릭하면 상세가 열리고, 여기서 볼 것은 **응답 헤더**(HTTP 응답에 실려 오는 헤더)임.

![[PEN200-Fig-110.png]]

*Network 도구의 응답 헤더 — `Server` 헤더가 웹 서버 소프트웨어 이름을, 기본 설정에서는 버전까지 드러냄*

헤더를 웹 서버만 만드는 것은 아님 — 웹 프록시는 원 클라이언트 IP 를 서버에 알리려 `X-Forwarded-For` 를 능동적으로 끼워 넣음. 과거에는 `X-` 로 시작하는 헤더를 비표준 헤더라 불렀으나, RFC6648 이 더 명확한 명명 규칙을 위해 `X-` 사용을 폐기 예정으로 지정함.

응답 헤더의 **이름이나 값이 기술 스택을 추가로 드러냄.** 비표준 헤더의 예로 `X-Powered-By`, `x-amz-cf-id`, `X-Aspnet-Version` 이 있고, 이름을 조사하면 더 나옴 — `x-amz-cf-id` 는 그 애플리케이션이 Amazon CloudFront 를 쓴다는 표시임.

**사이트맵**도 빠뜨리면 안 되는 요소임. 웹 애플리케이션은 검색 엔진 봇의 크롤링·색인을 돕기 위해 사이트맵 파일을 두는데, 여기에는 **크롤하지 말라는 지시**도 함께 들어감 — 그 대상이 대개 민감 페이지나 관리 콘솔이라, 정확히 공격자가 찾는 것임. 포함 지시는 sitemaps 프로토콜, 제외 지시는 `robots.txt` 가 담당함.

```
kali@kali:~$ curl https://www.google.com/robots.txt
User-agent: *
Disallow: /search
Allow: /search/about
Allow: /search/static
Allow: /search/howsearchworks
Disallow: /sdch
Disallow: /groups
Disallow: /index.html?
Disallow: /?
Allow: /?hl=
...
```

*`curl` 로 받은 `robots.txt` — `Allow`/`Disallow` 지시*

`Allow`·`Disallow` 는 「예의 바른(polite)」 크롤러가 접근해도 되는·안 되는 경로를 알리는 지시임. 대개는 흥미롭지 않고 유효하지 않은 항목도 섞여 있으나, **사이트 구조나 아직 안 밟은 영역의 단서**가 실릴 수 있어 넘기지 말 것.
