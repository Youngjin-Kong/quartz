# 8.4.1 Stored XSS와 Reflected XSS 이론

> **Stored vs Reflected XSS Theory** · PEN-200 §8.4.1

XSS 는 크게 **Stored** 와 **Reflected** 둘로 나뉨.

**Stored XSS**(Persistent XSS)는 페이로드가 DB 에 저장되거나 서버에 캐시되는 경우임. 애플리케이션이 그 값을 꺼내 취약 페이지 방문자 모두에게 표시하므로 **하나로 사이트 전체 사용자를 공격**할 수 있음. 포럼 댓글란, 상품 후기처럼 사용자 내용이 저장됐다 나중에 표시되는 곳에 자주 있음.

**Reflected XSS**는 페이로드를 조작된 요청·링크에 실어 보내고 애플리케이션이 그 값을 페이지 내용에 얹는 형태임. 대상은 **그 요청을 보내거나 링크를 방문한 한 명뿐**임. 검색 필드와 결과, 사용자 입력이 섞인 오류 메시지에 자주 생김.

두 유형 모두 클라이언트(브라우저) 측·서버 측 어느 쪽으로도, 또 **DOM 기반**으로도 나타남. 브라우저는 HTML 을 파싱해 내부 DOM 표현을 만드는데, 사용자가 제어하는 값으로 그 DOM 이 변형될 때 DOM 기반 XSS 가 성립함. 이것도 stored·reflected 양쪽이 가능하고, 핵심은 **브라우저가 페이지 내용을 파싱하는 시점에 삽입된 JavaScript 가 실행된다**는 점임.

전달·실행 경로와 무관하게 주입된 스크립트는 **페이지를 방문한 사용자의 컨텍스트로** 동작함 — 실행 주체가 애플리케이션이 아니라 사용자 브라우저임. 그럼에도 영향은 큼 — 세션 하이재킹, 악성 페이지로의 강제 리다이렉션, 그 사용자 권한의 로컬 애플리케이션 실행, 웹 애플리케이션 트로이목마화.
