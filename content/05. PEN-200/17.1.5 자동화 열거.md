# 17.1.5 자동화 열거

> **Automated Enumeration** · PEN-200 §17.1.5

앞 세 절의 수동 열거는 권한 상승 경로 둘을 찾아냈지만 시간이 많이 듦. 실제 평가에는 기한이 있어 수동 열거만으로는 감당이 안 되므로, 상황 파악과 민감정보 후보를 한 번에 뽑아주는 자동 도구를 병행함. 대표가 `winPEAS`.

자동 도구는 AV 에 차단될 수 있음. 그 경우 "Antivirus Evasion" 모듈의 우회 기법을 적용하거나, `Seatbelt`·`JAWS` 같은 다른 도구로 바꾸거나, 수동 열거로 돌아감.

Kali 에 `peass` 패키지를 설치한 뒤 64비트 바이너리를 홈으로 복사하고 웹 서버로 띄움.

```
kali@kali:~$ cp /usr/share/peass/winpeas/winPEASx64.exe .
kali@kali:~$ python3 -m http.server 80
Serving HTTP on 0.0.0.0 port 80 (http://0.0.0.0:80/) ...
```

대상(`dave` 로 도는 4444 바인드 셸)에서 PowerShell 을 띄우고 `iwr` 로 내려받음.


⚠️ 이 블록과 아래 winPEAS 출력 블록들은 교재 PDF 자체의 조판 문제가 있음 — hacktricks URL 이 지면 폭에 맞춰 두 줄로 접혀 있고, 섹션 제목의 들여쓰기는 PDF 원문에서 공백이 아니라 NUL 바이트임(여기서는 볼트 파일이 깨지지 않도록 같은 개수의 공백으로 바꿔 실었음). 그대로 복사해 쓰면 실패함.

여기서 winPEAS 는 대상을 **Windows 10 Pro** 로 보고함. 앞 절에서 확인한 실제 OS 는 Windows 11 이므로 **도구 판정을 그대로 믿으면 안 된다**는 첫 번째 사례임.

이어지는 보호 설정·PowerShell·NTLM 항목 중 transcript 파일 목록을 봄.

```
...
            PS default transcripts history
  Read the PS history inside these files (if any)
...
```

목록이 **비어 있음**. 그러나 앞 절에서 `C:\Users\Public\` 아래 transcript 를 직접 읽었으므로, 이것은 도구가 놓친 것임 — 수동 열거를 병행하지 않았으면 그대로 잃었을 발견임.

사용자 항목은 반대로 자동 도구가 강한 영역임. 계정과 소속 그룹이 한눈에 정리돼 나와, `Remote Desktop Users`·`Remote Management Users` 같은 그룹의 멤버를 빠르게 골라낼 수 있음.

그 목록에도 앞 절에서 찾은 dave 바탕화면의 `asdf.txt` 가 **없음** — 두 번째 누락임.

정리하면 winPEAS 는 이 대상에서 OS 를 오판했고 회의 메모·PowerShell 히스토리·transcript 를 전부 놓쳤음. 그럼에도 자동 도구를 쓰지 말자는 결론이 아니라 **한계를 알고 쓰자**는 결론임 — 랩과 달리 실무 대상은 파일이 수백·수천 개라, 자동 도구 없이는 파일을 훑는 데만 기한이 다 감. 자동 열거로 넓게 깔고 수동 열거로 빈틈을 메우는 조합이 답임.
