# 19.2.3 Socat 포트 포워딩

> **Port Forwarding with Socat** · PEN-200 §19.2.3

포워드가 어떻게 돌아야 하는지는 정해짐 — CONFLUENCE01 이 WAN 인터페이스의 TCP 2345 를 열고, 거기로 받은 패킷 전부를 내부 서브넷 PGDATABASE01 의 TCP 5432 로 넘김. 구성되고 나면 **CONFLUENCE01 의 2345 에 붙는 것이 PGDATABASE01 의 5432 에 직접 붙는 것과 완전히 같아짐.**

CONFLUENCE01 열거 중 Socat 이 설치돼 있는 것을 확인함. Socat 은 범용 네트워킹 도구로 명령 한 줄이면 단순 포트 포워드가 섬. *NIX 에 기본 설치되는 편은 아니므로, 없으면 정적 링크된 바이너리를 내려받아 실행하는 방법이 있음.

인자를 뜯어보면 — `-ddd` 상세 출력, `TCP-LISTEN:2345` 수신 포트, `fork` 연결을 받으면 자식 프로세스로 갈라져 한 번의 연결 뒤 죽지 않게 하는 것, `TCP:10.4.50.215:5432` 전달 대상. 2345 를 고른 이유는 특권 포트 범위(0-1024) 밖이라 상승된 권한이 필요 없기 때문임.

```
confluence@confluence01:/opt/atlassian/confluence/bin$ socat -ddd TCP-LISTEN:2345,fork
TCP:10.4.50.215:5432
```

*Hashcat 으로 `database_admin`·`hr_admin`·`rdp_admin` 비밀번호 크랙*

내부망을 더 열거하면 PGDATABASE01 이 SSH 서버도 돌리고 있음. 얻은 자격 증명을 거기 시험하려고 포워드를 바꿈 — 2345 를 물고 있던 기존 Socat 프로세스를 먼저 죽이고, TCP 2222 에서 listen 해 PGDATABASE01 의 TCP 22 로 넘기는 것을 새로 세움.

```
confluence@confluence01:/opt/atlassian/confluence/bin$ socat TCP-LISTEN:2222,fork
TCP:10.4.50.215:22
</bin$ socat TCP-LISTEN:2222,fork TCP:10.4.50.215:22
```

*포워드된 2222 로 SSH — `database_admin` 자격 증명 재사용 확인*

Socat 만이 *NIX 포트 포워드 수단인 것은 아님.

- `rinetd` — 데몬으로 도는 방식이라 장기 구성에는 낫지만 임시 포워드용으로는 다루기 번거로움
- Netcat 과 FIFO 명명 파이프 파일을 조합하는 방법
- root 권한이 있으면 `iptables`. 다만 구체적 설정은 그 호스트에 이미 걸린 구성에 좌우되고, Linux 에서 패킷을 전달하려면 `/proc/sys/net/ipv4/conf/[interface]/forwarding` 에 "1" 을 써서 해당 인터페이스의 포워딩을 켜야 함(이미 허용돼 있지 않다면)
