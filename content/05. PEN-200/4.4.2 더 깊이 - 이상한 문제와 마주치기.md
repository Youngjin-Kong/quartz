# 4.4.2 더 깊이 - 이상한 문제와 마주치기

> **Going Deeper: Encountering a Strange Problem** · PEN-200 §4.4.2

여기서부터는 리눅스를 좀 아는 학습자를 겨냥한 예시임 — 기술적 단계를 전부 따라가지 못해도 됨.

출발점은 **`chmod` 자체도 그냥 파일이라는 사실**임. 위치가 `/usr/bin/` 으로 다를 뿐 다른 파일과 같은 권한 규칙을 따름. `chmod +x` 를 칠 수 있는 유일한 이유는 `chmod` 파일에 실행 권한이 설정돼 있기 때문임. 그렇다면 질문 하나 — **권한을 설정하는 도구인 `chmod` 를 실행할 권한이 없다면 어떻게 하나?**

실수로 이 권한을 지우기는 쉽지 않지만, 여기서는 이미 지워진 상태를 가정함. 예전에 통했던 해법을 그대로 써 보면 새로운 오류가 나옴.

```
kali@kali:~$ ./find_employee_names.py
zsh: permission denied: ./find_employee_names.py
kali@kali:~$ chmod +x find_employee_names.py
zsh: permission denied: chmod
```

*스크립트도 안 되고, 고치려던 `chmod` 도 거부됨*

`chmod` 를 `chmod` 에 적용해도 같은 벽에 부딪힘. 파일의 구체적 위치인 `/usr/bin/chmod` 를 명시해도 결과는 같음.

```
kali@kali:~$ chmod +x /usr/bin/chmod
zsh: permission denied: chmod
```

*경로를 명시해도 `chmod` 실행 자체가 거부됨*

아직 막다른 길은 아님.

> 관찰력 좋은 학습자라면 「왜 내 파이썬 스크립트에는 `./` 가 필요했는데 `chmod` 에는 필요 없나」를 물을 수 있음. 답은 `PATH` 환경 변수와 관련되며 이 모듈의 범위를 벗어남 — 별도 학습 대상임.

지금까지는 대체로 **실행해 보는 것**으로 권한을 확인했음. 앞에서 쓴 `ls -l` 로 직접 확인하는 편이 나음 — 뒤에 파일명을 붙이면 그 파일만 볼 수 있음(안 붙이면 현재 디렉터리 전체).

```
kali@kali:~$ ls -l find_employee_names.py
-rw-r--r-- 1 kali kali 206 Jun  7 12:31 find_employee_names.py
kali@kali:~$ ls -l /usr/bin/ls
-rwxr-xr-x 1 root root 147176 Sep 24  2020 /usr/bin/ls
```

*두 파일 비교 — 스크립트에는 `x` 가 없고 `ls` 에는 있음*

스크립트는 `x` 가 없어 실행 불가, `ls` 는 `x` 가 있어 실행 가능 — 관측이 설명과 맞아떨어짐.
