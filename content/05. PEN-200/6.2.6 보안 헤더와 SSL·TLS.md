# 6.2.6 보안 헤더와 SSL·TLS

> **Security Headers and SSL/TLS** · PEN-200 §6.2.6

웹사이트·도메인의 보안 태세를 알아보는 특화 사이트들이 있음. 수동과 능동의 경계를 흐리지만 **스캔을 시작하는 주체가 제3자**라는 점이 요점임.

**Security Headers** — HTTP 응답 헤더를 분석해 대상 사이트의 보안 태세를 기초 수준으로 평가하므로, 결과에서 조직의 코딩·보안 관행을 짐작할 수 있음. MegaCorp One 스캔에서는 `Content-Security-Policy`·`X-Frame-Options` 같은 방어용 헤더가 여럿 빠져 있었음.

헤더가 없다는 것 자체가 곧 취약점은 아님. 다만 웹 개발자나 서버 관리자가 서버 하드닝(server hardening)에 익숙하지 않다는 신호일 수 있음. 서버 하드닝은 설정으로 서버를 안전하게 만드는 과정임 — 불필요한 서비스 비활성화, 쓰지 않는 서비스·계정 제거, 기본 비밀번호 교체, 적절한 서버 헤더 설정 등. 모든 서버 설정을 속속들이 알 필요는 없고 개념과 찾아볼 지점만 알아도 접근 방향을 정할 수 있음.

**Qualys SSL Labs 의 SSL Server Test** — 서버의 SSL/TLS 설정을 현행 모범 사례와 대조하고 Poodle·Heartbleed 같은 취약점도 식별함.

![[PEN200-Fig-033.png]]

*SSL Server Test 결과 — 레거시 TLS 버전 지원이 드러남*

결과는 Security Headers 쪽보다 나아 보였으나 서버가 TLS 1.0·1.1 을 지원함이 드러남. 안전하지 않은 암호 스위트를 구현해 레거시로 간주되는 버전들이므로, 대상이 현행 SSL/TLS 하드닝 모범 사례를 따르지 않는다는 뜻임. `TLS_DHE_RSA_WITH_AES_256_CBC_SHA` 스위트도 AES CBC 모드와 SHA1 양쪽의 다중 취약점 때문에 수년 전부터 비활성화가 권고돼 왔음.

이런 발견으로 대상의 보안 관행 수준을 가늠할 수 있음.
