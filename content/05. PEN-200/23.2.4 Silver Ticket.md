# 23.2.4 Silver Ticket

> **Silver Tickets** · PEN-200 §23.2.4

앞 절이 서비스 티켓을 «받아서 깨는» 것이었다면 이번에는 서비스 티켓을 «직접 위조»함.

서비스 계정 컨텍스트로 도는 응용은 사용자의 권한을 서비스 티켓에 담긴 그룹 멤버십으로 판단함. 그런데 대부분의 환경에서 응용은 그 사용자·그룹 권한을 따로 «검증하지 않음» — 티켓이 서비스 계정과 도메인 컨트롤러만 안다고 «여겨지는» 해시로 암호화돼 있으니 무결성을 맹신하는 것임.

검증 장치가 아예 없는 것은 아님. PAC(Privileged Account Certificate) validation 은 SPN 응용과 도메인 컨트롤러 사이의 «선택적» 검증 절차로, 켜져 있으면 인증하는 사용자와 그 권한을 도메인 컨트롤러가 검증함. 다만 실제 서비스 응용이 PAC 검증을 하는 경우가 드물어서 이 공격이 성립함.

예를 들어 `iis_service` 계정 컨텍스트로 도는 IIS 서버라면, 그 계정의 비밀번호나 NTLM 해시를 손에 넣은 시점에 원하는 권한을 박아 넣은 서비스 티켓을 스스로 만들어 낼 수 있음. 이렇게 만든 티켓이 **silver ticket** 임. 같은 SPN 이 여러 서버에 쓰이고 있으면 그 전부에 통함.

위조에 필요한 값은 셋임 — ① SPN 계정의 패스워드 해시 ② 도메인 SID ③ 대상 SPN.

먼저 현재 사용자로는 표적 자원에 접근이 안 되는 것을 확인해 둠 — `iwr -UseDefaultCredentials http://web04` 은 현재 사용자 자격 증명으로 요청을 보내며, 이 시점에는 401 Unauthorized 가 돌아옴.

②는 `whoami /user` 로 얻음. SID 는 여러 조각으로 이루어져 있고 마지막 조각이 사용자별 RID 이므로, **도메인 SID 는 RID 를 뗀 앞부분**임. 도메인 사용자는 같은 도메인에 있으므로 위 Mimikatz 출력의 SPN 계정 SID 에서 뽑아도 결과는 같음.

```
PS C:\Users\jeff> whoami /user
USER INFORMATION
----------------
User Name SID
========= =============================================
corp\jeff S-1-5-21-1987370270-658905905-1781884369-1105
```

③은 이 예시에서 IIS 웹 페이지가 목표이므로 `HTTP/web04.corp.com:80` 임.

세 값이 모이면 Mimikatz 의 `kerberos::golden` 모듈로 위조함 — 이름은 golden 이지만 golden ticket 과 silver ticket 을 모두 이 모듈이 만듦. 인자는 도메인 SID(`/sid:`), 도메인 이름(`/domain:`), SPN 이 도는 대상 호스트(`/target:`), SPN 프로토콜(`/service:`), SPN 계정의 NTLM 해시(`/rc4:`), 그리고 위조 티켓을 현재 머신 메모리에 주입하는 `/ptt` 임. `/user:` 에는 **실재하는 도메인 사용자**를 넣되, 권한과 그룹은 어차피 우리가 정하므로 누구든 상관없음.

*위조 후 — 같은 명령이 jeffadmin 으로 통과해 200 OK 반환*

주목할 점은 **jeffadmin 의 평문 비밀번호도 해시도 없이** 그 사용자로 접근했다는 것임 — 필요했던 것은 SPN 계정의 해시뿐임.

그래서 이 기법은 침투의 후반부 도구임. SPN 계정·머신 계정의 해시를 얻으려면 대개 이미 상당한 권한이 필요하기 때문임. 반대로 해시만 확보하면 그 SPN 에 대해 «임의의 사용자·임의의 권한»으로 티켓을 찍어낼 수 있음.

완화책도 알아둘 것 — Microsoft 가 PAC 구조를 확장하는 보안 패치를 냈고, 적용되면 도메인 컨트롤러가 `PAC_REQUESTOR` 필드를 검증함. 클라이언트와 KDC 가 같은 도메인일 때 **존재하지 않는 도메인 사용자로는 티켓을 위조할 수 없게 됨**. 이 갱신은 2022년 10월 11일부터 강제됨. 예시는 사용자 계정으로 도는 SPN 이었으나 머신 계정 SPN 에도 그대로 적용됨.
