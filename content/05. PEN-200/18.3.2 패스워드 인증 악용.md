# 18.3.2 패스워드 인증 악용

> **Abusing Password Authentication** · PEN-200 §18.3.2

Active Directory·LDAP 같은 중앙 인증을 쓰지 않는 리눅스는 패스워드를 `/etc/shadow` 에 두고, 이 파일은 일반 사용자가 못 읽음. 그러나 과거에는 해시가 계정 정보와 함께 **누구나 읽을 수 있는** `/etc/passwd` 에 있었음.

여기서 나오는 것이 이 기법의 핵심임 — **하위 호환 때문에 `/etc/passwd` 레코드의 두 번째 칼럼에 해시가 있으면 그것이 유효한 인증 자료로 취급되고, `/etc/shadow` 항목보다 «우선»함.** 즉 `/etc/passwd` 에 쓰기만 가능하면 아무 계정에나 임의의 패스워드를 심을 수 있음.

절차 — `openssl passwd` 로 해시를 만들고(옵션을 안 주면 리눅스 인증이 지원하는 crypt 알고리즘을 씀), 그 해시를 넣은 레코드를 `/etc/passwd` 에 덧붙인 뒤 `su` 로 전환함. UID·GID 를 **0** 으로 넣는 것이 슈퍼유저 계정으로 만드는 부분임.

```
joe@debian-privesc:~$ openssl passwd w00t
Fdzt.eqJQ4s0g
joe@debian-privesc:~$ echo "root2:Fdzt.eqJQ4s0g:0:0:root:/root:/bin/bash" >>
/etc/passwd
joe@debian-privesc:~$ su root2
Password: w00t
root@debian-privesc:/home/joe# id
uid=0(root) gid=0(root) groups=0(root)
```

주의 — `openssl passwd` 의 기본 출력 형식은 실행 시스템에 따라 다름. 오래된 시스템은 DES, 비교적 새 시스템은 MD5 형식을 낼 수 있으므로 대상이 받아들이는 형식인지 확인할 것.

`/etc/passwd` 가 world-writable 인 상황이 비현실적으로 보이지만, 서드파티 제품과의 하이브리드 연동을 편의 위주로 구성하다 이런 권한이 남는 조직이 실제로 있음.
