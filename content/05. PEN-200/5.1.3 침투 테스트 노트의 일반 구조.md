# 5.1.3 침투 테스트 노트의 일반 구조

> **The General Structure of Penetration Testing Notes** · PEN-200 §5.1.3

노트 작성은 간결하면서 정확한, 구조적인 접근이 필요함. 조직 방식은 무수히 많아 만능 권고는 무의미하나 참고할 원칙은 있음:

- 「다음에도 기억하겠지」 하고 일반적인 메모 몇 줄로 넘기지 말고 실제로 한 것을 정확히 기록할 것
- 입력한 모든 명령, 수정한 모든 코드 줄, GUI 에서 클릭한 위치까지 남겨 행위를 재현할 수 있게 할 것
- 많이 적어도 나중에 봤을 때 평가 중 무슨 일이 있었는지 떠오르지 않으면 쓸모가 없음
- 모호함이 없도록 구조화하고 충분히 상세할 것
- 설득력 있고 근거 있는 기술 보고서를 나중에 쓰려면 노트 안에 기술적 세부가 충분해야 함
- 일관성 없이 쓰면 다른 사람이 같은 테스트를 반복해 같은 결과를 얻기 어려움

권장 구조는 개인 취향을 허용할 만큼 추상적임. 목표는 무엇이 일어났는지 상기시키고 발견한 이슈를 복제할 수 있게 하는 것임. 넓게 시작해 각 절로 파고드는 방식이 쉽고 확장 가능함 — 이 top-down 접근은 가장 넓은 활동에서 출발해 초점을 좁히고 세부 수준을 늘려가며 일어난 일을 정확히 재현할 재료를 모두 갖추게 함.

웹 취약점을 발견했을 때 남길 노트의 항목 예:

- **Application Name** — 다중 애플리케이션 테스트에서 중요하고, 그 자체가 자연스러운 폴더·파일 구조가 됨
- **URL** — 탐지한 취약점의 위치를 지시하는 정확한 URL
- **Request Type** — GET·POST·OPTIONS 등 요청 종류와 거기에 가한 수동 변경. 예로 POST 요청을 가로채 username 이나 password 를 바꿔 전달한 것
- **Issue Detail** — 우리 행위로 유발되는 취약점의 개요. 해당하는 CVE 를 지목하거나 관측된 영향을 설명하며, 서비스 거부·원격 코드 실행·권한 상승 등으로 영향을 분류함
- **Proof of Concept Payload** — 취약점을 유발하는 문자열 또는 코드 블록. 노트에서 가장 중요한 부분으로, 이슈를 확정 짓고 재현하게 만드는 것임. 필요한 전제조건을 모두 나열하고 다시 유발하는 데 필요한 정확한 코드·명령을 실을 것

Cross-Site Scripting(XSS) 테스트를 예로 구체화하면, 대상에는 XSSBlog.html 이라는 웹 페이지가 있고 접속하면 블로그 항목을 입력할 수 있음.

이 요청들을 보내는 동안 아래처럼 행위를 기록해 둠.

```
Testing for Cross-Site Scripting
Testing Target: 192.168.1.52
Application:    XSSBlog
Date Started:   31 March 2022
1.  Navigated to the application
    http://192.168.1.52/XSSBlog.html
    Result: Blog page displayed as expected
2.  Entered our standard XSS test data:
    You will rejoice to hear that no disaster has accompanied the
    commencement of an enterprise which you have regarded with such
    evil forebodings.<script>alert("Your computer is infected!");</script>
    I arrived here yesterday, and my first task is to assure my dear
    sister of my welfare and increasing confidence in the success of
    my undertaking.
3.  Clicked Submit to post the blog entry.
    Result: Blog entry appeared to save correctly.
4.  Navigated to read the blog post
    http://192.168.1.52/XSSRead.php
    Result: The blog started to display and then the expected alert popped up.
5.  Test indicated the site is vulnerable to XSS.
PoC payload: <script>alert(‘Your computer is infected!')</script>
```

*테스트 노트 예시*

이렇게 하면 다른 테스터가 따라올 수 있는 일관되고 포괄적인 노트를 단순·빠르게, 확장 가능한 형태로 남기게 됨. 다만 노트 자체가 고객에게 낼 보고서는 아님 — 나중에 보고서를 조립할 때 값을 하는 재료임.
