# 17.1.1 Windows 권한과 접근 제어 이해

> **Understanding Windows Privileges and Access Control** · PEN-200 §17.1.1

## 메커니즘

Windows 에서 권한(privilege) 은 파일시스템 수정이나 사용자 추가처럼 시스템과 관련된 로컬 작업을 특정 계정이 수행할 수 있는가를 가리킴. 이를 허용하거나 거부하려면 작업의 출처를 식별하고 그 작업에 필요한 권한이 충분한지 판정할 제어 장치가 필요하고, 그 장치가 SID·액세스 토큰·MIC·UAC 넷임.

**SID(Security Identifier)** — Windows 가 인증 가능한 주체(principal), 즉 사용자와 그룹을 식별하는 고유값. 로컬 계정·그룹의 SID 는 LSA(Local Security Authority) 가, 도메인 사용자·그룹의 SID 는 도메인 컨트롤러(DC) 가 생성함. 사용자나 그룹이 만들어질 때 생성되고 이후 변경되지 않음. 접근 제어 관리에서 Windows 는 사용자 이름이 아니라 SID 만으로 주체를 식별함.

SID 문자열은 `-` 로 구분된 부분들로 구성되며, 아래가 그 기본 구조임.

```
S-R-X-Y
```

맨 앞 `S` 는 이 문자열이 SID 임을 나타내는 리터럴이고, `R` 은 리비전으로 SID 구조가 여전히 초판이라 항상 1 임. `X` 는 SID 를 발급한 식별자 권한(identifier authority) 으로, 가장 흔한 값 5 는 NT Authority 를 뜻하며 로컬·도메인 사용자와 그룹에 쓰임. `Y` 는 식별자 권한의 하위 권한들로 도메인 식별자와 RID(relative identifier) 로 이루어짐. 도메인 식별자는 도메인 사용자면 도메인의 SID, 로컬 사용자면 로컬 머신의 SID, 내장 주체면 32 이며, RID 가 사용자·그룹 같은 개별 주체를 결정함.

```
S-1-5-21-1336799502-1441772794-948155058-1001
```

위 예에서 RID 는 1001 임. 거의 모든 주체의 RID 가 1000 부터 시작하므로 이 계정이 시스템에서 두 번째로 만들어진 로컬 사용자임을 알 수 있음. RID 가 1000 미만인 것들은 잘 알려진 SID(well-known SID) 로, 특정 사용자·그룹이 아니라 일반적·내장 주체를 가리킴.

```
S-1-0-0                       Nobody
S-1-1-0                       Everybody
S-1-5-11                      Authenticated Users
S-1-5-18                      Local System
S-1-5-domainidentifier-500    Administrator
```
*권한 상승 맥락에서 유용한 잘 알려진 SID*

이 모듈에서 SID 를 직접 다루지는 않지만, Windows 가 주체를 어떻게 식별하는지 알아야 액세스 토큰을 이해할 수 있고 뒤의 Active Directory 모듈에서도 필수임.

**액세스 토큰(access token)** — 사용자가 인증되면 Windows 가 그 사용자에게 할당하는 토큰. 토큰은 현재 유효한 규칙·속성의 집합인 보안 컨텍스트(security context) 를 담고, 그 내용은 사용자의 SID, 소속 그룹들의 SID, 사용자·그룹 권한, 그리고 토큰의 적용 범위를 기술하는 정보임. 사용자가 프로세스나 스레드를 시작하면 사용자 액세스 토큰의 사본인 기본 토큰(primary token) 이 그 객체에 할당되고, 이 토큰이 다른 객체와 상호작용할 때 갖는 권한을 규정함. 스레드에는 가장 토큰(impersonation token) 을 따로 할당할 수 있는데, 이때 그 스레드는 소유 프로세스의 기본 토큰이 아니라 가장 토큰의 보안 컨텍스트로 객체를 다룸 — 스레드에 프로세스와 다른 보안 컨텍스트를 부여하기 위한 장치임.

**MIC(Mandatory Integrity Control)** — SID·토큰과 별개로 Windows 가 강제하는 장치로, 미리 정의된 무결성 수준(integrity level) 에 따라 보안 객체 접근을 제한함. 무결성 수준은 Windows 가 애플리케이션과 객체에 부여하는 신뢰의 크기이며, 낮은 무결성 프로세스가 높은 무결성 프로세스를 수정하지 못하게 막음. 프로세스와 객체는 그것을 만든 사용자의 무결성 수준을 상속하되, 실행 파일 자체가 낮은 무결성이면 거기서 생성된 프로세스도 같은 낮은 수준을 상속함. **접근 권한(permission) 이 충분하더라도 낮은 무결성 주체는 높은 무결성 객체를 수정할 수 없음** — 접근 권한 검사를 통과해도 별도로 걸리는 관문임. Windows Vista 이후 프로세스는 다음 수준들로 실행됨.

```
- System integrity – Kernel-mode processes with SYSTEM privileges
- High integrity – Processes with administrative privileges
- Medium integrity – Processes running with standard user privileges
- Low integrity level – Restricted processes, often used for security
[sandboxing](https://en.wikipedia.org/wiki/Sandbox_(software_development)), such as
web browsers.
- Untrusted – The lowest integrity level, assigned to highly restricted processes that
pose potential security risks
```
*무결성 수준*

확인 방법 — 프로세스의 무결성 수준은 Process Explorer, 사용자의 무결성 수준은 `whoami /groups`, 파일의 무결성 수준은 `icacls`. 예로 Process Explorer 에서 관리자 사용자로 시작한 PowerShell 프로세스는 High, 일반 사용자로 시작한 것은 Medium 으로 나타남.

`[가정]` 원문 산문은 뒤에서 무결성 수준을 Untrusted 를 뺀 네 단계로 다시 열거하지만 리스팅은 다섯 단계임 — 리스팅 쪽을 정본으로 삼음.

**UAC(User Account Control)** — 무결성 수준에 더해 무단 권한 상승을 제한하는 기능으로, 실행한 사용자가 Administrator 이더라도 대부분의 애플리케이션과 작업을 표준 사용자 권한으로 실행함. 이를 강제하기 위해 Windows 는 관리자 사용자에게 로그온 시점에 액세스 토큰 두 개를 발급함 — 비권한 작업 전부를 처리하는 표준 사용자 토큰(필터링된 관리자 토큰) 과, 상승된 권한이 명시적으로 필요할 때만 활성화되는 관리자 토큰임. 관리자 토큰을 쓰려면 UAC 동의 프롬프트를 승인해야 함.

따라서 **Administrator 그룹의 구성원이라는 사실만으로 프로세스가 높은 무결성으로 실행되지는 않음.** 기본값은 Medium 이고 Medium 에서는 시스템 파일이나 레지스트리 키를 수정할 수 없어 High 로 승격해야 하며, 그래서 특정 작업에서 세션 승격 프롬프트가 뜸. 공격자와 침투 테스터가 UAC 우회를 노리는 것도 High 무결성으로 프로세스를 실행해 시스템 자원에 제한 없이 접근하기 위함임.
