# 7.2.4 스캔 결과 분석

> **Analyzing the Results** · PEN-200 §7.2.4

- ⚠️ 이 절의 VM 그룹은 앞 절과 «다름» — 절 하단의 VM 그룹을 켜서 쓸 것. 또한 Nessus 와 플러그인이 계속 갱신되므로 결과·그룹핑·표시 정보가 교재와 조금씩 다를 수 있음.
- My Scans 에서 스캔을 클릭하면 결과 대시보드로 들어감. 첫 화면인 Hosts 는 스캔된 호스트 전부와 취약점 데이터의 시각 표현을 보여 줘 중요한 발견과 시스템별 보안 상태를 한눈에 잡게 함. 우측 하단은 전체 대상의 취약점 분포, 그 위는 스캔 일반 정보임.
- 호스트 항목을 클릭하면 그 호스트의 취약점 목록이 나옴.

![[PEN200-Fig-058.png]]
*호스트별 취약점 목록 — Severity 의 MIXED 와 Count 열이 그룹핑을 나타냄*

- Severity 열로 심각한 발견인지를 즉시 가름. Nessus 가 발견을 «묶을» 때는 심각도를 MIXED 로 표시하고 Count 열에 묶인 개수를 보여 줌. 그룹을 클릭하면 안의 발견 목록이 펼쳐지고, 개별 발견을 클릭하면 상세로 들어감.
  - 예시에서는 Family 열이 Web Servers 인 Apache Httpd (Multiple Issues) 그룹을 열어 그 안의 Apache 2.4.49 < 2.4.51 Path Traversal Vulnerability 를 확인함.
- 발견 상세에는 취약점 자체의 정보와 «그것을 탐지한 플러그인» 정보, 연관 위험도, 익스플로잇 존재 여부, 참고 링크가 함께 담김.
- 대상 하나를 파는 것과 별개로 전체 대상의 중요 취약점을 훑고 싶을 때 쓰는 것이 VPR Top Threats — VPR(Vulnerability Priority Rating)로 우선순위를 매긴 상위 10 개 목록임. 예시에서는 설정상 6 개만 잡혀 6 개만 나옴. Nessus 버전에 따라 이 탭이 없을 수 있으나 개별 발견에는 VPR 값이 그대로 들어 있음.
- Remediations — 플러그인이 함께 담은 조치·완화 방안을 모아 보여 줌.
- History — 같은 설정으로 돌린 스캔 이력. 이전 결과의 검토·비교에 씀.
- Report 대시보드에서는 보고서 생성 외에 스캔 설정 변경, 재실행, 데이터 내보내기가 가능함. Audit Trail 을 설정하면 «특정 플러그인이 왜 그렇게 동작했는지»를 분석할 수 있어 미탐을 줄이는 데 씀.
- PDF 보고서 — Report 버튼을 누르면 템플릿 선택 창이 뜸. 호스트별로 묶인 상세 발견을 담는 Detailed Vulnerabilities By Host 를 고르고 형식을 PDF 로 지정해 Generate Report. 상세 대신 요약이 필요하면 Complete List of Vulnerabilities by Host 를 씀.
