# 10.2.3 블라인드 SQL 인젝션

> **Blind SQL Injections** · PEN-200 §10.2.3

앞 절들의 페이로드는 질의 결과가 화면에 실려 오는 in-band 였음. **블라인드**는 DB 응답이 전혀 돌아오지 않아, 애플리케이션의 **반응 차이**로 참·거짓을 추론하는 경우임.

두 갈래:

- **불리언 기반** — 질의가 TRUE 냐 FALSE 냐에 따라 애플리케이션이 서로 다른, 예측 가능한 화면을 돌려줌. ⚠️ 판단 근거가 되는 출력이 DB 가 아니라 **애플리케이션 쪽**에서 나온다는 점에서 여전히 블라인드임
- **시간 기반** — DB 에 일정 시간 대기를 시키고 **응답 지연 여부**로 참·거짓을 판정함

예제 페이지는 URL 의 `user` 파라미터로 사용자 레코드를 조회해 사용자명·해시·설명을 뿌림. 불리언 기반 시험:

```
http://192.168.50.16/blindsqli.php?user=offsec' AND 1=1 -- //
```

*불리언 기반 SQLi 시험*

`1=1` 은 항상 참이므로 **해당 사용자가 실재할 때만** 값이 돌아옴 → 조건을 바꿔 가며 이 참·거짓 차이를 관찰하면 다른 사용자명을 열거하거나, 질의를 확장해 다른 테이블의 데이터까지 확인할 수 있음.

시간 기반은 같은 판정을 지연으로 바꾼 것임.

```
http://192.168.50.16/blindsqli.php?user=offsec' AND IF (1=1, sleep(3),'false') -- //
```

*시간 기반 SQLi 시험*

조건이 참이면 `sleep(3)` 이 걸려 페이지가 약 3초 멈춤. 존재하지 않는 사용자면 조건 자체가 성립하지 않아 지연이 없음.

⚠️ 블라인드에서는 **유효한 입력과 잘못된 입력 양쪽의 기준 반응을 먼저 재 둘 것** — 비교 대상이 없으면 지연이나 화면 차이를 오독함.

참·거짓을 하나씩 물어 가며 추론하는 방식이라 손으로 하면 시간이 크게 드는 공격이고, 그래서 `sqlmap` 류 자동화가 붙는 지점임.
