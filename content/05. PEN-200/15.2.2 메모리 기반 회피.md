# 15.2.2 메모리 기반 회피

> **In-Memory Evasion** · PEN-200 §15.2.2

**인메모리 인젝션**(PE Injection)은 Windows 에서 AV 를 우회하는 대표적 기법임. 악성 바이너리를 난독화하거나 새 섹션을 만들거나 기존 권한을 바꾸는 대신 **휘발성 메모리를 조작**함. 최대 이점은 디스크에 파일을 전혀 쓰지 않는다는 것 — 대부분의 AV 제품이 집중하는 영역을 통째로 비켜감.

디스크를 안 쓰는 기법은 여럿이지만 나머지는 C/C++ 수준의 저수준 배경이 필요해 범위 밖이고, PowerShell 을 이용한 인메모리 인젝션만 뒤에서 상세히 다룸.

**원격 프로세스 메모리 인젝션**(Remote Process Memory Injection)은 악성이 아닌 정상 PE 에 페이로드를 주입하는 기법임. 흔한 구현은 Windows API 조합임 — 먼저 `OpenProcess` 로 접근 권한이 있는 대상 프로세스의 유효한 `HANDLE` 을 얻고, `VirtualAllocEx` 로 그 프로세스 문맥에 메모리를 할당하고, `WriteProcessMemory` 로 새로 할당된 메모리에 악성 페이로드를 복사한 뒤, 보통 `CreateRemoteThread` 로 별도 스레드에서 메모리 안의 페이로드를 실행함. 뒤의 실습은 이를 단순화해 «로컬» powershell.exe 를 대상으로 삼고, 무거운 부분은 PowerShell 이 대신하게 함.

**리플렉티브 DLL 인젝션**(Reflective DLL Injection)은 일반 DLL 인젝션이 `LoadLibrary` 로 디스크의 악성 DLL 을 적재하는 것과 달리, 공격자가 **프로세스 메모리에 올려 둔 DLL 을 적재**하려는 기법임. 난점은 `LoadLibrary` 가 메모리에서의 DLL 적재를 지원하지 않고 Windows 가 그 일을 해 줄 API 를 아예 노출하지 않는다는 것 — 그래서 **디스크 DLL 에 의존하지 않는 로더를 공격자가 직접 구현해야 함.**

**프로세스 할로잉**(Process Hollowing)은 악성이 아닌 프로세스를 일시 중단 상태로 띄운 뒤, 메모리에 올라온 그 프로세스의 이미지를 걷어내고 악성 실행 이미지로 교체하고, 프로세스를 재개시킴. 결과적으로 정상 프로세스 대신 악성 코드가 실행됨.

**인라인 후킹**(Inline hooking)은 메모리를 수정해 함수에 후크 — 실행 흐름을 우리 코드로 돌리는 명령 — 를 심는 기법임. 악성 코드가 실행되고 나면 흐름이 수정된 함수로 되돌아가 이어지므로, **겉보기에는 원래 코드만 실행된 것처럼 보임.**

후킹은 루트킷이 즐겨 쓰는 기법임. 루트킷은 유저 공간·커널, 나아가 부트나 하이퍼바이저 같은 더 낮은 OS 보호 링의 시스템 구성 요소를 변조해 대상 시스템에 전용·지속 접근을 확보하는 은밀한 악성코드임. 후크를 심으려면 관리자 권한이 필요해, 대개 상승된 셸이나 권한 상승(privilege escalation) 취약점을 거쳐 설치됨.
