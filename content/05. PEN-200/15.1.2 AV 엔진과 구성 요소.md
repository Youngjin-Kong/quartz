# 15.1.2 AV 엔진과 구성 요소

> **AV Engines and Components** · PEN-200 §15.1.2

현대 AV 의 연료는 인터넷에 있는 벤더 시그니처 DB 에서 받아오는 갱신분임. 받은 정의는 로컬 시그니처 DB 에 저장되고, 그것이 다시 개별 엔진에 공급되는 구조임.

구성 요소는 대체로 이 일곱임 — File Engine, Memory Engine, Network Engine, Disassembler, Emulator/Sandbox, Browser Plugin, Machine Learning Engine. 각 엔진이 시그니처 DB 와 «동시에» 작동해 개별 이벤트를 양성·악성·미지 중 하나로 등급화함.

**File engine** 은 예약 스캔과 실시간 스캔을 모두 담당함. 예약 스캔은 파일시스템 전체를 훑어 각 파일의 메타데이터나 데이터를 시그니처 엔진에 넘기는 단순한 동작임. 반면 실시간 스캔은 웹에서 새 악성코드를 내려받는 것 같은 «새로운 파일 동작»을 잡아내야 하고, 그러려면 커널 수준에서 이벤트를 식별해야 해 전용 미니필터 드라이버가 필요함. **현대 AV 가 커널과 유저랜드 양쪽에서 도는 이유가 이것** — 그래야 OS 전 범위를 검증할 수 있음.

**Memory engine** 은 런타임에 각 프로세스의 메모리 공간을 검사해 알려진 바이너리 시그니처나 메모리 인젝션 공격으로 이어질 수 있는 의심스러운 API 호출을 찾음.

**Network engine** 은 로컬 네트워크 인터페이스의 인바운드·아웃바운드 트래픽을 검사하고, 시그니처가 맞으면 악성코드가 C2(Command and Control) 서버와 통신하는 것을 차단하려 시도함.

악성코드는 탐지를 더 어렵게 하려고 자체 루틴으로 암복호화해 정체를 감춤. AV 는 여기에 **패커나 암호를 디스어셈블한 뒤 샌드박스(에뮬레이터)에 올려 실행하는 것**으로 맞섬. **Disassembler** 엔진이 기계어를 어셈블리로 번역해 원래 프로그램 코드 섹션을 재구성하고 인코딩·디코딩 루틴을 찾아냄. **샌드박스**는 AV 내부의 격리 환경이라 악성코드를 시스템 피해 없이 적재·실행할 수 있고, 언패킹·디코딩이 끝나 실행 중인 상태가 되면 알려진 시그니처와 철저히 대조할 수 있음.

브라우저는 자체 샌드박스로 보호돼 AV 시야가 막히므로, 현대 AV 는 **브라우저 플러그인**으로 가시성을 확보해 브라우저 안에서 실행될 악성 콘텐츠를 탐지함. 여기에 클라우드의 연산 자원과 알고리즘에 기대 미지 위협을 잡는 **머신러닝** 구성 요소가 점점 핵심으로 자리잡는 중임.
