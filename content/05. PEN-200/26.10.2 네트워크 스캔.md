# 26.10.2 네트워크 스캔

> **Scanning the Network** · PEN-200 §26.10.2

인터페이스가 둘이라는 것은 **반대편에 발견할 것이 있다는 신호**임. 게다가 이런 사설 네트워크의 서비스는 보안이 느슨한 경우가 많음 — 조직이 「사설망은 사설이다」라고 믿거나 인증을 리버스 프록시가 처리한다고 전제하기 때문임. 서비스에 직접 닿을 수만 있으면 그 계층을 통째로 우회하게 됨.

도구 선택이 문제임. nmap 은 컨테이너에 없을 확률이 높고, 설치하는 것 자체가 어렵거나 은밀하지 않음. meterpreter 로 터널링해 스캔하는 방법도 있으나 **느리고 결과가 부정확함.** 반면 셸을 Python 으로 땄으므로 **대상에 Python 이 있는 것은 확실함** — 이미 가진 것으로 스캔하는 쪽이 맞음.

```
kali@kali:~$ nano netscan.py
kali@kali:~$ cat -n netscan.py
01  import socket
02  import ipaddress
03  import sys
04
05  def port_scan(ip_range, ports):
06      for ip in ip_range:
07          print(f"Scanning {ip}")
08          for port in ports:
09              sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
10              sock.settimeout(.2)
11              result = sock.connect_ex((str(ip), port))
12              if result == 0:
13                  print(f"Port {port} is open on {ip}")
14              sock.close()
15
16  ip_range = ipaddress.IPv4Network(sys.argv[1], strict=False)
17  ports = [80, 443, 8080]  # List of ports to scan
18
19  port_scan(ip_range, ports)
```

*표준 라이브러리만 쓰는 포트 스캐너 — 어느 Python 환경에나 있는 모듈이라 설치가 필요 없음*

- `socket`·`ipaddress`·`sys` 는 기본 제공 모듈이라 추가 설치가 없음
- `connect_ex()` 는 예외 대신 반환값을 주므로 `0` 이면 열린 포트임
- 타임아웃 0.2초 — 로컬 네트워크를 스캔하므로 짧게 잡아도 됨
- 포트는 웹 위주로 `[80, 443, 8080]` 만 — ⚠️ **포트를 하나 늘릴 때마다 스캔 시간이 크게 늘어남**

전달 경로는 2단임 — 먼저 `scp` 로 개인 Kali → 클라우드 Kali.

```
kali@kali:~$ scp ./netscan.py kali@34.203.75.99:/home/kali/
kali@34.203.75.99's password:
netscan.py                                100%  462     2.0KB/s   00:00
```

*클라우드 Kali 의 `/home/kali/` 로 복사*


`172.18.0.1/24` 에서 80 포트 서비스 넷을 찾음. `172.18.0.1` 은 게이트웨이일 것이고, 컨테이너 환경에서 그것은 **호스트가 외부로 노출한 포트**를 가리키는 경우가 많음. 정체는 `curl` 헤더로 봄.

Jenkins 는 대상으로서 값이 큼 — 시크릿과 다른 환경에 대한 접근을 품고 있는 경우가 많음. 거기에 등록까지 열려 있으므로 다음 단계는 계정 생성이고, 그 전에 **Kali 에서 이 내부 서비스에 닿을 경로**를 먼저 만들어야 함.
