# 12 클라이언트 사이드 공격

> **Client-side Attacks** · PEN-200 §12

경계(perimeter) 돌파에서 노출 서비스의 기술적 취약점을 익스플로잇하는 고전적 방식은 갈수록 드물고 어려워지는 추세임. Verizon 보고서 기준 경계 침해 벡터 2위가 피싱(phishing) 이고 1위는 자격 증명 공격인데, 피싱은 대개 클라이언트 사이드 공격을 실어 나름.

**클라이언트 사이드 공격 = 악성 파일을 사용자에게 직접 전달하고, 사용자가 자기 머신에서 그것을 실행하는 순간 내부망 발판을 얻는 방식.** 노리는 것은 외부 서비스가 아니라 클라이언트 로컬 소프트웨어의 기능이나 약점임 — 브라우저, OS 구성요소, 오피스 프로그램.

여기서 기술 외 능력이 필수가 되는 이유 — 코드가 실행되려면 **사용자를 설득하거나 속여야** 하기 때문임. 즉 시스템 관리·네트워킹 같은 기술뿐 아니라 인간 심리, 기업 문화, 사회적 관례에 대한 이해가 성공률을 좌우함. 사람의 편향과 취약함을 다루는 영역이라는 점에서 다른 벡터와 성격이 다름.

동시에 윤리·법적 경계가 걸림. 목표는 대상 시스템에서의 코드 실행이지, 직원 협박이나 경찰 사칭처럼 선을 넘는 것이 아님.

방어가 까다로운 구조적 이유 — 기업 내부망의 클라이언트는 외부에서 직접 닿는 시스템이 아니고 외부 노출 서비스도 거의 제공하지 않음. 스캔·패치 중심 방어가 걸리지 않는 자리라 완화가 어렵고, 그래서 새로운 방어 패러다임이 나온 배경이 됨.

전달 방식(delivery mechanism)과 페이로드(payload)의 조합으로 구성됨 —

- 이메일 첨부, 악성 사이트·파일로 유도하는 링크
- 더 고급 수단 — USB 드로핑, 워터링 홀(watering hole)

어느 쪽을 쓰든 공통 제약은 같음. 클라이언트는 외부에 노출되는 일이 드물어 **라우팅되지 않는 내부망의 대상에게 페이로드를 밀어 넣어야** 함. 이메일 경로는 스팸 필터·방화벽 등이 링크와 첨부를 스캔하면서 갈수록 어려워지고 있음.

벡터와 페이로드를 고르기 전에 **정찰이 먼저**임 — 페이로드가 대상의 OS 및 설치 애플리케이션과 맞아떨어져야 하기 때문. 대상이 Windows 면 Windows Script Host 로 실행되는 악성 JScript 나 악성 리소스를 가리키는 `.lnk` 바로가기 같은 선택지가 열리고, Microsoft Office 가 깔려 있으면 악성 매크로를 심은 문서를 쓸 수 있음.
