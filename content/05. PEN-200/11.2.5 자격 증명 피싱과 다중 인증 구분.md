# 11.2.5 자격 증명 피싱과 다중 인증 구분

> **Differentiate Credential Phishing and Multi-Factor Authentication (MFA)** · PEN-200 §11.2.5

## 다중 인증(MFA)

자격 증명을 손에 넣어도 **다중 인증(Multi-Factor Authentication, MFA)** 이 다음 벽으로 서 있음. 자격 증명이 털린 뒤에도 공격 속도를 늦추려고 도입된 장치임. 대응 수단은 여럿 —

**프롬프트 폭탄(prompt bombing)** — 푸시 승인 방식 MFA 를 겨냥함. 로그인 시도를 반복해 대상 휴대폰에 승인 요청을 쏟아부음. 여기서 **MFA 피로(MFA fatigue)** 가 발생함 — 사용자가 정상 요청이 오작동한 것으로 여기고 알림을 멈추려 하나를 승인해버림. Lapsus$ 그룹이 실제로 써먹은 방식임.

**로그인 흐름에 MFA 입력 추가** — 자격 증명 탈취 사이트의 로그인 절차에 MFA 프롬프트를 붙여 토큰까지 확보함. 다만 **토큰 수명이 매우 짧아 즉시 실제 서비스로 중계해야 하므로 타이밍이 핵심**임. 얻는 것은 1회성 접근뿐이지만 국소적으로 쓰면 효과가 큼.

**브라우저 중간자(browser-in-the-middle)** — 실제 세션을 프록시해 인증 정보를 캡처함. 대상 입장에서는 진짜 사이트와 상호작용하는 것이 맞지만, 로그인으로 생성된 세션과 MFA 토큰이 공격자 통제 아래 놓임. `cuddlephish` 같은 도구가 자동화함. **공인 IP 가 필요해 로컬에서 간단히 세울 수 없다는 제약**이 있고, 침해 가정(assumed breach) 형태로 내부 웹 애플리케이션 접근을 노리는 상황에서는 이 제약이 실제 문제가 됨.

**무차별 대입** — 토큰이 보통 6자리 숫자라 이론상 가능함. 그러나 **MFA 서버가 시도 횟수를 무제한 허용하고 응답 유효 시간도 극단적으로 길어야** 성립하므로 현실성이 낮음.

**사회공학** — 헬프데스크나 IT 부서원 같은 신뢰받는 인물을 사칭해 직접 연락하고 토큰을 불러달라고 함. 구실이 매우 탄탄해야 함.

**SIM 스와핑** — MFA 토큰이 SMS 로 오는 경우 번호 자체를 가로채 토큰을 직접 수신함. 법적 문제 때문에 **정상적인 침투 테스트에서는 쓸 수 없지만**, SMS 기반 MFA 를 겨냥해 실제로 쓰이는 수법이라 알고 있어야 함.
