# 22.4.1 SharpHound 데이터 수집

> **Collecting Data with SharpHound** · PEN-200 §22.4.1

역할 분담 — 수집은 SharpHound, 분석·정리·표현은 BloodHound 임. SharpHound 는 C# 으로 작성됐고 Windows API 와 LDAP 네임스페이스 함수를 씀. 앞 절에서 손으로 돌린 것과 같은 계열이라 예컨대 로그온 세션 열거에 `NetWkstaUserEnum` 과 `NetSessionEnum` 을 시도하고, Remote Registry 서비스에도 질의함.

이론상 같은 정보를 수동으로 모을 수 있는데도 자동화를 겹치는 이유는 **관계를 그래프로 보면 눈에 안 띄던 공격 경로가 드러나기 때문**임.

배포 형태는 셋 — 직접 컴파일, 컴파일된 실행 파일, PowerShell 스크립트. 여기서는 스크립트를 씀. CLIENT75 의 `C:\Tools` 에 있는 파일은 낡았으므로 쓰지 않고, 최신 zip 을 Kali 로 내려받아 `Sharphound.ps1` 만 꺼내 CLIENT75 로 옮긴 뒤 메모리에 임포트함.

```
PS C:\Users\stephanie> cd .\Downloads\
PS C:\Users\stephanie\Downloads> powershell -ep bypass
Windows PowerShell
Copyright (C) Microsoft Corporation. All rights reserved.
Install the latest PowerShell for new features and improvements!
https://aka.ms/PSWindows
PS C:\Users\stephanie\Downloads> Import-Module .\Sharphound.ps1
```

실행 함수 이름은 `Invoke-BloodHound` 임 — 이 단계에서 돌리는 것은 SharpHound 인데 이름이 BloodHound 라 직관에 어긋남. 옵션은 `Get-Help Invoke-BloodHound` 로 확인함.

⚠️ 아래 블록은 PDF 추출 과정에서 줄이 접혀 있음. 파라미터 이름이 줄 끝·줄 머리로 갈라진 곳은 이어 붙여 읽을 것.

`-CollectionMethod` 가 수집 방식을 정함. `All` 은 로컬 그룹 정책을 제외한 모든 수집 방식을 수행함. 기본적으로 데이터를 JSON 으로 모아 자동으로 zip 으로 묶어주므로 나중에 Kali 로 옮기기 쉬움. 저장 위치와 파일 접두어는 `-OutputDirectory`·`-OutputPrefix` 로 지정함.

⚠️ 아래 명령도 줄이 접혀 있음. `-OutputDirectory` 가 갈라진 것이므로 한 줄로 이어 칠 것.

```
PS C:\Users\stephanie\Downloads> Invoke-BloodHound -CollectionMethod All -
OutputDirectory C:\Users\stephanie\Desktop\ -OutputPrefix "corp audit"
```

*수집 로그 — 적용된 수집 방식 목록과 끝의 객체 수(예시 환경에서 309개)가 판정 근거임*

**수집 결과는 실행한 계정(여기서는 stephanie) 관점의 스냅숏**이라 그 계정이 접근할 수 있는 범위만 담김 — 이후 분석을 읽을 때의 전제임.

산출물은 지정한 경로에 `<접두어>_<타임스탬프>_BloodHound.zip` 과 `.bin` 파일로 떨어짐.

`.bin` 은 수집 속도를 올리는 캐시라 분석에는 필요 없고 지워도 무방함.

SharpHound 는 루핑도 지원함 — 정한 질의를 일정 기간 주기적으로 반복 실행하는 방식임. 위처럼 한 번 돌리면 그 시점의 스냅숏만 남아, 예컨대 수집 이후 로그온한 사용자는 분석에서 통째로 빠짐. 환경이 바뀌는 것을 잡으려면 루핑이 유리하고, 캐시 파일이 그 반복을 빠르게 함.
