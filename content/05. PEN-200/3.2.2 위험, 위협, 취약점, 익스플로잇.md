# 3.2.2 위험, 위협, 취약점, 익스플로잇

> **Risks, Threats, Vulnerabilities, and Exploits** · PEN-200 §3.2.2

이후 이론을 따라가려면 네 용어의 구분이 먼저임 — 위험(risk)·위협(threat)·취약점(vulnerability)·익스플로잇(exploit).

**위험** — 넷 중 가장 근본적이고 사이버보안 밖에서도 통용됨. 두 축으로 정의됨: ①부정적 사건이 일어날 «확률» ②그것이 일어났을 때 우리가 가치를 두는 것에 미치는 «영향». 두 축이 네 사분면을 만듦 — 저확률·저영향 / 저확률·고영향 / 고확률·저영향 / 고확률·고영향. 실무에서 늘 던질 질문 둘 — 「이 공격이 일어날 가능성은 얼마나 되는가」, 「일어난다면 최악의 결과는 무엇인가」.

**위협** — 특정 위험을 특정 «원인»에 귀속시킬 수 있을 때 그 원인을 위협이라 부름. 즉 우리가 지키려는 자산에 위험을 가하는 무엇임. 위협이 전부 인간인 것은 아님 — 네트워크가 지역 전력망에 의존한다면 심한 뇌우도 운영에 대한 위협임. 다만 관심의 상당 부분은 인간 위협과 인간이 만든 악성 프로그램에 있음. 위협을 체현한 개인·집단을 **위협 행위자(threat actor)** 라 하며, 이 말에는 «의지·동기·지능»이 있다는 함의가 붙음.

**취약점** — 위협이 실제 위험이 되려면 대상이 어떤 식으로든 취약해야 함. 취약점은 «위협이 피해를 끼치도록 허용하는 결함»임. 결함이라고 다 취약점은 아님 — 다리에 포장재가 긁혔거나 완벽히 직선이 아닌 미관상 결함은 다리에 손상 위험을 만들지 않으므로 취약점이 아님. 반면 구조적 결함이 있다면 과적이나 강풍 같은 «특정 위협»에 취약해짐.

**Log4j 사례(2021년 12월)** — 널리 쓰이는 Java 로깅 라이브러리 Apache Log4j 에서 발견됨. JNDI 툴킷 기능이 로그를 풍부하게 만들려고 기본값으로 다운로드 요청을 허용했고, 내려받은 것이 유효한 Java 파일이면 서버가 그것을 실행했음. 따라서 사용자 입력(사용자명·HTTP 헤더 등)이 «로그로 남기 전에 제대로 정제되지 않으면» 원격의 미인가 사용자가 악성 Java 파일을 내려받게 만들어 서버에서 명령을 실행할 수 있었음.

- 라이브러리 사용 범위가 넓어 CVSS(Common Vulnerability Scoring System) 최고 등급인 **10.0 Critical** 이 매겨졌고, 벤더·기업·개인이 취약 시스템을 찾아 패치하고 침해 흔적을 뒤지는 소동으로 이어짐. 직후 Log4j 의 추가 취약점들이 더 발견돼 상황을 악화시킴
- 예방 — 사용자 제공 데이터의 정제. 완화 — 웹 요청·코드 실행처럼 위험한 기능을 «기본값으로 비활성화»

**익스플로잇** — 프로그램에서 취약점은 「사용자가 프로그래머가 의도하지 않은 목적을 달성할 수 있을 때」 발생함. 그 목적이 «가져서는 안 될 접근이나 권한»을 주고, 그것이 «의도적·악의적»으로 추구될 때 그 행위가 익스플로잇이 됨. 영어에서 명사이자 동사로 쓰임 — 명사로는 특정 취약점을 악용하는 절차, 동사로는 그 절차를 실제로 수행해 안정적으로 악용하는 것.

**공격면과 공격 벡터** — 공격면(attack surface)은 시스템·네트워크에서 악용될 수 있는 접점 전체임. 공격 벡터(attack vector)는 위협 행위자의 목적을 진전시키는 «취약점 + 악용 방법»의 특정 조합임. 방어자는 공격면을 최대한 줄이려 하고, 공격자는 주어진 공격면을 훑어 유망한 벡터를 찾음.
