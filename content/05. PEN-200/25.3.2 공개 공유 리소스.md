# 25.3.2 공개 공유 리소스

> **Publicly Shared Resources** · PEN-200 §25.3.2

어떤 클라우드 자산은 기능의 성격상 인터넷에 게시되는 것이 당연함 — 조직이 EC2 인스턴스의 기반으로 쓰는 표준 OS 이미지(Ubuntu, Debian 등)가 그 예이고, CSP 가 접근 수단도 편하게 제공함. 반대로 커스텀 머신 이미지, 가상 디스크·데이터베이스 스냅샷처럼 내부용으로 설계된 것도 있음.

그런데 대형 조직은 퍼블릭 클라우드 계정을 여러 개 두고 **계정 간, 때로는 공개로** 이런 리소스를 공유해야 할 때가 있음. ⚠️ 공유 책임 모델상 그렇게 공개된 리소스에 민감 데이터가 없어야 하지만, **실제로는 항상 그렇지는 않음** — 여기가 공격 지점임.

이 절에서 노리는 리소스 셋:

- 공개 공유된 AMI(Amazon Machine Image)
- 공개 공유된 EBS(Elastic Block Storage) 스냅샷
- RDS(관계형 데이터베이스) 스냅샷

**이들에게는 접근용 도메인이나 URL 이 대개 없음.** 따라서 CSP API 로 요청해야만 닿음 — 앞 단위의 도메인 기반 정찰이 통하지 않는 영역임.

AMI 는 OS 와 소프트웨어·파일이 담긴 가상 머신 이미지이고, EC2 인스턴스를 띄우려면 반드시 하나를 지정해야 함. 보통 AWS·서드파티 파트너·커뮤니티·타 계정이 공개한 AMI 카탈로그에서 고름.

`ec2 describe-images` 는 그 계정이 읽을 수 있는 **모든** 이미지를 나열해 출력이 지나치게 큼. `--owners amazon` 으로 AWS 제공분만 남기고, `--executable-users all` 을 더하면 자기 소유 공개 AMI 를 포함해 공개 AMI 가 빠짐없이 나옴. ⚠️ 필터를 걸어도 완료까지 30~60초 걸림.

```

users all
{

            "ImageLocation": "amazon/Deep Learning Base AMI (Amazon Linux 2) Version
53.4",

            "Public": true,

            "PlatformDetails": "Linux/UNIX",
            "UsageOperation": "RunInstances",
            "State": "available",
            "BlockDeviceMappings": [
                {
                    "DeviceName": "/dev/xvda",
                    "Ebs": {
                        "DeleteOnTermination": true,

```

응답에서 `ImageId`·`ImageLocation`·`CreationDate`·`PlatformDetails` 같은 속성을 읽음.

타 계정의 AMI 를 보려면 `--owners` 에 **대상의 계정 ID** 를 넣어야 하는데, 계정 ID 는 AWS 가입 시 부여되는 고유 식별자라 아직 알 수 없음. 대신 API 의 필터 기능으로 다른 속성을 찍어 우회함. 필터 표현식 구조는 이러함.

```
--filters "Name=filter-name,Values=filter-value1,filter-value2,..."
```

*출처: 원문 Listing 943 — 필터 표현식 형식*

`Name` 은 걸러낼 객체 속성, `Values` 는 그 속성의 값임. `*Offseclab*` 처럼 `*` 와일드카드를 쓰면 앞뒤로 임의 개수(0개 포함)의 문자를 허용해, 단어가 포함되기만 하면 매칭됨.

```
    --filters "Name=description,Values=*Offseclab*"
```

*출처: 원문 Listing 944 — offseclab 단어를 노리는 필터 표현식*

먼저 `description` 속성으로 걸어 봄.

```
kali@kali:~$ aws --profile attacker ec2 describe-images --executable-users all --
filters "Name=description,Values=*Offseclab*"
{
    "Images": []
}
```

*출처: 원문 Listing 946 — name 속성 필터로 대상의 AMI 적중*

AMI 하나가 잡혔고, 더 중요하게는 응답의 `OwnerId` 로 **대상 조직의 것으로 보이는 계정 ID 가 드러남.** 이것이 이 절의 실질적 수확임 — 계정 ID 를 확보하면 그 계정 소유의 다른 AMI 나 리소스를 다시 훑을 수 있음.

같은 방식으로 공개 EBS 스냅샷은 `ec2 describe-snapshots` 에 필터를 걸어 찾음.

```
kali@kali:~$ aws --profile attacker ec2 describe-snapshots --filters
"Name=description,Values=*offseclab*"
{
    "Snapshots": []
}
```

*출처: 원문 Listing 947 — 공개 스냅샷 필터 결과(해당 없음)*

일반화하면 **황금률은 없음.** 검색 방법은 리소스 종류·서비스 API·CSP 마다 달라짐. 정공법은 해당 CSP 에서 공개 노출이 가능한 리소스가 무엇인지 조사하고 시도할 서비스의 문서를 확인하는 것임.

이런 리소스를 찾으면 공격 표면이 넓어지고 새 벡터가 열림. 예컨대 찾아낸 AMI 로 EC2 인스턴스를 직접 띄워 그 안에서 민감 데이터를 뒤질 수 있음. 직접적인 접근 수단이 안 나오더라도 대상에 대한 이해는 그만큼 넓어짐.
