# 25.2.1 랩 접속

> **Accessing the Lab** · PEN-200 §25.2.1

도메인 이름 하나 말고는 아무 정보가 없는 상태에서 조직 하나를 대상으로 정찰하는 시나리오임.

배포에 몇 분이 걸리고, 완료 후에도 부가 서비스가 뜨는 데 5~10분이 더 걸림. 배포가 끝나면 뒤에서 쓸 정보를 받음 — 퍼블릭 DNS 의 IP 주소, 대상 도메인 이름, IAM 사용자 `attacker` 의 ACCESS_KEY_ID 와 SECRET_ACCESS_KEY.

실제로 게시된 도메인을 건드리지 않기 위해 랩 안에 배포된 **커스텀 퍼블릭 DNS** 를 대상으로 삼음. 기법과 도구 자체는 어떤 공개 도메인에도 그대로 적용됨.

먼저 로컬 환경의 DNS 를 랩 DNS 로 바꿔야 함. Kali 의 `/etc/resolv.conf` **맨 앞에** nameserver 줄을 추가해 질의가 랩 DNS 로 먼저 가게 함.

```
kali@kali:~$ sudo nano /etc/resolv.conf
[sudo] password for kali:
kali@kali:~$ cat /etc/resolv.conf
# Generated by NetworkManager
nameserver 44.205.254.229
nameserver 1.1.1.1
```

*출처: 원문 Listing 927 — resolv.conf 맨 앞에 랩 DNS 를 추가한 상태*

⚠️ **DNS 서버의 공인 IP 는 랩을 재시작할 때마다 바뀜.** 그때마다 이 설정을 다시 해야 함. 또 커스텀 DNS 는 랩 시작 후 응답하기까지 5분쯤 걸리므로, 질의가 성공해야 서비스가 다 떴다고 볼 수 있음.

검증은 `host` 로 두 번 함 — 먼저 DNS 서버 IP 를 명시해 서버가 응답하는지 확인하고, 다음으로 서버를 빼고 실행해 시스템 설정이 실제로 먹었는지 확인함.

```
kali@kali:~$ host www.offseclab.io 44.205.254.229
www.offseclab.io has address 52.70.117.69
kali@kali:~$ host www.offseclab.io
www.offseclab.io has address 52.70.117.69
```

*출처: 원문 Listing 928 — DNS 서버 지정 조회와 시스템 기본 조회 비교*

⚠️ 함정 — 일부 ISP 가 외부 DNS 서버 질의를 막음. 흔하지는 않지만 이 경우 위 두 명령이 모두 실패함. 모바일 핫스팟 경유가 우회책이고, 최악의 경우에도 영향은 '도메인 정찰' 절에 한정됨.

설정은 영구적이지 않음. Kali 기본 네트워크 구성이 NetworkManager 라 네트워크 서비스나 OS 를 재시작하면 `resolv.conf` 내용을 덮어씀. 작업이 끝나면 추가한 nameserver 항목을 지우거나, 더 간단하게 NetworkManager 를 재시작해 원상 복구할 것.

```
kali@kali:~$ sudo systemctl restart NetworkManager
[sudo] password for kali:
kali@kali:~$ cat /etc/resolv.conf
# Generated by NetworkManager
nameserver 1.1.1.1
```

*출처: 원문 Listing 929 — NetworkManager 재시작으로 DNS 설정 원복*

IAM 사용자 자격 증명은 지금 쓰지 않고 모듈 뒤쪽에서 사용함.
