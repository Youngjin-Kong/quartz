# 21.1.1 MSF 설정과 사용

> **Setup and Work with MSF** · PEN-200 §21.1.1

Kali 에는 Metasploit 이 기본 설치돼 있으나 **기본 설정에서는 데이터베이스 서비스가 뜨지 않음.** DB 없이도 돌아가지만 대상 호스트 정보와 익스플로잇 성공 이력을 남기려면 필요함. Metasploit 은 PostgreSQL 을 쓰는데 Kali 에서는 실행 상태도, 부팅 시 활성화도 돼 있지 않음. `msfdb init` 이 서비스 기동과 DB 생성·초기화를 한 번에 처리함.

```
kali@kali:~$ sudo msfdb init
[+] Starting database
[+] Creating database user 'msf'
[+] Creating databases 'msf'
[+] Creating databases 'msf_test'
[+] Creating configuration file '/usr/share/metasploit-framework/config/database.yml'
[+] Creating initial database schema
```

*DB 생성·초기화 — msf 사용자, msf·msf_test DB, 설정 파일까지 만들어짐*

부팅 시 자동 기동은 `sudo systemctl enable postgresql` 로 걺.

```
kali@kali:~$ sudo systemctl enable postgresql
Synchronizing state of postgresql.service with SysV service script with
/lib/systemd/systemd-sysv-install.
Executing: /lib/systemd/systemd-sysv-install enable postgresql
Created symlink /etc/systemd/system/multi-user.target.wants/postgresql.service →
/lib/systemd/system/postgresql.service.
```

*부팅 시 자동 기동 등록 — multi-user.target.wants 에 심볼릭 링크가 생김*

콘솔은 `sudo msfconsole` 로 띄우고, 배너와 버전 정보를 지우려면 `-q` 를 붙임. 뜬 뒤 DB 연결 상태는 `db_status` 로 확인함.

```
kali@kali:~$ sudo msfconsole
...
       =[ metasploit v6.2.20-dev                          ]
+ -- --=[ 2251 exploits - 1187 auxiliary - 399 post       ]
+ -- --=[ 951 payloads - 45 encoders - 11 nops            ]
+ -- --=[ 9 evasion                                       ]
Metasploit tip: Use help <command> to learn more
about any command
Metasploit Documentation: https://docs.metasploit.com/
msf6 >
```

*msfconsole 기동 — 배너에 모듈 수와 버전이 찍히고 `msf6 >` 프롬프트가 뜸*

```
msf6 > db_status
[*] Connected to msf. Connection type: postgresql.
```

*DB 연결 확인 — postgresql 로 연결됐으면 준비 완료*

명령은 범주로 나뉨 — Core · Module · Job · Resource Script · Database Backend · Credentials Backend · Developer. 전체 목록은 `help` 로 봄. 이 모듈에서 쓰는 것 대부분이 Module 계열(`search`·`show`·`use`)과 Database Backend 계열(`db_nmap`·`hosts`·`services`·`vulns`·`creds`·`loot`·`notes`·`workspace`)에 있음.

```
msf6 > help

    -------       -----------

    ...

===============

    -------       -----------
    ...
```

*`help` 출력 — 범주별 명령 목록(원문이 `...` 로 축약한 형태 그대로)*

**workspace 는 평가 간 결과를 격리하는 장치임.** DB 는 그대로 남으므로 다음 침투 테스트를 시작하면 이전 평가 결과와 섞임. `workspace` 만 치면 목록, 이름을 붙이면 전환, `-a <이름>` 이면 생성이고 생성 즉시 현재 워크스페이스가 됨.

```
msf6 > workspace
* default
msf6 > workspace -a pen200
[*] Added workspace: pen200
[*] Workspace: pen200
```

*pen200 워크스페이스 생성*

`db_nmap` 은 Metasploit 안에서 Nmap 을 실행하고 결과를 DB 에 저장하는 래퍼임. 문법은 Nmap 과 동일해 `db_nmap -A 192.168.50.202` 처럼 씀.

*db_nmap 으로 BRUTE2 스캔 — 결과가 그대로 DB 에 쌓임*

쌓인 결과는 `hosts` 로 발견된 호스트를, `services` 로 발견된 서비스를 조회함. `-p` 에 포트 번호를 주면 그 포트만 걸러냄 — **대상이 많은 평가에서 특정 서비스가 도는 호스트를 즉시 추려내는 용도임.**

```
msf6 > hosts
Hosts
=====

-------         ---  ----  -------       ---------  -----  -------  ----  --------
192.168.50.202             Windows 2016                    server
```

*발견된 서비스 목록과 포트 필터*

모듈은 수천 개이고 범주로 나뉨. 유효한 범주는 시작 배너에도 요약되지만 `show -h` 로도 확인함.

```
msf6 > show -h
[*] Valid parameters for the "show" command are: all, encoders, nops, exploits,
payloads, auxiliary, post, plugins, info, options
[*] Additional module-specific parameters are: missing, advanced, evasion, targets,
actions
msf6 >
```

*show 명령이 받는 인자 — 모듈 범주와 모듈별 추가 파라미터*

모듈 활성화는 `use <모듈명>` 임. 이름은 슬래시로 구분된 계층 구조(모듈 종류 / OS·벤더·앱·동작·프로토콜 / 모듈 이름)를 따라 탐색이 쉬움.
