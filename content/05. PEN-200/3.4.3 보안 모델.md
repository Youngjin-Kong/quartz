# 3.4.3 보안 모델

> **Security Models** · PEN-200 §3.4.3

보안 모델은 정보 시스템에 보안 통제를 구현할 때 쓰는 일종의 스키마임. 구체적 통제를 지정하는 일은 드물고, 이론적 틀과 (경우에 따라) 여러 맥락에 구현할 수 있는 규칙 집합을 제시함. 널리 알려진 모델 다수가 접근 통제를 겨냥하며, 어떤 것은 기밀성 또는 무결성에 특화돼 있고 어떤 것은 더 일반적임.

**기밀성 중심**

- **Bell–LaPadula** — 다중 보안 등급(비밀 취급 없음·대외비·비밀·1급비밀 등)을 가진 시스템의 접근 통제. 정부·군에서 어느 등급이 어떤 객체에 접근하는지 정하는 데 주로 쓰임. 규칙은 셋 — 자기보다 높은 등급의 내용을 읽지 못함(Simple Security Property), 자기보다 낮은 등급으로 쓰지 못함(Star Security Property), 맥락에 따라 자기 등급 외에는 읽기·쓰기 자체를 금지함(Discretionary Security Property)
- **Brewer and Nash** — 같은 접근 통제이되 목적이 이해 상충 최소화임. 회계·컨설팅 조직에서 쓰이며 데이터 분리와 동적 접근 통제를 사용함. 동적 통제란 「이미 무엇을 봤는가」에 따라 접근을 막는 방식 — 경쟁 관계인 두 고객을 함께 상대하는 조직에서, 한쪽 데이터를 열람한 담당자에게 경쟁사 데이터 접근을 일시 차단하는 식

**무결성 중심**

- **Biba** — 사람과 정보에 무결성 등급을 부여해 무결성을 지키는 접근 통제. 자기보다 낮은 등급의 데이터를 읽지 못하고(Simple Integrity Property), 자기보다 높은 등급으로 쓰지 못하며(Star Integrity Property), 자기보다 높은 등급의 정보에 접근을 요청하지도 못함(Invocation Property). 방향이 Bell–LaPadula 와 뒤집혀 있다는 점이 핵심
- **Clark-Wilson** — 접근 통제 트리플(주체·프로그램(트랜잭션)·객체)로 무결성을 구현함. 주체가 데이터 객체에 직접 손대지 못하고, 무결성 정책을 강제하는 프로그램들을 «거쳐서만» 접근·수정함

**일반 접근 통제**

- **RBAC(Role-Based Access Control)** — 권한을 역할에 부여하고 그 역할을 사용자에게 적용함. 사용자마다 직접 권한을 주지 않는 것이 요점이며, 클라우드 IAM 에서 널리 쓰임
- **ABAC(Attribute-Based Access Control)** — 사용자와 객체에 속성을 붙이고, 규칙이 그 속성으로 「누가 무엇에 어떤 접근을 하는가」를 판정함. 더 세분화되고 더 동적이라는 것이 장점
