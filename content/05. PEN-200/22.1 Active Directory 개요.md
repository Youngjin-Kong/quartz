# 22.1 Active Directory 개요

> **Active Directory - Introduction** · PEN-200 §22.1

AD 는 서비스이면서 동시에 **관리 계층**임. 사용자·그룹·컴퓨터 정보를 담고 이들을 통틀어 객체(object)라 부름. 객체마다 걸린 권한이 그 객체가 도메인 안에서 갖는 권한을 결정함. 담긴 정보가 많다는 것은 곧 공격면이 넓다는 뜻이라, 구성과 유지 자체가 관리자에게 부담임.

구성의 첫 단계는 `corp.com` 같은 도메인 이름을 만드는 것이고 `corp` 자리에는 보통 조직명이 들어감. 그 아래에 컴퓨터·사용자·그룹 등 조직에 딸린 객체를 추가함. AD 환경은 **DNS 에 결정적으로 의존**해서, 전형적인 도메인 컨트롤러는 해당 도메인의 authoritative DNS 서버 역할도 겸함.

객체 관리를 쉽게 하려고 관리자는 객체를 조직 단위(Organizational Unit, OU)로 묶음. OU 는 파일시스템 폴더에 해당하는 컨테이너임. 컴퓨터 객체는 도메인에 가입된 실제 서버·워크스테이션을, 사용자 객체는 그 컴퓨터에 로그인할 수 있는 계정을 나타냄. 모든 AD 객체는 속성(attribute)을 갖고 속성 목록은 객체 유형마다 다름 — 사용자 객체라면 이름·성·사용자명·전화번호 같은 것.

사용자가 도메인에 로그인하려 하면 요청이 **도메인 컨트롤러(Domain Controller, DC)** 로 가고 DC 가 로그인 허용 여부를 판단함. DC 는 도메인의 허브이자 핵심이라 모든 OU·객체·속성을 저장하고 있음. 그래서 AD 를 열거하는 내내 DC 를 주의 깊게 들여다보게 됨.

객체는 AD 그룹에 넣어 한 단위로 관리할 수 있음 — 그룹 단위로 파일 서버 공유 접근을 주거나 도메인 내 여러 클라이언트의 관리자 권한을 줄 수 있음. **공격자가 노리는 것은 고권한 그룹**임. `Domain Admins` 구성원은 도메인에서 가장 높은 권한을 가진 축이라, 여기 속한 계정 하나만 장악해도 사실상 도메인 전체를 쥠.

공격 범위는 도메인 하나로 끝나지 않을 수 있음 — AD 인스턴스는 도메인 트리 안에 여러 도메인을, 도메인 포리스트 안에 여러 트리를 담을 수 있기 때문임. 포리스트 안의 도메인마다 `Domain Admins` 가 따로 있지만, `Enterprise Admins` 구성원은 **포리스트 내 모든 도메인을 통제하고 모든 DC 에서 Administrator 권한**을 가짐 — 최상위 표적임.

열거는 이후 공격 단계의 성공률을 직접 끌어올리는 작업임. 수동 열거에 쓰는 도구는 대부분 LDAP(Lightweight Directory Access Protocol)에 기대고 있고, 기초 기법을 익힌 뒤 자동화로 규모를 키우는 순서로 감.
