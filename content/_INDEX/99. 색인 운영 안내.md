# 색인 운영 안내

## 머신 노트를 새로 추가했을 때

```powershell
& "C:\Users\QQ\Documents\Obsidian Vault\_INDEX\_tools\refresh.ps1"
```

3단계가 자동 실행된다.

1. `extract.py` — 모든 노트를 다시 읽어 nmap 덤프·명령어에서 메타데이터 추출 → `_tools/meta.json`
2. `inject.py --refresh --apply` — 프론트매터 재계산 후 교체
3. `build_index.py` — `_INDEX/` 색인 노트 7개 재생성

실행 후 Obsidian에서 `Ctrl+R`.

## 안전장치

- **본문은 절대 수정되지 않는다.** 프론트매터 블록만 붙이거나 갈아낀다.
- **손으로 쓴 프론트매터는 보존된다.** 교체 대상은 `tech_count:` 필드가 있는 블록, 즉 이 도구가 생성한 것으로 한정된다. 노트에 직접 프론트매터를 쓰면 그 노트는 영구히 건드리지 않는다.
- git 저장소가 초기화돼 있다. 결과가 마음에 안 들면 `git checkout .` 로 되돌린다.
- 원본 스냅샷 커밋: `15671e5` (프론트매터 주입 전)

## 기법 태그를 추가·수정하려면

`_tools/extract.py` 의 `TECH_RAW` 리스트에 한 줄 추가한다.

```python
("tech/lin/새기법", [r"시그니처정규식", r"대체표현"]),
```

한국어 명칭과 설명은 `_tools/build_index.py` 의 `TECH_INFO` 에 같은 키로 넣는다.
포트별 행동 지침은 같은 파일의 `PORT_PLAY` 에 있다.

## 실행 시 주의

- **`_INDEX/` 의 00~06 노트는 자동 생성물이다.** 손으로 고치면 다음 `refresh.ps1` 에서 지워진다. 내용을 바꾸려면 `_tools/build_index.py` 를 고친다. 이 99번 노트만 손으로 관리한다.
- **노트를 작성하는 중에 돌리지 말 것.** 2026-08-19 구축 당시 다른 세션이 `03. PG/Hub.md` 를 쓰는 중에 실행해 주입한 프론트매터가 덮어써졌다. 추출과 주입 사이에 파일이 바뀌면 그 노트만 누락된다. 증상은 "새 노트에 태그가 없다"이고, 조치는 **한 번 더 실행**이면 된다.

## 알려진 한계

- 기법 판정은 **본문 문자열 매칭**이다. 시도했다가 실패한 기법도 태그가 붙는다. 태그는 "이 노트에 언급됨"이지 "이 기법으로 뚫었음"이 아니다.
- 치트시트는 모든 기법을 언급하므로 태그가 40~60개씩 붙는다. 정상이다.
- `os` 미판정 노트는 nmap 출력이 없는 노트다.
- CVE 12종 이상이 검출된 노트는 취약점 스캐너 출력 덤프로 추정해 `cve_bulk` 로 표시된다.
